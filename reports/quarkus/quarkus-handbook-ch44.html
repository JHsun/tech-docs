Container Image：Docker、Jib 與 Buildpacks

程式碼打包成 JAR 只是第一步 ── 現代部署的終點是 OCI container image。 Quarkus 提供三種建 image 方式：Docker（完全控制 Dockerfile）、 Jib（不需 Docker daemon，CI 友善）、Buildpacks（零 Dockerfile）。 本章把三者的權衡說清楚，再深入多架構 multi-arch build（amd64 + arm64）、 image 最小化（distroless / micro）、安全掃描整合，以及 Quarkus 的一鍵建 image 屬性。

讀者 🔵 開發者 🟠 SRE
版本 Quarkus 3.33 LTS · Jib 3.x · UBI 9

三種方式對比

方式需要 Docker daemonDockerfile適合
Docker✅ 需要自己寫（完全控制）需要客製化基底 image、安全 hardening
Jib❌ 不需要不需要CI 環境（無 Docker）、Jib 自動分層優化
Buildpacks✅ 需要不需要標準化流程、Cloud Foundry / Heroku 生態

Docker Extension

bash · 加擴充
quarkus extension add container-image-docker
application.properties
quarkus.container-image.builder=docker

# image 名稱設定
quarkus.container-image.registry=ghcr.io
quarkus.container-image.group=example-org
quarkus.container-image.name=catalog-service
quarkus.container-image.tag=${quarkus.application.version}

# 也加 latest tag
quarkus.container-image.additional-tags=latest

# 建完自動 push
quarkus.container-image.push=true

# 使用的 Dockerfile
quarkus.docker.dockerfile-jvm-path=src/main/docker/Dockerfile.jvm
bash · 建並 push
./mvnw package -Dquarkus.container-image.build=true \
               -Dquarkus.container-image.push=true

生產 Dockerfile.jvm（Quarkus 官方範本改良版）

Dockerfile · 多層次 fast-jar
FROM eclipse-temurin:21-jre-ubi9-minimal

# 安全：使用非 root user
RUN groupadd -g 1001 quarkus \
 && useradd -u 1001 -g quarkus -m -s /bin/bash quarkus

WORKDIR /deployments

# 1. 先複製依賴（很少變 → Docker cache 命中率高）
COPY --chown=quarkus:quarkus target/quarkus-app/lib/ /deployments/lib/

# 2. 再複製 Quarkus 主 JAR 和 boot 檔案
COPY --chown=quarkus:quarkus target/quarkus-app/*.jar /deployments/
COPY --chown=quarkus:quarkus target/quarkus-app/app/ /deployments/app/
COPY --chown=quarkus:quarkus target/quarkus-app/quarkus/ /deployments/quarkus/

USER quarkus
EXPOSE 8080
EXPOSE 9000

ENV JAVA_OPTS="-XX:+UseG1GC -XX:MaxRAMPercentage=75 -XX:+UseContainerSupport \
               -XX:+ExitOnOutOfMemoryError -XX:+HeapDumpOnOutOfMemoryError \
               -Djava.util.logging.manager=org.jboss.logmanager.LogManager"

ENTRYPOINT ["java", "-jar", "/deployments/quarkus-run.jar"]

Jib：不需要 Docker Daemon

Jib 直接從 Maven / Gradle 建立 OCI image，不呼叫 Docker。 適合 CI 環境（如 GitHub Actions 的 ubuntu-latest runner，不一定有 Docker daemon）。

bash
quarkus extension add container-image-jib
application.properties
quarkus.container-image.builder=jib

# Jib 使用的基底 image
quarkus.jib.base-jvm-image=eclipse-temurin:21-jre-ubi9-minimal

# Jib 自動分層（lib / app 獨立層）
# 這是 Jib 預設行為，不需要額外設定

# 非 root user
quarkus.jib.jvm-additional-arguments=-Djava.util.logging.manager=org.jboss.logmanager.LogManager

# 不需要 Docker 就能 push 到 registry
quarkus.container-image.push=true
quarkus.container-image.registry=ghcr.io
✓
Jib 的優勢
  • 不需要 Docker daemon── 在沒有 docker socket 的 CI 環境直接 push
  • 自動最佳化分層── dependencies / resources / classes 各一層
  • 不需要 Dockerfile── 設定全在 application.properties
  • Rootless 預設── 比 Docker 預設更安全

Native Image 的 Dockerfile

Dockerfile · Multi-stage native build
## Stage 1：用 Mandrel builder 建 native binary
FROM quay.io/quarkus/ubi9-quarkus-mandrel-builder-image:jdk-21 AS build

COPY --chown=quarkus:quarkus --chmod=0755 mvnw /code/mvnw
COPY --chown=quarkus:quarkus .mvn /code/.mvn
COPY --chown=quarkus:quarkus pom.xml /code/
USER quarkus
WORKDIR /code

# 先下載依賴（可 cache）
RUN ./mvnw dependency:go-offline -B -q

# 再複製源碼
COPY --chown=quarkus:quarkus src /code/src

# 建 native binary（記憶體需求 >= 4GB）
RUN ./mvnw package -Pnative -DskipTests -q

## Stage 2：最小化 runtime image
FROM quay.io/quarkus/ubi9-quarkus-micro-image:2.0

WORKDIR /work
COPY --from=build --chown=1001:root /code/target/*-runner /work/application

RUN chmod 755 /work/application
USER 1001
EXPOSE 8080 9000

ENTRYPOINT ["/work/application", "-Dquarkus.http.host=0.0.0.0"]
ℹ︎
Base image 選型
  • JVM 模式：eclipse-temurin:21-jre-ubi9-minimal 或 ubi9-minimal + JDK
  • Native 模式：quay.io/quarkus/ubi9-quarkus-micro-image:2.0（最小，約 6MB）
  • Distroless：quay.io/quarkus/quarkus-distroless-image:2.0（無 shell，安全性最高）
安全優先選 distroless；需要 shell 調試選 micro；JVM 模式用 temurin-ubi。

container-image 通用設定

application.properties · 完整 image 設定
# Registry 登入（也可用 docker login 或 CI secret）
quarkus.container-image.username=${REGISTRY_USER}
quarkus.container-image.password=${REGISTRY_PASSWORD}

# Image 識別
quarkus.container-image.registry=ghcr.io
quarkus.container-image.group=example-org
quarkus.container-image.name=${quarkus.application.name}
quarkus.container-image.tag=${quarkus.application.version}
quarkus.container-image.additional-tags=latest

# Labels
quarkus.container-image.labels."org.opencontainers.image.title"=catalog-service
quarkus.container-image.labels."org.opencontainers.image.version"=${quarkus.application.version}
quarkus.container-image.labels."org.opencontainers.image.revision"=${git.commit.id}

# 預設不 push，CI 才 push
quarkus.container-image.push=false
%prod.quarkus.container-image.push=true

Multi-arch Build（amd64 + arm64）

Apple Silicon 普及後，arm64 image 變得必要。Docker Buildx + QEMU 可以一次建兩個架構：

bash · Docker Buildx multi-arch（CI 推薦）
# 建立 multi-arch builder
docker buildx create --name mybuilder --use

# 建並 push 兩個架構（CI 中執行）
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  --tag ghcr.io/example-org/catalog-service:1.4.2 \
  --tag ghcr.io/example-org/catalog-service:latest \
  --file src/main/docker/Dockerfile.jvm \
  --push \
  .
⚠
Native Image 的 multi-arch
Native binary 是平台相關的（linux/amd64 != linux/arm64）。 建 native multi-arch image 需要在各自平台上分別 build，再合成 manifest list。
一般做法：
  1. amd64 runner 建 native amd64 image
  2. arm64 runner 建 native arm64 image
  3. docker manifest create 合成 multi-arch manifest
成本高，只在有明確需求時做。

Image 安全掃描

yaml · GitHub Actions：build + scan + push
- name: Build container image
  run: ./mvnw package -Dquarkus.container-image.build=true

- name: Scan with Trivy
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: 'ghcr.io/example-org/catalog-service:${{ github.sha }}'
    format: 'sarif'
    output: 'trivy-results.sarif'
    severity: 'CRITICAL,HIGH'
    exit-code: '1'    # 有 CRITICAL / HIGH 就 fail CI

- name: Push (only if scan passed)
  run: docker push ghcr.io/example-org/catalog-service:${{ github.sha }}

常見陷阱

症狀原因解法
Docker push 在 CI 失敗沒登入 registry用 docker login 或設 quarkus.container-image.username/password
Jib push 失敗 TLS 錯誤私有 registry 用自簽憑證quarkus.jib.allow-insecure-registries=true（開發用）或設定 CA
Native image 啟動報 ELF 格式錯誤在 macOS build 但部署到 linux改用 container build：-Dquarkus.native.container-build=true
Distroless image 無法執行 df/ps沒有 shell調試用 micro image；distroless 只用生產
Image 太大（JVM 400MB+）用了 JDK image 而非 JRE換 eclipse-temurin:21-jre-ubi9-minimal（JRE 只要 ~200MB）

本章小結

  • 三種建 image 方式：Docker（完全控制）/ Jib（無 daemon，CI 友善）/ Buildpacks（零 Dockerfile）。
  • Docker 搭配 fast-jar 分層：先 COPY lib/（cache 命中），再 COPY app/（常更新），推送速度快 10 倍。
  • Jib：CI 環境推薦，不需 docker socket，自動最佳化分層，設定全在 properties。
  • Native Dockerfile：multi-stage，Stage 1 用 Mandrel builder，Stage 2 用 ubi9-micro（~6MB）。
  • Base image 選型：JVM 用 temurin-jre-ubi9；Native 用 ubi9-micro 或 distroless（最安全）。
  • Multi-arch：JVM 用 Docker Buildx 一次建兩架構；Native 需分平台各建一次。
  • 安全：非 root user（UID 1001）必設；加 Trivy 掃描 CRITICAL/HIGH；OCI label 標示版本與 commit。
  • quarkus.container-image.* 屬性統一管控 image 名稱、tag、registry、push 行為。
