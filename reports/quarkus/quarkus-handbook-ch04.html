Dev Services 與 Compose Dev Services

當你加入 quarkus-hibernate-orm 卻沒在配置裡寫資料庫連線， Quarkus 不會抱怨，而是自動幫你拉起一個 PostgreSQL 容器。 這個看似「魔法」的能力，就是 Dev Services ── Quarkus 開發者愉悅感的另一個基石。

什麼是 Dev Services？

Dev Services 是 Quarkus 在 dev 與 test 模式下，自動偵測未配置的依賴服務並用容器啟動它們的機制。 你不需要寫 docker-compose.yml、不需要手動拉容器、不需要在 application.properties 設連線字串。

零配置開發：加擴充、按 Run，依賴就自己跑起來了。

觸發條件

Dev Services 不會無緣無故啟動容器。觸發需要同時滿足以下條件：

  1. 裝了對應擴充（例如 quarkus-jdbc-postgresql、quarkus-messaging-kafka）
  2. 沒有顯式配置連線資訊（沒設 quarkus.datasource.jdbc.url 等）
  3. 容器執行階段可用（Docker、Podman、或其他 OCI runtime）
  4. 模式為 dev 或 test（不會在 prod profile 啟動）
⚠
「沒配置」才會啟動
這是 Dev Services 最容易誤解的地方。一旦你在 application.properties 設了 quarkus.datasource.jdbc.url=jdbc:postgresql://...， Dev Services 就會把這個資料來源視為「使用者已自行管理」而不啟動容器。 若想保留配置又要用 Dev Services，可以加 quarkus.datasource.devservices.enabled=true 強制開啟。

親手體驗：加一個 PostgreSQL

以第 3 章建立的 catalog-service 為基礎，加入 Hibernate ORM Panache 與 PostgreSQL：

Quarkus CLI
quarkus extension add hibernate-orm-panache jdbc-postgresql
Maven
./mvnw quarkus:add-extension -Dextensions="hibernate-orm-panache,jdbc-postgresql"
Gradle
./gradlew addExtension --extensions="hibernate-orm-panache,jdbc-postgresql"

加一個簡單的 entity：

Java · Product.java
package com.example.shop;

import io.quarkus.hibernate.orm.panache.PanacheEntity;
import jakarta.persistence.Entity;
import java.math.BigDecimal;

@Entity
public class Product extends PanacheEntity {
    public String name;
    public BigDecimal price;
}

不要在 application.properties 寫任何 datasource 設定，直接跑：

bash
quarkus dev

看終端：

INFO [io.qua.dev.pos.dep.DevServicesPostgresqlProcessor] Dev Services for PostgreSQL started. INFO [org.tes.uti.ImageNameSubstitutor] Image name substitution will be performed by: DefaultImageNameSubstitutor INFO [org.tes.doc.DockerClientProviderStrategy] Loaded org.testcontainers.dockerclient.UnixSocketClientProviderStrategy INFO [org.tes.DockerClientFactory] Docker client connected (Podman 5.2.1) INFO [tc.pos.16] Container postgres:16 is starting: localhost:54321 INFO [tc.pos.16] Container postgres:16 started in PT2.847S INFO [io.quarkus] catalog-service 1.0.0-SNAPSHOT on JVM started in 4.123s. 關鍵訊息：

  • Dev Services for PostgreSQL started ── 偵測到沒配置，自動啟動
  • Container postgres:16 started in PT2.847S ── 拉起官方 PostgreSQL 16 容器（首次會花時間下載 image）
  • localhost:54321 ── 隨機 port，避免衝突
  • 注入連線資訊到應用，Hibernate ORM 直接連上

Dev UI 中的 Dev Services

打開 http://localhost:8080/q/dev-ui，找到「Dev Services」卡片， 你會看到所有啟動的容器、它們的 image、port、environment、network。

更實用的是「Datasources」卡片，它提供：

  • SQL Console ── 直接在瀏覽器執行 SQL 查詢，不用裝 DBeaver/pgAdmin
  • Connection 資訊 ── 隨機 port 改變時不用猜
  • HQL Console（Hibernate ORM）── 直接執行 HQL，看 SQL 翻譯結果
✓
使用 IDE 連線
若想用 IntelliJ 或 DBeaver 連，從 Dev UI 抄 JDBC URL + 隨機 port。 使用者名稱密碼通常是 quarkus / quarkus（每個 Dev Service 略有不同，以 Dev UI 顯示為準）。

客製化 Dev Services

大部分 Dev Services 都有可調整的設定。以 PostgreSQL 為例：

application.properties · PostgreSQL Dev Service 客製
# 指定容器 image
quarkus.datasource.devservices.image-name=postgres:15

# 固定 port（不指定則隨機）
quarkus.datasource.devservices.port=5432

# 自訂帳密
quarkus.datasource.username=shop_user
quarkus.datasource.password=shop_pass

# 預先載入 SQL（容器啟動後立刻執行）
quarkus.datasource.devservices.init-script-path=db/init.sql

# 自訂容器名稱（方便用 docker ps 識別）
quarkus.datasource.devservices.container-properties.HOSTNAME=catalog-db

# 在停止 dev mode 時保留容器（下次啟動更快）
quarkus.datasource.devservices.reuse=true

Dev Services 共享機制

如果你同時開了 catalog-service、order-service 兩個 Quarkus 應用， 且都需要 PostgreSQL，Quarkus 預設會共享同一個容器（透過 Testcontainers 標籤識別）。 這避免了開多個應用就拉多個資料庫的浪費。

application.properties · 共享行為控制
# 預設 true，與其他 Quarkus app 共享相同 service 的容器
quarkus.datasource.devservices.shared=true

# 共享識別 label（同 label 才會共享，不同 label 就獨立）
quarkus.datasource.devservices.service-name=shared-postgres

Compose Dev Services

Dev Services 解決單一服務的自動化，但實際專案常常需要多個服務協作： PostgreSQL + Redis + Keycloak + Kafka 一起運作。每個都靠 Dev Services 各自啟動， 缺乏「整組服務」的協調能力（網路拓樸、啟動順序、共享資料）。

Quarkus 3.22 引入 Compose Dev Services 解決這個痛點。 你寫一個 compose-devservices.yml，Quarkus 在 dev/test 模式自動 docker compose up 並把容器資訊注入到 Quarkus 配置。

建立 compose-devservices.yml

在專案根目錄建立檔案：

compose-devservices.yml · 多容器協作
name: catalog-stack

services:
  postgres:
    image: postgres:17
    environment:
      POSTGRES_USER: shop
      POSTGRES_PASSWORD: shop
      POSTGRES_DB: catalog
    ports:
      - "5432"   # 不寫 host port，讓 Quarkus 抓動態 port
    labels:
      io.quarkus.devservices.compose.config_map.quarkus.datasource.username: shop
      io.quarkus.devservices.compose.config_map.quarkus.datasource.password: shop

  redis:
    image: redis:8
    ports:
      - "6379"

  keycloak:
    image: quay.io/keycloak/keycloak:26
    command: ["start-dev"]
    environment:
      KEYCLOAK_ADMIN: admin
      KEYCLOAK_ADMIN_PASSWORD: admin
    ports:
      - "8080"

啟動 dev mode：

$ quarkus dev INFO [io.qua.dev.com.dep.ComposeDevServicesProcessor] Starting Compose project 'catalog-stack' from compose-devservices.yml INFO [io.qua.dev.com.dep.ComposeDevServicesProcessor] Running: docker compose --project-name catalog-stack up -d INFO Container catalog-stack-postgres-1 Started INFO Container catalog-stack-redis-1 Started INFO Container catalog-stack-keycloak-1 Started INFO Compose Dev Services discovered services: postgres, redis, keycloak INFO Auto-configured datasource → catalog-stack-postgres-1:5432 INFO Auto-configured redis-client → catalog-stack-redis-1:6379 INFO Auto-configured OIDC → catalog-stack-keycloak-1:8080 INFO Listening on: http://localhost:8080

幾個關鍵點：

  • 檔名固定：compose-devservices.yml（也支援 compose-devservices.yaml）
  • port 寫成 "5432"（不指定 host port），Quarkus 會自動抓動態 port 並注入
  • 各擴充的 Dev Services 會偵測 compose 的服務並覆寫自己的容器啟動行為
  • 透過 labels 可以給 Quarkus 額外的配置 hint

環境隔離：每個 profile 一個 compose

Quarkus 也支援針對不同 profile 用不同 compose 檔：

application.properties
quarkus.compose.dev-services.files=compose-devservices.yml,compose-overrides.yml

# 或針對 test profile
%test.quarkus.compose.dev-services.files=compose-test.yml

Dev Services vs Compose Dev Services 對照

面向內建 Dev ServicesCompose Dev Services
配置方式application.propertiescompose-devservices.yml
學習曲線低，零配置即可需熟悉 compose 語法
客製能力中等，受限於 Quarkus 提供的屬性高，完整 compose spec 支援
多容器協作受限，每個服務獨立原生支援，共享網路與啟動順序
跨團隊一致性需各 service 各自設定一份 yml 全部統一
適合場景單服務、簡單依賴多服務、複雜拓樸、團隊共用
ℹ︎
兩者可共存
Compose Dev Services 啟動的服務，會自動讓內建 Dev Services 不重複啟動。 例如 compose 已經跑 postgres，內建的 PostgreSQL Dev Service 偵測到後會跳過，直接用 compose 的那個。 這讓你可以從「內建 Dev Services」漸進演進到「Compose Dev Services」，不需大改。

在測試中的 Dev Services

Dev Services 不只在 quarkus dev 啟動，跑 @QuarkusTest 時也會自動啟動。 這代表你的單元測試與整合測試不需要外部資料庫，CI 環境也不用準備依賴服務。

Java · 測試直接用 Dev Service 啟動的資料庫
@QuarkusTest
class ProductRepositoryTest {

    @Inject
    EntityManager em;

    @Test
    @TestTransaction  // 每個測試後 rollback
    void shouldPersistProduct() {
        Product p = new Product();
        p.name = "Widget";
        p.price = new BigDecimal("9.99");
        p.persist();

        assertNotNull(p.id);
        assertEquals(1L, Product.count());
    }
}

跑 ./mvnw test 時，Quarkus 自動啟動 PostgreSQL 容器、執行測試、停止容器。 CI 機器只需要有 Docker 或 Podman，不用預先安裝 PostgreSQL。

DevOps / SRE 視角

避免讓 Dev Services 影響生產配置

Quarkus 設計上 Dev Services 只在 dev 與 test profile 啟動， 但若不小心在生產配置忘了寫 datasource URL，Quarkus 不會嘗試啟動容器，但會啟動失敗。 建議在 application.properties 用 %prod. 前綴明確區分：

application.properties
# dev / test：留空交給 Dev Services
# %prod：明確配置

%prod.quarkus.datasource.username=${DB_USER}
%prod.quarkus.datasource.password=${DB_PASSWORD}
%prod.quarkus.datasource.jdbc.url=jdbc:postgresql://${DB_HOST}:5432/catalog

# 防呆：禁止 prod 啟動 Dev Services
%prod.quarkus.devservices.enabled=false

讓團隊共用 compose 基線

把 compose-devservices.yml 提交到 Git，新成員 clone 專案立刻有相同依賴環境。 比起每人各自 brew install postgresql、版本不一導致的 bug 來得可靠許多。

CI/CD 對 Dev Services 的注意事項

環境配置建議
GitHub Actions ubuntu-latest 內建 Docker，無需額外設定即可跑 Dev Services 測試
GitLab CI 需用 docker:dind service，或 GitLab Runner 啟用 docker socket binding
Jenkins on K8s Pod 需 mount docker socket，或用 sysbox-runc rootless 容器
Tekton 用 docker-in-docker sidecar task
⚠
Image pull 速度
CI 第一次跑會花很多時間下載 image。建議在 CI runner 預先 docker pull 常用 image， 或啟用 layer cache、registry mirror（如 Harbor 內網 cache）來加速。

關閉 Dev Services

有時你想用本機已啟動的服務（例如連到開發伺服器上的測試資料庫），可以關掉 Dev Services：

application.properties
# 全域關閉所有 Dev Services
quarkus.devservices.enabled=false

# 只關閉 datasource Dev Service
quarkus.datasource.devservices.enabled=false

# 啟動時用環境變數覆寫
# QUARKUS_DEVSERVICES_ENABLED=false quarkus dev

常見陷阱

症狀原因解法
Dev Services 沒啟動 已在配置裡寫了 datasource URL 移除 URL，或加 quarkus.datasource.devservices.enabled=true 強制啟動
「No container runtime was found」 Docker/Podman 未啟動或 DOCKER_HOST 設錯 檢查容器執行階段（見第 2 章）
啟動超慢（> 1 分鐘） 首次下載 image 或網路慢 預先 docker pull postgres:17；CI 用 registry mirror
port 衝突 多個 Quarkus app 同時啟動，沒共享 service-name 設 quarkus.datasource.devservices.shared=true + service-name
Compose service 找不到 檔名拼錯（需 compose-devservices.yml） 確認檔名與路徑；可用 quarkus.compose.dev-services.files 自訂
停止 dev mode 後容器沒清乾淨 非正常退出（kill -9） 手動 docker compose down；或設 reuse=false 避免殘留

本章小結

  • Dev Services = 加擴充 + 沒配置 + 有容器 runtime → 自動拉容器並注入配置。
  • 底層用 Testcontainers，所以 image 版本、port、environment 都可用 application.properties 客製。
  • 同 Quarkus 應用共享容器（透過 service-name label），不會浪費資源。
  • Compose Dev Services 解決多服務協作場景，寫一份 compose-devservices.yml 即可。
  • 內建 Dev Services 與 Compose 可無縫共存，內建會避讓 compose 已啟動的服務。
  • SRE 應該把 compose 檔提交到 Git，建立團隊環境基線；生產配置用 %prod. 前綴明確隔離。
