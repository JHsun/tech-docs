CI/CD 整合：GitHub Actions 與 GitLab CI

本章給出兩套可直接使用的 CI/CD pipeline 範本 ── GitHub Actions 與 GitLab CI/CD， 涵蓋 PR 快速反饋（unit + integration test）、main branch 自動建 container image 並推到 registry、 以及 GitOps with ArgoCD 的 K8s 部署鏈。 核心原則：快的測試給每個 commit，慢的（Native build、E2E）只在關鍵節點跑。

讀者 🔵 開發者 🟠 SRE
版本 Quarkus 3.33 LTS · GitHub Actions · GitLab CI
預估閱讀 20 分鐘

CI/CD Pipeline 設計原則

ℹ︎
快 / 慢分層原則
  • 每個 commit（PR）：Unit test + @QuarkusTest ── 目標 <5 分鐘
  • merge 到 main：+ @QuarkusIntegrationTest + build JVM image + push
  • release tag / nightly：+ Native build + 安全掃描
分層能讓開發者快速得到反饋，又不讓 main branch 帶著未測試的 native binary。

GitHub Actions 完整範本

yaml · .github/workflows/ci.yml（PR 快速反饋）
name: CI

on:
  pull_request:
    branches: [main, develop]
  push:
    branches: [main]

env:
  JAVA_VERSION: '21'
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}

jobs:
  # ─── 快速測試（每次 PR 都跑）─────────────────────────────
  test:
    name: Test
    runs-on: ubuntu-latest
    services:
      docker:
        image: docker:dind
        options: --privileged

    steps:
    - uses: actions/checkout@v4

    - uses: actions/setup-java@v4
      with:
        java-version: ${{ env.JAVA_VERSION }}
        distribution: temurin
        cache: maven

    - name: Run tests
      run: ./mvnw test
      env:
        TESTCONTAINERS_RYUK_DISABLED: false

    - name: Upload test results
      uses: actions/upload-artifact@v4
      if: always()
      with:
        name: test-results
        path: target/surefire-reports/

  # ─── Build + Push image（只在 main branch）────────────────
  build-image:
    name: Build & Push JVM Image
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest

    permissions:
      contents: read
      packages: write

    steps:
    - uses: actions/checkout@v4

    - uses: actions/setup-java@v4
      with:
        java-version: ${{ env.JAVA_VERSION }}
        distribution: temurin
        cache: maven

    - name: Log in to GHCR
      uses: docker/login-action@v3
      with:
        registry: ${{ env.REGISTRY }}
        username: ${{ github.actor }}
        password: ${{ secrets.GITHUB_TOKEN }}

    - name: Build & push container image
      run: |
        ./mvnw package -DskipTests \
          -Dquarkus.container-image.build=true \
          -Dquarkus.container-image.push=true \
          -Dquarkus.container-image.registry=${{ env.REGISTRY }} \
          -Dquarkus.container-image.group=${{ github.repository_owner }} \
          -Dquarkus.container-image.name=catalog-service \
          -Dquarkus.container-image.tag=${{ github.sha }}

    # 可選：更新 GitOps repo 觸發 ArgoCD
    - name: Update image tag in GitOps repo
      uses: actions/checkout@v4
      with:
        repository: example-org/gitops-manifests
        token: ${{ secrets.GITOPS_TOKEN }}
        path: gitops
    - run: |
        cd gitops
        sed -i "s|image: .*catalog-service:.*|image: ${{ env.REGISTRY }}/example-org/catalog-service:${{ github.sha }}|" \
          k8s/catalog-service/deployment.yaml
        git config user.email "ci@example.com"
        git config user.name "CI Bot"
        git add . && git commit -m "Update catalog-service to ${{ github.sha }}" && git push
yaml · .github/workflows/native.yml（Native build，只在 tag / nightly）
name: Native Build

on:
  push:
    tags: ['v*']          # 發版時
  schedule:
    - cron: '0 2 * * 1'  # 每週一凌晨 2 點

jobs:
  native-build:
    name: Native Build & Push
    runs-on: ubuntu-latest

    permissions:
      contents: read
      packages: write

    steps:
    - uses: actions/checkout@v4

    - uses: actions/setup-java@v4
      with:
        java-version: '21'
        distribution: temurin
        cache: maven

    - uses: docker/login-action@v3
      with:
        registry: ghcr.io
        username: ${{ github.actor }}
        password: ${{ secrets.GITHUB_TOKEN }}

    - name: Build Native Image
      run: |
        ./mvnw package -Pnative -DskipTests \
          -Dquarkus.native.container-build=true \
          -Dquarkus.container-image.build=true \
          -Dquarkus.container-image.push=true \
          -Dquarkus.container-image.tag=${{ github.ref_name }}-native

    - name: Scan with Trivy
      uses: aquasecurity/trivy-action@master
      with:
        image-ref: 'ghcr.io/example-org/catalog-service:${{ github.ref_name }}-native'
        severity: 'CRITICAL,HIGH'
        exit-code: '1'

GitLab CI/CD 範本

yaml · .gitlab-ci.yml
image: eclipse-temurin:21-jdk

variables:
  MAVEN_OPTS: "-Dmaven.repo.local=$CI_PROJECT_DIR/.m2/repository"
  DOCKER_HOST: tcp://docker:2376
  DOCKER_TLS_CERTDIR: "/certs"

cache:
  key: "$CI_JOB_NAME"
  paths:
    - .m2/repository/

stages:
  - test
  - build
  - security
  - deploy

# ─── Test（每次 commit）──────────────────────────────
unit-test:
  stage: test
  services:
    - docker:dind
  script:
    - ./mvnw test
  artifacts:
    reports:
      junit: target/surefire-reports/*.xml
    when: always

# ─── Build image（main branch）──────────────────────
build-jvm-image:
  stage: build
  only: [main]
  services:
    - docker:dind
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - |
      ./mvnw package -DskipTests \
        -Dquarkus.container-image.build=true \
        -Dquarkus.container-image.push=true \
        -Dquarkus.container-image.registry=$CI_REGISTRY \
        -Dquarkus.container-image.group=$CI_PROJECT_NAMESPACE \
        -Dquarkus.container-image.tag=$CI_COMMIT_SHA

# ─── Security scan──────────────────────────────────
trivy-scan:
  stage: security
  only: [main]
  image: aquasec/trivy:latest
  script:
    - trivy image --exit-code 1 --severity CRITICAL,HIGH
        $CI_REGISTRY/$CI_PROJECT_NAMESPACE/catalog-service:$CI_COMMIT_SHA

# ─── Native（tag 才跑）──────────────────────────────
build-native:
  stage: build
  only:
    - /^v\d+\.\d+\.\d+$/    # 只在 semver tag
  services:
    - docker:dind
  script:
    - |
      ./mvnw package -Pnative -DskipTests \
        -Dquarkus.native.container-build=true \
        -Dquarkus.container-image.build=true \
        -Dquarkus.container-image.push=true \
        -Dquarkus.container-image.tag=$CI_COMMIT_TAG-native

Maven 依賴 Cache 最佳實踐

yaml · GitHub Actions Maven cache
- uses: actions/setup-java@v4
  with:
    java-version: '21'
    distribution: temurin
    # 內建 Maven cache，以 pom.xml 作為 cache key
    cache: maven
✓
Cache 策略
  • actions/setup-java 的 cache: maven 自動以 pom.xml hash 作 key
  • Testcontainers image：CI runner 重用，但 Docker layer cache 通常不跨 job
  • Quarkus build cache：target/ 可 cache，但 artifact 通常重建比 restore 快

Secrets 管理

⚠
不要把 secrets 寫在 YAML
  • Registry credential → GitHub Secrets / GitLab CI/CD Variables
  • DB password → 不應出現在 CI，用 Dev Services 或 Testcontainers
  • API key → GitHub Secrets + env variable 注入
  • Production secret → Vault / AWS SSM / K8s Secret（GitOps 管理）

本章小結

  • CI/CD 分三層：PR（快速測試）→ main（build + push）→ tag/nightly（native + E2E）。
  • GitHub Actions：actions/setup-java cache: maven 自動 cache；GITHUB_TOKEN 推 GHCR；Permissions 控制最小化。
  • GitLab CI：services: docker:dind；$CI_REGISTRY 系列變數；artifact reports 發布測試結果。
  • Native build 只在 release tag 或 nightly 跑 ── 太慢不適合每個 PR。
  • Container image 推到 registry 後，用 GitOps（ArgoCD） 更新 K8s manifest，ArgoCD 自動同步。
  • Secrets：Registry credential 放 CI secrets；DB 用 Dev Services；生產 secrets 走 Vault / K8s Secret。
