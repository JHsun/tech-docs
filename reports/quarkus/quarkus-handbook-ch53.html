自訂 Configuration：Config Source 與 Converter

MicroProfile Config 不只能讀 application.properties ── 它有完整的 Config Source 層級機制，讓你從環境變數、Vault、資料庫、Kubernetes ConfigMap 讀取設定。本章講透 Config Source priority、自訂 Converter、@ConfigMapping（型別安全群組設定），以及如何在程式碼裡動態讀取設定而不是只能用 @ConfigProperty。

版本 Quarkus 3.33 LTS · MicroProfile Config 3.x · SmallRye Config 3.x
預估閱讀 22 分鐘
更新 2026-05-16

Config Source 優先序

MicroProfile Config 把所有設定來源抽象為 ConfigSource，每個來源有 ordinal（數字越大優先序越高）。後覆蓋前：

Config Source預設 ordinal範例
System properties（-Dkey=val）400CLI 覆寫
Environment variables300K8s Secret 注入
.env 檔（dev 用）295本地秘密
application.properties250主設定檔
Kubernetes ConfigMap（quarkus-kubernetes-config）270K8s 外部化
Vault（quarkus-vault）高（可設定）Secrets 管理
ℹ︎
環境變數命名轉換
quarkus.datasource.jdbc.url 可以用環境變數 QUARKUS_DATASOURCE_JDBC_URL 覆寫 ── dot 換 underscore、大寫。K8s Secret 注入環境變數時自動適用。

@ConfigMapping：型別安全設定群組

多個相關設定用 @ConfigProperty 一個個注入很醜且難測試。@ConfigMapping 把它們群組成介面：

Java
import io.smallrye.config.ConfigMapping;
import io.smallrye.config.WithDefault;
import java.util.Optional;

@ConfigMapping(prefix = "payment.gateway")
public interface PaymentGatewayConfig {

    String url();
    String apiKey();

    @WithDefault("30s")
    String timeout();

    Optional<String> proxyHost();

    // 巢狀 group
    Retry retry();

    interface Retry {
        @WithDefault("3")
        int maxAttempts();
        @WithDefault("200ms")
        String delay();
    }
}

// application.properties
// payment.gateway.url=https://api.stripe.com
// payment.gateway.api-key=sk_live_xxx
// payment.gateway.retry.max-attempts=5
Java · 注入與使用
@ApplicationScoped
public class PaymentService {

    @Inject PaymentGatewayConfig config;

    public Receipt charge(Order order) {
        // 型別安全存取
        String url = config.url();
        int maxRetries = config.retry().maxAttempts();
        // ...
    }
}

// 測試時可以用 @QuarkusTest + application.properties 覆寫
// 或用 QuarkusTestProfile 設不同值

自訂 ConfigSource

Java · 從資料庫讀設定
import org.eclipse.microprofile.config.spi.ConfigSource;
import java.util.Map;
import java.util.Set;

public class DatabaseConfigSource implements ConfigSource {

    // 注意：ConfigSource 很早初始化，CDI 不可用，需要自行建立 JDBC 連線
    private final Map<String, String> values;

    public DatabaseConfigSource() {
        this.values = loadFromDatabase();
    }

    private Map<String, String> loadFromDatabase() {
        // 直接 JDBC，不能用 @Inject
        try (var conn = DriverManager.getConnection(
                System.getenv("DB_URL"), ...)) {
            // SELECT key, value FROM app_config WHERE active = true
            // ...
        }
    }

    @Override public Map<String, String> getProperties() { return values; }
    @Override public Set<String> getPropertyNames() { return values.keySet(); }
    @Override public String getValue(String key) { return values.get(key); }
    @Override public String getName() { return "DatabaseConfigSource"; }
    @Override public int getOrdinal() { return 200; }  // 低於 env var，高於 properties
}

// 在 META-INF/services/org.eclipse.microprofile.config.spi.ConfigSource 中宣告：
// com.example.config.DatabaseConfigSource

自訂 Converter

MicroProfile Config 內建轉換 String → int、boolean、Duration 等。自訂型別需要 Converter：

Java
import org.eclipse.microprofile.config.spi.Converter;

public class RegionConverter implements Converter<Region> {
    @Override
    public Region convert(String value) {
        return switch (value.toLowerCase()) {
            case "us-east", "use1" -> Region.US_EAST_1;
            case "eu-west", "euw1" -> Region.EU_WEST_1;
            case "ap-east", "ape1" -> Region.AP_EAST_1;
            default -> throw new IllegalArgumentException(
                "Unknown region: " + value);
        };
    }
}

// 宣告：META-INF/services/org.eclipse.microprofile.config.spi.Converter
// com.example.config.RegionConverter

// 使用
@ConfigProperty(name = "aws.region")
Region region;

設定值驗證

Java · Bean Validation 在 @ConfigMapping
@ConfigMapping(prefix = "http.server")
@Validated    // 觸發 Bean Validation
public interface HttpServerConfig {

    @Min(80) @Max(65535)
    int port();

    @NotBlank
    String host();

    @Min(1) @Max(1000)
    int maxConnections();

    @Pattern(regexp = "https?://.*")
    String baseUrl();
}

驗證失敗在 application 啟動時就報錯，不會等到 runtime 才發現設定錯誤。

動態讀取設定

Java
import org.eclipse.microprofile.config.Config;
import org.eclipse.microprofile.config.ConfigProvider;

@ApplicationScoped
public class FeatureFlagService {

    // 每次呼叫時動態讀（適合 feature flag，可能會改變）
    public boolean isEnabled(String feature) {
        Config config = ConfigProvider.getConfig();
        return config.getOptionalValue("feature." + feature, Boolean.class)
            .orElse(false);
    }

    // 也可以 @Inject
    @Inject Config config;

    public Optional<String> getRaw(String key) {
        return config.getOptionalValue(key, String.class);
    }
}

本章小結

  • Config Source 有 ordinal 優先序：System properties（400）> Env vars（300）> application.properties（250）。
  • @ConfigMapping：型別安全設定群組，支援巢狀、Optional、預設值，比散落的 @ConfigProperty 更易維護。
  • 自訂 ConfigSource：實作 ConfigSource 介面，在 META-INF/services 宣告 ── 可從任何來源讀設定。
  • 自訂 Converter：把 String 轉成自訂型別（Region、Duration、URL），在 META-INF/services 宣告。
  • Bean Validation + @Validated：啟動時驗證設定值，fail-fast。
  • 動態讀取：ConfigProvider.getConfig().getOptionalValue() 適合 feature flag 等可能動態變化的設定。
