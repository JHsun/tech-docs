測試基礎：@QuarkusTest 與 RestAssured

測試是 Quarkus 的一等公民 ── 不是附加功能，而是核心工作流程。 @QuarkusTest 在同一個 JVM 內啟動真正的應用，Dev Services 自動起 DB / Kafka / Redis， 讓你寫的 test 既真實又快速。本章從最基礎的 @QuarkusTest + RestAssured 開始， 涵蓋 @InjectMock（Mockito CDI 整合）、@TestHTTPEndpoint、 @QuarkusTestProfile（多設定場景），以及讓你存 partial mock 的 @Spy。 所有範例都接在 catalog-service 貫穿專案上。

@QuarkusTest 的差異化

特性@QuarkusTest傳統 @SpringBootTest
啟動速度快（build-time 已完成大部分初始化）慢（runtime 掃描）
DB / Kafka 等外部依賴Dev Services 自動啟容器需手動配置 Testcontainers
Test 與 App 在同 JVM✅（可注入 CDI bean）✅（有 context）
Native Image 測試✅（@QuarkusIntegrationTest）有限
Continuous Testing✅ 內建（dev 模式按 r）需外部工具

第一個 @QuarkusTest

Java · ProductResourceTest.java
import io.quarkus.test.junit.QuarkusTest;
import io.restassured.RestAssured;
import org.junit.jupiter.api.Test;
import static io.restassured.RestAssured.given;
import static org.hamcrest.Matchers.*;

@QuarkusTest            // ← 啟動完整 Quarkus app（含 Dev Services）
class ProductResourceTest {

    @Test
    void listProducts_shouldReturn200WithList() {
        given()
            .when().get("/api/products")
            .then()
                .statusCode(200)
                .contentType("application/json")
                .body("$.size()", greaterThan(0))
                .body("[0].name", not(emptyString()));
    }

    @Test
    void getProduct_notFound_shouldReturn404() {
        given()
            .when().get("/api/products/99999")
            .then()
                .statusCode(404);
    }

    @Test
    void createProduct_shouldReturn201() {
        given()
            .contentType("application/json")
            .body("""
                {
                    "name": "Test Product",
                    "price": 29.99,
                    "category": "electronics"
                }
                """)
            .when().post("/api/products")
            .then()
                .statusCode(201)
                .header("Location", containsString("/api/products/"))
                .body("id", notNullValue())
                .body("name", equalTo("Test Product"));
    }
}
✓
Dev Services 自動處理外部依賴
如果你的 application.properties 沒有設 DB 連線，Dev Services 會在測試執行前自動用 Testcontainers 啟一個 PostgreSQL。
你不需要寫任何 container 初始化程式碼。

@TestHTTPEndpoint：省去路徑硬編

Java
import io.quarkus.test.common.http.TestHTTPEndpoint;
import io.quarkus.test.junit.QuarkusTest;

@QuarkusTest
@TestHTTPEndpoint(ProductResource.class)   // ← 自動解析 @Path("/api/products")
class ProductResourceTest {

    @Test
    void listProducts() {
        given()
            .when().get()                  // ← 不需要寫 "/api/products"
            .then().statusCode(200);
    }

    @Test
    void getById() {
        given()
            .pathParam("id", 1L)
            .when().get("/{id}")
            .then().statusCode(200);
    }
}

@InjectMock：Mockito CDI 整合

當你想隔離外部依賴（Payment gateway、外部 REST client），用 @InjectMock 把真實 CDI bean 換成 Mockito mock：

Java · 隔離外部 Payment client
import io.quarkus.test.InjectMock;
import org.mockito.Mockito;

@QuarkusTest
class OrderServiceTest {

    @InjectMock                              // ← 替換 CDI context 中的 bean
    PaymentGatewayClient paymentClient;

    @Inject
    OrderService orderService;               // ← 注入真實的 OrderService

    @Test
    void placeOrder_paymentSuccess_shouldCreateOrder() {
        // given
        Mockito.when(paymentClient.charge(Mockito.any()))
            .thenReturn(new PaymentResult("APPROVED", "txn-123"));

        // when
        Order result = orderService.placeOrder(new CreateOrderRequest("prod-1", 2));

        // then
        Assertions.assertNotNull(result.id());
        Assertions.assertEquals("CONFIRMED", result.status());
        Mockito.verify(paymentClient).charge(Mockito.any());
    }

    @Test
    void placeOrder_paymentDeclined_shouldThrow() {
        Mockito.when(paymentClient.charge(Mockito.any()))
            .thenThrow(new PaymentDeclinedException("INSUFFICIENT_FUNDS"));

        Assertions.assertThrows(
            PaymentDeclinedException.class,
            () -> orderService.placeOrder(new CreateOrderRequest("prod-1", 2))
        );
    }
}
⚠
@InjectMock 與 @ApplicationScoped 的注意
@InjectMock 替換的是 CDI context 中的 bean proxy。
若目標 bean 是 @ApplicationScoped，mock 是全局的 ── 不同 test method 之間要確保 Mockito.reset() 或用 @BeforeEach 重設。
Quarkus 的 quarkus-junit5-mockito 在每個 @Test 後自動重設 mock，所以通常不需要手動 reset。

@Spy：部分 mock

Java · @Spy 只覆寫特定方法
import io.quarkus.test.junit.mockito.InjectSpy;

@QuarkusTest
class PricingServiceTest {

    @InjectSpy           // ← 真實 bean，但可以 stub 特定方法
    PricingService pricingService;

    @Test
    void calculate_withStubbedExternalRate() {
        // 只 stub 呼叫外部匯率 API 的方法
        Mockito.doReturn(new ExchangeRate("USD", 31.5))
            .when(pricingService).getExchangeRate("USD");

        // 其餘邏輯仍用真實實作
        Price result = pricingService.calculate("prod-1", "USD");
        Assertions.assertNotNull(result);
    }
}

@QuarkusTestProfile：多組設定

不同測試場景可能需要不同設定（啟用特定 feature flag、換 datasource）。用 @QuarkusTestProfile：

Java · 定義 Profile
import io.quarkus.test.junit.QuarkusTestProfile;
import java.util.Map;

public class PremiumFeatureProfile implements QuarkusTestProfile {

    @Override
    public Map<String, String> getConfigOverrides() {
        return Map.of(
            "feature.premium.enabled", "true",
            "order.discount.max-pct", "50"
        );
    }

    @Override
    public String getConfigProfile() {
        return "test-premium";     // 使用 %test-premium.* properties
    }
}
Java · 使用 Profile
import io.quarkus.test.junit.TestProfile;

@QuarkusTest
@TestProfile(PremiumFeatureProfile.class)
class PremiumOrderTest {

    @Test
    void placeOrder_premiumDiscount_applied() {
        // 在這個 test class 中 feature.premium.enabled=true
        given()
            .body(orderJson)
            .when().post("/api/orders")
            .then()
                .statusCode(201)
                .body("discount_pct", greaterThan(0));
    }
}

// 不同 profile 的 test 類別在各自獨立的 Quarkus 實例中執行
// 同一 profile 的 test 類別共用同一個 Quarkus 實例（速度快）
ℹ︎
Test 執行模型
同一個 @QuarkusTestProfile（含預設）的所有 test class → 共用一個 Quarkus 實例（啟動一次）
不同 profile → 各自啟動一個 Quarkus 實例。
所以 profile 越多 = 啟動次數越多 = 測試整體越慢。盡量合併同場景的 test。

測試中的 @Transactional

Java · 測試資料清理
@QuarkusTest
class OrderRepositoryTest {

    @Inject OrderRepository repo;

    @Test
    @Transactional             // ← 測試後自動 rollback（JUnit 5 + Quarkus 整合）
    void save_shouldPersistOrder() {
        Order o = new Order("cust-1", List.of(new OrderItem("prod-1", 2)));
        repo.persist(o);

        Order found = repo.findById(o.id);
        Assertions.assertNotNull(found);
        Assertions.assertEquals("cust-1", found.customerId);
    }
}
⚠
@Transactional 在 @QuarkusTest 不會自動 rollback
與 Spring 的 @Transactional rollback 行為不同，Quarkus 的 @Transactional 在 test 中 會真正 commit。
要達到 rollback 效果有兩個選擇：
1. 每個 test 前後用 @BeforeEach/@AfterEach 清資料
2. 用 @QuarkusTestResource 搭配 Testcontainers，每個 test class 重建 DB（下一章）

RestAssured 常用技巧

Java · 完整 RestAssured 示範
@QuarkusTest
class AdvancedRestAssuredTest {

    @Test
    void testWithAuth() {
        given()
            .auth().oauth2("test-token")          // Bearer token
            .header("X-Request-Id", "test-123")
            .queryParam("page", 0)
            .queryParam("size", 10)
            .when().get("/api/orders")
            .then()
                .statusCode(200)
                .body("content.size()", lessThanOrEqualTo(10))
                .body("totalElements", greaterThanOrEqualTo(0));
    }

    @Test
    void testWithJsonBody() {
        var id = given()
            .contentType("application/json")
            .body(Map.of("name", "Widget", "price", 9.99))
            .when().post("/api/products")
            .then().statusCode(201)
            .extract().path("id");              // 提取回傳的 id

        // 用提取的 id 做後續操作
        given()
            .when().get("/api/products/" + id)
            .then().statusCode(200)
            .body("name", equalTo("Widget"));
    }

    @Test
    void testResponseSchema() {
        given()
            .when().get("/api/products/1")
            .then()
                .statusCode(200)
                .body(matchesJsonSchemaInClasspath("schemas/product.json"));  // JSON Schema 驗證
    }
}

貫穿專案進度：catalog-service 測試範例

Java · ProductResourceTest（完整）
package com.example.catalog;

import io.quarkus.test.common.http.TestHTTPEndpoint;
import io.quarkus.test.junit.QuarkusTest;
import io.quarkus.test.InjectMock;
import org.junit.jupiter.api.*;
import org.mockito.Mockito;
import java.util.List;

import static io.restassured.RestAssured.given;
import static org.hamcrest.Matchers.*;

@QuarkusTest
@TestHTTPEndpoint(ProductResource.class)
@TestMethodOrder(MethodOrderer.OrderAnnotation.class)
class ProductResourceTest {

    @InjectMock
    InventoryClient inventoryClient;

    @BeforeEach
    void setUp() {
        Mockito.when(inventoryClient.checkStock(Mockito.anyString()))
            .thenReturn(new Stock("AVAILABLE", 100));
    }

    @Test
    @Order(1)
    void list_shouldReturnPagedResult() {
        given()
            .queryParam("page", 0).queryParam("size", 5)
            .when().get()
            .then()
                .statusCode(200)
                .body("content", hasSize(lessThanOrEqualTo(5)))
                .body("page.number", equalTo(0));
    }

    @Test
    @Order(2)
    void create_validProduct_shouldReturn201() {
        given()
            .contentType("application/json")
            .body("""
                {"name":"Keyboard","price":149.00,"categoryId":1}
                """)
            .when().post()
            .then()
                .statusCode(201)
                .body("id", greaterThan(0))
                .body("name", equalTo("Keyboard"))
                .body("stock.status", equalTo("AVAILABLE"));
    }

    @Test
    @Order(3)
    void getById_notFound_shouldReturn404WithProblemJson() {
        given()
            .when().get("/{id}", 99999L)
            .then()
                .statusCode(404)
                .contentType("application/problem+json")
                .body("title", equalTo("Not Found"))
                .body("detail", containsString("99999"));
    }
}

常見陷阱

症狀原因解法
@Inject 在 test 中拿到 null沒加 @QuarkusTest確認加了 @QuarkusTest；純 unit test 用 Mockito 不需要 CDI
測試資料殘留影響其他 test@Transactional 不 rollback@BeforeEach 清資料，或用 Testcontainers 每次重建 DB（ch42）
多 @QuarkusTestProfile 測試很慢每個 profile 重啟 Quarkus合併同場景 test 到同一 profile，減少啟動次數
@InjectMock 不生效沒加 quarkus-junit5-mockito 依賴加 <artifactId>quarkus-junit5-mockito</artifactId>
RestAssured baseURI 錯誤port 不對Quarkus 自動設 RestAssured.baseURI ── 不需手動設；確認用 given().when().get(path) 不是 new URL(...)
Dev Services 啟動失敗沒有 Docker安裝 Docker / Podman；或配置真實 DB connection 讓 Dev Services 跳過

本章小結

  • @QuarkusTest：啟動完整 Quarkus app（含 CDI / Dev Services），在同一 JVM 執行 test ── 真實、快速。
  • Dev Services 自動啟 DB / Kafka 等依賴 container，無需手動配置。
  • RestAssured：流式 API 測試 HTTP endpoint；given().when().then() 三段式。
  • @TestHTTPEndpoint：自動解析 @Path，消除路徑字串硬編。
  • @InjectMock：把 CDI bean 替換成 Mockito mock，隔離外部依賴；每個 @Test 後自動重設。
  • @InjectSpy：真實 bean + 可以 stub 特定方法（partial mock）。
  • @QuarkusTestProfile：不同場景的設定組合；同 profile 共用 Quarkus 實例，節省啟動時間。
  • @Transactional 在 test 中 不自動 rollback ── 需自行清理測試資料。
  • 測試金字塔：大多數 test 用 @QuarkusTest（快）；少數用 @QuarkusIntegrationTest（真實，下一章）。
