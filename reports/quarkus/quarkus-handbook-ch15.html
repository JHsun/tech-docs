Hibernate ORM 與 Jakarta Persistence

REST API 寫完了，但回傳的是寫死的測試資料 ── 此時資料庫該登場。Quarkus 整合 Hibernate ORM 6 + Agroal 連線池 + Jakarta Persistence 標準， 透過 build-time 預先掃描 entity 與優化 metadata，讓啟動快、記憶體少、native image 也能跑。 本章是 Part IV 的地基，後面 Panache、Reactive、Transactions 都建立在此之上。

ℹ︎
Quarkus 的關鍵差異
與傳統 Spring Boot 不同，Quarkus 把大量 Hibernate 初始化工作移到 build time：entity 掃描、JPQL 解析、Connection metadata、dialect 決定。 成果是啟動快 5–10 倍、記憶體少一半、能 compile 成 native image。代價是 entity class 與 query 在編譯期就需要固定。

⚠
連線池大小選擇
常見誤區：「連線越多越快」。實際上連線池大小應該遠小於業務併發。經驗值： max-size = vCPU 數 × 2 + 1（取自《High Performance Java Persistence》）。 16 個連線通常能服務數千 RPS，因為每個 query 只佔用連線數毫秒。 開太大反而拖累 DB（context switch、lock 競爭）。

第一個 Entity

Java · Product entity
import jakarta.persistence.*;
import java.math.BigDecimal;
import java.time.Instant;

@Entity
@Table(name = "products")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String name;

    @Column(name = "sku", unique = true, length = 20)
    private String sku;

    @Column(nullable = false, precision = 10, scale = 2)
    private BigDecimal price;

    @Lob
    private String description;

    @Column(name = "created_at", updatable = false)
    private Instant createdAt;

    @Version
    private Long version;            // 樂觀鎖

    @PrePersist
    void onCreate() {
        this.createdAt = Instant.now();
    }

    // getters/setters 省略
}
✓
關鍵註解一覽
  • @Entity ── 標示為 JPA 實體
  • @Table(name=...) ── 對應資料表名（不寫則用 class 名）
  • @Id ── 主鍵
  • @GeneratedValue ── 自動產生 ID（IDENTITY、SEQUENCE、UUID）
  • @Column ── 控制欄位名、長度、可空性、唯一性
  • @Version ── 樂觀鎖版本欄位
  • @PrePersist / @PreUpdate ── 生命週期 callback

Schema Management 策略

application.properties
quarkus.hibernate-orm.database.generation=...
策略行為適用
none不動 schemaschema 由 Flyway/Liquibase 管（第 19 章）
validate啟動時驗證 entity vs schema 一致生產環境推薦
update自動加欄位／表（不刪）個人開發，不建議生產
create啟動時 drop + create整合測試
drop-and-create同上，更明確整合測試
⚠
生產絕對不要 update / create
update 看似方便但會「悄悄」改 schema、失控加 column；create 會清光生產資料。 生產 schema 永遠由顯式 migration 工具（Flyway/Liquibase）管理，Hibernate 端設 validate 確認應用 entity 與 DB 對齊。

EntityManager：核心 API

Java · 基本 CRUD
import jakarta.enterprise.context.ApplicationScoped;
import jakarta.inject.Inject;
import jakarta.persistence.EntityManager;
import jakarta.transaction.Transactional;

@ApplicationScoped
public class ProductRepository {

    @Inject EntityManager em;

    @Transactional
    public Product create(Product p) {
        em.persist(p);                  // INSERT
        return p;                       // ID 已填回
    }

    public Product findById(Long id) {
        return em.find(Product.class, id);   // SELECT by PK
    }

    @Transactional
    public Product update(Long id, BigDecimal newPrice) {
        Product p = em.find(Product.class, id);
        p.setPrice(newPrice);           // 不需呼叫 update！
        return p;                       // 交易結束時自動 flush
    }

    @Transactional
    public void delete(Long id) {
        Product p = em.find(Product.class, id);
        em.remove(p);
    }
}
✓
「Managed Entity」的魔法
第 13 行 p.setPrice(newPrice) 後沒呼叫 em.merge() 或 em.update()， 但 UPDATE 還是會發 ── 因為 em.find() 取出的 entity 處於 managed 狀態， JPA 在交易結束（commit）時自動偵測變動並 flush。這叫「dirty checking」，省去大量樣板程式。

Entity 的三種狀態

stateDiagram-v2
  [*] --> Transient: new Product
  Transient --> Managed: em.persist
  Managed --> Detached: em.detach / 交易結束
  Detached --> Managed: em.merge
  Managed --> Removed: em.remove
  Removed --> [*]: 交易 commit

交易管理：@Transactional

Quarkus 用 Jakarta Transactions（前身 JTA）實作交易，最簡單的方式是 @Transactional：

Java · 業務 service 使用交易
@ApplicationScoped
public class OrderService {

    @Inject EntityManager em;
    @Inject ProductRepository products;

    @Transactional       // 整個方法在同一個交易
    public Order placeOrder(CreateOrderRequest req) {
        Product p = products.findById(req.productId());
        if (p.getStock() < req.quantity()) {
            throw new InsufficientStockException();
        }
        p.setStock(p.getStock() - req.quantity());
        Order order = new Order(p, req.quantity());
        em.persist(order);
        return order;
    }
}

傳播行為

類型意義
REQUIRED（預設）有交易就加入，沒有則開新
REQUIRES_NEW暫停外層，必開新交易（如審計日誌）
MANDATORY必須在交易內，否則拋例外
SUPPORTS有就用、沒就無交易執行
NOT_SUPPORTED暫停現有交易（read-only 查詢加速）
NEVER必須無交易，否則拋例外
⚠
Rollback 規則
@Transactional 預設只在 unchecked exception（RuntimeException 或 Error）發生時 rollback。 若要 checked exception 也 rollback：@Transactional(rollbackOn = MyCheckedException.class)。 生產上強烈建議用 unchecked exception 代表業務錯誤。

JPQL：物件導向的查詢語言

JPQL 寫的是entity 與 field 名，不是 table 與 column：

Java · JPQL 查詢
// 1. 簡單 list
List<Product> all = em.createQuery(
    "SELECT p FROM Product p ORDER BY p.name", Product.class)
    .getResultList();

// 2. 帶參數
List<Product> expensive = em.createQuery(
    "SELECT p FROM Product p WHERE p.price > :min", Product.class)
    .setParameter("min", new BigDecimal("100"))
    .getResultList();

// 3. 投影 DTO（避免抓整顆 entity）
List<ProductSummary> summaries = em.createQuery("""
    SELECT new com.example.ProductSummary(p.id, p.name, p.price)
    FROM Product p
    WHERE p.price > :min
    """, ProductSummary.class)
    .setParameter("min", new BigDecimal("100"))
    .getResultList();

// 4. 分頁
List<Product> page = em.createQuery(
    "SELECT p FROM Product p ORDER BY p.id", Product.class)
    .setFirstResult(0)
    .setMaxResults(20)
    .getResultList();

// 5. 單筆結果（找不到拋 NoResultException）
Product single = em.createQuery(
    "SELECT p FROM Product p WHERE p.sku = :sku", Product.class)
    .setParameter("sku", "WID-000001")
    .getSingleResult();

NamedQuery：把 query 與 entity 放一起

Java · NamedQuery 範例
@Entity
@NamedQueries({
    @NamedQuery(name = "Product.findBySku",
                query = "SELECT p FROM Product p WHERE p.sku = :sku"),
    @NamedQuery(name = "Product.countByPriceRange",
                query = "SELECT COUNT(p) FROM Product p WHERE p.price BETWEEN :min AND :max")
})
public class Product { /* ... */ }

// 使用
Product p = em.createNamedQuery("Product.findBySku", Product.class)
    .setParameter("sku", "WID-000001")
    .getSingleResult();

好處：Quarkus 在 build time 驗證 query 語法。如果 query 有錯，build 就 fail，而不是 runtime 才爆炸。

Criteria API：型別安全查詢

JPQL 是字串，IDE 沒辦法檢查欄位拼字。Criteria 是程式化建構 query：

Java · Criteria 動態查詢
import jakarta.persistence.criteria.*;

public List<Product> search(String nameLike, BigDecimal minPrice, BigDecimal maxPrice) {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<Product> cq = cb.createQuery(Product.class);
    Root<Product> root = cq.from(Product.class);

    List<Predicate> predicates = new ArrayList<>();
    if (nameLike != null) {
        predicates.add(cb.like(cb.lower(root.get("name")), "%" + nameLike.toLowerCase() + "%"));
    }
    if (minPrice != null) {
        predicates.add(cb.greaterThanOrEqualTo(root.get("price"), minPrice));
    }
    if (maxPrice != null) {
        predicates.add(cb.lessThanOrEqualTo(root.get("price"), maxPrice));
    }
    cq.where(predicates.toArray(new Predicate[0]));
    cq.orderBy(cb.asc(root.get("name")));

    return em.createQuery(cq).getResultList();
}

適合動態組合條件的搜尋場景。寫死 query 用 JPQL 就好。

Native SQL：脫離 ORM

有些情境（複雜分析、PostgreSQL JSONB 操作、效能極限調校）超出 JPQL 能力，就 fallback 到 native SQL：

Java · Native SQL
// 回傳 entity
List<Product> results = em.createNativeQuery("""
    SELECT * FROM products
    WHERE to_tsvector('chinese', name) @@ to_tsquery(:q)
    """, Product.class)
    .setParameter("q", "widget")
    .getResultList();

// 回傳 Object[]（自訂欄位）
List<Object[]> rows = em.createNativeQuery("""
    SELECT category, COUNT(*), AVG(price)
    FROM products GROUP BY category
    """).getResultList();

// 使用 @SqlResultSetMapping 對映到 DTO

關聯：@OneToMany、@ManyToOne 等

Java · 雙向 One-to-Many
@Entity
public class Category {
    @Id @GeneratedValue Long id;
    String name;

    @OneToMany(mappedBy = "category", fetch = FetchType.LAZY)
    List<Product> products = new ArrayList<>();
}

@Entity
public class Product {
    @Id @GeneratedValue Long id;
    String name;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "category_id")
    Category category;
}

Fetch 策略：LAZY 還是 EAGER？

⚠
永遠 LAZY，除非有強烈理由
FetchType.EAGER 會在每次 load entity 時都自動 JOIN 關聯表，無法控制。看似方便，但常導致：
  • 抓回大量不需要的資料（網路 + 記憶體浪費）
  • 無法用 fetch join 精確控制
  • 傳遞性 EAGER：A → B → C 一次全抓
所有 @ManyToOne / @OneToMany / @OneToOne 都用 LAZY，再依需求用 JOIN FETCH 顯式抓。

N+1 問題與解法

最經典的 ORM 陷阱：

Java · ❌ N+1 範例
// ❌ 這段 code 會跑 1 次 + N 次 SQL
List<Product> products = em.createQuery("SELECT p FROM Product p", Product.class).getResultList();
for (Product p : products) {
    System.out.println(p.getCategory().getName());   // ← 每次都觸發一次 SELECT category
}

100 個產品 = 1 + 100 = 101 次 SQL。解法：

方式 A：JOIN FETCH

Java · JOIN FETCH
// ✓ 1 次 SQL 帶回 product + category
List<Product> products = em.createQuery("""
    SELECT p FROM Product p JOIN FETCH p.category
    """, Product.class).getResultList();

方式 B：EntityGraph

Java · EntityGraph
EntityGraph<?> graph = em.createEntityGraph(Product.class);
graph.addAttributeNodes("category", "tags");

List<Product> products = em.createQuery("SELECT p FROM Product p", Product.class)
    .setHint("jakarta.persistence.fetchgraph", graph)
    .getResultList();

方式 C：批次抓取（@BatchSize）

Java
@Entity
public class Product {
    @ManyToOne(fetch = FetchType.LAZY)
    @org.hibernate.annotations.BatchSize(size = 20)    // 一次批 20 個
    Category category;
}

二級快取

Hibernate 二級快取（second-level cache）跨 session 共享 entity 物件，大幅減少 DB 查詢。Quarkus 內建支援：

application.properties
quarkus.hibernate-orm.second-level-caching-enabled=true
quarkus.hibernate-orm.cache."com.example.Product".expiration.max-idle=10M
quarkus.hibernate-orm.cache."com.example.Product".memory.object-count=1000
Java · 標記 entity 可快取
import jakarta.persistence.Cacheable;
import org.hibernate.annotations.Cache;
import org.hibernate.annotations.CacheConcurrencyStrategy;

@Entity
@Cacheable
@Cache(usage = CacheConcurrencyStrategy.READ_WRITE)
public class Product { /* ... */ }
ℹ︎
何時用二級快取
適合：讀多寫少、變動頻率低的 entity（國家清單、設定、不常改的產品 metadata）。 不適合：高頻變更、嚴格一致性要求、整個應用就一個 read replica。 多 Pod 環境要小心：每個 Pod 有自己的本地快取，可能不一致；需配置分散式快取（如 Infinispan）。

命名策略：Java vs SQL

Java 慣用 camelCase（createdAt），SQL 慣用 snake_case（created_at）。Hibernate 預設不轉換，逐個寫 @Column(name="created_at") 累。

application.properties
# 自動 camelCase → snake_case
quarkus.hibernate-orm.physical-naming-strategy=org.hibernate.boot.model.naming.CamelCaseToUnderscoresNamingStrategy

之後 private Instant createdAt; 自動對映到 created_at 欄位。

貫穿專案進度：catalog-service 接上資料庫

Java · 完整 Product entity
@Entity
@Table(name = "products", indexes = {
    @Index(name = "idx_products_sku", columnList = "sku"),
    @Index(name = "idx_products_category", columnList = "category_id")
})
public class Product {

    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String name;

    @Column(unique = true, length = 20)
    private String sku;

    @Column(nullable = false, precision = 10, scale = 2)
    private BigDecimal price;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "category_id")
    private Category category;

    @Column(name = "created_at", updatable = false, nullable = false)
    private Instant createdAt;

    @Column(name = "updated_at")
    private Instant updatedAt;

    @Version
    private Long version;

    @PrePersist
    void onCreate() {
        Instant now = Instant.now();
        this.createdAt = now;
        this.updatedAt = now;
    }

    @PreUpdate
    void onUpdate() { this.updatedAt = Instant.now(); }
}

連線池調校原則

✦
Agroal 生產配置 checklist
  • max-size：vCPU × 2，例：4 核心 Pod → 8–10
  • min-size：max 的 25-50%，避免冷啟動
  • acquisition-timeout：3-5s，超時就拋例外（不要無限等）
  • max-lifetime：30M，配合 DB-side timeout（避免 stale connection）
  • idle-removal-interval：5M，清掉閒置連線釋放資源
  • 監控：quarkus.datasource.metrics.enabled=true 暴露 connection pool 指標

常見陷阱

症狀原因解法
LazyInitializationException 交易結束後存取 LAZY 欄位 在交易內用 JOIN FETCH 或 EntityGraph 預載
啟動慢、entity 沒掃到 packages 沒設或 entity 在 jar 內 用 quarkus.index-dependency 索引外部 jar
UPDATE 沒生效 沒包在交易內 方法加 @Transactional
Connection pool 耗盡 慢 query 或交易太長 用 metrics 找出元兇、切短交易、優化 query
主鍵衝突 IDENTITY 在某些 DB 行為不一致 PostgreSQL 用 SEQUENCE，Oracle 12c+ 同
樂觀鎖失敗 OptimisticLockException 多執行緒同時更新 retry 機制 或改悲觀鎖 LockModeType.PESSIMISTIC_WRITE

本章小結

  • Quarkus 整合 Hibernate ORM 6 + Agroal + JDBC driver，build-time 預掃描 entity，啟動快、native 友善。
  • Datasource 三個必填：db-kind、credentials、JDBC URL。Dev 模式可全免（Dev Services）。
  • 連線池大小 ≈ vCPU × 2，不要無腦放大。
  • Entity 用 @Entity + @Id + @GeneratedValue，所有關聯預設 LAZY。
  • EntityManager 三大 API：persist、find、createQuery；managed entity 自動 dirty-check。
  • 交易：@Transactional，預設 REQUIRED，rollback 只對 unchecked exception。
  • 查詢：JPQL（字串）／Criteria（動態組合）／Native SQL（脫離 ORM）。
  • N+1 解法：JOIN FETCH、EntityGraph、@BatchSize。
  • 二級快取：@Cacheable + 配置 second-level-caching-enabled=true。
  • schema-management 生產用 validate，DDL 由 Flyway/Liquibase 管（第 19 章）。
  • 用 CamelCaseToUnderscoresNamingStrategy 自動 camel ↔ snake。
