Helm：多環境部署管理

Kubernetes YAML 管理三個環境（dev / staging / prod）的副本， 三份幾乎一樣只有 replicas、URL、資源限制不同的 YAML ── 這是維護噩夢。 Helm 把 YAML 變成有參數化 values.yaml 的模板， 讓同一份 chart 輕鬆 deploy 到任何環境。Quarkus 提供兩條路： quarkus-helm 擴充（build time 自動生成 chart）和 手寫 Helm chart（完全控制）。本章兩條路都講，再整合 ArgoCD GitOps。

讀者 🔵 開發者 🟠 SRE
版本 Quarkus 3.33 LTS · Helm 3.x · ArgoCD 2.x
預估閱讀 26 分鐘
更新 2026-05-16

為什麼需要 Helm

問題Helm 解法
三個環境三份幾乎一樣的 YAML一個 chart，三個 values 檔案
更新 image tag 要改多個地方values.yaml 只改一個 image.tag
Rollback 沒有版本記錄helm rollback 有完整 release history
複雜 K8s 資源依賴順序Helm hooks 控制順序

方式 A：quarkus-helm 擴充

bash
quarkus extension add helm

build 後在 target/helm/kubernetes/catalog-service/ 生成完整 chart：

bash · 生成的 chart 結構
target/helm/kubernetes/catalog-service/
├── Chart.yaml
├── values.yaml           ← 預設值（Quarkus 自動填）
├── values-dev.yaml       ← dev 覆寫（可自訂）
├── values-prod.yaml      ← prod 覆寫
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    ├── configmap.yaml
    └── hpa.yaml
application.properties · quarkus-helm 設定
# Chart metadata
quarkus.helm.name=catalog-service
quarkus.helm.version=1.4.2
quarkus.helm.description=Catalog microservice for the Quarkus Shop

# values.yaml 的覆寫對應
quarkus.helm.values."image.repository".value=ghcr.io/example-org/catalog-service
quarkus.helm.values."image.tag".value=${quarkus.application.version}

# 多環境值
quarkus.helm.values."replicaCount".value=1
# dev profile
%dev.quarkus.helm.values."replicaCount".value=1
# prod profile
%prod.quarkus.helm.values."replicaCount".value=3
bash · 安裝到叢集
# dev
helm install catalog-service target/helm/kubernetes/catalog-service \
  --namespace catalog-dev --create-namespace \
  -f target/helm/kubernetes/catalog-service/values-dev.yaml

# prod
helm install catalog-service target/helm/kubernetes/catalog-service \
  --namespace catalog-prod --create-namespace \
  -f target/helm/kubernetes/catalog-service/values-prod.yaml

# 升版
helm upgrade catalog-service target/helm/kubernetes/catalog-service \
  --namespace catalog-prod \
  --set image.tag=1.5.0

# 回滾
helm rollback catalog-service 1 --namespace catalog-prod

方式 B：手寫 Helm Chart（完全控制）

yaml · values.yaml（預設值）
replicaCount: 2

image:
  repository: ghcr.io/example-org/catalog-service
  tag: "latest"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 8080
  managementPort: 9000

resources:
  requests:
    cpu: 250m
    memory: 256Mi
  limits:
    cpu: 1000m
    memory: 512Mi

autoscaling:
  enabled: false
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 70

config:
  logLevel: INFO
  dbUrl: jdbc:postgresql://postgres:5432/catalog

ingress:
  enabled: false
  host: catalog.example.com
  tls: true
yaml · values-prod.yaml（prod 覆寫）
replicaCount: 5

image:
  tag: "1.4.2"      # 指定版本，不用 latest

resources:
  requests:
    cpu: 500m
    memory: 512Mi
  limits:
    cpu: 2000m
    memory: 1Gi

autoscaling:
  enabled: true
  minReplicas: 3
  maxReplicas: 20

ingress:
  enabled: true
  host: catalog.prod.example.com

config:
  logLevel: WARN
yaml · templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "catalog.fullname" . }}
  labels:
    {{- include "catalog.labels" . | nindent 4 }}
spec:
  {{- if not .Values.autoscaling.enabled }}
  replicas: {{ .Values.replicaCount }}
  {{- end }}
  selector:
    matchLabels:
      {{- include "catalog.selectorLabels" . | nindent 6 }}
  template:
    spec:
      containers:
      - name: {{ .Chart.Name }}
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
        imagePullPolicy: {{ .Values.image.pullPolicy }}
        ports:
        - containerPort: 8080
          name: http
        - containerPort: 9000
          name: management
        resources:
          {{- toYaml .Values.resources | nindent 10 }}
        env:
        - name: QUARKUS_LOG_LEVEL
          value: {{ .Values.config.logLevel | quote }}
        startupProbe:
          httpGet: { path: /q/health/started, port: 9000 }
          failureThreshold: 30
          periodSeconds: 5
        livenessProbe:
          httpGet: { path: /q/health/live, port: 9000 }
          periodSeconds: 20
          failureThreshold: 3
        readinessProbe:
          httpGet: { path: /q/health/ready, port: 9000 }
          periodSeconds: 10
          failureThreshold: 3

GitOps with ArgoCD

Helm chart 放 GitOps repo，ArgoCD 監控 repo，有 diff 就自動同步：

yaml · ArgoCD Application（catalog-service）
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: catalog-service-prod
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/example-org/gitops-manifests
    targetRevision: HEAD
    path: charts/catalog-service
    helm:
      valueFiles:
        - values-prod.yaml
      parameters:
        - name: image.tag
          value: "1.4.2"      # CI pipeline 更新這個值
  destination:
    server: https://kubernetes.default.svc
    namespace: catalog-prod
  syncPolicy:
    automated:
      prune: true        # 刪掉 K8s 上多餘的資源
      selfHeal: true     # 有人手動改了就自動回到 Git 狀態
    syncOptions:
      - CreateNamespace=true
✓
GitOps 工作流
  1. CI 建 image → push 到 registry（tag = git SHA）
  2. CI 更新 gitops-manifests 的 image.tag（自動 PR 或直接 push）
  3. ArgoCD 偵測到 gitops-manifests 變更
  4. ArgoCD 自動 sync → kubectl apply → 新 Pod 滾動更新
  5. Rollback = 在 gitops-manifests 改回舊 tag 或 git revert
所有部署狀態都在 Git，可 audit、可回滾、可 PR review。

本章小結

  • Helm 解決多環境 YAML 重複問題：一個 chart + 多個 values 檔案。
  • quarkus-helm 擴充：build time 自動生成 chart，適合快速起步。
  • 手寫 Helm chart：模板 + values，對大型團隊更靈活、可 PR review。
  • 核心指令：install / upgrade / rollback / --set 覆寫單一值。
  • ArgoCD GitOps：CI 更新 image tag → gitops-manifests PR → ArgoCD 自動 sync → 零手動 kubectl。
  • selfHeal: true：有人手動改了 K8s 資源，ArgoCD 自動回到 Git 狀態 ── drift 防護。
