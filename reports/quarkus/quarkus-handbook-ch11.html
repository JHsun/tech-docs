Bean Validation 與 OpenAPI

生產級 API 必須做兩件事：驗證輸入、提供文件。Bean Validation（Hibernate Validator）讓你 用註解宣告約束條件，OpenAPI 自動把這些約束、endpoint、DTO 變成機器可讀的合約， 再透過 Swagger UI 變成人類可探索的介面。三者整合後， 你寫一份 Java 程式碼，就同時得到驗證邏輯與完整文件。

為什麼 Validation 與 OpenAPI 該一起學

這兩個主題經常分開教，但 Quarkus 把它們整合得很緊密：你寫的每個 @NotBlank、@Size、@Min， 都會自動反映在 OpenAPI 文件。一份程式碼，三份產出：執行期驗證、文件、客戶端 SDK。

基本驗證

欄位層級約束

Java · Product DTO 加約束
import jakarta.validation.constraints.*;
import java.math.BigDecimal;

public record CreateProductRequest(
    @NotBlank(message = "名稱不可為空")
    @Size(min = 2, max = 100, message = "名稱長度需在 2~100 字之間")
    String name,

    @NotNull
    @DecimalMin(value = "0.01", message = "價格必須大於 0")
    @DecimalMax(value = "999999.99")
    @Digits(integer = 6, fraction = 2)
    BigDecimal price,

    @Size(max = 1000)
    String description,

    @NotEmpty
    @Size(max = 10)
    List<@NotBlank @Size(max = 30) String> tags,

    @Email
    String contactEmail,

    @Future
    LocalDate availableFrom
) {}

常用約束一覽

註解用途
@NotNull不可為 null
@NotEmpty字串、集合、陣列不可為空
@NotBlank字串不可為 null、空、空白
@Size(min, max)長度／大小範圍
@Min(n) / @Max(n)整數範圍
@DecimalMin / @DecimalMax小數範圍
@Positive / @Negative正／負數
@Emailemail 格式
@Pattern(regexp)正規表達式
@Past / @Future日期時間在過去／未來
@Digits(integer, fraction)數字位數
@AssertTrue / @AssertFalse布林值斷言

在 endpoint 觸發驗證

Java · 用 @Valid 觸發
@Path("/products")
public class ProductResource {

    @POST
    public Response create(@Valid CreateProductRequest req) {
        Product p = service.create(req);
        return Response.created(URI.create("/products/" + p.id())).entity(p).build();
    }

    @GET @Path("/{id}")
    public Product get(@Valid @PathParam("id") @Positive Long id) {
        return service.findById(id);
    }

    @GET
    public List<Product> list(
        @QueryParam("page") @Min(0) @DefaultValue("0") int page,
        @QueryParam("size") @Min(1) @Max(100) @DefaultValue("20") int size
    ) {
        return service.list(page, size);
    }
}
✓
何時加 @Valid
  • 方法參數是物件且要驗證物件內欄位 → 加 @Valid
  • 方法參數本身要套約束（PathParam、QueryParam）→ 直接加 @Positive 等，不需 @Valid
  • 物件內部有另一個物件需要遞迴驗證 → 在欄位加 @Valid

處理驗證失敗

驗證失敗時，Quarkus 預設回傳 400 Bad Request + 簡單訊息。對 API 而言，需要更友善的錯誤格式：

Java · 自訂驗證錯誤格式
import jakarta.validation.ConstraintViolationException;
import org.jboss.resteasy.reactive.server.ServerExceptionMapper;

public record ValidationError(String field, String message, Object rejectedValue) {}
public record ErrorResponse(String code, String message, List<ValidationError> errors) {}

public class ValidationExceptionMappers {

    @ServerExceptionMapper
    public RestResponse<ErrorResponse> handle(ConstraintViolationException ex) {
        List<ValidationError> errors = ex.getConstraintViolations().stream()
            .map(v -> new ValidationError(
                lastNode(v.getPropertyPath()),
                v.getMessage(),
                v.getInvalidValue()))
            .toList();
        return RestResponse.status(Response.Status.BAD_REQUEST,
            new ErrorResponse("VALIDATION_FAILED", "輸入驗證失敗", errors));
    }

    private static String lastNode(jakarta.validation.Path p) {
        String full = p.toString();
        int idx = full.lastIndexOf('.');
        return idx >= 0 ? full.substring(idx + 1) : full;
    }
}

$ curl -X POST http://localhost:8080/products \ -H "Content-Type: application/json" \ -d '{"name": "", "price": -1, "tags": []}' HTTP/1.1 400 Bad Request { "code": "VALIDATION_FAILED", "message": "輸入驗證失敗", "errors": [ {"field": "name", "message": "名稱不可為空", "rejectedValue": ""}, {"field": "price", "message": "價格必須大於 0", "rejectedValue": -1}, {"field": "tags", "message": "must not be empty", "rejectedValue": []} ] }

自訂驗證約束

業務規則常常需要自訂約束。範例：驗證產品 SKU 格式（3 個英文字母 + 連字號 + 6 位數字）：

Java · 自訂註解
import jakarta.validation.Constraint;
import jakarta.validation.Payload;
import java.lang.annotation.*;

@Documented
@Constraint(validatedBy = SkuValidator.class)
@Target({ ElementType.FIELD, ElementType.PARAMETER })
@Retention(RetentionPolicy.RUNTIME)
public @interface ValidSku {
    String message() default "SKU 格式錯誤，需為 ABC-123456";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}
Java · Validator 實作
import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;
import java.util.regex.Pattern;

public class SkuValidator implements ConstraintValidator<ValidSku, String> {

    private static final Pattern PATTERN = Pattern.compile("^[A-Z]{3}-\\d{6}$");

    @Override
    public boolean isValid(String value, ConstraintValidatorContext ctx) {
        if (value == null) return true;     // null 由 @NotNull 處理
        return PATTERN.matcher(value).matches();
    }
}
Java · 使用
public record CreateProductRequest(
    @NotNull
    @ValidSku
    String sku,

    @NotBlank String name
) {}

跨欄位驗證

有些規則涉及多個欄位的關係，例如「結束日期不可早於開始日期」。用 class-level constraint：

Java · 跨欄位約束註解
@Constraint(validatedBy = DateRangeValidator.class)
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface ValidDateRange {
    String message() default "結束日期必須晚於開始日期";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

public class DateRangeValidator implements ConstraintValidator<ValidDateRange, Promotion> {
    @Override
    public boolean isValid(Promotion p, ConstraintValidatorContext ctx) {
        if (p.startDate() == null || p.endDate() == null) return true;
        return p.endDate().isAfter(p.startDate());
    }
}

@ValidDateRange
public record Promotion(
    @NotNull LocalDate startDate,
    @NotNull LocalDate endDate,
    @NotBlank String name
) {}

openapi: 3.1.0
info:

OpenAPI 註解強化

自動生成已不錯，加幾個註解可讓文件更專業：

Java · 完整 OpenAPI 註解
import org.eclipse.microprofile.openapi.annotations.*;
import org.eclipse.microprofile.openapi.annotations.media.*;
import org.eclipse.microprofile.openapi.annotations.parameters.*;
import org.eclipse.microprofile.openapi.annotations.responses.*;
import org.eclipse.microprofile.openapi.annotations.tags.Tag;

@Path("/products")
@Tag(name = "Products", description = "產品目錄管理")
public class ProductResource {

    @POST
    @Operation(
        summary = "建立新產品",
        description = "建立並回傳產品。SKU 必須為 ABC-123456 格式且全域唯一。")
    @APIResponses({
        @APIResponse(responseCode = "201", description = "建立成功",
            content = @Content(schema = @Schema(implementation = Product.class))),
        @APIResponse(responseCode = "400", description = "輸入驗證失敗",
            content = @Content(schema = @Schema(implementation = ErrorResponse.class))),
        @APIResponse(responseCode = "409", description = "SKU 重複")
    })
    public Response create(
        @RequestBody(
            description = "新產品資料",
            required = true,
            content = @Content(examples = @ExampleObject(
                name = "basic",
                value = """
                    {"name": "Widget", "price": 9.99, "sku": "WID-000001"}
                    """))
        )
        @Valid CreateProductRequest req) {
        // ...
    }

    @GET @Path("/{id}")
    @Operation(summary = "依 ID 取得產品")
    public Product get(
        @Parameter(description = "產品 ID", example = "42", required = true)
        @PathParam("id") @Positive Long id) {
        return service.findById(id);
    }
}

DTO 加 @Schema 註解

Java · @Schema 強化 DTO 文件
import org.eclipse.microprofile.openapi.annotations.media.Schema;

@Schema(name = "CreateProductRequest", description = "新增產品的請求 payload")
public record CreateProductRequest(
    @Schema(description = "產品名稱", example = "Widget", minLength = 2, maxLength = 100)
    @NotBlank @Size(min = 2, max = 100)
    String name,

    @Schema(description = "單價（美元）", example = "9.99")
    @NotNull @DecimalMin("0.01")
    BigDecimal price,

    @Schema(description = "SKU 編號", example = "WID-000001", pattern = "^[A-Z]{3}-\\d{6}$")
    @ValidSku
    String sku
) {}

Security Schemes

標示 API 需要哪種認證，讓 Swagger UI 顯示「Authorize」按鈕：

Java · 定義 Security Scheme
import org.eclipse.microprofile.openapi.annotations.OpenAPIDefinition;
import org.eclipse.microprofile.openapi.annotations.security.*;

@OpenAPIDefinition(
    info = @Info(title = "Catalog API", version = "1.0"),
    security = @SecurityRequirement(name = "BearerAuth")
)
@SecurityScheme(
    securitySchemeName = "BearerAuth",
    type = SecuritySchemeType.HTTP,
    scheme = "bearer",
    bearerFormat = "JWT"
)
@ApplicationPath("/")
public class CatalogApplication extends Application {}

個別 endpoint 可標 @SecurityRequirement 或 @SecurityRequirementsSet 覆寫全域設定。

使用靜態 OpenAPI 文件

有時候你想先寫合約再寫程式（contract-first），把 OpenAPI YAML 當作 source of truth：

用 OpenAPI 產生客戶端 SDK

OpenAPI 最大價值之一：自動產生多種語言的 client SDK。

    -i openapi.json \
    -g python \
    -o ./catalog-client-py

npx @openapitools/openapi-generator-cli generate \
    -i openapi.json \
    -g go \
    -o ./catalog-client-go
✓
SRE 加值用法
把 SDK 生成放進 CI/CD：服務變更時自動產生新版 SDK 並發到 npm/PyPI 內部 registry， 所有 consumer 服務以 dependency 方式取得最新型別定義，避免「我以為 API 是這樣」的整合 bug。

Contract Testing

OpenAPI 不只是文件，還可以用來檢測 API 變更是否破壞 backward compatibility：

bash · OpenAPI diff
# 用 openapi-diff 工具比較新舊版本
docker run --rm -v $(pwd):/specs openapitools/openapi-diff:latest \
    /specs/openapi-old.yaml /specs/openapi-new.yaml

把這個放進 CI，每次 PR 自動跑 diff，新增的 breaking change（移除欄位、改型別）會 fail build。

貫穿專案進度

把驗證與 OpenAPI 整合到 catalog-service：

Java · 完整生產級 endpoint
@Path("/api/v1/products")
@Tag(name = "Products", description = "產品目錄 CRUD")
@Produces(MediaType.APPLICATION_JSON)
@Consumes(MediaType.APPLICATION_JSON)
@SecurityRequirement(name = "BearerAuth")
public class ProductResource {

    @Inject ProductService service;

    @POST
    @Operation(summary = "建立產品")
    @APIResponses({
        @APIResponse(responseCode = "201", description = "建立成功"),
        @APIResponse(responseCode = "400", description = "輸入驗證失敗"),
        @APIResponse(responseCode = "409", description = "SKU 重複")
    })
    public Response create(@Valid CreateProductRequest req, @Context UriInfo uri) {
        Product p = service.create(req);
        return Response.created(uri.getAbsolutePathBuilder().path("/" + p.id()).build())
            .entity(p).build();
    }

    @GET @Path("/{id}")
    @Operation(summary = "查詢產品", description = "依 ID 取得單一產品")
    @APIResponse(responseCode = "404", description = "產品不存在")
    public Product get(
        @Parameter(description = "產品 ID", example = "42")
        @PathParam("id") @Positive Long id) {
        return service.findById(id)
            .orElseThrow(() -> new ProductNotFoundException(id));
    }

    @GET
    @Operation(summary = "列出產品")
    public PagedResult<Product> list(
        @Parameter(description = "頁碼", example = "0")
        @QueryParam("page") @Min(0) @DefaultValue("0") int page,

        @Parameter(description = "每頁數量", example = "20")
        @QueryParam("size") @Min(1) @Max(100) @DefaultValue("20") int size) {
        return service.list(page, size);
    }
}

@Schema(description = "新增產品的請求")
public record CreateProductRequest(
    @Schema(example = "Widget") @NotBlank @Size(min = 2, max = 100) String name,
    @Schema(example = "9.99") @NotNull @DecimalMin("0.01") BigDecimal price,
    @Schema(example = "WID-000001") @ValidSku String sku,
    @Schema(example = "好用的小工具") @Size(max = 1000) String description
) {}

DevOps / SRE 視角

把 OpenAPI 納入 CI/CD

  1. 每次 build 匯出 spec：quarkus.smallrye-openapi.store-schema-directory=target/openapi
  2. 提交到 spec repo：所有 microservice 的 OpenAPI 集中在一個 repo，方便團隊瀏覽
  3. 跑 openapi-diff：偵測 breaking change，失敗時阻擋 merge
  4. 自動產生 SDK：發到內部 registry，consumer 服務拉取
  5. 配置 API Gateway：Kong、APISIX 可從 OpenAPI 自動配置路由、rate limit、auth

API 版本演進策略

策略實作適用
URL 版本/api/v1 → /api/v2最常見，可控可觀察
Header 版本Accept: application/vnd.example.v2+jsonRESTful 純粹派
新增不破壞只加欄位、新值，從不刪長期演進的核心 API

常見陷阱

症狀原因解法
驗證沒生效 缺 @Valid endpoint 方法參數加 @Valid
自訂 message 沒顯示 用了預設 {...} 引用 確認 message 字串直接寫，或 messages.properties 中 key 正確
Swagger UI 看不到 生產 profile 預設關閉 %prod.quarkus.swagger-ui.always-include=true
OpenAPI 缺少某 endpoint 是 @ServerExceptionMapper 沒寫到 schema 需手動加 @APIResponse
無法用 Swagger 試打需驗證的 API 缺 SecurityScheme 或沒按「Authorize」 加 @SecurityScheme，在 UI 上輸入 token
套用 OpenAPI 註解但不生效 誤用了 io.swagger.v3.oas.annotations 用 MicroProfile 的 org.eclipse.microprofile.openapi.annotations

本章小結

  • Quarkus 整合 Hibernate Validator（Bean Validation 3.0 實作），用註解宣告約束。
  • endpoint 方法參數加 @Valid 觸發 DTO 驗證；參數本身的約束（@Positive 等）直接寫即可。
  • 用 @ServerExceptionMapper 把 ConstraintViolationException 轉成友善錯誤格式。
  • 跨欄位驗證用 class-level constraint；自訂約束 = 註解 + Validator。
  • SmallRye OpenAPI（quarkus-smallrye-openapi）自動生成 OpenAPI 3.1，含 Bean Validation 約束。
  • 用 MicroProfile OpenAPI 註解（@Operation、@Schema、@APIResponse）強化文件。
  • Swagger UI 在 /q/swagger-ui，dev 預設啟用，prod 需明確配置。
  • OpenAPI 文件可產生多語言 SDK、做 contract testing、配置 API gateway。
  • 小心：別用 io.swagger.v3.oas.annotations（Swagger 原生），Quarkus 用的是 org.eclipse.microprofile.openapi.annotations。
