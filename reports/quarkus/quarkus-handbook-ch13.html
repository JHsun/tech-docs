Chapter 13 · Part III

WebSocket

REST 是 request–response：你問一句、它答一句。但聊天、即時通知、儀表板、線上協作這類場景需要雙向、持久的通道 ── 這就是 WebSocket。Quarkus 提供現代化的 websockets-next，用 @WebSocket + @OnTextMessage 等簡潔註解， 自動處理 JSON 序列化、broadcasting、執行緒模型與安全整合。

本章學習目標

讀者類型本章重點
🟢 初學者用 @WebSocket、@OnOpen、@OnTextMessage 寫第一個雙向通訊端點。
🔵 開發者掌握 OpenConnections、broadcast、JSON 自動轉換、@PathParam 與 UserData。
🟠 SRE理解 WebSocket 在 K8s/Ingress 環境的特殊性，與 Security 整合。

為什麼 WebSocket（而不是 SSE 或 polling）

方案方向適用備註
Pollingclient → server狀態變動很慢的場景簡單但浪費資源
SSE單向 server → client通知、價格推送第 9 章已介紹
WebSocket雙向聊天、協作、遊戲、即時控制本章主題
gRPC streaming雙向（基於 HTTP/2）服務間高效流式第 14 章

WebSocket 的特性：

  • 以 HTTP Upgrade 開始（瀏覽器、防火牆友善）
  • 之後升級為 TCP 全雙工長連線
  • 每筆訊息開銷很小（不需要重新建 HTTP）

兩個擴充：Next（新）與 Classic（舊）

ℹ︎
選擇 websockets-next
Quarkus 有兩個 WebSocket 擴充：
  • quarkus-websockets-next ⭐ ── 新的 Quarkus 原生實作，本章使用
  • quarkus-websockets ── 舊的 JSR 356 相容層，僅遷移舊系統時使用
Next 版本不實作 Jakarta WebSocket 規範（JSR 356），改為更簡潔、與 Vert.x event-loop 緊密整合的設計。 新專案一律使用 Next 版本。

加擴充

bash
quarkus extension add websockets-next

第一個範例：Echo Server

Java · Echo Server
import io.quarkus.websockets.next.OnTextMessage;
import io.quarkus.websockets.next.WebSocket;

@WebSocket(path = "/echo")
public class EchoSocket {

    @OnTextMessage
    public String onMessage(String message) {
        return "echo: " + message;
    }
}

用瀏覽器 console 測試：

JavaScript · 瀏覽器 console
const ws = new WebSocket("ws://localhost:8080/echo");
ws.onmessage = e => console.log("收到:", e.data);
ws.onopen = () => ws.send("Hello Quarkus!");
// 收到: echo: Hello Quarkus!
✓
六行程式碼，全自動
幕後 Quarkus 已經幫你：路由註冊、HTTP Upgrade、訊息 frame 解析、執行緒分派、回應序列化。 比 JSR 356 寫法少超過一半的樣板程式。

所有 callback 註解

註解觸發時機最多幾個
@OnOpen新連線建立1
@OnTextMessage收到文字訊息1
@OnBinaryMessage收到二進位訊息1
@OnPingMessage收到 ping frame1
@OnPongMessage收到 pong frame1
@OnClose連線關閉1
@OnError處理過程拋例外任意

每個 endpoint 必須至少有 @OnTextMessage／@OnBinaryMessage 或 @OnOpen 其中之一。

生命週期完整示範

Java · 完整生命週期
import io.quarkus.logging.Log;
import io.quarkus.websockets.next.*;

@WebSocket(path = "/chat/{username}")
public class ChatSocket {

    @OnOpen
    public String onOpen(WebSocketConnection conn) {
        String name = conn.pathParam("username");
        Log.infof("使用者 %s 上線 (id=%s)", name, conn.id());
        return "歡迎 " + name + " 加入！";
    }

    @OnTextMessage
    public String onMessage(String message, WebSocketConnection conn) {
        String name = conn.pathParam("username");
        return name + ": " + message;
    }

    @OnClose
    public void onClose(WebSocketConnection conn) {
        Log.infof("使用者 %s 離線", conn.pathParam("username"));
    }

    @OnError
    public void onError(Throwable t, WebSocketConnection conn) {
        Log.errorf(t, "連線 %s 發生錯誤", conn.id());
    }
}
⚠
@OnOpen 回傳值會被傳送
若 @OnOpen 方法回傳 String 或 record，Quarkus 會自動把它當作訊息送給該 client（不是廣播）。 若不需回應，宣告為 void 即可。

路徑參數與連線資訊

Java · 取得各種資訊
@WebSocket(path = "/room/{roomId}/user/{userId}")
public class RoomSocket {

    @OnOpen
    public void onOpen(WebSocketConnection conn,
                       @PathParam String roomId,
                       @PathParam String userId) {
        Log.infof("user=%s 進入房間 %s, 連線 id=%s",
            userId, roomId, conn.id());
        // 也可從 conn 取：conn.pathParam("roomId")
        // header：conn.handshakeRequest().header("...")
        // query：conn.handshakeRequest().query()
    }

    @OnTextMessage
    public String onMessage(String msg) { return msg; }
}

JSON 訊息自動轉換

不止接收字串，Quarkus 自動處理 JSON 序列化／反序列化：

Java · JSON 訊息
@WebSocket(path = "/chat")
public class JsonChatSocket {

    public record ChatMessage(String user, String text, long timestamp) {}
    public record ChatReply(String text, boolean accepted) {}

    @OnTextMessage
    public ChatReply onMessage(ChatMessage incoming) {
        Log.infof("[%s] %s", incoming.user(), incoming.text());
        return new ChatReply("已收到", true);
    }
}

Client 端：

JavaScript
ws.send(JSON.stringify({ user: "Alice", text: "嗨", timestamp: Date.now() }));
ws.onmessage = e => {
  const reply = JSON.parse(e.data);   // {text: "已收到", accepted: true}
};

廣播：一人發、所有人收

方式 A：@OnTextMessage(broadcast = true)

最簡單：在 @OnTextMessage 標 broadcast = true，回傳值會送給所有連到該 endpoint 的 client：

Java · 自動廣播
@WebSocket(path = "/chat/{username}")
public class ChatSocket {

    @OnTextMessage(broadcast = true)
    public ChatMessage onMessage(ChatMessage msg, WebSocketConnection conn) {
        return new ChatMessage(
            conn.pathParam("username"),
            msg.text(),
            System.currentTimeMillis());
    }
}

方式 B：用 OpenConnections 精細控制

需要更精細的控制（例如只廣播給同房間使用者），注入 OpenConnections：

Java · 同房間廣播
@WebSocket(path = "/room/{roomId}")
public class RoomSocket {

    @Inject OpenConnections openConnections;

    @OnTextMessage
    public void onMessage(ChatMessage msg, WebSocketConnection sender) {
        String myRoom = sender.pathParam("roomId");
        openConnections.stream()
            .filter(c -> myRoom.equals(c.pathParam("roomId")))
            .filter(c -> !c.id().equals(sender.id()))      // 不發給自己
            .forEach(c -> c.sendTextAndAwait(msg));
    }
}

定時推送：搭配 @Scheduled

經典應用：實時儀表板。從外部觸發推送（不是來自 WebSocket 訊息），需要從外部存取 connections：

Java · JVM Heap 監控（每 3 秒推一次）
import io.quarkus.scheduler.Scheduled;
import io.quarkus.websockets.next.*;
import java.lang.management.ManagementFactory;
import java.lang.management.MemoryUsage;

@WebSocket(path = "/monitor/heap")
public class HeapMonitorSocket {

    @Inject OpenConnections openConnections;

    @OnOpen
    public void onOpen(WebSocketConnection conn) {
        Log.infof("監控 client 連入：%s", conn.id());
    }

    @Scheduled(every = "3s")
    public void pushHeapUsage() {
        if (openConnections.stream().findAny().isEmpty()) return;

        MemoryUsage heap = ManagementFactory.getMemoryMXBean().getHeapMemoryUsage();
        HeapStat stat = new HeapStat(
            heap.getUsed() / 1024 / 1024,
            heap.getMax() / 1024 / 1024,
            System.currentTimeMillis());

        openConnections.stream().forEach(c -> c.sendTextAndAwait(stat));
    }

    public record HeapStat(long usedMb, long maxMb, long timestamp) {}
}
⚠
不要在 endpoint class 內 @Inject WebSocketConnection 來做外部推送
WebSocketConnection 是 @SessionScoped，不能在 @Scheduled 或其他外部 bean 中注入並使用。 要在外部觸發推送，永遠透過 OpenConnections（@ApplicationScoped）取得。

UserData：附加任意連線狀態

連線開啟時要記下「這個 user 的訂閱清單」、「最後活動時間」等資料？用 UserData + TypedKey：

Java · UserData
import io.quarkus.websockets.next.UserData.TypedKey;

@WebSocket(path = "/notifications/{username}")
public class NotificationSocket {

    static final TypedKey<Boolean> PREMIUM = TypedKey.forBoolean("premium");
    static final TypedKey<Long> LAST_SEEN = TypedKey.forLong("lastSeen");

    @Inject UserService userService;

    @OnOpen
    public void onOpen(WebSocketConnection conn) {
        String user = conn.pathParam("username");
        conn.userData().put(PREMIUM, userService.isPremium(user));
        conn.userData().put(LAST_SEEN, System.currentTimeMillis());
    }

    @OnTextMessage
    public String onMessage(String msg, WebSocketConnection conn) {
        conn.userData().put(LAST_SEEN, System.currentTimeMillis());
        if (Boolean.TRUE.equals(conn.userData().get(PREMIUM))) {
            return "premium user: " + msg;
        }
        return "free user: " + msg;
    }
}

執行緒模型

跟 Quarkus REST 一樣，WebSocket Next 預設在 event-loop 跑非阻塞邏輯：

flowchart LR
  classDef el fill:__SOFT_OK__,stroke:__OK__,color:__TXT__
  classDef block fill:__SOFT_WARN__,stroke:__WARN__,color:__TXT__
  classDef vt fill:__SOFT_INFO__,stroke:__INFO__,color:__TXT__

  Msg[收到訊息] --> D{方法是否阻塞?}
  D -->|回傳 Uni / Multi / 非阻塞| EL[Event Loop]:::el
  D -->|"@Blocking 或 @Transactional"| WP[Worker Pool]:::block
  D -->|"@RunOnVirtualThread"| VT[Virtual Thread]:::vt

圖 13-1 ─ WebSocket Next 的執行緒分派與 Quarkus REST 一致

Java · 三種寫法
// 非阻塞（預設，跑在 event-loop）
@OnTextMessage
public Uni<Response> nonBlocking(String msg) {
    return Uni.createFrom().item(() -> new Response("ok"));
}

// 明確阻塞（會 dispatch 到 worker pool）
@OnTextMessage
@Blocking
public Response withBlocking(String msg) {
    return jdbcService.lookup(msg);    // 阻塞 OK
}

// 虛擬執行緒（JDK 21+，阻塞但 cheap）
@OnTextMessage
@RunOnVirtualThread
public Response withVirtual(String msg) {
    return jdbcService.lookup(msg);
}

與 Security 整合

WebSocket 可以整合 Quarkus Security 做身分驗證與授權。第 27 章會詳述安全機制，這裡只示範整合：

application.properties
# 注意：WebSocket 安全整合需要關閉 proactive 認證
quarkus.http.auth.proactive=false
Java · 受保護的 endpoint
import jakarta.annotation.security.RolesAllowed;
import jakarta.annotation.security.PermitAll;

@WebSocket(path = "/admin/console")
@RolesAllowed("admin")     // 整個 endpoint 限 admin
public class AdminConsoleSocket {

    @OnTextMessage
    public String execute(String cmd) {
        return "executed: " + cmd;
    }

    @OnError
    public String handleAuthError(io.quarkus.security.ForbiddenException ex) {
        return "拒絕：權限不足";
    }
}

// 或 method 層級
@WebSocket(path = "/mixed")
public class MixedSocket {

    @OnOpen @PermitAll
    public String welcome() { return "歡迎"; }

    @OnTextMessage @RolesAllowed("user")
    public String chat(String msg) { return msg; }
}

WebSocket Client：你也能當 client

Quarkus 不只能當 server，也能當 WebSocket client 連接其他服務：

Java · 宣告 client endpoint
import io.quarkus.websockets.next.WebSocketClient;
import io.quarkus.websockets.next.OnTextMessage;

@WebSocketClient(path = "/stream/{topic}")
public class PriceStreamClient {

    @OnTextMessage
    public void onPriceUpdate(PriceUpdate update) {
        Log.infof("收到價格更新: %s = %s", update.symbol(), update.price());
    }

    public record PriceUpdate(String symbol, BigDecimal price) {}
}
Java · 建立連線
import io.quarkus.websockets.next.WebSocketConnector;

@ApplicationScoped
public class PriceService {

    @Inject WebSocketConnector<PriceStreamClient> connector;

    void subscribe() {
        connector
            .baseUri("wss://prices.example.com")
            .pathParam("topic", "BTC-USD")
            .addHeader("Authorization", "Bearer " + token)
            .connectAndAwait();
    }
}

貫穿專案進度：catalog-service 加上即時通知

讓管理員 dashboard 收到「新訂單」即時推播：

Java · 完整範例
@WebSocket(path = "/admin/orders/stream")
@RolesAllowed("admin")
public class OrderStreamSocket {

    @Inject OpenConnections openConnections;

    public record OrderEvent(String type, Long orderId, BigDecimal amount, Instant at) {}

    @OnOpen
    public OrderEvent welcome() {
        return new OrderEvent("welcome", null, null, Instant.now());
    }

    /** 由 OrderService 在新訂單建立時呼叫 */
    public void broadcast(OrderEvent ev) {
        openConnections.stream()
            .forEach(c -> c.sendTextAndAwait(ev));
    }
}

// OrderService 從 Producer 那邊呼叫
@ApplicationScoped
public class OrderService {

    @Inject OrderStreamSocket stream;

    public Order createOrder(...) {
        Order order = /* ... 寫入 DB */;
        stream.broadcast(new OrderStreamSocket.OrderEvent(
            "ORDER_CREATED", order.id(), order.total(), Instant.now()));
        return order;
    }
}

DevOps / SRE 視角

K8s / Ingress 環境的 WebSocket 注意事項

⚠
WebSocket 在 K8s 的常見坑
  1. Ingress 預設 timeout 太短：NGINX Ingress 預設 60s idle 就會切連線。需設 nginx.ingress.kubernetes.io/proxy-read-timeout: "3600" 等註解。
  2. Sticky session：因連線狀態在某 Pod 上，rolling update 會中斷所有連線。可接受短暫斷線，或用 Redis 等共享 connection registry。
  3. Service Mesh：Istio/Linkerd 對 WebSocket 有額外配置（HTTP upgrade 允許）。
  4. 水平擴展：單一 Pod 廣播只能到自己持有的連線。多 Pod 需用 Redis Pub/Sub 或 Kafka 跨 Pod 傳訊。

觀測與 metrics

  • 監控當前連線數（OpenConnections.stream().count()）並暴露為 Micrometer gauge
  • 記錄每秒 WebSocket frame 數量、平均訊息大小
  • 連線異常斷開率（@OnError 觸發次數）

容量規劃

典型容量：單個 Quarkus Pod（2vCPU、2GB）可同時持有 10,000+ 個閒置 WebSocket 連線，活躍訊息率取決於負載。

常見陷阱

症狀原因解法
外部 bean 注入 WebSocketConnection 是 null 它是 @SessionScoped，只能在 endpoint 內注入 用 OpenConnections 從外部存取
@RolesAllowed 不生效 未關閉 proactive 認證 設 quarkus.http.auth.proactive=false
K8s 環境每 60 秒斷線 Ingress idle timeout 設 NGINX proxy-read-timeout、或開啟 ping/pong heartbeat
JSON 訊息收不到 record 物件 沒有 quarkus-rest-jackson 或 JSON-B 加 JSON 擴充（通常已透過 REST 引入）
瀏覽器 CORS 錯誤 誤把 CORS 當 WebSocket 認證 WebSocket 不走 CORS，但 handshake 走；通常設好 CORS 即可
多 Pod 之間訊息收不到 沒做跨 Pod 廣播 加 Redis Pub/Sub 或 Kafka 中介

本章小結

  • 新專案一律用 quarkus-websockets-next，不是舊的 JSR 356 相容版本。
  • Server endpoint 用 @WebSocket(path = "...") 標示，支援 {param} 路徑變數。
  • Callbacks：@OnOpen、@OnTextMessage、@OnBinaryMessage、@OnClose、@OnError。
  • 方法回傳 record／物件即自動 JSON 序列化送回 client；參數同樣自動反序列化。
  • 廣播：@OnTextMessage(broadcast = true)（簡單）或 OpenConnections（精細）。
  • 外部 bean 推送：透過 OpenConnections，不要注入 WebSocketConnection。
  • 每連線狀態用 WebSocketConnection.userData() + TypedKey。
  • 執行緒模型與 REST 一致：預設 event-loop、可加 @Blocking 或 @RunOnVirtualThread。
  • Security 整合需 quarkus.http.auth.proactive=false，然後用 @RolesAllowed。
  • WebSocket Client：@WebSocketClient + WebSocketConnector 注入。
  • K8s 部署注意 Ingress timeout、sticky session、跨 Pod 廣播策略。
