Authentication 基礎

一個沒有 authentication 的 API 等於把鑰匙留在門口。 本章把 Quarkus Security 整個架構掀開：HttpAuthenticationMechanism 抽 credential、IdentityProvider 驗證身份、SecurityIdentity 在整個 request lifecycle 流動。 從 Basic auth 起步，理解這套架構之後，第 29 章 JWT/OIDC 才會「就只是換一個 mechanism」── 不是另一套東西。

先說清楚：AuthN ≠ AuthZ

術語意義典型問題
Authentication（AuthN）身份驗證 ── 你是誰？確認使用者真的是 alice@example.com
Authorization（AuthZ）授權 ── 你能做什麼？alice 能讀訂單，但不能刪

本章專注 AuthN。AuthZ（角色、權限）在第 30 章詳述。

圖 28-1 ─ Quarkus Security 三段流程：抽 credential → 驗證 → 產生 SecurityIdentity

✓
為什麼這個分離很重要
Mechanism（怎麼抽 credential）與 IdentityProvider（怎麼驗證）正交。 所以你可以：用 Basic auth 抽 username/password，背後用 JPA 驗； 用 JWT 抽 token，背後用 OIDC 驗； 換驗證方式時只換一邊。這就是 Quarkus 「Security 不是黑盒」的核心精神。

內建的 Mechanism

Mechanism來源典型場景
Basic內建，無需擴充內部工具、admin endpoint、測試
Form內建傳統 server-rendered web app
Mutual TLS內建服務間驗證、金融場域
Bearer Token (JWT)quarkus-smallrye-jwt無狀態 API、微服務（第 29 章）
OIDC Bearerquarkus-oidcOIDC IdP 簽發的 token（第 29 章）
OIDC Code Flowquarkus-oidcweb 應用 SSO（第 31 章 Keycloak）
WebAuthnquarkus-security-webauthn無密碼登入（passkey）

本章先把 Basic auth + JPA 走通；JWT/OIDC 留給下一章。

第一個範例：Basic Auth + JPA

加擴充

bash
quarkus extension add security-jpa-reactive jdbc-postgresql hibernate-orm-panache
ℹ︎
兩個 JPA Security 擴充選擇
  • quarkus-security-jpa ── 阻塞式（傳統 Hibernate ORM）
  • quarkus-security-jpa-reactive ── 反應式（Hibernate Reactive，第 17 章）
多數情況選 security-jpa 就好，混在 reactive 應用裡反而麻煩。

User Entity

Java · 帶 Security 註解的 Entity
import io.quarkus.security.jpa.*;
import io.quarkus.hibernate.orm.panache.PanacheEntity;
import jakarta.persistence.*;

@Entity @Table(name = "users")
@UserDefinition           // 標記這個 entity 是「使用者」來源
public class User extends PanacheEntity {

    @Username
    public String username;

    @Password               // 預設 bcrypt 雜湊
    public String password;

    @Roles                  // 角色字串（逗號分隔，或多筆 join）
    public String role;

    /** 註冊新使用者（密碼自動 hash） */
    public static void add(String username, String password, String role) {
        User u = new User();
        u.username = username;
        u.password = BcryptUtil.bcryptHash(password);
        u.role = role;
        u.persist();
    }
}
⚠
絕對不要存明文密碼
@Password 預設用 bcrypt。註冊／改密碼必須用 BcryptUtil.bcryptHash(plain)。 存明文密碼是2026 年仍會發生的 OWASP Top 10 經典錯誤。

受保護的 endpoint

Java
import io.quarkus.security.Authenticated;
import io.quarkus.security.identity.SecurityIdentity;
import jakarta.annotation.security.PermitAll;
import jakarta.inject.Inject;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;

@Path("/")
public class HelloResource {

    @Inject SecurityIdentity identity;

    @GET @Path("/public")
    @PermitAll                       // 不需登入
    public String publicHello() {
        return "Hello, anonymous";
    }

    @GET @Path("/me")
    @Authenticated                   // 需登入，任何角色皆可
    public String me() {
        return "Hello, " + identity.getPrincipal().getName();
    }
}

實測

$ # 公開 endpoint $ curl http://localhost:8080/public Hello, anonymous $ # 未登入訪問受保護 endpoint $ curl -i http://localhost:8080/me HTTP/1.1 401 Unauthorized WWW-Authenticate: Basic $ # 帶 Basic credential $ curl -u alice:s3cret http://localhost:8080/me Hello, alice

SecurityIdentity：authenticated 後的核心物件

所有受保護的 endpoint 都可以注入 SecurityIdentity，取得當前登入者資訊：

Java · SecurityIdentity 常用 API
@Inject SecurityIdentity identity;

// 使用者名稱
String username = identity.getPrincipal().getName();

// 角色清單
Set<String> roles = identity.getRoles();

// 角色檢查
boolean isAdmin = identity.hasRole("admin");

// 是否匿名（未登入）
boolean anon = identity.isAnonymous();

// 取出原始 credential
PasswordCredential pwd = identity.getCredential(PasswordCredential.class);

// 自訂 attributes（OIDC token claims、JWT 額外欄位等）
String email = (String) identity.getAttribute("email");

HTTP Security Policy：以路徑保護

annotation 是程式碼層面的保護；HTTP Security Policy 是配置層面的保護，適合廣泛規則（如「/admin/** 都要 admin」）：

application.properties
# 規則 1：所有 /api/** 都要登入
quarkus.http.auth.permission.authenticated.paths=/api/*
quarkus.http.auth.permission.authenticated.policy=authenticated

# 規則 2：/admin/** 限 admin 角色
quarkus.http.auth.policy.admin-policy.roles-allowed=admin
quarkus.http.auth.permission.admin.paths=/admin/*
quarkus.http.auth.permission.admin.policy=admin-policy

# 規則 3：/public/** 與健康檢查 endpoint 完全放行
quarkus.http.auth.permission.public.paths=/public/*,/q/health/*
quarkus.http.auth.permission.public.policy=permit
quarkus.http.auth.permission.public.methods=GET
⚠
Policy 與 annotation 的優先序
HTTP Security Policy 在 endpoint 比對之前就執行（在 Vert.x 層）。
@RolesAllowed 在 endpoint 比對之後執行（在 CDI interceptor 層）。
兩者都會生效，且都要通過。實務上：用 Policy 做粗粒度（路徑前綴），用 annotation 做細粒度（特定方法）。

Proactive Authentication：預設行為與取捨

Quarkus 預設啟用 proactive authentication：

  • 只要請求帶 credential（Authorization header、cookie 等），就會立即執行 authentication
  • 即使目標 endpoint 是 @PermitAll 也會驗，驗證失敗整個請求 401

好處：早期失敗、簡化邏輯。壞處：無效 credential 的請求也會被拒絕，即使該 endpoint 公開。

application.properties · 關閉 proactive auth
quarkus.http.auth.proactive=false

關掉後：

  • 無 annotation 與無 policy 規則的 endpoint 完全跳過 auth ── 即使請求帶 credential
  • 同一個 endpoint 上可用 annotation 切換 mechanism（如 @BasicAuthentication vs @AuthorizationCodeFlow）

多 mechanism 並存

同個應用可同時有「Basic auth for admin tools」與「OIDC for user-facing API」：

application.properties
# /admin 用 Basic auth
quarkus.http.auth.permission.admin.paths=/admin/*
quarkus.http.auth.permission.admin.policy=authenticated
quarkus.http.auth.permission.admin.auth-mechanism=basic

# /api 用 OIDC Bearer
quarkus.http.auth.permission.api.paths=/api/*
quarkus.http.auth.permission.api.policy=authenticated
quarkus.http.auth.permission.api.auth-mechanism=bearer

# /service 兩種都接受
quarkus.http.auth.permission.both.paths=/service/*
quarkus.http.auth.permission.both.policy=authenticated

從 Quarkus 3.10+ 也可以用 annotation 切換（需關閉 proactive auth）：

Java · annotation 選 mechanism
import io.quarkus.vertx.http.runtime.security.annotation.BasicAuthentication;
import io.quarkus.oidc.AuthorizationCodeFlow;

@Path("/hello")
public class HelloResource {

    @GET @Path("/basic")
    @BasicAuthentication
    public String forAdminTool() { return "via Basic"; }

    @GET @Path("/web")
    @AuthorizationCodeFlow
    @RolesAllowed("user")
    public String forWebApp() { return "via OIDC code flow"; }
}

Form-based Authentication（傳統 web 用）

SPA 與 API 多用 token；但 server-rendered web app 仍適合 form auth：

application.properties
quarkus.http.auth.form.enabled=true
quarkus.http.auth.form.login-page=/login.html
quarkus.http.auth.form.error-page=/login-error.html
quarkus.http.auth.form.landing-page=/dashboard.html
quarkus.http.auth.form.post-location=/j_security_check
quarkus.http.auth.form.username-parameter=j_username
quarkus.http.auth.form.password-parameter=j_password

# Session cookie 加密 key
quarkus.http.auth.session.encryption-key=${SESSION_KEY}

登入成功後 Quarkus 自動發 encrypted cookie 維持 session；用 IdentityProvider 同 Basic auth。

自訂 IdentityProvider

不想用 JPA、想驗 LDAP / Active Directory / 自家 user service？實作自訂 IdentityProvider：

Java · 自訂 LDAP IdentityProvider
import io.quarkus.security.identity.IdentityProvider;
import io.quarkus.security.identity.AuthenticationRequestContext;
import io.quarkus.security.identity.request.UsernamePasswordAuthenticationRequest;
import io.quarkus.security.identity.SecurityIdentity;
import io.quarkus.security.runtime.QuarkusSecurityIdentity;
import io.smallrye.mutiny.Uni;
import jakarta.enterprise.context.ApplicationScoped;

@ApplicationScoped
public class LdapIdentityProvider
        implements IdentityProvider<UsernamePasswordAuthenticationRequest> {

    @Inject LdapClient ldap;

    @Override
    public Class<UsernamePasswordAuthenticationRequest> getRequestType() {
        return UsernamePasswordAuthenticationRequest.class;
    }

    @Override
    public Uni<SecurityIdentity> authenticate(
            UsernamePasswordAuthenticationRequest req,
            AuthenticationRequestContext ctx) {
        return Uni.createFrom().item(() -> {
            LdapUser user = ldap.bind(req.getUsername(),
                                       new String(req.getPassword().getPassword()));
            if (user == null) return null;        // 驗證失敗
            return QuarkusSecurityIdentity.builder()
                .setPrincipal(() -> user.getDn())
                .addRoles(user.getGroups())
                .addAttribute("email", user.getEmail())
                .build();
        });
    }
}

注冊為 @ApplicationScoped bean 後，Basic auth 自動使用此 IdentityProvider。可同時註冊多個 IdentityProvider，Quarkus 會依 request type 自動選擇。

貫穿專案進度：catalog-service 的內部管理 API

catalog-service 對外用 OIDC（第 29 章），但內部管理 endpoint（reload cache、reset 統計）只給營運團隊用：

application.properties
# 內部管理 endpoint：Basic auth + admin role
quarkus.http.auth.basic=true

quarkus.http.auth.policy.admin-only.roles-allowed=admin
quarkus.http.auth.permission.admin.paths=/internal/*
quarkus.http.auth.permission.admin.policy=admin-only
quarkus.http.auth.permission.admin.auth-mechanism=basic
Java
@Path("/internal")
@RolesAllowed("admin")
public class InternalAdminResource {

    @POST @Path("/cache/clear")
    public Response clearCache() {
        cacheService.clear();
        return Response.noContent().build();
    }

    @POST @Path("/reload-config")
    public Response reload() {
        configService.reload();
        return Response.ok().build();
    }
}

把這些 endpoint 與業務 API 隔開、用不同 auth 機制，是務實的「最小權限」實踐。

DevOps / SRE 視角

✓
生產上線 checklist
  1. 強制 HTTPS：quarkus.http.insecure-requests=disabled；不然 Basic auth 等於明文傳密碼
  2. 密碼用 bcrypt（@Password 預設）；改密碼時用 BcryptUtil.bcryptHash
  3. 禁用無 Auth 的管理 endpoint：/q/health 可開、/q/metrics 需 auth、/q/dev 永遠關
  4. 登入失敗訊息一致：不要區分「使用者不存在」與「密碼錯」── 防 enumeration
  5. rate limiting：登入 endpoint 加 brute force 防護（第 38 章 Fault Tolerance）
  6. 監控 401 / 403 rate：突然飆升是攻擊徵兆
  7. Session cookie：設 Secure + HttpOnly + SameSite=Strict
  8. 稽核 log：誰、何時、登入哪個 endpoint ── 用 SecurityIdentity 紀錄

常見陷阱

症狀原因解法
已加 @Authenticated 但 endpoint 仍可匿名訪問 同 class 內部呼叫（CDI proxy 限制，類似第 18 章 @Transactional） 拆到別的 bean
登入正確但 401 密碼欄位存的不是 bcrypt hash 而是明文 用 BcryptUtil.bcryptHash() 重設密碼
Basic auth 401 但沒 WWW-Authenticate header 機制未啟用 確認 quarkus.http.auth.basic=true 或裝對應 extension
SecurityIdentity 注入是 anonymous 該路徑沒被 policy 或 annotation 觸發 auth 加 @Authenticated 或 HTTP Security Policy
Form auth 登入後立即又被踢回登入頁 session encryption key 沒設或每次重啟都換 顯式設 quarkus.http.auth.session.encryption-key 為穩定 secret
多 mechanism 衝突 沒指定 auth-mechanism 顯式指定 path 對應的 mechanism
正式環境密碼被掃出來 明文存 DB 立即重設所有密碼、改用 bcrypt、做 incident response

本章小結

  • AuthN ≠ AuthZ：本章專注「你是誰」，AuthZ 在第 30 章。
  • Quarkus Security 三大角色：HttpAuthenticationMechanism（抽 credential）→ IdentityProvider（驗證）→ SecurityIdentity（結果）。
  • 內建 mechanism：Basic / Form / mTLS；擴充 mechanism：JWT / OIDC / WebAuthn。
  • Basic auth + JPA 是最快上手組合：quarkus-security-jpa + @UserDefinition 標註 entity。
  • 密碼必須用 bcrypt（@Password 預設、BcryptUtil.bcryptHash）。
  • 保護方式有兩層：HTTP Security Policy（路徑、配置層）與 annotation（程式碼層）。
  • Proactive authentication 預設開啟：有 credential 就驗。可關閉以用 annotation 切換 mechanism。
  • 多 mechanism 並存：不同路徑用不同 auth（如 admin 用 Basic、API 用 OIDC）。
  • 自訂 IdentityProvider 接 LDAP / 既有 user service ── 改一個 bean 就好，business code 不變。
  • SRE 重點：強制 HTTPS、bcrypt 密碼、登入失敗一致訊息、rate limiting、稽核 log。
