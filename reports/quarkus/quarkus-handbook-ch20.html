NoSQL 整合

並非所有資料都適合塞進關聯式資料庫。MongoDB 適合 schema 變動快的文件型業務； Redis 是 session／快取／佇列的瑞士刀；Cassandra 為超大規模寫入優化； Neo4j 解決社交網路、推薦系統等圖結構問題。 本章介紹 Quarkus 怎麼整合這四類 NoSQL，並提供選型決策樹 ── 避免「為新潮而 NoSQL」的常見錯誤。

⚠
先問：你真的需要 NoSQL 嗎？
現代 PostgreSQL 16+ 已支援 JSONB、全文索引、地理空間、向量搜尋。單一 PG cluster 多半就夠用。 導入 NoSQL 前先問：
  • 規模真的需要分散式嗎？（< 1TB 資料、< 10k QPS → PG 通常行）
  • 關聯式 schema 真的不適合？（PG 的 JSONB 已能存彈性結構）
  • 有 DBA / SRE 能維運多個 DB 嗎？
別把架構複雜度當成熟度的證明。Polyglot persistence 是必要時才採用。

第一個 Entity

Java · MongoDB Entity
import io.quarkus.mongodb.panache.PanacheMongoEntity;
import io.quarkus.mongodb.panache.common.MongoEntity;
import org.bson.codecs.pojo.annotations.BsonProperty;
import org.bson.codecs.pojo.annotations.BsonIgnore;

@MongoEntity(collection = "products")
public class Product extends PanacheMongoEntity {     // 自動 ObjectId 作 _id

    public String name;
    public String sku;
    public BigDecimal price;

    @BsonProperty("createdAt")
    public Instant createdAt = Instant.now();

    @BsonIgnore
    public transient String runtimeOnlyField;     // 不寫入 DB

    // 巢狀文件直接是 Java 物件
    public Specs specs;
    public List<String> tags = new ArrayList<>();

    // 自訂查詢
    public static Optional<Product> findBySku(String sku) {
        return find("sku", sku).firstResultOptional();
    }

    public static List<Product> findByTag(String tag) {
        return list("tags", tag);
    }

    public static class Specs {
        public String weight;
        public Map<String, String> dimensions;
    }
}
✓
與 Hibernate Panache 幾乎一樣
比較第 16 章的 PanacheEntity：MongoDB 版只是換了 package、改用 BSON 註解，查詢 API 完全相同。 團隊一旦熟悉一邊，另一邊上手只要幾分鐘。

使用

Java · CRUD
// Create
Product p = new Product();
p.name = "Widget";
p.tags = List.of("electronics", "popular");
p.persist();         // 不需要 @Transactional！

// Read
Product found = Product.findById(new ObjectId("..."));
List<Product> widgets = Product.list("name", "Widget");
List<Product> expensive = Product.list("price >= ?1", new BigDecimal("100"));

// Update
p.price = new BigDecimal("19.99");
p.update();          // 用 update 取代 Hibernate 的自動 dirty check

// Delete
Product.deleteById(p.id);

// Aggregation（複雜查詢退回 raw driver）
@Inject MongoClient mongo;
AggregateIterable<Document> result = mongo
    .getDatabase("catalog").getCollection("products")
    .aggregate(List.of(
        Aggregates.match(Filters.gte("price", 100)),
        Aggregates.group("$category", Accumulators.avg("avgPrice", "$price"))
    ));
⚠
MongoDB 沒有 dirty checking
跟 Hibernate ORM 不同，MongoDB Panache 需要顯式呼叫 p.update()。 這是因為 MongoDB driver 不追蹤物件變動。

使用 RedisDataSource

Java · 高階 API
import io.quarkus.redis.datasource.RedisDataSource;
import io.quarkus.redis.datasource.value.ValueCommands;
import io.quarkus.redis.datasource.keys.KeyCommands;

@ApplicationScoped
public class ProductCacheService {

    private final ValueCommands<String, Product> values;
    private final KeyCommands<String> keys;

    public ProductCacheService(RedisDataSource redis) {
        this.values = redis.value(Product.class);    // 自動 JSON 序列化
        this.keys = redis.key();
    }

    public void cache(Product p) {
        // SET with TTL 60 秒
        values.setex("product:" + p.id, 60, p);
    }

    public Product get(String id) {
        return values.get("product:" + id);     // 找不到回 null
    }

    public void invalidate(String id) {
        keys.del("product:" + id);
    }
}

原子操作：分散式鎖、計數器

Java · 各種 Redis 用法
// 計數器
redis.value(Long.class).incrby("page_views:home", 1);

// 分散式鎖（簡易版）
boolean acquired = redis.value(String.class)
    .setnx("lock:order:" + orderId, "owner-" + nodeId);
if (acquired) {
    try { doWork(); } finally {
        redis.key().del("lock:order:" + orderId);
    }
}

// Hash
HashCommands<String, String, String> hash = redis.hash(String.class);
hash.hset("user:123", "name", "Alice");
hash.hset("user:123", "email", "alice@example.com");
Map<String, String> user = hash.hgetall("user:123");

// List（佇列）
ListCommands<String, String> list = redis.list(String.class);
list.lpush("jobs", "task-1", "task-2");
String job = list.rpop("jobs");

// Pub/Sub
PubSubCommands<String> pubsub = redis.pubsub(String.class);
pubsub.publish("notifications", "new-order");

Java · 用 QuarkusCqlSession
import com.datastax.oss.quarkus.runtime.api.session.QuarkusCqlSession;
import com.datastax.oss.driver.api.core.cql.*;
import io.smallrye.mutiny.Multi;
import io.smallrye.mutiny.Uni;

@ApplicationScoped
public class EventService {

    @Inject QuarkusCqlSession session;

    /**
     * Cassandra 經典場景：時間序列寫入
     * partition key = userId（同 user 資料同節點）
     * clustering key = ts DESC（最新事件優先）
     * TTL 30 天自動過期
     */
    public Uni<Void> recordEvent(String userId, Instant ts, String type, String payload) {
        return session.executeReactive(
            SimpleStatement.builder("""
                INSERT INTO user_events (user_id, event_time, event_type, payload)
                VALUES (?, ?, ?, ?) USING TTL 2592000
                """)
            .addPositionalValues(userId, ts, type, payload)
            .build()
        ).toUni().replaceWithVoid();
    }

    public Multi<UserEvent> recentEvents(String userId) {
        return session.executeReactive(
            SimpleStatement.builder("""
                SELECT user_id, event_time, event_type, payload
                FROM user_events
                WHERE user_id = ?
                LIMIT 100
                """)
            .addPositionalValue(userId).build())
        .map(row -> new UserEvent(
            row.getString("user_id"),
            row.getInstant("event_time"),
            row.getString("event_type"),
            row.getString("payload")));
    }

    public record UserEvent(String userId, Instant time, String type, String payload) {}
}
⚠
Cassandra 設計思維跟 SQL 完全不同
  • 不要寫 JOIN：Cassandra 不支援，要靠資料反正規化（同份資料多表存）
  • Query first, schema second：先想要怎麼查，再決定 partition key
  • 不要無條件全表掃：WHERE 一定要帶 partition key
  • 沒有強一致性：預設 eventual consistency，可調 consistency level
若你以為 Cassandra 是「分散式版 MySQL」就會踩雷。

用 Cypher 查詢

Java · Cypher 查詢範例
import org.neo4j.driver.Driver;
import org.neo4j.driver.Session;
import org.neo4j.driver.Result;

@ApplicationScoped
public class RecommendationService {

    @Inject Driver driver;

    /** 「買過此商品的人也買了什麼」── 圖 DB 的拿手好戲 */
    public List<String> alsoBought(String productSku) {
        try (Session session = driver.session()) {
            Result result = session.run("""
                MATCH (target:Product {sku: $sku})<-[:PURCHASED]-(user:User)
                MATCH (user)-[:PURCHASED]->(other:Product)
                WHERE other <> target
                RETURN other.name AS name, COUNT(*) AS frequency
                ORDER BY frequency DESC
                LIMIT 5
                """, Map.of("sku", productSku));

            return result.stream()
                .map(r -> r.get("name").asString())
                .toList();
        }
    }

    /** 朋友的朋友（2 度好友） */
    public List<String> friendsOfFriends(String userId) {
        try (Session session = driver.session()) {
            return session.run("""
                MATCH (u:User {id: $id})-[:FRIEND]->()-[:FRIEND]->(fof:User)
                WHERE fof.id <> $id
                AND NOT (u)-[:FRIEND]->(fof)
                RETURN DISTINCT fof.name
                """, Map.of("id", userId))
            .stream().map(r -> r.get(0).asString()).toList();
        }
    }
}
✓
同樣的查詢，SQL 寫起來會痛
上面的「朋友的朋友」用 SQL 寫需要至少 2 個 JOIN，且效能差。Cypher 表達一次性，Neo4j 引擎也針對圖遍歷優化。 但只是查單一節點 → 反而 SQL 比較快。圖 DB 不是萬靈丹，只在關係查詢有優勢。

⚠
Polyglot 的隱藏成本
  • 運維複雜度：每個 DB 都要 backup、monitoring、HA
  • 跨儲存一致性：訂單寫 PG、事件寫 Cassandra，可能不同步
  • 學習成本：團隊要懂 4 套查詢語言
  • 除錯困難：問題出在哪個儲存？
建議：起步先用單一 DB（通常 PG），隨負載成長再拆。不要一開始就 Polyglot。

DevOps / SRE 視角

各 NoSQL 的部署模式

NoSQLK8s 部署模式容量參考
MongoDB Replica Set（3 nodes）、StatefulSet 單 replica set ~10TB、~10k ops/s
Redis Sentinel（3 sentinel + 1 master + 1 replica）或 Cluster 單 instance 100k+ ops/s、記憶體吃緊
Cassandra StatefulSet、至少 3 nodes 線性擴展，每節點數 TB
Neo4j Causal Cluster（3 core + N read replica） 單 core 可達數十億節點

備份策略

✓
每個 NoSQL 都要設備份
  • MongoDB：mongodump + Atlas 連續備份；replica set 不等於備份
  • Redis：RDB snapshot（定期）+ AOF（每秒 fsync）；但 Redis 通常存可重建的資料
  • Cassandra：nodetool snapshot + 上傳到 S3
  • Neo4j：online backup 工具（企業版才有）

何時不該用各種 NoSQL

⚠
每個 NoSQL 的「不適合」場景
  • MongoDB 不適合：強關聯（JOIN 多）、複雜分析（OLAP）、需 ACID 跨文件
  • Redis 不適合：永久儲存（記憶體成本太高）、大型物件（>1MB）
  • Cassandra 不適合：< 1TB 資料（單 PG 還好）、強一致性、複雜查詢（無 JOIN）
  • Neo4j 不適合：純 CRUD、簡單關聯（用 PG 一個 JOIN 就完事）、超大規模寫入

常見陷阱

症狀原因解法
MongoDB p.update() 沒生效 沒呼叫 update 方法 顯式 entity.update()
Redis 連線斷掉後拋例外 未配置 retry 加 fault tolerance（第 32 章）或設 quarkus.redis.timeout
Redis 記憶體爆滿 所有 key 都沒 TTL setex 或設 maxmemory-policy=allkeys-lru
Cassandra UNCONFIGURED_TABLE 表還沒建立 用 cassandra-migration 等工具管 schema
Neo4j query 變超慢 缺索引 CREATE INDEX FOR (u:User) ON (u.id)
Polyglot 寫入不同步 沒有跨 DB 交易 用第 18 章 Saga 模式 或 outbox pattern

本章小結

  • NoSQL 四大家族：文件型（MongoDB）／Key-Value（Redis）／寬欄式（Cassandra）／圖型（Neo4j）。
  • 導入 NoSQL 前先問：PostgreSQL 真的不夠嗎？JSONB、全文搜尋、向量搜尋已能取代多數 NoSQL 場景。
  • MongoDB Panache 與 Hibernate Panache API 幾乎相同；差別在需要顯式 update()。
  • Redis 用 RedisDataSource 高階 API；搭配 quarkus-redis-cache 可用 @CacheResult 註解。
  • Cassandra 是 Quarkiverse 擴充，思維與 SQL 完全不同：query first, schema second，反正規化是常態。
  • Neo4j 用 Cypher 表達圖遍歷查詢；單純 CRUD 用 SQL 更快，圖 DB 只在關係查詢有優勢。
  • Polyglot Persistence 看似強大，但運維成本顯著；起步先用單一 DB。
  • 每種 NoSQL 都有 Dev Services 支援，本機開發 zero config。
