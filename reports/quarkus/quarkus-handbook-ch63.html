擴充開發基礎：@BuildStep 與 BuildItem

Quarkus 的每一個功能都是一個擴充 ── 從 REST 到 Kafka 到 Hibernate，全部以擴充的形式提供。 了解如何開發擴充，就是了解 Quarkus 最底層的運作方式。 擴充由兩個模組組成：runtime（使用者看到的 API）和 deployment（build time 的處理器）。 @BuildStep 在 build time 消費和生產 BuildItem，@Recorder 把 build time 的決策錄製成 runtime 執行的程式碼。

版本 Quarkus 3.33 LTS
預估閱讀 30 分鐘
更新 2026-05-16

Runtime 模組：使用者看到的 API

Java · runtime/GreetingConfig.java
// runtime 模組：定義擴充的設定
@ConfigMapping(prefix = "greeting")
@ConfigPhase.BUILD_AND_RUN_TIME_FIXED
public interface GreetingConfig {
    /** 問候語，預設 Hello */
    @WithDefault("Hello")
    String message();
    /** 是否啟用 */
    @WithDefault("true")
    boolean enabled();
}

// runtime/GreetingRecorder.java
// @Recorder 標記：Quarkus 會用這個類別在 runtime 執行被「錄製」的方法
@Recorder
public class GreetingRecorder {

    public void registerGreeter(GreetingConfig config) {
        // 這個方法的呼叫在 build time 被錄製
        // runtime 時真正執行
        if (config.enabled()) {
            GreetingService.initialize(config.message());
        }
    }
}

Deployment 模組：@BuildStep

Java · deployment/GreetingProcessor.java
import io.quarkus.deployment.annotations.BuildStep;
import io.quarkus.deployment.annotations.Record;
import io.quarkus.deployment.annotations.ExecutionTime;
import io.quarkus.arc.deployment.SyntheticBeanBuildItem;

public class GreetingProcessor {

    // 1. 讀取設定，生產 AdditionalBeanBuildItem（告訴 ArC 要注冊哪些 bean）
    @BuildStep
    AdditionalBeanBuildItem registerBeans() {
        return AdditionalBeanBuildItem.unremovableOf(GreetingService.class);
    }

    // 2. 在 runtime 執行 @Recorder 的方法（錄製動作）
    @BuildStep
    @Record(ExecutionTime.RUNTIME_INIT)   // RUNTIME_INIT = 應用啟動時執行
    void setupGreeting(
        GreetingConfig config,            // build time 讀取設定
        GreetingRecorder recorder,        // 注入 recorder
        BuildProducer<GreetingBuildItem> greetingProducer) {

        recorder.registerGreeter(config);
        greetingProducer.produce(new GreetingBuildItem(config.message()));
    }

    // 3. 消費其他 BuildItem，生產健康端點
    @BuildStep
    void registerHealthCheck(
        List<GreetingBuildItem> greetings,          // 消費
        BuildProducer<HealthBuildItem> health) {    // 生產

        if (!greetings.isEmpty()) {
            health.produce(new HealthBuildItem(GreetingHealthCheck.class.getName(), true));
        }
    }
}

BuildItem：Build Time 資料傳遞

BuildItem 是 build time 的「訊息傳遞」機制 ── @BuildStep 之間透過生產/消費 BuildItem 傳遞資料：

Java · 自訂 BuildItem
import io.quarkus.builder.item.SimpleBuildItem;
import io.quarkus.builder.item.MultiBuildItem;

// SimpleBuildItem：整個 build 只能有一個實例
public final class GreetingBuildItem extends SimpleBuildItem {
    private final String message;
    public GreetingBuildItem(String message) { this.message = message; }
    public String getMessage() { return message; }
}

// MultiBuildItem：可以有多個實例（如多個 health check）
public final class GreetingProviderBuildItem extends MultiBuildItem {
    private final Class<?> providerClass;
    public GreetingProviderBuildItem(Class<?> clazz) { this.providerClass = clazz; }
    public Class<?> getProviderClass() { return providerClass; }
}

ExecutionTime：Static Init vs Runtime Init

ExecutionTime執行時機Native 行為
STATIC_INIT應用啟動前（靜態初始化）在 native build 時執行，結果直接序列化進 binary
RUNTIME_INIT應用啟動時（runtime 初始化）每次啟動都執行（可讀取 runtime 設定）
ℹ︎
選哪個 ExecutionTime？
設定在 build time 就確定（ConfigPhase.BUILD_AND_RUN_TIME_FIXED）→ STATIC_INIT（更快）
設定需要在 runtime 讀取（如環境變數、Vault secret）→ RUNTIME_INIT

擴充測試

Java · 擴充整合測試
// deployment 模組的測試
@QuarkusUnitTest
class GreetingExtensionTest {

    @RegisterExtension
    static final QuarkusUnitTest config = new QuarkusUnitTest()
        .overrideConfigKey("greeting.message", "Howdy")
        .overrideConfigKey("greeting.enabled", "true")
        .setArchiveProducer(() ->
            ShrinkWrap.create(JavaArchive.class));

    @Inject GreetingService greetingService;

    @Test
    void shouldGreetWithCustomMessage() {
        Assertions.assertEquals("Howdy", greetingService.getMessage());
    }
}

本章小結

  • 擴充 = runtime 模組（使用者 API）+ deployment 模組（build time 處理器），單向依賴。
  • @BuildStep：在 build time 執行，消費/生產 BuildItem，DAG 自動計算執行順序。
  • BuildItem：build time 的資料傳遞；SimpleBuildItem（唯一）vs MultiBuildItem（多個）。
  • @Recorder：橋接 build time 和 runtime ── 在 build time 錄製方法呼叫，runtime 真正執行。
  • ExecutionTime.STATIC_INIT：可在 native build 時固化，更快；RUNTIME_INIT：讀 runtime 設定。
  • 腳手架：quarkus create extension 自動生成雙模組結構與整合測試。
