日誌（Logging）

日誌是應用的「黑盒子飛行紀錄器」── 出事時你只有它能依靠。 Quarkus 以 JBoss Log Manager 為核心，整合所有主流日誌 API（JBoss Logging、SLF4J、Log4j、JUL）， 並在容器與 Kubernetes 時代提供 JSON 結構化日誌、集中式日誌、OpenTelemetry Logging 等現代化整合。

ℹ︎

你可以在同一個應用裡，業務程式碼用 Log，第三方庫用 SLF4J，Hibernate 用 JBoss Logging ── 所有日誌都會匯入同一個 JBoss Log Manager，配置與輸出一致。

取得 Logger 的四種方式

方式 1：io.quarkus.logging.Log（推薦）

Quarkus 專屬簡化 API。不需要宣告 logger 欄位，所有方法都是 static：

Java · Log API
import io.quarkus.logging.Log;

public class ProductService {

    public Product findById(Long id) {
        Log.infof("查詢產品 id=%d", id);

        try {
            // ...
        } catch (Exception e) {
            Log.errorf(e, "查詢失敗 id=%d", id);    // 帶 exception
            throw e;
        }
        return /* ... */;
    }
}

魔法：Quarkus 在編譯期幫每個使用 Log 的 class 自動產生 private static final Logger 欄位，logger 名稱就是 class 的 FQN。所以你的程式碼乾淨，效能也跟手動宣告完全一樣。

⚠
只能用在「自己的應用程式碼」
io.quarkus.logging.Log 依賴 build-time 改寫，不能用在外部依賴或擴充內部，否則 runtime 會丟例外。 寫擴充或 library 請改用 org.jboss.logging.Logger.getLogger(...)。

方式 2：JBoss Logging（傳統方式）

Java · JBoss Logging
import org.jboss.logging.Logger;

public class ProductService {
    private static final Logger LOG = Logger.getLogger(ProductService.class);

    public Product findById(Long id) {
        LOG.infof("查詢產品 id=%d", id);
        return /* ... */;
    }
}

方式 3：@Inject Logger（CDI bean 限定）

Java · 注入 Logger
@ApplicationScoped
public class ProductService {
    @Inject Logger log;

    public Product findById(Long id) {
        log.infof("查詢產品 id=%d", id);
        return /* ... */;
    }
}

方式 4：SLF4J / Log4j2 / JUL（相容）

若你用習慣 SLF4J，沒問題，Quarkus 會自動橋接到 JBoss Log Manager：

Java · SLF4J
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class ProductService {
    private static final Logger log = LoggerFactory.getLogger(ProductService.class);

    public Product findById(Long id) {
        log.info("查詢產品 id={}", id);    // SLF4J 風格 placeholder
        return /* ... */;
    }
}

日誌等級

Quarkus 支援標準 7 個等級，依嚴重程度排列：

等級數值典型用途
FATAL1100系統無法繼續運作的致命錯誤
ERROR1000業務錯誤、需要關注但應用仍可運作
WARN900可能的問題、降級行為、慢操作
INFO800業務事件、啟動／關閉訊息
DEBUG500除錯資訊，生產通常關閉
TRACE400非常細的執行軌跡，幾乎只在排查問題時開啟

基本配置

所有日誌配置都在 application.properties：

application.properties · 基本配置
# root logger 等級（全域預設）
quarkus.log.level=INFO

# 特定 category 等級（包名）
quarkus.log.category."com.example.shop".level=DEBUG
quarkus.log.category."org.hibernate".level=WARN
quarkus.log.category."io.netty".level=ERROR

# Console handler 格式
quarkus.log.console.format=%d{HH:mm:ss} %-5p [%c{2.}] (%t) %s%e%n
quarkus.log.console.color=true
quarkus.log.console.level=INFO

格式變數（pattern）

變數意義
%d{HH:mm:ss.SSS}日期時間（可自訂格式）
%-5p等級（左對齊，5 字寬）
%ccategory 名稱（logger）
%c{2.}category 縮寫（最後 2 段）
%tthread 名稱
%s訊息
%eexception
%n換行
%X{key}MDC 取值

Build-time minimum level

⚠
Native Image 重要陷阱
Quarkus 有個特殊屬性 quarkus.log.min-level，它是build-time 固定的「最低可能等級」。 若編譯時設成 INFO，那麼 runtime 改為 DEBUG 也不會生效，因為 build 時已把 isDebugEnabled 優化成 false。要在 prod 動態啟用 DEBUG，需 build 時設 quarkus.log.min-level=DEBUG（會犧牲一點效能）。

Categories：分類控制

每個 logger 都屬於一個 category（通常就是 class 的 FQN）。category 之間有階層關係，子繼承父：

application.properties · 階層
# 全域預設
quarkus.log.level=INFO

# com.example 整個包設 DEBUG
quarkus.log.category."com.example".level=DEBUG

# 但 com.example.noisy 太多日誌，只看 WARN
quarkus.log.category."com.example.noisy".level=WARN

# 第三方雜訊
quarkus.log.category."org.apache.kafka.clients".level=WARN
quarkus.log.category."io.netty".level=ERROR
quarkus.log.category."org.hibernate.SQL".level=DEBUG     # 看 SQL
quarkus.log.category."org.hibernate.orm.jdbc.bind".level=TRACE  # 看 SQL 參數

Handlers：輸出目的地

Quarkus 內建幾個 handler，可同時啟用多個：

Console Handler（預設啟用）

application.properties
quarkus.log.console.enable=true
quarkus.log.console.format=%d{HH:mm:ss} %-5p [%c{2.}] (%t) %s%e%n
quarkus.log.console.color=true
quarkus.log.console.level=INFO

File Handler（滾動檔案）

application.properties
quarkus.log.file.enable=true
quarkus.log.file.path=/var/log/catalog/app.log
quarkus.log.file.level=INFO
quarkus.log.file.format=%d{yyyy-MM-dd HH:mm:ss} %-5p [%c] %s%e%n

# 滾動配置（依大小）
quarkus.log.file.rotation.max-file-size=10M
quarkus.log.file.rotation.max-backup-index=20

# 或依時間
quarkus.log.file.rotation.file-suffix=.yyyy-MM-dd
quarkus.log.file.rotation.rotate-on-boot=true

Syslog Handler

application.properties
quarkus.log.syslog.enable=true
quarkus.log.syslog.endpoint=logserver:514
quarkus.log.syslog.protocol=tcp
quarkus.log.syslog.app-name=catalog-service
quarkus.log.syslog.facility=local-use-0
quarkus.log.syslog.level=INFO

JSON 結構化日誌

容器化部署的關鍵需求：日誌必須是結構化的，才能在 ELK / Loki / Datadog 等系統解析、查詢、聚合。

bash · 加 JSON 擴充
quarkus extension add logging-json
application.properties · prod 啟用 JSON
# dev 維持人類可讀
%dev.quarkus.log.console.json=false

# prod 用 JSON 格式
%prod.quarkus.log.console.json=true
%prod.quarkus.log.console.json.pretty-print=false       # 一行一筆
%prod.quarkus.log.console.json.exception-output-type=detailed
%prod.quarkus.log.console.json.additional-field."service.name".value=catalog-service
%prod.quarkus.log.console.json.additional-field."service.version".value=${quarkus.application.version}

輸出範例：

// dev 模式（人類可讀） 14:32:15 INFO [c.e.s.ProductService] (executor-thread-1) 查詢產品 id=42 // prod 模式（JSON 結構化） {"timestamp":"2026-05-14T14:32:15.123Z","sequence":48,"loggerClassName":"org.jboss.logging.Logger","loggerName":"com.example.shop.ProductService","level":"INFO","message":"查詢產品 id=42","threadName":"executor-thread-1","threadId":21,"mdc":{},"ndc":"","hostName":"catalog-7b9c4d-x2k","processName":"java","processId":1,"service.name":"catalog-service","service.version":"1.0.0"}
✓
為什麼 JSON 是雲端原生標準
K8s 把 stdout / stderr 寫入 node 的 log 檔，Fluent Bit / Vector 等 agent 讀取後送到後端。 若日誌是 plain text，agent 需 regex 解析（脆弱、慢）；若是 JSON，欄位直接可用，查詢 level:ERROR AND service.name:catalog 一秒完成。

MDC：請求情境追蹤

MDC（Mapped Diagnostic Context）是個 thread-local 的 key-value map， 讓你把 request ID、user ID、trace ID 等情境附加到該執行緒所有日誌，無需每次手動帶。

Java · MDC 使用
import org.jboss.logging.MDC;

@Path("/products")
public class ProductResource {

    @GET @Path("/{id}")
    public Product get(@PathParam("id") Long id, @Context HttpHeaders headers) {
        String requestId = headers.getHeaderString("X-Request-Id");
        MDC.put("requestId", requestId);
        MDC.put("productId", String.valueOf(id));
        try {
            return service.findById(id);
        } finally {
            MDC.clear();    // 重要：清除以免污染下個請求
        }
    }
}

對應的 format 加入 %X{...}：

application.properties
quarkus.log.console.format=%d{HH:mm:ss} %-5p [%c{2.}] [req=%X{requestId}] %s%e%n

Reactive 環境的 MDC

傳統 MDC 用 ThreadLocal，但響應式程式碼會跨 thread 跳躍，MDC 會丟失。 Quarkus 透過 Context Propagation 解決，需加擴充 quarkus-smallrye-context-propagation（預設多數 reactive 擴充已包含）。 第 21 章會深入。

與 Trace 關聯（OpenTelemetry）

微服務環境一個經典痛點：請求跨多個服務，看日誌時很難拼湊全貌。把 trace ID 寫進日誌，就能用 traceId 把所有相關日誌串起來。

bash · 加 OTel 擴充
quarkus extension add opentelemetry
application.properties · 日誌格式含 trace 資訊
# 把 traceId / spanId 寫進每筆日誌
quarkus.log.console.format=%d{HH:mm:ss} %-5p traceId=%X{traceId} spanId=%X{spanId} [%c{2.}] %s%e%n

# 啟用把所有日誌也送到 OTel collector（OTLP）
quarkus.otel.logs.enabled=true
quarkus.otel.exporter.otlp.endpoint=http://otel-collector:4317

輸出：

14:32:15 INFO traceId=5B8EFFF798038103D269B633813FC60C spanId=EEE19B7EC3C1B174 [c.e.s.ProductService] 查詢產品 id=42 14:32:15 INFO traceId=5B8EFFF798038103D269B633813FC60C spanId=A1B2C3D4E5F6 [c.e.p.PricingClient] 呼叫定價 API

在 Grafana / Jaeger 中可以從一筆 trace 跳到對應日誌、再從日誌跳回 trace，整個請求鏈一目了然。第 36 章會深入 OTel Tracing。

集中式日誌：Graylog / Logstash / Fluentd

若你的後端不用 OTel collector，而是傳統的 Graylog / ELK，Quarkus 提供 GELF 擴充：

bash
quarkus extension add logging-gelf
application.properties
quarkus.log.handler.gelf.enabled=true
quarkus.log.handler.gelf.host=tcp:graylog.internal
quarkus.log.handler.gelf.port=12201
quarkus.log.handler.gelf.facility=catalog-service
quarkus.log.handler.gelf.level=INFO

# 額外欄位
quarkus.log.handler.gelf.additional-field."environment".value=${ENVIRONMENT}
quarkus.log.handler.gelf.additional-field."environment".type=String

日誌最佳實踐

✦
寫好日誌的原則
  1. 用對等級：INFO 是「業務事件」、WARN 是「有點不對勁」、ERROR 是「事情壞了」
  2. 用 placeholder，不用字串拼接：log.infof("query id=%d", id) 而非 "query id=" + id
  3. 記錄關鍵 ID：requestId、userId、orderId 是排查問題的線索
  4. 例外要帶完整 stack：Log.errorf(ex, "失敗") 而非 Log.error(ex.getMessage())
  5. 不要記敏感資料：密碼、信用卡、PII 永遠不該進日誌
  6. 避開 DEBUG 在 hot path：高頻方法即使等級是 DEBUG，字串建構仍會耗效能（用 log.isDebugEnabled() 保護）

避免敏感資料洩漏

Java · ❌ 不要這樣寫
// ❌ 整個 user 物件 toString 可能含密碼、token
Log.infof("登入 user=%s", user);

// ❌ 完整 request body 進日誌
Log.debugf("收到 request: %s", requestBody);

// ✓ 只記必要欄位
Log.infof("登入 userId=%s username=%s", user.id, user.username);

// ✓ 過濾敏感欄位
Log.debugf("收到 request: orderId=%s, items=%d", req.orderId, req.items.size());

DevOps / SRE 視角

容器化日誌標準做法

  1. 只寫 stdout/stderr，不寫檔案（K8s 由 kubelet 收集 stdout）
  2. JSON 格式，所有欄位平鋪可解析
  3. 結構化欄位優於訊息字串：service name、environment、pod name 應該是 JSON 欄位
  4. Fluent Bit / Vector / OTel Collector 部署成 DaemonSet 收集所有 Pod 的 stdout
  5. 後端：Loki（與 Grafana 整合好）、Elasticsearch（功能強但貴）、Datadog Logs（雲端服務）

常見陷阱

症狀原因解法
改 quarkus.log.level 不生效（native） 未調整 quarkus.log.min-level build 時設 quarkus.log.min-level=DEBUG
@QuarkusTest 看不到應用日誌 Surefire 沒設 logging.manager 在 pom.xml 設 -Djava.util.logging.manager=org.jboss.logmanager.LogManager
JSON 日誌沒有 traceId 欄位 OTel 擴充未裝 加 quarkus-opentelemetry
Reactive 程式碼 MDC 丟失 Context propagation 沒生效 確認有 quarkus-smallrye-context-propagation
檔案 handler 寫不出來 容器內 path 無寫權限 改寫 stdout，由 K8s 收集
第三方 library 日誌過多 未個別調整 category quarkus.log.category."org.xxx".level=WARN

本章小結

  • Quarkus 用 JBoss Log Manager 統一後端，相容 JBoss Logging / SLF4J / Log4j / JUL 所有主流 API。
  • 推薦使用 io.quarkus.logging.Log：靜態方法、編譯期改寫、零 boilerplate。
  • 透過 category 精細控制各 package 日誌等級，handlers 同時輸出到 console / file / syslog 等。
  • JSON 結構化日誌是雲端原生標準，加 quarkus-logging-json 即可。
  • MDC 把 request ID、user ID 等情境附加到每筆日誌；reactive 環境需 context propagation。
  • OpenTelemetry Logging（quarkus.otel.logs.enabled=true）把日誌與 trace 關聯，可從 trace 跳到日誌、反之亦然。
  • SRE 紅線：注意 quarkus.log.min-level 是 build-time、避免記錄敏感資料、永遠用 placeholder 而非字串拼接。
