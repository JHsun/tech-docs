OpenShift 部署

OpenShift 是 Red Hat 的企業 K8s 平台，與 Quarkus 有最深度的整合： quarkus-openshift 擴充自動生成 OpenShift 專屬的 DeploymentConfig（或 Deployment）、 Route（取代 Ingress）、ImageStream，並支援 S2I（Source-to-Image） ── 直接從源碼在叢集內建 image。 本章涵蓋兩種部署策略（外部 image 與 S2I 叢集內建），以及 Quarkus 在 OpenShift 上的零配置體驗。

OpenShift vs Kubernetes：關鍵差異

概念KubernetesOpenShift
外部存取IngressRoute（更簡單，自動 TLS）
Image 管理直接拉 imageImageStream（叢集內 registry）
叢集內建 image無原生支援S2I / BuildConfig
安全預設寬鬆嚴格（non-root 強制、SCC）
CI/CD 整合需外部 CITekton Pipelines 原生支援

quarkus-openshift 擴充

bash
quarkus extension add openshift

策略 A：外部 image（CI 建好再部署）

這是最常見的現代做法：CI 建好 image push 到 quay.io / ghcr.io，OpenShift 部署時直接拉。

application.properties
# 使用外部 registry 的 image
quarkus.container-image.registry=quay.io
quarkus.container-image.group=example-org
quarkus.container-image.name=catalog-service
quarkus.container-image.tag=1.4.2

# OpenShift 專屬設定
quarkus.openshift.deployment-kind=Deployment    # 推薦用 Deployment（非 DeploymentConfig）
quarkus.openshift.namespace=catalog-prod
quarkus.openshift.replicas=3

# 生成 Route（HTTP）
quarkus.openshift.route.expose=true
quarkus.openshift.route.host=catalog.apps.ocp.example.com

# TLS route（使用 OpenShift 自動憑證）
quarkus.openshift.route.tls-termination=edge

# Resource 限制
quarkus.openshift.resources.requests.cpu=250m
quarkus.openshift.resources.requests.memory=256Mi
quarkus.openshift.resources.limits.cpu=1000m
quarkus.openshift.resources.limits.memory=512Mi
bash · 一鍵部署
# 登入 OpenShift
oc login --token=sha256~xxx --server=https://api.ocp.example.com:6443

# Build + Deploy（不建 image，用外部 registry）
./mvnw package -Dquarkus.kubernetes.deploy=true

策略 B：S2I 叢集內建（OpenShift 原生體驗）

S2I（Source-to-Image）讓 OpenShift 直接在叢集內從源碼建 image。 不需要 CI，適合快速開發迭代或不能使用外部 registry 的環境：

application.properties · S2I docker 策略
# S2I 用 Docker 策略（用 Dockerfile 在叢集內建）
quarkus.openshift.build-strategy=docker

# 使用 OpenShift 內部 registry
quarkus.container-image.registry=image-registry.openshift-image-registry.svc:5000
quarkus.container-image.group=catalog-prod

# 允許 OpenShift 自簽憑證（常見於企業 OCP）
quarkus.kubernetes-client.trust-certs=true

# 部署到叢集
quarkus.kubernetes.deploy=true
bash · S2I 一鍵建並部署
./mvnw package -Dquarkus.kubernetes.deploy=true

Quarkus 會：

  1. 把 target/quarkus-app/ 上傳到 OpenShift
  2. 觸發 BuildConfig → 在叢集內建 image
  3. image push 到 ImageStream
  4. Deployment 拉 ImageStream 部署

Route：OpenShift 的 Ingress

yaml · 生成的 Route
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: catalog-service
  namespace: catalog-prod
spec:
  host: catalog.apps.ocp.example.com
  to:
    kind: Service
    name: catalog-service
  port:
    targetPort: http
  tls:
    termination: edge              # edge = TLS 在 router 終止，Pod 用 HTTP
    insecureEdgeTerminationPolicy: Redirect

SCC：安全上下文限制

⚠
OpenShift 預設禁止 root 容器
OpenShift 的 restricted SCC（預設）不允許以 root（UID 0）執行容器。
Quarkus 官方 base image 已使用 UID 1001 ── 直接相容。
若自訂 Dockerfile 用了 USER root 會被拒絕，要改成：
USER 1001 或 RUN chown -R 1001 /app && USER 1001

OpenShift Serverless（Knative）

OpenShift Serverless 是 Red Hat 商業化的 Knative。Quarkus 一行設定切換：

application.properties · Knative on OpenShift
# 生成 Knative Service（而非 Deployment）
quarkus.kubernetes.deployment-target=knative

# 配合 OpenShift Serverless
quarkus.openshift.build-strategy=docker
quarkus.kubernetes-client.trust-certs=true
quarkus.kubernetes.deploy=true

Knative 的詳細配置見下一章（ch51 Serverless）。

本章小結

  • OpenShift = Kubernetes + Route + ImageStream + S2I + Tekton + 嚴格安全策略。
  • quarkus-openshift：自動生成 Deployment/Route/ImageStream，一行擴充搞定。
  • 策略 A（外部 image）：CI 建好 push 到 quay.io/ghcr.io，OCP 拉 ── 現代企業主流。
  • 策略 B（S2I 叢集內建）：OpenShift 原生體驗，適合不能用外部 registry 的環境。
  • Route：OpenShift 的 Ingress，edge TLS 終止最常用，自動憑證。
  • SCC：restricted 預設禁 root ── Quarkus 官方 image 已 UID 1001，直接相容。
  • OpenShift Serverless = Knative，用 quarkus.kubernetes.deployment-target=knative 切換。
