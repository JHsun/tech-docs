Chapter 33 · Part VII

Logging

可觀測性的三大訊號 ── logs、metrics、traces ── 當中 logs 最古老、最便宜，也最容易寫爛。 本章從 Quarkus 的 JBoss Logging 基座開始，理解配置怎麼放、為什麼 dev 用人眼可讀格式而 prod 用 JSON、 為什麼MDC（Mapped Diagnostic Context）是分散式系統的命脈、 為什麼async logging 是高吞吐應用必開的選項。 最後用 OpenTelemetry Logging 把 logs 與 traces / metrics 串成一條線。

Logs 給你上下文（user X 下了單失敗，因為庫存查詢回 timeout）； metrics 給你趨勢（過去 5 分鐘 timeout 從 2% 飆到 30%）； traces 給你因果（那一筆 request 在 inventory-service 等了 4.8 秒）。 本章先把 logs 打好底，後面 4 章接 metrics、traces、health、profiling。

Quarkus 的 Logging 基座

Quarkus 用 JBoss Logging + JBoss LogManager（與 WildFly 同源），但所有主流 logging API 都能無縫接上：

來源 API怎麼處理
java.util.logging (JUL)直接走 LogManager
Apache Commons Logging橋接到 JBoss
SLF4J（最常見）橋接到 JBoss
Log4j 1.x / 2.x橋接到 JBoss

意思是 ── 用任何 library，最終都統一從 quarkus.log.* 配置。不要自己拉 logback.xml 或 log4j2.xml，會被忽略或衝突。

寫 log 的兩種風格

Java · 推薦：io.quarkus.logging.Log 靜態方法
import io.quarkus.logging.Log;

@Path("/orders")
public class OrderResource {

    @POST
    public Order create(OrderRequest req) {
        Log.infof("收到訂單請求 user=%s items=%d", req.userId(), req.items().size());
        // ...
        Log.warnf("庫存不足 sku=%s", sku);
        return order;
    }
}

io.quarkus.logging.Log 是 build-time 處理的靜態 logger，類別資訊由 Quarkus 在編譯期注入，不用宣告 private static final Logger LOG = ...。

Java · 傳統：SLF4J / JBoss
// SLF4J 風格
private static final Logger LOG = LoggerFactory.getLogger(OrderResource.class);
LOG.info("收到訂單請求 user={} items={}", userId, items.size());

// JBoss Logging 風格
private static final Logger LOG = Logger.getLogger(OrderResource.class);
LOG.infof("收到訂單請求 user=%s items=%d", userId, items.size());
ℹ︎
用哪一個？
新專案直接用 io.quarkus.logging.Log ── 省一行宣告，build-time 處理零執行期開銷。 既有專案不必硬遷移，但混用要小心 ── 同 class 內用同一個。

Log Level 與 Category

Level 從寬到嚴

Level典型用途
TRACE極詳細逐行流程，平時關閉
DEBUG開發階段細節，prod 通常關
INFO正常業務事件（收到訂單、完成任務）
WARN異常但已自動處理（重試成功、降級觸發）
ERROR業務失敗、需人工介入
FATAL應用無法繼續

Category 分群控制

Quarkus 用 package 名稱當 category（與 Java logging 慣例一致）。可分群設 level：

application.properties
# 全域預設
quarkus.log.level=INFO

# 我自己的 package 開 DEBUG
quarkus.log.category."com.example.catalog".level=DEBUG

# Hibernate SQL log 開 DEBUG（dev 時 debug 用）
%dev.quarkus.log.category."org.hibernate.SQL".level=DEBUG

# 第三方雜訊壓低
quarkus.log.category."io.netty".level=WARN
quarkus.log.category."org.apache.kafka.clients".level=WARN

# 安全相關提高
quarkus.log.category."io.quarkus.security".level=INFO

Console Format：dev 給人看 vs prod 給機器看

application.properties · dev：人眼可讀
%dev.quarkus.log.console.format=%d{HH:mm:ss.SSS} %-5p [%c{1.}] (%t) %s%e%n
%dev.quarkus.log.console.color=true
15:42:18.234 INFO [c.e.c.OrderResource] (executor-thread-1) 收到訂單請求 user=alice items=3
application.properties · prod：JSON 結構化
# 加擴充：quarkus-logging-json
%prod.quarkus.log.console.json.enabled=true
%prod.quarkus.log.console.json.print-details=false  # class/method/line 高成本
%prod.quarkus.log.console.json.pretty-print=false   # 一行一個 JSON
{"timestamp":"2026-05-14T15:42:18.234Z","level":"INFO","loggerName":"com.example.catalog.OrderResource","message":"收到訂單請求 user=alice items=3","mdc":{"traceId":"a3f1...","spanId":"b9d2..."}}
✓
為什麼這樣分
  • dev 模式：你坐在 terminal 前讀 log，色彩 + 緊湊格式最舒服
  • prod 模式：log 進 Loki/ELK/Splunk，機器要 parse ── JSON 才能直接 query
  • 用 %dev. / %prod. profile prefix 自動切換，零手動
pretty-print 在 prod 千萬不要開 ── 一個 log 跨多行會被 log 收集器解析失敗。

MDC：分散式系統的命脈

Mapped Diagnostic Context 是 thread-local（在 Quarkus 是 reactive-context-local）的 key-value 儲存空間。 每筆 log 自動帶上這些 key-value，同一 request 內所有 log 都能用 traceId 串起來。

Java · 在 REST request filter 注入 traceId
import jakarta.annotation.Priority;
import jakarta.ws.rs.Priorities;
import jakarta.ws.rs.container.ContainerRequestContext;
import jakarta.ws.rs.container.ContainerRequestFilter;
import jakarta.ws.rs.ext.Provider;
import org.jboss.logmanager.MDC;
import java.util.UUID;

@Provider
@Priority(Priorities.USER - 100)
public class CorrelationFilter implements ContainerRequestFilter {

    @Override
    public void filter(ContainerRequestContext ctx) {
        // 接受上游傳來的 traceId，或自己產生
        String traceId = ctx.getHeaderString("X-Trace-Id");
        if (traceId == null) {
            traceId = UUID.randomUUID().toString();
        }
        MDC.put("traceId", traceId);
        MDC.put("method", ctx.getMethod());
        MDC.put("path", ctx.getUriInfo().getPath());
    }
}
application.properties · format 加上 MDC
# %X{key} 取 MDC 值
%dev.quarkus.log.console.format=%d{HH:mm:ss.SSS} %-5p [%X{traceId}] [%c{1.}] %s%e%n

# JSON 模式自動把整個 MDC 放進 mdc 物件，無需特別配置
15:42:18.234 INFO [a3f1-9e8c] [c.e.c.OrderResource] 收到訂單請求 user=alice 15:42:18.345 INFO [a3f1-9e8c] [c.e.c.OrderService] 檢查庫存 sku=ABC-123 15:42:18.412 WARN [a3f1-9e8c] [c.e.c.InventoryClient] 庫存查詢 timeout

有 traceId 之後，在 Kibana / Loki 用 traceId=a3f1-9e8c 一查 ── 整條 request 的所有 log 全跳出來。

⚠
Reactive 與 MDC：Quarkus 已替你想好
傳統 Java MDC 是 thread-local，reactive code 跨 thread 切換時會丟。 Quarkus 自己實作了 reactive-aware MDC ── 用 duplicated context（每個 request 一個隔離區）保留 MDC。 REST Client 回 Uni、ManagedExecutor 切換、Vert.x executeBlocking ── 都會自動傳遞 MDC。

命名 Handler：把不同 log 送到不同地方

典型場景：audit log 必須跟業務 log 分檔案，方便合規稽核：

application.properties
# 定義一個叫 "audit" 的命名檔案 handler
quarkus.log.handler.file.audit.enable=true
quarkus.log.handler.file.audit.path=/var/log/catalog/audit.log
quarkus.log.handler.file.audit.level=INFO
quarkus.log.handler.file.audit.format=%d{yyyy-MM-dd'T'HH:mm:ss.SSSZ} AUDIT [%X{traceId}] %s%n
quarkus.log.handler.file.audit.rotation.max-file-size=50M
quarkus.log.handler.file.audit.rotation.max-backup-index=20

# 把 com.example.catalog.audit 這個 logger 接到 audit handler
# 且不走 root handler（不污染主 log）
quarkus.log.category."com.example.catalog.audit".handlers=audit
quarkus.log.category."com.example.catalog.audit".use-parent-handlers=false
quarkus.log.category."com.example.catalog.audit".level=INFO
Java · audit logger 寫稽核
package com.example.catalog.audit;
import org.jboss.logging.Logger;

@ApplicationScoped
public class AuditLogger {
    private static final Logger LOG = Logger.getLogger(AuditLogger.class);

    public void orderPlaced(String userId, Long orderId, BigDecimal amount) {
        LOG.infof("ORDER_PLACED user=%s orderId=%d amount=%s", userId, orderId, amount);
    }

    public void permissionDenied(String userId, String resource) {
        LOG.warnf("PERMISSION_DENIED user=%s resource=%s", userId, resource);
    }
}

這個 logger 寫的內容只進 audit.log，主應用 log 完全不會看到 ── 合規場景必備。

Async Logging：高吞吐必開

每次 Log.info() 預設是同步寫出 ── 在高 QPS 下會塞住 request thread。打開 async 後，log 寫入丟給專用 thread 處理：

application.properties
# Console async
%prod.quarkus.log.console.async=true
%prod.quarkus.log.console.async.queue-length=1024
%prod.quarkus.log.console.async.overflow=DISCARD

# File async（檔案寫入更值得 async）
%prod.quarkus.log.file.async=true
%prod.quarkus.log.file.async.queue-length=512
Overflow 策略行為適用
BLOCKqueue 滿時阻塞呼叫者（預設）確保不丟 log，但會拖慢 request
DISCARDqueue 滿時丟掉新 log業務日誌：寧可丟也不能慢
⚠
Audit log 永遠用 BLOCK，業務 log 可以 DISCARD
Audit / 合規日誌不能丟，寧可慢；業務 log 可以接受極端情況下丟一些。設策略前先想清楚這條 log 的角色。

檔案 Rotation

application.properties
quarkus.log.file.enable=true
quarkus.log.file.path=/var/log/catalog/app.log

# Size-based rotation
quarkus.log.file.rotation.max-file-size=100M
quarkus.log.file.rotation.max-backup-index=10
quarkus.log.file.rotation.file-suffix=.yyyy-MM-dd

# 也可改成 time-based rotation（每天一檔）
# 設了 file-suffix（含日期格式）即啟用 time rotation
⚠
K8s 上的真實
在 K8s 上多數情況不該寫檔：寫到 stdout，讓 K8s log collector（Fluentd / Vector / Promtail）抓走。 寫檔的場景：audit log 需保存到 PVC、或 sidecar 模式特別處理。

敏感資訊 mask

Logs 是合規地雷區：credit card 號、SSN、密碼意外進 log 就是 OWASP A09 (Logging Failures)。

方法 A：自訂 Formatter

Java · 自訂 mask formatter
import org.jboss.logmanager.ExtFormatter;
import org.jboss.logmanager.ExtLogRecord;
import java.util.regex.Pattern;

public class MaskingFormatter extends ExtFormatter {

    private static final Pattern CARD = Pattern.compile("\\b\\d{13,16}\\b");
    private static final Pattern EMAIL = Pattern.compile("[\\w.-]+@[\\w.-]+");

    @Override
    public String format(ExtLogRecord record) {
        String msg = record.getFormattedMessage();
        msg = CARD.matcher(msg).replaceAll("****-****-****-****");
        msg = EMAIL.matcher(msg).replaceAll(m -> {
            String email = m.group();
            int at = email.indexOf('@');
            return email.charAt(0) + "***" + email.substring(at);
        });
        return "%s %-5s [%s] %s%n".formatted(
            record.getInstant(), record.getLevel(),
            record.getLoggerName(), msg);
    }
}

方法 B：源頭就不要記

最佳實踐：用結構化欄位明確區隔，敏感欄位根本不進 log。

Java · ❌ 危險
Log.infof("處理付款 request=%s", request);  // 整個物件 toString 可能含卡號
Java · ✓ 安全
Log.infof("處理付款 userId=%s amount=%s last4=%s",
          request.userId(), request.amount(), request.cardLast4());

OpenTelemetry Logging：統一三大訊號

傳統做法：log 走一條 pipeline（Fluentd → Elasticsearch），traces 走另一條（Jaeger），metrics 又一條（Prometheus）。 OpenTelemetry 把三者統一成同一個協定 OTLP，後端可以是 Grafana Tempo + Loki + Mimir 或廠商 SaaS。

✓
最大好處：log 與 trace 自動關聯
啟用後，每筆 log 自動帶上當前 span 的 traceId 與 spanId，在 Grafana 點任何一筆 log，可直接跳到對應的 trace 看完整 request 流。 這個關聯是 OTel 出現的主因。

DevOps / SRE 視角

✓
Logging 上線 checklist
  1. Prod 必開 JSON：機器可解析才能 query
  2. MDC 帶 traceId、userId、tenantId：分散式系統的命脈
  3. Async logging：console + file 都開，business 用 DISCARD、audit 用 BLOCK
  4. 第三方雜訊壓 WARN：Netty、Kafka client、Hibernate SQL 是 noise 大戶
  5. K8s 寫 stdout，不寫檔：除非 audit 等特殊需求
  6. 檔案 rotation：max-file-size + max-backup-index 避免塞滿磁碟
  7. 敏感資訊 mask 或源頭不記：OWASP A09
  8. OpenTelemetry 統一：log/metric/trace 同協定、可關聯
  9. log volume budget：每 service 每天設上限，超過 alert（成本與信噪比）
  10. 禁用 println / printStackTrace：CI 加 checkstyle 規則

Log volume 經濟學

⚠
Log 是有成本的
一個 microservice 每天 1GB log × 50 個服務 × 30 天 = 1.5TB ── Loki / Splunk / Datadog 帳單會嚇人。 控制原則：
  • INFO 是業務事件，不是每行流程：每筆訂單 1-3 條 INFO 已足夠
  • 不要 log 進迴圈：批次處理改成「處理 N 筆完成」
  • sampling：trace-level log 抽樣 1%
  • 動態 level：Dev UI 或 K8s ConfigMap 改 level，不重啟 Pod

常見陷阱

症狀原因解法
Log 設定不生效 放了 logback.xml 或 log4j.properties 刪掉；統一用 application.properties
reactive 中 MDC 不見 用 SLF4J 的 MDC 而非 JBoss 的 用 org.jboss.logmanager.MDC
JSON log 多行 / 跨 line pretty-print=true prod 設 false
K8s 看不到 log 寫到檔案而非 stdout 關 file handler，console enable
磁碟塞滿 沒設 rotation 設 max-file-size + max-backup-index
啟動 hang 住沒 log async queue 太小被 BLOCK，啟動瞬間 burst 啟動階段先 sync，啟動完再 async；或調大 queue
性能差 + log 量大 I/O 阻塞 async logging
log 中看到密碼 / 卡號 沒做 mask / 直接 toString 整個物件 用結構化欄位 + 自訂 formatter mask

本章小結

  • 三大訊號分工：logs（發生什麼）、metrics（多少）、traces（時間花在哪），互補不替代。
  • Quarkus 底層是 JBoss Logging + LogManager，自動橋接 SLF4J / Log4j / JUL；不要自帶 logback.xml。
  • 寫 log 用 io.quarkus.logging.Log 靜態方法，省一行宣告，build-time 處理。
  • Level 從 TRACE 到 FATAL；Category 按 package 設不同 level。
  • dev 用 plain + color、prod 用 JSON，用 %dev. / %prod. profile prefix 自動切。
  • MDC 是分散式系統的命脈：在 request filter 注入 traceId / userId，所有 log 自動帶上。
  • Quarkus 的 MDC 是 reactive-aware，跨 thread 不丟失。
  • 命名 Handler：audit log 獨立檔案 + 不走 root handler。
  • Async logging 高吞吐必開；business log 用 DISCARD、audit 用 BLOCK。
  • K8s 環境寫 stdout 讓 log collector 抓，不寫檔（audit 例外）。
  • 敏感資訊：自訂 formatter mask、或源頭就用結構化欄位不記敏感物件。
  • OpenTelemetry Logging 統一三大訊號協定，log 自動帶 traceId/spanId，與 trace 雙向跳轉。
  • SRE 重點：JSON + MDC + async、log volume budget、動態 level、CI 擋 println。
