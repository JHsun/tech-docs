配置管理

配置看似簡單，卻是 Java 應用最常踩坑的地方：寫死成 production 上線、密碼明文進 Git、profile 切換錯誤…… Quarkus 採用 MicroProfile Config 標準 + SmallRye Config 實作，提供 類型安全、profile 感知、可加密、可注入的完整配置體系。本章建立你的配置心智模型。

Quarkus 配置哲學

Quarkus 的配置基於兩個業界標準：

  • MicroProfile Config：Eclipse 規範，定義配置 API 與來源。
  • SmallRye Config：Red Hat 維護的 MicroProfile Config 實作，並擴充了 @ConfigMapping、Profiles 等強大功能。
一份 application.properties，從筆電到 Kubernetes 全程通用。

核心設計原則

  1. 單一配置入口：application.properties 或 application.yaml 統一管理
  2. 多來源合併：系統屬性、環境變數、檔案、Kubernetes Secret 都可作為來源
  3. 優先順序明確：高優先級覆寫低優先級，無神祕行為
  4. 類型安全：透過 @ConfigMapping 把字串轉成強型別物件
  5. Profile 感知：%dev、%test、%prod 自動切換

配置來源與優先順序

當同一個屬性出現在多個來源，Quarkus 依照優先順序決定使用哪個值。優先級越高（數字越大）越先勝出：

400
System Properties（系統屬性） -Dquarkus.http.port=9090 啟動時指定
優先級最高
300
Environment Variables（環境變數） QUARKUS_HTTP_PORT=9090 或從 K8s Secret 注入
大寫底線
295
.env 檔（當前工作目錄） 本機開發用，不要進 Git
.env
260
$PWD/config/application.properties 部署目錄旁的外部配置，方便 ops 修改
外部
250
application.properties / application.yaml classpath 中的主要配置檔
主檔
100
microprofile-config.properties MicroProfile 規範要求的傳統檔名
優先級最低
ℹ︎
屬性命名轉換規則
Quarkus 自動處理三種寫法：
  • quarkus.http.port ─ properties 格式
  • QUARKUS_HTTP_PORT ─ 環境變數（任何非字母數字都變底線）
  • quarkus.http.port ─ yaml 巢狀結構
所以你在 K8s 設環境變數時用 QUARKUS_DATASOURCE_USERNAME，等同於 properties 的 quarkus.datasource.username。

Properties vs YAML

Quarkus 預設使用 application.properties，但可加擴充改用 YAML：

properties · 預設
quarkus.http.port=8080
quarkus.http.cors.enabled=true
quarkus.http.cors.origins=https://example.com,https://admin.example.com

quarkus.log.level=INFO
quarkus.log.category."com.example".level=DEBUG

app.greeting=Hello
app.features.search.enabled=true
app.features.cart.max-items=99
yaml · 需 quarkus-config-yaml 擴充
quarkus:
  http:
    port: 8080
    cors:
      enabled: true
      origins:
        - https://example.com
        - https://admin.example.com
  log:
    level: INFO
    category:
      "com.example":
        level: DEBUG

app:
  greeting: Hello
  features:
    search:
      enabled: true
    cart:
      max-items: 99
bash · 啟用 YAML 支援
quarkus extension add config-yaml
ℹ︎
該用哪一個？
properties：簡單扁平結構、配置量少、團隊熟悉 Spring Boot。
yaml：巢狀深、list 多、需要註解區塊。
本書範例以 properties 為主，因為它少一個依賴、行為一致，且環境變數轉換更直觀。

注入單一屬性：@ConfigProperty

最基本的注入方式來自 MicroProfile Config：

Java · @ConfigProperty 基本用法
import org.eclipse.microprofile.config.inject.ConfigProperty;

@ApplicationScoped
public class GreetingService {

    @ConfigProperty(name = "app.greeting")
    String greeting;

    @ConfigProperty(name = "app.greeting.suffix", defaultValue = "!")
    String suffix;

    @ConfigProperty(name = "app.greeting.name")
    Optional<String> name;     // 可選屬性，沒設定時為 empty

    public String hello() {
        return greeting + (name.orElse("World")) + suffix;
    }
}

對應 application.properties：

application.properties
app.greeting=Hello, 
# app.greeting.suffix 未設定 → 使用 defaultValue "!"
# app.greeting.name 未設定 → Optional.empty()

支援的型別包括：

  • 原始型別與包裝類別（int、boolean、Long 等）
  • String、URL、URI、Duration、Path 等
  • List<T>、Set<T>（用逗號分隔）
  • Optional<T>
  • 自訂 Converter<T> 註冊的型別

類型安全：@ConfigMapping

@ConfigProperty 適合零星屬性，但配置一多就到處散落。 @ConfigMapping 是 SmallRye 提供的進階機制，將一組相關配置綁定到一個 interface， 類似 Spring 的 @ConfigurationProperties。

Java · ConfigMapping interface
import io.smallrye.config.ConfigMapping;
import io.smallrye.config.WithDefault;
import io.smallrye.config.WithName;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.Max;
import java.util.List;
import java.util.Optional;

@ConfigMapping(prefix = "app")
public interface AppConfig {

    String greeting();

    @WithDefault("!")
    String suffix();

    Optional<String> name();

    Features features();   // 巢狀結構

    interface Features {
        Search search();
        Cart cart();

        interface Search {
            boolean enabled();
        }

        interface Cart {
            @Min(1) @Max(999)
            @WithDefault("99")
            int maxItems();
        }
    }

    @WithName("origins")    // 對應 app.origins.list（可改實際 key 名稱）
    List<String> allowedOrigins();
}

使用方式：直接注入 interface，Quarkus 在編譯期生成實作：

Java · 注入並使用
@ApplicationScoped
public class GreetingService {

    private final AppConfig config;

    public GreetingService(AppConfig config) {  // constructor 注入
        this.config = config;
    }

    public String hello() {
        return config.greeting() + config.name().orElse("World") + config.suffix();
    }

    public int cartLimit() {
        return config.features().cart().maxItems();
    }
}
✓
為什麼推薦 @ConfigMapping
  • 類型安全：編譯期錯誤捕獲，IDE 自動補全
  • 結構清晰：相關配置聚集成樹，巢狀對應 properties 命名
  • 啟動驗證：屬性缺失或型別不符，啟動時立即失敗，而非執行時才爆
  • Bean Validation 整合：可加 @Min、@Max、@NotNull 等
  • 無 reflection：Native Image 友善

Profiles：環境感知配置

同一份 application.properties，在 dev / test / prod 不同環境需要不同值。 Quarkus Profile 機制讓你用 %profile. 前綴覆寫屬性：

application.properties · Profile 用法
# 預設值（dev / test / prod 皆生效）
app.greeting=Hello

# dev profile 覆寫
%dev.app.greeting=Hello (dev mode)
%dev.quarkus.log.level=DEBUG

# test profile 覆寫
%test.app.greeting=Hello (testing)

# prod profile 覆寫
%prod.app.greeting=Welcome
%prod.quarkus.log.level=WARN
%prod.quarkus.datasource.jdbc.url=${DB_URL}
%prod.quarkus.datasource.username=${DB_USER}
%prod.quarkus.datasource.password=${DB_PASSWORD}

內建 Profile

Profile啟動方式用途
devquarkus dev / mvn quarkus:dev開發模式，Live Reload + Dev Services 啟用
testmvn test / @QuarkusTest測試模式，Dev Services 啟用
prodjava -jar / native binary生產模式，Dev Services 停用

自訂 Profile

除了內建三個，可定義自己的 profile：

application.properties · 自訂 staging profile
%staging.app.greeting=Hello (staging)
%staging.quarkus.log.level=INFO
%staging.quarkus.datasource.jdbc.url=jdbc:postgresql://staging-db:5432/app

啟動時指定：

bash · 三種啟動 staging profile 的方法
# 方法 1：系統屬性
java -Dquarkus.profile=staging -jar quarkus-run.jar

# 方法 2：環境變數（K8s 慣用）
export QUARKUS_PROFILE=staging
java -jar quarkus-run.jar

# 方法 3：dev mode 也支援
quarkus dev -Dquarkus.profile=staging

Profile-aware 檔案

當配置量大時，可拆成獨立檔案：

專案結構
src/main/resources/
├── application.properties          ← 預設與共用
├── application-dev.properties      ← dev 專屬
├── application-staging.properties  ← staging 專屬
└── application-prod.properties     ← prod 專屬

檔案內不需要加 %dev. 前綴，因為檔名已表明 profile：

application-prod.properties
# 不需要 %prod. 前綴
app.greeting=Welcome
quarkus.log.level=WARN
quarkus.datasource.jdbc.url=${DB_URL}

Property Expressions：屬性引用與環境變數注入

Quarkus 支援在屬性值中引用其他屬性或環境變數，語法是 ${...}：

application.properties · 表達式範例
# 引用環境變數
quarkus.datasource.username=${DB_USER}

# 帶預設值
quarkus.datasource.password=${DB_PASSWORD:default-password}

# 引用其他屬性
app.base-url=https://api.example.com
app.users-endpoint=${app.base-url}/users

# 巢狀引用
app.tier=${TIER:dev}
app.cache.size=${CACHE_${app.tier}:100}     # 對應 CACHE_DEV、CACHE_PROD

# 內建特殊變數
mp.messaging.incoming.events.group.id=consumer-${quarkus.uuid}

Quarkus 內建表達式

表達式說明
${quarkus.uuid}啟動時隨機產生的 UUID，每次啟動不同（dev mode reload 也會變）
${MP_REGISTER_KEY}從環境變數讀
${user.home}JDK 系統屬性

Secrets：加密敏感資訊

生產環境的密碼、API key、TLS 私鑰絕不能明文進 Git。Quarkus 提供 SmallRye Config Secret Keys 機制，讓配置中可放加密值，啟動時用 key 解密。

方法 1：使用 AES-GCM-NoPadding 加密（內建）

application.properties · 加密屬性
# 加密後的密碼
quarkus.datasource.password=${aes-gcm-nopadding::DJNrZ6LfpupFv6QbXyXhvzD8eVDnDa_kTliQBpuzTobDZxlg}

# 解密金鑰（這個本身必須從環境變數注入，絕不能放 Git）
smallrye.config.secret-handler.aes-gcm-nopadding.encryption-key=${ENCRYPTION_KEY}

運作流程：

sequenceDiagram
  participant App as Quarkus 啟動
  participant Cfg as Config Layer
  participant KMS as 環境變數
ENCRYPTION_KEY
  participant Code as 你的程式碼

  App->>Cfg: 讀取 application.properties
  Cfg->>Cfg: 偵測 ${aes-gcm-nopadding::...}
  Cfg->>KMS: 取 ENCRYPTION_KEY
  KMS-->>Cfg: 金鑰
  Cfg->>Cfg: 用金鑰解密 secret
  Cfg-->>Code: 注入解密後的明文

圖 5-1 ─ Secret Keys 解密流程：應用啟動時自動解密，業務程式只看到明文

方法 2：搭配 Vault / Kubernetes Secret

更現代的做法是不在應用層管金鑰，而是讓 K8s 注入：

k8s/secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: catalog-secrets
type: Opaque
stringData:
  DB_PASSWORD: "real-db-password"
  API_KEY: "real-api-key"
k8s/deployment.yaml · 摘錄
spec:
  containers:
  - name: catalog
    image: catalog:1.0
    envFrom:
    - secretRef:
        name: catalog-secrets
application.properties · 引用環境變數
%prod.quarkus.datasource.password=${DB_PASSWORD}
%prod.app.external-api.key=${API_KEY}

方法 3：Kubernetes Config Source 擴充

讓 Quarkus 直接從 Kubernetes API 讀 ConfigMap / Secret：

bash
quarkus extension add kubernetes-config
application.properties
%prod.quarkus.kubernetes-config.enabled=true
%prod.quarkus.kubernetes-config.config-maps=catalog-config
%prod.quarkus.kubernetes-config.secrets.enabled=true
%prod.quarkus.kubernetes-config.secrets=catalog-secrets

Quarkus 會自動生成所需的 ServiceAccount / Role / RoleBinding。

⚠
不要在 Git 放金鑰
所有加密 secret 的解密金鑰本身一定要透過環境變數、Vault、KMS、或 K8s Secret 注入。 把金鑰直接寫進 application.properties 等於把保險箱跟鑰匙放在一起。

Build-time vs Runtime 配置

這是 Quarkus 獨特的概念，也是最常困惑開發者的地方。 Quarkus 把某些配置在編譯期就決定（為了 Native Image 優化），無法在執行期動態改變：

  classDef run fill:__SOFT_OK__,stroke:__OK__,color:__TXT__,font-weight:bold

  BuildTime --> |鎖定後不可改| App[最終應用]
  RunTime --> |可由環境變數覆寫| App

圖 5-2 ─ Build-time 配置鎖定在打包階段，runtime 配置可用環境變數動態覆寫

如何分辨？

查官方 Configuration Reference Guide，每個屬性都標示了類型：

圖示類型能否在生產覆寫
🔒Build-time fixed❌ 不能，需重新編譯
無Runtime overridable✓ 可用環境變數或 -D 覆寫
⚠
SRE 常見痛點
團隊在 dev 環境一切正常，但部署到 prod 時想用環境變數開關某個功能，發現「怎麼改都沒效果」。 原因通常是改到了 build-time 屬性。解法：用 @IfBuildProperty + @UnlessBuildProperty 搭配「多個 build 產出」策略，或改為 runtime 等效屬性。

Dev UI Configuration 介面

http://localhost:8080/q/dev-ui → Configuration 卡片，列出當前所有配置值與來源。 在 dev mode 可直接修改並立即生效（不需重啟）。

程式內查詢

Java · 程式內查詢配置
import org.eclipse.microprofile.config.Config;
import org.eclipse.microprofile.config.ConfigProvider;

Config config = ConfigProvider.getConfig();

// 取值
String greeting = config.getValue("app.greeting", String.class);

    System.out.println(src.getName() + " (ordinal=" + src.getOrdinal() + ")")

DevOps / SRE 視角：四環境配置策略

本節示範一個真實生產級配置策略，分四環境：local（筆電）、dev、staging、prod。

application.properties · 完整四環境範例
### 共用基底（所有環境）
quarkus.application.name=catalog-service
quarkus.http.port=8080

app.greeting=Hello

### dev profile（本機 + Dev Services）
%dev.quarkus.log.level=DEBUG
%dev.quarkus.hibernate-orm.log.sql=true
# datasource 留空，讓 Dev Services 自動啟動

### test profile
%test.quarkus.log.level=INFO

### staging profile
%staging.quarkus.log.level=INFO
%staging.quarkus.datasource.jdbc.url=jdbc:postgresql://staging-db.internal:5432/catalog
%staging.quarkus.datasource.username=${DB_USER}
%staging.quarkus.datasource.password=${DB_PASSWORD}
%staging.quarkus.hibernate-orm.database.generation=update

### prod profile
%prod.quarkus.log.level=WARN
%prod.quarkus.log.console.json=true
%prod.quarkus.datasource.jdbc.url=${DB_URL}
%prod.quarkus.datasource.username=${DB_USER}
%prod.quarkus.datasource.password=${DB_PASSWORD}
%prod.quarkus.hibernate-orm.database.generation=validate
%prod.quarkus.devservices.enabled=false

啟動時驗證配置

為了避免「部署上去才發現環境變數沒設」的悲劇，用 @ConfigMapping + 啟動 hook 驗證：

Java · 啟動驗證
@ConfigMapping(prefix = "app.external-api")
public interface ExternalApiConfig {
    @NotBlank   // Bean Validation：缺值時啟動失敗
    String baseUrl();

    @NotBlank
    String apiKey();

    @Min(100) @Max(60000)
    @WithDefault("3000")
    int timeoutMs();
}

@ApplicationScoped
public class ConfigValidator {
    void onStart(@Observes StartupEvent ev, ExternalApiConfig cfg) {
        Log.infof("External API: %s (timeout=%dms)", cfg.baseUrl(), cfg.timeoutMs());
    }
}

來源優先級實戰：K8s 環境

典型 K8s 部署的配置覆寫鏈：

# 開發筆電 $ quarkus dev ↓ 使用 %dev 配置，Dev Services 拉資料庫 # 部署到 staging $ kubectl apply -f staging/ ↓ Pod env QUARKUS_PROFILE=staging ↓ Pod envFrom secretRef catalog-secrets-staging ↓ 應用啟動 → 套用 %staging 配置，DB_URL/DB_PASSWORD 來自 Secret # 部署到 prod $ kubectl apply -f prod/ ↓ Pod env QUARKUS_PROFILE=prod ↓ envFrom secretRef catalog-secrets-prod + configMapRef catalog-config ↓ %prod 配置生效，all secrets 來自 K8s Secret

常見陷阱

症狀原因解法
環境變數設了卻沒生效 命名轉換錯誤 用大寫底線：quarkus.http.port → QUARKUS_HTTP_PORT
profile 沒切換 QUARKUS_PROFILE 拼錯或未設定 啟動 log 找 Profile prod activated 確認
「config property is required」 必填屬性缺值 加 defaultValue、改 Optional、或補上設定
覆寫 build-time 屬性無效 該屬性是 build-time fixed 查 Config Reference 確認類型，需重新打包
List 解析錯誤 含逗號的字串 用 \\ 跳脫，或改用 indexed key（app.list[0]=A）
Native Image 找不到屬性 build-time 配置在 native 編譯前未設定 build 時就要把 build-time 屬性傳入：mvn package -Dnative -Dapp.x=y

本章小結

  • Quarkus 配置基於 MicroProfile Config + SmallRye Config，標準清楚、實作強大。
  • 來源優先級：System Properties > Env Vars > .env > 外部 properties > classpath properties。
  • @ConfigProperty 適合零星屬性，@ConfigMapping 是推薦做法：類型安全、結構清晰、啟動即驗證。
  • Profiles 用 %dev.、%prod. 前綴，或拆 application-{profile}.properties。
  • Property Expressions (${...}) 是引用環境變數的標準語法，可帶預設值。
  • Secrets 三種策略：內建 AES 加密、環境變數注入、Kubernetes Config Source 擴充。
  • 留意 build-time vs runtime 屬性差異 ── 這是 Quarkus 獨特概念。
  • 生產配置一律用 %prod. 前綴明確隔離，並用啟動 hook 驗證關鍵屬性。
