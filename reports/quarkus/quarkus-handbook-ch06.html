CDI 與依賴注入

Quarkus 的依賴注入容器叫 ArC，實作 Jakarta CDI Lite 4.1 規範，但有個關鍵差異： 所有 DI 圖在編譯期就解析完成。這讓你失去某些 reflection 動態能力， 但換來秒級啟動、native image 友善、和啟動前的型別錯誤捕獲。

為什麼 Quarkus 自己做一套 DI 容器

CDI 規範自 2009 年起就是 Jakarta EE 標準，傳統實作有 Weld（WildFly 用）、OpenWebBeans 等。 Quarkus 選擇實作自己的 CDI 容器 ArC，原因是：

  • 傳統 CDI 大量依賴 runtime reflection：啟動時掃描 classpath、產生 proxy、解析依賴圖
  • 對 Native Image 不友善：reflection 必須事先註冊，PortableExtension 無法用
  • 啟動時間慢：典型 Weld 應用啟動需 2~5 秒

ArC 的設計反其道而行：編譯期完成大部分工作。 Maven 跑到 mvn package 時，ArC 已經分析了所有 Bean、解析完依賴圖、產生對應的 Java bytecode。 執行時只剩「載入這份預先計算好的結構」這件事。

把 reflection 從 runtime 推到 build-time，這就是 Quarkus 速度的祕密。

最簡單的依賴注入

從一個典型的 Service-Repository 結構開始：

Java · 基本 DI
import jakarta.enterprise.context.ApplicationScoped;
import jakarta.inject.Inject;

@ApplicationScoped
public class ProductRepository {
    public Product findById(Long id) {
        return /* ... */;
    }
}

@ApplicationScoped
public class ProductService {

    @Inject
    ProductRepository repository;       // field 注入

    public Product getProduct(Long id) {
        return repository.findById(id);
    }
}

注意兩個關鍵：

  1. 類別上的 scope 註解（如 @ApplicationScoped）讓 ArC 認為它是個 Bean
  2. 欄位上的 @Inject 標示注入點，由 ArC 在編譯期解析並注入

Quarkus 推薦：Constructor 注入

雖然 field 注入語法最短，但 Quarkus 官方更推薦 constructor 注入：

Java · Constructor 注入（推薦）
@ApplicationScoped
public class ProductService {

    private final ProductRepository repository;

    public ProductService(ProductRepository repository) {  // 唯一 constructor，@Inject 可省略
        this.repository = repository;
    }
}

優點：

  • final 欄位：強制不可變，符合 OOP 最佳實踐
  • 容易單元測試：直接 new ProductService(mockRepo)
  • 顯式依賴：constructor 參數一目了然
  • 唯一 constructor 時 @Inject 可省略：程式碼更乾淨
✓
Native Image 提示
Quarkus 建議用 package-private 修飾（不寫 private）注入欄位、建構子、方法， 避免 ArC 退回到 reflection 路徑。這對 native image 體積與啟動更友善。

Bean Scope（生命週期）

Scope 決定一個 Bean 的生命週期：什麼時候建立、什麼時候銷毀、被哪些注入點共享。 Quarkus 支援的 Scope 與 Spring 對照：

Quarkus / CDISpring 等價生命週期典型用途
@ApplicationScoped@Component (singleton)應用啟動到關閉無狀態 Service、Repository（最常用）
@Singleton@Component同上，但無 client proxy需要高效能、不需要 proxy 的工具類
@RequestScoped@RequestScope單一 HTTP 請求期間請求上下文、user info
@SessionScoped@SessionScopeHTTP session 期間使用者 session 狀態（傳統 web app）
@Dependent@Scope("prototype")跟隨注入點的生命週期輕量物件、每次注入不同實例
@TransactionScoped—單一 JTA 交易期間交易內部狀態

@ApplicationScoped vs @Singleton 差異

兩者都是「整個應用共享一個實例」，但 @ApplicationScoped 會建立 client proxy：

Java · proxy 差異
@ApplicationScoped       // 注入時拿到的是 proxy，真正的 instance 在第一次呼叫時才建立
public class CachingService { ... }

@Singleton               // 注入時拿到的就是真正的 instance（lazy 但無 proxy）
public class CounterService { ... }

Client proxy 有幾個好處：

  • 解決循環依賴：A 注入 B，B 注入 A，proxy 讓兩者都能成功初始化
  • 方便測試替換：mock 替換時不需重啟容器
  • 支援 lazy 初始化：建立 instance 的時機推遲到第一次呼叫
ℹ︎
預設選 @ApplicationScoped
Quarkus 官方建議無特殊情況一律用 @ApplicationScoped。@Singleton 省了 proxy 的些微開銷，但失去循環依賴解析能力，僅在效能極度敏感的工具類使用。

Imperative vs Reactive：對應的 DI 模式

同一個 Service 在命令式與響應式寫法的 DI 沒有差別，差別只在於回傳型別：

Java · Imperative
@ApplicationScoped
public class ProductService {

    private final ProductRepository repository;

    public ProductService(ProductRepository repository) {
        this.repository = repository;
    }

    public List<Product> listAll() {
        return repository.findAll();          // 阻塞呼叫
    }
}
Java · Reactive (Mutiny)
@ApplicationScoped
public class ProductService {

    private final ProductRepository repository;

    public ProductService(ProductRepository repository) {
        this.repository = repository;
    }

    public Uni<List<Product>> listAll() {
        return repository.findAll();           // 非阻塞，回傳 Uni
    }
}

Qualifier：消歧義

當同型別有多個 Bean 時，光靠型別無法判斷要注入哪個，這時需要 Qualifier：

Java · Qualifier 定義
import jakarta.inject.Qualifier;
import java.lang.annotation.*;

@Qualifier
@Retention(RetentionPolicy.RUNTIME)
@Target({ ElementType.FIELD, ElementType.PARAMETER, ElementType.TYPE })
public @interface PaymentGateway {
    Type value();
    enum Type { STRIPE, PAYPAL, MOCK }
}
Java · 使用 Qualifier
@PaymentGateway(Type.STRIPE)
@ApplicationScoped
public class StripePaymentService implements PaymentService { ... }

@PaymentGateway(Type.PAYPAL)
@ApplicationScoped
public class PayPalPaymentService implements PaymentService { ... }

// 注入時明確指定
@ApplicationScoped
public class OrderService {

    @Inject @PaymentGateway(Type.STRIPE)
    PaymentService stripe;

    @Inject @PaymentGateway(Type.PAYPAL)
    PaymentService paypal;
}
⚠
不要用 @Named
CDI 也支援 @Named("stripe") 字串型 qualifier，但不建議： 與預設 @Default qualifier 互動可能衝突，且字串容易拼錯。 要用字串改用 Quarkus 專屬的 @Identifier("stripe")。

Producer Methods：把第三方類別變成 Bean

若你想注入不是自己寫的類別（如 RestTemplate、自訂的 thread pool），它沒辦法加 @ApplicationScoped。 解法：寫 producer method，由 ArC 呼叫它取得 Bean instance：

Java · Producer 範例
@ApplicationScoped
public class InfrastructureProducer {

    @Produces
    @ApplicationScoped
    public ObjectMapper objectMapper() {
        ObjectMapper m = new ObjectMapper();
        m.registerModule(new JavaTimeModule());
        return m;
    }

    @Produces
    @ApplicationScoped
    @Named("io-pool")
    public ExecutorService ioExecutor() {
        return Executors.newVirtualThreadPerTaskExecutor();  // JDK 21 虛擬執行緒
    }
}

// 使用
@ApplicationScoped
public class JsonService {
    @Inject ObjectMapper mapper;             // 由 producer 提供
    @Inject @Named("io-pool") ExecutorService pool;
}

Quarkus 簡化：跳過 @Produces

Quarkus 對 producer 做了優化：若方法已標 scope，@Produces 可省略。

Java · 簡化版（Quarkus 專屬）
@ApplicationScoped
public class InfrastructureProducer {

    @ApplicationScoped       // 隱含 @Produces
    public ObjectMapper objectMapper() { ... }
}

@Alternative 與 @IfBuildProfile：環境切換

需要在不同環境注入不同實作？兩種寫法：

方法 1：@Alternative + @Priority

Java · Alternative 模式
@ApplicationScoped
public class StripePaymentService implements PaymentService { ... }

@Alternative
@Priority(1)
@ApplicationScoped
public class MockPaymentService implements PaymentService { ... }
application.properties · 啟用 alternative
%test.quarkus.arc.selected-alternatives=MockPaymentService

方法 2：@IfBuildProfile（Quarkus 專屬，更直觀）

Java · @IfBuildProfile
@IfBuildProfile("prod")
@ApplicationScoped
public class StripePaymentService implements PaymentService { ... }

@IfBuildProfile("dev")
@ApplicationScoped
public class MockPaymentService implements PaymentService { ... }

@UnlessBuildProfile("prod")
@ApplicationScoped
public class DevModeLogger { ... }

方法 3：@DefaultBean（Quarkus 專屬，覆寫機制）

當沒有其他 Bean實作該介面時才生效，常用於擴充提供「預設值」：

Java · @DefaultBean
@DefaultBean
@ApplicationScoped
public class DefaultEmailService implements EmailService { ... }

// 若應用內有 @ApplicationScoped public class CustomEmailService implements EmailService
// 則上面那個 Default 自動讓位

Interceptor：橫切關注點

Interceptor 用來把跨多個方法的邏輯（log、計時、權限、交易、retry）統一管理， 避免污染業務程式碼。流程： 

sequenceDiagram
  participant Caller
  participant Proxy as ArC Proxy
  participant ICA as Interceptor A
  participant ICB as Interceptor B
  participant Bean as 真正的 Bean

  Caller->>Proxy: doWork
  Proxy->>ICA: AroundInvoke
  ICA->>ICB: proceed
  ICB->>Bean: 真正執行
  Bean-->>ICB: 結果
  ICB-->>ICA: 結果
  ICA-->>Proxy: 結果
  Proxy-->>Caller: 結果

圖 6-2 ─ Interceptor 鏈式呼叫順序，每個 interceptor 可在前後插入邏輯

三步驟建立 Interceptor

① 定義 Interceptor Binding：

Java · @Logged binding
import jakarta.interceptor.InterceptorBinding;
import java.lang.annotation.*;

@InterceptorBinding
@Retention(RetentionPolicy.RUNTIME)
@Target({ ElementType.METHOD, ElementType.TYPE })
public @interface Logged { }

② 實作 Interceptor：

Java · LoggingInterceptor
@Logged
@Interceptor
@Priority(Interceptor.Priority.APPLICATION)
public class LoggingInterceptor {

    private static final Logger LOG = Logger.getLogger(LoggingInterceptor.class);

    @AroundInvoke
    Object log(InvocationContext ctx) throws Exception {
        long start = System.nanoTime();
        try {
            return ctx.proceed();           // 呼叫真正的方法
        } finally {
            long elapsed = (System.nanoTime() - start) / 1_000_000;
            LOG.infof("[%s] took %dms", ctx.getMethod().getName(), elapsed);
        }
    }
}

③ 套用到 Bean：

Java · 使用
@ApplicationScoped
public class ProductService {

    @Logged                         // 只在這個方法套用
    public Product findById(Long id) { ... }
}

// 或整個 class 都套用
@Logged
@ApplicationScoped
public class ProductService { ... }
ℹ︎
Quarkus 內建多個 interceptor binding
  • @Transactional ── 自動交易管理
  • @CacheResult / @CacheInvalidate ── 快取
  • @RolesAllowed ── 角色授權
  • @Retry / @Timeout / @CircuitBreaker ── Fault Tolerance
這些都會在後續章節深入。

Event 與 @Observes：解耦通訊

CDI Event 是應用內部的發布／訂閱機制。發布者不需知道誰在聽，訂閱者不需知道誰會發。 類似 Spring 的 ApplicationEventPublisher，但更標準化。

Java · Event 完整範例
// 1. 定義事件型別（record 最簡潔）
public record OrderPlaced(String orderId, BigDecimal total) {}

// 2. 發布者
@ApplicationScoped
public class OrderService {

    @Inject
    Event<OrderPlaced> orderEvent;

    public void placeOrder(Order order) {
        // ... 儲存訂單 ...
        orderEvent.fire(new OrderPlaced(order.getId(), order.getTotal()));
    }
}

// 3. 訂閱者（可有多個）
@ApplicationScoped
public class EmailNotifier {
    void onOrder(@Observes OrderPlaced event) {
        // 寄送確認信
    }
}

@ApplicationScoped
public class InventoryUpdater {
    void onOrder(@Observes OrderPlaced event) {
        // 更新庫存
    }
}

非同步 Event

Java · 非同步觀察者
@ApplicationScoped
public class OrderService {

    @Inject
    Event<OrderPlaced> orderEvent;

    public void placeOrder(Order order) {
        orderEvent.fireAsync(new OrderPlaced(order.getId(), order.getTotal()));
    }
}

@ApplicationScoped
public class HeavyReportGenerator {
    void onOrder(@ObservesAsync OrderPlaced event) {
        // 在 worker thread 執行，不阻塞發布者
    }
}

Spring DI 相容層

Quarkus 提供 Spring DI 相容擴充，讓你能用 Spring 註解寫 Quarkus 應用， 方便團隊漸進遷移。加擴充即可：

bash
quarkus extension add spring-di
Java · 用 Spring 註解寫 Quarkus
import org.springframework.stereotype.Service;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;

@Service                              // Spring 註解，等同於 @ApplicationScoped
public class ProductService {

    @Autowired                        // 等同於 @Inject
    ProductRepository repository;

    @Value("${app.greeting}")         // 等同於 @ConfigProperty
    String greeting;
}

Spring DI ↔ CDI 註解對照

SpringJakarta CDI說明
@Component@Singleton單例 Bean
@Service@ApplicationScoped業務服務
@Repository@ApplicationScoped資料存取
@Controller(REST 用 @Path)Web 控制器
@Configuration(用 producer)配置類別
@Bean@Produces產生 Bean
@Autowired@Inject注入
@Value@ConfigProperty配置值注入

@Primary@DefaultBean預設 Bean
@Profile("dev")@IfBuildProfile("dev")profile 啟用
⚠
相容層的限制
Spring DI 擴充支援的是註解語法，不是 Spring runtime。所以：
  • 無 Spring AOP（要用 CDI Interceptor）
  • 無 ApplicationContext.getBean()
  • 無 Spring Boot AutoConfiguration
  • 適合遷移過渡期，新專案建議直接用 CDI

處理循環依賴

A 注入 B，B 注入 A，這是設計層面就該避免的情況。但偶爾不可避，Quarkus 透過 client proxy 能正常運作：

Java · 循環依賴解析
@ApplicationScoped              // client proxy 才能解循環，所以不能用 @Singleton
public class ServiceA {
    @Inject ServiceB b;
    public void doA() { b.doB(); }
}

@ApplicationScoped
public class ServiceB {
    @Inject ServiceA a;
    public void doB() { /* don't call a.doA() to avoid stack overflow */ }
}
⚠
設計建議
若你常常遇到循環依賴，那是設計問題而非工具問題。考慮：
  • 抽出第三個 Bean 處理共用邏輯
  • 用 Event 讓兩者解耦
  • 合併成同一個 Bean（若兩者邏輯緊密）

未使用的 Bean 會被刪除

Quarkus 為了優化 native image 體積，預設會刪除沒被注入過的 Bean。 通常這沒問題，但若你透過 reflection 或 CDI.current() 動態查找，會找不到：

Java · 標記不可刪除
import io.quarkus.arc.Unremovable;

@Unremovable
@ApplicationScoped
public class DynamicallyLookedUpService { ... }

或在配置裡列：

application.properties
quarkus.arc.unremovable-types=com.example.dynamic.*

貫穿專案進度：catalog-service 加入 DI 結構

把第 3 章建立的 catalog-service 重構成正規 DI 分層：

Java · 完整分層
// repository 層
@ApplicationScoped
public class ProductRepository {
    public List<Product> findAll() { ... }
    public Product findById(Long id) { ... }
}

// service 層（業務邏輯）
@ApplicationScoped
public class ProductService {

    private final ProductRepository repository;
    private final Event<ProductCreated> productCreated;

    public ProductService(ProductRepository repository, Event<ProductCreated> productCreated) {
        this.repository = repository;
        this.productCreated = productCreated;
    }

    @Transactional
    @Logged                                  // 套用 LoggingInterceptor
    public Product create(Product p) {
        repository.persist(p);
        productCreated.fire(new ProductCreated(p.id, p.name));
        return p;
    }
}

// REST 層
@Path("/products")
public class ProductResource {

    private final ProductService service;

    public ProductResource(ProductService service) {
        this.service = service;
    }

    @POST
    public Product create(Product p) {
        return service.create(p);
    }
}

常見陷阱

症狀原因解法
UnsatisfiedResolutionException 找不到符合的 Bean 確認類別有 scope 註解、qualifier 是否一致
AmbiguousResolutionException 多個 Bean 都符合 用 Qualifier 區分，或用 @DefaultBean / @Alternative
注入的欄位永遠是 null 類別沒被 ArC 管理（缺 scope 註解） 加上 @ApplicationScoped 等
動態查找 Bean 失敗 Bean 被 ArC 視為無用刪除 加 @Unremovable
循環依賴 stack overflow 互相呼叫變遞迴 確保不要在循環的兩端互相呼叫對方
interceptor 沒生效 方法是 private 改為 package-private 或 public
Kotlin 的 class final 導致 proxy 失敗 CDI 預設要求類別可繼承 用 kotlin-allopen plugin，或 Quarkus 已自動處理（arc.transform-unproxyable-classes=true）

本章小結

  • Quarkus 用自家的 ArC 容器實作 CDI Lite 4.1，把 DI 圖解析推到編譯期。
  • 常用 scope：@ApplicationScoped（最常用）、@Singleton、@RequestScoped、@Dependent。
  • 推薦 constructor 注入，唯一 constructor 時可省略 @Inject。
  • Qualifier 解多型別衝突，避免用 @Named，改用自訂 Qualifier 或 @Identifier。
  • Producer methods 把第三方類別包裝成 Bean；Quarkus 簡化：scope 註解隱含 @Produces。
  • @IfBuildProfile / @DefaultBean 是 Quarkus 簡化版的環境切換機制。
  • Interceptor 處理橫切關注：log、retry、cache、transaction。
  • Event + @Observes 提供應用內解耦的 pub/sub 機制。
  • Spring DI 相容層幫助漸進遷移，但有限制，新專案建議直接 CDI。
  • /q/arc 與 Dev UI CDI Beans 卡片是除錯神器。
