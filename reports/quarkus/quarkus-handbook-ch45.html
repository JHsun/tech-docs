Native Image：GraalVM 與 Mandrel

Native Image 是 Quarkus 最令人印象深刻的特性之一 ── 啟動 <100ms、記憶體 20–60MB、 image 大小幾乎縮小到 JVM 版本的 1/5。但它也帶來了挑戰： Reflection、動態代理、類別載入等「JVM 黑魔法」在 AOT 世界不能理所當然。 本章把 Quarkus 如何在 build time 解決這些問題說清楚，教你處理「第三方函式庫不 native 相容」的情況， 並給出 GraalVM vs Mandrel 的選擇建議與 CI 資源需求。

Native Image 的本質

GraalVM native-image 工具從 main() 出發靜態分析可達程式碼（reachability analysis）， 把它們 AOT 編譯成平台原生二進位。沒被分析到的程式碼 不會進入最終 binary，所以記憶體小。

但這個「靜態封閉世界假設」與 JVM 的動態能力矛盾：

JVM 特性Native Image 處理方式
Reflection需要在 build time 宣告哪些類別 / 方法 / 欄位需要 reflection（reflect-config.json）
動態代理需要宣告哪些介面會被代理（proxy-config.json）
動態類別載入大部分不支援（Class.forName(unknown) 在 runtime 無法工作）
Resource 載入需宣告哪些 classpath resource 需要包進 binary（resource-config.json）
JNI需要宣告（jni-config.json）
✓
Quarkus 幾乎處理了所有這些
這就是為什麼「Quarkus for Native」比「Spring Boot for Native」容易： Quarkus 在 build time 就完成了 CDI bean 解析、REST endpoint 掃描、Hibernate entity 處理。 它知道哪些類別需要 reflection，自動生成對應的 config。 你使用官方 Quarkus 擴充 → 90% 的問題自動解決。 問題通常來自自己加的第三方 library。

GraalVM vs Mandrel

項目GraalVM CEMandrel
定位通用 polyglot VM（含 Python / JS / R support）Quarkus 專用，只保留 native-image 功能
大小較大（約 500MB+）較小（只含 native-image 部分）
Quarkus 支援✅ 完整✅ 完整（Red Hat 官方支援）
Profile-guided Optimization (PGO)Oracle GraalVM EE 才有❌ 不支援
Linux container build✅✅（推薦）
CI 推薦社群通用Quarkus 官方推薦（K8s / Linux）
ℹ︎
2026 年的建議
CI/CD + Linux 部署：用 Mandrel（用官方 builder image，不需本地安裝）
需要 PGO：用 Oracle GraalVM EE（付費，效能更高）
macOS 開發測試：用 GraalVM CE（Mandrel 不支援 macOS amd64）

Build 指令

bash · 本地 native build（需安裝 GraalVM）
# 確認 GraalVM 已安裝
java -version  # 應該是 GraalVM 或 Mandrel

# Build
./mvnw package -Pnative

# 執行
./target/catalog-service-1.0.0-runner
bash · 容器 build（不需本地 GraalVM，推薦）
./mvnw package -Pnative \
  -Dquarkus.native.container-build=true \
  -Dquarkus.native.builder-image=quay.io/quarkus/ubi9-quarkus-mandrel-builder-image:jdk-21

# 連同 container image 一起建
./mvnw package -Pnative \
  -Dquarkus.native.container-build=true \
  -Dquarkus.container-image.build=true

application.properties native 設定

application.properties
# Native 通用設定
quarkus.native.container-build=true
quarkus.native.builder-image=quay.io/quarkus/ubi9-quarkus-mandrel-builder-image:jdk-21
quarkus.native.resources.includes=**/*.sql,**/*.json,db/migration/**

# 調整 native build 的記憶體限制（預設 80% RAM）
quarkus.native.native-image-xmx=6g

# 開啟 heap dump（native 也可以，需在 compile time 決定）
quarkus.native.enable-heap-dump=true

# Debug info（不建議 prod，但 staging 有用）
# quarkus.native.debug.enabled=true

處理 Reflection：三種方法

方法 A：使用官方 Quarkus 擴充（最佳）

如果你的 third-party library 有對應的 Quarkus 擴充，用擴充就好。擴充已經處理好所有 reflection config。

方法 B：@RegisterForReflection 注解

Java
import io.quarkus.runtime.annotations.RegisterForReflection;

// 自己的 DTO（Jackson 序列化需要 reflection）
@RegisterForReflection
public class ProductDto {
    public String name;
    public double price;
}

// 第三方類別（加在任意 Quarkus 類別或單獨的 config 類別）
@RegisterForReflection(targets = {
    com.thirdparty.SomeClass.class,
    com.thirdparty.AnotherClass.class
})
public class ReflectionConfig {
    // 空 class，只是為了放 annotation
}

方法 C：reflect-config.json（手動）

json · src/main/resources/META-INF/native-image/reflect-config.json
[
  {
    "name": "com.thirdparty.SomeClass",
    "allDeclaredConstructors": true,
    "allPublicMethods": true,
    "allDeclaredFields": true
  },
  {
    "name": "com.thirdparty.SomeInterface",
    "allPublicMethods": true
  }
]

找出需要 reflection 的類別：Tracing Agent

bash · 用 GraalVM Tracing Agent 自動收集
# 在 JVM 模式下跑，agent 記錄所有 reflection 使用
java -agentlib:native-image-agent=config-output-dir=src/main/resources/META-INF/native-image \
     -jar target/quarkus-app/quarkus-run.jar

# 跑幾個測試 / 負載 → 盡量觸發所有程式路徑
curl http://localhost:8080/api/products
curl -X POST http://localhost:8080/api/orders ...

# Ctrl+C → agent 輸出所有 config 到 META-INF/native-image/
# 然後 native build 就能用這些 config

Resource 配置

application.properties · 包含 classpath resource
# 把 SQL migration、JSON 設定等包進 native binary
quarkus.native.resources.includes=db/migration/*.sql,import.sql,META-INF/openapi.yaml
# 排除不需要的（節省 binary 大小）
quarkus.native.resources.excludes=**/*.txt

CI 資源需求

⚠
Native build 很耗資源
典型 native build 需要：
  • CPU：4 核以上（8 核大約快 2 倍）
  • 記憶體：8GB 以上（GraalVM 文件建議 ≥ 4GB，複雜應用需要更多）
  • 時間：5–15 分鐘（視應用複雜度）
GitHub Actions 使用 ubuntu-latest-8-cores 或自訂 runner 可以加速。
yaml · GitHub Actions native build
name: Native Build
on:
  push:
    branches: [main]

jobs:
  native-build:
    runs-on: ubuntu-latest    # 或 ubuntu-latest-8-cores（付費）
    steps:
    - uses: actions/checkout@v4

    - uses: actions/setup-java@v4
      with:
        java-version: '21'
        distribution: 'temurin'
        cache: 'maven'

    - name: Build Native Image
      run: |
        ./mvnw package -Pnative \
          -Dquarkus.native.container-build=true \
          -Dquarkus.container-image.build=true \
          -Dquarkus.container-image.push=true \
          -Dquarkus.container-image.registry=ghcr.io \
          -Dquarkus.container-image.group=${{ github.repository_owner }} \
          -Dquarkus.container-image.tag=${{ github.sha }}
      env:
        QUARKUS_CONTAINER_IMAGE_USERNAME: ${{ github.actor }}
        QUARKUS_CONTAINER_IMAGE_PASSWORD: ${{ secrets.GITHUB_TOKEN }}

常見 Native Build 問題

錯誤訊息原因解法
ClassNotFoundException 在 runtime類別未被 reachability 分析涵蓋加 @RegisterForReflection 或 reflect-config.json
Missing resourceclasspath resource 未包進 binary加 quarkus.native.resources.includes
Build 時 OOM記憶體不足加 -Dquarkus.native.native-image-xmx=8g；或升 runner 記憶體
Build 在 macOS 後跑在 Linux 出錯native binary 是 platform-specific用 quarkus.native.container-build=true 建 Linux binary
Third-party library 不 native 相容大量 reflection / 動態代理用 GraalVM Tracing Agent 收集；或換 native-compatible 版本

本章小結

  • Native Image = GraalVM AOT 編譯，只包含「可達程式碼」── 啟動 <100ms、記憶體 20–60MB。
  • 挑戰：Reflection / 動態代理 / 動態類別載入需要在 build time 宣告。
  • Quarkus 已處理大部分：CDI、REST、Hibernate 全自動。第三方 library 才需要手動配置。
  • 選型：CI/Linux → Mandrel（官方 builder image）；需要 PGO → Oracle GraalVM EE；macOS 測試 → GraalVM CE。
  • Build 方式：本地（需安裝 GraalVM）或容器 build（--container-build，推薦）。
  • Reflection 配置三法：官方擴充（最佳） > @RegisterForReflection > reflect-config.json。
  • Tracing Agent 自動收集所有 reflection 使用，生成 config ── 適合第三方 library 初次整合。
  • CI 資源：需 4+ CPU、8GB+ RAM、5–15 分鐘 ── 只在 main branch 跑。
  • quarkus.native.resources.includes 確保 SQL migration、JSON 等 resource 包進 binary。
