環境準備與工具鏈

Quarkus 的開發體驗很大程度上仰賴一套協作良好的工具鏈：JDK、Maven 或 Gradle、Quarkus CLI、 容器執行階段、IDE。本章手把手帶你把這些零件組裝起來，並建立日後可重複使用的「開發工作站基線」。

讀者 🟢 初學者
版本 Quarkus 3.33 LTS
JDK 21 （17 為 fallback）
預估閱讀 25 分鐘
更新 2026-05-14

本章學習目標

讀者類型本章重點
🟢 初學者了解每個工具的用途，並能依步驟在自己的電腦完成安裝與驗證。
🔵 開發者熟悉 Maven / Gradle / CLI 三套工具鏈的差異，知道何時用哪一個。
🟠 DevOps / SRE建立「可重現的開發環境基線」與授權安全的容器執行階段選擇。

第 1 步：安裝 JDK 21

Quarkus 3.33 LTS 支援 JDK 17 與 21。本書以 JDK 21 為主，原因有三： 虛擬執行緒（Virtual Threads）正式 GA、 ZGC 大幅改善、 Pattern Matching for switch 等語法穩定。 JDK 17 仍是 LTS，遇到差異會額外標示。

選擇 JDK 發行版

☕

Eclipse Temurin

最廣泛使用的 OpenJDK 發行版，Adoptium 維護。本書範例的預設選擇。

免費跨平台長期支援
⚡

GraalVM CE

Oracle 維護，內建 Native Image 編譯器。若要做 Native 編譯（第 44 章），直接裝這個。

含 native-imageJVM 模式仍可用
🟢

Mandrel

Red Hat 維護的 GraalVM 下游分支，專為 Quarkus 優化。Red Hat build of Quarkus 官方推薦。

含 native-imageRH 認證
🪶

Amazon Corretto

AWS 維護，與 AWS Lambda Java Runtime 一致。要部署到 Lambda 推薦使用。

AWS 親和免費

安裝指令（按平台）

macOS · SDKMAN! 推薦 
# 1. 安裝 SDKMAN!（版本管理工具）
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"

# 2. 列出可用 JDK 版本
sdk list java

# 3. 安裝 Temurin 21 並設為預設
sdk install java 21.0.5-tem
sdk default java 21.0.5-tem

# 4. 驗證
java -version
# openjdk version "21.0.5" 2024-10-15 LTS
Linux · SDKMAN! 推薦 
# Ubuntu / Debian 需先確保 zip 與 curl
sudo apt update && sudo apt install -y zip unzip curl

# 安裝 SDKMAN!
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"

# 安裝 Temurin 21
sdk install java 21.0.5-tem
sdk default java 21.0.5-tem

# 驗證
java -version
Windows · 推薦使用 WSL 2 + SDKMAN! 
# 1. 啟用 WSL 2（PowerShell 系統管理員）
wsl --install

# 2. 重啟後在 Ubuntu shell 中執行 Linux tab 的指令
# 或在原生 Windows 用 Chocolatey:
choco install temurin21
choco install maven
choco install gradle
choco install quarkus

# 驗證
java -version
ℹ︎
為什麼推薦 SDKMAN!
SDKMAN! 能在同一台機器上管理多個 JDK 版本並隨意切換（sdk use java 17.0.13-tem）， 同時也能安裝 Maven、Gradle、Quarkus CLI、jbang。對於 Java 開發者而言，幾乎是工作站的必備工具。 Windows 原生不支援，但透過 WSL 2 可獲得完整體驗。

第 2 步：建構工具（三選一或全裝）

Quarkus 支援三種建構工具入口，本書每章關鍵指令都會三者對照。原則上：

  • Maven：最廣泛使用，Spring Boot 開發者熟悉。CI/CD 環境普遍預裝。
  • Gradle：建構速度快、DSL 靈活，Kotlin 開發者偏好。
  • Quarkus CLI：包裝以上兩者，提供統一指令；不一定要裝，但裝了會大幅提升開發體驗。
📦

Apache Maven

3.9.x+

Quarkus 3.33 內建 Maven Wrapper，理論上可不裝。但建議裝以便手動執行非 Quarkus 指令。

🐘

Gradle

8.x

建議 8.5 或更高版本以完整支援 JDK 21。Gradle Wrapper 同樣內建於 Quarkus 產生的專案。

⚙️

Quarkus CLI

3.33.x

統一指令入口，自動偵測專案使用 Maven 或 Gradle。新建專案、加擴充、跑 dev mode 都更簡潔。

安裝指令

SDKMAN! · 三件套一次裝齊 
sdk install maven
sdk install gradle
sdk install quarkus

# 驗證
mvn -v
gradle -v
quarkus --version
# 3.33.1
Homebrew 
brew install maven gradle quarkusio/tap/quarkus

# 驗證

Chocolatey (PowerShell as Admin)

# 驗證

# Windows PowerShell
iex "& { $(iwr https://ps.jbang.dev) } app install --fresh --force quarkus@quarkusio"

# 加入 PATH 後驗證

第 3 步：容器執行階段

Quarkus 的 Dev Services 會自動拉起 PostgreSQL、Kafka、Keycloak 等依賴容器， 你只要安裝任一個 OCI-compatible runtime 即可。Native Image 建構也需要容器來提供 Mandrel 編譯環境。

🐳

Docker Desktop

最熟悉，但 2026 年起對 250 員工或年營收 1000 萬美元以上的企業需付費授權。

UI 完整商用授權有限制
🦭

Podman Desktop

Red Hat 出品，免費商用、daemonless、rootless。Quarkus 與 Red Hat 生態的天然搭配。

免費商用RootlessK8s 整合
🐄

Rancher Desktop

SUSE 出品，內建 k3s，適合需要本機 Kubernetes 的開發者。

免費商用含 K8s
🌊

OrbStack

僅 macOS，效能極佳（記憶體佔用為 Docker 1/4），但對企業用戶收費。

僅 macOS速度最快商用付費

本書推薦組合

✓
推薦：Podman Desktop
本書範例會以 Podman Desktop 為示範，因為它在所有平台免費、與 Quarkus 親和度最高、 且 Quarkus Dev Services 自 3.16 起官方測試與 Podman 相容性最完整。 在 macOS 上記得把 DOCKER_HOST 指向 Podman socket，Quarkus 才能找到容器執行階段。
Podman Desktop · macOS 
brew install --cask podman-desktop

# Podman Desktop 會自動建立預設 machine
podman machine init
podman machine start

# 讓 Testcontainers / Dev Services 找到 Podman socket
export DOCKER_HOST="unix://$(podman machine inspect --format '{{.ConnectionInfo.PodmanSocket.Path}}')"

# 加到 ~/.zshrc 或 ~/.bashrc 永久生效
echo 'export DOCKER_HOST="unix:///var/run/docker.sock"' >> ~/.zshrc

# 驗證
podman info
Podman · Linux 原生 
# Fedora / RHEL
sudo dnf install -y podman podman-compose

# Ubuntu / Debian
sudo apt install -y podman podman-compose

# 啟用 socket（Testcontainers 需要）
systemctl --user enable --now podman.socket
export DOCKER_HOST="unix:///run/user/$UID/podman/podman.sock"

# 驗證
podman info
Podman Desktop · Windows 
# 透過 winget
winget install -e --id RedHat.Podman-Desktop

# 啟動 Podman Desktop GUI 並建立 machine
# 從 GUI 安裝 Compose 擴充以支援 docker-compose 檔案

# 驗證
podman info
⚠
DOCKER_HOST 是 Dev Services 的關鍵
Quarkus Dev Services 內部使用 Testcontainers，後者預設找 /var/run/docker.sock。 若你用 Podman，必須透過 DOCKER_HOST 環境變數告訴它 Podman socket 的位置，否則 quarkus dev 啟動時會出現「Could not find a valid Docker environment」錯誤。

第 4 步：IDE 與擴充套件

Quarkus 對主流 Java IDE 都提供官方擴充。三大選擇都能完整支援， 選你最順手的即可。三者都會：

  • 讀取 application.properties 並提供屬性 auto-complete 與驗證
  • 讓你直接從 IDE 啟動 dev mode、debug、新建專案、加擴充
  • 整合 Qute 模板引擎的語法 highlighting
🧠

第 5 步：完整環境驗證

跑完所有安裝步驟後，用一段腳本檢查所有元件版本。

bash · 環境體檢腳本 
#!/usr/bin/env bash
echo "──── Quarkus 開發環境體檢 ────"
echo
echo "[ JDK ]"
java -version 2>&1 | head -1

echo
echo "[ Maven ]"
mvn -v | head -1

echo
echo "[ Gradle ]"
gradle -v | grep '^Gradle'

echo
echo "[ Quarkus CLI ]"
quarkus --version

echo
echo "[ Container Runtime ]"
if command -v podman >/dev/null; then podman --version
elif command -v docker >/dev/null; then docker --version
else echo "✗ 無容器執行階段"; fi

echo
echo "[ DOCKER_HOST ]"
echo "${DOCKER_HOST:-未設定（Linux 預設 /var/run/docker.sock）}"

echo
echo "──── 完成 ────"

✓ 環境就緒檢查清單

  • java -version 顯示 21.x（或 17.x）
  • mvn -v 顯示 3.9.x，且 Java version: 21.x
  • gradle -v 顯示 8.5 以上
  • quarkus --version 顯示 3.33.x
  • podman info 或 docker ps 能正常執行
  • Testcontainers 找得到容器 socket（DOCKER_HOST 已正確設定）
  • IDE 安裝對應 Quarkus 擴充並已重啟

DevOps / SRE 視角：團隊環境一致性

個人裝完只是起點，要讓整個團隊都有同樣的環境，才是 SRE 該關心的事。

策略 1：SDKMAN! + 共享 .sdkmanrc

專案根目錄放一個 .sdkmanrc 檔，新成員 cd 進專案資料夾，SDKMAN! 會提示自動切換到指定版本：

.sdkmanrc · 提交到 Git 跟程式碼一起版控 
java=21.0.5-tem
maven=3.9.9
gradle=8.10.2
quarkus=3.33.1

策略 2：Dev Container（VS Code / GitHub Codespaces）

把整個工具鏈打包成容器映像檔，新成員「Reopen in Container」就有完整環境， 幾分鐘上工。Quarkus 官方提供 quay.io/quarkus/ubi-quarkus-mandrel-builder-image 作為基礎映像。

.devcontainer/devcontainer.json 
{
  "name": "Quarkus Dev",
  "image": "mcr.microsoft.com/devcontainers/java:21",
  "features": {
    "ghcr.io/devcontainers/features/java:1": { "version": "21", "installMaven": "true", "installGradle": "true" },
    "ghcr.io/devcontainers/features/docker-in-docker:2": {}
  },
  "postCreateCommand": "curl -Ls https://sh.jbang.dev | bash -s - app install --force quarkus@quarkusio",
  "customizations": {
    "vscode": {
      "extensions": [ "vscjava.vscode-java-pack", "redhat.vscode-quarkus", "redhat.vscode-microprofile" ]
    }
  }
}

策略 3：CI/CD 使用相同版本

在 GitHub Actions、GitLab CI 上把 JDK 與 Quarkus 版本固定，確保「開發機通過」就等於「CI 通過」。

.github/workflows/build.yml · 摘錄 
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup JDK 21 Temurin
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'
          cache: maven
      - name: Build with Maven
        run: ./mvnw -B verify

常見陷阱與排查

症狀可能原因排查
quarkus dev 啟動慢且 Dev Services 卡住 容器執行階段未啟動或 DOCKER_HOST 設錯 podman info / docker ps 驗證；檢查環境變數
java: invalid target release: 21 Maven / Gradle 使用了較舊的 JDK echo $JAVA_HOME、mvn -v 確認版本一致
quarkus: command not found SDKMAN! 或 JBang 安裝後 shell 未重新載入 新開終端視窗，或 source ~/.sdkman/bin/sdkman-init.sh
IntelliJ 找不到 quarkus.http.port 屬性 未安裝 Quarkus Tools 擴充 Plugins → 搜尋 Quarkus Tools → 安裝後重啟
Gradle build 卡在 configuration cache Gradle 版本與 Quarkus plugin 不相容 升級 Gradle 至 8.5+，或 --no-configuration-cache

本章小結

  • SDKMAN! 是 Java 開發者管理 JDK、Maven、Gradle、Quarkus CLI 的最佳工具。
  • 本書以 Temurin JDK 21 為主，需要 Native 編譯時改用 Mandrel。
  • 建構工具三者並列：Maven / Gradle / Quarkus CLI。CLI 是最方便的入口，但底層仍是 Maven 或 Gradle。
  • 容器執行階段推薦 Podman Desktop（免費商用、daemonless），記得設定 DOCKER_HOST。
  • SRE 應為團隊建立版本一致性策略：.sdkmanrc + Dev Container + CI 固定版本。
