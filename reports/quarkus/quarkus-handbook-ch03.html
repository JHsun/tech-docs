你的第一個 Quarkus 應用

工具裝好了，是時候動手了。本章帶你從零建立一個 Quarkus 專案，認識 Dev Mode 的開發魔法、 Dev UI 的全景儀表板，並真正理解 Live Reload 在底層做了什麼 ── 這是 Quarkus 開發者愉悅感的起點。

讀者 🟢 初學者
版本 Quarkus 3.33 LTS
JDK 21
預估閱讀 30 分鐘

本章學習目標

讀者類型本章重點

建立新專案

有三種建立 Quarkus 專案的方式：Quarkus CLI（最簡潔）、Maven plugin（最普及）、 code.quarkus.io（最直覺）。本書範例會以 CLI 為主軸，附 Maven / Gradle 對照。

方法 A：Quarkus CLI（推薦）

bash · Quarkus CLI 
quarkus create app com.example:hello-quarkus \
  --extension=rest,rest-jackson \
  --java=21

cd hello-quarkus

這條指令做了幾件事：

  • 建立 hello-quarkus/ 目錄
  • 產生 pom.xml，以 Maven 為預設建構工具
  • 加入 quarkus-rest 與 quarkus-rest-jackson 擴充（REST + JSON 支援）
  • 產生範例 GreetingResource.java 與對應測試
  • 使用 JDK 21 作為目標版本
ℹ︎
想用 Gradle？加一個參數
quarkus create app com.example:hello-quarkus --extension=rest,rest-jackson --gradle 會產生 Gradle 專案結構（build.gradle.kts）。Kotlin 開發者可加 --kotlin。

方法 B：Maven plugin

bash · Maven Plugin (不需先裝 CLI) 
mvn io.quarkus.platform:quarkus-maven-plugin:3.33.1:create \
  -DprojectGroupId=com.example \
  -DprojectArtifactId=hello-quarkus \
  -Dextensions="rest,rest-jackson" \
  -DjavaVersion=21

cd hello-quarkus

方法 C：code.quarkus.io 線上產生器

打開 code.quarkus.io， 介面上勾選想要的擴充、設定 Group/Artifact、下載 zip 檔。最適合初次接觸的讀者， 也是探索擴充生態的好工具：左側分類列出全部擴充，每個都附說明。

專案結構解析

進入專案目錄，看一下 Quarkus 為你生成的東西：

hello-quarkus/ ├── .mvn/ # Maven Wrapper ├── src/ │ ├── main/ │ │ ├── docker/ # 4 種 Dockerfile 範本（JVM / native / micro / legacy） │ │ ├── java/com/example/ │ │ │ └── GreetingResource.java # 範例 REST endpoint │ │ └── resources/ │ │ ├── application.properties # 配置檔（dev/prod 共用） │ │ └── META-INF/resources/ │ │ └── index.html # 啟動歡迎頁 │ └── test/ │ └── java/com/example/ │ ├── GreetingResourceTest.java # JVM 模式測試 │ └── GreetingResourceIT.java # Native 模式整合測試 ├── .gitignore ├── mvnw / mvnw.cmd # Maven Wrapper 腳本 ├── pom.xml # Maven 設定 └── README.md

三個檔案值得立刻看一下：

① GreetingResource.java

Java · 範例 REST endpoint 
package com.example;

import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/hello")
public class GreetingResource {

    @GET
    @Produces(MediaType.TEXT_PLAIN)
    public String hello() {
        return "Hello from Quarkus REST";
    }
}

注意這裡是 Jakarta REST 標準註解（@Path、@GET、@Produces）， 而不是 Spring 的 @RestController。Quarkus 預設遵循 Jakarta EE 標準。

② application.properties

application.properties · 預設為空，等你加東西 
# Examples:
# quarkus.http.port=8080
# quarkus.log.level=INFO
# quarkus.datasource.username=...

配置在第 5 章會深入講解。現在只要知道：所有 Quarkus 與擴充的設定都集中在這個檔案。

③ pom.xml 關鍵片段

pom.xml · Quarkus 相關片段 
<properties>
    <maven.compiler.release>21</maven.compiler.release>
    <quarkus.platform.version>3.33.1</quarkus.platform.version>
    <quarkus.platform.group-id>io.quarkus.platform</quarkus.platform.group-id>
    <quarkus.platform.artifact-id>quarkus-bom</quarkus.platform.artifact-id>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>${quarkus.platform.group-id}</groupId>
            <artifactId>${quarkus.platform.artifact-id}</artifactId>
            <version>${quarkus.platform.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>io.quarkus</groupId>
        <artifactId>quarkus-rest</artifactId>
    </dependency>
    <dependency>
        <groupId>io.quarkus</groupId>
        <artifactId>quarkus-rest-jackson</artifactId>
    </dependency>
</dependencies>

BOM（Bill of Materials）是 Quarkus 版本管理的關鍵：所有擴充的版本由 quarkus-bom 統一鎖定， 你只需在 <dependencies> 寫 groupId 與 artifactId，無需指定 version。 這避免了 dependency hell 與版本不相容問題。

體驗 Live Reload

Quarkus Dev Mode 最讓人驚艷的功能：不關閉應用、直接改原始碼。 打開 GreetingResource.java，把回傳字串改一下：

Java · 修改後
@GET
@Produces(MediaType.TEXT_PLAIN)
public String hello() {
    return "Bonjour from Quarkus!";  // 改成這樣
}

儲存檔案。不要重啟應用。再執行一次 curl：

bash
curl http://localhost:8080/hello
# → Bonjour from Quarkus!

看看終端，Quarkus 已偵測到變更並自動重編譯：

INFO [io.qua.dep.dev.RuntimeUpdatesProcessor] Changed source files detected, recompiling [GreetingResource.java] INFO [io.qua.dep.dev.RuntimeUpdatesProcessor] Live reload total time: 0.135s
改一行程式、按一次刷新，下一個 request 就是新的程式碼在執行。

Live Reload 的觸發機制

你可能會問：「為什麼是發送 request 才重新編譯？」這是設計上刻意的：

  • 不在儲存時立即編譯，避免你連打三個錯字、每次儲存都觸發失敗編譯
  • 請求進來時才檢查檔案 mtime，若有變動才重編譯（典型 200~500ms）
  • 若編譯失敗，會在 http://localhost:8080 顯示美觀的錯誤頁，含完整 stack trace 與原始碼定位

底層魔法：ClassLoader 階層

傳統 Java 應用無法熱替換類別（除非用 JRebel 等付費工具）。Quarkus 怎麼做到的？ 答案是專為 Dev Mode 設計的 ClassLoader 階層： 

flowchart TB
  classDef base fill:__SOFT_INFO__,stroke:__INFO__,color:__TXT__
  classDef change fill:__SOFT_OK__,stroke:__OK__,color:__TXT__,font-weight:bold
  classDef sys fill:__SOFT_WARN__,stroke:__WARN__,color:__TXT__

  Sys[System ClassLoader
JDK · Quarkus runtime]:::sys
  Base[Base ClassLoader
不變的依賴 · 第三方 jar]:::base
  Aug[Augmentation ClassLoader
build-time 產物]:::base
  Run["RuntimeUpdates ClassLoader
你的應用程式碼 · 隨檔案變動而重建"]:::change
  App[執行中的應用]:::change

  Sys --> Base
  Base --> Aug
  Aug --> Run
  Run --> App

圖 3-1 ─ Dev Mode 的 ClassLoader 階層：只有最上層（你的程式碼）會在檔案變動時被替換

當你儲存 GreetingResource.java，Quarkus 只丟棄並重建最上層的 RuntimeUpdates ClassLoader， 把新編譯的 .class 載入。下層的依賴、Quarkus 框架本身完全不動，所以速度極快。

⚠
生產環境完全不同
Production 模式下這套 ClassLoader 階層完全不存在，只有一個專為應用打包的單一 ClassLoader。 這也是為什麼 Quarkus 生產應用啟動如此快、記憶體如此小 ── 因為 dev mode 的所有開銷在生產環境完全消失。 這項差異在第 7 節「Dev vs Production 架構差異」會深入。

Dev UI：開發儀表板

Dev Mode 啟動後，瀏覽器打開：

URL
http://localhost:8080/q/dev-ui

這是 Quarkus Dev UI ── 一個只在 dev 模式存在的儀表板。 從 Quarkus 3.x 起改用 Web Components（Lit + Vaadin）重寫，比舊版更現代、更互動。

Dev Mode 終端指令

剛剛終端底部那行 Press [r] [o] [:] [h] for more options 是 Quarkus 互動式開發者控制台。按下 h 看完整選單：

按鍵功能使用時機
r恢復／暫停 Continuous Testing切換是否在檔案變動時自動跑測試
o切換測試輸出顯示想看詳細 println / log 時打開
f只重跑失敗的測試只想處理紅燈，省時間
b切換 broken-only 模式只跑失敗測試，修一個少一個
v列出最近的測試失敗失敗訊息被刷掉時用
p暫停測試暫時關掉測試以加速 reload
s強制重啟（清空狀態）遇到奇怪行為時清乾淨重來
i切換 instrumentation 模式保留應用狀態的 reload，特殊用途
l切換 live reload暫時關閉自動 reload
:進入指令模式輸入 quit、config 等指令
q退出 dev mode結束開發

Continuous Testing

按下 r，Quarkus 進入 Continuous Testing 模式：每次儲存原始碼， 它會自動找出受影響的測試並執行，把結果顯示在終端與 Dev UI。

Press [r] to resume testing> → user pressed [r] Running 1 tests All 1 tests are passing (0 skipped), 1 tests were run in 1247ms. Tests completed at 14:25:13. Press [r] to re-run, [v] to view full results, [p] to pause, [h] for more options>

打開 src/test/java/com/example/GreetingResourceTest.java 看一下預設測試：

Java · 預設測試
@QuarkusTest
class GreetingResourceTest {

    @Test
    void testHelloEndpoint() {
        given()
          .when().get("/hello")
          .then()
             .statusCode(200)
             .body(is("Hello from Quarkus REST"));
    }
}

把剛剛的訊息改成 "Bonjour" 後，這個測試會失敗。Quarkus 立刻在終端顯示紅色， Dev UI 的 Continuous Testing 區塊也會即時更新。把斷言改成新字串、儲存，秒變綠燈。

✦
為什麼這比傳統 TDD 強？
傳統 TDD：寫測試 → 切換到終端 → 跑 mvn test →（等 30 秒）→ 看結果。
Quarkus Continuous Testing：寫測試 → 儲存 → 0.5 秒後直接看結果。反饋迴圈時間從秒級降到亞秒級。

Dev Mode vs Production 架構差異

這節是 🟠 SRE 必讀。Quarkus 的 Dev Mode 與 Production Mode 不只是「配置不同」， 而是架構不同。理解差異能避免把 dev-only 行為帶入生產。

面向Dev ModeProduction

Dev Services自動啟動容器不存在，需自行配置

profiledevprod
⚠
SRE 必須知道的紅線
  • 絕對不要在生產執行 quarkus dev 或 quarkus:dev，它會啟用所有開發功能，包括允許從 Dev UI 修改配置、執行 SQL 等危險操作。
  • 生產用 java -jar target/quarkus-app/quarkus-run.jar（標準 JVM）或對應的 Native 執行檔。
  • Dev Services 不會在生產啟動，所以正式環境的資料庫、Kafka 連線必須在 application.properties 用 %prod. 前綴明確指定。

打包成生產 jar

體驗完 Dev Mode，來看看生產打包長什麼樣：

Quarkus CLI
quarkus build
java -jar target/quarkus-app/quarkus-run.jar
Maven
./mvnw package
java -jar target/quarkus-app/quarkus-run.jar
Gradle
./gradlew build
java -jar build/quarkus-app/quarkus-run.jar

打包完成的目錄結構（Quarkus 預設使用 Fast-Jar 格式）：

target/ └── quarkus-app/ ├── quarkus-run.jar # 啟動入口（很小） ├── app/ # 你的應用程式碼 ├── lib/ # 所有依賴 └── quarkus/ # build-time augmentation 產物

啟動生產 jar，注意啟動時間：

$ java -jar target/quarkus-app/quarkus-run.jar INFO [io.quarkus] hello-quarkus 1.0.0-SNAPSHOT on JVM started in 0.685s. INFO Profile prod activated.

0.685 秒 ── 比 Dev Mode 還快，因為沒有任何 dev 開銷。記憶體也降到約 70 MB（同樣的應用）。

貫穿專案進度：catalog-service 起手式

從本章開始，我們會把每章的成果累積到貫穿全書的微服務 quarkus-shop。 今天先建立 catalog-service 的骨架：

bash · 建立 catalog-service
quarkus create app com.example.shop:catalog-service \
  --extension=rest,rest-jackson,smallrye-openapi \
  --java=21

cd catalog-service
quarkus dev

瀏覽器打開 http://localhost:8080/q/swagger-ui，因為加了 smallrye-openapi， 你會看到一個現成的 Swagger UI 視覺化 API 文件。 第 11 章會深入 OpenAPI；現在只要記得「加擴充即得功能」就是 Quarkus 的精神。

常見陷阱

症狀原因解法
Dev Mode 啟動慢且報「Could not find a valid Docker environment」 容器執行階段未啟動（Dev Services 找不到） 啟動 Podman/Docker，或在 application.properties 加 quarkus.devservices.enabled=false
Live Reload 不生效 檔案監控失敗（常見於 WSL 與 NFS） 確認檔案在 Linux 原生檔案系統；按 s 強制重啟
儲存 .java 後 reload 變超慢 專案有很多 dependency，aug 階段重跑慢 升級 SSD、啟用 build cache，或拆模組
同時兩個 dev mode 啟不來 port 8080 衝突 quarkus dev -Dquarkus.http.port=8081
Dev UI 連不上 URL 寫錯了（常打成 /q/dev） 正確 URL 是 /q/dev-ui

本章小結

  • 三種建立專案的方法：Quarkus CLI、Maven plugin、code.quarkus.io。
  • Quarkus 專案結構乾淨，application.properties 是配置中樞，pom.xml 的 BOM 統一鎖定版本。
  • Dev Mode = Live Reload + Dev UI + Continuous Testing + Dev Services + 美觀錯誤頁，是 Quarkus 開發體驗的核心。
  • Live Reload 靠多層 ClassLoader 階層實現，只重建你的應用程式碼，所以快。
  • Dev UI（/q/dev-ui）是擴充提供開發工具的展示廳，務必養成隨手打開的習慣。
  • Production 模式架構完全不同 ── 單一 ClassLoader、無 Dev Services、啟動更快、記憶體更小。
