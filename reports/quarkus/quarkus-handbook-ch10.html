REST Client

微服務架構中，呼叫其他服務跟接受呼叫同樣重要。Quarkus REST Client 用宣告式介面取代手寫 HTTP 呼叫 ── 定義一個 Java interface，加幾個註解，就有了型別安全、自動序列化、整合 OIDC 與服務發現的完整 client。

為什麼要用宣告式 Client

用「呼叫 Stripe API」當例子，看看三種寫法的差別：

Java · 原生 HTTP（不推薦）
HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.stripe.com/v1/charges"))
    .header("Authorization", "Bearer " + apiKey)
    .header("Content-Type", "application/json")
    .POST(BodyPublishers.ofString(objectMapper.writeValueAsString(charge)))
    .build();
HttpResponse<String> res = client.send(request, BodyHandlers.ofString());
Charge result = objectMapper.readValue(res.body(), Charge.class);
// 還沒處理 status code、retry、timeout、log...
Java · Builder 模式
StripeApi api = RestClientBuilder.newBuilder()
    .baseUri(URI.create("https://api.stripe.com"))
    .build(StripeApi.class);
Charge result = api.createCharge(charge);
// 還是需要在某處宣告 StripeApi interface
Java · 宣告式（推薦）
@RegisterRestClient(configKey = "stripe")
@Path("/v1")
public interface StripeApi {

    @POST @Path("/charges")
    Charge createCharge(Charge charge);
}

// 使用
@Inject @RestClient StripeApi stripe;
Charge result = stripe.createCharge(charge);
介面宣告完，Quarkus 自動產生 client 實作，注入即用。

基本用法

加擴充：

bash
quarkus extension add rest-client rest-client-jackson

步驟 1：定義 client interface

Java · PricingApiClient
import org.eclipse.microprofile.rest.client.inject.RegisterRestClient;
import jakarta.ws.rs.*;
import jakarta.ws.rs.core.MediaType;

@RegisterRestClient(configKey = "pricing-api")
@Path("/v1/prices")
@Produces(MediaType.APPLICATION_JSON)
@Consumes(MediaType.APPLICATION_JSON)
public interface PricingApiClient {

    @GET
    @Path("/{productId}")
    Price getPrice(@PathParam("productId") Long productId);

    @POST
    Price createPrice(Price price);

    @GET
    List<Price> listPrices(@QueryParam("currency") String currency);
}

步驟 2：配置 base URL

application.properties
# 用 configKey 對應 interface
quarkus.rest-client.pricing-api.url=https://pricing.example.com
quarkus.rest-client.pricing-api.read-timeout=5000
quarkus.rest-client.pricing-api.connect-timeout=2000

# 不同環境不同 URL
%dev.quarkus.rest-client.pricing-api.url=http://localhost:8081
%prod.quarkus.rest-client.pricing-api.url=https://pricing.internal

步驟 3：注入並使用

Java · 注入
import org.eclipse.microprofile.rest.client.inject.RestClient;

@ApplicationScoped
public class CatalogService {

    @Inject @RestClient
    PricingApiClient pricingApi;

    public ProductWithPrice enrich(Product p) {
        Price price = pricingApi.getPrice(p.id());
        return new ProductWithPrice(p, price);
    }
}
✓
注意 @RestClient 註解
注入時必須加 @RestClient，否則 CDI 會找不到 Bean，因為 client 是 ArC 透過特殊機制產生的。 這個註解就是 qualifier，告訴 ArC 「我要的是 REST client 版本，不是任何同型別的 implementation」。

Reactive 版本

把回傳型別改為 Uni 或 Multi，client 自動切換為非阻塞模式：

Java · Reactive client
@RegisterRestClient(configKey = "pricing-api")
@Path("/v1/prices")
public interface PricingApiClient {

    @GET
    @Path("/{productId}")
    Uni<Price> getPrice(@PathParam("productId") Long productId);

    @POST
    Uni<Price> createPrice(Price price);
}

// 使用
@GET
@Path("/{id}/with-price")
public Uni<ProductWithPrice> getEnriched(@PathParam("id") Long id) {
    return Uni.combine().all().unis(
        productService.findById(id),
        pricingApi.getPrice(id)
    ).asTuple().map(t -> new ProductWithPrice(t.getItem1(), t.getItem2()));
}
ℹ︎
並行呼叫的威力
上面範例同時發出兩個 HTTP 請求，最後合併結果。整體時間 = max(產品查詢, 價格查詢)，而非 sum。 這是 reactive client 比 imperative 更明顯的優勢場景。

錯誤處理

當遠端服務回傳 4xx / 5xx，預設行為是丟 WebApplicationException。可以自訂：

方式 A：ResponseExceptionMapper

Java · 自訂例外對應
import org.eclipse.microprofile.rest.client.ext.ResponseExceptionMapper;

public class PricingApiExceptionMapper implements ResponseExceptionMapper<PricingException> {

    @Override
    public PricingException toThrowable(Response response) {
        return new PricingException(
            response.getStatus(),
            response.readEntity(String.class));
    }

    @Override
    public boolean handles(int status, MultivaluedMap<String, Object> headers) {
        return status >= 400;
    }
}

// 註冊到 client
@RegisterRestClient(configKey = "pricing-api")
@RegisterProvider(PricingApiExceptionMapper.class)
@Path("/v1/prices")
public interface PricingApiClient { /* ... */ }

方式 B：@ClientExceptionMapper（Quarkus 專屬，更簡潔）

Java · @ClientExceptionMapper
import org.jboss.resteasy.reactive.ClientExceptionMapper;
import jakarta.ws.rs.core.Response;

public class PricingExceptionMappers {

    @ClientExceptionMapper
    static PricingException toException(Response response) {
        if (response.getStatus() == 404) return new PriceNotFoundException();
        if (response.getStatus() >= 500) return new PricingServiceUnavailable();
        return null;     // null 表示不處理，丟預設例外
    }
}

Request / Response Filters

加 header（如 API key）、log、token 注入都用 filter：

Java · 加 API Key Filter
@Provider
public class ApiKeyFilter implements ClientRequestFilter {

    @ConfigProperty(name = "pricing.api.key")
    String apiKey;

    @Override
    public void filter(ClientRequestContext ctx) {
        ctx.getHeaders().add("X-API-Key", apiKey);
    }
}

@RegisterRestClient(configKey = "pricing-api")
@RegisterProvider(ApiKeyFilter.class)
public interface PricingApiClient { /* ... */ }

Quarkus 風格：@ClientRequestFilter / @ClientResponseFilter

Java · 註解式 filter
import org.jboss.resteasy.reactive.client.ClientRequestFilter;

public class PricingFilters {

    @ClientRequestFilter
    public static void addApiKey(ClientRequestContext ctx) {
        ctx.getHeaders().add("X-API-Key", System.getenv("PRICING_API_KEY"));
    }

    @ClientResponseFilter
    public static void logResponse(ClientRequestContext req, ClientResponseContext res) {
        Log.infof("← %s %s : %d", req.getMethod(), req.getUri(), res.getStatus());
    }
}

Multipart 檔案上傳

Client 端發送 multipart：

Java · 上傳檔案的 client
import org.jboss.resteasy.reactive.RestForm;
import org.jboss.resteasy.reactive.PartType;
import java.io.File;

@RegisterRestClient(configKey = "storage-api")
@Path("/v1/files")
public interface StorageClient {

    @POST
    @Consumes(MediaType.MULTIPART_FORM_DATA)
    UploadResult upload(
        @RestForm("file") @PartType(MediaType.APPLICATION_OCTET_STREAM) File file,
        @RestForm("description") @PartType(MediaType.TEXT_PLAIN) String description
    );
}

// 使用
@Inject @RestClient StorageClient storage;
File file = Path.of("/tmp/report.pdf").toFile();
UploadResult result = storage.upload(file, "Q4 報告");

支援的負載平衡策略：

策略說明
round-robin輪詢，預設
least-requests選當前進行中請求最少的實例
least-response-time選平均回應時間最短的
random隨機，最低開銷
sticky同一 caller 黏在同一實例（session affinity）
power-of-two-choices隨機選兩個，從中選請求少的，理論最優

OIDC 認證：自動帶 Token

微服務之間呼叫時，常常需要帶 Bearer Token。手寫 token 取得與刷新太繁瑣， Quarkus 提供 OIDC client filter 自動處理：

bash
quarkus extension add oidc-client rest-client-oidc-filter
application.properties · OIDC Client 配置
quarkus.oidc-client.auth-server-url=https://auth.example.com/realms/internal
quarkus.oidc-client.client-id=catalog-service
quarkus.oidc-client.credentials.secret=${OIDC_CLIENT_SECRET}
quarkus.oidc-client.grant.type=client
Java · 自動帶 Token
import io.quarkus.oidc.client.filter.OidcClientFilter;

@RegisterRestClient(configKey = "pricing-api")
@OidcClientFilter             // 標一下，自動加 Bearer Token
@Path("/v1/prices")
public interface PricingApiClient {

    @GET @Path("/{id}")
    Uni<Price> getPrice(@PathParam("id") Long id);
}

Token Propagation：轉發使用者 token

另一種情境：你的 endpoint 收到使用者的 token，想原封不動轉發給下游服務：

Java · Token 轉發
import io.quarkus.oidc.token.propagation.AccessToken;

@RegisterRestClient(configKey = "inventory-api")
@AccessToken                  // 從當前請求 propagate token
@Path("/v1/inventory")
public interface InventoryClient {

    @GET @Path("/{productId}")
    Stock getStock(@PathParam("productId") Long productId);
}

貫穿專案進度

catalog-service 整合 pricing-api 完整範例：

Java · 串連 client 到 Service
// 1. Client 定義
@RegisterRestClient(configKey = "pricing-api")
@OidcClientFilter
@Path("/v1/prices")
public interface PricingApiClient {

    @GET @Path("/{productId}")
    Uni<Price> getPrice(@PathParam("productId") Long productId);

    @ClientExceptionMapper
    static PricingException mapException(Response response) {
        if (response.getStatus() == 404) return new PriceNotFoundException();
        return null;
    }
}

// 2. Service 使用
@ApplicationScoped
public class CatalogService {

    @Inject @RestClient PricingApiClient pricingApi;
    @Inject ProductRepository repository;

    public Uni<ProductWithPrice> getEnriched(Long id) {
        Product product = repository.findById(id);
        return pricingApi.getPrice(id)
            .onFailure(PriceNotFoundException.class)
                .recoverWithItem(() -> Price.zero())
            .map(price -> new ProductWithPrice(product, price));
    }
}

// 3. REST endpoint
@GET
@Path("/{id}/enriched")
public Uni<ProductWithPrice> getEnriched(@PathParam("id") Long id) {
    return catalogService.getEnriched(id);
}

DevOps / SRE 視角

避免雪崩：合理的 timeout

⚠
沒設 timeout = 等死
Java client 預設 timeout 通常是「無限」。下游慢 = 你的應用 thread 全部卡死。 務必設 connect-timeout 與 read-timeout。 建議：connect-timeout 1-2s、read-timeout 依業務調整（多數應 < 10s）。

連線池大小

ℹ︎
經驗法則
connection-pool-size 應該大於你預期的同時併發呼叫數，但不要無限放大。 50~200 是常見起點。若看到「connection pool exhausted」就提升、或檢查是否有 connection leak。

觀測指標

整合 Micrometer 後（第 35 章），每個 REST Client 自動產生：

  • http.client.requests.seconds ── 呼叫延遲分布
  • http.client.requests.active ── 進行中請求數
  • http.client.connection.pool.size ── 連線池使用

常見陷阱

症狀原因解法
注入失敗：Unsatisfied dependency 缺 @RestClient qualifier @Inject @RestClient PricingApiClient client;
所有呼叫變 404 interface 與 server 的 @Path 拼接錯誤 檢查 quarkus.rest-client.{key}.url 是否含 base path
JSON 序列化失敗 沒裝 rest-client-jackson quarkus extension add rest-client-jackson
每次呼叫都重新建連線 connection-ttl 太短或連線池太小 調大池大小、檢查 Keep-Alive header
Stork 找不到服務 K8s namespace 或 service name 不對 檢查 kubectl get svc -n <ns> 確認服務存在
OIDC token 一直失敗 client_secret 過期或 scope 不對 檢查 auth server 設定、看 OIDC log

本章小結

  • Quarkus REST Client 用宣告式 Java interface + @RegisterRestClient，取代手寫 HTTP 呼叫。
  • 使用時注入要加 @RestClient qualifier。
  • 回傳 Uni / Multi 即自動成為 reactive client，支援並行組合。
  • 例外處理用 @ClientExceptionMapper（Quarkus 簡化版）或 ResponseExceptionMapper（標準）。
  • Filter 用 @ClientRequestFilter / @ClientResponseFilter 處理 header、log。
  • Stork 提供服務發現（K8s/Consul/Eureka/DNS）與負載平衡，URL 改用 stork:// 前綴即可。
  • OIDC Client Filter 自動取得、快取、刷新 token；Token Propagation 轉發使用者 token。
  • SRE 紅線：永遠設 connect-timeout 與 read-timeout，否則下游故障時你會跟著掛。
