Chapter 52 · Part XII

ArC 深入：Build-time CDI

Quarkus 的 CDI 容器 ArC 不是在 runtime 掃描 classpath、不是在執行時解析 bean ── 它在 build time 就完成所有分析、生成 bytecode proxy、刪除未使用的 bean。 理解 ArC 的運作模型，讓你知道為什麼 private method 的 @Transactional 被忽略、 為什麼 CDI.current().select() 要小心使用、以及如何用 Qualifier / Producer / Interceptor / Decorator 組合出乾淨的業務架構。

讀者 🔵 開發者
版本 Quarkus 3.33 LTS · ArC / CDI Lite 4.x
預估閱讀 30 分鐘
更新 2026-05-16

ArC 的 Build-time 模型

傳統 CDI 實作（如 Weld）在 runtime 掃描 classpath 找 bean。ArC 把這一切移到 build time：

ℹ︎
Build time CDI 的四個階段
  1. Bean Discovery：找出所有帶 bean-defining annotation 的類別（@ApplicationScoped、@Singleton等）
  2. Validation：注入點型別檢查、ambiguous bean 偵測、循環依賴 ── 編譯期就報錯
  3. Unused Bean Removal：找出沒有任何注入點使用的 bean → 移除（減少記憶體）
  4. Bytecode Generation：生成 proxy class、interceptor wrapper、injection code ── runtime 零反射

Scope 選擇

Scope語意注意
@ApplicationScoped整個應用唯一實例（lazy proxy）最常用；有 proxy，可以被 replace
@Singleton整個應用唯一實例（no proxy）無 proxy，效能略好；不能被 mock
@RequestScoped每個 HTTP 請求一個實例需要 HTTP context；Reactive 場景小心
@Dependent跟著注入點的生命週期每次注入產生新實例
@SessionScopedHTTP session 級別需要 quarkus-undertow
⚠
@ApplicationScoped vs @Singleton 的關鍵差異
@ApplicationScoped bean 會被包成 client proxy（代理物件），支援 lazy init、可被 mock（@InjectMock）。
@Singleton bean 沒有 proxy，直接是真實物件，效能略好但無法被 InjectMock 替換。
建議：大部分 service bean 用 @ApplicationScoped；只有效能極敏感的工具類才用 @Singleton。

Qualifier：同型別多實作

你有 NotificationService 介面，需要 email 和 SMS 兩種實作。Qualifier 解決歧義：

Java · 定義 Qualifier
import jakarta.inject.Qualifier;
import java.lang.annotation.*;

// 宣告 qualifier
@Qualifier
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.FIELD, ElementType.METHOD, ElementType.TYPE, ElementType.PARAMETER})
public @interface Channel {
    String value();
}

// 有 members 的 qualifier
@Qualifier
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.FIELD, ElementType.TYPE, ElementType.PARAMETER})
public @interface Priority {
    Level level() default Level.NORMAL;
    enum Level { LOW, NORMAL, HIGH }
}
Java · 多實作
// 實作 A
@ApplicationScoped
@Channel("email")
public class EmailNotificationService implements NotificationService {
    public void send(Notification n) { /* email 邏輯 */ }
}

// 實作 B
@ApplicationScoped
@Channel("sms")
public class SmsNotificationService implements NotificationService {
    public void send(Notification n) { /* SMS 邏輯 */ }
}

// 使用端注入特定實作
@ApplicationScoped
public class OrderService {

    @Inject @Channel("email")
    NotificationService emailNotifier;

    @Inject @Channel("sms")
    NotificationService smsNotifier;

    // 或動態選擇
    @Inject @Any
    Instance<NotificationService> notifiers;

    public void notifyAll(Notification n) {
        notifiers.stream().forEach(s -> s.send(n));
    }
}

Producer：動態 bean 建立

當 bean 不是簡單的 new 能建立的（需要配置、來自第三方 library），用 Producer：

Java · Producer method 與 field
@ApplicationScoped
public class InfrastructureProducers {

    @ConfigProperty(name = "aws.region") String region;
    @ConfigProperty(name = "aws.access-key") String accessKey;
    @ConfigProperty(name = "aws.secret-key") String secretKey;

    // Producer method：建立 S3Client 並交給 CDI 管理
    @Produces
    @ApplicationScoped
    public S3Client s3Client() {
        return S3Client.builder()
            .region(Region.of(region))
            .credentialsProvider(
                StaticCredentialsProvider.create(
                    AwsBasicCredentials.create(accessKey, secretKey)))
            .build();
    }

    // Producer field（簡單情況）
    @Produces
    @ApplicationScoped
    ObjectMapper objectMapper = new ObjectMapper()
        .enable(MapperFeature.ACCEPT_CASE_INSENSITIVE_ENUMS);
}

// 使用：直接 @Inject
@ApplicationScoped
public class UploadService {
    @Inject S3Client s3;
    @Inject ObjectMapper mapper;
}
ℹ︎
@Disposes：Producer 的資源清理
Producer 的對應是 Disposer ── bean scope 結束時呼叫：
@Disposes void closeS3(@Disposes S3Client s3) { s3.close(); }

Interceptor：橫切面關注點

Java · 自訂 Interceptor
// Step 1：定義 binding annotation
@InterceptorBinding
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface Audited {
    String action() default "";
}

// Step 2：實作 Interceptor
@Audited
@Interceptor
@Priority(Interceptor.Priority.APPLICATION)
public class AuditInterceptor {

    private static final Logger AUDIT = Logger.getLogger("com.example.audit");

    @AroundInvoke
    Object audit(InvocationContext ctx) throws Exception {
        String user = SecurityContext.currentUser();
        String method = ctx.getMethod().getName();
        Audited ann = ctx.getMethod().getAnnotation(Audited.class);

        Object result = ctx.proceed();

        AUDIT.infof("AUDIT user=%s action=%s method=%s",
            user, ann.action(), method);
        return result;
    }
}

// Step 3：使用
@ApplicationScoped
public class AdminService {

    @Audited(action = "DELETE_USER")
    public void deleteUser(String userId) { ... }

    @Audited(action = "GRANT_ROLE")
    public void grantRole(String userId, String role) { ... }
}
⚠
Interceptor 不作用於 private 方法
ArC 的 interceptor 透過 proxy 實作。proxy 無法攔截 private 方法呼叫（Java 的可見性規則）。
把 @Transactional、@Audited、@Retry 加在 private 方法上 ── Quarkus 3.x 起會直接 build failure。
解法：改成 public 或 package-private；或把邏輯移到 public 方法。

Decorator：增強現有 Bean

Decorator 是 Interceptor 的近親，但更「業務導向」── 它知道自己在增強什麼介面：

Java · 快取 Decorator
@Decorator
@Priority(10)
public class CachingProductService implements ProductService {

    @Inject @Delegate @Any
    ProductService delegate;             // 指向真實實作

    @Inject
    @CacheResult(cacheName = "products")
    ProductService cachedDelegate;       // 包一層 cache

    @Override
    public Product findById(Long id) {
        return cachedDelegate.findById(id);  // 先查 cache
    }

    @Override
    public List<Product> findAll() {
        return delegate.findAll();       // 不 cache 列表
    }
}

Unused Bean Removal

ArC build time 移除「沒有任何注入點使用」的 bean，減少記憶體與 binary 大小。 但有時候你的 bean 是「programmatically 查詢」而非直接 @Inject，就可能被誤刪：

application.properties · 控制移除行為
# 完全關閉（不建議，會增加 binary 大小）
# quarkus.arc.remove-unused-beans=false

# 只移除 framework beans，保留 application beans
quarkus.arc.remove-unused-beans=fwk

# 預設（所有未用的都移除）
quarkus.arc.remove-unused-beans=all
Java · 明確告訴 ArC「這個 bean 會被用」
// 方式 A：@Unremovable（只用於你確定需要保留的情況）
@ApplicationScoped
@io.quarkus.arc.Unremovable
public class SomeEventListener {
    public void onEvent(@Observes SomeEvent e) { ... }
}

// 方式 B：用 @Observes 宣告 observer 就不會被移除
@ApplicationScoped
public class StartupBean {
    void onStart(@Observes StartupEvent e) {
        Log.info("Application started!");
    }
}

Build Compatible Extension

傳統 CDI Portable Extensions 在 Quarkus 不支援（需要 runtime 的 SPI）。 替代方案是 CDI 4.0 的 Build Compatible Extension，在 build time 操作 bean 元資料：

Java · Build Compatible Extension（簡例）
import jakarta.enterprise.inject.build.compatible.spi.*;
import jakarta.enterprise.lang.model.declarations.ClassInfo;

public class MyExtension implements BuildCompatibleExtension {

    @Discovery
    public void discovery(ScannedClasses scan) {
        // 找出所有帶 @MyAnnotation 的類別，告訴 ArC 要處理它們
        scan.add("com.example.SomeClass");
    }

    @Enhancement(types = MyAnnotation.class)
    public void enhance(ClassConfig clazz, Messages messages) {
        // build time 為這些類別加 qualifier 或 scope
        clazz.addAnnotation(ApplicationScoped.class);
    }

    @Validation
    public void validate(BeanInfo bean, Messages messages) {
        // build time 驗證，錯誤在 build 就報出
    }
}

// 在 META-INF/services/jakarta.enterprise.inject.build.compatible.spi.BuildCompatibleExtension 中宣告類別名
ℹ︎
Build Compatible Extension 的使用場景
大多數開發者不需要寫 Build Compatible Extension ── 這是給 Quarkus 擴充作者用的 SPI。
如果你只是要自訂業務 bean 行為，Qualifier / Producer / Interceptor 就夠了。
Build Compatible Extension 適合：跨多個 bean 批次操作、自動化 registration、框架整合。

常見陷阱

症狀原因解法
Bean 找不到但明明有定義被 unused bean removal 移除加 @Unremovable 或用 @Observes
@Transactional 無效果（private 方法）proxy 無法攔截 private改 public；Quarkus 3.x 直接 build failure 提醒
Ambiguous dependency 錯誤兩個同型別無 qualifier 的 bean加 Qualifier 區分，或用 @Default + @Alternative
@ApplicationScoped 不可被 mock用了 @Singleton（無 proxy）改 @ApplicationScoped，或用 @Alternative 測試替代
CDI.current().select() 找不到 beanprogrammatic lookup 被誤刪加 @Unremovable 或在 application.properties 關閉移除

本章小結

  • ArC = Build-time CDI。Bean discovery、validation、unused removal、proxy 生成 ── 全在 build time。
  • Scope 選型：@ApplicationScoped（有 proxy，可 mock，推薦）vs @Singleton（無 proxy，略快，不可 mock）。
  • Qualifier：同型別多實作用 qualifier 消除歧義；@Any + Instance<T> 動態選擇。
  • Producer：第三方物件或需要複雜初始化的 bean；@Produces + @Disposes 管理生命週期。
  • Interceptor：橫切面（logging、audit、retry）；不作用於 private 方法（Quarkus build failure）。
  • Decorator：業務導向的 bean 增強；@Delegate 包裝真實實作。
  • Unused bean removal：@Unremovable 保護 programmatic 使用的 bean；observer method 自動保留。
  • Build Compatible Extension：Quarkus 擴充作者的 SPI，取代傳統 CDI Portable Extension。
