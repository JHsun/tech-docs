建構工具：Maven、Gradle 與 Quarkus CLI

Quarkus 支援三種建構方式，各有適用情境。Maven 是企業最主流的選擇，生態最成熟； Gradle 增量建構快、Kotlin DSL 易讀、適合大型多模組； Quarkus CLI 是最快速的起步工具，且三種工具都可以混用。 本章涵蓋：BOM 管理、擴充管理（add / remove / list）、打包格式（fast-jar / uber-jar / AOT jar）、 多模組專案結構、build profiles，最後整合 Quarkus Update 工具讓升版本不再是噩夢。

Quarkus CLI：最快速的起步方式

bash · 安裝 Quarkus CLI
# 用 SDKMAN（推薦）
sdk install quarkus

# 用 Homebrew（macOS）
brew install quarkusio/tap/quarkus

# 驗證
quarkus --version
bash · 常用 CLI 指令速查
# 建立新專案（Maven）
quarkus create app com.example:catalog-service \
  --extension="rest-jackson,hibernate-orm-panache,jdbc-postgresql,smallrye-health,opentelemetry"

# 建立新專案（Gradle Kotlin DSL）
quarkus create app com.example:catalog-service \
  --build-tool=gradle-kotlin-dsl \
  --extension="rest-jackson,hibernate-orm-panache"

# 啟動 dev 模式
quarkus dev

# 管理擴充
quarkus extension add opentelemetry
quarkus extension remove hibernate-search-orm-elasticsearch
quarkus extension list --installed
quarkus extension list --available | grep kafka

# 打包
quarkus build
quarkus build --native                         # native build
quarkus build -Dquarkus.container-image.build=true  # 順便建 Docker image

# 升版本
quarkus update                                 # 互動式升版
quarkus update --no-rewrite                    # 只更新 BOM，不做 code rewrite

Maven 建構詳解

BOM 管理

pom.xml · BOM 與 Plugin
<properties>
    <quarkus.platform.version>3.33.0</quarkus.platform.version>
    <compiler-plugin.version>3.13.0</compiler-plugin.version>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>

<dependencyManagement>
    <dependencies>
        <!-- Quarkus BOM：統一管理所有擴充版本 -->
        <dependency>
            <groupId>io.quarkus.platform</groupId>
            <artifactId>quarkus-bom</artifactId>
            <version>${quarkus.platform.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<build>
    <plugins>
        <plugin>
            <groupId>io.quarkus.platform</groupId>
            <artifactId>quarkus-maven-plugin</artifactId>
            <version>${quarkus.platform.version}</version>
            <extensions>true</extensions>
            <executions>
                <execution>
                    <goals>
                        <goal>build</goal>
                        <goal>generate-code</goal>
                        <goal>generate-code-tests</goal>
                    </goals>
                </execution>
            </executions>
        </plugin>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>${compiler-plugin.version}</version>
        </plugin>
    </plugins>
</build>

常用 Maven 指令速查

bash
# 開發
./mvnw quarkus:dev                      # dev 模式（熱重載）
./mvnw quarkus:dev -Ddebug=5005         # 附加 debugger

# 測試
./mvnw test                             # 只跑 @QuarkusTest
./mvnw verify                           # test + @QuarkusIntegrationTest
./mvnw test -pl catalog-service         # 只測特定模組

# 打包
./mvnw package                          # fast-jar（預設）
./mvnw package -Dquarkus.package.jar.type=uber-jar
./mvnw package -Dquarkus.package.jar.type=aot-jar

# Native
./mvnw package -Pnative
./mvnw package -Pnative -Dquarkus.native.container-build=true

# 依賴分析
./mvnw dependency:tree
./mvnw dependency:analyze               # 找未用 / 缺少的依賴

打包格式選型

格式說明適合
fast-jar（預設）target/quarkus-app/ 目錄結構，依賴分層 cache 友善容器部署（K8s）── Docker layer cache 命中率高
uber-jar所有依賴打進單一 JAR傳統部署、不想管目錄結構
aot-jarJVM 上的 ahead-of-time 初始化想縮短啟動時間但保留 JVM 診斷能力
nativeGraalVM native binary，含精簡 JVMScale-to-zero、記憶體嚴格限制
application.properties
# 設定打包格式（也可以 -D 覆寫）
quarkus.package.jar.type=fast-jar       # 預設
# quarkus.package.jar.type=uber-jar
# quarkus.package.jar.type=aot-jar

# uber-jar 輸出名稱
quarkus.package.output-name=catalog-service

fast-jar 的目錄結構

target/quarkus-app/ ├── lib/ │ ├── boot/ ← Quarkus 核心 bootstrap │ └── main/ ← 所有依賴 JAR（Docker layer cache 對象） ├── app/ │ └── catalog-service-1.0.jar ← 你的業務程式碼 └── quarkus-run.jar ← entry point（極小）
✓
fast-jar 為什麼快
Dockerfile 把 lib/ 和 quarkus-run.jar 分成兩層：
  1. COPY target/quarkus-app/lib/ /deployments/lib/（很少變）
  2. COPY target/quarkus-app/*.jar /deployments/（業務碼，常更新）
只有業務程式碼改動時，只有第 2 層 invalidated ── Docker push 速度快 10 倍。

Gradle Kotlin DSL

build.gradle.kts
plugins {
    kotlin("jvm") version "2.0.0"
    kotlin("plugin.allopen") version "2.0.0"
    id("io.quarkus") version "3.33.0"
}

repositories { mavenCentral() }

val quarkusPlatformGroupId = "io.quarkus.platform"
val quarkusPlatformVersion = "3.33.0"

dependencies {
    implementation(enforcedPlatform("${quarkusPlatformGroupId}:quarkus-bom:${quarkusPlatformVersion}"))

    implementation("io.quarkus:quarkus-rest-jackson")
    implementation("io.quarkus:quarkus-hibernate-orm-panache")
    implementation("io.quarkus:quarkus-jdbc-postgresql")
    implementation("io.quarkus:quarkus-smallrye-health")
    implementation("io.quarkus:quarkus-opentelemetry")

    testImplementation("io.quarkus:quarkus-junit5")
    testImplementation("io.rest-assured:rest-assured")
}

java {
    sourceCompatibility = JavaVersion.VERSION_21
    targetCompatibility = JavaVersion.VERSION_21
}

allOpen {
    // Quarkus 需要 CDI bean 不是 final
    annotation("jakarta.enterprise.context.ApplicationScoped")
    annotation("jakarta.persistence.Entity")
}

tasks.withType<Test> {
    systemProperty("java.util.logging.manager", "org.jboss.logmanager.LogManager")
}

多模組專案結構

bash · 典型結構
catalog-platform/                       # 父 POM
├── pom.xml                             # BOM import、pluginManagement
├── catalog-api/                        # 共用 API DTO（無 Quarkus 依賴）
│   └── pom.xml
├── catalog-service/                    # Quarkus 主服務
│   ├── pom.xml
│   └── src/
├── inventory-client/                   # REST Client stub
│   └── pom.xml
└── catalog-it/                         # @QuarkusIntegrationTest（分開模組避免影響 test 速度）
    └── pom.xml
pom.xml · 父 POM 關鍵設定
<parent>
    <groupId>io.quarkus.platform</groupId>
    <artifactId>quarkus-bom</artifactId>
    <version>3.33.0</version>
    <relativePath/>
</parent>

<modules>
    <module>catalog-api</module>
    <module>catalog-service</module>
    <module>inventory-client</module>
    <module>catalog-it</module>
</modules>

Build Profiles

pom.xml · 常用 profiles
<profiles>
    <!-- Native 建構 -->
    <profile>
        <id>native</id>
        <activation>
            <property><name>native</name></property>
        </activation>
        <properties>
            <skipITs>false</skipITs>
            <quarkus.native.enabled>true</quarkus.native.enabled>
        </properties>
    </profile>

    <!-- 同時建 Docker image -->
    <profile>
        <id>container</id>
        <properties>
            <quarkus.container-image.build>true</quarkus.container-image.build>
            <quarkus.container-image.push>true</quarkus.container-image.push>
        </properties>
    </profile>
</profiles>

quarkus update：升版本不再是噩夢

Quarkus 每 4–6 週發一個 minor release，每年發 LTS。升版本靠人工改 pom.xml 很容易漏掉 breaking change。quarkus update 用 OpenRewrite 自動做：

bash · quarkus update 流程
# 查看有哪些更新可用
quarkus update --dry-run

# 執行更新（自動修改 pom.xml、程式碼）
quarkus update

# 跨多個 major 版本（如 2.x → 3.x）
quarkus update --stream 3.x

# 只更新 BOM，不做 code rewrite
quarkus update --no-rewrite

# 更新後跑測試確認
./mvnw verify
✓
quarkus update 做了什麼
  1. 更新 quarkus.platform.version
  2. OpenRewrite recipe 自動改過時的 API（如 javax.* → jakarta.*）
  3. 更新廢棄的設定 key 名稱
  4. 更新測試 annotation（如 @NativeImageTest → @QuarkusIntegrationTest）
不保證 100% 無縫，但處理了 80–90% 的機械性工作。

常見陷阱

症狀原因解法
quarkus:dev 與 IDE 衝突兩個 JVM 都在監聽 debug port用 -Ddebug=false 關閉 dev mode debugger；或改 -Ddebug=5006
uber-jar 啟動找不到 MainMain-Class manifest 沒設用 fast-jar 或確認 quarkus-maven-plugin 正確配置
多模組 dev 模式子模組改不觸發 reloadQuarkus 只 watch 當前模組加 -Dquarkus.live-reload.watched-resources 或用 Gradle 複合建構
Gradle allOpen 忘加CDI bean 是 final，Quarkus 無法 proxy確保 allOpen 包含所有 CDI scope annotation
quarkus update 後測試失敗Breaking change 沒被 recipe 涵蓋看 Quarkus migration guide；搜 changelog

本章小結

  • Quarkus CLI：最快建立專案；extension add/remove/list 管理擴充；update 升版本。
  • Maven：企業主流；BOM 統一依賴版本；wrapper（mvnw）確保版本一致。
  • Gradle Kotlin DSL：增量建構快；需 allOpen plugin 讓 CDI bean 可被 proxy。
  • 打包格式：fast-jar（K8s 優化）、uber-jar（單檔傳統部署）、aot-jar（縮短啟動）、native（Scale-to-zero）。
  • fast-jar 分層結構讓 Docker build cache 命中率極高 ── lib/ 幾乎不變，app/ 常更新。
  • 多模組推薦把 IT test 抽到獨立模組，避免影響主 build 速度。
  • quarkus update：OpenRewrite 自動升版本；不能替代人工 review，但省去 80% 機械工作。
