Part 1 · Chapter 02 · Getting Started

入門Getting Started

用三條 quickstart 路徑——Docker、Kubernetes、Linux Host——在 10 分鐘內跑起 Falco， 觸發第一個 alert 並學會看懂輸出。本章對應官方 docs/getting-started/。

⏱ 預估閱讀 + 操作 60-90 分鐘 📚 對應 docs/getting-started/ 初學者 SRE 開發者

2.1在開始之前

Falco 直接觀察 Linux kernel 事件，因此環境前置條件比一般應用嚴格。先確認你的環境符合需求，否則後面會卡在 driver 載入。

三條路徑速覽

PATH 1 🐳 Docker 最快上手，5 分鐘內看到 alert PATH 2 ☸️ Kubernetes (Helm) 最接近生產環境 PATH 3 🐧 Linux Host 非容器化環境或 VM

環境需求

項目需求備註
KernelLinux 5.8+（推薦 Modern eBPF）4.14+ 可用 legacy eBPF（已 deprecated）
架構x86_64 或 aarch64 (ARM64)Apple Silicon Mac 無法直接跑（不是 Linux）
權限root / privileged container需要存取 /proc、/sys、/dev
Kubernetes1.23+（任一 distro）節點必須是 Linux，不能是 Docker Desktop k8s
🚨
Docker Desktop 行不通：在 macOS / Windows 上的 Docker Desktop 並不是真正的 Linux 容器， 它跑在 VM 裡，Falco 無法存取宿主 kernel。要在 Mac 上玩 Falco，請：
  1. 跑一台 Linux VM (Multipass、UTM、Lima)
  2. 用 cloud Linux VM（AWS/GCP/Azure）
  3. 或用 kind / minikube 配 Linux 後端

2.2路徑一：Docker Quickstart

最簡單的方式。一行 docker run 把 Falco 跑起來，立刻能看到 alert。適合在 Linux VM 上做第一次體驗。

準備一台 Linux 主機

確認 kernel 與必要工具：

bash · 環境檢查
uname -r                # kernel 版本 (>= 5.8 最佳)
cat /etc/os-release     # 確認 distro
which docker            # docker 已安裝
docker version          # docker 版本

啟動 Falco 容器

下面這條指令會自動下載最新版 Falco，掛上必要的主機路徑，以 Modern eBPF driver 啟動：

bash · 啟動 Falco
sudo docker run --rm -it \
  --name falco \
  --privileged \
  -v /var/run/docker.sock:/host/var/run/docker.sock \
  -v /proc:/host/proc:ro \
  -v /etc:/host/etc:ro \
  falcosecurity/falco:0.43.1

看到下面這類訊息就表示 Falco 已經在監聽 syscalls：

Falco version: 0.43.1 Falco initialized with configuration files: /etc/falco/falco.yaml System info: Linux 6.5.0-... Loaded event sources: syscall Starting health webserver with threadiness 0, listening on port 8765 Falco initialized. Detected 0 dropped events Starting health webserver with threadiness 0, listening on 0.0.0.0:8765

觸發第一個 alert

開另一個 terminal，做一個 Falco 預設規則會抓的動作——讀取 /etc/shadow：

bash · 觸發測試
# 製造一個會觸發 default rule 的動作
sudo cat /etc/shadow > /dev/null

# 或：在容器內開 shell
docker run --rm -it alpine sh -c "ls /etc"

切回跑 Falco 的 terminal，應該會看到類似這樣的 alert：

15:42:18.123456789: Warning Sensitive file opened for reading by non-trusted program (file=/etc/shadow user=root process=cat command=cat /etc/shadow parent=bash terminal=34816)
💡
Driver 自動偵測：從 v0.36 開始，Falco 啟動時會自動嘗試載入 Modern eBPF； 若失敗才 fallback 到 legacy eBPF 或 kmod。多數現代 Linux 不用手動指定 driver。 若需強制：加 -e FALCO_BPF_PROBE=""（legacy eBPF）或先跑 falco-driver-loader。

停止與清理

bash · 停止 Falco
# 容器本身用 --rm，Ctrl+C 後自動清掉
# 若用 -d 跑：
docker stop falco
docker rm falco

2.3路徑二：Kubernetes Quickstart (Helm)

生產環境最接近的部署方式。透過官方 Helm chart 一鍵安裝 DaemonSet，每個節點一個 Falco pod。

📌
Operator vs Helm：從 Falco Operator 0.2.0 (2026-03) 起，官方文件已將 Operator 列為 k8s 推薦方式， 但 Helm 仍完全支援。初學者建議先用 Helm 練手；進入生產後再評估 Operator。 Operator 的完整教學在 Ch.08 · 安裝部署。

確認叢集條件

bash · 前置檢查
kubectl get nodes -o wide                 # 節點是 Linux 嗎？
kubectl version --short                    # k8s 版本 (>= 1.23)
helm version                               # helm 已安裝 (>= 3.7)
kubectl get nodes -o jsonpath='{.items[*].status.nodeInfo.kernelVersion}'

加 Helm repo 並安裝

bash · 安裝 Falco
# 1) 加 repo
helm repo add falcosecurity https://falcosecurity.github.io/charts
helm repo update

# 2) 一行安裝
helm install --replace falco \
  --namespace falco --create-namespace \
  --set tty=true \
  falcosecurity/falco

# 3) 等 pods ready
kubectl wait pods --for=condition=Ready --all -n falco --timeout=120s

查看 pods：

bash · 驗證
kubectl get pods -n falco -o wide
# NAME          READY   STATUS    RESTARTS   AGE   NODE
# falco-2x5pq   2/2     Running   0          45s   worker-1
# falco-7knpz   2/2     Running   0          45s   worker-2

每個 pod 是兩個 container（falco 本身 + falcoctl sidecar 負責拉 rules/plugins）。

觸發 alert

建一個 nginx pod，然後在裡面做敏感操作：

bash · 製造事件
# 部署 nginx
kubectl run nginx --image=nginx
kubectl wait --for=condition=Ready pod/nginx --timeout=60s

# 觸發 1：寫入 /etc（會觸發 "File below /etc opened for writing"）
kubectl exec nginx -- touch /etc/test_file_for_falco_rule

# 觸發 2：在容器內開 shell（會觸發 "Terminal shell in container"）
kubectl exec -it nginx -- /bin/bash -c "whoami"

看 Falco 的 alert

bash · 查看 alerts
# tail 所有 falco pod 的 log
kubectl logs -n falco -l app.kubernetes.io/name=falco \
  --tail=100 -f

# 或單 pod
kubectl logs -n falco falco-2x5pq -c falco -f

你會看到類似這樣的 alert（注意已自動補上 K8s metadata）：

13:14:27.811647863: Warning File below /etc opened for writing (file=/etc/test_file_for_falco_rule process=touch parent=containerd-shim user=root command=touch /etc/test_file_for_falco_rule container_id=bf74f1749e23 container_image=docker.io/library/nginx container_name=nginx k8s_ns=default k8s_pod_name=nginx)

關鍵差別：對比 Docker 路徑的 alert，這裡多了 container_* 與 k8s_* 欄位——這就是 Falco 透過 container plugin 自動 enrich 的結果。

客製化 values（生產雛形）

用一份 values.yaml 把基本生產參數固定下來，避免每次都用 --set：

values.yaml · 基礎生產設定
## values.yaml — Falco quickstart 生產雛形
tty: true                     # 即時 flush 輸出

driver:
  enabled: true
  kind: modern_ebpf           # 推薦
  # kind 可選: modern_ebpf | kmod | ebpf (legacy, deprecated)

collectors:
  enabled: true
  containerd:
    enabled: true
    socket: /run/containerd/containerd.sock
  docker:
    enabled: false            # 用 containerd 就不用 docker

falco:
  json_output: true                       # log 用 JSON 比較好被解析
  json_include_output_property: true
  log_stderr: true
  log_syslog: false
  priority: debug                          # 開發階段；prod 改 notice

  # 預設規則由 falcoctl sidecar 管理，這裡不需要列
  rules_files:
    - /etc/falco/falco_rules.yaml
    - /etc/falco/falco_rules.local.yaml
    - /etc/falco/rules.d

# 啟用 falcosidekick 把告警轉發出去（細節見 Ch.05）
falcosidekick:
  enabled: true
  webui:
    enabled: true             # 提供本地 UI 看 alerts
bash · 用 values 重新部署
helm upgrade --install falco \
  -n falco --create-namespace \
  -f values.yaml \
  falcosecurity/falco

# 等待 rollout
kubectl rollout status ds/falco -n falco --timeout=120s

# 看 falcosidekick UI
kubectl port-forward -n falco svc/falco-falcosidekick-ui 2802:2802
# 瀏覽器開 http://localhost:2802

移除

bash · 卸載
helm uninstall falco -n falco
kubectl delete namespace falco

2.4路徑三：Linux Host Quickstart

若你的工作負載直接跑在 VM 或 bare metal（沒有 k8s），用 DEB / RPM 包安裝 Falco 是最自然的方式。 Falco 會註冊成 systemd service。

匯入 GPG key（v0.43 後必做）

2026-01 官方輪替了 GPG key，新舊都要按官方步驟匯入：

bash · DEB 系（Ubuntu / Debian）
curl -fsSL https://falco.org/repo/falcosecurity-packages.asc | \
  sudo gpg --dearmor -o /usr/share/keyrings/falco-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/falco-archive-keyring.gpg] \
https://download.falco.org/packages/deb stable main" | \
  sudo tee /etc/apt/sources.list.d/falcosecurity.list

sudo apt-get update -y
bash · RPM 系（CentOS / RHEL / Fedora）
sudo rpm --import https://falco.org/repo/falcosecurity-packages.asc

sudo curl -s -o /etc/yum.repos.d/falcosecurity.repo \
  https://falco.org/repo/falcosecurity-rpm.repo

sudo yum -y update
⚠️
升級舊機器警告：2026-01-17 前安裝的舊節點若沒匯入新 key，apt update 會因 signature 失敗中斷。 要先 apt-key del 舊指紋，或乾脆刪掉 /etc/apt/trusted.gpg.d/ 內舊檔，再執行上面的步驟。 新 key fingerprint：478B2FBBC75F4237B731DA4365106822B35B1B1F。

安裝

bash · 安裝（DEB）
sudo apt-get install -y falco
# 安裝過程會跳互動視窗詢問 driver；選擇 "Modern eBPF"
bash · 安裝（RPM）
sudo yum install -y falco

啟動 service

bash · 啟動 systemd unit
# Modern eBPF 模式
sudo systemctl enable --now falco-modern-bpf.service

# 看狀態
sudo systemctl status falco-modern-bpf.service

# 看即時 log
sudo journalctl -fu falco-modern-bpf.service
💡
不同 unit 對應不同 driver：
  • falco-modern-bpf.service ← Modern eBPF（推薦）
  • falco-bpf.service ← Legacy eBPF（已 deprecated）
  • falco-kmod.service ← Kernel module（需 kernel headers）
三者擇一啟用，不要同時開。

觸發 alert 並驗證

bash · 觸發測試
# 製造事件
sudo touch /etc/test_file_for_falco_rule

# 確認 alert
sudo journalctl -fu falco-modern-bpf.service | grep -i "file below /etc"

主要設定檔位置

檔案用途
/etc/falco/falco.yaml主設定：driver、outputs、metrics
/etc/falco/falco_rules.yaml官方預設 rules（勿直接修改）
/etc/falco/falco_rules.local.yaml你的自訂 rules（在此編輯）
/etc/falco/rules.d/放更多 rule 檔的目錄
/etc/falco/falcoctl/falcoctl 設定（rule/plugin 更新來源）

2.5解讀第一份 alert 輸出

Falco alert 不只一行文字——它承載了 rule 名稱、嚴重度、觸發環境、process tree、container/k8s context。 看得懂結構才能快速判斷是 false positive 還是真威脅。

純文字格式（預設）

15:42:18.123456789: Warning Sensitive file opened for reading by non-trusted program (file=/etc/shadow user=root process=cat command=cat /etc/shadow parent=bash)

欄位拆解：

欄位意義來自
15:42:18.123…事件觸發時間（nanosecond 精度）kernel
Warningrule 的 priority 等級rule 定義
「Sensitive file…」rule 的 output 模板rule 定義
file=...觸發事件相關欄位syscall 參數
process=...觸發 process 名稱kernel proc info

JSON 格式（推薦給機器解析）

把 falco.json_output: true 打開後，每筆 alert 都會變成單行 JSON：

json · 範例 alert
{
  "hostname": "worker-1",
  "output": "15:42:18.123456789: Warning File below /etc opened for writing (file=/etc/test_file_for_falco_rule ...)",
  "output_fields": {
    "container.id": "bf74f1749e23",
    "container.image.repository": "docker.io/library/nginx",
    "evt.time": 1739720538123456789,
    "fd.name": "/etc/test_file_for_falco_rule",
    "k8s.ns.name": "default",
    "k8s.pod.name": "nginx",
    "proc.cmdline": "touch /etc/test_file_for_falco_rule",
    "proc.name": "touch",
    "proc.pname": "containerd-shim",
    "user.name": "root"
  },
  "priority": "Warning",
  "rule": "Write below etc",
  "source": "syscall",
  "tags": ["filesystem", "mitre_persistence", "T1098"],
  "time": "2026-05-15T15:42:18.123456789Z"
}

JSON 格式適合：

  • 送進 SIEM / data lake：Elasticsearch、Splunk、Loki、BigQuery 都能直接索引
  • 用 jq 篩選：kubectl logs ... | jq 'select(.priority=="Critical")'
  • 對接 falcosidekick：sidekick 直接吃 JSON，路由到 Slack/PagerDuty

Priority 等級

Falco 沿用 syslog 風格的 priority，從低到高：

等級典型情境建議處理
Emergency系統幾乎不能用立即 page on-call
Alert需立即處理立即通知
Critical嚴重情境，例如 root 異常活動立即通知
Error錯誤或可疑同工時段告警
Warning需注意但不緊急每日彙整
Notice應該留意的事件每日彙整
Informational一般訊息記錄即可
Debug除錯用開發階段
✓
實務建議：生產環境把 Falco 自身 priority 設為 notice 以上， 避免被 informational/debug 訊息淹沒；告警轉發時再依 priority 分流（如 Critical 以上 → PagerDuty；Warning → Slack）。

2.6Learning Environments（互動沙箱）

若你連 Linux VM 都不想開，Falco 官方有幾個 web-based 互動環境，瀏覽器即可體驗。

環境適合連結
Falco Sandbox (Killercoda) 無需安裝；含預先觸發的 scenarios killercoda.com/falco
Falco Playground 專門練習寫 rule，內建 condition 編輯器與 syscall mock 官方 Learning Environments
event-generator 本地跑的容器，自動產生各種會觸發 rule 的事件，方便壓力測試 github.com/falcosecurity/event-generator

event-generator 速試

在已經跑著 Falco 的環境裡（host 或 k8s），跑這個容器自動觸發各種預設 rule，用來驗證部署是否正常：

bash · Docker 環境
docker run -it --rm falcosecurity/event-generator run syscall \
  --loop
bash · Kubernetes 環境
# 在另一個 namespace 跑 event-generator
kubectl run event-generator \
  --image=falcosecurity/event-generator \
  --restart=Never \
  -- run syscall --loop

# 然後到 falco namespace 看 alert
kubectl logs -n falco -l app.kubernetes.io/name=falco --tail=200 | grep "Notice\|Warning\|Critical"

2.7第一次部署檢查清單

不管走哪條路徑，跑完之後對著這份清單檢查，確認你已經完成「runtime detection 就位」的最小可行配置。

項目檢查指令 / 觀察點OK?
Falco process 在跑 systemctl status falco-* / kubectl get pods -n falco ☐
Driver 載入成功 啟動 log 沒有 Failed to find a usable BPF probe ☐
沒有大量 dropped event 啟動 log 看 Detected N dropped events，N=0 為佳 ☐
能觸發測試 alert touch /etc/test_file_for_falco_rule 後可見 ☐
輸出格式正確 JSON / 純文字 之一可被解析 ☐
K8s metadata 有 enrich (僅 k8s) alert 內含 k8s_pod_name 等欄位 ☐
不影響 workload 效能 跑壓測前後 latency 差 < 5% ☐
🎉
完成第一次部署！到這裡你已經有了一個能跑、能觸發 alert 的 Falco。 下一步是真正理解它的工作原理——往 Ch.03 · Event Sources 開始深入。
