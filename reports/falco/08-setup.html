8.1部署決策樹

Falco 有 5 種主要部署方式。沒有「最好」的選擇，只有「最適合你環境」的選擇。

圖 8.1 · 部署方式決策樹

五種方式對比

方式適用優點限制
Operator K8s 生產環境（新建） CRD 管理；ecosystem 一鍵；GitOps 友善 需安裝 operator；學習曲線
Helm K8s 生產環境（現有） 完整、成熟、社群熟悉 values.yaml 較複雜

DEB/RPM VM / bare metal systemd 整合；apt/yum 自動更新 每節點手動裝
Tarball 無 package manager 的 distro 完全可控 需自己管 systemd unit
💡
官方立場（2026-03 起）：Falco Operator 0.2.0 為「推薦的 K8s 部署方式」， Helm chart 仍完整支援、未來不會消失。新部署建議從 Operator 開始； 已用 Helm 的環境不需立刻遷移。

8.2方式一：Falco Operator

Falco Operator 用 Kubernetes Custom Resources 來宣告式管理 Falco 實例、規則、plugins。 v0.2.0 (2026-03) 是首個 production-ready release。

Falco Operator 0.2.0RECOMMENDED

提供四個核心 CRD：

  • Falco：宣告一個 Falco 實例（含 driver、collectors、resources）
  • FalcoRule：管理規則（支援 OCI artifact、ConfigMap、inline）
  • FalcoPlugin：載入 plugin
  • FalcoComponent：管理 ecosystem（falcosidekick、UI、k8s-metacollector）

STEP 1 — 安裝 Operator

bash · 用 Helm 裝 Operator
helm repo add falcosecurity https://falcosecurity.github.io/charts
helm repo update

helm install falco-operator falcosecurity/falco-operator \
  --namespace falco-system --create-namespace \
  --version 0.2.0

kubectl get pods -n falco-system
# falco-operator-controller-manager-xxx   2/2 Running

STEP 2 — 部署 Falco 實例（CR）

yaml · Falco CR
apiVersion: falco.falcosecurity.org/v1alpha2
kind: Falco
metadata:
  name: falco
  namespace: falco
spec:
  version: 0.43.1
  driver:
    kind: modern_ebpf
  collectors:
    enabled: true
    containerd:
      enabled: true
    kubernetes:
      enabled: true
  config:
    inline:
      json_output: true
      json_include_output_property: true
      priority: notice
      static_fields:
        cluster: prod-us-east-1
        env: prod
  resources:
    requests: { cpu: 100m, memory: 256Mi }
    limits:   { cpu: 1000m, memory: 1Gi }
bash · 套用
kubectl create ns falco
kubectl apply -f falco-cr.yaml

# 觀察狀態
kubectl get falco -n falco -w
kubectl describe falco falco -n falco

STEP 3 — 管理 rules（FalcoRule CR）

用 inline YAML（小規模）或 ConfigMap 參照（大規模）：

yaml · FalcoRule inline
apiVersion: falco.falcosecurity.org/v1alpha2
kind: FalcoRule
metadata:
  name: custom-prod-rules
  namespace: falco
spec:
  falcoRef:
    name: falco
  rules:
    inline:
      - rule: Untrusted Image in Production
        desc: production ns 出現非可信 image
        condition: >
          spawned_process and k8s.ns.name = production
          and not container.image.repository startswith myregistry.example.com/
        output: "Untrusted image (image=%container.image.repository pod=%k8s.pod.name)"
        priority: CRITICAL
        tags: [custom, supply_chain]

STEP 4 — 啟用 ecosystem（FalcoComponent）

yaml · 啟用 falcosidekick + UI
apiVersion: falco.falcosecurity.org/v1alpha2
kind: FalcoComponent
metadata:
  name: ecosystem
  namespace: falco
spec:
  falcoRef:
    name: falco
  falcosidekick:
    enabled: true
    replicaCount: 2
    config:
      slack:
        webhookurl: "https://hooks.slack.com/..."
        minimumpriority: notice
  webui:
    enabled: true
  k8sMetacollector:
    enabled: true
✓
Operator 的 GitOps 紅利：所有 Falco config / rules / ecosystem 都是 CR， 天然適合 Argo CD / Flux。把這些 YAML 放進 git repo，PR review、版本控制、rollback 全部到位。

8.3方式二：Helm Chart（完整 production values）

Helm 仍是現有環境的主流。下面是一份「對齊 v0.43、生產就緒」的完整 values.yaml 範本。

完整 production values.yaml

values.yaml · production-ready
# ============================================================
# Falco Helm values — production-ready (對齊 Falco v0.43)
# Helm chart 版本 4.x（與 Falco 0.43 對應，請以 helm search repo 為準）
# ============================================================

image:
  registry: docker.io
  repository: falcosecurity/falco-no-driver
  tag: "0.43.1"
  pullPolicy: IfNotPresent

tty: true

# ============== Driver ==============
driver:
  enabled: true
  kind: modern_ebpf            # 推薦；ARM64 / x86_64 皆支援
  loader:
    enabled: true
    initContainer:
      enabled: true

# ============== Collectors（container metadata）==============
collectors:
  enabled: true
  docker: { enabled: false }
  containerd:
    enabled: true
    socket: /run/containerd/containerd.sock
  crio:
    enabled: false
  kubernetes:
    enabled: true

# ============== Resources ==============
resources:
  requests: { cpu: 100m, memory: 256Mi }
  limits:   { cpu: 1000m, memory: 1Gi }

# ============== Tolerations（讓 Falco 也跑在 master）==============
tolerations:
  - effect: NoSchedule
    operator: Exists
  - key: node-role.kubernetes.io/control-plane
    operator: Exists
    effect: NoSchedule

# ============== falcoctl sidecar（自動更新 rules / plugins）==============
falcoctl:
  artifact:
    install:
      enabled: true
      refs:
        - falco-rules:5
        - k8saudit-rules:0.10
        - k8saudit:0.7
    follow:
      enabled: true
      refs:
        - falco-rules:5
      every: 6h
  config:
    artifact:
      install:
        rulesfilesdir: /etc/falco
        pluginsdir: /usr/share/falco/plugins
    indexes:
      - name: falcosecurity
        url: https://falcosecurity.github.io/falcoctl/index.yaml

# ============== Falco config ==============
falco:
  json_output: true
  json_include_output_property: true
  json_include_tags_property: true
  log_stderr: true
  log_syslog: false
  priority: notice

  rules_files:
    - /etc/falco/falco_rules.yaml
    - /etc/falco/falco_rules.local.yaml
    - /etc/falco/rules.d

  static_fields:
    cluster: prod-us-east-1
    env: prod
    region: us-east-1

  base_syscalls:
    repair: true

  syscall_event_drops:
    threshold: 0.1
    actions: [log, alert]
    rate: 0.03333
    max_burst: 1

  http_output:
    enabled: true
    url: "http://falco-falcosidekick:2801/"
    keep_alive: false

  metrics:
    enabled: true
    interval: 1h
    output_rule: true
    rules_counters_enabled: true
    resource_utilization_enabled: true
    state_counters_enabled: true
    kernel_event_counters_enabled: true
    libbpf_stats_enabled: true
    convert_memory_to_mb: true

  webserver:
    enabled: true
    listen_port: 8765
    k8s_healthz_endpoint: /healthz
    ssl_enabled: false
    prometheus_metrics_enabled: true

# ============== Custom rules（範例）==============
customRules:
  custom-prod.yaml: |-
    - macro: trusted_image
      condition: container.image.repository startswith "myregistry.example.com/"

    - rule: Untrusted Image in Production
      desc: production 出現非可信來源 image
      condition: spawned_process and k8s.ns.name = production and not trusted_image
      output: "Untrusted image (image=%container.image.repository pod=%k8s.pod.name)"
      priority: CRITICAL
      tags: [supply_chain, custom]

# ============== falcosidekick ==============
falcosidekick:
  enabled: true
  replicaCount: 2
  config:
    customfields: "cluster:prod-us"
    slack:
      webhookurl: ""              # 從 Secret 注入（見下）
      minimumpriority: notice
      channel: "#security-alerts"
    pagerduty:
      routingkey: ""
      minimumpriority: critical
    loki:
      hostport: "http://loki.logging:3100"
      tenant: falco
  webui:
    enabled: true
    replicaCount: 1
    redis: { enabled: true }

# ============== Prometheus 整合 ==============
serviceMonitor:
  create: true
  namespace: monitoring
  interval: 30s
  labels:
    release: kube-prometheus-stack

# ============== Extra env（注入 secret）==============
extra:
  env:
    - name: NODE_NAME
      valueFrom: { fieldRef: { fieldPath: spec.nodeName } }

用 Secret 注入 webhook URL

bash · 注入 Slack webhook
# 建 secret
kubectl create secret generic falco-slack -n falco \
  --from-literal=webhookurl="https://hooks.slack.com/services/..."

# 在 values.yaml 用 existingSecret
helm upgrade --install falco -n falco -f values.yaml \
  --set falcosidekick.config.slack.webhookurl="" \
  falcosecurity/falco

# 或在 values 內用 envFrom 模式（更乾淨）
# 詳細寫法見官方 chart 文件

套用 / 升級 / 卸載

bash · Helm 操作三件套
# 安裝
helm install falco -n falco --create-namespace \
  -f values.yaml falcosecurity/falco

# 升級
helm upgrade falco -n falco -f values.yaml falcosecurity/falco
kubectl rollout status ds/falco -n falco

# diff（建議裝 helm-diff plugin）
helm diff upgrade falco -n falco -f values.yaml falcosecurity/falco

# 卸載
helm uninstall falco -n falco
kubectl delete ns falco
⚠️
Chart 版本對應 Falco 版本：升級時不只看 chart 版本，也要看內含的 image.tag。 可在 Artifact Hub 或 GitHub Releases 比對。用 helm search repo falcosecurity/falco --versions 列出所有版本。

8.4方式三：Container 部署

非 K8s 但容器化的環境（Nomad、純 Docker host、CI 環境）。可選 driver 內建版本與分離版本。

三種官方 image

Image包含用途
falcosecurity/falcofalco + 全部 driver單獨跑、自帶 driver-loader
falcosecurity/falco-no-driverfalco + falcoctl，無 driverK8s + 外掛 driver loader（Helm 預設）
falcosecurity/falco-driver-loaderdriver build/load 工具init container 專用

單機 Docker 跑法

bash · 啟動 Falco container
docker run --rm -d --name falco \
  --privileged \
  -v /var/run/docker.sock:/host/var/run/docker.sock \
  -v /proc:/host/proc:ro \
  -v /etc:/host/etc:ro \
  -v $(pwd)/falco.yaml:/etc/falco/falco.yaml:ro \
  -v $(pwd)/custom-rules.yaml:/etc/falco/rules.d/custom-rules.yaml:ro \
  -p 8765:8765 \
  falcosecurity/falco:0.43.1

docker-compose 範例

docker-compose.yaml
version: "3.8"

services:
  falco:
    image: falcosecurity/falco:0.43.1
    container_name: falco
    privileged: true
    restart: unless-stopped
    volumes:
      - /var/run/docker.sock:/host/var/run/docker.sock
      - /proc:/host/proc:ro
      - /etc:/host/etc:ro
      - ./falco.yaml:/etc/falco/falco.yaml:ro
      - ./custom-rules.yaml:/etc/falco/rules.d/custom-rules.yaml:ro
    ports:
      - "8765:8765"
    depends_on:
      - falcosidekick

  falcosidekick:
    image: falcosecurity/falcosidekick:2.32.0
    environment:
      SLACK_WEBHOOKURL: "${SLACK_WEBHOOK}"
      SLACK_MINIMUMPRIORITY: notice
    ports:
      - "2801:2801"

8.5方式四：DEB / RPM Host 安裝

VM 與 bare metal 環境。安裝完後變成 systemd service。 對 v0.43，GPG key 已在 2026-01 輪替——舊機升級要重匯 key。

新節點安裝

bash · Ubuntu / Debian
curl -fsSL https://falco.org/repo/falcosecurity-packages.asc | \
  sudo gpg --dearmor -o /usr/share/keyrings/falco-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/falco-archive-keyring.gpg] \
https://download.falco.org/packages/deb stable main" | \
  sudo tee /etc/apt/sources.list.d/falcosecurity.list

sudo apt-get update
sudo apt-get install -y falco
# 互動選擇 Modern eBPF
bash · RHEL / CentOS / Fedora
sudo rpm --import https://falco.org/repo/falcosecurity-packages.asc

sudo curl -s -o /etc/yum.repos.d/falcosecurity.repo \
  https://falco.org/repo/falcosecurity-rpm.repo

sudo yum install -y falco

啟動對應的 systemd unit

bash · 三選一
sudo systemctl enable --now falco-modern-bpf.service  # 推薦
# sudo systemctl enable --now falco-bpf.service       # legacy eBPF (deprecated)
# sudo systemctl enable --now falco-kmod.service      # kmod

sudo systemctl status falco-modern-bpf.service
sudo journalctl -fu falco-modern-bpf.service

舊機升級的 GPG key 處理

  1. 移除舊 key：sudo apt-key del <舊指紋> 或刪 /etc/apt/trusted.gpg.d/ 內舊檔
  2. 按上面步驟匯入新 key
  3. 再 apt update / yum update

用 falcoctl 自動更新 rules

主機端 Falco 也可裝 falcoctl 自動拉新 rules：

bash · falcoctl on host

8.6方式五：Tarball 手動安裝

不喜歡 package manager、用 minimal OS（Alpine、Talos）、或想 air-gapped 部署時用。

bash · 下載並安裝
VERSION=0.43.1
ARCH=x86_64        # 或 aarch64

curl -fsSL https://download.falco.org/packages/bin/${ARCH}/falco-${VERSION}-${ARCH}.tar.gz \
  | sudo tar -xz -C /opt

sudo ln -s /opt/falco-${VERSION}-${ARCH} /opt/falco

# 自己寫 systemd unit
sudo tee /etc/systemd/system/falco.service <<'EOF'
[Unit]
Description=Falco Runtime Security
After=network.target

[Service]
ExecStart=/opt/falco/usr/bin/falco -c /opt/falco/etc/falco/falco.yaml
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now falco
⚠️
缺點：沒有 apt/yum 自動安全更新；driver 需手動處理； 用 tarball 時建議自己包成 OCI artifact 或 internal package 統一管理。

8.7EKS 特殊環境

EKS 託管 control plane，使用者不能改 API server flags——這影響 k8s_audit plugin 部署。 好消息：2025 起 Falco 已成為官方 EKS Add-on。

方式 A：EKS Add-on（最簡單）

bash · EKS Add-on
aws eks create-addon \
  --cluster-name my-eks-cluster \
  --addon-name falcosecurity_falco \
  --addon-version v0.43.1-eksbuild.1 \
  --resolve-conflicts OVERWRITE

aws eks describe-addon \
  --cluster-name my-eks-cluster \
  --addon-name falcosecurity_falco

方式 B：Helm + k8saudit-eks plugin

用 plugin 從 CloudWatch 拉 audit log。需要先在 CloudWatch 啟用 EKS audit log：

bash · 啟用 EKS audit log
aws eks update-cluster-config \
  --name my-eks-cluster \
  --logging '{"clusterLogging":[{"types":["audit"],"enabled":true}]}'
values.yaml · 啟用 k8saudit-eks
falco:
  load_plugins: [k8saudit-eks, json]
  plugins:
    - name: k8saudit-eks
      library_path: libk8saudit-eks.so
      init_config:
        region: us-east-1
        profile: ""                      # 留空用 IRSA
        shift: 10                        # 從 N 秒前開始
        polling_interval: 5s
      open_params: /aws/eks/my-eks-cluster/cluster

falcoctl:
  artifact:
    install:
      enabled: true
      refs:
        - k8saudit-eks:0.7
        - k8saudit-rules:0.10

# IRSA 設定：service account 綁 IAM role
serviceAccount:
  create: true
  annotations:
    eks.amazonaws.com/role-arn: "arn:aws:iam::123456789012:role/falco-cloudwatch-reader"

IAM Policy（給 falco service account）

json · CloudWatch read policy
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "logs:DescribeLogGroups",
      "logs:DescribeLogStreams",
      "logs:GetLogEvents",
      "logs:FilterLogEvents"
    ],
    "Resource": "arn:aws:logs:us-east-1:123456789012:log-group:/aws/eks/my-eks-cluster/cluster:*"
  }]
}

8.8GKE 特殊環境

GKE Standard 跟自管 K8s 差不多；GKE Autopilot 限制嚴格（不能跑 privileged pod）—— Falco 在 Autopilot 上幾乎無法部署，需用 GKE Standard。

GKE Standard 部署

用 Helm 部署沒有特殊處理；唯一注意：GKE 預設用 containerd，socket 路徑同 Helm 預設。

K8s audit log（用 gcpaudit plugin）

GKE 不允許改 API server，要透過 Cloud Logging：

values.yaml · gcpaudit plugin
falco:
  load_plugins: [gcpaudit, json]
  plugins:
    - name: gcpaudit
      library_path: libgcpaudit.so
      init_config: ""
      open_params: '{"projectid":"my-project","subscription":"falco-audit-sub"}'

falcoctl:
  artifact:
    install:
      enabled: true
      refs:
        - gcpaudit:0.5
        - gcpaudit-rules:0.4

# Workload Identity 綁 GCP service account
serviceAccount:
  create: true
  annotations:
    iam.gke.io/gcp-service-account: "falco-audit@my-project.iam.gserviceaccount.com"

事前準備

  1. 在 GCP 開 Audit Log → 設 Pub/Sub topic
  2. 建 Subscription falco-audit-sub
  3. 給 GCP SA 權限 roles/pubsub.subscriber
  4. 用 Workload Identity 綁到 K8s SA
⚠️
GKE Autopilot 不可用：Autopilot 禁止 privileged pod、不允許掛 hostPath、限制 capabilities， Falco 無法獲取 syscall。生產若需 runtime security，改用 GKE Standard 或 GKE node auto-provisioning。

8.9AKS 特殊環境

AKS 行為接近 GKE Standard。Audit log 需透過 Diagnostic Settings 送到 Event Hub 或 Log Analytics。

啟用 audit log

bash · az cli
az monitor diagnostic-settings create \
  --resource $(az aks show -g rg -n my-aks --query id -o tsv) \
  --name falco-audit \
  --logs '[{"category":"kube-audit","enabled":true}]' \
  --event-hub falco-audit-hub \
  --event-hub-rule "RootManageSharedAccessKey"

用通用 webhook plugin（社群方案）

目前沒有官方 AKS plugin。實務上有兩條路：

  • 用 Azure Function 把 Event Hub 訊息轉成 HTTP POST 給 Falco 的 k8saudit webhook
  • 用社群 plugin（如 azure-eventhub，仍 incubating）

8.10falcoctl 完整指南

falcoctl 是 Falco 生態的 package manager——從 OCI registry 拉 rules 與 plugins、 管理版本、自動更新。

核心 artifact 類型

Artifact內容典型版本
falco-rules官方 syscall ruleset5（major track）
k8saudit-rulesK8s audit ruleset0.10
k8sauditK8s audit plugin0.7
cloudtrailCloudTrail plugin0.13
oktaOkta plugin0.10
containercontainer metadata plugin0.6

常用命令

bash · falcoctl 速查
# 列出已知 artifact
falcoctl artifact search

# 看 artifact 詳細
falcoctl artifact info falco-rules:5

# 安裝特定版本
falcoctl artifact install falco-rules:5.0.0

# 安裝最新（follow latest tag）
falcoctl artifact install falco-rules --latest

# 列已安裝
falcoctl artifact list

# 移除
falcoctl artifact uninstall k8saudit

# 啟動 follow daemon（持續輪詢更新）
falcoctl artifact follow falco-rules:5 --every=6h

從私有 registry 拉 artifact

bash · 私有 OCI registry
falcoctl registry auth oauth registry.mycompany.com \
  --client-id ... --client-secret ...

falcoctl artifact install registry.mycompany.com/falco/custom-rules:1.0

8.11升級與版本管理

Falco 的「升級」其實有三條獨立軌道：binary、driver、rules， 各自有自己的 cadence。

三軌獨立升級

軌道cadence升級方式
Falco binary季度 minor (v0.42 → v0.43)helm upgrade / apt upgrade
Driver跟 binary 走自動由 driver-loader 處理
Rules持續，獨立版本falcoctl follow（不用 helm upgrade）

升級 Falco 版本（Helm）

bash · 升級流程
# 1. 看可用版本
helm search repo falcosecurity/falco --versions | head -10

# 2. 做 diff
helm diff upgrade falco -n falco -f values.yaml \
  --version <new-chart-version> \
  falcosecurity/falco

# 3. 漸進升級：先在 staging cluster
# 4. 套用
helm upgrade falco -n falco -f values.yaml \
  --version <new-chart-version> \
  falcosecurity/falco

# 5. 等 rollout
kubectl rollout status ds/falco -n falco --timeout=300s

# 6. 驗證 alert 仍會觸發
kubectl run test-trigger --image=alpine --restart=Never -- sh -c "touch /etc/foo"
kubectl logs -n falco -l app.kubernetes.io/name=falco | grep -i "below /etc"

升級 Rules（不重啟 binary）

如果用了 falcoctl follow，rules 會自動拉新版。 Falco binary 內建 inotify，偵測到 rule 檔變動會 hot reload，不會中斷監控。

Rollback

bash · helm rollback
helm history falco -n falco
helm rollback falco <revision> -n falco
