Outputs
輸出與告警

Alert 觸發後要送到哪裡？本章涵蓋 Falco 五大原生 output channels、輸出格式 (text / JSON)、 以及生態系最重要的 falcosidekick——它把 Falco 接到 60+ 種下游系統。

⏱ 預估閱讀 45 分鐘 📚 對應 docs/concepts/outputs/ 初學者 SRE

5.1Output 架構總覽

Falco 觸發 alert 後，會把資料送到啟用的 channels。一個 alert 可以同時送多個 channel。 從 Falco 自身的 channels 出來後，通常會經 falcosidekick 路由到更多下游。 

flowchart LR
    R[Rule Match] --> F[Falco Engine]
    F --> C1[stdout]
    F --> C2[file]
    F --> C3[syslog]
    F --> C4[program]
    F --> C5[http/https]
    C5 --> S[falcosidekick]
    S --> O1[Slack]
    S --> O2[PagerDuty]
    S --> O3[Elasticsearch]
    S --> O4[Loki / Splunk]
    S --> O5[S3 / GCS]
    S --> O6[Webhook / Lambda]
    S --> O7[60+ outputs]

5.2五大原生 Channels

Falco 內建 5 種 output channel。每個都可獨立 enable/disable、設定格式。

① stdout_output — 標準輸出

最簡單、最常用。容器化部署時尤其方便——由 kubectl logs 直接看，再由 log collector (Fluent Bit / Vector) 收走。

falco.yaml
stdout_output:
  enabled: true

② file_output — 寫到檔案

非容器環境或想自己管理 log rotation 時用。

falco.yaml
file_output:
  enabled: true
  keep_alive: false                # true = 開檔不關，效能好但檔被 rotate 時要 SIGHUP
  filename: /var/log/falco/events.log

③ syslog_output — Syslog

傳統 SIEM 整合最常用。透過 local syslog daemon 轉發到中央。

falco.yaml
syslog_output:
  enabled: true

④ program_output — 外部程式

每筆 alert 觸發一個外部命令，alert 內容從 stdin 讀入。能做最 ad-hoc 的整合，但效能低、不適合高流量。

falco.yaml
program_output:
  enabled: true
  keep_alive: false
  program: |
    jq '{text: .output}' | curl -s -d @- -X POST \
      -H 'Content-Type: application/json' \
      "$SLACK_WEBHOOK_URL"
🚨
慎用：每筆 alert 都 fork 一次新 process，CPU 開銷大。高流量環境改用 http_output + falcosidekick。

⑤ http_output — HTTP(S) Webhook

生產推薦的方式。Falco 把每筆 alert POST 到指定 URL，搭配 falcosidekick 就能扇出。

falco.yaml
http_output:
  enabled: true
  url: "http://falcosidekick:2801/"
  user_agent: "falcosecurity/falco"
  insecure: false
  ca_cert: ""
  ca_bundle: ""
  ca_path: "/etc/ssl/certs"
  mtls: false
  client_cert: ""
  client_key: ""
  echo: false
  compress_uploads: false
  keep_alive: false

5.3輸出格式：Text vs JSON

所有 channels 共用同一個格式設定。生產環境一律用 JSON，方便下游 parse、SIEM 索引、做欄位查詢。

啟用 JSON

falco.yaml · JSON 輸出
json_output: true
json_include_output_property: true
json_include_tags_property: true
log_stderr: true
log_syslog: false
priority: notice

v0.43 新功能：static_fields

把固定的 metadata（叢集名、環境）注入每筆 alert——下游分流方便很多：

falco.yaml · static_fields
static_fields:
  cluster: production-us-east-1
  env: prod
  team: platform-security
  region: us-east-1

每筆 alert 的 output_fields 都會多出這幾個 key。Helm 部署中用 downward API 把 nodeName 也注入：

values.yaml · downward API
extra:
  env:
    - name: NODE_NAME
      valueFrom: { fieldRef: { fieldPath: spec.nodeName } }

falco:
  static_fields:
    cluster: my-prod-cluster
    node: ${NODE_NAME}

5.4falcosidekick — 告警的 fan-out 大腦

falcosidekick 是 Falco 生態系最重要的伴侶。它收 Falco 的 HTTP alert，路由到 60+ 種下游： Slack、PagerDuty、Teams、Discord、Email、Elasticsearch、Loki、Splunk、S3、Lambda、Kafka、NATS……

用 Helm 一鍵啟用 falcosidekick + UI

values.yaml · falcosidekick
falcosidekick:
  enabled: true
  replicaCount: 2
  config:
    debug: false
    customfields: "cluster:prod-us"
    outputfieldformat: "**Rule**: "

    slack:
      webhookurl: "https://hooks.slack.com/services/AAA/BBB/CCC"
      minimumpriority: notice
      messageformat: "Falco alert in {{ .OutputFields.k8s.ns.name }}"
      channel: "#security-alerts"
      username: falco-bot
      icon: ":fire:"
      footer: "Generated by Falco"

    pagerduty:
      routingkey: "xxxxxxxxxxxx"
      minimumpriority: critical

    elasticsearch:
      hostport: "http://elasticsearch.logging:9200"
      index: "falco"
      type: "_doc"
      minimumpriority: debug

    loki:
      hostport: "http://loki.logging:3100"
      tenant: "falco"
      extralabels: "cluster,env"

  webui:
    enabled: true
    replicaCount: 1
    redis:
      enabled: true

  service:
    type: ClusterIP
    port: 2801

套用與驗證

bash
helm upgrade falco -n falco -f values.yaml falcosecurity/falco
kubectl rollout status deployment/falco-falcosidekick -n falco

kubectl logs -n falco -l app.kubernetes.io/name=falcosidekick -f

kubectl port-forward -n falco svc/falco-falcosidekick-ui 2802:2802
# 瀏覽器開 http://localhost:2802

常用整合速覽

下游用途建議 minimumpriority
Slack團隊 chat 告警notice
PagerDuty / OpsGenieon-call 通知critical
MS Teams / Discord替代 Slacknotice
Elasticsearch長期存查debug
LokiGrafana 整合debug
S3 / GCS合規歸檔debug
Webhook自訂後處理視情況
Kafka / NATS事件匯流排debug
SMTP傳統 emailerror
💡
分流原則：建議「全收進 SIEM/Loki + 高優先 page on-call + 中優先進 chat」三層。 不要單一渠道收所有 priority，否則重要告警會被洗掉。

5.5Buffering、Retry 與 Rate Limiting

Output 端故障（網路斷、下游服務掛）會 block Falco 處理新事件，造成 syscall drop。 透過 buffer 與 throttling 機制隔離問題。

輸出緩衝（v0.42+）

falco.yaml · outputs queue
outputs:
  rate: 0
  max_burst: 1000
  timeout: 2000

outputs_queue:
  capacity: 0
  # 建議生產設 10000~50000

對 program / http output 的 keep_alive

keep_alive: true 讓 Falco 不每次 fork process / 重開連線—— program 提升 ~10x throughput；http 省 TCP handshake。但代價是檔案 rotate 或下游重啟時 Falco 不會自動重連，需 kill -HUP。

5.6心智模型總結

  • 5 種 channel：stdout / file / syslog / program / http，可同時啟用多個
  • 格式幾乎必選 JSON（json_output: true）
  • 用 static_fields 把 cluster / env / region 烙進每筆 alert
  • http_output → falcosidekick 是生產標配路徑
  • 不同 priority 走不同 channel（PagerDuty / Slack / SIEM 三層）
  • gRPC output 已 deprecated
  • 注意 output buffer 與 timeout，避免下游故障拖累 Falco 自身
