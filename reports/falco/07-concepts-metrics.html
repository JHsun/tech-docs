Part 2.5 · Chapter 07 · Concepts

Metrics
監控 Falco 自身

Falco 不只觀察別人，自己也要被觀察。v0.38+ 內建 Prometheus exporter， 提供 syscall 處理速率、規則命中、drop 數、資源使用等指標。 這章教你開啟、抓 metrics、與 Grafana 整合。

⏱ 預估閱讀 25 分鐘 📚 對應 docs/concepts/metrics/ SRE

7.1為什麼要監控 Falco 自己

Falco 監控你的系統——但它自己也可能出問題： Driver 故障、ring buffer 滿、規則錯誤、CPU/RAM 飆高、HTTP output 卡住⋯⋯ 沒監控等於沒 detection。

關鍵問題：你怎麼知道 Falco 還在工作？

  • 「沒有 alert」是因為真的沒事，還是 Falco 掛了？
  • Drop rate 開始上升嗎？
  • 哪條 rule 觸發最多？哪條從來沒觸發？
  • 哪個 node 上的 Falco 比較吃 CPU？

這些都是 metrics 要回答的問題。

⚠️
合規要求：SOC 2、PCI-DSS、ISO 27001 等稽核框架，通常要求安全偵測工具本身的「可用性與完整性」也要有持續監控證據。 Falco metrics 是最低成本的合規舉證來源。

7.2啟用 Metrics

v0.38+ 內建支援 Prometheus exporter。在 falco.yaml 中啟用即可。

基本設定

falco.yaml · 啟用 metrics
metrics:
  enabled: true
  interval: 1h                  # 內部快照間隔（影響 log line metrics）
  output_rule: true             # 把 metrics 也當作 alert 發出（適合 Loki/SIEM 端整合）

  # ==================== 細項 ====================
  rules_counters_enabled: true               # 每條 rule 命中次數
  resource_utilization_enabled: true         # CPU、RSS、container 記憶體
  state_counters_enabled: true               # threads/fds/containers 數量
  kernel_event_counters_enabled: true        # 各 syscall 計數
  libbpf_stats_enabled: true                 # eBPF 內部統計
  convert_memory_to_mb: true                 # 統一單位
  include_empty_values: false

webserver:
  enabled: true
  threadiness: 0                  # 0 = auto (CPU 數)
  listen_port: 8765
  k8s_healthz_endpoint: /healthz
  ssl_enabled: false
  prometheus_metrics_enabled: true   # 暴露 /metrics
  endpoint: /metrics                 # 預設路徑

透過 Helm 啟用

values.yaml
falco:
  metrics:
    enabled: true
    interval: 1h
    output_rule: true
    rules_counters_enabled: true
    resource_utilization_enabled: true
    state_counters_enabled: true
    kernel_event_counters_enabled: true
    libbpf_stats_enabled: true
    convert_memory_to_mb: true
  webserver:
    enabled: true
    listen_port: 8765
    prometheus_metrics_enabled: true

serviceMonitor:
  create: true
  namespace: monitoring         # Prometheus Operator 的 namespace
  interval: 30s
  scrapeTimeout: 10s
  labels:
    release: kube-prometheus-stack

抓 metrics 看看

bash · port-forward 後 curl
POD=$(kubectl get pod -n falco -l app.kubernetes.io/name=falco -o name | head -1)
kubectl port-forward -n falco $POD 8765:8765 &
curl -s http://localhost:8765/metrics | head -40

7.3核心 Metrics 解讀

Falco 暴露上百個 metric，下面整理生產上最常監控的核心指標。

falcosecurity_falco_n_evts_total

從啟動以來累積處理的事件總數。計算 rate 看 throughput——突降到 0 表示 driver 出問題。

falcosecurity_falco_n_drops_total

最重要的健康指標。事件流失數。任何持續增長都要 alert——通常需調校 ring buffer 或 base_syscalls。

falcosecurity_falco_n_drops_perc

近期 drop 比例。建議 alert threshold > 0.1%。

falcosecurity_falco_rules_matches_total{rule="..."}

每條 rule 的命中次數。可以：
① 找出 noisy rule（命中量極大 → 該 tune 或加 exception）
② 找出 dead rule（從未命中 → 可能太緊或環境不適用）

falcosecurity_falco_cpu_usage_perc

Falco process CPU 使用率。生產上每節點通常 1-5%；超過 20% 就要看是 driver 還是 rule engine 在吃。

falcosecurity_falco_memory_rss_bytes

RSS 記憶體。穩定環境通常 100-300 MB。緩慢攀升可能是 memory leak（罕見，但回報 issue）。

falcosecurity_falco_kernel_event_X_total

各 syscall 計數，X 是 syscall 名（如 open、execve）。用來理解 workload 特徵，輔助 base_syscalls 調校。

falcosecurity_falco_n_threads

Falco 追蹤的 thread 數量。極大值通常表示有處理不過來的事件流。

7.4Prometheus + Grafana 整合

用 Prometheus Operator 的 ServiceMonitor 自動發現 Falco metrics。 Grafana 端有官方 dashboard 可直接用。

ServiceMonitor（kube-prometheus-stack）

Helm chart 內建 serviceMonitor.create: true 會自動產生：

yaml · 自動產生的 ServiceMonitor
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: falco
  namespace: monitoring
  labels:
    release: kube-prometheus-stack
spec:
  selector:
    matchLabels:
      app.kubernetes.io/name: falco
  namespaceSelector:
    matchNames: [falco]
  endpoints:
    - port: metrics
      path: /metrics
      interval: 30s

關鍵 Alert Rules（PromQL）

yaml · PrometheusRule
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: falco-health
  namespace: monitoring
spec:
  groups:
    - name: falco-health
      rules:
        # 1. Falco 沒在處理事件
        - alert: FalcoNotProcessingEvents
          expr: rate(falcosecurity_falco_n_evts_total[5m]) == 0
          for: 5m
          labels: { severity: critical }
          annotations:
            summary: "Falco on {{ $labels.instance }} 沒在處理事件"

        # 2. Drop rate 過高
        - alert: FalcoDroppingEvents
          expr: rate(falcosecurity_falco_n_drops_total[5m]) > 10
          for: 10m
          labels: { severity: warning }
          annotations:
            summary: "Falco drop 率持續高於 10/s on {{ $labels.instance }}"

        # 3. CPU 過高
        - alert: FalcoHighCPU
          expr: falcosecurity_falco_cpu_usage_perc > 20
          for: 15m
          labels: { severity: warning }
          annotations:
            summary: "Falco CPU > 20% on {{ $labels.instance }}"

        # 4. 任一 critical rule 觸發
        - alert: FalcoCriticalAlertFired
          expr: |
            increase(falcosecurity_falco_rules_matches_total{priority="critical"}[5m]) > 0
          labels: { severity: critical }
          annotations:
            summary: "Falco CRITICAL 規則觸發: {{ $labels.rule }}"

Grafana Dashboard

官方有 dashboard 可用：

  • Falco Cluster Dashboard (ID 11914)
  • Falco Metrics (ID 17537, v0.38+)

匯入方式：Grafana → Dashboards → Import → 輸入 dashboard ID。

7.5Health endpoint

除了 /metrics，Falco webserver 還暴露 health endpoint，供 Kubernetes liveness/readiness probe 使用。

Endpoints

Endpoint用途HTTP code
/healthzliveness：falco process 還活著嗎200 OK / 500 死
/metricsPrometheus metrics200 OK
/versionsfalco/driver/plugin 版本資訊200 OK

Helm 預設的 probe 配置

yaml · Pod spec 片段
livenessProbe:
  httpGet:
    path: /healthz
    port: 8765
  initialDelaySeconds: 60
  periodSeconds: 15

readinessProbe:
  httpGet:
    path: /healthz
    port: 8765
  initialDelaySeconds: 30
  periodSeconds: 15

7.6心智模型總結

  • Falco v0.38+ 內建 Prometheus exporter 與 health endpoint
  • 啟用 metrics 後對 /metrics 抓資料，配 Prometheus + Grafana
  • 核心 SLI：events processed rate、drop rate、CPU、rule matches
  • 四條必設 alert：not processing、dropping、high CPU、critical rule fired
  • 用 metrics 找 noisy / dead rules 做 tune；合規稽核也用同樣資料
