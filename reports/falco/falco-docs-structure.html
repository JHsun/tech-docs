05Repo 對應關係

網站文件由 Hugo 從 falcosecurity/falco-website 渲染。每個導覽節點對應到 repo 內 content/en/docs/<section>/ 下的 markdown 檔。

網站章節 Repo 路徑 說明
Getting Started content/en/docs/getting-started/ 三條 quickstart 平台路徑
Setup content/en/docs/setup/ 含 operator、kubernetes、container、packages 子目錄
Concepts → Event Sources content/en/docs/concepts/event-sources/ kernel/ 與 plugins/ 二大來源
Concepts → Rules content/en/docs/concepts/rules/ 14 個子頁，涵蓋 basic-elements、conditions、exceptions、overriding 等
Concepts → Outputs content/en/docs/concepts/outputs/ channels / formatting / forwarding
Reference → Rules content/en/docs/reference/rules/ 含 supported-events/ 由 falco --list-events --markdown 自動生成
Reference → Default Rules 動態抓取 透過 rules_list shortcode 從 falcosecurity/rules repo 即時載入
Developer Guide content/en/docs/developer-guide/ plugins/ 與 grpc/

動態生成示意

supported-events 頁面並非手寫，而是用 Falco binary 自身產生 markdown，再 commit 進 repo。 這保證文件與 binary 行為完全同步： 

falco --list-events --markdown \
  > ./content/en/docs/reference/rules/supported-events/supported-events.md

同樣的，default rules 頁面透過 Hugo shortcode 即時從 GitHub 抓 YAML：

{{- $stableURL := printf
   "https://raw.githubusercontent.com/falcosecurity/rules/falco-rules-%s/rules/falco_rules.yaml"
   .Site.Params.rulesStableVersion -}}
💡
設計重點：把「會隨版本變動的東西」全部 generate 而非手寫，是 Falco 文件最值得學習的地方。 --list-events、--list -N、--list -F 等 CLI 都被 release 流程用來產出 reference 頁。

06Concepts vs Reference：分工原則

這是讀 Falco 文件最常踩雷的地方——同一個主題（Rules、Plugins）會同時出現在 Concepts 與 Reference。其實兩者切角完全不同。

    A --> C[Reference

    B --> B1[Rule Basics]
    B --> B2[Condition Syntax]
    B --> B3[Exceptions / Overriding]
    C --> C1[Supported Fields 表]
    C --> C2[Supported Events 表]
    C --> C3[Default Macros 列表]
    C --> C4[Default Rules 完整 YAML]

07觀察與筆記

幾個從章節結構推出的設計意圖，與閱讀時值得留意的點。

① 雙層 Plugins 文件

Plugins 同時出現在三處：Concepts/Plugins（架構概念）、 Developer Guide/Plugins（開發流程）、Reference/Plugins（API spec）。 這是有意的分層：終端使用者只需讀 Concepts；plugin 作者讀完三層。

② Deprecation 訊號

v0.43 的文件 (Last modified 2026-01-23) 把 legacy eBPF probe gVisor gRPC 三者標記為 deprecated。新讀者可直接跳過這些章節，把注意力放在 Modern eBPF。

⚠️
注意：Developer Guide → gRPC API 整章已 deprecated。如要做 outputs forwarding， 請改看 Concepts → Outputs → Forwarding 並搭配 falcosidekick。

③ Versions 切換器

頂部 Versions 選單可切換到 v0.26 ~ v0.43。每個版本對應 repo 一個獨立 deploy。 若需引用過去行為（例如某 macro 在 v0.36 才支援 rule_matching: all）， 可切回該版查證。

④ Edit / Issue 三按鈕

每頁底部有 Edit this page、Create documentation issue、Create project issue。 這是 Hugo + Docsy 主題的標配，鼓勵讀者直接修文件——文件本身就是個 Pull Request 友善的 onboarding 入口。

⑤ Style Guide of Falco Rules

藏在 Concepts → Rules → Style Guide 的一頁，常被忽略。 寫自訂 rule 前建議先讀，避免在 PR 階段被退件——例如命名慣例、tag 規範、output 格式等。
