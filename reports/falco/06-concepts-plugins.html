Plugins
外掛架構

Plugin 是 Falco 擴展邊界的關鍵——讓它從「容器安全」變成「雲端全棧偵測平台」。 本章解釋 plugin 兩種類型 (source / extractor)、生命週期，並走過官方 registry 的重要 plugins。 開發 plugin 的詳細流程在 Ch.10。

⏱ 預估閱讀 35 分鐘 📚 對應 docs/concepts/plugins/ SRE 開發者

6.1什麼是 Plugin

Plugin 是動態載入的共享函式庫 (.so)，遵循 Falco Plugin API， 在 Falco 啟動時透過 dlopen 載入。它讓 Falco 能：

  • 新增 event source（例：把 AWS CloudTrail logs 當成 source）
  • 擴充 field（extractor）（例：從現有事件中萃取新欄位給 rule 用）

兩種 plugin 類型

類型角色典型範例
Source plugin提供新 event sourcek8saudit、cloudtrail、okta
Extractor plugin給現有 source 加 fieldjson（解析 JSON 字串成欄位）
兩者皆是同時提供 source 與 extract field多數官方 plugin（含 container）
💡
內建 vs Plugin：syscall source 是 Falco 內建（透過 driver 提供），不算 plugin。 所有非 syscall 的 event source 都來自 plugin。

6.2Plugin 架構

每個 plugin 透過 C ABI 與 Falco 通訊，由幾個 vtable function 構成。

flowchart LR
    F[falco binary] -->|dlopen| P[plugin.so]
    P --> I[plugin_init
讀 init_config]
    P --> O[plugin_open
讀 open_params]
    P --> N[plugin_next_batch
產出事件流]
    P --> E[plugin_extract_fields
把事件解析成欄位]
    N -->|events| F
    E -->|field values| F
    F --> R[Rule Engine]
    style F fill:#cffafe,stroke:#0891b2,color:#0c2b35
    style P fill:#fef3c7,stroke:#d97706,color:#7a4a05
圖 6.1 · Plugin 與 Falco 的互動

啟用 plugin 的三段設定

falco.yaml · plugin 設定範例
load_plugins: [k8saudit, json]

plugins:
  - name: k8saudit
    library_path: libk8saudit.so          # 相對於 plugins_dir
    init_config: ""                        # plugin 初始化 JSON
    open_params: "http://:9765/k8s-audit"  # 來源 endpoint

  - name: json
    library_path: libjson.so
    init_config: ""

plugins_dir: /usr/share/falco/plugins

Plugin 生命週期

  1. Load：Falco 啟動時讀 load_plugins，dlopen 對應 .so
  2. Init：呼叫 plugin_init()，傳入 init_config
  3. Open：對 source plugin 呼叫 plugin_open()，傳入 open_params
  4. Run：Falco 不斷呼叫 plugin_next_batch() 拉新事件
  5. Extract：規則匹配時呼叫 plugin_extract_fields() 取欄位值
  6. Close：Falco 結束前呼叫 plugin_close()

6.3官方 Plugin Registry

所有官方認可的 plugin 集中在 falcosecurity/plugins repo。 每個 plugin 有自己的 maturity 等級（stable / incubating / sandbox），與 rules maturity 概念一致。

Stable 等級 plugins

containerstable

v0.41 起把 container metadata 補強邏輯獨立成 plugin。絕大多數 default rules 依賴它， Helm/Operator 部署預設安裝。提供 container.*、k8s.* 欄位。

k8sauditstable

從 K8s API server 收 audit logs。支援兩種 ingest 模式：HTTP webhook（被動）、檔案輪詢。 提供 ka.* 欄位族。

bash · 安裝
falcoctl artifact install k8saudit:0.7
falcoctl artifact install k8saudit-rules:0.10

cloudtrailstable

輪詢 S3 bucket 中的 CloudTrail logs。能觀察 AWS 全部 IAM、EC2、S3、Lambda 等 API。 需 IAM role 給 S3 read 權限。

oktastable

輪詢 Okta System Log API。需 API token。能偵測 MFA bypass、admin 異常操作、suspicious login。

jsonstable

Extractor plugin。把任意 JSON 字串解析成可被 condition 引用的欄位（用 jq-style path）。 常與其他 source plugin 搭配。

Incubating / Sandbox 等級

k8saudit-ekssandbox

專門從 AWS CloudWatch Logs 拉 EKS audit logs。EKS 用戶幾乎都要這個。

gcpauditsandbox

從 GCP Cloud Logging 拉 audit logs。GKE 適用。

githubsandbox

GitHub Audit API。偵測 repo 機密外洩、admin 操作等。需 PAT。

krsisandbox

Kernel Runtime Security Instrumentation——用 LSM hook 而非 tracepoint， 可獲取更多 kernel 內部資訊。實驗中。

完整清單見 Plugins Registry。

6.4用 falcoctl 管理 Plugins

falcoctl 是 plugin 與 rules 的 package manager。它從 OCI registry 拉 plugin artifact、 放到對應目錄、更新 falco.yaml 配置。

核心命令

bash · falcoctl 速查
# 看可用的 artifacts
falcoctl artifact search

# 看本地已安裝
falcoctl artifact list

# 安裝 plugin (含其官方 ruleset)
falcoctl artifact install k8saudit:0.7
falcoctl artifact install k8saudit-rules:0.10

# 升級到最新
falcoctl artifact install k8saudit --latest

# 看 plugin 詳情
falcoctl artifact info k8saudit:0.7

# 移除
falcoctl artifact uninstall k8saudit

falcoctl 設定（指定來源 registry）

/etc/falcoctl/falcoctl.yaml
artifact:
  install:
    refs:
      - falco-rules:5
      - k8saudit-rules:0.10
    rulesfilesdir: /etc/falco
    pluginsdir: /usr/share/falco/plugins
  follow:
    refs:
      - falco-rules:5                      # 自動追蹤 stable 5.x 系列更新
    every: 6h

indexes:
  - name: falcosecurity
    url: https://falcosecurity.github.io/falcoctl/index.yaml

K8s 中的 falcoctl sidecar

Helm chart 預設會在 Falco DaemonSet 中跑一個 falcoctl sidecar，負責定期拉新版 rule 與 plugin。 這讓你不用重 deploy 整個 DaemonSet 就能 update rules——重要的安全 best practice。

values.yaml · falcoctl sidecar
falcoctl:
  artifact:
    install:
      enabled: true
      refs:
        - falco-rules:5
        - k8saudit-rules:0.10
        - k8saudit:0.7
    follow:
      enabled: true
      refs:
        - falco-rules:5
      every: 6h

6.5K8s Audit Plugin 完整範例

結合 Ch.03 與 Ch.05 的內容，這節示範端到端啟用 k8saudit——大概是最有價值的非 syscall plugin。

架構

flowchart LR
    A[K8s API Server] -->|audit webhook| W[k8saudit-webhook
NodePort/LB]
    W --> P[k8saudit plugin
in falco pod]
    P --> F[Falco engine]
    F --> R[k8s_audit_rules.yaml]
    R --> O[Outputs]
    style P fill:#cffafe,stroke:#0891b2,color:#0c2b35

STEP 1 — Falco 端啟用 plugin

values.yaml
falco:
  load_plugins: [k8saudit, json]
  plugins:
    - name: k8saudit
      library_path: libk8saudit.so
      init_config: ""
      open_params: "http://:9765/k8s-audit"
    - name: json
      library_path: libjson.so
      init_config: ""
  rules_files:
    - /etc/falco/falco_rules.yaml
    - /etc/falco/k8s_audit_rules.yaml

falcoctl:
  artifact:
    install:
      enabled: true
      refs:
        - k8saudit:0.7
        - k8saudit-rules:0.10

services:
  - name: k8saudit-webhook
    type: NodePort
    ports:
      - port: 9765
        nodePort: 30007
        protocol: TCP

STEP 2 — K8s API server 設定 audit webhook

不同 distro 設定方式不同（self-managed kubeadm / EKS / GKE / AKS）。kubeadm 範例：

/etc/kubernetes/audit-policy.yaml
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
  - level: Metadata
    omitStages: [RequestReceived]
/etc/kubernetes/audit-webhook.yaml
apiVersion: v1
kind: Config
clusters:
  - name: falco
    cluster:
      server: http://<NODE_IP>:30007/k8s-audit
contexts:
  - name: default-context
    context:
      cluster: falco
      user: ""
current-context: default-context

在 API server 啟動參數加：

kube-apiserver args
--audit-policy-file=/etc/kubernetes/audit-policy.yaml
--audit-webhook-config-file=/etc/kubernetes/audit-webhook.yaml
--audit-webhook-batch-max-wait=5s

STEP 3 — 驗證

bash · 驗證
# 製造 audit event
kubectl exec -it nginx -- /bin/sh

# Falco 應該收到 k8s_audit source 的 event
kubectl logs -n falco -l app.kubernetes.io/name=falco -c falco | \
  grep "k8s_audit"
⚠️
EKS / GKE / AKS 例外：託管 k8s 不允許改 API server 啟動參數。EKS 用 k8saudit-eks 從 CloudWatch 拉； GKE 用 gcpaudit。AKS 須開 diagnostic settings 把 audit 送到 EventHub。詳見 Ch.08。

6.6心智模型總結

  • Plugin 兩類：source plugin（提供 events）與 extractor plugin（提供 fields）
  • 用 .so 動態載入；遵循 Plugin API
  • 必裝 container plugin，default rules 才能正常 enrich
  • 用 falcoctl 管理；Helm 預設啟用 sidecar 自動更新
  • K8s Audit、CloudTrail、Okta 是擴大 detection 範圍的最重要 plugins
  • 託管 K8s (EKS/GKE/AKS) 須用對應雲 plugin，無法直接走 webhook
