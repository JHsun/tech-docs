14.2CLI Cheatsheet（一頁速查）

🚀 啟動與驗證

# 啟動（systemd） sudo systemctl enable --now falco-modern-bpf.service # 看 log sudo journalctl -fu falco-modern-bpf.service # 驗證 rule 語法 falco --validate /etc/falco/rules.d/custom.yaml # dry-run（不真的處理） falco --dry-run -r my.yaml # 看版本 falco --version

📋 列表查詢

# 列所有支援欄位 falco --list-fields | less # 列所有支援事件 falco --list-events --markdown > events.md # 列當前載入的 rule falco -L # 列當前載入的 syscall set falco --list-syscalls # 列已載入 plugins falco --list-plugins

🎯 規則控制

# 只跑特定 tag falco -t container # 停用某 tag falco -T maturity_sandbox # 停用單條 rule falco -D "Read sensitive file untrusted" # 啟用單條 rule falco -e "Run shell untrusted"

📹 Capture / Replay

# 錄製 60 秒 falco --capture-file=/tmp/run.scap --capture-duration=60s # 對 capture 重播 rule falco -r my-new-rules.yaml -e /tmp/run.scap

☸ Kubernetes 常用

# 看 falco DaemonSet kubectl get ds -n falco # tail 所有 falco pod log kubectl logs -n falco -l app.kubernetes.io/name=falco -c falco -f # 進 falco pod 內 debug kubectl exec -it -n falco $(kubectl get pod -n falco -l app.kubernetes.io/name=falco -o name | head -1) -c falco -- /bin/bash # 拉 metrics kubectl port-forward -n falco svc/falco 8765:8765 & curl http://localhost:8765/metrics # 看 sidekick-ui kubectl port-forward -n falco svc/falco-falcosidekick-ui 2802:2802

📦 falcoctl

# 列已安裝 artifacts falcoctl artifact list # 安裝特定版本 falcoctl artifact install falco-rules:5.0.0 # 持續追蹤更新 falcoctl artifact follow falco-rules:5 --every=6h # 看 artifact 詳情 falcoctl artifact info k8saudit:0.7 # 推 plugin 到 registry falcoctl registry push ghcr.io/yourorg/plugin:0.1.0 --type plugin libmy.so

🛠 Helm

# 安裝 helm install falco -n falco --create-namespace -f values.yaml falcosecurity/falco # 升級 helm upgrade falco -n falco -f values.yaml falcosecurity/falco # diff（須裝 helm-diff plugin） helm diff upgrade falco -n falco -f values.yaml falcosecurity/falco # 列可用版本 helm search repo falcosecurity/falco --versions | head -10 # rollback helm rollback falco <revision> -n falco

14.3常用 Rule 範例集（20+ 條）

把 Ch.04 學到的語法落地成可拷貝即用的範例。涵蓋容器、檔案、網路、權限、雲端五大類。

容器與權限

R-01 · 偵測 privileged container 啟動

情境：合規場景；不應該有 privileged container（除已知白名單）

yaml
- rule: Privileged Container Started
  desc: 偵測 privileged 模式容器啟動，可能繞過隔離
  condition: >
    spawned_process and container and container.privileged = true
    and not container.image.repository in (trusted_privileged_images)
  output: >
    Privileged container started
    (image=%container.image.repository pod=%k8s.pod.name ns=%k8s.ns.name)
  priority: CRITICAL
  tags: [container, privilege_escalation, mitre_privilege_escalation, T1611]

R-02 · 容器內 sudo 使用

情境：容器 image 應該已是最小權限；用 sudo 是不正常

yaml
- rule: Sudo Usage in Container
  desc: 容器內偵測到 sudo 命令
  condition: >
    spawned_process and container
    and proc.name = "sudo"
    and not container.image.repository in (sudo_allowed_images)
  output: >
    sudo invoked in container
    (user=%user.name cmdline=%proc.cmdline image=%container.image.repository pod=%k8s.pod.name)
  priority: WARNING
  tags: [container, privilege_escalation]

R-03 · Setuid binary 執行

情境：偵測權限提升的常見手法

yaml
- rule: Setuid Binary Executed
  desc: 偵測 setuid binary 被執行，可能是 privilege escalation
  condition: >
    spawned_process and container
    and proc.is_setuid = true
    and not proc.name in (allowed_setuid_binaries)
  output: >
    Setuid binary executed (proc=%proc.name parent=%proc.pname user=%user.name pod=%k8s.pod.name)
  priority: WARNING
  tags: [process, privilege_escalation, mitre_privilege_escalation]

檔案系統

R-04 · 寫入 /etc

經典 — 對 system config 的修改

yaml
- rule: Modify /etc
  desc: 偵測對 /etc 的任何寫入
  condition: >
    evt.type in (write, openat, openat2, mkdir, rename, unlink, symlink, link, chmod)
    and fs.path.name startswith "/etc/"
    and not proc.name in (apt, dpkg, yum, dnf, kubelet, snapd)
    and not container.image.repository startswith "k8s.gcr.io/pause"
  output: >
    Modification below /etc (syscall=%evt.type path=%fs.path.name proc=%proc.name pod=%k8s.pod.name)
  priority: WARNING
  tags: [filesystem, mitre_persistence, T1098]

R-05 · 讀取敏感檔案 /etc/shadow

yaml
- rule: Read /etc/shadow
  desc: 偵測非預期 process 讀取 /etc/shadow
  condition: >
    evt.type in (open, openat, openat2)
    and fd.name in ("/etc/shadow", "/etc/shadow-", "/etc/gshadow")
    and not proc.name in (sshd, login, passwd, chpasswd, vipw)
  output: >
    Sensitive file read (file=%fd.name proc=%proc.name parent=%proc.pname pod=%k8s.pod.name)
  priority: CRITICAL
  tags: [filesystem, credential_access, T1003.008]

R-06 · 建立 symlink 指向敏感檔

yaml
- rule: Symlink to Sensitive File
  desc: 偵測 symlink 指向敏感系統檔
  condition: >
    evt.type in (symlink, symlinkat)
    and fs.path.target in (sensitive_file_paths)
  output: >
    Symlink to sensitive file (target=%fs.path.target source=%fs.path.source proc=%proc.name)
  priority: WARNING
  tags: [filesystem, defense_evasion, T1027.001]

R-07 · 修改 SSH 設定

yaml
- rule: Modify SSH Authorized Keys
  desc: 偵測對 SSH authorized_keys 的修改（後門植入跡象）
  condition: >
    evt.type in (write, openat) and fd.is_open_write = true
    and (fd.name endswith ".ssh/authorized_keys" or fd.name endswith ".ssh/known_hosts")
  output: >
    SSH key file modified (file=%fd.name proc=%proc.name pod=%k8s.pod.name)
  priority: CRITICAL
  tags: [persistence, ssh, T1098.004]

網路

R-08 · 連線到 mining pool

yaml
- rule: Crypto Mining Pool Connection
  desc: 偵測連線到已知 crypto mining pool 網域
  condition: >
    evt.type = connect and evt.dir = <
    and (fd.sip.name endswith ".minexmr.com"
         or fd.sip.name endswith ".moneroocean.stream"
         or fd.sip.name endswith ".supportxmr.com"
         or fd.sip.name endswith ".nanopool.org"
         or fd.sip.name endswith ".pool.minergate.com")
  output: >
    Mining pool connection (dest=%fd.sip.name:%fd.sport proc=%proc.cmdline pod=%k8s.pod.name)
  priority: CRITICAL
  tags: [network, mitre_impact, T1496]

R-09 · 容器內執行網路工具

yaml
- rule: Network Tool Launched in Container
  desc: 偵測 nc/ncat/socat 等網路工具在容器內執行
  condition: >
    spawned_process and container
    and proc.name in (nc, ncat, netcat, socat, nmap)
  output: >
    Network tool in container (tool=%proc.name parent=%proc.pname cmd=%proc.cmdline pod=%k8s.pod.name image=%container.image.repository)
  priority: WARNING
  tags: [network, lateral_movement, T1105]

R-10 · 容器內 SSH client

yaml
- rule: SSH Client in Container
  desc: 容器內偵測 ssh/scp/sftp client（lateral movement 跡象）
  condition: >
    spawned_process and container
    and proc.name in (ssh, scp, sftp)
  output: >
    SSH client launched in container (cmd=%proc.cmdline pod=%k8s.pod.name)
  priority: WARNING
  tags: [network, lateral_movement, T1021.004]

程序行為

R-11 · 容器內 shell（複習官方經典）

yaml
- rule: Shell in Container (Custom)
  desc: 偵測容器內 shell 啟動，排除 known sources
  condition: >
    spawned_process and container
    and proc.name in (shell_binaries)
    and not (proc.pname in (runc, containerd-shim) and proc.aname[2] in (containerd, kubelet))
  output: >
    Shell in container (shell=%proc.name parent=%proc.pname pod=%k8s.pod.name)
  priority: WARNING
  tags: [container, shell, mitre_execution, T1059.004]

R-12 · 從 web server 啟動 shell（command injection）

yaml
- macro: web_server_ancestor
  condition: proc.aname[2] in (nginx, httpd, apache2, node, php-fpm)

- rule: Shell from Web Server
  desc: web server 啟動 shell — command injection 強烈跡象
  condition: >
    spawned_process and container
    and proc.name in (shell_binaries)
    and web_server_ancestor
  output: >
    Shell from web server (shell=%proc.name grandparent=%proc.aname[2] cmdline=%proc.cmdline pod=%k8s.pod.name)
  priority: CRITICAL
  tags: [shell, web, mitre_initial_access, T1190]

R-13 · 容器 namespace 切換（容器逃逸跡象）

yaml
- rule: Container Namespace Change
  desc: 容器內呼叫 setns / unshare，可能是逃逸嘗試
  condition: >
    evt.type in (setns, unshare) and container
    and not proc.name in (runc, docker, containerd)
  output: >
    Namespace change inside container (syscall=%evt.type proc=%proc.name pod=%k8s.pod.name)
  priority: CRITICAL
  tags: [container, container_escape, T1611]

R-14 · Kernel module 載入

yaml
- rule: Kernel Module Loaded
  desc: 載入 kernel module — 可能是 rootkit
  condition: >
    evt.type in (init_module, finit_module)
    and not proc.name in (kmod, insmod, modprobe, systemd, systemd-modules)
  output: >
    Kernel module loaded (proc=%proc.name pod=%k8s.pod.name)
  priority: CRITICAL
  tags: [kernel, persistence, T1547.006]

R-15 · ptrace 使用（process injection）

yaml
- list: allowed_ptrace_tools
  items: [strace, ltrace, gdb, lldb, perf]

- rule: Ptrace Usage
  desc: 偵測 ptrace — 常用於 process injection 或 debug
  condition: >
    evt.type = ptrace
    and not proc.name in (allowed_ptrace_tools)
  output: >
    Ptrace used (proc=%proc.name target_pid=%evt.arg.pid request=%evt.arg.request pod=%k8s.pod.name)
  priority: WARNING
  tags: [process, injection, T1055.008]

K8s Audit（plugin: k8saudit）

R-16 · kubectl exec 進入 pod

yaml
- rule: Exec into Pod
  desc: 偵測 kubectl exec 進入 pod
  condition: >
    kevt and pod_subresource and ka.target.subresource = "exec"
    and not ka.user.name in (allowed_exec_users)
  output: >
    Exec into pod (user=%ka.user.name target_pod=%ka.target.name ns=%ka.target.namespace)
  priority: NOTICE
  source: k8s_audit
  tags: [k8s, exec, mitre_lateral_movement]

R-17 · ClusterRoleBinding 變更

yaml
- rule: ClusterRoleBinding Created/Modified
  desc: 偵測 ClusterRoleBinding 異動，特別是給 cluster-admin
  condition: >
    kevt and ka.verb in (create, update, patch)
    and ka.target.resource = "clusterrolebindings"
  output: >
    ClusterRoleBinding modified (user=%ka.user.name verb=%ka.verb target=%ka.target.name role=%ka.req.binding.role)
  priority: WARNING
  source: k8s_audit
  tags: [k8s, rbac, privilege_escalation, T1098]

R-18 · 異常 Service Account 存取 Secret

yaml
- rule: Service Account Token Access to Sensitive Secret
  desc: SA 存取了不該存取的 secret
  condition: >
    kevt and ka.verb = "get"
    and ka.target.resource = "secrets"
    and ka.user.name startswith "system:serviceaccount:"
    and ka.target.namespace in (sensitive_namespaces)
  output: >
    SA accessed sensitive secret (sa=%ka.user.name secret=%ka.target.name ns=%ka.target.namespace)
  priority: WARNING
  source: k8s_audit
  tags: [k8s, secret, credential_access]

雲端（plugin: cloudtrail）

R-19 · AWS root account 使用

yaml
- rule: AWS Root Account Activity
  desc: 偵測 root account 操作（應永遠不該發生）
  condition: >
    ct.user.identitytype = "Root"
    and not ct.eventtype = "AwsServiceEvent"
  output: >
    AWS root activity (event=%ct.name region=%ct.region source_ip=%ct.srcip)
  priority: CRITICAL
  source: aws_cloudtrail
  tags: [aws, root, mitre_persistence]

R-20 · CloudTrail 自己被停用

yaml
- rule: CloudTrail Logging Disabled
  desc: 偵測 CloudTrail 被停用（攻擊者在掩蓋蹤跡）
  condition: >
    ct.name in (StopLogging, DeleteTrail, UpdateTrail)
    and not ct.error exists
  output: >
    CloudTrail logging disabled (event=%ct.name user=%ct.user.name source_ip=%ct.srcip)
  priority: CRITICAL
  source: aws_cloudtrail
  tags: [aws, defense_evasion, T1562.008]

14.4Falco Roadmap（公開資訊整理）

官方 roadmap 公開於 GitHub project board，下面是 2026 大方向整理。

近期已交付（2025-2026）

  • ✅ CNCF Graduated (2024)
  • ✅ Falco Operator 0.1 / 0.2 production-ready
  • ✅ Modern eBPF 預設化
  • ✅ Falco EKS Add-on
  • ✅ Container plugin 獨立化
  • ✅ Prometheus exporter 內建

進行中 / 規劃中

  • 🚧 multi-source rules（單一 rule 跨 source 關聯）
  • 🚧 Operator 持續強化（rule auto-tuning, ML-assisted）
  • 🚧 IDE plugin（VSCode rule authoring）
  • 🚧 Plugin SDK Rust 進入 stable
  • 🚧 更多 cloud plugins（GCP Cloud Audit、Azure Activity Log）
  • 🚧 整合 Stratoshark 更深

已 deprecated（v0.43 標記）

  • ❌ Legacy eBPF probe → 改用 Modern eBPF
  • ❌ gVisor engine → 評估替代
  • ❌ gRPC API → 改用 HTTP + falcosidekick
  • ❌ evt.dir 欄位族 → 不要再用
  • ❌ %container.info output placeholder（已移除）
  • ❌ append: true → 改用 override
  • ❌ falco-exporter（OSS 已棄） → 用內建 Prometheus exporter

最新狀態查：github.com/orgs/falcosecurity/projects

14.5版本支援政策

Falco 發版 cadence

  • Minor release：每季 (~3 個月一版)，例如 v0.42 → v0.43
  • Patch release：bug / CVE 修正時發，例如 v0.43.1
  • 支援範圍：最新與前一個 minor。例如 v0.43 釋出後仍支援 v0.42；v0.41 進入 EOL
  • Default ruleset：獨立版本，當前 5.x，跟 Falco minor release 對齊
  • Plugin：各 plugin 獨立 semver，部分支援多 Falco 版本
