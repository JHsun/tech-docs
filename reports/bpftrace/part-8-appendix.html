📌 探針選擇優先順序

  1. 有 tracepoint 用 tracepoint（穩定、有型別化 args）
  2. 需追任意函式 → fentry/fexit（比 kprobe 快、能取 args）
  3. 沒有以上才退回 kprobe/kretprobe
  4. 使用者空間 → 先看 USDT，再退回 uprobe

APPENDIX E 錯誤訊息對照表

從錯誤訊息直接查到原因與解法 —— 把 stderr 倒進這裡，多半能秒查到對策。

E.1 編譯期錯誤

syntax error, unexpected ...

語法錯誤。常見原因：分號漏掉、大括號不對齊、保留字當變數名。

解法：用 bpftrace --fmt（0.25）自動 reformat 後對照差異。

Can't determine type of variable

scratch 變數第一次使用時無法推斷型別。

解法：加顯式 cast，例如 let $x = (uint64)0;

Type mismatch: expected X, got Y

賦值、比較、傳參時型別不相容。

解法：顯式 cast；確認字串/整數/指標分清楚。

Field 'X' is not part of struct 'Y'

struct 沒有該欄位。可能是 kernel 版本差異、struct 改名。

解法：bpftool btf dump file /sys/kernel/btf/vmlinux | grep -A 30 'STRUCT Y' 確認實際欄位。

E.2 Attach 期錯誤

No probes to attach

wildcard 沒比對到任何探針。

解法：bpftrace -l 'pattern' 確認；檢查 kernel 版本。

probe full

attach probe 數超過 max_probes。

解法：config max_probes = 5000 或用更窄 wildcard。

Cannot read /sys/kernel/debug/tracing/...

tracefs 沒掛或非 root。

解法：sudo mount -t tracefs nodev /sys/kernel/tracing 或用 sudo。

Failed to attach uprobe to PID X: No such file

uprobe 目標 binary 路徑不對 / 容器內 binary host 看不到。

解法：檢查 ls -l /proc/<PID>/exe；容器情境用 /proc/<PID>/root/...。

ERROR: Could not find BTF

沒有 vmlinux BTF。fentry / 結構欄位等都不能用。

解法：升 kernel 5.4+ 並啟用 CONFIG_DEBUG_INFO_BTF；或安裝 kernel-debuginfo；或 BPFTRACE_BTF 指向自取的 BTF。

E.3 Verifier 拒絕

stack/frame size limit exceeded

scratch 變數總和 > 512 bytes BPF stack。

解法：降 max_strlen=64；少用字串 scratch；複用變數。

unbounded loop

for 迴圈 verifier 算不出邊界。

解法：改用 unroll(N)；range 用 const 上限。

math between map_value pointer and unbounded register

對 map 取出的指標做 verifier 算不出範圍的算術。

解法：運算前加 mask；先存 scratch 再操作。

BPF program is too large. Processed N insn

單一 probe BPF 程式超過內核指令上限。

解法：單 probe 拆多個；簡化邏輯；避免過度 inline。

E.4 執行期警告

WARNING: lost N events

perf ring buffer 滿，user space 處理不及。

解法：聚合代替 printf；config perf_rb_pages = 256（或更高）。

Failed to probe_read_user / probe_read_kernel: Bad address (-14)

位址空間判斷錯：用 user reader 讀 kernel ptr，或反之。

解法：用 kptr() / uptr() 顯式標註；用 -kk 看完整錯誤位置。

map dropped events

map 寫入失敗（容量滿、key 衝突）。

解法：用 lruhash；調高 max entries；定期 clear()。

E.5 應用層錯誤

cannot assign requested address (uprobe)

uprobe target offset 超出 binary 範圍。

解法：nm --defined-only ./binary 確認 symbol 仍在；確認沒被 inline 或 strip。

USDT probe not firing

USDT semaphore 沒被啟用。

解法：加 -p <PID> 或 --usdt-file-activation；或 -c CMD 啟動 child。

G.7 推薦學習路徑

💡 三類讀者的精進路線

初學者（剛從本手冊 Part I-III 起步）

  1. 跑完 bpftrace.org 的 One-liner Tutorial。
  2. 從 Production Tools 目錄挑 3-5 個熟悉的（biolatency / opensnoop / tcpconnect）讀原始碼。
  3. 挑自己工作環境上的一個小問題用 bpftrace 解決。
  4. 讀完 Part IV-V 的標準函式庫章節。

開發者（要寫穩定的長期工具）

  1. 讀 Part VII 全部（CLI / Config / Debug / BTF / Production）。
  2. 讀 Brendan Gregg 的 BPF Performance Tools 第 5 章 (bpftrace) + 第 13-15 章（CPU / 排程 / 記憶體）。
  3. 看 bpftrace 原始碼的 src/parser.yy + src/types.cpp 理解語言設計。
  4. 嘗試貢獻 bpftrace 一個小 feature 或 bug fix。

SRE / Production 工程師

  1. 讀 Part VI 全部（19 個 case study）。
  2. 讀 USE Method + Off-CPU Analysis 兩篇。
  3. 把本手冊範本（cpu_diag.bt / io_diag.bt / net_diag.bt）部署到測試環境，熟悉常駐運維。
  4. 建立自家 fleet 的「bpftrace 工具庫」 + systemd 整合，讓 incident response 標準化。

手冊終章

📚 整本手冊的旅程

從第 1 章「什麼是 bpftrace」到最後一篇附錄，本手冊涵蓋：

  • 36 章正文 + 7 篇附錄
  • 19 個完整 production case study
  • 17 張 SVG 解釋圖
  • 40+ 張對照表
  • 70+ 段可直接執行的範例
  • 完整覆蓋官方 Language / Stdlib / CLI 三大區塊
  • 0.25 版所有新功能（Records / pcomm / build_id stack / syscall_name / fexit:bpf / --fmt 等）

bpftrace 不是萬靈丹，但它把「動態追蹤」從 DTrace 時代的高深技術變成了人人能在 production 上用的日常工具。願這本手冊讓你寫下的每一支 .bt 都更精準、更安全、更貼近真實系統的脈動。

把學到的工具用起來、把寫出的腳本分享出去 —— 整個 BPF 社群都會因此更好。
