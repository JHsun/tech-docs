CHAPTER 19 內建變數（Built-in Variables） 🔰 初學 🛠 開發

內建變數 = bpftrace 提供的「免費資料」。不需要 cast、不用記函式名，直接拿來用。本章按用途分組，避免按字母序的學習斷層。

19.1 什麼是內建變數

內建變數（builtin）是 bpftrace 預先定義好的特殊變數，不需要前綴 $ 或 @ 就能在 action 內直接使用。背後通常對應一個 BPF helper 呼叫。

例如 pid 對應 bpf_get_current_pid_tgid()，nsecs 對應 bpf_ktime_get_ns()。

📌 builtin 與 function 的界線是模糊的

0.25 起官方文件統稱為 "Helpers"。pid 與 pid() 等價，tid 與 tid() 等價。沒參數或全部用 default 的 helper 可省略括號。

19.2 行程相關

Builtin型別意義
piduint32當前 process ID（kernel tgid，多執行緒程式所有 thread 共享）
tiduint32當前 thread ID（kernel pid，每 thread 獨立）
uiduint32使用者 ID
giduint32群組 ID
commstring[16]當前 process 名稱（thread name）
pcomm (0.25 新)string[16]當前 process 的 group leader name（與 ps 看到的一致）
cpiduint32用 -c CMD 啟動的 child process PID（沒用 -c 時為 0）
has_cpidbool是否有 child process（即是否用了 -c）
usernamestring當前使用者名稱（async，user space 解析）
curtaskstruct task_struct *當前 task_struct 指標

⚠️ comm vs pcomm 差異

多執行緒程式裡，每個 thread 可以有不同的名稱（prctl(PR_SET_NAME)）。

  • comm：執行 probe 的那個 thread 的 name。
  • pcomm：整個 process 的 main name（所有 thread 都一樣，與 ps -p PID -o comm 一致）。

追多執行緒服務時，pcomm 通常更接近你的直覺。

tid() 帶參數版本（0.25）

// container 環境內，預設拿到的是 host 的 tid
// 想要 container 內的 namespace tid 時：
tracepoint:syscalls:sys_enter_read {
  printf("host_tid=%d, container_tid=%d\n",
         tid(init),       // host PID namespace 的 tid
         tid());           // 預設 = curr_ns，當前 namespace 的 tid
}

pid() 也支援同樣的 (curr_ns) / (init) 參數。

19.3 系統與時間相關

Builtin型別意義
cpuint當前 CPU id（process 跑在哪顆 CPU）
numaidint當前 NUMA node id
ncpusuint64系統 CPU 總數（編譯期常數）
jiffiesuint64kernel jiffies 計數
elapseduint64bpftrace 啟動以來的奈秒數
nsecsuint64奈秒時間戳（預設 monotonic）

nsecs 的四種時間源

BEGIN {
  printf("monotonic: %lu\n",  nsecs);                  // 預設 = monotonic
  printf("monotonic: %lu\n",  nsecs(monotonic));       // 從開機算起，不受時間調整影響
  printf("boot:      %lu\n",  nsecs(boot));            // 從開機算起，含 suspend 時間
  printf("tai:       %lu\n",  nsecs(tai));             // CLOCK_TAI（國際原子時，無閏秒）
  printf("sw_tai:    %lu\n",  nsecs(sw_tai));          // 軟體版 tai，舊 kernel 用
  exit();
}
來源特性適用
monotonic單調遞增，suspend 期間暫停量延遲（最常用）
boot單調遞增，包含 suspend跨 suspend 仍要連續的時間軸
tai對應 wall clock，無閏秒與外部系統時間對齊
sw_tai軟體模擬 tai，老 kernel 才需要kernel ≤ 5.7

19.4 探針上下文（Probe Context）

Builtin型別意義
probestring當前 probe 全名（含路徑）
funcstring當前 probe 的函式名（不含類別）
argsstructtracepoint / fentry / fexit / rawtracepoint 的引數結構
arg0..argNint64kprobe / uprobe / usdt 的引數（暫存器值）
retvalint64kretprobe / uretprobe 的返回值
numaidint當前 NUMA node id

用 probe 與 func 做 wildcard probe 的歸類

// 一條 probe 抓所有 vfs_，依 func 分組計數
kprobe:vfs_* {
  @[func] = count();
}

// 改用 probe 會看到完整路徑
kprobe:vfs_* {
  @[probe] = count();
  // probe 例如：kprobe:vfs_read
  // func  例如：vfs_read
}

19.5 隨機與其他

Builtin意義
rand32-bit 隨機數（每次呼叫不同）
cgroup當前 cgroup id（v2）
$1, $2, ...positional 參數
$#positional 參數總數

💡 抽樣大流量事件

用 rand 做 1/N 取樣，避免每事件都跑：

kprobe:vfs_read /rand % 100 == 0/ {     // 1% 取樣
  @[ustack] = count();
}

CHAPTER 20 輸出與格式化 🔰 初學 🛠 開發 ⚙️ SRE

printf / print / time / strftime / cat / system / errorf / fail / assert —— 把資料送出 BPF runtime 的所有方式。

20.1 printf — 主力輸出

printf(fmt, args...)

async

類 C printf。資料送到 perf ring buffer，由 user-space bpftrace 取出後格式化印出。

specifier意義
%d %ld %lld有號十進制整數
%u %lu %llu無號十進制整數
%x %lx %llx十六進制（小寫）
%X十六進制（大寫）
%o八進制
%s字串（NULL 截止）
%c單字元（從整數 ASCII 轉）
%p指標
%rraw bytes（搭配 buf()）
%rxraw bytes 全 hex（含 \x 前綴）
%rhraw bytes hex（無 \x，bytes 間空白）

常用格式化技巧

BEGIN {
  // 寬度與對齊
  printf("%-16s %6d\n", "hello", 42);     // 左對齊字串、右對齊數字
  // 補零
  printf("%08x\n", 0xff);                  // 000000ff
  // 浮點不支援，用整數縮放
  $pct = 8542;
  printf("%d.%02d%%\n", $pct / 100, $pct % 100);   // 85.42%
}

20.2 print — 印 map 或值

print(value [, top_n [, div]])

async

列印 map、scratch 值、tuple。對 map 可指定 top N 並 divide 數值。

END {
  print(@count);              // 印整個 map
  print(@count, 10);          // 只印 top 10
  print(@latency, 10, 1000);  // top 10，每筆數值除以 1000
  print($x);                  // 印 scratch 變數
  print((1, "hello"));        // 印 tuple
}

20.3 time / strftime — 時間輸出

time(fmt)

async

取「user-space 處理事件的時間」並依 fmt 印出。不是 probe 觸發當下的時間。

strftime(fmt, nsecs) → string

把奈秒時間戳依 fmt 格式化為字串，同步處理。可塞進 printf。

BEGIN {
  // 直接印當前時間
  time("%H:%M:%S\n");                                    // async
}

tracepoint:syscalls:sys_enter_open {
  // 把事件當下時間戳格式化後嵌入 printf
  printf("[%s] %s opens\n", strftime("%H:%M:%S", nsecs), comm);
}

⚠️ time() 的時間戳是 user space 取的，不是 probe 觸發時間

當 user space 處理 ring buffer 比 probe 觸發慢，time() 印出的時間會比事件實際發生晚幾毫秒甚至幾秒。要精確時間軸請用 strftime("%H:%M:%S", nsecs)。

20.4 cat — 印檔案內容

cat(fmt, args...)

async

把 fmt 套用 args 後當路徑名，在 user space 開啟並印出該檔案。

tracepoint:syscalls:sys_enter_execve {
  cat("/proc/%d/maps", pid);
}

⚠️ cat 是 async，process 可能已經結束

因為 cat 在 user space 執行，等到 bpftrace 從 ring buffer 讀到事件時，/proc/PID/... 可能已經消失（process 結束）。短命 process 的觀測要小心，或改用 BPF helper 在 kernel 取資料。

20.5 system — 執行 shell 命令

system(fmt, args...)

async unsafe

在 user space 執行 shell 命令。必須用 --unsafe 啟用。

// 看到問題時自動 dump 狀態
tracepoint:signal:signal_generate /args.sig == 11/ {
  system("/bin/grep VmSize /proc/%d/status", args.pid);
}
sudo bpftrace --unsafe segv_dump.bt

⛔ system() 是 production 殺手

每觸發一次就 fork 一個 shell。在高頻 probe 上用 system() 會在幾秒內讓系統 fork bomb。絕對不要在 hot path 用。 適合 BEGIN / END / interval / 低頻條件觸發。

20.6 errorf / fail / assert — 編譯期斷言（0.24+）

errorf(fmt, args...)

compile-time

編譯期錯誤訊息。腳本繼續編譯但會報錯。

fail(fmt, args...)

compile-time

編譯期立即失敗 —— 整個腳本不會載入。常用於檢查環境條件。

assert(condition, msg)

運行期斷言，failed 會 exit。

// 確保 kernel 支援需要的 helper
BEGIN {
  if (!kfunc_exist("bpf_get_socket_cookie")) {
    fail("kernel does not support bpf_get_socket_cookie");
  }
  printf("starting...\n");
}

// 運行期檢查 invariant
kprobe:vfs_read {
  assert(arg2 < 1 << 30, "unreasonably large read size");
  @reads = count();
}

20.7 預設 map 列印行為

程式結束時 bpftrace 會自動印所有非空 map。三種控制方式：

// 方法 1：config 關閉
config = { print_maps_on_exit = false; }

// 方法 2：END 內 clear 不想印的
END {
  clear(@temp);
  print(@important);
}

// 方法 3：用底線 scratch 變數吃掉非預期 map
// （適用於少數場合，清理意圖更明確）

CHAPTER 21 字串、buffer 與位址處理 🛠 開發

字串處理 · 二進位 buffer · IP/MAC 位址 · 型別反思 —— 把原始記憶體變成可讀資訊的所有工具。

21.1 字串函式

str(ptr [, len]) → string

從 char* 讀取 NULL-terminated 字串。len 預設 BPFTRACE_MAX_STRLEN（1024）。

strcontains(haystack, needle) → bool

判斷 haystack 是否包含 needle（不是 regex）。

strncmp(s1, s2, n) → int

類 C strncmp，比較前 n bytes。

strerror(errno) → string

把 errno 轉可讀錯誤字串（user space 解析，async）。

tracepoint:syscalls:sys_enter_openat
/strcontains(str(args.filename), "/proc")/ {
  printf("%s reads /proc: %s\n", comm, str(args.filename));
}

kretprobe:vfs_read /(int64)retval < 0/ {
  printf("%s read failed: %s\n", comm, strerror(-(int64)retval));
}

21.2 buf — 二進位 buffer

buf(ptr, len) → buffer

讀取 len bytes 的二進位內容，可塞入 printf 的 %r / %rx / %rh。

tracepoint:syscalls:sys_enter_write /comm == "myapp"/ {
  // %r：raw bytes，遇到不可印字元會 \xNN
  printf("write: %r\n", buf(args.buf, args.count));
  // %rx：全 hex 含 \x
  printf("hex:   %rx\n", buf(args.buf, args.count));
  // %rh：純 hex，bytes 間空白（適合 hexdump 風格）
  printf("dump:  %rh\n", buf(args.buf, args.count));
}
write: GET / HTTP/1.1\r\nHost: example.com\r\n\r\n
hex:   \x47\x45\x54\x20\x2f\x20\x48\x54\x54\x50\x2f\x31\x2e\x31...
dump:  47 45 54 20 2f 20 48 54 54 50 2f 31 2e 31 0d 0a 48 6f 73 74 ...

21.3 memcmp

memcmp(a, b, len) → int

類 C memcmp。常用於比對二進位 token / signature。

// 看到 magic header 才報告
fexit:vfs_read /retval > 4/ {
  let $magic = "\x7fELF";
  let $hdr = (int8 *)args.buf;
  if (memcmp($hdr, $magic, 4) == 0) {
    printf("%s read an ELF\n", comm);
  }
}

21.4 IP 位址處理

ntop([family,] addr) → string

把 IP 位址轉可讀字串。family 可省略（自動偵測 IPv4 vs IPv6）。

pton(addr_str) → byte[]

把字串 IP 位址轉二進位（IPv4 是 4 bytes、IPv6 是 16 bytes）。

fentry:tcp_connect {
  $sk = args.sk;
  // skc_daddr 是 __be32（network byte order）
  printf("connect to %s:%d\n",
         ntop($sk->__sk_common.skc_daddr),
         bswap($sk->__sk_common.skc_dport));
}

// 比對特定 IP
fentry:tcp_connect
/args.sk->__sk_common.skc_daddr == (uint32)pton("8.8.8.8")/ {
  printf("connecting to Google DNS\n");
}

bswap — byte order 反轉

bswap(n) → uint

反轉 byte order。用於 __be16 / __be32 轉 host order。

21.5 macaddr

macaddr(addr) → string

把 6-byte MAC address 轉可讀字串（aa:bb:cc:dd:ee:ff）。

kprobe:eth_type_trans {
  // arg0 是 struct sk_buff *
  // skb->data 前 6 bytes 是目的 MAC，再 6 bytes 是來源 MAC
  $skb = (struct sk_buff *)arg0;
  printf("%s -> %s\n",
         macaddr($skb->data + 6),  // src
         macaddr($skb->data));      // dst
}

21.6 型別反思（Type Introspection）

在寫泛型 macro / 條件分支時很有用。編譯期判斷型別：

Builtin意義
is_array(x)是否為陣列
is_integer(x)是否為整數
is_str(x)是否為字串
is_ptr(x)是否為指標
is_literal(x)是否為字面值（編譯期可知）
is_unsigned_integer(x)是否為無號整數
 
// 寫一個 macro 對任何型別都能 dump
macro dump(x) {
  if (is_str(x)) {
    printf("string: %s\n", x);
  } else if (is_integer(x)) {
    printf("int: %d\n", x);
  } else if (is_ptr(x)) {
    printf("ptr: 0x%lx\n", x);
  } else {
    print(x);
  }
}

21.7 join — 字串陣列合併

join(arr [, sep])

async

把 char** 陣列以 sep（預設空白）合併成一個字串直接印出。不能當值使用。

tracepoint:syscalls:sys_enter_execve {
  // args.argv 是 char **，把所有 arg 印成一行
  printf("[%d] ", pid);
  join(args.argv);          // 自動印一行
}

CHAPTER 22 符號、位址與堆疊 🛠 開發 ⚙️ SRE

把「位址」變「函式名」、把「sample」變「火焰圖原料」 —— 觀測之所以好看，全靠這幾個 helper。

22.1 取符號位址

kaddr(name) → ptr

compile-time

取得 kernel 全域符號的位址。從 /proc/kallsyms 解析。

uaddr(sym) → ptr

compile-time

取得 user binary 的符號位址。不支援 ASLR（每次跑 PIE 程式位址會變）。預設返回 uint64*，視 ELF 大小自動成 uint8/16/32/64。

percpu_kaddr(name [, cpu]) → ptr

取得 per-CPU kernel 變數的位址（指定 CPU，預設當前 CPU）。

kfunc_exist(name) → bool · kfunc_allowed(name) → bool

compile-time

檢查 kernel 函式是否存在 / 是否可被 BPF 呼叫。

// 印 kernel load average
interval:s:1 {
  $avenrun = kaddr("avenrun");
  $load1   = *$avenrun;
  printf("load1 (raw): %d\n", $load1);
}

// 條件編譯：環境支援才掛 probe
BEGIN {
  if (!kfunc_exist("tcp_set_state")) {
    fail("tcp_set_state not available");
  }
}

22.2 位址 → 名稱：ksym / usym

ksym(addr) → string

async

把 kernel address 解析為 symbol 名稱（含 +offset）。

usym(addr) → string

async

把 user address 解析為 symbol。需要 binary 與 PID 上下文。

// 看到 kernel function pointer，用 ksym 解析
kprobe:do_softirq {
  printf("softirq from: %s\n", ksym(reg("ip")));
}

// 看 user app 的呼叫者
uprobe:./myapp:my_func {
  printf("called by: %s\n", usym(*(uint64*)reg("sp")));
}

22.3 path() — bpf_d_path

path(path_struct_ptr) → string

解析 struct path 為完整路徑字串。需 kernel 5.10+。

fentry:vfs_open {
  // args.path 是 const struct path *
  printf("opening: %s\n", path(args.path));
}

📌 path() vs 手動拼路徑

傳統做法是讀 file->f_path.dentry->d_name.name，但這只有最後一個 component（檔名），不是完整路徑。path() 透過 bpf_d_path 走完整 dentry chain，才是完整路徑。

22.4 cgroup 與 path

cgroup → uint64

當前 process 的 cgroup id（cgroup v2）。當作 builtin 使用。

cgroup_path(id [, hierarchy]) → string

async

把 cgroup id 轉路徑字串。只能用於 print，不能當值。

cgroupid(path) → uint64

compile-time

把 cgroup 路徑轉 id。常用於 predicate 過濾特定容器。

// 只追特定 container 的 syscall
tracepoint:raw_syscalls:sys_enter
/cgroup == cgroupid("/sys/fs/cgroup/system.slice/myservice.service")/ {
  @[syscall_name(args.id)] = count();
}

// 統計各 cgroup 的事件量
kprobe:vfs_read {
  @[cgroup_path(cgroup)] = count();
}

⚠️ cgroup_path 結果只能 print

因為解析在 user space 做，回傳的不是真字串而是 print-only token。不能存到 map、不能比對。要比對請用 cgroupid()（compile-time）對 cgroup builtin。

22.5 kstack 與 ustack

kstack([mode] [, limit]) → stack

async

取 kernel stack trace。

ustack([mode] [, limit]) → stack

async

取 user stack trace。

三個 mode（0.25 多了 build_id）

Mode輸出用途
bpftrace（預設）多行縮排格式人讀
perf位址 + 符號 +offset，每行一個 frame給 stackcollapse / 火焰圖
raw純位址，無符號解析除錯、自己後處理
build_id (0.25 新)位址 + 對應 binary 的 build_id跨機解析、容器環境
 
// 1. 預設 bpftrace mode
profile:hz:99 {
  @[ustack] = count();
}

// 2. 給火焰圖用：perf mode + 限制深度
profile:hz:99 {
  @[ustack(perf, 32), comm] = count();
}

// 3. 容器環境：用 build_id 跨機解析
profile:hz:99 {
  @[ustack(build_id)] = count();
}

整合 FlameGraph 工具鏈

# 1. 採樣 30 秒，輸出 perf 格式
sudo bpftrace -e '
profile:hz:99 { @[ustack(perf), comm] = count(); }
interval:s:30 { exit(); }
' > out.bt

# 2. 給 FlameGraph 工具
git clone https://github.com/brendangregg/FlameGraph
./FlameGraph/stackcollapse-bpftrace.pl out.bt | \
  ./FlameGraph/flamegraph.pl > flame.svg

💡 stack 取不到的常見原因

  • Inline 函式不會在 stack 上出現。
  • JIT 程式（V8、JVM）的 user stack 通常解析不到（需要符號 perf-map 等專門設置）。
  • kernel stack 缺 frame pointer：用 perf mode + DWARF unwind 才完整（bpftrace 仰賴 BPF 的 stack helper，現代 kernel 已可信）。
