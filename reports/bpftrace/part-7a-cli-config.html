CHAPTER 33 CLI 全選項解析 ⚙️ SRE

把 bpftrace --help 列出的每個選項按用途分組講清楚。本章是字典式參考，遇到不熟悉的旗標可隨時翻閱。

33.1 命令列概觀

bpftrace [OPTIONS] [filename | - | -e 'program'] [arguments...]

三種主要呼叫方式：

形式用法
One-linerbpftrace -e 'program' [args...]
腳本檔bpftrace path/to/script.bt [args...]
Stdinecho 'program' | bpftrace -

33.2 程式輸入相關

-e 'PROGRAM'

在命令列直接給程式字串。最常用於 one-liner。

FILENAME

從檔案讀取程式。慣例副檔名 .bt。可搭配 shebang #!/usr/bin/env bpftrace 直接執行。

-

從 stdin 讀取程式。適合在 pipeline 中使用，例如 cat script.bt | bpftrace -。

-I PATH

新增 C header search path（傳給 libclang）。需要 include kernel header 或自家 struct 定義時使用。

sudo bpftrace -I /usr/src/linux-headers-$(uname -r)/include script.bt

--include FILE

強制 include 一個 C header（如同程式開頭加 #include "FILE"）。可重複使用。

33.3 探針與目標選擇

-l [SEARCH_PATTERN]

列出符合 pattern 的可用探針。詳見第 11 章 listing probes。
bpftrace -l 'kprobe:vfs_*'

-lv [SEARCH_PATTERN] 最常用

同 -l 但顯示每個探針的型別化參數。是寫腳本前的探索利器。

-p PID

限定追蹤特定 process。對 USDT / uprobe / uretprobe / hardware / software / profile / interval / watchpoint 自動套用過濾；其他 probe 也會在 BPF 內加 PID filter。

-c 'COMMAND'

啟動一個 child process 並追蹤它。child 結束時 bpftrace 也結束。cpid builtin 提供 child PID。

sudo bpftrace -c "/usr/bin/myapp arg1" -e '
usdt:./myapp:my_probe /pid == cpid/ {
  printf("child fired probe\n");
}'

--probe-filter REGEX

用 regex 排除符合的探針。當你寫 wildcard kprobe:tcp_* 但其中某些函式特別吃 CPU 不想追，這個選項在 attach 階段就排除。

sudo bpftrace --probe-filter 'tcp_v4_rcv|tcp_recvmsg' script.bt

--usdt-file-activation

用 檔案路徑啟用 USDT semaphore，而非 PID。掃 /proc/*/maps 找出有掛載該 binary 的 process 並 attach。只在 attach 當下做一次，後來啟動的 process 抓不到。

33.4 輸出控制

-o FILENAME

把 bpftrace 輸出寫到檔案而不是 stdout。不包含 -c 啟動的 child 輸出；錯誤仍寫到 stderr。

-f FORMAT

輸出格式。text（預設）或 json。json 模式給程式解析很方便。

sudo bpftrace -f json -e '
tracepoint:syscalls:sys_enter_open { printf("%s\n", str(args.filename)); }
' | jq .

-B MODE

stdout buffer 模式：none / line（預設） / full。

  • none：無 buffer，每次 I/O 立即寫。整合 streaming 處理時用。
  • line：遇到 \n 或 buffer 滿才寫。預設。
  • full：buffer 滿才寫。最快但延遲最高。

-q

Quiet。抑制非致命警告（例如 attach 訊息、map dropped events）。

--no-warnings

抑制所有 warning。比 -q 更激進。

-k

BPF helper 失敗時發 warning（除了 probe_read_*）。詳見第 18 章。

-kk

BPF helper 失敗都發 warning，包含 probe_read_*。除錯位址空間問題的利器。

33.5 安全與行為控制

--unsafe 危險

啟用副作用 helper：system()、signal()、override()、kprobe 對 raw address。必須清楚知道副作用才用。

--info

顯示 build info、kernel features、可用 helpers、可用 probe types。沒輸出腳本前先看 --info是診斷環境問題的第一步。

sudo bpftrace --info | grep -A 1 'Probe types'

--dry-run

編譯 + attach 但不執行任何 action。用於 CI / 部署前驗證腳本能載入。

sudo bpftrace --dry-run myscript.bt && echo "Script OK"

--test STAGE

跑 test: probe（unit-test 風格 assertion）。詳見第 12 章。

--bench

跑 bench: probe。

33.6 Debug 與診斷

-v

Verbose 輸出。顯示 attach 細節、map 資訊、BPF prog id 等。

-d STAGE

Debug 輸出指定編譯階段。可用 -d 多次或逗號分隔多個 stage。詳見第 35 章。

可用 stage：ast / codegen / codegen-opt / dis / libbpf / verifier / all

sudo bpftrace -d codegen -e '...' 2>&1 | less

33.7 功能旗標（Feature Flags）

--no-feature FEATURE

關閉某個 BPF 功能，強制 fallback。當你需要在較舊 kernel 跑同樣腳本，或某功能在環境上行為怪異時使用。

可用 feature：

  • uprobe_multi：多 uprobe 一次 attach 機制。
  • kprobe_multi：多 kprobe 一次 attach。
  • kprobe_session：kprobe session API（kernel 6.10+）。
sudo bpftrace --no-feature kprobe_multi script.bt

33.8 0.25 新增：--fmt 自動格式化

--fmt 0.25 新

類似 gofmt / black，自動格式化 .bt 腳本。會 reformat 後寫回原檔。

bpftrace --fmt myscript.bt

CHAPTER 34 Config 變數與環境變數 🛠 開發 ⚙️ SRE

CLI 控制「執行行為」，Config 控制「程式行為」。本章把每一個 config 變數攤開 —— 知道哪個變數能解決什麼問題，是 production 維護的核心能力。

34.1 三種設定方式與優先順序

同一個變數可以在三個地方設定，優先順序從高到低：

圖 34.1 — 三種設定方式的優先序：環境變數 > Config Block > 預設

34.2 Config Block 語法

Config Block 必須放在所有 action block 之前（preamble）：

config = {
  stack_mode    = perf;
  max_map_keys  = 8192;
  max_strlen    = 128;
  on_stack_limit = 256;
}

let @lat = lruhash(8192);

BEGIN { ... }

變數名稱有三種等價寫法：

// 全部等價
config = {
  stack_mode = perf;            // 推薦：簡短
  STACK_MODE = perf;            // 大寫
  BPFTRACE_STACK_MODE = perf;   // 加 BPFTRACE_ 前綴
}

34.3 Map 與字串相關 config

max_map_keys (預設 4096)

未明確宣告的 map 預設容量上限。長跑腳本一定要顯式設定 map declaration 而非依賴這個。

config = { max_map_keys = 32768; }

max_strlen (預設 1024)

每個 string scratch 變數佔的 stack 空間。BPF stack 上限 512 bytes —— 這個值放太大會直接讓 verifier 拒絕載入。

多數情境設 64 或 128 就夠用。

str_trunc_trailer (預設 "...")

字串被截斷時加上的 suffix。設為空字串可關閉。

on_stack_limit (預設 0 = 自動)

大型物件移到 pre-allocated memory 而非 stack 的閾值（bytes）。當你遇到「BPF stack overflow」錯誤時調整。

34.4 Probe 限制相關

max_probes (預設 1024)

單一腳本能 attach 的 probe 數量上限。保護機制—— wildcard 比對到太多函式時會擋下。

若確實需要追大量函式：

config = { max_probes = 5000; }

missing_probes (預設 "warn")

wildcard 探針其中部分掛不上時的行為：

  • error：整個腳本失敗。
  • warn：印警告，繼續。
  • ignore：安靜略過。

max_bpf_progs (預設 512)

BPF program 數量上限（一個 probe 對應一個 prog）。通常與 max_probes 配合調整。

34.5 輸出與堆疊

stack_mode (預設 "bpftrace")

kstack/ustack 預設輸出格式。

  • bpftrace：人讀的多行格式。
  • perf：perf script 風格，給 stackcollapse / FlameGraph。
  • raw：純位址。
  • build_id：含 build_id 的位址（0.25 新）。

print_maps_on_exit (預設 true)

程式結束時自動印所有非空 map。設 false 後完全靠 print() 顯式印。

perf_rb_pages (預設依系統記憶體決定)

每 CPU 的 perf ring buffer 大小（pages，4KB/page）。範圍 64–4096。

看到 WARNING: lost N events → 調大這個值。

config = { perf_rb_pages = 256; }   // 1MB per CPU

max_cat_bytes (預設 4096)

cat() 函式單次能讀的最大 bytes。

34.6 Symbol 解析

cache_user_symbols (預設依 ASLR / -c 決定)

user space 符號的 cache 策略：

  • PER_PROGRAM：依 binary 共用 cache。有 ASLR 多 process 時不準確。
  • PER_PID：每 process 獨立 cache。準確但記憶體消耗大。
  • NONE：不 cache。最省記憶體最慢。

預設：ASLR 關閉或 -c 啟動 → PER_PROGRAM；其他 → PER_PID。

lazy_symbolication (預設 true)

true：lazy（需要時才解析符號）。false：attach 時就把所有 symbol 解析好。

追蹤短時間 process 時設 false 可避免 process 已死才解符號的問題。

cpp_demangle (預設 true)

C++ 符號 demangle。詳見第 22 章。

show_debug_info (預設 true 若有 Blazesym)

printing kstack/ustack 時是否顯示檔名:行號 + inline 標記。需 build 時帶 Blazesym 才支援。

34.7 安全與授權

license (預設 "GPL")

BPF program 的授權字串。某些 GPL-only 的 helper 必須以 GPL 授權才能呼叫。

config = { license = "Dual MIT/GPL"; }

log_size (預設 1000000)

BPF verifier log buffer 大小（bytes）。複雜程式 verifier 拒絕時，看到 truncated log → 調大這個值才能看到完整錯誤。

34.8 Unstable feature 開關（0.25）

0.25 把幾個 unstable 功能加上 opt-in flag，避免使用者誤用：

unstable_tseries

啟用 tseries() map 函式。預設 disabled。

unstable_addr

啟用某些位址相關的 unstable 行為。

unstable_map_decl

啟用實驗性 map declaration 變體（0.25 大部分已穩定，僅最新 syntax 留在 unstable）。

config = {
  unstable_tseries = enable;       // 啟用
}

interval:s:1 {
  @reads = tseries(args.count, 100ms, 60, "sum");
}

34.9 環境變數（CLI 中無對應 flag）

有些設定只能透過環境變數提供：

環境變數用途
BPFTRACE_BTF BTF 檔案路徑。沒設時 bpftrace 從預設位置找（/sys/kernel/btf/vmlinux 等）。
BPFTRACE_KERNEL_SOURCE Kernel source 路徑（用於 kprobe + offset）。
BPFTRACE_KERNEL_BUILD out-of-tree kernel build 路徑。
BPFTRACE_VMLINUX vmlinux 路徑（kprobe + offset 解析時需要）。
BPFTRACE_DEBUG_OUTPUT 設 1 → 把 bpftrace runtime debug 訊息寫到 trace_pipe。
BPFTRACE_COLOR 輸出顏色：auto（預設） / always / never。

34.10 Clang 工具鏈相關環境變數

bpftrace 用 libclang 解析 C header。Clang 標準環境變數都有效：

變數作用
CPATH所有語言的 include path
C_INCLUDE_PATHC 專用 include path
CPLUS_INCLUDE_PATHC++ 專用 include path
 
# 在容器或非標準環境裡，告訴 bpftrace 去哪找 header
export CPATH=/opt/myproj/include:/usr/local/include
sudo -E bpftrace script.bt

34.11 Production 級腳本 config 範本

// production_template.bt
config = {
  // Map 容量
  max_map_keys     = 32768;     // 視預期 key 數調整
  max_probes       = 2000;      // wildcard 大時調高

  // 字串
  max_strlen       = 128;        // 多數場景 64-128 夠用

  // Stack 顯示
  stack_mode       = perf;       // 給 FlameGraph 用
  show_debug_info  = false;      // production 不需檔名行號

  // 探針缺失行為
  missing_probes   = "warn";     // 不希望整個 fail

  // 輸出控制
  print_maps_on_exit = true;
  perf_rb_pages    = 256;        // 1MB per CPU 給 hot path

  // 符號解析
  lazy_symbolication = true;     // 短命 process 改 false
}

let @start = lruhash(8192);

BEGIN {
  printf("=== Tracing started ===\n");
}

// ... 你的 probe 邏輯 ...

END {
  clear(@start);
  printf("=== Tracing ended ===\n");
}

💡 把 config 變動寫進 git history

每次因 production 問題調整某個 config 變數，把調整原因寫到腳本註解。三個月後重看才知道為什麼當初要設 max_strlen=64。例如：

config = {
  // 2024-09: nginx access log path 平均 80 chars，128 足夠
  // 設成 1024 會讓 BPF stack 爆，拒絕載入
  max_strlen = 128;
}
