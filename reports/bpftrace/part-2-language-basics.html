CHAPTER 04 資料型別與字面值 🔰 初學 🛠 開發

bpftrace 是強型別但會自動升級的語言。先把型別系統與字面值寫法看一遍，後面的章節就不會被神秘的型別錯誤拖住。

4.1 基本資料型別

bpftrace 內建的基本型別只有兩大類：整數家族與 string。沒有浮點數、也沒有獨立的 char 型別。

型別大小說明
bool1 bytetrue / false 字面值（0.24+ 才有真布林字面值；之前要用 1/0）
uint8 / int81 byte8-bit 無/有號整數
uint16 / int162 bytes16-bit
uint32 / int324 bytes32-bit
uint64 / int648 bytes64-bit；多數 builtin 預設此型
string動態NULL-terminated char array；上限受 BPFTRACE_MAX_STRLEN 控制（預設 1024）

4.2 整數的自動型別推導

bpftrace 預設會挑「能裝得下的最小型別」當字面值的型別：

BEGIN {
  $x = 1 << 16;
  printf("%d %d\n", (uint16)$x, $x);
  // 輸出: 0 65536
  // 因為 $x 是 uint8 起步，左移後溢出；強制轉 uint16 也只剩低 16 bit
}

賦值時，bpftrace 會在能無損推廣的前提下自動升級型別：

BEGIN {
  $a = 1;        // $a 起始為 uint8
  $b = -1000;    // $b 起始為 int16
  $a = $b;       // OK: $a 升為 int16

  $c = (uint64)1;
  $d = (int64)-1;
  $c = $d;       // ❌ ERROR: 沒有「同時能裝下 uint64 與 int64」的型別
}

⚠️ 型別第一次賦值決定終身

變數的型別在第一次賦值時被鎖定，之後若試圖塞入不相容的值會編譯失敗。如果你想預先指定型別，用顯式 cast：

$bytes = (uint64)0;   // 先給型別
@total[pid] = (uint64)0;

4.3 BTF 來的整數型別

當系統有 vmlinux BTF（幾乎所有現代 distro 都有）時，可以用 kernel 慣用的型別名稱：

BEGIN {
  $a = (uint64_t)1;   // 等同 (uint64)1
  $b = (s32)-100;     // s32 = int32
}

4.4 字串

字串以雙引號標示，內部就是一個 NULL-terminated 的 char array：

BEGIN {
  $greeting = "Hello, world";
  printf("%s (length includes NUL)\n", $greeting);
}

字串字面值支援以下跳脫序列：

跳脫意義
\n換行
\tTab
\0nn八進位 ASCII
\xnn十六進位 ASCII

📌 沒有 char 字面值

bpftrace 不支援 'A' 這種寫法。需要 ASCII 字元時直接用整數：

BEGIN { printf("Echo A: %c\n", 65); }   // 65 = 'A'

BTF char[] 自動轉成 string

kernel 結構裡的 char[] 或 int8[] 在 bpftrace 裡會自動以 string 看待：

tracepoint:syscalls:sys_enter_open {
  // args.filename 在 tracepoint metadata 是 const char *
  printf("opened: %s\n", str(args.filename));
}

偶爾你會需要反過來把字串視為 byte array，這時可以強轉：

BEGIN {
  $a = (int8[])"mystring";
  printf("first byte: 0x%x\n", $a[0]);    // 'm' = 0x6d
}

str() 在什麼時候必要

當 bpftrace 無法判斷 pointer 處於 user 還是 kernel address space 時，必須用 str() 顯式讀取：

kprobe:vfs_open {
  // arg0 是 (struct path *)
  // 直接取 .dentry.d_name.name 是 const unsigned char *，但 bpftrace 不確定該用 user 還是 kernel read
  printf("path: %s\n", str(((struct path *)arg0).dentry.d_name.name));
}

4.5 字面值寫法

整數字面值的四種進位

BEGIN {
  $dec = 1024;          // 十進位
  $oct = 02000;         // 八進位 (前綴 0)，1024
  $hex = 0x400;         // 十六進位 (前綴 0x 或 0X)，1024
  $sci = 1e3;           // 科學記號，1000 (僅整數，不支援 1e-3)
}

底線分隔大數字

BEGIN {
  $big = 1_000_123_000;   // 等同 1000123000，純粹為了好讀
}

C 風格 suffix（被忽略，不影響型別）

BEGIN {
  $a = 123UL;       // 與 123 完全相同（suffix 被解析但不影響大小）
  $b = 123LL;       // 同上
}

時間 duration suffix

這個非常實用 —— bpftrace 會在編譯期把帶單位的字面值轉成奈秒整數：

BEGIN {
  $a = 1m;      // 60_000_000_000 ns
  $b = 100ms;   // 100_000_000 ns
  $c = 1h + 30m; // 5_400_000_000_000 ns
  printf("%d ns\n", $a);
}
Suffix意義換算
nsnanosecond1
usmicrosecond1_000
msmillisecond1_000_000
ssecond1_000_000_000
mminute60s
hhour3600s
dday86400s

💡 SRE 慣用法

追 latency 時直接拿 nsecs 與 duration literal 比較，可讀性會提升許多：

kretprobe:vfs_read /@start[tid]/ {
  $dur = nsecs - @start[tid];
  if ($dur > 10ms) {       // 比 10000000 易讀
    printf("slow read: %d us\n", $dur / 1us);
  }
  delete(@start, tid);
}

4.6 識別字與保留字

識別字必須符合 regex [_a-zA-Z][_a-zA-Z0-9]* —— 跟多數語言一致。

保留字（不能當變數名稱）：

break  config  continue  else  for  if  import  let  macro  offsetof
return  sizeof  unroll  while (deprecated)

📌 return vs exit()

return 結束當前 probe，下一個事件來時還會繼續。
exit() 結束整個 bpftrace 進程，會觸發 END probe 然後退出。

4.7 不支援浮點數的應對

BPF 不允許浮點 → bpftrace 沒 float / double。需要小數或百分比時：

// ❌ 這在 bpftrace 行不通
// $rate = $hits / $total;

// ✅ 整數縮放後再除回去
$pct_x100 = ($hits * 10000) / $total;
printf("hit rate: %d.%02d%%\n", $pct_x100 / 100, $pct_x100 % 100);

// ✅ 時間用 ns 起跳，最後再轉成需要的單位
$lat_us = (nsecs - @start[tid]) / 1000;

CHAPTER 05 變數與 Map 🔰 初學 🛠 開發

bpftrace 只有兩種變數：scratch 與 map。看懂它們的差別與生命週期，效能與正確性就拿到 80% 分數。

5.1 兩種變數的本質差異

圖 5.1 — Scratch 與 Map 變數的差異

5.2 Scratch 變數

名稱以 $ 開頭，存在於 BPF stack 上，作用域限定在當前 lexical block。

BEGIN {
  $a = 1;
  if ($a == 1) {
    $b = "hello";    // 只在 if block 內可見
    $a = 2;
  }
  // $b 在這裡無法存取
}

let 預先宣告

明確宣告變數可提升可讀性，也能在尚未指派值時預定型別：

BEGIN {
  let $a = 1;
  let $b;          // 尚未賦值，預設 0
  if ($a == 1) {
    $b = "hello";
    $a = 2;
  }
}

⚠️ Scratch 變數有 stack 額度

每個 probe 可用的 BPF stack 共 512 bytes。一個 string scratch 變數預設就佔 1024 bytes（BPFTRACE_MAX_STRLEN），所以放兩個字串通常會超標。

常見對策：

  • 把 BPFTRACE_MAX_STRLEN 降到 64 或 128。
  • 不要重複建立 scratch 字串 —— 直接 printf 或 str() 後立刻使用。
  • 把長字串塞進 map（map 不佔 stack）。

5.3 Map 變數

名稱以 @ 開頭，存在於 BPF map 內，所有 probe 共享，bpftrace user-space 也能讀。

Scalar map（無 key）

tracepoint:raw_syscalls:sys_enter {
  @syscalls = count();   // 沒有 key，全域累計
}

單 key map

tracepoint:syscalls:sys_enter_read {
  @reads_by_pid[pid] = count();
}

多 key map（tuple key）

tracepoint:syscalls:sys_enter_read {
  @reads[pid, comm] = count();      // 簡寫
  // 等同 @reads[(pid, comm)] = count();
}

5.4 Map 宣告（0.25 已穩定）

不宣告也能用 map（會用預設 hash type，並套用 max_map_keys 上限）。但主動宣告能挑底層 BPF map type、指定 max entries，是 production 級腳本的好習慣。

宣告語法對應 BPF map type用途
let @m = hash(N);BPF_MAP_TYPE_HASH一般用途，key 量已知或受控
let @m = lruhash(N);BPF_MAP_TYPE_LRU_HASH長期執行、key 量未知，自動淘汰
let @m = percpuhash(N);BPF_MAP_TYPE_PERCPU_HASH避免 CPU 間競爭，純計數場景
let @m = percpulruhash(N);BPF_MAP_TYPE_LRU_PERCPU_HASHper-CPU + LRU 淘汰
 
// 宣告必須在所有 probe 之前
let @latency_hist = hash(1024);
let @last_seen    = lruhash(10000);

kprobe:do_nanosleep {
  @last_seen[pid] = nsecs;
}

⚠️ LRU 不保證精確淘汰最舊

BPF LRU map 是近似 LRU，加入新元素時可能會一次淘汰多個 key。寫腳本時不要依賴「淘汰順序」做業務邏輯。

💡 沒宣告會怎樣？

不宣告的 map 自動套用 max_map_keys（預設 4096）。對於跑得短的 ad-hoc 腳本沒問題；但跑數小時或一天的腳本，常常會看到「map full」導致資料漏記。長跑腳本一律明確宣告 map type 與容量。

5.5 Per-Thread 變數慣用法

追蹤函式進入/退出的延遲時，常見做法是用 tid（thread id）當 map key：

let @start = lruhash(10000);

kprobe:do_nanosleep {
  @start[tid] = nsecs;
}

kretprobe:do_nanosleep /has_key(@start, tid)/ {
  $dur = nsecs - @start[tid];
  printf("slept for %d ms\n", $dur / 1ms);
  delete(@start, tid);
}

幾個必備技巧：

  • 用 tid 而不是 pid。pid 在 bpftrace 是 thread group id，多執行緒程式裡所有 thread 共用同一 pid。
  • kretprobe 一定要先 has_key() 檢查 —— bpftrace 啟動時可能進入函式已經發生，導致 retprobe 取不到對應的 entry。
  • 使用完一定要 delete()，否則 map 會慢慢膨脹。

5.6 跨 probe 傳遞輸出參數

Tracepoint exit 通常無法直接看到 entry 的參數。用 map 把 entry 階段的資訊「桶」到 exit 階段：

tracepoint:syscalls:sys_enter_wait4 {
  @ru[tid] = args.ru;          // 暫存 entry 參數
}

tracepoint:syscalls:sys_exit_wait4 {
  $ru = @ru[tid];
  delete(@ru, tid);
  if ($ru != 0 && args.ret >= 0) {
    printf("got rusage from %d\n", pid);
  }
}

CHAPTER 06 運算子與運算式 🛠 開發

運算子表大致與 C 一致，但有幾處 BPF 特有的眉角 —— 整數正負號混合、map 自增的 race、字串/tuple 的有限比較 —— 提早知道少踩雷。

6.1 算術運算子

運算子意義
+整數加法
-整數減法
*整數乘法
/整數除法
%整數取餘

規則：

  • 有號與無號混合運算時，bpftrace 會嘗試靜態證明轉換安全；不安全時會發 warning 並可能產生未定義行為。
  • 大小不同的整數會自動推廣到較大者；正負號保留。
  • 指標只能與整數做加減。減法時指標必須在左側。
  • 指標可用於邏輯運算 —— 非 NULL 視為 true。
BEGIN {
  printf("%d\n", (uint32)5 + (uint8)3);   // 8 (升級到 uint32)
  // 指標算術
  let $p = (int8 *)0x100;
  let $q = $p + 16;                        // OK
  // let $r = 16 + $p;                     // ❌ 指標必須在左
}

6.2 邏輯與位元運算子

類別運算子意義
邏輯&&AND（短路）
||OR（短路）
!NOT
位元&AND
|OR
^XOR
<<左移
>>右移

6.3 關聯運算子

適用對象不同：

運算子整數 / 指標字串 / 整數陣列 / tuple
== !=✅✅
< <= > >=✅❌
 
kprobe:vfs_read /comm == "bash"/ { ... }   // ✅ 字串相等
// kprobe:vfs_read /comm < "z"/ { ... }    // ❌ 字串無排序

6.4 賦值運算子

scratch 變數與 map 變數都支援以下複合賦值：

=  <<=  >>=  +=  -=  *=  /=  %=  &=  |=  ^=

例如 @x -= 5 等同 @x = @x - 5。

6.5 自增 / 自減

BEGIN {
  $x = 10;
  $y = $x--;    // y = 10; x = 9 (post-decrement)
  $a = 10;
  $b = --$a;    // a = 9;  b = 9 (pre-decrement)
}

幾個關鍵守則：

  • 只能用於變數，不能用於 expression。
  • Map 變數沒宣告或沒賦值時，++ / -- 會隱含初始化為 0。
  • Scratch 變數則必須先初始化才能用 ++ / --。

⛔ 全域 map 上的 ++ / -- 會掉資料

@global++ 在多 CPU 同時觸發時，因為 BPF map 沒有 atomic increment，更新會遺失。需要精確計數時用 count()：

// ❌ 多 CPU 下會掉
profile:hz:99 { @hits++; }

// ✅ count() 內部用 per-CPU 累計
profile:hz:99 { @hits = count(); }

count() 在 user space 讀取時會把所有 CPU 的部分和加總，得到精確數值。

6.6 Block Expression（區塊運算式）

大括號區塊本身可以當運算式使用，最後一個運算式（無分號結尾）就是區塊的值：

BEGIN {
  let $a = {
    let $b = 1;
    $b           // 沒分號 → 整個區塊的值是 1
  };
  printf("%d\n", $a);   // 1
}

Discard Expression（捨棄運算式）

有些函式會在「結果被丟棄」時發 warning（例如 has_key、delete）。如果你故意要丟棄，用底線吃掉：

{ 1 }                      // ⚠ warning: 結果被丟棄
$a = { 1 }                 // OK
has_key(@a, 1);            // ⚠ warning
$b = has_key(@a, 1);       // OK
_ = has_key(@a, 1);        // OK，明確表態「我不在乎結果」

CHAPTER 07 控制流程 🛠 開發

if / 三元 / for / unroll —— 在 BPF verifier 受限的世界裡，這幾個構造各自有不同的「能用 / 不能用」邊界。

7.1 if / else

kprobe:vfs_read {
  if (arg2 < 16) {
    @small = count();
  } else if (arg2 < 1024) {
    @medium = count();
  } else {
    @large = count();
  }
}

7.2 三元運算子

格式：condition ? ifTrue : ifFalse。兩個分支必須是相同型別，不能混。

BEGIN {
  $a = 5;
  $a == 1 ? print("one") : print("not one");
  $b = $a > 0 ? $a : -1;
}

7.3 Filter / Predicate（探針層的 if）

把 if 寫到 probe 後面的 /.../，使整個 action 變成有條件執行：

kprobe:vfs_read /comm == "bash" && arg2 > 1024/ {
  printf("big bash read\n");
}

// 等同於
kprobe:vfs_read {
  if (comm == "bash" && arg2 > 1024) {
    printf("big bash read\n");
  }
}

兩種寫法在功能上等價，但 predicate 形式更清晰，也利於 wildcard probe 上的條件過濾。

7.4 For 迴圈

bpftrace 的 for 有兩種模式：iterate map 與 iterate range。

遍歷 map

END {
  for ($kv : @counts) {
    printf("key=%d, val=%d\n", $kv.0, $kv.1);
  }
}

多 key 的 map，$kv.0 本身又是 tuple：

// @hits 的 key 是 (pid, comm)
END {
  for ($kv : @hits) {
    let $pid  = $kv.0.0;
    let $comm = $kv.0.1;
    let $cnt  = $kv.1;
    printf("%d %s -> %d\n", $pid, $comm, $cnt);
  }
}

遍歷整數範圍（0.24+）

範圍格式 start..end，包含 start，不含 end：

BEGIN {
  for ($i : 0..ncpus) {
    print($i);    // 印 0, 1, ..., ncpus-1
  }
}

📌 範圍的求值時機

start 與 end 在進入迴圈前求值一次，迴圈內變更不影響。下面的例子會印 0–9：

$a = 10;
for ($i : 0..$a) {
  print($i);
  $a--;          // 不影響 end
}

控制語句

語句行為
continue跳過區塊剩餘部分，進入下一輪
break跳出迴圈
return結束目前 probe（連帶跳出迴圈）

⛔ 0.25 變更：exit() 不能在迴圈內

exit() 隱含 return，但在迴圈內呼叫會產生未定義行為，所以 0.25 起編譯期就會擋下。需要在迴圈內中止整個程式時：

// ❌ 0.25 編譯失敗
for ($i : 0..100) {
  if ($i == 5) { exit(); }
}

// ✅ 先 break 跳出，再 exit()
for ($i : 0..100) {
  if ($i == 5) { break; }
}
exit();

7.5 While 迴圈（不建議）

while 已標記為 deprecated 且未來會移除。請改用 for，因為 for 更容易讓 verifier 證明邊界。

7.6 Unroll（編譯期展開）

unroll(n) 在編譯期把 block 重複展開 n 次。n 必須是大於 0 的常數：

interval:s:1 {
  unroll(3) {
    print("Unrolled");
  }
}

// 等同於：
interval:s:1 {
  print("Unrolled");
  print("Unrolled");
  print("Unrolled");
}

💡 unroll 在什麼場合有用？

  • 固定步驟的字串/陣列處理（避免 verifier 算不出 loop 邊界）。
  • 對舊 kernel（不支援 BPF loop）的相容。
  • 純粹想避免 loop overhead 時。

新 kernel（5.3+）有 BPF loop 原生支援，多數情境直接用 for 就好。

CHAPTER 08 結構化資料：Array · Pointer · Struct · Tuple · Record 🛠 開發

bpftrace 提供五種結構化資料 —— 各自定位不同。看完這章後，從 kernel struct 取資料、跨 probe 傳遞複雜資料都不會卡。

8.1 Array（陣列）

支援一維陣列存取，使用 [] 運算子。不能用 C 風格的字面值建構，只能從 pointer 讀進變數：

struct MyStruct {
  int y[4];
}

kprobe:dummy {
  $s = (struct MyStruct *)arg0;
  print($s.y[0]);   // 0.25 自動 deref，等同 $s->y[0]
  print($s.y[3]);
}

8.2 Pointer（指標）

用法與 C 大致相同。0.25 起 . 是偏好的存取運算子（會自動 deref 指標），-> 仍可用但只是 alias。

kprobe:vfs_open {
  // 0.25 推薦寫法
  $name = ((struct path *)arg0).dentry.d_name.name;

  // 0.24 及更早的寫法（仍可用）
  $name2 = ((struct path *)arg0)->dentry->d_name->name;
}

8.3 Struct（結構體）

使用 BTF 提供的 kernel struct

有 BTF 時，所有 kernel struct 都不需要 #include 就能直接用：

kprobe:vfs_open {
  printf("open path: %s\n",
         str(((struct path *)arg0).dentry.d_name.name));
}

自訂 struct

放在 preamble 區，與 C struct 寫法一致：

struct request_meta {
  uint64 start_ns;
  uint32 user_id;
}

kprobe:my_handle_request {
  $m = (struct request_meta *)arg0;
  printf("user=%d, started=%d\n", $m.user_id, $m.start_ns);
}

⚠️ 不能從零建構 struct

C 的 struct X v = {.f1 = 1} 在 bpftrace不支援。struct 變數只能透過 cast pointer 後讀進來，不能憑空產生。需要組合資料時改用 tuple 或 record。

8.4 Tuple（不可變多元組）

用 (...) 包起來的固定長度、各欄位可不同型別的序列。常用於：

  • Map 多 key（後面會看到）。
  • 函式回傳多個值。
  • 暫存一組相關資料。
interval:s:1 {
  $a = (1, "hello");
  $b = (3, 4, $a);             // 嵌套
  print($a);                    // (1, "hello")
  print($b);                    // (3, 4, (1, "hello"))
  print($b.0);                  // 3
  print($a[1]);                 // "hello" (array-style 也行，但 index 必須是字面整數)
}

特殊形式：

  • 單元素 tuple：(1,)（後綴逗號必要）
  • 空 tuple：()

8.5 Record（具名 struct-like，0.25 新增）

Record 是 0.25 新加入的型別。把 tuple 的每個欄位賦予名字，使用 . 取值：

interval:s:1 {
  $a = (color="green", size=2);
  print($a);             // { .color = "green", .size = 2 }
  print($a.size);        // 2

  // 重新賦值時，欄位順序可變
  $a = (size=10, color="blue");
  print($a.color);       // "blue"
}

📌 Record vs Tuple vs Struct

  • Tuple：用位置存取（$a.0、$a[1]）。輕量、適合短暫使用。
  • Record：用名稱存取（$a.size）。可讀性高、適合作為腳本內部 API。不可變。
  • Struct：對應 kernel/user 程式裡已存在的記憶體佈局，從 pointer 解析而來。

8.6 型別轉換（Type Conversion）

整數與指標互轉用一般 cast 語法：

$y = (uint32)$z;
$py = (int16 *)$pz;

整數升級時：高位元用符號擴展；降級時直接砍掉高位。

整數陣列轉換（最常用於 IP 位址）

整數可與整數陣列互轉，前提是兩者大小相同（or omit size 自動推導）：

BEGIN {
  $a = (uint8[8])12345;
  printf("%x %x\n", $a[0], $a[1]);  // 39 30
  printf("%d\n", (uint64)$a);       // 12345
}

實戰場景 —— 比對 socket 結構裡的 IPv4：

fentry:tcp_connect {
  // skc_daddr 是 __be32（network byte order, uint32）
  // pton("127.0.0.1") 回傳的是 char[4]
  // 用 (uint32) cast 把 char[4] 轉成同型別後比對
  if (args.sk.__sk_common.skc_daddr == (uint32)pton("127.0.0.1")) {
    printf("connecting to localhost\n");
  }
}

CHAPTER 09 命令列參數 🛠 開發 ⚙️ SRE

讓腳本能接受外部輸入，是把 ad-hoc 腳本升級為可重用工具的關鍵。bpftrace 提供 positional 與 named 兩種，後者強烈推薦。

9.1 Positional Parameters（位置參數）

用 $1、$2、... $N 存取，$# 是參數總數：

// trace_pid.bt
BEGIN {
  printf("Tracing PID=%d, threshold=%d ms (got %d args)\n",
         $1, $2, $#);
}

kprobe:do_nanosleep /pid == $1/ {
  @start[tid] = nsecs;
}

kretprobe:do_nanosleep /@start[tid]/ {
  $dur = (nsecs - @start[tid]) / 1ms;
  if ($dur > $2) {
    printf("[pid %d] slept %d ms\n", pid, $dur);
  }
  delete(@start, tid);
}
sudo bpftrace trace_pid.bt 1234 100
# Tracing PID=1234, threshold=100 ms (got 2 args)

參數型別：依使用情境動態決定

  • 用在數值情境（算術、比較）→ 整數，未提供時預設 0。
  • 用在字串情境（str()）→ 字串指標，未提供時預設 ""。
  • 用在 probe 引數（如 tracepoint:block:block_rq_issue /args.bytes > $1/）→ 字串轉整數。

字串指標運算

positional 參數用在 str() 時是指向字串字面值的指標，可以做有限的指標算術 —— 加上一個小於等於字串長度的常數：

# bpftrace -e 'BEGIN { printf("%s\n", str($1 + 1)); }' "hello"
# ello

9.2 Named Parameters（具名參數，0.24+ 推薦）

透過 getopt() 存取，命令列上要在 -- 之後傳入。

// app_trace.bt
BEGIN {
  let $tgt_pid   = getopt("pid", 0,    "Target PID (0=all)");
  let $threshold = getopt("ms",  100,  "Latency threshold in ms");
  let $verbose   = getopt("verbose",   "verbose output");
  printf("pid=%d, ms=%d, verbose=%d\n", $tgt_pid, $threshold, $verbose);
}
sudo bpftrace app_trace.bt -- --pid=1234 --ms=50 --verbose
# pid=1234, ms=50, verbose=1

getopt() 三種型別

呼叫方式型別命令列形式
getopt("name")bool--name / --name=true / --name=1 / --name=false
getopt("name", false)bool同上
getopt("name", 100)int--name=200
getopt("name", "default")string--name=hello

💡 自動產生 --help

給 getopt() 加第三個 description 參數後，使用者執行 --help 會自動印出所有 named param 與說明 —— 比 positional 親切非常多。

9.3 兩者並用

positional 可放在 -- 前後；named 必須放在 -- 之後：

sudo bpftrace -e '
BEGIN { print(($1, $2, getopt("aa", 1), getopt("bb"))); }
' p1 -- --aa=20 --bb p2
# (p1, p2, 20, true)

📌 named 優先於 positional 的時機

當腳本參數 ≥ 2 個、或某些參數是選用時，named 大幅降低使用者錯誤的機會。Positional 適合 一兩個必填參數 的快速腳本（例：trace 某個 PID）。

CHAPTER 10 Macros（衛生巨集） 🛠 開發

Macro 是 0.25 已穩定的功能。把重複邏輯抽出、跨 probe 共用 —— 但別把它當成 C 巨集，bpftrace macro 是有型別感知的。

10.1 為什麼要用 Macro

當多個 probe 共用一段邏輯（計算延遲、印 stack、判斷某條件），一直複製貼上會讓腳本難維護。Macro 提供「語意感知的文字替換」 —— 看起來像文字展開，但 bpftrace 知道每個參數的型別。

10.2 基本語法

macro NAME(params) {
  body
}

參數簽章決定每個參數要傳入哪種東西：

參數簽章必須傳入備註
$ascratch 變數macro 可能會修改它
b (裸名)任何運算式每次使用 b 處等同重新貼上整個運算式
@cmap 變數macro 可能會修改它

10.3 範例

macro one() {
  1
}

macro add_one(x) {
  x + 1
}

macro add_one_to_each($a, @b) {
  $a += 1;
  @b += 1;
}

macro side_effects(x) {
  x;
  x;
  x;
}

macro add_two(x) {
  add_one(x) + 1
}

BEGIN {
  print(one());                    // 1
  print(one);                       // 1（無參 macro 可省略括號）

  $a = 10;
  print(add_one($a));               // 11
  print(add_one(1 + 1));            // 3

  @b = 5;
  add_one_to_each($a, @b);
  print($a + @b);                   // 17

  side_effects({ printf("hi") });   // hihihi（執行 3 次）

  print(add_two(1));                // 3
}

10.4 衛生（Hygiene）原則

Macro body 只能存取透過參數傳入的變數和 map。直接引用未傳入的全域 map 會被擋下：

// ❌ 不衛生：macro 偷偷改外部 @x
macro unhygienic_access() {
  @x++
}

// ❌ 型別不符：macro 期望 scratch 變數，傳入 map 或字面值
macro wrong_param($x) { $x++ }

BEGIN {
  @x = 1;
  unhygienic_access();           // ❌ @x 沒被傳入

  wrong_param(@x);               // ❌ 期望 $x scratch
  wrong_param(1 + 1);            // ❌ 期望 $x scratch
}

10.5 求值次數陷阱

裸名參數每次出現都重新求值。如果你只想求值一次，先綁到變數：

// ❌ rand 被呼叫 3 次
macro side_effects(x) {
  x; x; x;
}

// ✅ 用 let 綁定，只求值一次
macro side_effects_v2(x) {
  let $x = x;
  $x; $x; $x;
}

BEGIN {
  side_effects(rand);       // 取 3 次不同的隨機數
  side_effects_v2(rand);    // 取 1 次後重複使用
}

10.6 實戰：抽出 latency 計時邏輯

多個 probe pair 都要做「進入記時間 → 退出算 delta」這件事，可抽成 macro：

let @ts = lruhash(8192);

macro start_timer(@m) {
  @m[tid] = nsecs;
}

macro end_timer(@m, threshold_ns) {
  if (has_key(@m, tid)) {
    let $delta = nsecs - @m[tid];
    delete(@m, tid);
    if ($delta > threshold_ns) {
      printf("[%s] tid=%d, lat=%d us\n",
             func, tid, $delta / 1us);
    }
  }
}

kprobe:vfs_read       { start_timer(@ts); }
kretprobe:vfs_read    { end_timer(@ts, 5ms); }

kprobe:vfs_write      { start_timer(@ts); }
kretprobe:vfs_write   { end_timer(@ts, 5ms); }

💡 Macro 用得好的指標

  • 抽出來的邏輯是「跨 probe 重複」而非「特定 probe 才有意義」。
  • 名稱清楚表達意圖（start_timer 比 x 好）。
  • 參數簽章嚴謹 —— 該是 map 就用 @，該是 scratch 就用 $。
  • 避免在 macro 內呼叫 macro 太多層；除錯訊息會難追。
