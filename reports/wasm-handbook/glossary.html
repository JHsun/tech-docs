A B C D E F G H I J K L M N O P R S T U V W

A

ABI 應用程式二進位介面 Application Binary Interface → M02, M07

兩個獨立編譯的程式碼模組互相呼叫時，雙方必須遵守的低階呼叫規範——包含參數如何傳遞、回傳值如何處理、記憶體 layout 等。Wasm 的 Canonical ABI 是 Component Model 的核心。

Ahead-of-Time Compilation 預先編譯 AOT → M02, M10

執行前就把 .wasm 編譯為原生機器碼。對比於 JIT（執行時編譯）。AOT 加快啟動但綁定 CPU 架構，常用於生產部署。Wasmtime 可用 wasmtime compile 預編譯為 .cwasm。

Ambient Authority 環境權限 → M03

傳統作業系統的安全模型——程式預設取得各種能力（讀檔、聯網），權限由 ACL 事後檢查。對比於 capability-based 沒有這種「環境權限」。

AssemblyScript AssemblyScript → M05

TypeScript-like 語法的 Wasm 專用語言。設計上對 web 開發者友善，產出 binary 小，但生態相對較小。

Asm.js asm.js → M01

Mozilla 2013 推出的 JS 子集，作為 Wasm 前身。把 JS 限制在「typed assembly」風格，讓引擎能 AOT 編譯。Wasm 採用了它的核心理念——靜態型別、易優化——但改為二進位格式。

B

Binary Format 二進位格式 → M02

Wasm 模組的標準傳輸格式（.wasm 副檔名）。對比於 WAT（文字格式）。所有 runtime 載入的都是二進位格式。

Blazor Blazor → M05

Microsoft 推出的把 C# 編到 Wasm 的框架。內含 .NET runtime + Mono on Wasm，binary 較大（數 MB）但 enterprise 採用率高。

Bytecode Alliance Bytecode 聯盟 → M01

2019 年由 Mozilla、Fastly、Intel、Red Hat 創立的非營利組織，致力推動 Wasm 與 WASI 在瀏覽器外的標準化。維護 Wasmtime、WAMR、wit-bindgen、cargo-component 等核心工具。

C

Canonical ABI 標準 ABI → M07

Component Model 的標準 ABI——定義 WIT 高階型別（string、list、record、resource）如何「lower」到 core Wasm 原語（i32、memory bytes），以及反向的「lift」。是跨語言 component 互通的基礎。

Capability-based Security 能力導向安全 → M03

1970 年代提出的安全模型——程式預設無能力，所有能力以不可偽造的 handle 形式明確授予。Wasm 是第一個讓這套模型在主流落地的技術。對比於 permission-based 模型。

cargo-component cargo-component → M05, M07

Bytecode Alliance 開發的 Rust 工具，專為產出 WASI 0.2 component 設計。自動生成 WIT 綁定，是 2026 Rust component 開發的事實標準。

Circuit Breaker 斷路器 → M03, M10

分散式系統模式：當下游連續失敗時暫時停止呼叫（「open」狀態），冷卻一段時間後再嘗試。保護下游不被打死。Wasm host 對 outbound 呼叫加 circuit breaker 是標準做法。

CNCF 雲端原生運算基金會 Cloud Native Computing Foundation → M01

Linux Foundation 旗下的雲端原生治理組織。Wasm 相關專案：wasmCloud（Incubating）、WasmEdge（Sandbox）、SpinKube（Sandbox）。

Cold Start 冷啟動 → M05, M08, M10

從「無此實例」到「第一行業務邏輯執行」的時間。Wasm 的招牌特性：µs 到低毫秒，比容器（數百毫秒到秒級）快 2-3 個數量級，讓 scale-to-zero 真正可用。

Component 元件 → M07

Component Model 中的部署單位——core module 加上 WIT 介面與 Canonical ABI。可跨語言組合、跨 runtime 可攜。對比於 core module。

Component Model 元件模型 → M07

Wasm 的高階抽象層，引入 WIT 與 Canonical ABI 讓不同語言的 Wasm component 能正確互通。2026 達到 1.0 里程碑，是 Wasm「Docker moment」的核心拼圖。

Confused Deputy Problem 糊塗代理人問題 → M03

傳統 permission-based 系統的經典安全問題——程式以自己權限執行被誘騙的操作，導致權限被濫用。Capability-based 模型從架構上消除這個問題。

containerd-wasm-shims containerd Wasm shim → M06, M08

Microsoft + Fermyon + Docker 共同維護的 containerd 擴展，讓 K8s 可用 RuntimeClass 機制直接執行 .wasm。包含 containerd-shim-spin、shim-wasmedge、shim-wasmtime 等。2026 K8s 跑 Wasm 的事實標準。

Core Module 核心模組 → M02, M07

傳統 Wasm 模組——只有 i32/i64/f32/f64/v128 等原語型別，無 WIT 介面。對比於 component。Component 內部仍包含 core module。

Cranelift Cranelift → M02, M06

Bytecode Alliance 開發的 JIT/AOT 編譯器後端，Rust 寫。Wasmtime 預設用 Cranelift。設計目標：快編譯（比 LLVM 快很多）、安全（無 UB）、跨平台。

D

Dart Dart → M05

Google 推出的程式語言，2024 起原生支援 Wasm GC，Flutter Web 主推。是 GC 類語言中 Wasm 整合最成熟的之一。

DNS Rebinding DNS 重綁定攻擊 → M03

攻擊者控制 DNS 解析結果，第一次回應公開 IP（通過 allowlist），第二次回應內網 IP（執行攻擊）。防禦：解析後鎖定 IP，不讓 dial 重新解析 hostname。

E

Emscripten Emscripten → M05

把 C/C++ 編譯到 Wasm 的工具鏈，主打瀏覽器整合。自動生成 JS glue code、模擬 SDL/OpenGL 等 API。對比於 WASI SDK（純伺服器導向）。

Envoy Envoy → M08

CNCF 畢業專案的 service proxy，是 Istio 的資料平面。透過 Proxy-Wasm spec 支援 Wasm filter，讓 service mesh 邏輯可用 Wasm 寫。

Epoch Interruption 紀元中斷 → M03

Wasmtime 的 CPU 限制機制——定期讓 runtime 檢查「該不該中止」。開銷低（無每指令扣費），但精度低（毫秒級）。對比於 fuel。

Extism Extism → M06

多語言 Wasm 外掛系統框架。底層支援 Wasmtime / wazero，宿主端 SDK 涵蓋 Go、Python、Node、PHP、Ruby、Rust 等。適合「應用想支援第三方 Wasm 外掛」場景。

F

Fastly Compute@Edge Fastly Compute → M06, M08

Fastly 的邊緣 Wasm serverless 平台。全球 PoP 部署，µs 級冷啟動。原本是 VCL 的進化版，2019 開始公測。底層 Wasmtime fork。

Fermyon Fermyon → M06

Spin 與 SpinKube 的母公司，由前 Microsoft / Deis Labs 團隊創立。2025 年被 Akamai 收購。Spin 是「Wasm serverless 為主」概念的最積極推動者。

Filter 過濾器 → M08, Capstone

在請求處理 pipeline 中插入的邏輯單元。Proxy-Wasm 將 Envoy / Istio filter 模型標準化。Capstone 專案的核心概念。

Flutter Flutter → M05

Google 的跨平台 UI framework，使用 Dart 語言。Flutter Web with Wasm（2024 stable）用 Wasm 取代 dart2js，效能近 native。

FQCN 完整限定類別名稱 Fully Qualified Class Name —

在程式設計中指完整命名空間 + 類別名稱。Wasm 中類似概念是「namespace:package/interface@version」如 wasi:http/incoming-handler@0.2.0。

Fuel 燃料（CPU 配額） → M03, M10

Wasmtime 的精確 CPU 計量機制——每執行一條 Wasm 指令消耗一單位 fuel，用盡時 trap。精確但有少量開銷。對比於 epoch interruption。

G

Garbage Collection 垃圾回收 GC → M01, M05

自動記憶體管理機制。Wasm 3.0（2025-09）原生加入 GC 提案，讓 Java、Kotlin、Dart、Scheme 等 GC 語言可以用宿主 GC，binary 大幅瘦身。

Graceful Shutdown 優雅關閉 → M10

收到 SIGTERM 後的正確關機順序：先讓 LB 切走流量、等進行中請求完成、再關閉資源、最後 exit。對 Wasm host 是必要設計。

H

Handle 控制代碼 → M03, M07

能力導向安全的核心抽象——不可偽造、不可拷貝的物件參考。Wasm 中常以 i32 ID 表示，由宿主維護 registry。Component Model 把 handle 表達成 first-class 的 resource 型別。

Host 宿主 → M02, M03

執行 Wasm 模組的環境。可以是瀏覽器、Wasmtime 嵌入的應用、Spin 平台等。宿主提供 import 給 Wasm，並負責安全邊界執行。

Host Function 宿主函式 → M02, M03

Wasm 模組透過 import 取得的外部函式。安全邊界——所有 Wasm 對外能力都靠 host function 提供。

HPA 水平自動擴縮 HorizontalPodAutoscaler → M08, M10

K8s 內建的自動擴縮機制，依 CPU、記憶體、或自訂 metric 動態調整 Pod 數量。Wasm 部署的標準配套。

I

Idempotent 冪等 → M10

操作重複執行多次結果相同（HTTP GET、PUT 設計上冪等）。對 Wasm HA 設計很關鍵——instance 可隨時被銷毀重建，所有對外操作必須冪等。

Import / Export 匯入 / 匯出 → M02

Wasm 模組的邊界宣告。Import 是模組需要的能力（從宿主取得）；Export 是模組對外提供的能力（給宿主呼叫）。capability-based 安全的物理基礎。

Instance 實例 → M02

Wasm module 的執行時實體。同一 module 可實例化多次，每個 instance 有獨立的 linear memory 與 global state。

Instance Pool 實例池 → M10

預先建立一批 Wasm instance 等請求使用，減少 per-request instantiate 成本。Wasmtime 內建 PoolingAllocator 提供高效實作。

Istio Istio → M08

CNCF 畢業的 service mesh，資料平面用 Envoy。透過 WasmPlugin CRD 支援 Wasm filter，讓服務間流量處理用 Wasm 客製。

J

jco jco → M07

Bytecode Alliance 的 JS component 工具，可把 JS 編譯成 WASI 0.2 component（componentize），或把 component transpile 成 ES module 在瀏覽器使用。

JIT 即時編譯 Just-in-Time → M02, M06

執行時動態編譯 Wasm 為原生碼。對比於 AOT。Wasmtime、V8 等預設用 JIT。

Javy Javy → M05

Shopify 開源的 JS-to-Wasm 工具——QuickJS 引擎 + 你的 JS code 打包成單一 .wasm。Shopify Functions 大量使用。

K

Krustlet Krustlet → M01, M06

Microsoft 2020 推出的「把 Wasm 當 K8s first-class workload」kubelet 替代。2024 已 archived——被 containerd-wasm-shims 取代。新專案不要採用。

KWasm Operator KWasm 運算子 → M08

K8s operator 自動在 nodes 上安裝 Wasm shim（如 containerd-shim-spin）。簡化 K8s 採用 Wasm 的流程。

L

Lift / Lower 提升 / 降低 → M07

Canonical ABI 的兩個方向轉換。Lower：把 WIT 高階型別降到 core Wasm 原語（string → ptr+len）；Lift：反向。跨 component 邊界時兩端各做一次。

Linear Memory 線性記憶體 → M02

Wasm instance 配有的連續位元組陣列。從 0 開始、64KB 一頁、可動態 grow、宿主可讀寫但 Wasm 不能讀宿主記憶體——沙箱隔離的根本。

Linker 連結器 → M06

runtime 中負責「把 import 連到實際實作」的元件。Wasmtime 的 Linker、wazero 的 ModuleBuilder 都是此概念。

Linker / Loader 連結與載入 → M07

Build-time linking（wac compose）與 runtime linking（wasmCloud 動態 wire）兩種策略。前者產出單一 binary，後者支援動態替換。

Liveness Probe 存活探針 → M10

K8s 健康檢查——判斷容器是否還活著，失敗會 restart。對比於 readiness probe（判斷是否準備好接流量）。

Load Balancer 負載平衡器 LB → M10

流量分發層。L4（TCP/UDP）vs L7（HTTP）。Wasm 部署建議用 consistent hashing 而非 round-robin，提高 AOT cache 命中率。

M

Memory64 64-bit 記憶體 → M01

Wasm 3.0（2025-09）的提案——linear memory 與 table 可用 64-bit 位址，解除 4GB 上限。對 AI 推論、大型運算、邊緣 ML 是必要條件。

Mermaid Mermaid —

流程圖描述語言，本 handbook 所有圖表用 Mermaid 寫成。

Module 模組 → M02

編譯後的 .wasm binary。包含 type、function、memory、import、export 等 section。對應到 OOP 的 class，需要實例化才能執行。

N

NaCl / PNaCl Native Client → M01

Google 2008-2014 推出的瀏覽器內跑原生程式碼方案，是 Wasm 前身之一。後因「跟 CPU 架構綁定」「Web 安全模型整合困難」「其他瀏覽器不買單」而被取代。

NATS NATS → M06

高效能訊息系統。wasmCloud 用 NATS 作為 control plane，hosts 與 actors 透過 NATS lattice 通訊。

O

OCI 開放容器倡議 Open Container Initiative → M07, M08

容器 image 標準。2024 起 OCI spec 正式支援 Wasm 作為 first-class artifact——可以同時在 registry 存放容器與 Wasm。

OOM 記憶體不足 Out of Memory → M10

記憶體用盡。Wasm 沙箱保證：單一 instance OOM 只導致該 instance trap，不影響 host process——這是 Wasm 故障半徑小的根本。

OpenTelemetry OpenTelemetry OTel / OTLP → M09

CNCF 畢業專案，雲端原生可觀測性的事實標準。定義 traces、logs、metrics 三大支柱的 API、SDK、wire protocol（OTLP）。Wasm 生態（Spin、wasmCloud）已內建整合。

P

PDB Pod 中斷預算 PodDisruptionBudget → M10

K8s 內建機制，保證自願中斷（node drain、rolling update）時最少有 N 個 Pod 可用。Wasm HA 配套標準。

Playbook 行動手冊 —

運維場景常見術語——預先寫好的「事件 X 該怎麼處理」程序文件。Ansible 用同詞代表自動化腳本。本書多用前者意思。

PoolingAllocator 池式分配器 → M10

Wasmtime 內建的記憶體分配策略，預分配一塊記憶體給多個 instance 重用，比預設 OnDemandAllocator 高效得多。生產部署建議啟用。

Preview 1 / Preview 2 / Preview 3 預覽版 1 / 2 / 3 → M04

WASI 的版本命名。2024 改為新命名：Preview 1 = WASI 0.1，Preview 2 = WASI 0.2，Preview 3 = WASI 0.3。2026 年 0.2 stable，0.3 預覽。

Proxy-Wasm Proxy-Wasm → M08

業界 spec，定義 proxy（Envoy、Istio、APISIX、Kong、MOSN）與 Wasm filter 的 ABI。讓同一個 Wasm filter 可在多個 proxy 跑。

Pyodide Pyodide → M05

把 CPython + NumPy + SciPy 全套編到 Wasm，瀏覽器內跑 Python 科學運算。Binary ~10MB，啟動秒級，但完整 PyPI 套件可用。

R

Readiness Probe 就緒探針 → M10

K8s 健康檢查——判斷 Pod 是否準備好接流量。失敗時 LB 排除該 Pod 但不重啟。對比於 liveness probe。

Resource 資源 → M04, M07

WIT 中的 first-class 型別，代表 capability handle。不可拷貝、不可序列化、有自動 destructor。是 capability-based 安全的型別系統表達。

RuntimeClass 執行時類別 → M08

K8s 機制，讓 Pod 指定使用的容器 runtime（如 containerd、CRI-O、各種 Wasm shim）。Wasm 在 K8s 跑的核心配套。

S

Sandbox 沙箱 → M03

隔離不可信程式碼的安全環境。Wasm 是 VM-level sandbox，比 OS-level（cgroup、namespace）更強的型別與記憶體隔離保證。

Scale-to-Zero 縮容至零 → M08, M10

無流量時 Pod 數降到 0。傳統容器有冷啟動懲罰，需 keep-warm 隱藏；Wasm µs 級冷啟動讓 scale-to-zero 真的可用——閒置時零成本。

SpinKube SpinKube → M06, M08

CNCF Sandbox 專案，K8s operator 把 Spin 應用以 SpinApp CRD 部署。提供高階抽象簡化「K8s 跑 Wasm」流程。Fermyon、Microsoft、SUSE 共同維護。

Spin / Spin Factors Spin / Spin Factors → M06, M08

Fermyon 開源的 Wasm serverless framework。HTTP / Redis / cron 事件驅動，內建 KV、SQLite、AI inference 等能力。Spin 3.0（2026 Q1）引入 Factors 架構讓 host capability 變成可插拔模組。

SSRF 伺服器端請求偽造 Server-Side Request Forgery → M03

攻擊技巧——誘使伺服器向內網或敏感端點發請求。capability-based 模型從架構消除（沒給的目標 socket 都打不開），但仍要防 DNS rebinding。

Stack Machine 堆疊式虛擬機 → M02

用 stack 而非 register 表達運算的 VM 架構。Wasm、JVM、CLR 都採此模型。優點：binary 小、解碼快、易驗證。執行時通常 JIT/AOT 編譯為 register-based 原生碼。

T

Tail Call 尾呼叫 → M01

函式最後一個操作是呼叫另一個函式。Wasm 3.0 原生支援 tail call 優化，函式式語言（Scheme、OCaml）的遞迴能常數空間執行。

Tempo / Loki / Mimir Grafana Tempo / Loki / Mimir → M09

Grafana Labs 的觀測 stack：Tempo 存 traces、Loki 存 logs、Mimir 存 metrics。都支援 OTel ingest，搭配 Grafana UI 形成完整觀測平台。

TinyGo TinyGo → M05

基於 LLVM 的 Go 替代編譯器，專為小 binary 設計。支援 Go 語言子集，編出的 Wasm 體積比標準 Go 小 5-20 倍。2024 起原生支援 wasip2 + Component Model。2026 主流 Wasm + Go 選擇。

Trace Context 追蹤脈絡 → M09

W3C 標準，描述 distributed tracing 中的「我屬於哪個 trace、parent 是誰」。透過 HTTP header（traceparent、tracestate）傳遞。Wasm 中要顯式 propagate 給 component。

Trap 陷阱 → M02

Wasm 執行時的「不可恢復錯誤」——記憶體越界、整數除零、stack overflow、unreachable 指令等。Trap 中止當前執行，runtime 把錯誤回給宿主。安全模型的最後防線。

U

Untrusted Guest 不可信客體 → M03

Wasm 模組相對於宿主的角色定位——即使是自家 binary 也要當作不可信。所有從 Wasm 來的資料當不可信輸入處理。

V

Validation 驗證 → M02

Wasm 載入時的靜態檢查——型別正確、記憶體訪問有效、控制流結構合法。通過 validation 的 module 在型別系統內保證「不會亂走」。

Variant 變體 → M04, M07

WIT 中的 tagged union 型別——值是多種可能型別之一，配上區分標籤。對應 Rust enum、TypeScript discriminated union。

W

W3C 全球資訊網協會 World Wide Web Consortium → M01

Web 標準制訂組織。Wasm 1.0（2019）、2.0（2022）、3.0（2025）的 spec 都是 W3C Recommendation。

wac WebAssembly 組合工具 WebAssembly Compositions → M07

CLI 工具，把多個 component 組合成一個。wac plug 簡單 wire；wac compose 用 .wac 檔聲明複雜組合。

WAMR WebAssembly 微執行時 WebAssembly Micro Runtime → M06

Bytecode Alliance 旗下的嵌入式 Wasm runtime，C 寫。記憶體佔用可低至 85KB，支援 Linux、Zephyr、FreeRTOS、SGX、Nuttx、ESP-IDF。汽車、工業客戶採用。

WASI Wasm 系統介面 WebAssembly System Interface → M04

Wasm 的 POSIX——標準化、能力導向的系統介面。讓 Wasm 跳出瀏覽器，可在伺服器、邊緣、嵌入式跑。Preview 1 → 0.2 → 0.3 演進。

WASI-NN WASI 神經網路 → M05, M06

WASI 的 ML inference 子集。支援 PyTorch、TensorFlow Lite、OpenVINO 等。WasmEdge 是主要實作者。

WASI-OTel WASI OpenTelemetry → M09

提案中的 WASI world，把 OTel 變成 first-class Wasm 介面，解決 trace context 跨邊界、SDK 編譯等問題。截至 2026 仍 Phase 0，但 Spin、wasmCloud 有提前實作。

WASIX WASIX → M04, M06

Wasmer 公司推出的 WASI Preview 1 fork，加入 POSIX fork/threads/signals 擴充。優：移植既有 POSIX 程式容易。缺：綁定 Wasmer 生態，不是標準。

Wasm 3.0 Wasm 3.0 → M01

2025-09 live 的 W3C Recommendation。重大更新：GC、memory64、exception handling、tail calls、multiple memories、relaxed SIMD。對 Java、Dart、Kotlin 等 GC 語言意義重大。

wasm-bindgen wasm-bindgen → M05

Rust 工具，自動生成 Rust ↔ JS 綁定。讓瀏覽器內 Rust Wasm 與 JS、DOM、Web API 互通。

wasmCloud wasmCloud → M06

CNCF Incubating 專案。分散式 actor model 平台，跨雲跨邊緣的 Wasm runtime。底層用 Wasmtime。American Express 等企業生產採用。

WasmEdge WasmEdge → M06

CNCF Incubating 專案。C++ 寫的 Wasm runtime，主打邊緣 + AI 推論。內建 WASI-NN，支援 LLM serving。

Wasmer Wasmer → M06

Wasmer Inc. 推出的 Wasm runtime，Rust 寫。三種後端可選：Cranelift、LLVM、Singlepass。主推 WASIX，提供 POSIX 移植性。

Wasmtime Wasmtime → M06

Bytecode Alliance 旗艦 Wasm runtime，Rust 寫。事實上的 WASI 參考實作，最新提案首發。Fastly Compute、Spin、wasmCloud 等都用 Wasmtime。

WAT WebAssembly 文字格式 WebAssembly Text Format → M02

.wasm binary 的人類可讀 S-expression 對應。debug 與學習用，生產不用 WAT 部署。wasm-tools print 反組譯 .wasm 為 WAT。

wazero wazero → M06

Tetratelabs 開源的 Wasm runtime，純 Go 寫、零 CGO。對 Go 宿主整合最自然。WASI 0.1 完整、0.2 進行中。

WIT Wasm 介面型別 WebAssembly Interface Types → M04, M07

Component Model 的介面定義語言。支援 record、variant、resource、list、option、result、future、stream 等高階型別。跨語言綁定生成的基礎。

wit-bindgen wit-bindgen → M05, M07

Bytecode Alliance 工具，從 WIT 介面生成多語言綁定（Rust、Go、Python、JS、C 等）。讓寫 component 像呼叫一般函式。

wkg wkg wasm-pkg-tools → M05, M07

Bytecode Alliance 的 component 套件管理工具。像 npm / cargo 之於 component——推/拉 OCI registry、解析 WIT 依賴。2026 component 分發的標準工具。

World 世界 → M04

WIT 中的概念——描述 component 的「形狀」：它匯入什麼、匯出什麼。標準 world 如 wasi:cli/command、wasi:http/proxy 等。

SYMBOLS符號與縮寫附錄

.wasm Wasm binary 副檔名

Wasm 二進位 module / component 的標準副檔名。

.wat Wasm text 副檔名

WAT 文字格式檔副檔名。用 wasm-tools parse 可組譯為 .wasm。

.wit WIT 介面定義

WIT 介面定義檔副檔名。

.cwasm Wasmtime AOT 編譯

Wasmtime wasmtime compile 產出的 AOT 編譯結果。跟 CPU 架構與 Wasmtime 版本綁定。

FaaS 函式即服務 Function as a Service

Serverless 的核心模型。Wasm 因冷啟動極快適合 FaaS。

RED Metrics RED 指標

服務監控的核心三指標：Rate（請求速率）、Errors（錯誤率）、Duration（延遲）。OTel 應用 metric 設計的起點。
