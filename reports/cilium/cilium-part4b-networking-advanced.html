1. BGP Control Plane

1.1 BGP 在 Cilium 的角色

Cilium 內建 BGP speaker（基於 GoBGP），讓 cluster node 跟資料中心 router 建立 BGP session，把以下三類路由宣告到 underlay：

  • Pod CIDR：讓外部能直連 Pod IP（native routing 必備）
  • Service ClusterIP：外部可直接連 ClusterIP
  • LoadBalancer IP（VIP）：替代雲端 LB，地端用 BGP 廣播 VIP
💡 BGP 不是 datapath

官方明確指出：BGP Control Plane 不處理 datapath。它只負責把路由宣告出去，封包走 underlay 的 Linux routing。所以 BGP 用於 cluster 對外連通，不該用來做 cluster 內 pod 互通（那是 routing mode 的工作）。

yaml
apiVersion: cilium.io/v2

metadata:
  name: bgp-advertisements
  labels:
    advertise: "bgp"           # PeerConfig 用 matchLabels 找這條
spec:
  advertisements:
    # 宣告每 node 自己分配到的 Pod CIDR
    - advertisementType: "PodCIDR"
      attributes:
        communities:
          standard: ["65000:1"]   # 標 community 給 spine 套 policy

    # 宣告特定 Service 的 LoadBalancer VIP

          - ExternalIP
      selector:
        matchLabels:
          bgp-announce: "true"   # Service 加這 label 才被宣告

1.4 Auto-discovery（自動發現 peer）

大型 fabric 環境，每 node 手動填 peerAddress 很麻煩。1.18+ 新增 DefaultGateway auto-discovery：Cilium 用每 node 的 default route 推斷 peer 是誰。

yaml
apiVersion: cilium.io/v2
kind: CiliumBGPClusterConfig
metadata:
  name: cilium-bgp-auto
spec:
  nodeSelector:
    matchLabels:
      bgp: "true"
  bgpInstances:
    - name: "instance-auto"
      localASN: 65000
      peers:
        - name: "auto-peer"
          peerASN: 65100
          autoDiscovery:
            mode: DefaultGateway
            defaultGateway:
              addressFamily: ipv4
          peerConfigRef:
            name: "cilium-peer"

ToR 端要配合開 BGP listen range（FRR / Cumulus / Arista 都有），允許 dynamic neighbor：

text
# FRR 範例
router bgp 65100
 neighbor CILIUM peer-group
 neighbor CILIUM remote-as external
 bgp listen range 10.0.0.0/24 peer-group CILIUM

1.5 故障排除

症狀原因排查
BGP session 不起來 底層 IP 不通 / capability mismatch / ASN 寫錯 先 ping peer；看 kubectl logs ds/cilium 過濾 subsys=bgp-control-plane；用 tcpdump 抓 179
type: cilium.io/NoMatchingNode nodeSelector 沒選到 node 確認 node label：kubectl get nodes --show-labels
type: cilium.io/ConflictingClusterConfigs 多個 ClusterConfig 選到同 node 調整 nodeSelector 避免重疊
Agent 重啟後路由消失，short outage 沒開 graceful restart PeerConfig 加 gracefulRestart.enabled: true
Service VIP 沒被宣告 Service 沒加 label / Advertisement selector 寫錯 cilium bgp routes advertised 看實際狀態
backend 都掛了，VIP 還在宣告（cluster policy） 1.19 預設 --enable-no-service-endpoints-routable=true 需要時可設 false，讓 backend 全掛時 withdraw VIP
⚠ 升級 Cilium 時務必 pre-pull image

BGP speaker 在 agent 內，升級時 agent 重啟會中斷 session。image 沒 pre-pull 等於把 BGP 中斷時間拉長。pre-flight 流程（第三部）對 BGP 環境特別重要。

2. LoadBalancer IPAM（LB IPAM）

地端 K8s cluster 通常沒有雲端 LB，Service.type=LoadBalancer 會卡在 <pending>。Cilium LB IPAM 解這個問題：給 pool，自動配發 VIP，再用 BGP 或 L2 announcement 對外曝光。

yaml
# 建立一個 LB IP pool
apiVersion: "cilium.io/v2alpha1"
kind: CiliumLoadBalancerIPPool
metadata:
  name: "production"
spec:
  blocks:
    - cidr: "192.168.100.0/24"   # 一段可路由 IP
  serviceSelector:
    matchLabels:
      env: production              # 只給 prod Service 用
yaml
# Service 加 label 觸發
apiVersion: v1
kind: Service
metadata:
  name: my-app
  labels:
    env: production
    bgp-announce: "true"           # 同時讓 §1 的 BGP advertisement 宣告
spec:
  type: LoadBalancer
  selector:
    app: my-app
  ports:
    - port: 80
bash
# 觀察分配狀態
kubectl get svc my-app
# 預期: EXTERNAL-IP 變成 192.168.100.5

# 看 IP Pool 用量
kubectl get ciliumloadbalancerippool production -o yaml
# 看 status.conditions 與 status.unused

進階：

  • spec.allowFirstLastIPs: "Yes" 允許用 .0 / .255
  • 多個 pool 可同時存在，selector 決定誰拿哪段
  • Service 可加 annotation lbipam.cilium.io/ips 指定要哪個 IP
  • Service 加 lbipam.cilium.io/sharing-key 多 Service 共用同一 IP（不同 port）

3. ClusterMesh（多叢集網路）

3.1 概念

ClusterMesh 把多個獨立 K8s cluster串成一張網。目的：

  • 跨地災備：主備 cluster 互通，DR failover 不需要 reconfigure
  • 跨地服務：使用者就近連最近 region 的後端
  • 分階段遷移：新舊 cluster 並存，逐步搬服務
  • 環境隔離但能互通：production / staging 不同 cluster，但少數共用服務（觀察、log）能直連

每個 cluster 跑一個 clustermesh-apiserver（背後是 etcd），對外透過 LoadBalancer Service 暴露。兩 cluster 互相連對方的 apiserver，同步 identity、endpoint、Service 資訊。Pod 之間用直接 IP 通訊（沒有 NAT 或 proxy）。

3.2 前置需求（硬條件）

  • 所有 cluster 同樣的 datapath mode（都 tunnel 或都 native）
  • Pod CIDR 不能重疊（每個 cluster 用獨立段）
  • 每 cluster 有唯一 cluster.id (1–255) 與 cluster.name
  • 所有 cluster 的 node 之間有 IP 連通（通常是 VPN 或 VPC peering）
  • 跨 cluster 互相允許 datapath port（VXLAN 8472、Geneve 6081、TCP 2379 給 etcd）

3.4 Global Services（跨 cluster 服務）

給一個 Service 加 annotation，它的 endpoints 會自動包含所有 cluster 同名 Service 的 backends：

yaml
# 兩 cluster 都建這個 Service（同名同 namespace）
apiVersion: v1
kind: Service
metadata:
  name: rebel-base
  namespace: default
  annotations:
    service.cilium.io/global: "true"   # 關鍵 annotation
spec:
  type: ClusterIP
  selector:
    app: rebel-base
  ports:
    - port: 80

實際 demo：

bash
# cluster 1: 部署 backend pod

apiVersion: apps/v1
kind: Deployment

3.5 跨叢集 Network Policy（1.19 重大變更）

⚠ 1.19 預設行為大變

1.19 起，Network Policy 的 selector 若未明確指定 cluster，預設只允許 local cluster 的 endpoint。從 1.18 升級時請務必檢查既有 policy。

1.19 新 policy 寫法（明確指定 cluster）：

yaml
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: allow-from-c1-and-c2
spec:
  endpointSelector:
    matchLabels:
      app: backend
  ingress:
    - fromEndpoints:
        - matchLabels:
            app: frontend
            io.cilium.k8s.policy.cluster: c1     # 明確指定來自 c1
        - matchLabels:
            app: frontend
            io.cilium.k8s.policy.cluster: c2     # 與 c2

檢查目前 policy 哪些會受影響：

bash
cilium clustermesh inspect-policy-default-local-cluster --all-namespaces

3.6 Service Affinity（流量偏好）

Global service 預設 round-robin 跨 cluster。某些場景你想優先用 local cluster，遠端只當 backup：

yaml
apiVersion: v1
kind: Service
metadata:
  name: rebel-base
  annotations:
    service.cilium.io/global: "true"
    service.cilium.io/affinity: "local"   # local / remote / none
    # local: 優先 local，全 fail 才用 remote
    # remote: 優先 remote
    # none: 不偏好

4. Egress Gateway

4.1 用途

場景：你的 cluster 要連舊有的外部 firewall 後系統（資料庫、ERP、SaaS），firewall 只放行特定 IP。但 K8s pod IP 是動態的，每個 node 出去的 src IP 也不同。Egress Gateway 解這問題：

  • 離開 cluster 時 SNAT 成 gateway node 上預先準備的 IP（如 10.1.2.50）
  • External firewall 只認得這個 IP 即可

4.2 啟用與 Policy

bash
# 必要前提
helm upgrade cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --reuse-values \
  --set egressGateway.enabled=true \
  --set bpf.masquerade=true \
  --set kubeProxyReplacement=true

kubectl -n kube-system rollout restart ds/cilium
kubectl -n kube-system rollout restart deploy/cilium-operator

# 把要當 gateway 的 node 加 label
kubectl label node node-gw egress-gateway="true"

# 在 node-gw 上手動建 egress IP（你的網管要先在 router/firewall 配對應 ARP/路由）
# 例如 node-gw 主 eth0 IP 是 10.1.2.10，要額外掛 10.1.2.50:
# ip addr add 10.1.2.50/24 dev eth0
yaml
apiVersion: cilium.io/v2
kind: CiliumEgressGatewayPolicy
metadata:
  name: billing-egress
spec:
  # 哪些 pod 要被導
  selectors:
    - podSelector:
        matchLabels:
          app: billing
          io.kubernetes.pod.namespace: production

  # 哪些目的 CIDR 要走 gateway
  destinationCIDRs:
    - "203.0.113.10/32"      # 只對特定外部系統
    - "203.0.113.20/32"

  # 排除（如 cluster 內部、雲端 metadata）
  excludedCIDRs:
    - "10.0.0.0/8"

  # Gateway 設定
  egressGateway:
    nodeSelector:
      matchLabels:
        egress-gateway: "true"   # 配對前面 label
    interface: eth0               # gateway node 上的出向介面
    egressIP: "10.1.2.50"        # SNAT 後的 src IP
bash
# 驗證 policy 套用
kubectl get ciliumegressgatewaypolicy
kubectl describe ciliumegressgatewaypolicy billing-egress

# 從 billing pod 連出去
kubectl exec -n production deploy/billing -- curl -s ifconfig.me
# 預期: 10.1.2.50（或對應的 public IP）

4.3 故障排除與限制

⚠ 已知限制
  • 不相容 ClusterMesh（gateway 必須與 pod 同 cluster）
  • 不相容 CiliumEndpointSlice（issue #24833）
  • 不相容 identityAllocationMode: kvstore，必須用 crd（預設）
  • Pod 剛啟動時有短暫延遲政策才套用，期間流量可能仍從 node IP 出去

典型問題：

  • egressIP 沒手動掛到 gateway node interface → ARP 不通
  • excludedCIDRs 忘了排除 cluster 內 IP → 內部 service 變慢
  • 多個 policy 衝突 → 優先級看 policy 寫的 IP 範圍細緻度
  • Gateway node down → 流量斷（多 gateway HA 在 1.18+ 開始支援 nodeSelector 多 node）

5. L2 Announcements Beta

沒有 BGP fabric 的辦公室、家用、edge 環境，又想要 LoadBalancer Service 對外曝光？L2 Announcements 用 ARP（IPv4）/ NDP（IPv6）讓 Service VIP 在 LAN 上「以為自己是某 node 的 IP」：

  • 對外宣告 ExternalIP 或 LoadBalancer VIP
  • 每 service 一個 VIP，避開 NodePort 共用 port 的麻煩
  • 選一個 node 當 leader 回應 ARP，node 掛了自動切到下一個

啟用

bash
helm upgrade cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --reuse-values \
  --set l2announcements.enabled=true \
  --set kubeProxyReplacement=true \
  --set externalIPs.enabled=true \
  --set devices='{eth0}'        # 在哪些介面廣播
yaml
apiVersion: "cilium.io/v2alpha1"
kind: CiliumL2AnnouncementPolicy
metadata:
  name: policy1
spec:
  serviceSelector:
    matchLabels:
      color: blue           # 哪些 service 要被宣告
  nodeSelector:
    matchExpressions:
      - { key: node-role.kubernetes.io/control-plane, operator: DoesNotExist }
  interfaces:
    - eth0                  # 從哪些介面回 ARP
  externalIPs: true
  loadBalancerIPs: true

搭配 §2 的 LB IPAM，從一個 pool 拿 VIP：

yaml
apiVersion: "cilium.io/v2alpha1"
kind: CiliumLoadBalancerIPPool
metadata:
  name: lan-pool
spec:
  blocks:
    - cidr: "192.168.1.240/29"   # LAN 內保留段，避開 DHCP 範圍
  serviceSelector:
    matchLabels:
      color: blue

限制

  • 不做負載平衡：每個 VIP 只有一個 node 在回 ARP，所有流量先進那個 node，再由 cluster 內 BPF LB 分到 backend
  • 不相容 externalTrafficPolicy: Local
  • VIP 必須在 LAN 同一個 L2 域才能被廣播
  • 大量 service 同時切 leader 時可能小卡頓

L2 Pod Announcements

1.18+ 還有 L2 Pod Announcements：讓每個 Pod 的 IP 也用 ARP 宣告，讓 LAN 上的設備能直接連 Pod。少用，但在 IoT、邊緣場景有需求。

6. Node IPAM LB

單機 / 微型環境（一台或兩台 node），上面沒人想搞 BGP 或 L2 announcement，但又要 type: LoadBalancer 能用。Node IPAM LB 直接用 node 自己的 IP 當 LoadBalancer IP，超簡單：

bash
helm upgrade cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --reuse-values \
  --set nodeIPAM.enabled=true
yaml
# Service 標 loadBalancerClass: io.cilium/node
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  type: LoadBalancer
  loadBalancerClass: io.cilium/node      # 關鍵
  selector:
    app: my-app
  ports:
    - port: 80

Cilium 會把 EXTERNAL-IP 設為其中一個 node 的 IP，外部訪問該 IP 就能到 service。適合 K3s / homelab 等場景。

7. VXLAN Tunnel Endpoint (VTEP) 整合 Beta

有些既有環境已經有 外部 VXLAN tunnel endpoint（如 VMware NSX、傳統交換機），要讓 K8s pod 與 VM/裸機在同一個 VXLAN overlay 通訊。Cilium VTEP 整合讓 Cilium 學到外部 VTEP 的存在，並把流量正確封裝過去。

配置概覽：

yaml
vtep:
  enabled: true
  endpoint: "192.168.1.100"      # 外部 VTEP IP
  cidr: "10.50.0.0/16"           # 該 VTEP 後面的網段
  mask: "255.255.0.0"
  mac: "aa:bb:cc:dd:ee:ff"       # VTEP 的 MAC

主要限制：只支援 IPv4、需要與 cluster 同 VNI、配置變更要 restart agent。詳情見官方 VTEP 頁面。

8. Multicast 支援 Beta

大多數 cloud-native 應用不用 multicast，但某些金融/電信協定（PIM、IGMP，部分 service discovery 機制）仍依賴。1.16+ 起 Cilium 提供 IPv4 multicast 支援（Beta）。

啟用與設定

bash
helm upgrade cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --reuse-values \
  --set multicast.enabled=true
bash
# 建立 multicast group
cilium-dbg multicast group add 239.1.1.1

# 加 subscriber（Pod IP）
cilium-dbg multicast subscriber add 239.1.1.1 10.10.0.5

# 看狀態
cilium-dbg multicast group list
cilium-dbg multicast subscriber list 239.1.1.1

1.19 為 L2 Announcements 增加了 IGMP/VRRP 協定的 host firewall match 支援，這對 multicast / HA 環境很有用。

限制

  • 只支援 IPv4（IPv6 multicast 還沒）
  • 不支援 ClusterMesh 跨 cluster multicast
  • 需要 underlay 支援 IGMP snooping，否則效率差

9. 為 Pod 指定 MAC 位址

某些遺留系統（軟體 license 綁 MAC、特定 hardware 偵測）要求 Pod 有可預測或固定的 MAC。Cilium 支援 pod annotation 指定：

yaml
apiVersion: v1
kind: Pod
metadata:
  name: license-app
  annotations:
    cilium.io/mac-address: "02:42:ac:11:00:05"
spec:
  containers:
  - name: app
    image: my-licensed-app

注意：MAC 必須符合locally administered位元（第二個 hex 數字是 2/6/A/E），避免跟全球唯一 MAC 撞。

10. 本章重點回顧

  • BGP Control Plane 用四個 CRD 管理：ClusterConfig（主入口）+ PeerConfig（可重用）+ Advertisement（宣告什麼）+ NodeConfig（自動產生）。記得開 gracefulRestart。
  • LB IPAM 給 LoadBalancer Service 分配 VIP；搭配 BGP 或 L2 announcement 對外曝光。
  • ClusterMesh 三個必填：唯一 cluster.name、唯一 cluster.id、不重疊 Pod CIDR。Service 加 service.cilium.io/global: "true" 就跨 cluster。
  • 1.19 重大變更：ClusterMesh + Network Policy selector 預設只允許 local cluster，升級前用 cilium clustermesh inspect-policy-default-local-cluster 檢查。
  • Egress Gateway 解「外部 firewall 只認固定 IP」問題；不相容 ClusterMesh、CiliumEndpointSlice、kvstore identity mode。
  • L2 Announcements 無 BGP 環境的 LoadBalancer 解法，用 ARP/NDP；不做負載平衡，VIP 只綁 leader node。
  • Node IPAM LB 是最簡單的 LoadBalancer：直接用 node IP，homelab / K3s 場景常用。
  • VTEP、Multicast、Pod MAC 是特殊場景功能，多半 Beta，先確認需求再開。
