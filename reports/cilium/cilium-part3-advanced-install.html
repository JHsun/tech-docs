進階安裝

第二部用 cilium install 一鍵裝完是給學習用的；生產環境通常用 Helm + 版控的 values.yaml。本章涵蓋 Helm 完整流程、CNI 遷移、各 K8s 發行版差異、三大雲端託管整合、CNI chaining，是 DevOps/SRE 上線前必讀。

對應官方文件：Advanced Installation 全章 Cilium 版本：1.19.x 主要對象：DevOps / SRE

1. 安裝路徑選擇

Cilium 提供四條主要安裝路徑，差別在「自動化程度」與「客製彈性」。挑路徑前先回答兩個問題：

2. Node Taints & Unmanaged Pods

這節雖然看似冷門，但生產環境每次安裝都會踩，先看完省得後面 debug。

2.1 為什麼需要 taint

場景：你的 K8s cluster 已經跑了一段時間，node 上有 Pod 在 host network mode（如 kube-proxy、DNS）。你裝 Cilium 上去，cilium-agent 需要時間啟動並把 BPF 寫到 kernel。在這個短暫的「沒網路」期間，新建立的 Pod 會：

  • 拿不到 IP，因為 CNI 還沒就緒
  • 就算拿到 IP，網路也是斷的（沒 datapath）
  • 變成「unmanaged pod」，後面就算 Cilium 起來了，也不會自動接管

解法：在建立 cluster 時，給 node 加 taint node.cilium.io/agent-not-ready=true:NoExecute。意義是「Cilium agent 沒 ready 前，禁止排程任何 Pod 到這個 node」。Cilium agent 起來後會自己移除 taint。

⚠ kind / minikube 不需要這個 taint

本地 lab 用 cilium install 都不會踩這坑，因為 cluster 是空的。只有雲端託管 K8s 與生產自建環境需要。

2.2 雲端託管的 taint 設定

bash
# GKE
gcloud container clusters create my-cluster \
  --node-taints node.cilium.io/agent-not-ready=true:NoExecute \
  --zone us-west2-a

# EKS (eksctl ClusterConfig)
managedNodeGroups:
  - name: ng-1
    taints:
      - key: "node.cilium.io/agent-not-ready"
        value: "true"
        effect: "NoExecute"

# AKS - 透過 az 建 node pool
az aks nodepool add \
  --cluster-name my-cluster \
  --resource-group my-rg \
  --name nodepool1 \
  --node-taints node.cilium.io/agent-not-ready=true:NoExecute

2.3 已存在叢集：手動 restart unmanaged pods

如果 cluster 已經跑著，沒辦法重建來加 taint，安裝完 Cilium 後請手動重啟所有非 host network的 Pod：

bash
# 找出非 hostNetwork 且不在 kube-system 的 pod，逐一刪除（會自動重建）
kubectl get pods --all-namespaces -o wide \
  --field-selector spec.nodeName!=,status.phase=Running \
  -o json | jq -r '.items[] |
    select(.spec.hostNetwork != true) |
    "\(.metadata.namespace)/\(.metadata.name)"' \
  | while read pod; do
      NS=${pod%/*}
      NAME=${pod#*/}
      kubectl delete pod -n "$NS" "$NAME"
      sleep 1
    done

# 或者只重啟特定 namespace
kubectl rollout restart deployment -n my-app

3. Helm 安裝詳解

3.1 OCI vs Traditional Repository

Cilium 1.15 起官方 Helm chart 同時發佈到兩處：

方式URL適合場景
OCI Registry（推薦） oci://quay.io/cilium/charts/cilium 新部署、CI/CD、GitOps；不用 helm repo add
Traditional https://helm.cilium.io/ 舊有自動化、習慣 helm repo search

兩者 chart 內容完全一樣，只是分發協定不同。本章後續範例都用 OCI。

💡 OCI 版號注意

Helm chart 版號是 SemVer 2.0，不帶 v 前綴（例如 1.19.3）；container image tag 帶 v（例如 v1.19.3）。Helm 指令用前者。

3.2 完整 values.yaml 範例

下面是一份「生產可用、合理預設」的 values 範例，kube-proxy 完全替換 + Hubble 全套 + IPv4 only + tunnel 模式。對應檔案命名 cilium-values.yaml：

yaml
# cilium-values.yaml
# 此檔案應入版控（Git），任何配置變更走 PR review

# ===== 基本 =====
cluster:
  name: my-prod-cluster      # 多叢集環境必填，每叢集唯一
  id: 1                      # 1-255，多叢集環境必填，每叢集唯一

# ===== Datapath =====
kubeProxyReplacement: true              # 取代 kube-proxy（推薦）
k8sServiceHost: "10.0.0.10"             # K8s API server VIP（kubeProxyReplacement=true 必填）
k8sServicePort: 6443

routingMode: tunnel                     # tunnel / native
tunnelProtocol: vxlan                   # vxlan / geneve

# ===== IPAM =====
ipam:
  mode: cluster-pool                    # 預設；其他選項：kubernetes / multi-pool / eni / azure
  operator:
    clusterPoolIPv4PodCIDRList:
      - "10.244.0.0/16"
    clusterPoolIPv4MaskSize: 24         # 每 node 分到的 /24

# ===== IPv4/IPv6 =====
ipv4:
  enabled: true
ipv6:
  enabled: false

# ===== Hubble =====
hubble:
  enabled: true
  relay:
    enabled: true
    replicas: 2
  ui:
    enabled: true
  metrics:
    enabled:
      - dns:query;ignoreAAAA
      - drop
      - tcp
      - flow
      - port-distribution
      - icmp
      - http
    serviceMonitor:
      enabled: true                     # 已裝 Prometheus Operator 才能開
  tls:
    auto:
      enabled: true                     # 自動產 mTLS 憑證
      method: helm

# ===== Operator =====
operator:
  replicas: 2                           # 生產 ≥ 2
  rollOutPods: true                     # 改 ConfigMap 自動 rollout

# ===== Encryption (選用) =====
encryption:
  enabled: false                        # 啟用前先讀第六部
  type: wireguard                       # wireguard / ipsec

# ===== Prometheus =====
prometheus:
  enabled: true
  serviceMonitor:
    enabled: true

# ===== 升級相容性（重要） =====
# 第一次安裝填 Cilium 版號；之後升級才需要動
upgradeCompatibility: "1.19"

# ===== Resources =====
resources:
  limits:
    memory: "4Gi"
  requests:
    cpu: "100m"
    memory: "512Mi"
⚠ upgradeCompatibility 不要省略

這個 value 標記「叢集最早從哪個版本開始裝」，影響 BPF map 預設大小與某些行為的相容性。第一次安裝就要寫，未來升級才能依此判斷。

3.3 安裝實作

bash
# 1. 建 namespace（如果不用 kube-system）
kubectl create namespace cilium-system

# 2. 安裝
helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --values cilium-values.yaml

# 3. 等 ready
cilium status --wait

# 4. 完整驗證
cilium connectivity test

更新 values（不換 chart 版本）：

bash
# 改 values.yaml 後
helm upgrade cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --values cilium-values.yaml \
  --reuse-values=false                  # 完整覆蓋（建議）

# 確認 ConfigMap 變更已被 agent 套用
kubectl -n kube-system rollout restart ds/cilium

3.4 升級 minor version（pre-flight check 必跑）

從 1.18 → 1.19 這類 minor 升級必須先跑 pre-flight。它的工作：

  • 把新版 image pre-pull 到每個 node（避免升級時下載卡住）
  • 驗證現有 CRD 與資源能被新版解析
  • 檢查 BPF map 大小是否需要調整
bash
# Step 1: 跑 pre-flight（會建立 cilium-pre-flight-check DaemonSet）
helm install cilium-preflight oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --set preflight.enabled=true \
  --set agent=false \
  --set operator.enabled=false

# Step 2: 等所有 node 的 pre-flight 完成
kubectl get ds cilium-pre-flight-check -n kube-system
# 預期 DESIRED == READY == NODES 數量

# Step 3: 把 CNP（CiliumNetworkPolicy）格式驗證跑完
kubectl get ciliumpreflightconfigs -o yaml
# 預期 status.cnpStatus 全部 OK

# Step 4: 移除 pre-flight
helm uninstall cilium-preflight -n kube-system

# Step 5: 真正升級
# 先匯出舊版 values
helm get values cilium -n kube-system -o yaml > old-values.yaml
# 檢查 old-values.yaml 有沒有被 deprecated 的欄位（看 Release Notes）

# 升級（重要：minor 升級不要用 --reuse-values）
helm upgrade cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  -f old-values.yaml \
  --set upgradeCompatibility=1.18       # 從哪一版升上來
⚠ 1.18 → 1.19 重點：policyDefaultLocalCluster

1.19 預設 policyDefaultLocalCluster=true，ClusterMesh 環境的 Network Policy selector 若未指定 cluster，只允許 local cluster。升級前用以下指令找出受影響 policy：

cilium clustermesh inspect-policy-default-local-cluster --all-namespaces

3.5 chart 簽章驗證

Cilium chart 用 cosign 簽章，CI/CD pipeline 建議驗證後再 install：

bash
# 安裝 cosign
go install github.com/sigstore/cosign/v2/cmd/cosign@latest

# 驗證 chart 簽章
cosign verify \
  --certificate-identity-regexp='https://github.com/cilium/cilium/.*' \
  --certificate-oidc-issuer=https://token.actions.githubusercontent.com \
  quay.io/cilium/charts/cilium:1.19.3

# 用 digest pinning（最高安全性）
helm pull oci://quay.io/cilium/charts/cilium --version 1.19.3
# 取得 sha256 digest 後
helm install cilium oci://quay.io/cilium/charts/cilium@sha256:abc123... \
  --namespace kube-system

5. 從其他 CNI 遷移

5.1 概念：為什麼能 zero-downtime

傳統的 CNI 換裝是「重建 cluster + 復原工作負載」。Cilium 從 1.13 起官方支援 live migration，原理是：

  • 讓 Cilium 與舊 CNI 用不同的 Pod CIDR，Linux routing 就能自動分流
  • 用不同的 encapsulation port（如 Geneve 6081）避免衝突
  • 逐 node 遷移：cordon → drain → 切 CNI → 啟用 Cilium → uncordon
  • 整個遷移期間 Cilium 的 NetworkPolicy enforcement 先關閉（避免擋到舊 CNI 的 Pod）

5.2 前置需求與限制

  • 不同 Pod CIDR：Cilium 跟舊 CNI 不能重疊
  • 不同封裝：兩邊都用 VXLAN 會撞 port 4789，建議 Cilium 改 Geneve
  • 暫關 NetworkPolicy enforcement：policyEnforcementMode=never
  • 不支援切 IP family：v4 → v6 不能藉這次遷移完成
  • 同步移除舊 CNI：遷移後務必清掉 /etc/cni/net.d/ 舊 CNI conf

5.3 Lab：Flannel → Cilium

用 kind 模擬完整遷移。先建一個跑 Flannel 的 cluster：

bash
# 1. 建空 cluster
cat <<EOF > kind-migration.yaml
apiVersion: kind.x-k8s.io/v1alpha4
kind: Cluster
name: migration-lab
nodes:
  - role: control-plane
  - role: worker
  - role: worker
networking:
  disableDefaultCNI: true
EOF
kind create cluster --config kind-migration.yaml

# 2. 裝必要 CNI plugins binary
kubectl apply -n kube-system --server-side \
  -f https://raw.githubusercontent.com/cilium/cilium/1.19.3/examples/misc/migration/install-reference-cni-plugins.yaml

# 3. 裝 Flannel
kubectl apply --server-side \
  -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

kubectl wait --for=condition=Ready nodes --all --timeout=120s

# 4. 部署測試 app（裡面跑 ping 互測 pod 連線）
kubectl create deploy testapp --image=nicolaka/netshoot \
  --replicas=3 -- sleep infinity

現在 cluster 用 Flannel，Pod CIDR 是 10.244.0.0/16。開始遷移：

bash
# Step 1: 用 Helm 安裝 Cilium，但設為「不 attach 到 host CNI」
cat <<EOF > cilium-migration-values.yaml
operator:
  unmanagedPodWatcher:
    restart: false       # 別重啟舊 CNI 管的 Pod
routingMode: tunnel
tunnelProtocol: geneve   # 用 Geneve 避免跟 Flannel VXLAN 撞
tunnelPort: 6081

# 用不同的 Pod CIDR
ipam:
  mode: cluster-pool
  operator:
    clusterPoolIPv4PodCIDRList:
      - "10.245.0.0/16"

# 暫關 policy enforcement
policyEnforcement: never

# 不 install CNI conf，避免立刻搶 CNI
cni:
  customConf: true
  uninstall: false

# 不取代 kube-proxy（避免遷移過程斷服務）
kubeProxyReplacement: false
EOF

helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  -f cilium-migration-values.yaml

cilium status --wait

# Step 2: 寫 CiliumNodeConfig 標記哪些 node 該接管
# 這個物件控制特定 label 的 node 啟用完整 Cilium CNI

cat <<EOF | kubectl apply -f -
apiVersion: cilium.io/v2
kind: CiliumNodeConfig
metadata:
  name: cilium-migration
  namespace: kube-system
spec:
  nodeSelector:
    matchLabels:
      io.cilium.migration/cilium-default: "true"
  defaults:
    write-cni-conf-when-ready: /host/etc/cni/net.d/05-cilium.conflist
    custom-cni-conf: "false"
    cni-exclusive: "true"
EOF

# Step 3: 對第一個 node 開始遷移
NODE="migration-lab-worker"

# 3a. 加 migration label，觸發 CiliumNodeConfig
kubectl label node $NODE io.cilium.migration/cilium-default=true

# 3b. cordon + drain（讓工作負載搬走）
kubectl cordon $NODE
kubectl drain $NODE --ignore-daemonsets --delete-emptydir-data --force

# 3c. 在 node 內手動移除舊 CNI conf（也可以做進 DaemonSet）
docker exec $NODE rm -f /etc/cni/net.d/10-flannel.conflist

# 3d. 重啟 cilium-agent on this node
kubectl -n kube-system delete pod -l app.kubernetes.io/name=cilium-agent \
  --field-selector spec.nodeName=$NODE

# 3e. 確認 cilium-agent 重新啟動完成
sleep 10
kubectl -n kube-system get pods -l app.kubernetes.io/name=cilium-agent \
  --field-selector spec.nodeName=$NODE

# 3f. uncordon
kubectl uncordon $NODE

# 3g. 驗證：新建一個 pod 確認用 Cilium IP（10.245.x.x）
kubectl run test-migrated --image=nicolaka/netshoot \
  --overrides='{"spec":{"nodeName":"'$NODE'"}}' \
  --rm -it -- ip a

# Step 4: 重複 Step 3 對其他 node
NODE="migration-lab-worker2"
kubectl label node $NODE io.cilium.migration/cilium-default=true
kubectl cordon $NODE
kubectl drain $NODE --ignore-daemonsets --delete-emptydir-data --force
docker exec $NODE rm -f /etc/cni/net.d/10-flannel.conflist
kubectl -n kube-system delete pod -l app.kubernetes.io/name=cilium-agent \
  --field-selector spec.nodeName=$NODE
sleep 10
kubectl uncordon $NODE

# Control plane 也要遷
NODE="migration-lab-control-plane"
kubectl label node $NODE io.cilium.migration/cilium-default=true
# ... 同樣流程

全部 node 遷完後，做最後切換：

bash
# Step 5: 移除 Flannel
kubectl delete -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

# Step 6: 把 Cilium 切回「完整模式」
cat <<EOF > cilium-final-values.yaml
# 跟原本一樣，但移除 migration 相關
operator:
  unmanagedPodWatcher:
    restart: true
routingMode: tunnel
tunnelProtocol: vxlan        # 可以切回 vxlan
ipam:
  mode: cluster-pool
  operator:
    clusterPoolIPv4PodCIDRList:
      - "10.245.0.0/16"

# 啟用完整功能
policyEnforcement: default
kubeProxyReplacement: true
k8sServiceHost: "..."        # 改成真實 API server
k8sServicePort: 6443

cni:
  customConf: false
  exclusive: true
EOF

helm upgrade cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  -f cilium-final-values.yaml

# 重啟 agent 套用
kubectl -n kube-system rollout restart ds/cilium

# 最終驗證
cilium status --wait
cilium connectivity test
✓ 生產實踐建議
  • 務必先在 staging 用相同流程演練
  • 遷移過程持續跑 connectivity monitor（如 goldpinger）
  • 每 node 完成後等 10–30 分鐘確認應用穩定，再動下一個
  • 準備 rollback：保留舊 CNI manifest，必要時可重新部署回去
  • policy enforcement 在全部完成前不要打開，避免誤擋舊 CNI 流量

6. K8s 發行版安裝

6.1 kubeadm

kubeadm 是最常見的自建 K8s 安裝方式。建 cluster 時要關閉預設 CNI 與 kube-proxy：

bash
# 在第一個 control-plane 節點
cat <<EOF > kubeadm-config.yaml
apiVersion: kubeadm.k8s.io/v1beta4
kind: ClusterConfiguration
kubernetesVersion: v1.31.0
networking:
  podSubnet: "10.244.0.0/16"
  serviceSubnet: "10.96.0.0/12"
---
apiVersion: kubeadm.k8s.io/v1beta4
kind: InitConfiguration
nodeRegistration:
  taints:
    # Cilium agent 起來前禁排程
    - key: "node.cilium.io/agent-not-ready"
      value: "true"
      effect: "NoExecute"
---
apiVersion: kubeproxy.config.k8s.io/v1alpha1
kind: KubeProxyConfiguration
# 完全跳過 kube-proxy 安裝
EOF

# init 時跳過 kube-proxy phase
sudo kubeadm init --config kubeadm-config.yaml --skip-phases=addon/kube-proxy

# 之後裝 Cilium（用 Helm）
helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --set kubeProxyReplacement=true \
  --set k8sServiceHost=$(hostname -i) \
  --set k8sServicePort=6443

6.2 K3s

K3s 預設自帶 Flannel 與 ServiceLB，要先關掉：

bash
# Server node
curl -sfL https://get.k3s.io | sh -s - \
  --flannel-backend=none \
  --disable-network-policy \
  --disable=traefik \
  --disable=servicelb \
  --disable-kube-proxy \
  --cluster-cidr=10.42.0.0/16

# Worker node
K3S_URL=https://<server-ip>:6443 \
K3S_TOKEN=<token> \
  curl -sfL https://get.k3s.io | sh -

# 設定 kubeconfig
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
chmod 644 /etc/rancher/k3s/k3s.yaml

# 裝 Cilium，pool CIDR 對齊 K3s 預設
cilium install --version 1.19.3 \
  --set kubeProxyReplacement=true \
  --set ipam.operator.clusterPoolIPv4PodCIDRList="10.42.0.0/16" \
  --set k8sServiceHost=$(hostname -i) \
  --set k8sServicePort=6443

6.3 k0s

k0s 用 k0sctl 部署，要在 k0sctl.yaml 設定不用內建 CNI：

yaml
apiVersion: k0sctl.k0sproject.io/v1beta1
kind: Cluster
spec:
  hosts:
    - ssh: { address: 10.0.0.1 }
      role: controller
    - ssh: { address: 10.0.0.2 }
      role: worker
  k0s:
    version: 1.31.0+k0s.0
    config:
      spec:
        network:
          provider: custom        # 關鍵：不裝內建 CNI
          podCIDR: 10.244.0.0/16
        api:
          extraArgs:
            anonymous-auth: "false"
bash
k0sctl apply --config k0sctl.yaml
k0sctl kubeconfig > ~/.kube/config

# 裝 Cilium
cilium install --version 1.19.3 --set kubeProxyReplacement=true

6.4 OpenShift OKD

OKD 用 Operator 模式，Cilium 提供官方 OperatorHub 安裝。重點：

  • OKD 預設 SCC 限制嚴格，Cilium 需要 privileged SCC
  • 不能裸用 cilium install，要用 OpenShift Helm 整合或 OLM
  • cluster install 時 --network-type=Cilium
bash
# 用 helm（要先給 SCC）
oc adm policy add-scc-to-user privileged -z cilium -n kube-system
oc adm policy add-scc-to-user privileged -z cilium-operator -n kube-system

helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --set cni.binPath=/var/lib/cni/bin \
  --set cni.confPath=/var/run/multus/cni/net.d \
  --set bgp.announce.loadbalancerIP=true \
  --set securityContext.privileged=true

6.5 Rancher / RKE

Rancher 提供 GUI 安裝；RKE / RKE2 安裝 Cilium 的關鍵是 cni binary path：

bash
# RKE2：cni binary 在 /opt/cni/bin（標準）
# 在 RKE2 config 設定使用 none CNI

# /etc/rancher/rke2/config.yaml
cni: "none"
disable-kube-proxy: true
cluster-cidr: "10.42.0.0/16"
service-cidr: "10.43.0.0/16"

systemctl restart rke2-server

# 裝 Cilium（取 K8s API IP）
helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --set kubeProxyReplacement=true \
  --set k8sServiceHost=<node-ip> \
  --set k8sServicePort=6443

6.6 VMware ESXi / NSX (Broadcom)

NSX 環境下 Cilium 跑得起來，但要注意：

  • VMware 的 LoadBalancer / NSX-T 與 Cilium LB IPAM 二選一
  • Multi-NIC VM 要設定 devices 明確指定接哪一張
  • 關閉 net.ipv4.tcp_l3mdev_accept 等可能干擾的核心參數

7. 雲端託管整合

7.1 AKS

Azure 提供兩種使用 Cilium 的方式：

方式說明適用
Azure CNI Powered by Cilium AKS 內建管理，自動升級，但功能受 AKS 限制 想要 managed、不需要 L7 policy / Hubble UI
BYOCNI（Bring Your Own CNI） 自己用 Helm 裝完整 OSS Cilium 需要完整功能（L7 policy、Hubble、ClusterMesh）

BYOCNI 流程

bash
export NAME="cilium-aks-$RANDOM"
export RG="${NAME}-rg"
az group create --name $RG -l westus2

# 關鍵：--network-plugin none
az aks create \
  --resource-group $RG \
  --name $NAME \
  --network-plugin none \
  --generate-ssh-keys

az aks get-credentials --resource-group $RG --name $NAME

# 注意 Pod CIDR 不要跟 Service CIDR 撞
helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --set aksbyocni.enabled=true \
  --set nodeinit.enabled=true

7.3 GKE

GKE 有原生 Cilium 整合叫 Dataplane V2，但功能落後 OSS Cilium 至少一個 minor version。要自裝完整版：

bash
export NAME="cilium-gke-$RANDOM"

# 注意：不啟用 Dataplane V2，否則會跟自裝 Cilium 衝突
gcloud container clusters create $NAME \
  --zone us-west2-a \
  --node-taints node.cilium.io/agent-not-ready=true:NoExecute \
  --num-nodes=3

gcloud container clusters get-credentials $NAME --zone us-west2-a

# 取得 K8s API 內部 IP
API_HOST=$(kubectl get endpoints kubernetes -o jsonpath='{.subsets[0].addresses[0].ip}')

helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.19.3 \
  --namespace kube-system \
  --set nodeinit.enabled=true \
  --set nodeinit.reconfigureKubelet=true \
  --set nodeinit.removeCbrBridge=true \
  --set cni.binPath=/home/kubernetes/bin \
  --set gke.enabled=true \
  --set ipam.mode=kubernetes \
  --set kubeProxyReplacement=true \
  --set k8sServiceHost=$API_HOST \
  --set k8sServicePort=443

9. CNI Chaining

有些場景你不能把舊 CNI 拿掉（例如 Calico 還有 BGP 在用，或 AWS VPC CNI 給 Pod 真實 VPC IP），但又想要 Cilium 的 policy / observability。CNI Chaining讓 Cilium 跟舊 CNI 並存：

  • 舊 CNI 負責：IPAM、路由、underlay 連通性
  • Cilium 負責：NetworkPolicy enforcement、L7 inspection、Hubble observability

支援的 chaining mode：

Mode用途
aws-vpc-cniEKS 場景，VPC CNI 給 IP，Cilium 做 policy / observability
azure-ipamAzure CNI 給 IP（已被 Azure CNI Powered by Cilium 取代）
generic-veth跟任何用 veth pair 的 CNI 串接（Calico、Flannel）
portmap只啟用 hostPort 支援

典型 generic-veth chaining values：

yaml
cni:
  chainingMode: generic-veth
  customConf: true
  configMap: cni-configuration

# 用一個 ConfigMap 餵 CNI conflist
extraConfig:
  cni-chaining-mode: generic-veth

# 關閉 Cilium 自己管理 routing / IPAM
enableIPv4Masquerade: false
endpointRoutes:
  enabled: false
l7Proxy: true                            # 留 L7 policy / Hubble
kubeProxyReplacement: false              # chaining 模式下不建議全替換

10. 本章重點回顧

  • 生產一律用 Helm，values.yaml 入版控，配置變更走 PR。
  • Helm chart 從 OCI registry（oci://quay.io/cilium/charts/cilium）安裝，搭配 cosign 簽章驗證。
  • 記得設 taint node.cilium.io/agent-not-ready=true:NoExecute，避免 unmanaged pod 問題。
  • 必填 values：cluster.name、cluster.id、kubeProxyReplacement、ipam.mode、upgradeCompatibility。
  • Minor 升級三件套：pre-flight check → 匯出舊 values 並檢查 deprecated → helm upgrade（不要用 --reuse-values）。
  • 從其他 CNI 遷移是支援的，關鍵：不同 Pod CIDR、不同 encapsulation port、暫關 policy enforcement、逐 node 進行。
  • 雲端託管：AKS BYOCNI、EKS（記得刪 aws-node）、GKE（避開 Dataplane V2）。
  • 不能拔舊 CNI 時，用 CNI Chaining 模式並存。
