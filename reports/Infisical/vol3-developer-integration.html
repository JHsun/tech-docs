容器內安裝範例 DevOps/SRE

最常見的需求：在自己的 Docker image 裡內建 CLI，給 entrypoint 用。Alpine + 鎖定版本：

# Dockerfile 片段
FROM node:20-alpine

# 鎖定 CLI 版本（請依實際 release 替換）
ARG INFISICAL_CLI_VERSION=v0.43.78

RUN apk add --no-cache bash sudo wget \
 && wget -qO- https://artifacts-cli.infisical.com/setup.apk.sh | sh \
 && apk update \
 && apk add infisical=${INFISICAL_CLI_VERSION#v}-r0 \
 && infisical --version

# entrypoint 用 CLI 注入 secret 後啟動 app
ENTRYPOINT ["infisical", "run", "--"]
CMD ["node", "server.js"]
Production 鎖版本的重要性

CI 與容器映像務必鎖 CLI 版本。Infisical CLI 演進很快，minor version 偶爾會調 default 行為（例如 --silent flag 的範圍）。沒鎖版本的話，某個半夜 release 出來，明天早上你的 pipeline 就壞了。

13.2　infisical login 多種登入模式

四種登入模式 開發者

CLI 區分「互動模式」（給人類用）與「非互動模式」（給 CI / 容器用）。

模式適用典型呼叫
瀏覽器登入本機開發infisical login
Email + 密碼無瀏覽器的 serverinfisical login --interactive 後選 email-password
Machine IdentityCI / 容器 / Podinfisical login --method=universal-auth ...
Self-Host domainSelf-Host 用戶多加 --domain=https://your.host

瀏覽器登入

# 預設指向 Cloud
infisical login

# Self-Host
infisical login --domain=https://infisical.acme.com

瀏覽器跳出授權頁，使用者按 Allow，CLI 收到 token 並寫入本機 keychain（macOS Keychain / Windows Credential Manager / Linux libsecret）。

Machine Identity 非互動登入

給 CI / 容器用，最常見是 Universal Auth：

# 寫入 INFISICAL_TOKEN 環境變數
export INFISICAL_TOKEN=$(infisical login \
  --method=universal-auth \
  --client-id=$INFISICAL_CLIENT_ID \
  --client-secret=$INFISICAL_CLIENT_SECRET \
  --silent --plain)

# 之後所有 infisical 子命令會優先讀 INFISICAL_TOKEN
infisical secrets

其他 Machine Identity 方法的 --method 對應名稱：

method 值必要參數
universal-auth--client-id、--client-secret
kubernetes--service-account-token-path、--identity-id
aws-iam--identity-id（自動從 EC2 metadata）
azure--identity-id
gcp-id-token / gcp-iam--identity-id
oidc-auth--identity-id、--jwt 或 --oidc-provider

登出與切換實例

# 切換目前 default domain
infisical user domain

# 列出已登入的所有 user / domain
infisical user

# 登出
infisical logout

13.3　infisical run 注入環境變數

核心使用模式 開發者

run 是 CLI 最常用的命令。把 secret fetch 後，注入成子行程的環境變數，然後執行你的應用程式。

# 基本：用 .infisical.json 的 default env
infisical run -- npm start

# 指定 environment
infisical run --env=production -- npm start
infisical run -e prod -- npm start

# 指定 path
infisical run --env=prod --path=/services/api -- node server.js

# 含子 folder 的 secret 也帶進來
infisical run --env=prod --recursive -- node server.js

# 不用 .infisical.json 檔，全部用 flag
infisical run \
  --projectId=$INFISICAL_PROJECT_ID \
  --env=production \
  --path=/services/api \
  --domain=$INFISICAL_DOMAIN \
  -- node server.js

watcher 模式：secret 變更自動重啟

# --watch：偵測 secret 變化時，重啟子行程
infisical run --env=dev --watch -- node dev-server.js

Watch 內部用 polling（預設 5 秒），適合本機開發。Production 環境不要用 watch——應該用 K8s Operator 或 Agent 接事件驅動的 reload。

環境變數的優先順序 DevOps/SRE

當系統 / shell 已存在某 env var，又從 Infisical 拉到同名值，誰勝出？預設規則：

  1. 原本系統的 env var（不被覆蓋，避免意外）
  2. Infisical 拉下來的值
  3. --env-file 指定的檔案

要強制 Infisical 覆蓋系統 env var，用 --override：

# 已有 NODE_ENV=development，要被 Infisical 設定的值蓋掉
infisical run --override -- node server.js

13.4　infisical secrets 增刪改查

讀取 開發者

# 列出當前 env 所有 secret
infisical secrets

# 取單一 secret 的明文（CI 用）
infisical secrets get DATABASE_URL --plain

# 在 script 裡用回傳值，順帶關掉 update 檢查與 tip 訊息
API_KEY=$(infisical secrets get API_KEY --plain --silent)

# 取多個（plain 模式各印一行）
infisical secrets get DATABASE_URL API_KEY JWT_SECRET --plain

寫入

# 單個 secret
infisical secrets set DATABASE_URL "postgres://..."

# 批次設定
infisical secrets set KEY1=val1 KEY2=val2 KEY3=val3

# 從檔案讀值（@ 前綴）
infisical secrets set CERTIFICATE=@/path/to/cert.pem

# 從 .env / YAML 批次匯入
infisical secrets set --file=.env

# 寫入特定 path
infisical secrets set DOMAIN=example.com --path=/services/api

# personal 類型（只屬於該使用者）
infisical secrets set DEBUG_TOKEN=xxx --type=personal

刪除

infisical secrets delete LEGACY_KEY OLD_TOKEN
infisical secrets delete DEPRECATED_API_KEY --path=/services/legacy

folder 操作

infisical secrets folders create --path /services/api
infisical secrets folders                           # 列出
infisical secrets folders delete --path /services/legacy

13.5　infisical export 與 infisical scan

export 三種格式 開發者

# 預設輸出 dotenv 到 stdout（給 pipe 用）
infisical export

# 指定格式與輸出檔
infisical export --format=dotenv --output-file=.env.runtime
infisical export --format=json   --output-file=secrets.json
infisical export --format=yaml   --output-file=secrets.yaml

# dotenv-export 模式輸出 'export KEY=val'，給 direnv 等用 eval 載入
eval "$(infisical export --format=dotenv-export --silent)"
# 之後當前 shell 已有所有 secret 變數
export 後立即清檔

把 secret 寫成檔案是「最後手段」。可以用 infisical run 注入時就不要 export。必須 export 時：(1) 確保檔名在 .gitignore 內、(2) build 完成立即 shred -u .env.runtime 抹除、(3) 檔案模式設 600。

scan：本機 / Git 掃描

# 掃當前目錄
infisical scan

# 只掃 staged 內容（pre-commit hook 用）
infisical scan --staged

# 掃 Git 歷史
infisical scan git --source=.

# 掃指定 commit 區間
infisical scan git --log="abc123^..HEAD"

# 安裝 pre-commit hook
infisical scan install --pre-commit-hook

13.6　.infisical.json 專案設定檔

檔案內容與用途 開發者

第一次在某資料夾跑 infisical init，會建立 .infisical.json：

{
  "workspaceId": "65cffa12-aaa7-4f1c-8e47-dbef0e7ac1b9",
  "defaultEnvironment": "dev",
  "gitBranchToEnvironmentMapping": {
    "main": "prod",
    "staging": "staging",
    "dev/*": "dev"
  }
}

三個欄位：

  • workspaceId：專案 ID。讓 CLI 知道指向哪個 Project。
  • defaultEnvironment：預設讀哪個環境。
  • gitBranchToEnvironmentMapping（選填）：CLI 讀取時若處於 git repo 內，依當前分支自動切環境。例如在 main 分支跑 infisical run 自動用 prod。
.infisical.json 安全嗎？

安全，可以 commit 進 Git。它不含 secret，只是「指向哪個 Project」的設定檔。整個專案的合作者只要登入過 CLI，clone 後 infisical run 就能自動用對 Project。

本章重點回顧

你應該掌握的 CLI 心法
  • 本機用瀏覽器登入；CI / 容器用 Machine Identity 非互動登入。
  • infisical run 是首選注入方式；infisical export 只在無法注入時才用，且用後立即清。
  • Production 鎖定 CLI 版本，避免 minor 升級導致行為變化。
  • .infisical.json 可進 Git，自動切環境用 git branch mapping。
  • scan + pre-commit hook 是最便宜的 secret leak 防線，所有 repo 都該裝。

14.1　SDK 共通設計與認證模式

新版 SDK 的統一設計 開發者

所有官方 SDK 採用一致的物件模型：

flowchart LR
  C[Client
建立時帶 host URL] --> A[client.auth]
  C --> S[client.secrets]
  C --> K[client.keys]

  A --> A1[universal_auth.login]
  A --> A2[kubernetes.login]
  A --> A3[aws_iam.login]
  A --> A4[gcp_id_token.login]
  A --> A5[azure.login]

  S --> S1[list_secrets]
  S --> S2[get_secret_by_name]
  S --> S3[create_secret]
  S --> S4[update_secret]
  S --> S5[delete_secret]

使用流程都是三步：

  1. 建立 client：傳入 host URL（Cloud 或 Self-Host）
  2. 認證：呼叫 client.auth.<method>.login(...)
  3. 操作：透過 client.secrets、client.keys 等子物件

認證方式對照

SDK 端的認證方法名稱與 CLI 略有不同，對照如下：

Auth 方法SDK 呼叫必要參數
Universal Authauth.universal_auth.loginclient_id、client_secret
Kubernetesauth.kubernetes.loginidentity_id、SA token（自動讀）
AWS IAMauth.aws_iam.loginidentity_id（簽名自動產）
GCP ID Tokenauth.gcp_id_token.loginidentity_id
GCP IAMauth.gcp_iam.loginidentity_id、service_account_key
Azureauth.azure.loginidentity_id
用環境變數讓登入更乾淨

所有 SDK 的認證方法都支援「不傳參直接讀環境變數」。例如 Universal Auth 自動讀 INFISICAL_UNIVERSAL_AUTH_CLIENT_ID 與 INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET。Production 程式碼推薦這種寫法，避免 client secret 出現在原始碼裡。

14.2　Node.js（Express 整合）

安裝

npm install @infisical/sdk
# 或
yarn add @infisical/sdk
# 或
pnpm add @infisical/sdk

Express 應用：啟動時載入所有 secret

// app.ts
import express from 'express';
import { InfisicalSDK } from '@infisical/sdk';

const app = express();
const PORT = 3000;

async function bootstrap() {
  const client = new InfisicalSDK({
    siteUrl: process.env.INFISICAL_HOST ?? 'https://app.infisical.com',
  });

  // 認證（從環境變數）
  await client.auth().universalAuth.login({
    clientId: process.env.INFISICAL_CLIENT_ID!,
    clientSecret: process.env.INFISICAL_CLIENT_SECRET!,
  });

  // 一次拉所有 secret 注入到 process.env
  const all = await client.secrets().listSecrets({
    projectId: process.env.INFISICAL_PROJECT_ID!,
    environment: process.env.INFISICAL_ENV ?? 'prod',
    secretPath: '/services/api',
  });
  for (const s of all.secrets) {
    process.env[s.secretKey] = s.secretValue;
  }

  app.get('/', (_req, res) => {
    res.send(`Stripe key prefix: ${process.env.STRIPE_KEY?.slice(0, 8)}…`);
  });

  app.listen(PORT, () => console.log(`listening on ${PORT}`));
}

bootstrap().catch((e) => {
  console.error('bootstrap failed', e);
  process.exit(1);
});

單獨取一筆 secret

const secret = await client.secrets().getSecretByName({
  secretName: 'DATABASE_URL',
  projectId: process.env.INFISICAL_PROJECT_ID!,
  environment: 'prod',
  secretPath: '/services/api',
});
console.log(secret.secretValue);

14.4　Go / Ruby / Java / C# 等價範例

Go（Gin 整合）開發者

// main.go
package main

import (
  "context"
  "log"
  "os"

  "github.com/gin-gonic/gin"
  infisical "github.com/infisical/go-sdk"
)

func main() {
  ctx := context.Background()
  client := infisical.NewInfisicalClient(ctx, infisical.Config{
    SiteUrl: os.Getenv("INFISICAL_HOST"),
  })

  _, err := client.Auth().UniversalAuthLogin(
    os.Getenv("INFISICAL_CLIENT_ID"),
    os.Getenv("INFISICAL_CLIENT_SECRET"),
  )
  if err != nil {
    log.Fatal(err)
  }

  r := gin.Default()
  r.GET("/", func(c *gin.Context) {
    s, err := client.Secrets().Retrieve(infisical.RetrieveSecretOptions{
      SecretKey:   "DATABASE_URL",
      ProjectID:   os.Getenv("INFISICAL_PROJECT_ID"),
      Environment: "prod",
      SecretPath:  "/services/api",
    })
    if err != nil {
      c.JSON(500, gin.H{"error": err.Error()})
      return
    }
    c.JSON(200, gin.H{"value_len": len(s.SecretValue)})
  })
  r.Run(":3000")
}

14.5　SDK 快取機制與舊版遷移

SDK 是否該快取？DevOps/SRE

多數 SDK 都有 cacheTTL 選項。預設值各語言不同，建議：

  • Web 服務啟動載入一次：如本章 14.2 / 14.3 範例，啟動時把所有 secret 拉到本機 process.env，後續就用 process.env，不再走 SDK——這是大多數 web 服務的最佳模式。
  • 長連線常駐服務需動態取：用 SDK 的 cacheTTL=300 之類設定，5 分鐘 refresh。配合 secret rotation 才能在合理時間內生效。
  • 每次都要最新值：cacheTTL=0。對極敏感、輪替頻繁的場景，但會增加每次 request 的延遲。

從舊版 SDK 遷移

舊套件（infisical-node、infisical for Python）的關鍵差異：

面向舊版（infisical-node / infisical）新版（@infisical/sdk / infisicalsdk）
套件名infisical-node@infisical/sdk

  4. 淘汰前先在 staging 跑 1 週確認快取與重連行為。

15.1　認證：Service Token vs Machine Identity

認證 header 開發者

所有 API 端點（除少數刻意公開的，如 /api/status、登入端點）都需要 Bearer token：

Authorization: Bearer <access-token>

取得 access token 的兩條路：

  1. Machine Identity 登入（推薦）：呼叫對應 Auth 端點換 access token，TTL 自訂。
  2. Service Token（舊式，仍支援）：直接拿固定 token 用，無 TTL 或 TTL 很長。

Universal Auth 登入範例

curl -X POST 'https://app.infisical.com/api/v1/auth/universal-auth/login' \
  -H "Content-Type: application/json" \
  -d '{
    "clientId": "abc-123",
    "clientSecret": "xxx-yyy-zzz"
  }'

# 回傳:
{
  "accessToken": "eyJhbG...",
  "expiresIn": 7200,
  "tokenType": "Bearer",
  "accessTokenMaxTTL": 7200
}

之後所有 API 呼叫帶這個 access token。

OIDC Auth 登入（CI 用）

# GitHub Actions 內取 OIDC token
JWT=$(curl -H "Authorization: bearer $ACTIONS_ID_TOKEN_REQUEST_TOKEN" \
  "$ACTIONS_ID_TOKEN_REQUEST_URL&audience=infisical" | jq -r .value)

# 用 JWT 換 Infisical access token
curl -X POST 'https://app.infisical.com/api/v1/auth/oidc-auth/login' \
  -H "Content-Type: application/json" \
  -d "{ \"identityId\": \"abc-123\", \"jwt\": \"$JWT\" }"

15.3　常用範例

讀取 secret

# 列出某 environment + path 下所有 secret
curl 'https://app.infisical.com/api/v3/secrets/raw?\
workspaceSlug=my-proj&environment=prod&secretPath=/services/api' \
  -H "Authorization: Bearer $ACCESS_TOKEN"

寫入 secret

curl -X POST 'https://app.infisical.com/api/v3/secrets/raw/STRIPE_KEY' \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "workspaceId": "PROJECT_ID",
    "environment": "prod",
    "secretValue": "sk_live_xxx",
    "secretPath": "/services/billing",
    "secretComment": "Stripe live key, rotated 2026-05-06"
  }'

建立 Machine Identity（程式化）

# 1. 建 identity
curl -X POST 'https://app.infisical.com/api/v1/identities' \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ci-deployer-prod",
    "organizationId": "ORG_ID",
    "role": "no-access"
  }'
# 回傳 { "identity": { "id": "id_xxx", ... } }

# 2. 配置 Universal Auth
curl -X POST "https://app.infisical.com/api/v1/auth/universal-auth/identities/$IDENTITY_ID" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{ "accessTokenTTL": 3600, "accessTokenMaxTTL": 7200 }'

# 3. 建立 client secret（用來實際登入）
curl -X POST "https://app.infisical.com/api/v1/auth/universal-auth/identities/$IDENTITY_ID/client-secrets" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{ "description": "ci runner", "ttl": 0, "numUsesLimit": 0 }'

簽發憑證

curl -X POST "https://app.infisical.com/api/v1/pki/profiles/$PROFILE_ID/issue" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{
    "commonName": "api.acme.local",
    "altNames": ["api-v2.acme.local"],
    "ttl": "90d"
  }'
# 回傳 cert + private key（base64 PEM）

查 audit log（給 SIEM 自家整合用）

curl "https://app.infisical.com/api/v1/organization/$ORG_ID/audit-logs?\
limit=100&\
startDate=2026-05-01T00:00:00Z&\
endDate=2026-05-06T00:00:00Z&\
eventType=update-secret" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

15.4　速率限制與分頁

Rate Limit DevOps/SRE

Cloud 預設 rate limit（會視方案調整）：

  • 讀取（GET secret）：每 IP / token 每分鐘 600 次
  • 寫入：每 IP / token 每分鐘 60 次
  • 登入：每 IP 每分鐘 30 次（防 brute-force）

觸發 rate limit 時回傳 429 Too Many Requests + Retry-After header。Self-Host 在 Server Admin Console 可調這些值。

分頁

列表型 endpoint 支援分頁：

# offset/limit 模式
curl '...endpoint?limit=50&offset=100'

# cursor 模式（部分新 endpoint）
curl '...endpoint?cursor=abc&limit=50'
# 回傳 { data: [...], nextCursor: "def" }
本章重點回顧
  • 所有 API 帶 Authorization: Bearer <token>；token 從 Machine Identity 登入端點換取。
  • Secret CRUD 用 /api/v3/secrets/raw/*；其他用 /api/v1/*。
  • 程式化建立 Identity / 簽憑證 / 查 audit 都有對應 endpoint，能完整自動化整套生命週期。
  • Production 整合務必處理 rate limit + 分頁 + 重試（exponential backoff）。
  • 整合多端點時，優先用 SDK，REST API 只在 SDK 沒包到的場景才直接打。
