Skills 系統：
知識的自我封裝與進化

Skills 是這個系統「自進化」的核心機制——agent 在完成複雜任務後， 把可重用的程序知識封裝成 SKILL.md 文件，下次遇到類似問題直接載入， 跳過重新探索的 token 消耗。Curator 自動維護 skill 庫的品質。

本 Part 產出：skills/ 完整系統（loader + tools + curator）
6.1
Part 6 · Skills 系統

Skill 的本質：可執行的程序知識

在說實作之前，先精確定義 skill 是什麼、不是什麼。

Skill 是什麼

可執行的程序知識——一份告訴 agent 「遇到這類問題，要按這個步驟做」的文件。 它比 memory 更結構化（有明確的 When / Procedure / Pitfalls）， 比 system prompt 更按需（不是一直佔用 context）。

Skill 不是什麼

不是 tool（tool 是 Python 函數，skill 是 Markdown 知識文件）。 不是 memory（memory 是事實紀錄，skill 是程序步驟）。 不是 system prompt（system prompt 永遠在，skill 按需載入）。

為什麼需要 Skill

每次遇到「deploy 到 Kubernetes」都要 agent 重新探索一遍，浪費 token 也容易犯相同錯誤。 把第一次做對的步驟封裝成 skill，之後直接載入——這就是「學習」的工程實作。

Progressive Disclosure 的代價

Level-0 索引（名稱 + 一句描述）約佔 3K tokens，無論 skill 庫有多少個 skill 都固定消耗這些。 完整 skill 內容只有 agent 決定需要時才載入，讓 skill 數量可以無限增長。

圖 6-1 · Skill 自進化閉環
flowchart LR TASK["使用者任務"] --> EXEC["Agent 執行\n可能犯錯也重試"] EXEC --> SUCCESS["任務成功"] SUCCESS --> CAPTURE["Skill 封裝觸發\n識別可重用的步驟"] CAPTURE --> WRITE["建立 SKILL.md\n儲存到 skills 目錄"] WRITE --> INDEX["下次 Session\nLevel-0 索引出現"] INDEX --> LOAD["agent 識別匹配\nskill_view 載入完整內容"] LOAD --> TASK

SKILL.md 格式規範

每個 skill 是一個目錄，目錄名稱即 skill ID，內含 SKILL.md。格式與 Hermes 完全相容，遵循 agentskills.io 開放標準。

markdown~/.myagent/skills/github-pr-workflow/SKILL.md（完整範例）
---
name: github-pr-workflow
description: 建立符合團隊規範的 GitHub Pull Request，含 branch、commit、PR 描述
version: 1.0.0
platforms: [linux, macos]
metadata:
  hermes:
    category: software-development
    tags: [git, github, pr, workflow]
    requires_toolsets: [terminal]
---

# GitHub PR Workflow

## When to Use
當使用者要求建立 PR、提交程式碼到 GitHub，或詢問 PR 流程時使用。

## Prerequisites
- 已在 terminal 確認 `git status`
- 確認目前在正確的 working directory

## Procedure

### 1. 確認目前狀態
```bash
git status
git log --oneline -5
```

### 2. 建立 feature branch
```bash
git checkout -b feat/TICKET-123-brief-description
```
Branch 命名規則：`{type}/{ticket}-{brief-description}`
type: feat / fix / refactor / docs / chore

### 3. Commit 規範
```bash
git add -p   # 互動式 staging，避免加入不相關的變更
git commit -m "feat(scope): brief description

- 詳細說明變更 1
- 詳細說明變更 2

Refs: TICKET-123"
```

### 4. Push 並建立 PR
```bash
git push -u origin HEAD
gh pr create --title "feat: ..." --body "..."
```

## Pitfalls
- 不要 `git add .`，使用 `git add -p` 避免提交測試用的 debug code
- PR 描述必須說明「為什麼」而不只是「做了什麼」

## Verification
- `gh pr view` 確認 PR 已建立
- CI checks 開始執行

Front-matter 欄位說明

欄位必填說明
name是唯一識別符，也是 slash 命令名稱（/github-pr-workflow）
description是Level-0 索引中顯示的一句話描述，LLM 靠這句話判斷是否載入
version否Curator 追蹤版本變化
platforms否限制平台（省略表示全部平台）
metadata.hermes.category否Level-0 索引的分組顯示
metadata.hermes.requires_toolsets否Conditional Activation：只有在指定 toolset 啟用時才顯示
metadata.hermes.fallback_for_toolsets否Conditional Activation：只有在指定 toolset 不可用時才顯示

正文必備區塊

區塊必填用途
## When to Use是描述觸發條件，讓 agent 知道何時該用這個 skill
## Procedure是步驟化的執行程序，agent 會逐步跟隨
## Pitfalls建議已知的陷阱與失敗模式，避免重蹈覆轍
## Verification建議完成後如何確認成功，讓 agent 自我驗證

Conditional Activation：依 Toolset 動態顯示

Conditional activation 讓 skill 根據當前 session 的 toolset 配置自動顯示或隱藏—— 不需要手動管理哪些 skill 要開關。

Front-matter 欄位行為典型用途
requires_toolsets: [terminal]只有 terminal toolset 啟用時才顯示需要執行命令的 skill
requires_toolsets: [web]只有 web toolset 啟用時才顯示需要搜尋網路的 skill
fallback_for_toolsets: [web]web toolset 不可用時才顯示DuckDuckGo 免費替代方案
pythonskills/loader.py — conditional activation 過濾
def _passes_conditional_activation(fm: dict, active_toolsets: set[str]) -> bool:
    """
    檢查 skill 的條件式啟用規則。
    active_toolsets：當前 session 啟用的 toolset 名稱集合。
    """
    meta = fm.get("metadata", {}).get("hermes", {})

    # requires_toolsets：所有列出的 toolset 都必須啟用
    requires = meta.get("requires_toolsets", [])
    if requires and not all(t in active_toolsets for t in requires):
        return False

    # fallback_for_toolsets：所有列出的 toolset 都必須不啟用
    fallback = meta.get("fallback_for_toolsets", [])
    if fallback and any(t in active_toolsets for t in fallback):
        return False

    return True

Part 6 · Skills 系統

Progressive Disclosure 實作：skills_list + skill_view

Skills 系統對 agent 暴露兩個 tool：skills_list（Level-0，固定消耗） 和 skill_view（Level-1，按需載入）。

pythonskills/loader.py（完整實作）
"""
skills/loader.py — Skill 載入與管理
提供 skills_list 和 skill_view 兩個 tool 的 handler
"""
from __future__ import annotations
import json, time
from pathlib import Path
import yaml
from agent.prompt_builder import get_agent_home
from tools.registry import registry


def get_skills_dir() -> Path:
    d = get_agent_home() / "skills"
    d.mkdir(parents=True, exist_ok=True)
    return d


def _parse_front_matter(content: str) -> dict:
    if not content.startswith("---"):
        return {}
    parts = content.split("---", 2)
    if len(parts) < 3:
        return {}
    try:
        return yaml.safe_load(parts[1]) or {}
    except yaml.YAMLError:
        return {}


def _passes_conditional_activation(fm: dict, active_toolsets: set[str]) -> bool:
    meta = fm.get("metadata", {}).get("hermes", {})
    requires = meta.get("requires_toolsets", [])
    if requires and not all(t in active_toolsets for t in requires):
        return False
    fallback = meta.get("fallback_for_toolsets", [])
    if fallback and any(t in active_toolsets for t in fallback):
        return False
    return True


def _load_all_skills(active_toolsets: set[str] | None = None) -> list[dict]:
    """載入所有符合條件的 skill 的 metadata。"""
    active = active_toolsets or set()
    skills = []
    for d in sorted(get_skills_dir().iterdir()):
        skill_file = d / "SKILL.md"
        if not skill_file.exists():
            continue
        content = skill_file.read_text(encoding="utf-8")
        fm = _parse_front_matter(content)
        if not fm.get("name"):
            fm["name"] = d.name

        # Platform 過濾
        platforms = fm.get("platforms")
        if platforms:
            import sys
            cur = "macos" if sys.platform == "darwin" else "windows" if sys.platform == "win32" else "linux"
            if cur not in platforms:
                continue

        # Conditional activation
        if not _passes_conditional_activation(fm, active):
            continue

        skills.append({
            "name": fm.get("name"),
            "description": fm.get("description", ""),
            "category": fm.get("metadata", {}).get("hermes", {}).get("category", "general"),
            "version": fm.get("version", "1.0.0"),
            "path": str(skill_file),
        })
    return skills


# ── Tool Handlers ──────────────────────────────────────────────────

SKILLS_LIST_SCHEMA = {
    "name": "skills_list",
    "description": "List all available skills with their names and descriptions (Level-0 index).",
    "parameters": {
        "type": "object",
        "properties": {
            "category": {"type": "string", "description": "Filter by category (optional)"}
        },
    },
}

SKILL_VIEW_SCHEMA = {
    "name": "skill_view",
    "description": "Load the full content of a skill by name. Use when a skill clearly matches your task.",
    "parameters": {
        "type": "object",
        "properties": {
            "name": {"type": "string", "description": "Skill name to load"},
        },
        "required": ["name"],
    },
}


def _skills_list_handler(args: dict) -> str:
    category_filter = args.get("category")
    skills = _load_all_skills()
    if category_filter:
        skills = [s for s in skills if s["category"] == category_filter]
    by_cat: dict[str, list] = {}
    for s in skills:
        by_cat.setdefault(s["category"], []).append(s)
    lines = []
    for cat, items in sorted(by_cat.items()):
        lines.append(f{cat}:)
        for it in items:
            lines.append(f"  - {it['name']}: {it['description']}")
    return json.dumps({"skills": lines, "total": len(skills)})


def _skill_view_handler(args: dict) -> str:
    name = args.get("name", "")
    skill_dir = get_skills_dir() / name
    skill_file = skill_dir / "SKILL.md"
    if not skill_file.exists():
        # 模糊匹配：name 作為 substring
        matches = [d for d in get_skills_dir().iterdir() if name.lower() in d.name.lower()]
        if not matches:
            return json.dumps({"error": f"Skill '{name}' not found"})
        skill_file = matches[0] / "SKILL.md"

    content = skill_file.read_text(encoding="utf-8")

    # 記錄使用次數（Curator 需要）
    _record_skill_access(skill_file.parent.name)

    return json.dumps({"name": name, "content": content})


def _record_skill_access(skill_name: str) -> None:
    """記錄 skill 使用次數，供 Curator 評估。"""
    stats_file = get_skills_dir() / ".curator_stats.json"
    stats: dict = {}
    if stats_file.exists():
        try:
            stats = json.loads(stats_file.read_text())
        except:
            stats = {}
    skill_stats = stats.setdefault(skill_name, {"uses": 0, "first_used": 0})
    if not skill_stats["first_used"]:
        skill_stats["first_used"] = time.time()
    skill_stats["uses"] += 1
    skill_stats["last_used"] = time.time()
    stats_file.write_text(json.dumps(stats, indent=2))


registry.register(name="skills_list", toolset="skills", schema=SKILLS_LIST_SCHEMA, handler=_skills_list_handler)
registry.register(name="skill_view", toolset="skills", schema=SKILL_VIEW_SCHEMA, handler=_skill_view_handler)

Agent 如何自創 Skill

「自創 skill」的觸發機制：agent 完成複雜任務後，system prompt 裡有一個 nudge， 提示 agent 考慮是否值得封裝成 skill。agent 判斷後呼叫 create_skill tool 完成建立。

Skill 建立 Tool

pythontools/skill_create_tool.py
"""tools/skill_create_tool.py — Agent 建立新 Skill 的 tool"""
import json, re
from pathlib import Path
from skills.loader import get_skills_dir
from tools.registry import registry

CREATE_SKILL_SCHEMA = {
    "name": "create_skill",
    "description": (
        "Create a new skill from the current task's steps. "
        "Use after successfully completing a complex, repeatable task."
    ),
    "parameters": {
        "type": "object",
        "properties": {
            "name": {"type": "string", "description": "Skill ID (lowercase, hyphens). e.g. 'deploy-to-k8s'"},
            "description": {"type": "string", "description": "One-sentence description for the Level-0 index"},
            "category": {"type": "string", "description": "Category for grouping. e.g. 'devops', 'software-development'"},
            "content": {"type": "string", "description": "Full SKILL.md body (When to Use, Procedure, Pitfalls, Verification)"},
            "requires_toolsets": {"type": "array", "items": {"type": "string"},
                                   "description": "Toolsets required for this skill"},
        },
        "required": ["name", "description", "content"],
    },
}


def _create_skill_handler(args: dict) -> str:
    name = re.sub(r'[^a-z0-9-]', '-', args["name"].lower()).strip('-')
    description = args["description"]
    category = args.get("category", "general")
    body = args["content"]
    requires = args.get("requires_toolsets", [])

    skill_dir = get_skills_dir() / name
    if skill_dir.exists():
        return json.dumps({"error": f"Skill '{name}' already exists. Use create_skill with a different name or update the existing one."})

    skill_dir.mkdir(parents=True)

    # 組裝 front-matter
    meta_section = ""
    if requires:
        meta_section = f"""metadata:
  hermes:
    category: {category}
    requires_toolsets: [{', '.join(requires)}]"""
    else:
        meta_section = f"""metadata:
  hermes:
    category: {category}"""

    front_matter = f"""---
name: {name}
description: {description}
version: 1.0.0
{meta_section}
---"""
    skill_content = front_matter + "\n\n" + body.strip()
    (skill_dir / "SKILL.md").write_text(skill_content, encoding="utf-8")

    return json.dumps({
        "success": True,
        "name": name,
        "path": str(skill_dir / "SKILL.md"),
        "message": f"Skill '{name}' created. It will appear in the index next session."
    })


registry.register(name="create_skill", toolset="skills", schema=CREATE_SKILL_SCHEMA, handler=_create_skill_handler)

Skill Nudge：觸發 agent 考慮封裝

pythonagent/prompt_builder.py — 加入 skill nudge
_SKILL_NUDGE = """After completing a complex or multi-step task successfully,
consider whether the procedure is reusable. If so, use create_skill to save it.
Good skills have: clear When-to-Use trigger, numbered Procedure steps,
known Pitfalls, and a Verification step."""

# 加入 _TOOL_GUIDANCE 或 Layer 2
設計決策日誌 #008

決策：Skill 建立由 agent 主動判斷，不自動觸發。
理由：自動觸發（每次任務完成都嘗試建立 skill）會產生大量品質低劣的 skill， 反而污染 Level-0 索引。讓 agent 判斷「這個流程夠通用嗎？值得保留嗎？」 是更高品質的過濾機制。
Hermes 的做法：在 system prompt 的 tool-guidance 層（Layer 2）加入 skill nudge， 讓 agent 在任務完成後自然考慮，而非強制要求。

Curator：Skill 品質的自動維護

Curator 是一個背景任務，追蹤 skill 的使用率和時效性， 自動歸檔長期未使用或內容陳舊的 skill，防止 skill 庫無限膨脹。

pythonskills/curator.py（完整實作）
"""
skills/curator.py — Skill 品質維護
評估使用率與時效，歸檔或建議更新陳舊的 skill。
"""
from __future__ import annotations
import json, logging, shutil, time
from dataclasses import dataclass
from pathlib import Path
from skills.loader import get_skills_dir

logger = logging.getLogger(__name__)

# 設定閾值
STALE_DAYS = 60           # 超過 60 天未使用 → 列入歸檔候選
MIN_USES_TO_KEEP = 3      # 30 天內不足 3 次使用 → 評估是否歸檔
ARCHIVE_SUBDIR = "archived"


@dataclass
class CuratorReport:
    """Curator 評估結果"""
    active: list[str]     # 健康的 skill
    stale: list[str]      # 陳舊的 skill（候選歸檔）
    archived: list[str]   # 本次歸檔的 skill
    new_skills: list[str] # 新發現的、從未被使用的 skill


def run_curator(dry_run: bool = False) -> CuratorReport:
    """
    執行 Curator 評估。
    dry_run=True 時只報告，不實際移動檔案。
    """
    skills_dir = get_skills_dir()
    stats_file = skills_dir / ".curator_stats.json"
    archive_dir = skills_dir / ARCHIVE_SUBDIR

    stats: dict = {}
    if stats_file.exists():
        try:
            stats = json.loads(stats_file.read_text())
        except:
            stats = {}

    now = time.time()
    active, stale, archived, new_skills = [], [], [], []

    for skill_dir in sorted(skills_dir.iterdir()):
        if skill_dir.name.startswith(".") or skill_dir.name == ARCHIVE_SUBDIR:
            continue
        if not (skill_dir / "SKILL.md").exists():
            continue

        name = skill_dir.name
        s = stats.get(name, {})
        uses = s.get("uses", 0)
        last_used = s.get("last_used", 0)
        first_used = s.get("first_used", 0)

        days_since_use = (now - last_used) / 86400 if last_used else float("inf")
        days_since_created = (now - skill_dir.stat().st_mtime) / 86400

        if uses == 0:
            if days_since_created < 7:
                new_skills.append(name)  # 新建立，給一週觀察期
            elif days_since_created > STALE_DAYS:
                stale.append(name)  # 從未使用且超過 60 天
            else:
                active.append(name)
        elif days_since_use > STALE_DAYS:
            stale.append(name)
        else:
            active.append(name)

    # 歸檔陳舊的 skill
    if not dry_run:
        archive_dir.mkdir(exist_ok=True)
        for name in stale:
            src = skills_dir / name
            dst = archive_dir / name
            if not dst.exists():
                shutil.move(str(src), str(dst))
                archived.append(name)
                logger.info(f"Curator: archived '{name}'")

    return CuratorReport(
        active=active, stale=stale, archived=archived, new_skills=new_skills
    )


def restore_skill(name: str) -> bool:
    """從歸檔恢復一個 skill。"""
    src = get_skills_dir() / ARCHIVE_SUBDIR / name
    dst = get_skills_dir() / name
    if not src.exists():
        return False
    shutil.move(str(src), str(dst))
    return True

練習 6.7：自創 Skill 閉環驗證
目標：agent 完成任務後自動建立 skill，下次載入時 token 消耗顯著減少
  1. 1
    手動建立一個假的 skill 目錄（如 ~/.myagent/skills/test-skill/SKILL.md），確認 build_skills_index() 能在輸出中看到它

    呼叫 skills_list tool，確認回傳 JSON 中包含該 skill
  3. 3
    呼叫 skill_view tool，確認能讀取完整 SKILL.md 內容
  4. 4
    呼叫 create_skill tool 建立一個真正的 skill（以「如何用 Python 建立虛擬環境」為題），確認檔案被建立且 front-matter 格式正確
  5. 5
    呼叫 _record_skill_access("test-skill") 兩次，確認 .curator_stats.json 中的 uses 從 0 增加到 2
  6. 6
    建立一個「60 天前」的 skill（修改 st_mtime），確認 run_curator(dry_run=True) 把它列在 stale 列表中
  7. 7
    驗證 conditional activation：建立一個 requires_toolsets: [terminal] 的 skill，在空的 active_toolsets 下呼叫 _passes_conditional_activation，確認回傳 False
完整驗證：在真實對話中告訴 agent「請把這個建立 git tag 的流程存成 skill」， agent 應呼叫 create_skill 建立 SKILL.md，下次新 session 的 system prompt 中應包含這個 skill 的 Level-0 條目。
