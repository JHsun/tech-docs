2.1
Part 2 · Provider 路由

為什麼需要 Provider 抽象

Part 1 的 MinimalAgent 直接把 openai.OpenAI(base_url=...) 寫死在 __init__。 這個設計有三個根本問題：

  • 訊息格式不同：Anthropic Messages API 的格式與 OpenAI 有差異（system prompt 的位置、tool call 的結構、vision 的格式）
  • Credential 不同：不同 provider 的 API key 環境變數名稱不同、auth 方式不同（有的用 OAuth token）
  • 功能不同：Anthropic 有 prompt caching，OpenAI 有 Responses API，這些在 chat_completions 介面上沒有統一

解法：把這三個差異封裝進 Transport 物件。 AIAgent 只看到統一的介面，不知道底層是哪個 provider。

圖 2-1 · Provider 抽象層架構
graph TB AA["AIAgent.run_conversation()"] --> TR["ProviderTransport\n統一介面"] TR --> CC["ChatCompletionsTransport\nOpenAI OpenRouter 任何 OpenAI-compatible"] TR --> AT["AnthropicTransport\n原生 Messages API 含 prompt cache"] TR --> RT["未來: ResponsesTransport\nOpenAI Responses API"]
設計決策日誌 #004

決策：Transport 負責訊息格式轉換，AIAgent 永遠使用 OpenAI-style message list 作為內部格式。
理由：OpenAI format 是業界事實標準，所有主要 provider 都提供 OpenAI-compatible endpoint。 選它作為內部格式意味著 ChatCompletionsTransport 基本上是 pass-through（零轉換）， 成本最低。只有 Anthropic 原生 API 需要非平凡的轉換。
Hermes 的做法：完全相同設計，agent/anthropic_adapter.py 負責轉換， 三種 API mode 最終都收斂到同一個內部 message format。

ProviderTransport ABC

pythonagent/providers/base.py
"""
agent/providers/base.py — Provider Transport 抽象基類
"""
from __future__ import annotations
from abc import ABC, abstractmethod
from dataclasses import dataclass
from enum import Enum
from typing import Any

Message = dict[str, Any]


class ApiMode(Enum):
    """三種 API 執行模式，對應不同的訊息格式與功能集。"""
    CHAT_COMPLETIONS = "chat_completions"   # OpenAI / OpenRouter / 任何 compatible
    ANTHROPIC_MESSAGES = "anthropic_messages" # Anthropic 原生 API
    CODEX_RESPONSES = "codex_responses"     # OpenAI Responses API（保留）


@dataclass
class TransportResponse:
    """
    Transport.call() 的統一回傳格式。
    不管底層是哪個 provider，AIAgent 永遠拿到這個結構。
    """
    # 純文字回覆（沒有 tool call 時）
    content: str | None
    # Tool call 列表（沒有時是空 list）
    tool_calls: list[dict]
    # 原始 assistant message（用於附加到 history）
    raw_message: Message
    # Token 用量統計
    usage: dict[str, int]


class ProviderTransport(ABC):
    """
    Provider Transport 抽象基類。
    每個 provider 實作這兩個方法。
    """

    @abstractmethod
    def call(
        self,
        messages: list[Message],
        tool_schemas: list[dict],
        model: str,
    ) -> TransportResponse:
        """
        呼叫 LLM，傳回統一格式的 TransportResponse。
        messages 是 OpenAI-style list（含 system）。
        tool_schemas 是 OpenAI function schema list。
        """

    @property
    @abstractmethod
    def api_mode(self) -> ApiMode:
        """回傳此 transport 使用的 API mode。"""

ChatCompletionsTransport

最通用的 transport。OpenAI format 直送，幾乎不需要轉換。 OpenRouter、所有 local LLM server（llama.cpp、Ollama、vLLM）都用這個。

pythonagent/providers/chat_completions.py
"""
agent/providers/chat_completions.py
OpenAI-compatible chat completions transport。
"""
from __future__ import annotations
import json, os
from openai import OpenAI
from .base import ApiMode, ProviderTransport, TransportResponse, Message


class ChatCompletionsTransport(ProviderTransport):

    def __init__(self, base_url: str, api_key: str) -> None:
        self.client = OpenAI(base_url=base_url, api_key=api_key)

    @property
    def api_mode(self) -> ApiMode:
        return ApiMode.CHAT_COMPLETIONS

    def call(
        self,
        messages: list[Message],
        tool_schemas: list[dict],
        model: str,
    ) -> TransportResponse:
        kwargs: dict = {"model": model, "messages": messages}
        if tool_schemas:
            kwargs["tools"] = [{"type": "function", "function": s} for s in tool_schemas]

        response = self.client.chat.completions.create(**kwargs)
        msg = response.choices[0].message

        # 把 tool_calls 序列化為統一格式
        parsed_tool_calls = []
        raw_tool_calls = []
        if msg.tool_calls:
            for tc in msg.tool_calls:
                try:
                    args = json.loads(tc.function.arguments)
                except json.JSONDecodeError:
                    args = {}
                parsed_tool_calls.append({
                    "id": tc.id, "name": tc.function.name, "arguments": args
                })
                raw_tool_calls.append({
                    "id": tc.id, "type": "function",
                    "function": {"name": tc.function.name, "arguments": tc.function.arguments},
                })

        raw_message: Message = {
            "role": "assistant",
            "content": msg.content,
            **({"tool_calls": raw_tool_calls} if raw_tool_calls else {}),
        }

        usage = {}
        if response.usage:
            usage = {
                "input_tokens": response.usage.prompt_tokens,
                "output_tokens": response.usage.completion_tokens,
            }

        return TransportResponse(
            content=msg.content,
            tool_calls=parsed_tool_calls,
            raw_message=raw_message,
            usage=usage,
        )

AnthropicTransport（含 Prompt Cache）

Anthropic Messages API 有三個與 OpenAI 不同的地方：

  • System prompt 位置：Anthropic 不允許 {"role":"system"} 在 messages list 裡，而是獨立的 system 參數
  • Tool call 格式：Anthropic 用 tool_use/tool_result content blocks，而非 OpenAI 的 tool_calls 欄位
  • Prompt cache：在特定位置加入 {"type":"text","cache_control":{"type":"ephemeral"}} 可讓 Anthropic 快取 prefix
pythonagent/providers/anthropic_transport.py
"""
agent/providers/anthropic_transport.py
Anthropic Messages API transport，含 prompt cache 支援。
"""
from __future__ import annotations
import json, os
from anthropic import Anthropic
from .base import ApiMode, ProviderTransport, TransportResponse, Message


class AnthropicTransport(ProviderTransport):

    def __init__(self, api_key: str, enable_cache: bool = True) -> None:
        self.client = Anthropic(api_key=api_key)
        self.enable_cache = enable_cache

    @property
    def api_mode(self) -> ApiMode:
        return ApiMode.ANTHROPIC_MESSAGES

    def _convert_messages(
        self, messages: list[Message]
    ) -> tuple[list, list[dict] | str]:
        """
        把 OpenAI-style messages 轉換成 Anthropic 格式。
        回傳 (anthropic_messages, system)。

        Anthropic 的特殊處：
        - system messages 抽取出來，不在 messages list 裡
        - role: "tool" 要轉換成 tool_result content block
        - role: "assistant" 含 tool_calls 要轉換成 tool_use content blocks
        """
        system_parts = []
        ant_messages = []

        for msg in messages:
            role = msg["role"]
            content = msg.get("content")

            if role == "system":
                # System messages 收集起來作為 system 參數
                system_parts.append({
                    "type": "text",
                    "text": content or "",
                })
                continue

            if role == "tool":
                # OpenAI tool result → Anthropic tool_result content block
                # 注意：Anthropic 要求 tool_result 和對應的 tool_use 在同一 user turn
                if ant_messages and ant_messages[-1]["role"] == "user":
                    existing = ant_messages[-1]["content"]
                    if isinstance(existing, list):
                        existing.append({
                            "type": "tool_result",
                            "tool_use_id": msg["tool_call_id"],
                            "content": content or "",
                        })
                    else:
                        ant_messages[-1]["content"] = [{
                            "type": "tool_result",
                            "tool_use_id": msg["tool_call_id"],
                            "content": content or "",
                        }]
                else:
                    ant_messages.append({
                        "role": "user",
                        "content": [{
                            "type": "tool_result",
                            "tool_use_id": msg["tool_call_id"],
                            "content": content or "",
                        }]
                    })
                continue

            if role == "assistant":
                tool_calls = msg.get("tool_calls")
                if tool_calls:
                    # OpenAI tool_calls → Anthropic tool_use content blocks
                    blocks = []
                    if content:
                        blocks.append({"type": "text", "text": content})
                    for tc in tool_calls:
                        fn = tc["function"]
                        try:
                            args = json.loads(fn["arguments"])
                        except (json.JSONDecodeError, KeyError):
                            args = {}
                        blocks.append({
                            "type": "tool_use",
                            "id": tc["id"],
                            "name": fn["name"],
                            "input": args,
                        })
                    ant_messages.append({"role": "assistant", "content": blocks})
                else:
                    ant_messages.append({"role": "assistant", "content": content or ""})
                continue

            # role: "user"
            ant_messages.append({"role": "user", "content": content or ""})

        # 加入 prompt cache breakpoint 在 system prompt 末尾
        if self.enable_cache and system_parts:
            system_parts[-1]["cache_control"] = {"type": "ephemeral"}

        return ant_messages, system_parts

    def _convert_tools(self, tool_schemas: list[dict]) -> list[dict]:
        """OpenAI function schema → Anthropic tool schema"""
        return [
            {
                "name": s["name"],
                "description": s.get("description", ""),
                "input_schema": s.get("parameters", {"type": "object", "properties": {}}),
            }
            for s in tool_schemas
        ]

    def call(
        self,
        messages: list[Message],
        tool_schemas: list[dict],
        model: str,
    ) -> TransportResponse:
        ant_messages, system = self._convert_messages(messages)

        kwargs: dict = {
            "model": model,
            "max_tokens": 8096,
            "messages": ant_messages,
        }
        if system:
            kwargs["system"] = system
        if tool_schemas:
            kwargs["tools"] = self._convert_tools(tool_schemas)

        response = self.client.messages.create(**kwargs)

        # 把 Anthropic response 轉換回 OpenAI 內部格式
        content_text = None
        parsed_tool_calls = []
        raw_tool_calls = []

        for block in response.content:
            if block.type == "text":
                content_text = block.text
            elif block.type == "tool_use":
                parsed_tool_calls.append({
                    "id": block.id, "name": block.name, "arguments": block.input
                })
                raw_tool_calls.append({
                    "id": block.id, "type": "function",
                    "function": {
                        "name": block.name,
                        "arguments": json.dumps(block.input),
                    },
                })

        raw_message: Message = {
            "role": "assistant", "content": content_text,
            **({"tool_calls": raw_tool_calls} if raw_tool_calls else {}),
        }

        usage = {
            "input_tokens": response.usage.input_tokens,
            "output_tokens": response.usage.output_tokens,
        }
        # Anthropic 快取命中的 token 數
        if hasattr(response.usage, "cache_read_input_tokens"):
            usage["cache_read_tokens"] = response.usage.cache_read_input_tokens or 0
            usage["cache_creation_tokens"] = response.usage.cache_creation_input_tokens or 0

        return TransportResponse(
            content=content_text,
            tool_calls=parsed_tool_calls,
            raw_message=raw_message,
            usage=usage,
        )
💡 Prompt Cache 的實際效果
加上 "cache_control": {"type": "ephemeral"} 後： 第一次請求 Anthropic 快取 system prompt prefix（寫入費用 = 輸入 token 費用）。 後續請求只要 prefix 完全相同，cache_read_tokens 費用約為輸入 token 的 10%。 長 system prompt（含完整 MEMORY.md + skill index）可以節省 90%+ 的輸入費用。

Provider 解析邏輯

現在實作 resolve_transport()：根據設定和環境變數， 自動選擇正確的 transport 並建立它。 優先序：CLI 明確指定 → config.yaml → 環境變數自動偵測。

pythonagent/providers/resolver.py
"""
agent/providers/resolver.py — Provider 解析與 Transport 建立。
"""
from __future__ import annotations
import os
from dataclasses import dataclass
from .base import ProviderTransport
from .chat_completions import ChatCompletionsTransport
from .anthropic_transport import AnthropicTransport


@dataclass
class ProviderConfig:
    """
    Provider 設定的完整描述。
    這是 resolver 輸入，也是 AIAgent 儲存 provider 狀態的結構。
    """
    provider: str          # "anthropic" | "openrouter" | "custom" | ...
    model: str             # 模型名稱，如 "claude-opus-4"
    api_key: str | None = None
    base_url: str | None = None
    enable_cache: bool = True


# Provider 名稱 → base URL 和 API key 環境變數的映射
_PROVIDER_DEFAULTS: dict[str, dict] = {
    "openrouter": {
        "base_url": "https://openrouter.ai/api/v1",
        "env_key": "OPENROUTER_API_KEY",
    },
    "nous": {
        "base_url": "https://inference-api.nousresearch.com/v1",
        "env_key": "NOUS_TOKEN",
    },
    "openai": {
        "base_url": "https://api.openai.com/v1",
        "env_key": "OPENAI_API_KEY",
    },
}

# 偵測 provider 的環境變數優先序
_AUTO_DETECT_ORDER = [
    ("ANTHROPIC_API_KEY", "anthropic"),
    ("NOUS_TOKEN", "nous"),
    ("OPENROUTER_API_KEY", "openrouter"),
    ("OPENAI_API_KEY", "openai"),
]


def resolve_transport(cfg: ProviderConfig) -> ProviderTransport:
    """
    根據 ProviderConfig 建立正確的 Transport 實例。
    如果 provider 是 "auto"，從環境變數自動偵測。
    """
    provider = cfg.provider.lower()

    if provider == "auto":
        provider = _auto_detect_provider()

    if provider == "anthropic":
        key = cfg.api_key or os.environ.get("ANTHROPIC_API_KEY", "")
        if not key:
            raise ValueError("ANTHROPIC_API_KEY not set")
        return AnthropicTransport(api_key=key, enable_cache=cfg.enable_cache)

    # 所有 OpenAI-compatible provider
    defaults = _PROVIDER_DEFAULTS.get(provider, {})
    base_url = cfg.base_url or defaults.get("base_url", "https://openrouter.ai/api/v1")
    env_key_name = defaults.get("env_key", "OPENAI_API_KEY")
    api_key = cfg.api_key or os.environ.get(env_key_name, "")

    if not api_key:
        raise ValueError(f"{env_key_name} not set for provider '{provider}'")

    return ChatCompletionsTransport(base_url=base_url, api_key=api_key)


def _auto_detect_provider() -> str:
    """
    按優先序檢查環境變數，回傳第一個有設定的 provider。
    Hermes 的 runtime_provider.py 也是這個邏輯：
    config.yaml 設定優先，沒設定才 auto-detect。
    """
    for env_var, provider in _AUTO_DETECT_ORDER:
        if os.environ.get(env_var):
            return provider
    raise ValueError(
        "No API key found. Set one of: "
        "ANTHROPIC_API_KEY, OPENROUTER_API_KEY, OPENAI_API_KEY, NOUS_TOKEN"
    )

Fallback 機制

Fallback 讓主 provider 失敗時自動切換備用，不中斷對話。 在 AIAgent 層實作，每個 session 最多啟動一次。

pythonagent/core.py（更新：加入 provider transport + fallback）
from agent.providers.base import ProviderTransport, TransportResponse
from agent.providers.resolver import ProviderConfig, resolve_transport


class AIAgent:
    """
    從 MinimalAgent 升級而來，加入 Provider Transport 抽象和 Fallback 機制。
    """

    def __init__(
        self,
        provider_cfg: ProviderConfig,
        system_prompt: str = "You are a helpful AI agent.",
        max_iterations: int = 25,
        fallback_cfg: ProviderConfig | None = None,
        tool_registry: dict | None = None,
        tool_schemas: list | None = None,
    ) -> None:
        self.provider_cfg = provider_cfg
        self.model = provider_cfg.model
        self.system_prompt = system_prompt
        self.max_iterations = max_iterations
        self.fallback_cfg = fallback_cfg
        self.tool_registry = tool_registry or {}
        self.tool_schemas = tool_schemas or []
        self.history: list[dict] = []

        # 初始化 transport
        self._transport: ProviderTransport = resolve_transport(provider_cfg)
        self._fallback_activated = False

    def _try_activate_fallback(self, error: Exception) -> bool:
        """
        嘗試啟動 fallback。
        回傳 True 表示成功切換，呼叫方應重試。
        回傳 False 表示沒有 fallback 或已啟動過，應將 error 往上拋。
        """
        if self._fallback_activated or self.fallback_cfg is None:
            return False

        try:
            self._transport = resolve_transport(self.fallback_cfg)
            self.model = self.fallback_cfg.model
            self._fallback_activated = True
            print(f"[Fallback activated: {self.fallback_cfg.provider}/{self.model}]")
            return True
        except Exception as e2:
            print(f"[Fallback activation failed: {e2}]")
            return False

    def _call_with_retry(self) -> TransportResponse:
        """
        呼叫 LLM，失敗時嘗試啟動 fallback 並重試一次。
        這是 Hermes run_agent.py 的 retry loop 的精簡版。
        """
        messages = [{"role": "system", "content": self.system_prompt}] + self.history
        try:
            return self._transport.call(messages, self.tool_schemas, self.model)
        except Exception as e:
            if self._try_activate_fallback(e):
                # 重試一次（用新的 transport）
                return self._transport.call(messages, self.tool_schemas, self.model)
            raise

    def run_conversation(self, user_message: str) -> ConversationResult:
        self.history.append({"role": "user", "content": user_message})
        iteration = 0

        while iteration < self.max_iterations:
            iteration += 1
            resp = self._call_with_retry()

            if not resp.tool_calls:
                self.history.append(resp.raw_message)
                return ConversationResult(
                    final_response=resp.content or "",
                    history=self.history.copy(),
                    iterations_used=iteration,
                )

            self.history.append(resp.raw_message)
            for tc in resp.tool_calls:
                result = self._dispatch_tool(tc["name"], tc["arguments"])
                self.history.append({
                    "role": "tool", "tool_call_id": tc["id"], "content": result
                })

        budget_msg = f"[Agent stopped: reached max_iterations={self.max_iterations}]"
        self.history.append({"role": "assistant", "content": budget_msg})
        return ConversationResult(
            final_response=budget_msg, history=self.history.copy(),
            iterations_used=self.max_iterations, stopped_by_budget=True,
        )

    def _dispatch_tool(self, name: str, arguments: dict) -> str:
        if name not in self.tool_registry:
            return f"Error: unknown tool '{name}'"
        try:
            r = self.tool_registry[name](**arguments)
            return r if isinstance(r, str) else json.dumps(r, ensure_ascii=False)
        except Exception as e:
            return f"Tool '{name}' error: {e}"

    def chat(self, msg: str) -> str:
        return self.run_conversation(msg).final_response

    def reset(self) -> None:
        self.history = []
        self._fallback_activated = False

Auxiliary Model：輔助任務用便宜模型

對話的主要推理需要強模型（Claude Opus、GPT-4o），但很多輔助任務不需要： 網頁摘要、context 壓縮、危險命令風險評估、記憶寫入。 為這些任務用便宜快速的模型可以大幅降低成本和延遲。

pythonagent/providers/auxiliary.py
"""
agent/providers/auxiliary.py — Auxiliary model client
用便宜模型處理輔助任務：摘要、壓縮、風險評估。
"""
from __future__ import annotations
from .resolver import ProviderConfig, resolve_transport


class AuxiliaryClient:
    """
    輔助模型客戶端。
    同一個 interface，但使用更便宜的模型。
    """

    def __init__(self, cfg: ProviderConfig) -> None:
        self._transport = resolve_transport(cfg)
        self._model = cfg.model

    def complete(self, prompt: str, system: str = "You are a helpful assistant.") -> str:
        """送一條 prompt，回傳純文字結果。"""
        messages = [
            {"role": "system", "content": system},
            {"role": "user", "content": prompt},
        ]
        resp = self._transport.call(messages, [], self._model)
        return resp.content or ""

    def summarize(self, text: str, max_chars: int = 500) -> str:
        """把長文摘要成 max_chars 以內的重點。"""
        return self.complete(
            f"Summarize the following in at most {max_chars} characters:\n\n{text}"
        )

    def assess_risk(self, command: str) -> str:
        """評估命令的危險程度：low / medium / high。"""
        result = self.complete(
            f"""Rate the risk of this shell command as "low", "medium", or "high".
Reply with only one word.

Command: {command}"""
        )
        word = result.strip().lower().split()[0] if result.strip() else "high"
        return word if word in ("low", "medium", "high") else "high"


# 全域預設 auxiliary client（在 AIAgent 初始化時設定）
_default_aux: AuxiliaryClient | None = None

def get_auxiliary() -> AuxiliaryClient | None:
    return _default_aux

def set_auxiliary(client: AuxiliaryClient) -> None:
    global _default_aux
    _default_aux = client

Tool 的本質：schema 與 handler 的分離

每個 tool 由兩個完全獨立的部分組成：

Schema（LLM 看到的）

JSON Schema 格式的函數描述：名稱、用途說明、參數定義、必填欄位。 LLM 根據這個決定是否呼叫、如何填參數。 schema 的品質直接決定 LLM 能否正確使用 tool。

Handler（實際執行的）

Python 函數，接收 LLM 填好的 arguments dict，執行實際工作，回傳字串結果。 Handler 不知道自己是被 LLM 呼叫的——它就是一個普通函數。

⚠ Hermes 的強制規則（我們也採用）
  • Handler 必須回傳 JSON string（用 json.dumps()），不能回傳 dict
  • 錯誤必須以 {"error": "message"} 回傳，不能拋出 exception
  • Handler 拋出 exception 會導致 tool result 是空的，LLM 不知道發生了什麼

ToolRegistry：自動發現與 Dispatch

pythontools/registry.py
"""
tools/registry.py — Tool Registry
自動發現、schema 收集、dispatch，不需要手動維護 import list。
"""
from __future__ import annotations
import importlib, inspect, json, logging, pkgutil
from dataclasses import dataclass, field
from typing import Any, Callable

logger = logging.getLogger(__name__)


@dataclass
class ToolEntry:
    """Registry 中每個 tool 的完整記錄。"""
    name: str
    schema: dict
    handler: Callable
    toolset: str                       # 所屬 toolset 名稱
    check_fn: Callable | None = None   # 依賴檢查函數，回傳 bool
    requires_env: list[str] = field(default_factory=list)


class ToolRegistry:
    """
    全域 tool registry。
    每個 tool 模組在 import 時呼叫 registry.register()，
    register() 在模組頂層觸發，無需手動維護 import list。
    """

    def __init__(self) -> None:
        self._tools: dict[str, ToolEntry] = {}
        self._hooks: dict[str, list[Callable]] = {
            "pre_tool_call": [],
            "post_tool_call": [],
        }

    def register(
        self,
        name: str,
        schema: dict,
        handler: Callable,
        toolset: str = "default",
        check_fn: Callable | None = None,
        requires_env: list[str] | None = None,
    ) -> None:
        """在 registry 中登記一個 tool。"""
        self._tools[name] = ToolEntry(
            name=name, schema=schema, handler=handler,
            toolset=toolset, check_fn=check_fn,
            requires_env=requires_env or [],
        )
        logger.debug(f"Registered tool: {name} (toolset={toolset})")

    def discover(self, package_name: str = "tools") -> int:
        """
        自動 import 指定 package 下的所有模組。
        模組頂層的 registry.register() 呼叫在 import 時自動觸發。
        回傳新發現的 tool 數量。
        """
        before = len(self._tools)
        pkg = importlib.import_module(package_name)
        pkg_path = getattr(pkg, "__path__", [])

        for _, module_name, _ in pkgutil.iter_modules(pkg_path):
            full_name = f"{package_name}.{module_name}"
            try:
                importlib.import_module(full_name)
            except ImportError as e:
                logger.warning(f"Could not import {full_name}: {e}")

        discovered = len(self._tools) - before
        logger.info(f"Discovered {discovered} tools in '{package_name}'")
        return discovered

    def get_schemas(
        self,
        toolsets: list[str] | None = None,
    ) -> list[dict]:
        """
        取得可用 tool 的 schema list（傳給 LLM API）。
        toolsets 為 None 則回傳所有 tool。
        check_fn 失敗的 tool 自動排除。
        """
        schemas = []
        for entry in self._tools.values():
            # Toolset 過濾
            if toolsets is not None and entry.toolset not in toolsets:
                continue
            # 依賴檢查：check_fn 回傳 False 則跳過
            if entry.check_fn is not None:
                try:
                    if not entry.check_fn():
                        continue
                except Exception:
                    continue
            schemas.append(entry.schema)
        return schemas

    def dispatch(self, name: str, arguments: dict, task_id: str = "") -> str:
        """
        執行指定 tool，觸發 pre/post hook。
        回傳 JSON 字串結果。
        """
        if name not in self._tools:
            return json.dumps({"error": f"Unknown tool: {name}"})

        ctx = {"tool_name": name, "arguments": arguments, "task_id": task_id}

        # pre_tool_call hook
        for hook in self._hooks["pre_tool_call"]:
            try:
                hook(ctx)
            except Exception as e:
                logger.warning(f"pre_tool_call hook error: {e}")

        # 執行 handler
        try:
            result = self._tools[name].handler(arguments)
            if not isinstance(result, str):
                result = json.dumps(result, ensure_ascii=False)
        except Exception as e:
            result = json.dumps({"error": f"{type(e).__name__}: {e}"})

        ctx["result"] = result

        # post_tool_call hook
        for hook in self._hooks["post_tool_call"]:
            try:
                hook(ctx)
            except Exception as e:
                logger.warning(f"post_tool_call hook error: {e}")

        return result

    def add_hook(self, event: str, fn: Callable) -> None:
        """訂閱 hook 事件。"""
        if event in self._hooks:
            self._hooks[event].append(fn)


# 全域 singleton（模組頂層 register() 呼叫時使用）
registry = ToolRegistry()

pythontools/terminal_tool.py
"""tools/terminal_tool.py — Shell 命令執行 tool"""
import json, subprocess
from tools.registry import registry

TERMINAL_SCHEMA = {
    "name": "terminal",
    "description": (
        "Execute a shell command and return its stdout and stderr. "
        "Use for file operations, system queries, running scripts, git commands, etc."
    ),
    "parameters": {
        "type": "object",
        "properties": {
            "command": {
                "type": "string",
                "description": "Shell command to execute, e.g. 'ls -la' or 'python script.py'",
            },
            "timeout": {
                "type": "integer",
                "description": "Timeout in seconds, default: 30",
                "default": 30,
            },
        },
        "required": ["command"],
    },
}


def _terminal_handler(args: dict) -> str:
    command = args.get("command", "")
    timeout = args.get("timeout", 30)
    if not command:
        return json.dumps({"error": "command is required"})
    try:
        result = subprocess.run(
            command, shell=True, capture_output=True,
            text=True, timeout=timeout,
        )
        output = result.stdout
        if result.stderr:
            output += ("\n[stderr]\n" if output else "") + result.stderr
        return json.dumps({
            "stdout": result.stdout,
            "stderr": result.stderr,
            "exit_code": result.returncode,
            "output": output.strip() or "(no output)",
        }, ensure_ascii=False)
    except subprocess.TimeoutExpired:
        return json.dumps({"error": f"Command timed out after {timeout}s"})
    except Exception as e:
        return json.dumps({"error": str(e)})


# 頂層 register — discover() 自動發現
registry.register(
    name="terminal", toolset="terminal",
    schema=TERMINAL_SCHEMA, handler=_terminal_handler,
)

"""tools/file_tool.py — 檔案讀寫 tool"""
import json, os
from pathlib import Path
from tools.registry import registry

READ_FILE_SCHEMA = {
    "name": "read_file",
    "description": "Read the contents of a file. Returns the file content as a string.",
    "parameters": {
        "type": "object",
        "properties": {
            "path": {"type": "string", "description": "File path to read, e.g. 'src/main.py'"},
            "encoding": {"type": "string", "description": "File encoding, default: utf-8", "default": "utf-8"},
        },
        "required": ["path"],
    },
}

WRITE_FILE_SCHEMA = {
    "name": "write_file",
    "description": "Write content to a file, creating parent directories if needed.",
    "parameters": {
        "type": "object",
        "properties": {
            "path": {"type": "string", "description": "File path to write"},
            "content": {"type": "string", "description": "Content to write"},
        },
        "required": ["path", "content"],
    },
}


def _read_handler(args: dict) -> str:
    try:
        p = Path(args["path"]).expanduser()
        if not p.exists():
            return json.dumps({"error": f"File not found: {p}"})
        text = p.read_text(encoding=args.get("encoding", "utf-8"))
        return json.dumps({"path": str(p), "content": text, "size": len(text)})
    except Exception as e:
        return json.dumps({"error": str(e)})

def _write_handler(args: dict) -> str:
    try:
        p = Path(args["path"]).expanduser()
        p.parent.mkdir(parents=True, exist_ok=True)
        p.write_text(args["content"], encoding="utf-8")
        return json.dumps({"success": True, "path": str(p), "bytes_written": len(args["content"].encode())})
    except Exception as e:
        return json.dumps({"error": str(e)})


registry.register(name="read_file", toolset="file", schema=READ_FILE_SCHEMA, handler=_read_handler)
registry.register(name="write_file", toolset="file", schema=WRITE_FILE_SCHEMA, handler=_write_handler)

Toolset 分組：per-platform 配置

Toolset 讓你用名稱選擇一組 tool，而不是逐一列舉。 不同平台用不同的 toolset preset：CLI 有完整工具集，Telegram bot 可能不開放 terminal。

pythontools/toolsets.py
"""
tools/toolsets.py — Toolset 定義與解析。
"""
from __future__ import annotations

# 每個 toolset 包含哪些 tool 名稱
TOOLSET_MAP: dict[str, list[str]] = {
    "terminal": ["terminal"],
    "file":     ["read_file", "write_file", "search_files"],
    "web":      ["web_search", "web_extract"],
    "memory":   ["memory"],
    "skills":   ["skills_list", "skill_view"],
    "delegation": ["delegate_task"],
    "cronjob":  ["cronjob"],
}

# Platform presets：每個平台預設啟用哪些 toolset
PLATFORM_PRESETS: dict[str, list[str]] = {
    "cli": ["terminal", "file", "web", "memory", "skills", "delegation"],
    "telegram": ["web", "memory", "skills", "file"],  # 不開放 terminal
    "batch": ["web", "terminal", "file"],  # 不需要記憶（skip_memory=True）
    "safe": ["web", "file"],   # 唯讀，無 terminal
}


def resolve_toolset_names(
    toolsets: str | list[str] | None = None,
    platform: str = "cli",
) -> list[str]:
    """
    把 toolset 名稱解析成 tool name list。
    None → 使用 platform preset。
    "all" → 所有 toolset。
    """
    if toolsets is None:
        toolsets = PLATFORM_PRESETS.get(platform, PLATFORM_PRESETS["cli"])
    elif isinstance(toolsets, str):
        toolsets = [toolsets]

    if "all" in toolsets or "*" in toolsets:
        return list({t for ts in TOOLSET_MAP.values() for t in ts})

    tool_names = []
    for ts in toolsets:
        tool_names.extend(TOOLSET_MAP.get(ts, [ts]))  # 如果不是 toolset 名稱，當 tool 名稱
    return list(dict.fromkeys(tool_names))  # 去重，保留順序

Approval Flow：危險命令審核

部分 shell 命令有破壞性（rm -rf、git reset --hard）。 在執行前檢查，需要用戶核准或自動評估。

pythontools/approval.py
"""
tools/approval.py — 危險命令審核
三種模式：manual（人工）、smart（LLM 評估）、off（略過）
"""
from __future__ import annotations
import re
from enum import Enum

class ApprovalMode(Enum):
    MANUAL = "manual"   # 人工核准
    SMART  = "smart"    # Auxiliary LLM 評估
    OFF    = "off"      # 不審核（CI/CD / YOLO mode）

# 危險命令正規表達式（子集，完整版在 Hermes tools/approval.py）
_DANGEROUS_PATTERNS: list[re.Pattern] = [
    re.compile(r'\brm\b.*(-r|-f|--recursive|--force)'),
    re.compile(r'\bgit\b.*(reset.*--hard|clean.*-f|checkout.*-f)'),
    re.compile(r'\btruncate\b'),
    re.compile(r'\bshred\b'),
    re.compile(r'\bdrop\s+table\b', re.IGNORECASE),
    re.compile(r'>(?!>)'),   # output redirect（> 但不是 >>）
    re.compile(r'\bsudo\b'),
]


def is_dangerous(command: str) -> bool:
    """檢查命令是否命中危險模式。"""
    return any(p.search(command) for p in _DANGEROUS_PATTERNS)


def check_approval(
    command: str,
    mode: ApprovalMode = ApprovalMode.MANUAL,
    aux_risk_fn=None,
) -> bool:
    """
    決定命令是否可以執行。
    回傳 True = 可以執行，False = 拒絕。
    aux_risk_fn: AuxiliaryClient.assess_risk 的 callable（smart mode 用）
    """
    if mode == ApprovalMode.OFF:
        return True

    if not is_dangerous(command):
        return True

    if mode == ApprovalMode.SMART and aux_risk_fn:
        risk = aux_risk_fn(command)
        if risk == "low":
            return True
        if risk == "high":
            return False
        # medium → fallthrough to manual

    # MANUAL mode 或 smart medium：請求人工核准
    print(f"\n⚠ Dangerous command detected:\n  {command}\nAllow? [y/N] ", end="")
    try:
        answer = input().strip().lower()
        return answer in ("y", "yes")
    except (EOFError, KeyboardInterrupt):
        return False  # 非互動環境（CI）預設拒絕
設計決策日誌 #005

決策：Approval 邏輯在 tool handler 外層，而非在 terminal_tool.py 內部。
理由：若在 handler 內部檢查，需要每個危險的 tool 各自實作 approval 邏輯，容易遺漏。 在 dispatch 層集中處理，所有 tool 都受保護。 這也讓 approval 邏輯可以被 mock，測試時不需要真正的 interactive input。
Hermes 的做法：在 handle_function_call()（run_agent.py 內）呼叫 approval_callback， 這個 callback 由入口層（CLI/Gateway）在建立 AIAgent 時傳入，完全解耦。

Plugin Hook 點：pre/post tool call

Hook 讓外部程式碼在不修改核心的情況下，在每次 tool 執行前後插入邏輯： 日誌記錄、metrics、guardrails、自動重試。

python範例：logging hook
import time
from tools.registry import registry

# 計時 hook：記錄每個 tool 的執行時間
_start_times: dict[str, float] = {}

def pre_hook(ctx: dict) -> None:
    task_id = ctx.get("task_id", "unknown")
    _start_times[task_id] = time.time()
    print(f"[Tool call] {ctx['tool_name']}({ctx['arguments']})")

def post_hook(ctx: dict) -> None:
    task_id = ctx.get("task_id", "unknown")
    elapsed = time.time() - _start_times.pop(task_id, time.time())
    print(f"[Tool done] {ctx['tool_name']} in {elapsed:.2f}s")

# 在 agent 初始化時註冊
registry.add_hook("pre_tool_call", pre_hook)
registry.add_hook("post_tool_call", post_hook)
