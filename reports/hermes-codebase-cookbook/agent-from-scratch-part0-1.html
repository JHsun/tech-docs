我們要建什麼

先說結論：我們要建的是一個自進化的 conversational agent 系統。 「自進化」不是行銷詞——它是一個工程上明確的設計：agent 在執行任務的過程中， 把可重用的知識封裝成 skill 文件，把學到的環境事實寫入持久記憶， 下一次遇到類似問題時直接利用這些積累。

整個系統分三層，每層有清晰的職責邊界：

圖 0-1 · 三層架構總覽
graph TB subgraph L1["入口層 Entry Points"] CLI["CLI / TUI\n終端互動介面"] GW["Gateway\nTelegram Discord Slack"] BATCH["Batch Runner\n訓練資料生成"] end subgraph L2["核心 Agent Core"] AA["AIAgent\nrun_conversation()"] PB["Prompt Builder\n10 層 system prompt"] TR["Tool Registry\n自動發現 dispatch"] SS["Session Store\nSQLite FTS5"] MEM["Memory Store\nMEMORY.md USER.md"] SK["Skills System\nSKILL.md 漸進載入"] end subgraph L3["工具後端 Backends"] TB["Terminal Backends\nlocal docker ssh modal"] WB["Web Backends\nFirecrawl DuckDuckGo"] BB["Browser Backends\nChromium Browserbase"] MC["MCP Servers\n動態擴充"] end L1 --> L2 L2 --> L3

注意：所有入口層共享同一個 AIAgent 核心。 不管是 terminal 的 CLI、Telegram 的 Gateway 還是 batch 訓練， 行為完全一致——這是 Hermes 最重要的架構決策之一。 platform-specific 的邏輯只存在於入口層的 adapter，不允許滲透進核心。

設計決策日誌 #001

決策：所有入口層共享單一 AIAgent 核心，platform 差異封裝在 adapter 層。
理由：若在核心 code 加入 if platform == "telegram" 的分支， 隨著平台增加，核心的複雜度呈線性增長，測試也變得困難。 Adapter 層讓每個平台可以獨立測試，核心保持單純。
代價：設計 adapter 介面需要提前想清楚所有平台的共同需求， 有些邊緣情況（如 Discord 的語音頻道）確實難以完全抽象。

自進化的閉環是怎麼運作的

「自進化」的核心是一個閉環：agent 使用工具完成任務，在這個過程中產生新知識， 並把這些知識存入持久化的結構（skill 文件 + memory 文件）， 下一個 session 的 system prompt 自動包含這些積累。

圖 0-2 · 自進化閉環（Learning Loop）
graph LR TASK["使用者任務"] --> EXEC["Agent 執行\n使用工具解決"] EXEC --> KNOW{"產生新知識?"} KNOW -->|"流程知識"| SKILL["建立 SKILL.md\n封裝可重用流程"] KNOW -->|"環境事實"| MEM["更新 MEMORY.md\n記錄學到的事實"] SKILL --> CURATOR["Curator 評估\n使用率 時效 品質"] CURATOR -->|"有效"| NEXT["下一個 Session\nLevel-0 索引注入 prompt"] MEM --> NEXT NEXT --> TASK

這個閉環有三個關鍵機制，我們在後面的 Part 會逐一實作：

Progressive Disclosure

Skill 不是全文塞進 prompt，而是只放 Level-0 索引（名稱 + 一句描述）。 Agent 按需載入完整內容。這讓 skill 數量可以無限增長而不消耗 context。

Frozen Snapshot

MEMORY.md 在 session 開始時讀入 system prompt，之後不再改變。 Agent 在 session 中更新記憶會立即寫入磁碟，但要下一個 session 才生效。 這確保 Anthropic prompt cache 的穩定性。

Curator 維護

Skill 的使用率和時效性由 Curator 追蹤。長期未使用或內容陳舊的 skill 會被自動歸檔， 防止 skill 庫無限膨脹。

概念速查：三個你會反覆看到的詞

Tool call（工具呼叫）

LLM 在回覆中不回傳文字，而是回傳一個 JSON 結構，指定要呼叫的函數名稱和參數。 我們的程式解析這個 JSON，執行對應的 Python 函數，把結果傳回 LLM。

Context window（上下文視窗）

LLM 每次能看到的最大 token 數量。超出限制的歷史必須壓縮或截斷。 這是整個系統很多設計決策的根本原因。

Prompt cache（提示詞快取）

Anthropic 允許把 system prompt 的 prefix 快取起來，後續請求只需付摘要 token 的費用。 要讓 cache 命中，prefix 必須完全穩定——這是 frozen snapshot 機制的工程動機。

AIAgent 的職責邊界

在寫程式碼之前，先精確定義 AIAgent 負責什麼、不負責什麼。 邊界模糊是 agent 架構腐化的最主要原因。

AIAgent 負責

  • 組裝 effective system prompt 和 tool schemas
  • 選擇正確的 provider 和 API mode
  • 管理對話歷史（conversation history）
  • 呼叫 LLM，解析回應（文字 or tool call）
  • dispatch tool call 給 tool registry 執行
  • 把 tool 結果附加回歷史，繼續推理
  • 維護 iteration budget（防止無限迴圈）
  • 壓縮 context（當 token 接近上限）
  • 把結果 persist 到 session store

AIAgent 不負責

  • 具體的 tool 實作（那是 tool registry 的事）
  • UI 渲染（那是 CLI/TUI 的事）
  • Platform 特定邏輯（那是 gateway adapter 的事）
  • Credential 管理（那是 provider runtime 的事）
User Input → AIAgent.run_conversation() → Final Response
↕ Tool Registry（執行 tool）
↕ LLM Provider（推理）

訊息格式：OpenAI-compatible message list

整個系統內部統一使用 OpenAI-compatible 訊息格式—— 這是 Hermes 的核心設計決策之一。 不管底層用的是 Anthropic、OpenRouter 還是其他 provider， conversation_history 永遠是這個格式， adapter 負責把它轉換成各 provider 的 native format。

四種 role 與對應結構

python
# role: "system" — system prompt（只出現一次，在最前面）
{"role": "system", "content": "You are a helpful AI agent..."}

# role: "user" — 使用者輸入
{"role": "user", "content": "幫我找出 src/ 目錄下所有超過 500 行的 Python 檔案"}

# role: "assistant" — LLM 的回覆（可以是純文字或含 tool_calls）
# 純文字回覆
{"role": "assistant", "content": "好的，我來幫你搜尋..."}

# 含 tool_calls 的回覆（content 通常為 None）
{
    "role": "assistant",
    "content": None,
    "tool_calls": [
        {
            "id": "call_abc123",
            "type": "function",
            "function": {
                "name": "terminal",
                "arguments": '{"command": "find src/ -name \'*.py\' | xargs wc -l"}'
            }
        }
    ]
}

# role: "tool" — tool 的執行結果（必須緊跟在含 tool_calls 的 assistant 訊息後）
{
    "role": "tool",
    "tool_call_id": "call_abc123",  # 對應 assistant 的 tool_call.id
    "content": "  1247 src/run_agent.py\n   892 src/cli.py\n..."
}

Role 交替規則（嚴格執行）

Provider 對訊息順序有嚴格要求，違反會導致 API 錯誤：

  • System 訊息只能在最前面，且只有一條
  • System 之後必須是 User，然後交替：User → Assistant → User → Assistant
  • 不能連續兩條 Assistant 訊息
  • 不能連續兩條 User 訊息
  • Tool 訊息只能緊跟在含 tool_calls 的 Assistant 之後
  • 同一輪的多個 tool 結果可以連續（並行 tool call 的場景）
⚠ 常見錯誤
很多初學者在 tool call 失敗時，直接把錯誤訊息以 user 角色附加到歷史， 導致 user → user 的連續訊息，provider 拒絕請求。 正確做法：錯誤訊息應該以 role: "tool"、包含對應的 tool_call_id 附加。

最小 chat()：約 30 行

先實作最最精簡的版本：送一條訊息，拿到一條文字回覆。 不考慮歷史、不考慮 tool call。目標是確認 LLM API 連線正常。

pythonagent/core.py（第一版）
"""
agent/core.py — 最小可執行 Agent（第一版）
"""
from __future__ import annotations
import os
from openai import OpenAI


class MinimalAgent:
    """
    最小可執行的 Agent。
    目前只支援單次對話，無歷史，無 tool call。
    """

    def __init__(
        self,
        model: str = "anthropic/claude-sonnet-4",
        system_prompt: str = "You are a helpful AI agent.",
        base_url: str = "https://openrouter.ai/api/v1",
        api_key: str | None = None,
    ) -> None:
        self.model = model
        self.system_prompt = system_prompt
        self.client = OpenAI(
            base_url=base_url,
            api_key=api_key or os.environ["OPENROUTER_API_KEY"],
        )

    def chat(self, user_message: str) -> str:
        """
        送出一條訊息，取得一條文字回覆。
        這是 run_conversation() 的最精簡版本。
        """
        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": user_message},
        ]
        response = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
        )
        return response.choices[0].message.content


if __name__ == "__main__":
    agent = MinimalAgent()
    reply = agent.chat("用繁體中文說一句話介紹自己")
    print(reply)

對話歷史管理

真正的對話需要記住之前說了什麼。把 conversation_history 從 chat() 外部傳入，讓同一個 agent 可以持續多輪對話。

pythonagent/core.py（更新）
from __future__ import annotations
import os
from typing import Any
from openai import OpenAI

# 型別別名，讓程式碼更易讀
Message = dict[str, Any]
History = list[Message]


class MinimalAgent:

    def __init__(
        self,
        model: str = "anthropic/claude-sonnet-4",
        system_prompt: str = "You are a helpful AI agent.",
        base_url: str = "https://openrouter.ai/api/v1",
        api_key: str | None = None,
    ) -> None:
        self.model = model
        self.system_prompt = system_prompt
        self.client = OpenAI(
            base_url=base_url,
            api_key=api_key or os.environ["OPENROUTER_API_KEY"],
        )
        # 對話歷史（不含 system prompt）
        self.history: History = []

    def _build_messages(self, extra: History | None = None) -> History:
        """
        組裝完整的 messages list：
        [system] + history + extra
        
        system prompt 永遠在最前面（Fixed prefix for prompt cache）。
        """
        msgs: History = [{"role": "system", "content": self.system_prompt}]
        msgs.extend(self.history)
        if extra:
            msgs.extend(extra)
        return msgs

    def chat(self, user_message: str) -> str:
        """
        送出訊息，取得回覆，自動維護歷史。
        """
        # 把新訊息加到歷史
        user_msg: Message = {"role": "user", "content": user_message}
        self.history.append(user_msg)

        # 呼叫 LLM
        response = self.client.chat.completions.create(
            model=self.model,
            messages=self._build_messages(),
        )
        assistant_content = response.choices[0].message.content or ""

        # 把 assistant 回覆也存入歷史
        assistant_msg: Message = {"role": "assistant", "content": assistant_content}
        self.history.append(assistant_msg)

        return assistant_content

    def reset(self) -> None:
        """清空對話歷史，開始新的 session。"""
        self.history = []


if __name__ == "__main__":
    agent = MinimalAgent()
    print(agent.chat("我的名字是 Alice"))
    print(agent.chat("你還記得我的名字嗎？"))  # 應該回答 Alice
設計決策日誌 #002

決策：history 不包含 system prompt，_build_messages() 每次組裝時才加入。
理由：把 system prompt 和對話歷史分開儲存，可以在不影響歷史的情況下更換 system prompt （例如 profile 切換）。更重要的是：_build_messages() 是未來插入 ephemeral layers 的地方， 分離設計讓這個擴展更自然。
注意：Part 4 加入 prompt builder 後，_build_messages() 會變成插入記憶、skill index、context files 的地方。

Tool call 解析

LLM 的回覆不一定是文字。當它想呼叫工具時， response.choices[0].message.tool_calls 會是一個非空 list。 我們需要解析這個 list，執行對應的函數，把結果附加回歷史。

Tool call 的資料結構

python
import json
from openai.types.chat import ChatCompletionMessage


def parse_tool_calls(message: ChatCompletionMessage) -> list[dict]:
    """
    從 LLM response message 解析所有 tool call。
    每個 tool call 解析為：{id, name, arguments}
    """
    if not message.tool_calls:
        return []

    parsed = []
    for tc in message.tool_calls:
        try:
            arguments = json.loads(tc.function.arguments)
        except json.JSONDecodeError:
            # LLM 偶爾產生不合法的 JSON，這裡做 graceful fallback
            arguments = {"raw": tc.function.arguments}

        parsed.append({
            "id": tc.id,
            "name": tc.function.name,
            "arguments": arguments,
        })
    return parsed


def make_tool_result_message(tool_call_id: str, result: str) -> dict:
    """
    把 tool 執行結果包裝成符合 OpenAI 格式的 message。
    """
    return {
        "role": "tool",
        "tool_call_id": tool_call_id,
        "content": result,
    }

    回傳值一律轉成 str（provider 要求 tool result 是字串）。
    """
    if name not in _FAKE_REGISTRY:
        return f"Error: unknown tool '{name}'"
    try:
        result = _FAKE_REGISTRY[name](**arguments)
        if not isinstance(result, str):
            result = json.dumps(result, ensure_ascii=False)
        return result
    except Exception as e:
        return f"Error executing tool '{name}': {e}"

"""
agent/core.py — 核心迴圈完整版
包含：對話歷史、tool call 解析與執行、iteration budget
"""
from __future__ import annotations
import json, os
from dataclasses import dataclass, field
from typing import Any, Callable
from openai import OpenAI

Message = dict[str, Any]
History = list[Message]


@dataclass
class ConversationResult:
    """run_conversation() 的回傳值。"""
    final_response: str
    history: History
    iterations_used: int
    stopped_by_budget: bool = False


class MinimalAgent:

    def __init__(
        self,
        model: str = "anthropic/claude-sonnet-4",
        system_prompt: str = "You are a helpful AI agent.",
        max_iterations: int = 25,
        base_url: str = "https://openrouter.ai/api/v1",
        api_key: str | None = None,
        tool_registry: dict[str, Callable] | None = None,
        tool_schemas: list[dict] | None = None,
    ) -> None:
        self.model = model
        self.system_prompt = system_prompt
        self.max_iterations = max_iterations
        self.client = OpenAI(
            base_url=base_url,
            api_key=api_key or os.environ["OPENROUTER_API_KEY"],
        )
        # tool_registry: {name: handler}，Part 3 會替換成 ToolRegistry
        self.tool_registry: dict[str, Callable] = tool_registry or {}
        # tool_schemas: OpenAI tool schema list，傳給 API
        self.tool_schemas: list[dict] = tool_schemas or []
        self.history: History = []

    def _build_messages(self) -> History:
        return [{"role": "system", "content": self.system_prompt}] + self.history

    def _dispatch_tool(self, name: str, arguments: dict) -> str:
        """執行 tool，回傳字串結果。"""
        if name not in self.tool_registry:
            return f"Error: unknown tool '{name}'. Available: {list(self.tool_registry)}"
        try:
            result = self.tool_registry[name](**arguments)
            return result if isinstance(result, str) else json.dumps(result, ensure_ascii=False)
        except Exception as e:
            return f"Tool '{name}' raised an exception: {type(e).__name__}: {e}"

    def run_conversation(self, user_message: str) -> ConversationResult:
        """
        主迴圈：處理一輪完整的對話，包含任意次數的 tool call。
        回傳 ConversationResult，包含最終回覆和執行統計。
        """
        # 1. 把 user message 加入歷史
        self.history.append({"role": "user", "content": user_message})

        iteration = 0

        while iteration < self.max_iterations:
            iteration += 1

            # 2. 組裝 messages 並呼叫 LLM
            api_kwargs: dict[str, Any] = {
                "model": self.model,
                "messages": self._build_messages(),
            }
            if self.tool_schemas:
                api_kwargs["tools"] = [
                    {"type": "function", "function": s} for s in self.tool_schemas
                ]

            response = self.client.chat.completions.create(**api_kwargs)
            msg = response.choices[0].message

            # 3. 判斷回應類型
            if not msg.tool_calls:
                # 純文字回覆：結束迴圈
                final = msg.content or ""
                self.history.append({"role": "assistant", "content": final})
                return ConversationResult(
                    final_response=final,
                    history=self.history.copy(),
                    iterations_used=iteration,
                )

            # 4. 有 tool_calls：把 assistant 訊息存入歷史
            assistant_msg: Message = {
                "role": "assistant",
                "content": msg.content,  # 通常是 None
                "tool_calls": [
                    {
                        "id": tc.id,
                        "type": "function",
                        "function": {
                            "name": tc.function.name,
                            "arguments": tc.function.arguments,
                        },
                    }
                    for tc in msg.tool_calls
                ],
            }
            self.history.append(assistant_msg)

            # 5. 執行每個 tool call，把結果存入歷史
            for tc in msg.tool_calls:
                try:
                    arguments = json.loads(tc.function.arguments)
                except json.JSONDecodeError:
                    arguments = {}

                result = self._dispatch_tool(tc.function.name, arguments)

                self.history.append({
                    "role": "tool",
                    "tool_call_id": tc.id,
                    "content": result,
                })

            # 6. 繼續迴圈，讓 LLM 基於 tool 結果繼續推理

        # 7. Iteration budget 耗盡
        budget_msg = f"[Agent stopped: reached max_iterations={self.max_iterations}]"
        self.history.append({"role": "assistant", "content": budget_msg})
        return ConversationResult(
            final_response=budget_msg,
            history=self.history.copy(),
            iterations_used=self.max_iterations,
            stopped_by_budget=True,
        )

    def chat(self, user_message: str) -> str:
        """run_conversation() 的便捷包裝，只回傳 final_response 字串。"""
        return self.run_conversation(user_message).final_response

    def reset(self) -> None:
        self.history = []
1.7
Part 1 · 核心迴圈

Iteration budget：防止無限迴圈

沒有 budget 限制的 agent 在 tool 呼叫失敗或 LLM 陷入迴圈思考時， 會永遠執行下去，產生巨額費用。這是 agent 系統最重要的安全機制之一。

三種停止條件

停止條件觸發時機我們的處理
正常結束LLM 回傳純文字（無 tool_calls）回傳 final_response，stopped_by_budget=False
Budget 耗盡iteration >= max_iterations回傳 budget_msg，stopped_by_budget=True
中斷信號使用者 Ctrl+C 或 Gateway 中斷事件Part 2 加入 interruptible API call 機制

Budget 的設定建議

場景建議 max_iterations原因
簡單查詢（RAG、問答）5–10通常 1-3 次 tool call 就夠
一般編程任務25（預設）可能需要多次迭代修復
複雜研究任務50–100需要多輪搜尋和整合
子代理（Delegation）15子代理通常有明確邊界的任務
設計決策日誌 #003

決策：Budget 耗盡時回傳特殊訊息而非拋出 exception。
理由：在 Gateway 場景，exception 會導致整個 Gateway 程序崩潰。 把「budget 耗盡」視為一種合法的結束狀態，讓呼叫方可以根據 stopped_by_budget 決定是否繼續、重試或通知使用者。
Hermes 的做法：同樣模式，但另外記錄到 trajectory，用於後續 RL 訓練的負樣本。

"""tests/test_part1.py — Part 1 完整驗證"""
import pytest
from agent.core import MinimalAgent

# ── Fake tool ──────────────────────────────────────────────────────

WEATHER_SCHEMA = {
    "name": "get_weather",
    "description": "Get current weather for a city.",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {
                "type": "string",
                "description": "City name, e.g. Taipei",
            }
        },
        "required": ["city"],
    },
}

def fake_weather(city: str) -> str:
    return f"{city}: 28°C, sunny, humidity 65%"

# ── Tests ──────────────────────────────────────────────────────────

def make_agent() -> MinimalAgent:
    return MinimalAgent(
        system_prompt="You are a weather assistant. Use tools to answer.",
        tool_registry={"get_weather": fake_weather},
        tool_schemas=[WEATHER_SCHEMA],
        max_iterations=10,
    )


def test_tool_call_happens():
    agent = make_agent()
    result = agent.run_conversation("What's the weather in Taipei?")
    assert result.iterations_used > 1, "Should have used at least one tool call"


def test_normal_termination():
    agent = make_agent()
    result = agent.run_conversation("What's the weather in Tokyo?")
    assert not result.stopped_by_budget


def test_response_contains_weather():
    agent = make_agent()
    result = agent.run_conversation("What's the weather in London?")
    resp = result.final_response.lower()
    assert any(w in resp for w in ["28", "sunny", "london", "°c"])


def test_role_alternation():
    """驗證 history 的 role 交替規則沒有被違反。"""
    agent = make_agent()
    agent.run_conversation("Weather in Paris?")

    prev_role = None
    for msg in agent.history:
        role = msg["role"]
        if role == "tool":
            # tool 訊息前一定是 assistant（含 tool_calls）
            assert prev_role == "assistant" or prev_role == "tool"
        elif role == "assistant":
            assert prev_role in ("user", "tool")
        elif role == "user":
            assert prev_role == "assistant" or prev_role is None
        prev_role = role


def test_budget_stops_loop():
    """Budget 機制：max_iterations=2 強制停止無窮迴圈。"""
    # 這個 tool 永遠回傳「繼續」，迫使 LLM 一直呼叫 tool
    # 但我們把 budget 設很低，確認它會停止
    agent = MinimalAgent(
        system_prompt="Always call get_weather before answering.",
        tool_registry={"get_weather": fake_weather},
        tool_schemas=[WEATHER_SCHEMA],
        max_iterations=2,  # 很小的 budget
    )
    result = agent.run_conversation("Keep checking weather for many cities.")
    assert result.iterations_used <= 2


if __name__ == "__main__":
    pytest.main(["tests/test_part1.py", "-v"])
