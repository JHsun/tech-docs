同時存在時的優先序

同時有 ~/.tofurc 與 ~/.terraformrc 時，OpenTofu 優先讀 ~/.tofurc，不會合併兩個檔案。在 XDG 模式下完全不讀 .terraformrc。同時跑 OpenTofu 與 Terraform 的開發機，建議內容寫在 ~/.terraformrc，OpenTofu 會以 fallback 方式讀到。

用環境變數指定自訂位置

Bash 
# 用環境變數指向自訂位置（檔名必須是 *.tfrc）
export TF_CLI_CONFIG_FILE="/etc/myorg/opentofu/team.tfrc"

# 確認 OpenTofu 找到
tofu version
# 如果有 plugin_cache_dir 等設定，會印出來

Windows 注意事項

Windows Explorer 隱藏副檔名陷阱

Windows Explorer 預設隱藏副檔名。你看到 tofu.rc 但實際是 tofu.rc.txt——OpenTofu 不認。請用 PowerShell 或 cmd 跑 dir 確認檔名。

3. 設定檔完整語法

CLI 設定檔用 HCL 語法（與 .tf 檔同），但不能用 expression 或函式呼叫——只能是字面值。

HCL · ~/.tofurc 完整範例 
# 1. Plugin cache（強烈建議設）
plugin_cache_dir = "$HOME/.terraform.d/plugin-cache"

# 2. Private registry token
credentials "registry.example.com" {
  token = "your-api-token"
}

credentials "app.terraform.io" {
  token = "tfe-token-here"
}

# 3. Credentials helper（動態取 token）
credentials_helper "vault" {
  args = ["get-token"]
}

# 4. OCI registry 認證（1.10+）
oci_default_credentials {
  discover_ambient_credentials = true
}

oci_credentials "ghcr.io" {
  username = "myuser"
  password = "ghp_xxxxx"
}

# 5. Provider 安裝行為
provider_installation {
  filesystem_mirror {
    path    = "/opt/providers"
    include = ["registry.example.com/*/*"]
  }

  direct {
    exclude = ["registry.example.com/*/*"]
  }
}

# 6. 關閉 checkpoint 通知
disable_checkpoint = true

4. credentials block 與 TF_TOKEN_xxx

credentials block 用於 OpenTofu 自有的「服務發現協定」（service discovery）——主要是 module/provider registry 與 TACOS 服務（Terraform Cloud/Enterprise）。

方式 1：credentials block（簡單但有風險）

HCL · ~/.tofurc 
credentials "registry.example.com" {
  token = "your-api-token-here"
}

credentials "app.terraform.io" {
  token = "tfe-token-here"
}

明文 token 的風險

把 token 寫在設定檔有兩個問題：① 機器被盜時 token 直接外洩；② 容易被誤 commit 進 git。本地開發可暫用，但 CI/CD 永遠該用環境變數。

方式 2：TF_TOKEN_xxx 環境變數（CI/CD 推薦）

OpenTofu 認識 TF_TOKEN_<hostname> 環境變數，自動視為對該 hostname 的 bearer token。

Hostname環境變數
app.opentofu.orgTF_TOKEN_app_opentofu_org
registry.example.comTF_TOKEN_registry_example_com
app.terraform.ioTF_TOKEN_app_terraform_io
含連字號 my-registry.comTF_TOKEN_my__registry_com（連字號 → 雙底線）
非 ASCII 字元先轉 punycode（xn--...）
Bash · TF_TOKEN 範例 
# 個人 dev 機（從 secret store 動態取得）
export TF_TOKEN_registry_example_com=$(secret-tool lookup registry token)

# CI/CD（從 secrets 注入）
# GitHub Actions：
# env:
#   TF_TOKEN_registry_example_com: ${{ secrets.REGISTRY_TOKEN }}

# 跑 init 會自動帶入認證
tofu init

命名規則完整說明

  • 句點 → 底線：app.opentofu.org → TF_TOKEN_app_opentofu_org
  • 連字號 → 雙底線：my-reg.com → TF_TOKEN_my__reg_com
  • 非 ASCII → punycode：例えば.com 先轉 xn--r8j3dr99h.com 再寫成 TF_TOKEN_xn--r8j3dr99h_com
  • 多個變數對應同一 hostname 時，最後設定的勝出

tofu login：互動式登入

本地開發機可以用 tofu login 走 OAuth flow，自動把 token 存到 ~/.terraform.d/credentials.tfrc.json：

Bash 
tofu login app.opentofu.org
# 開瀏覽器走 OAuth，授權後 token 自動寫入

# 之後 init / 引用該 hostname 的 module 都會自動帶 token

tofu logout app.opentofu.org   # 清除

5. credentials_helper：動態取得 token

對於更精細的需求（從 Vault、AWS Secrets Manager 動態取 token），用 credentials_helper。

helper 的機制

OpenTofu 在需要某 hostname 的 token 時，會：

  1. 先看 credentials block 是否有顯式定義
  2. 沒有的話，呼叫 helper 程式 tofu-credentials-<name>（PATH 中），把 hostname 用 JSON 從 stdin 傳入
  3. helper 從 stdout 回傳 JSON 格式的 credentials
  4. OpenTofu 把該 token 用於 API 呼叫

~/.tofurc 設定

HCL · ~/.tofurc 
credentials_helper "vault" {
  args = ["get-token"]
}

實作 tofu-credentials-vault helper

Bash · /usr/local/bin/tofu-credentials-vault 
#!/bin/bash
# tofu-credentials-vault
# OpenTofu 會用 stdin 送入 JSON: {"hostname": "registry.example.com"}
# 必須以 JSON 從 stdout 回傳: {"token": "xxx"}

set -e

# 讀取請求
REQUEST=$(cat)
HOSTNAME=$(echo "$REQUEST" | jq -r '.hostname')

# 從 Vault 取得 token
TOKEN=$(vault kv get -field=token "secret/registry/${HOSTNAME}")

if [ -z "$TOKEN" ]; then
  echo "{}" # 沒 token 就回空 JSON，OpenTofu 會 fallback
  exit 0
fi

# 回傳 credentials
echo "{\"token\": \"${TOKEN}\"}"
Bash · 安裝 
chmod +x /usr/local/bin/tofu-credentials-vault

# OpenTofu 會在 PATH 中找 tofu-credentials-vault 或 terraform-credentials-vault
which tofu-credentials-vault

credentials helper 的優勢

① Token 永遠不在磁碟上明文存在；② 自動 rotation（每次 init 都拿新的）；③ 配 SSO / Vault / AWS Secrets Manager 集中管理；④ 個人不需手動管理 ~/.tofurc。建議大型團隊採用。

6. OCI Registry 認證

OpenTofu 1.10+ 支援從 OCI registry 安裝 module 與 provider（第 10、11 章）。OCI 認證有獨立的設定 block。

方式 1：複用既有 docker / podman 認證（推薦）

OpenTofu 預設會讀取機器上既有的 OCI 認證檔（~/.docker/config.json、~/.config/containers/auth.json）：

Bash · 用 docker login 後 OpenTofu 自動可用 
# 標準的 OCI 登入流程
echo "$GHCR_TOKEN" | docker login ghcr.io -u USERNAME --password-stdin

# OpenTofu 會自動讀 ~/.docker/config.json
# 拉 OCI module 不需額外設定
tofu init   # 自動使用該認證

方式 2：明確在 ~/.tofurc 設定

HCL · ~/.tofurc 
# 預設 OCI credentials 行為
oci_default_credentials {
  discover_ambient_credentials = true   # 預設值，會找 docker / podman 設定

  # 如果只想用某些 docker config 檔，可指定
  docker_style_config_files = [
    "/etc/myorg/oci-auth.json",
  ]
}

# 特定 OCI repository 的明確認證
oci_credentials "ghcr.io" {
  username = "myuser"
  password = "ghp_xxxxx..."

  # 或用 access token + refresh token
  # access_token  = "..."
  # refresh_token = "..."
}

# 子路徑可以更細的認證
oci_credentials "ghcr.io/myorg" {
  username = "ci-bot"
  password = "ghp_yyyyy..."
}

方式 3：CI 環境用 docker login

YAML · GitHub Actions 
- name: Login to GHCR
  run: |
    echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io \
      -u ${{ github.actor }} --password-stdin

- name: OpenTofu init (用到 OCI module)
  run: tofu init
  # 自動讀取 docker login 的認證

7. provider_installation：mirror 設定

第 11 章已詳述。這裡列出 CLI 設定檔的完整語法：

四種安裝方式

方式用途
direct從 origin registry 直接下載（預設）
filesystem_mirror從本機目錄安裝
network_mirror從 HTTP mirror 服務安裝
oci_mirror從 OCI registry 安裝（1.10+）
dev_overrides本地開發 provider 用，不檢查版本與 hash

常見配置範例

① 純 direct（預設行為，明確寫出來）

HCL 
provider_installation {
  direct {
    # include = ["*/*"]   # 預設全部
  }
}

② Air-gapped：純 filesystem mirror

HCL · 完全離線 
provider_installation {
  filesystem_mirror {
    path    = "/opt/opentofu/providers"
    include = ["*/*"]
  }
  direct {
    exclude = ["*/*"]   # 完全不從 origin 下載
  }
}

③ 混合：內部 provider 從 mirror、其他從 direct

HCL · 混合策略 
provider_installation {
  filesystem_mirror {
    path    = "/opt/opentofu/providers"
    include = ["registry.example.com/myorg/*"]
  }
  direct {
    exclude = ["registry.example.com/myorg/*"]
  }
}

④ Network mirror（HTTP 服務）

HCL 
provider_installation {
  network_mirror {
    url     = "https://provider-mirror.mycompany.com/"
    include = ["*/*"]
  }
}

⑤ OCI mirror（1.10+ 獨家）

HCL · 從 OCI 拉 provider 
provider_installation {
  oci_mirror {
    repository_template = "ghcr.io/myorg/${type}"
    include             = ["registry.opentofu.org/hashicorp/*"]
  }
  direct {
    exclude = ["registry.opentofu.org/hashicorp/*"]
  }
}

repository_template 中的變數：

  • ${hostname}：來源 registry hostname
  • ${namespace}：provider namespace（如 hashicorp）
  • ${type}：provider name（如 aws）

⑥ dev_overrides（給 provider 開發者）

HCL · 用本地開發中的 provider 取代 registry 
provider_installation {
  dev_overrides {
    "myorg/myprovider" = "/Users/me/code/terraform-provider-myorg/bin"
  }

  # 仍要保留 direct，否則其他 provider 裝不了
  direct {}
}

dev_overrides 的注意事項

① 完全跳過版本約束與 hash 檢查；② 用了會強制重 init 且發 warning；③ 絕對不要在 production 機器上設定；④ 改完設定要記得移除。

8. plugin_cache_dir：加速 init

每個專案 init 都重新下載 provider 浪費時間與頻寬。設定全域 cache，不同專案能共用同版本 provider。

HCL · ~/.tofurc 
plugin_cache_dir = "$HOME/.terraform.d/plugin-cache"
Bash · 或用環境變數 
export TF_PLUGIN_CACHE_DIR="$HOME/.terraform.d/plugin-cache"
mkdir -p "$TF_PLUGIN_CACHE_DIR"

實際效益

場景無 cache有 cache
單一 provider，第一次 init下載一次下載一次（建立 cache）
新專案，相同 provider 版本再下載一次從 cache 拷貝（瞬時）
10 個 stack 的 mono-repo10 次下載 ≈ 10 倍時間1 次下載 + 9 次拷貝

CI/CD 中的 cache

CI runner 每次都是新環境，cache 無效。解法：用 CI 內建的 cache 機制把 plugin-cache 目錄放進去：

YAML · GitHub Actions cache 
- name: Cache OpenTofu Plugins
  uses: actions/cache@v4
  with:
    path: ~/.terraform.d/plugin-cache
    key: tofu-plugins-${{ hashFiles('**/.terraform.lock.hcl') }}
    restore-keys: |
      tofu-plugins-

- name: Setup OpenTofu
  uses: opentofu/setup-opentofu@v2
  with:
    tofu_version: 1.11.6

- name: Init
  run: |
    mkdir -p ~/.terraform.d/plugin-cache
    export TF_PLUGIN_CACHE_DIR=~/.terraform.d/plugin-cache
    tofu init -lockfile=readonly

9. CI/CD 中的 token 管理

原則：永遠用環境變數，永不用 ~/.tofurc

CI runner 的 file system 不安全（共享、log 可能洩漏）。所有 secret 從 CI 平台的 secrets store 注入環境變數。

GitHub Actions 標準模式

YAML · .github/workflows/tofu.yml 
name: OpenTofu

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read
  id-token: write     # OIDC 用
  pull-requests: write # PR comment 用

jobs:
  plan:
    runs-on: ubuntu-latest

    env:
      # AWS 用 OIDC，不需要 access key
      # 內部 provider registry token
      TF_TOKEN_registry_example_com: ${{ secrets.REGISTRY_TOKEN }}

      # 強制非互動
      TF_INPUT: "0"
      TF_IN_AUTOMATION: "true"

    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS via OIDC
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789012:role/GitHubActionsRole
          aws-region: us-east-1

      - name: Login to GHCR (for OCI modules/providers)
        run: echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io \
          -u ${{ github.actor }} --password-stdin

      - uses: opentofu/setup-opentofu@v2
        with:
          tofu_version: 1.11.6

      - name: Tofu init
        run: tofu init -lockfile=readonly -no-color

      - name: Tofu plan
        run: tofu plan -no-color -out=tfplan.bin -detailed-exitcode

      - name: Upload plan
        uses: actions/upload-artifact@v4
        with:
          name: tfplan
          path: tfplan.bin
          retention-days: 7

GitLab CI 模式

YAML · .gitlab-ci.yml 
image: ghcr.io/opentofu/opentofu:1.11.6

variables:
  TF_INPUT: "0"
  TF_IN_AUTOMATION: "true"
  # GitLab managed terraform state
  TF_TOKEN_gitlab_com: $CI_JOB_TOKEN
  # 內部 registry
  TF_TOKEN_registry_internal: $REGISTRY_TOKEN

stages: [validate, plan, apply]

validate:
  stage: validate
  script:
    - tofu init -backend=false -lockfile=readonly
    - tofu fmt -check -recursive
    - tofu validate

plan:
  stage: plan
  script:
    - tofu init -lockfile=readonly
    - tofu plan -out=tfplan.bin -detailed-exitcode
  artifacts:
    paths: [tfplan.bin]
    expire_in: 7 days

apply:
  stage: apply
  script:
    - tofu init -lockfile=readonly
    - tofu apply tfplan.bin
  when: manual
  only: [main]

10. 主流雲端 provider 的認證模式

注意：provider 的認證（AWS、Azure、GCP API）不是 CLI credentials block 的範疇。Provider 認證走自己的機制，由各 provider 定義。

AWS：OIDC + assume_role（CI 推薦）

HCL · provider 設定（無 secret） 
provider "aws" {
  region = "us-east-1"
  # 完全不寫 access_key/secret_key
  # CI 透過 OIDC 取得短期 STS credentials
}
YAML · GitHub Actions OIDC 
- name: Configure AWS Credentials
  uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::123456789012:role/GitHubActionsRole
    role-session-name: GitHubActions-${{ github.run_id }}
    aws-region: us-east-1

Azure：OIDC（federated credentials）

HCL 
provider "azurerm" {
  features {}
  use_oidc = true
  # ARM_CLIENT_ID、ARM_TENANT_ID、ARM_SUBSCRIPTION_ID 從環境變數
}

GCP：Workload Identity Federation

HCL 
provider "google" {
  project = "my-project"
  region  = "us-central1"
  # GOOGLE_APPLICATION_CREDENTIALS 由 OIDC step 設定
}

11. 常見陷阱與最佳實踐

陷阱 1：把 token 寫在 ~/.tofurc 然後 ~/.tofurc 進了 dotfiles repo

個人 dotfiles 同步是常見做法。~/.tofurc 含 token 時不要 commit，加到 .gitignore 或用 git-secret 加密。

陷阱 2：TF_TOKEN_xxx 連字號處理錯

Bash 
# ❌ hostname my-reg.com 寫成
TF_TOKEN_my-reg_com=...   # bash 不支援 = 前的連字號（實際根本是無效變數名）

# ✅ 連字號用雙底線
TF_TOKEN_my__reg_com=...

陷阱 3：Windows 上 ~/.tofurc 不認

Windows 應該是 %APPDATA%\opentofu\tofu.rc，路徑與檔名都不同。常見錯誤是把 Linux 的 ~/.tofurc 直接複製到 Windows。

陷阱 4：cache 目錄沒先建立

Bash 
# ❌ 設了 cache_dir 但目錄不存在
export TF_PLUGIN_CACHE_DIR="$HOME/.terraform.d/plugin-cache"
tofu init   # OpenTofu 會抱怨找不到目錄

# ✅ 先建立
mkdir -p "$TF_PLUGIN_CACHE_DIR"
tofu init

陷阱 5：dev_overrides 沒移除

provider 開發完設定改完忘了移除 dev_overrides。下個專案 init 時跑出莫名其妙的版本（你電腦上 build 的開發版）。每次寫完 dev_overrides 設定記得移除。

陷阱 6：CI 同時設 ~/.tofurc 與環境變數

環境變數優先於 credentials block。如果 CI 中兩者都設，環境變數會勝出。只用一種，不要混用，避免混淆。

最佳實踐速查

主題建議
本地開發 token用 tofu login 或 credentials_helper
CI/CD token用 TF_TOKEN_xxx 環境變數
Plugin cache必開：TF_PLUGIN_CACHE_DIR
OCI 認證用 docker login，OpenTofu 自動讀取
Air-gapped 環境filesystem_mirror + direct exclude
內部 providerOCI mirror（1.10+）或 filesystem mirror
Provider 開發dev_overrides，記得用完移除
跨 OS 開發團隊各 OS 用對應的設定路徑，內容用 ~/.terraformrc fallback
雲端 API 認證OIDC 短期憑證，絕不用永久 access key
secrets 管理從 Vault / AWS Secrets Manager / SSO 拉取，不寫在設定檔
~/.tofurc 同步不 commit、用 1Password / git-secret 加密

12. 本章重點與練習

重點回顧

  • CLI 設定影響你機器上跑的所有 OpenTofu 操作（vs 專案 .tf 設定僅影響該專案）
  • 位置：Linux/macOS ~/.tofurc（後備 ~/.terraformrc）；Windows %APPDATA%\opentofu\tofu.rc
  • TF_CLI_CONFIG_FILE 環境變數可指定自訂位置（檔名須 *.tfrc）
  • credentials block 用於 module/provider registry；CI 中改用 TF_TOKEN_<hostname> 環境變數
  • 命名規則：句點→底線、連字號→雙底線、非 ASCII→punycode
  • credentials_helper 動態取 token，配合 Vault / SSO 集中管理
  • oci_credentials / oci_default_credentials（1.10+）；最簡做法是 docker login，OpenTofu 自動讀
  • provider_installation：5 種方式（direct / filesystem_mirror / network_mirror / oci_mirror / dev_overrides）
  • plugin_cache_dir 必開，CI 配合 actions/cache 共享
  • CI/CD 永遠用環境變數注入 secret，永不用 .tofurc 寫死
  • 雲端 provider 認證走自己機制（OIDC 推薦），與 CLI credentials 是兩件事
⚡ 動手實作 · Hands-on Lab 16

CLI 設定全方位演練

  1. 練習 A · plugin cache：建立 ~/.tofurc 設 plugin_cache_dir，刪掉某專案的 .terraform/ 後 tofu init，觀察 cache 目錄；建立另一個專案用相同 provider，再次 init，確認從 cache 拷貝（速度快很多）
  2. 練習 B · TF_TOKEN_xxx 名稱演練：寫一個 shell script，把以下 hostname 轉成正確的環境變數名：
    • app.opentofu.org
    • my-registry.example.com
    • app.terraform.io
  3. 練習 C · filesystem mirror：手動下載一個 provider zip，按照規範解壓到 /opt/providers/registry.opentofu.org/hashicorp/local/2.5.1/<OS_ARCH>/，設定 ~/.tofurc 用 mirror，刪 .terraform/ 後 init 確認從 mirror 載入
  4. 練習 D · credentials_helper：寫一個 shell script tofu-credentials-test，從 stdin 讀 hostname JSON 後從 stdout 印 fake token；放到 /usr/local/bin/；在 ~/.tofurc 設定 credentials_helper "test" {}；觀察 OpenTofu 行為（log 中可看到 helper 被呼叫）
  5. 練習 E · OCI 認證：用 docker login ghcr.io 登入後，建立一個用 oci://ghcr.io/myorg/module 的 module 引用（如有發佈過），跑 init 確認認證自動帶入
  6. 挑戰題 1 · CI mock：寫一個 shell script 模擬 GitHub Actions 跑 OpenTofu 的環境：設 TF_INPUT=0、TF_IN_AUTOMATION=true、TF_TOKEN_xxx，跑 fmt → validate → plan
  7. 挑戰題 2 · 多平台 lock：跑 tofu providers lock -platform=linux_amd64 -platform=darwin_arm64 -platform=windows_amd64，看 lock 檔多平台 hash
  8. 清理 cache 與設定（rm -rf ~/.terraform.d/plugin-cache，移除測試 ~/.tofurc 設定）
