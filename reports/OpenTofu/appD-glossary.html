A

詞彙中文 / 解釋章節
Acceptance Test驗收測試。Provider 開發中對真實 cloud API 的整合測試。Ch 20
Alias別名。同一 provider 多個設定（多 region、多 account）的區分機制。Ch 11
Apply套用。實際執行 plan 計畫的變更，會修改雲端資源並寫入 state。Ch 3, 15
Argument參數。HCL block 內的 key = value 結構。Ch 5
AtlantisOSS 自架的 PR-driven OpenTofu/Terraform 自動化工具。透過 PR comment 觸發 plan/apply。Ch 21
Audit Log稽核日誌。記錄誰在何時對什麼資源做了什麼操作，合規必備。Ch 22
Auto-approve自動同意。tofu apply -auto-approve 跳過互動確認，CI/CD 中常用。Ch 15, 21

B

詞彙中文 / 解釋章節
Backend後端。state 儲存的位置，如 S3、GCS、Azure Blob、PostgreSQL 等。Ch 12
Backend ProtocolBackend 協定。OpenTofu 與 state backend 互動的介面定義。Ch 20
Blast Radius爆炸半徑。一次變更可能影響的資源範圍。Production 設計核心考量。Ch 22
Block區塊。HCL 中的命名語法單元，如 resource "x" "y" { ... }。Ch 5
Blue-Green Deployment藍綠部署。建立完整的新環境（綠），驗證後把流量從舊環境（藍）切過去。Ch 22
BUSL（Business Source License）HashiCorp 2023 年改用的授權，限制商業使用。是 OpenTofu fork 的觸發點。Ch 1

C

詞彙中文 / 解釋章節
Canary Deployment金絲雀部署。讓新版本接收一小部分流量逐步擴大，降低風險。Ch 22
Check Block檢查區塊。OpenTofu 1.5+ 推出的軟驗證機制，失敗只 warning 不擋 apply。Ch 13
Checkov專為 IaC 的靜態分析工具，內建上千條安全規則。Ch 21
CIDR（Classless Inter-Domain Routing）網段表示法，如 10.0.0.0/16。OpenTofu 有 cidrsubnet 等函式。Ch 8
CI/CD持續整合 / 持續部署。IaC CI/CD 與 app CI/CD 有本質差異（stateful、序列）。Ch 21
Cloud BlockHCP Terraform 專用的 backend 設定，OpenTofu 不支援。Ch 14
ConftestOPA 的 wrapper CLI，用 Rego 規則檢查 plan JSON。Ch 21
Configuration Aliases設定別名。Module 接受 alias provider 的宣告機制。Ch 11
CosignOCI artifact 簽章工具，可用 keyless（OIDC）簽章模式。Ch 18
Count計數。Meta-argument，建立多個同質資源。順序敏感，建議用 for_each 取代。Ch 9
create_before_destroy先建後刪。lifecycle 設定，避免重建資源時的停機。Ch 9, 22
Credentials Helper動態取 token 的 helper 程式，整合 Vault / SSO 等。Ch 16
Custom Conditions自訂條件。validation / precondition / postcondition / check 四種驗證機制統稱。Ch 13

D

詞彙中文 / 解釋章節
DAG（Directed Acyclic Graph）有向無環圖。OpenTofu 的 resource dependency graph 結構，所有操作都基於它。Ch 19
Data Source資料源。從外部讀取資料但不管理生命週期，用 data "TYPE" "NAME" 宣告。Ch 6
Default Tags預設標籤。Provider block 的 default_tags，自動套用到所有資源。Ch 11, 22
Default Workspace預設工作空間。每個專案啟動就有的 workspace，名為 default，不能刪除。Ch 17
Deferred Tools延遲載入工具。本書範圍以外的概念。—
depends_on顯式依賴。Meta-argument，明確指定資源依賴關係（不透過屬性引用時用）。Ch 9
deprecated 屬性OpenTofu 1.11+ variable / output 的屬性，標記為 deprecated 給遷移期。Ch 13, 14
Destroy銷毀。tofu destroy 銷毀當前 workspace 中所有受管資源。Ch 15
dev_overrides開發者覆寫。本機開發 provider 用，跳過版本與 hash 檢查。Ch 16, 20
Drift漂移。實際雲端狀態與 IaC 設定不同步（通常是有人在 console 改了）。Ch 12, 22
Drift Detection漂移偵測。用 tofu plan -refresh-only + 排程主動偵測 drift。Ch 22
Dynamic Block動態 block。用 dynamic "name" { for_each = ... } 動態產生 block。Ch 8

詞彙中文 / 解釋章節
each.key / each.valuefor_each 的 iteration 變數。Ch 9
enabled Meta-argumentOpenTofu 1.11+ 獨家。簡潔取代 count = ? 1 : 0 模式。Ch 9, 14
Encryption Block加密區塊。OpenTofu 1.7+ 獨家的 native state encryption 設定。Ch 12
env0SaaS TACOS 平台，支援 OpenTofu。Ch 21
Ephemeral暫存的。OpenTofu 1.10+ alpha、1.11+ 完整實作的 secret 不寫入 state 機制。Ch 13, 22
Ephemeral Resource暫存資源。ephemeral "TYPE" "NAME" { ... } 宣告，僅在 phase 內存活。Ch 13
Ephemeral Output / Variable暫存輸出/變數。標 ephemeral = true，不寫入 state。Ch 13
Expression表達式。HCL 中可被求值的部分，如 var.x + 1、[for x in y : ...]。Ch 8

F

詞彙中文 / 解釋章節
Filesystem Mirror檔案系統鏡像。Provider 從本機目錄安裝（air-gapped 用）。Ch 11, 16
FinOpsFinancial Operations。雲端成本管理實踐，OpenTofu 整合 Infracost。Ch 22
FQCN（Fully Qualified Collection Name）完整命名空間，但本書 OpenTofu 上下文中對應 provider source 的完整 hostname/namespace/name 格式。Ch 11
force-unlock強制解鎖。tofu force-unlock LOCK_ID，core 武器級指令。Ch 12
ForceNew強制重建。某些屬性改變必須 destroy + create（如 AMI ID）。Plan 顯示 forces replacement。Ch 19
for_eachMeta-argument，從 set/map 動態建立資源。比 count 更穩定（key 不變即不重建）。Ch 9
fork分叉。從另一個專案複製出來獨立發展。OpenTofu 是 Terraform 1.5.x 的 fork。Ch 1

G

詞彙中文 / 解釋章節
GHCR（GitHub Container Registry）GitHub 的 OCI registry，OpenTofu 1.10+ 可用來分發 module 與 provider。Ch 18
GitOps把 Git 當作基礎設施與部署的單一事實來源。Ch 21
go-getterHashiCorp 寫的多源下載 library，OpenTofu 用它從 Git/HTTP/S3/GCS 拉 module。Ch 10
Graph圖。OpenTofu 內部表示資源依賴的 DAG 結構。Ch 19
gRPCGoogle 開發的 RPC 框架。OpenTofu Core 與 provider 透過 gRPC 通訊。Ch 19

H

詞彙中文 / 解釋章節
handler處理器。一般指處理特定事件/錯誤的程式碼，OpenTofu 中常見於 provider 開發。Ch 20
Hands-on Lab動手實作。每章末尾的練習章節。全書
HashiCorpTerraform、Vault、Consul 等的開發公司。2023 年改 BUSL 授權引發 OpenTofu fork。Ch 1
HCL（HashiCorp Configuration Language）HashiCorp 設定語言。OpenTofu 使用的主要語言。Ch 5
HCP TerraformHashiCorp Cloud Platform 的 Terraform 服務（前 Terraform Cloud）。OpenTofu 不支援。Ch 4, 21
Heredoc多行字串語法，<<-EOT ... EOT。Ch 5
HTTP BackendHTTP 後端。實作幾個 HTTP endpoint 即可當 OpenTofu state backend。Ch 20

I

詞彙中文 / 解釋章節
IaC（Infrastructure as Code）基礎設施即程式碼。用程式碼描述基礎設施的方法論。Ch 1
idempotent冪等。多次執行結果一樣。OpenTofu apply 是 idempotent 的。Ch 3
Identity Churn身份顛簸。Production 失敗模式之一：for_each key 不穩定導致頻繁 destroy/create。Ch 22
ignore_changes忽略變更。lifecycle 設定，讓 OpenTofu 不關心特定屬性的外部變更。Ch 9
Implicit Edge / Explicit Edge隱式邊 / 顯式邊。Graph 中的依賴關係，前者來自屬性引用，後者來自 depends_on。Ch 19
Import Block匯入區塊。OpenTofu 1.5+ 推出，用 import { to = ..., id = ... } 宣告式納管既有資源。Ch 13
InfracostOSS 雲端成本估算工具，整合 OpenTofu plan 算月成本。Ch 22
Init初始化。tofu init 下載 provider/module、初始化 backend、寫 lock 檔。Ch 3, 15
IRSA（IAM Roles for Service Accounts）EKS 上 K8s service account 對應 AWS IAM role 的機制。Ch 16

L

詞彙中文 / 解釋章節
lifecycle生命週期。Resource block 內的 lifecycle block，控制 create_before_destroy、prevent_destroy、ignore_changes 等。Ch 9
Lineage血統。State 檔內的 UUID，防止把 state A 寫到 state B 的位置。Ch 12, 19
Local（block）本地值。locals { ... } 內定義的可重用 expression。Ch 7
Local Backend本地後端。State 存在本機 terraform.tfstate，個人專案用。Ch 12
Lock 檔鎖定檔。.terraform.lock.hcl，紀錄 provider 版本與 hash，必須 commit。Ch 11
Lock（state）狀態鎖。Apply 時取得，避免兩人同時寫 state。Ch 12

M

詞彙中文 / 解釋章節
managed_master_user_passwordAWS RDS 屬性，讓 AWS 管理 DB 密碼，密碼不進 state。Ch 22
Meta-Argument元參數。所有 resource/module 都能用的特殊參數，如 count、for_each、provider、lifecycle、depends_on、enabled。Ch 9
Mirror鏡像。Provider 安裝來源（filesystem / network / OCI mirror）。Ch 11, 16, 18
Module模組。可重用的 .tf 檔案集合，OpenTofu 模組化的基本單元。Ch 10
moved Block搬移區塊。重構 resource 名稱、搬進 module 時用，自動遷移 state 不重建資源。Ch 13
Monorepo單一倉庫。多個 stack 放同一 git repo。Ch 21
MPL（Mozilla Public License）OpenTofu 採用的開源授權，1.5.x 之前的 Terraform 也用 MPL。Ch 1

N

詞彙中文 / 解釋章節
Native State Encryption原生 state 加密。OpenTofu 1.7+ 獨家功能，client-side 加密 state。Ch 12
Network Mirror網路鏡像。Provider 從 HTTP mirror 服務安裝。Ch 11, 16

O

詞彙中文 / 解釋章節
OCI（Open Container Initiative）開放容器標準。OpenTofu 1.10+ 支援從 OCI registry 分發 module 與 provider。Ch 18
OIDC（OpenID Connect）身份驗證協定。CI/CD 中對 cloud provider 取得短期憑證的標準做法。Ch 16, 21
OpenBaoHashiCorp Vault 的社群 fork，OpenTofu 友善的 secret 管理工具。Ch 13
OpenTelemetry（OTEL）可觀測性標準。OpenTofu 1.10+ 內建 tracing 支援。Ch 22
OpenTofu本書主題。Terraform 1.5.x 的 OSS fork，受 Linux Foundation 治理。Ch 1
OPA（Open Policy Agent）通用 policy engine。Spacelift 與 conftest 都基於 OPA。Ch 21
oras CLIOCI registry 操作工具。推送 module / provider 到 OCI 用。Ch 18
Output輸出。output "x" { value = ... } 暴露給其他 stack 或 module 使用。Ch 7

P

詞彙中文 / 解釋章節
Parallelism並行度。tofu apply -parallelism=N，預設 10。Ch 19
Partial Apply部分套用。Apply 跑到一半失敗，state 紀錄部分已建立的資源。Ch 22
Partial Config部分設定。Backend block 只寫部分參數，其餘用 -backend-config 補。Ch 12
Plan計畫。tofu plan 顯示要做什麼變更，但不實際執行。Ch 3, 15
Plan Artifact / Plan FilePlan 產出檔，tofu plan -out=tfplan.bin。包含 sensitive 資料。Ch 21
playbook劇本。一般指 incident 處理或維運的標準流程文件。Ch 22
Plugin Cache外掛快取。Provider 全域 cache 目錄，加速 init。Ch 16
Plugin Frameworkterraform-plugin-framework。新一代 provider SDK，OpenTofu 完全相容。Ch 20
Policy as Code策略即程式碼。把規則寫成可版控的程式碼，plan 階段檢查違反。Ch 21
Postcondition後置條件。資源建立後驗證最終狀態，可用 self 變數。Ch 13
PR-driven WorkflowPR 驅動工作流程。所有變更走 PR review、CI plan、人工 approve、merge 後 apply。Ch 21
Precondition前置條件。資源建立前驗證假設為真。Ch 13
prevent_destroy防誤刪。lifecycle 設定，OpenTofu refuse 銷毀標記的資源。Ch 9
Provider提供者。OpenTofu 與外部 API 的橋樑（AWS、Azure、Datadog 等）。獨立 binary。Ch 11
provider for_eachOpenTofu 1.9+ 獨家。動態產生多個 provider 實例。Ch 11
Provider-defined FunctionsProvider 定義函式。OpenTofu 1.7+ 推出，輕量擴充無需完整 resource。Ch 20
Punycode把 IDN 轉成 ASCII 的編碼。TF_TOKEN_xxx 對非 ASCII hostname 用。Ch 16

R

詞彙中文 / 解釋章節
Refresh重新整理。讀取雲端當前狀態同步到 in-memory state。Ch 12, 15
refresh-only只 refresh。tofu plan -refresh-only，不計算變更，drift 偵測用。Ch 12, 22
Registry註冊中心。OpenTofu Public Registry / Private Registry / OCI Registry 三大類。Ch 18
RegoOPA 的 policy 語言。Conftest 規則用 Rego 寫。Ch 21
Removed Block移除區塊。OpenTofu 1.7+ 推出，宣告式從 state 移除（搭配 destroy = false 保留實體）。Ch 13
replace_triggered_by觸發替換。lifecycle 設定，引用屬性變化觸發資源重建。Ch 9
Resource資源。resource "TYPE" "NAME" { ... } 宣告，OpenTofu 管理的最小單位。Ch 6
Resource Module / Service Module資源模組 / 服務模組。500-line 原則的兩層 module 設計。Ch 22
required_providers必要提供者。terraform {} 內宣告依賴的 provider source 與 version。Ch 11
required_version必要版本。OpenTofu 自身的版本約束。Ch 14
RPO（Recovery Point Objective）恢復點目標。災難復原最多容忍多少資料遺失。Ch 22

S

詞彙中文 / 解釋章節
ScalrSaaS TACOS 平台，支援 OpenTofu。Ch 21
SDK（Software Development Kit）軟體開發套件。Provider 開發兩個 SDK：terraform-plugin-framework（推薦）與 SDKv2（legacy）。Ch 20
SemVer（Semantic Versioning）語意化版本。MAJOR.MINOR.PATCH。Ch 14
Sensitive敏感的。Variable / output 標 sensitive = true，不顯示在 CLI 但仍寫入 state。Ch 7
Service Discovery服務發現。Registry 透過 /.well-known/terraform.json 暴露 API endpoint。Ch 20
Splat Expression展開表達式。aws_instance.web[*].id 取列表中所有資源的某屬性。Ch 8
SOPS（Secrets OPerationS）secret 加密工具，加密 tfvars 後 commit。Ch 22
Spacelift專業 TACOS 平台，提供 stack dependency / OPA policy / drift detection。Ch 21
Stack堆疊。一個獨立的 OpenTofu 工作目錄與 state 對應的單元。全書
State狀態。OpenTofu 紀錄受管資源的 JSON 檔，包含敏感資料。Ch 12
Static Evaluation靜態評估。OpenTofu 1.8+ 讓 backend / module source 等也能用變數。Ch 17

T

詞彙中文 / 解釋章節
TACOS（Terraform Automation and Collaboration Software）Terraform 自動化協作平台統稱：Atlantis / Spacelift / env0 / Scalr 等。Ch 21
Tag Policy標籤政策。強制資源帶必要 tag（Owner、Environment、CostCenter）。Ch 22
terraform Blockterraform 區塊。OpenTofu 自身設定（required_version、backend、encryption 等）。Ch 14
terraform_remote_state跨 stack 引用 state output 的 data source。Ch 22
terraform.workspace當前 workspace 名稱的內建變數。Ch 17
tenv / tofuenvOpenTofu 版本管理工具，類似 nvm/pyenv。Ch 2
TerragruntGruntwork 出的 OpenTofu/Terraform 編排工具。1.0 版完整支援 OpenTofu。Ch 21
tflintOpenTofu/Terraform linter，靜態分析工具。Ch 21
tfplugin5 / tfplugin6Provider plugin protocol 版本。tfplugin6 是現代主流。Ch 19
TF_TOKEN_Private registry token 環境變數。連字號→雙底線、句點→底線。Ch 16
tofu testOpenTofu 1.6+ 內建測試框架，.tftest.hcl 副檔名。Ch 15
Topological Walk拓撲遍歷。Graph 處理順序，無依賴的先做、依賴關係建立順序。Ch 19

V

詞彙中文 / 解釋章節
Validation驗證。variable.validation block 限制變數值範圍。Ch 7, 13
Variable變數。variable "x" { type = ... } 宣告 module 的輸入。Ch 7
VaultHashiCorp 的 secret 管理工具。BUSL 授權後 OpenTofu 用戶建議改用 OpenBao。Ch 13
Versioning（S3）S3 物件版本控制。State 災難復原必開。Ch 12, 22

W

詞彙中文 / 解釋章節
Webhook網路勾子。Atlantis / Spacelift 等接收 git event 的 HTTP callback。Ch 21
Workspace工作空間。同一目錄、同 backend、多份 state 的機制。不適合區分 dev/prod 嚴肅環境。Ch 17
