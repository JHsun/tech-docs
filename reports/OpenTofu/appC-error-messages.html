常見錯誤訊息

把 OpenTofu 實戰中最常見的 50+ 個錯誤訊息整理成可查的故障排除手冊。每個錯誤含「症狀 → 原因 → 對策」，遇到 error 時直接搜本附錄。

錯誤分類

  1. init 階段錯誤
  2. 設定/語法錯誤
  3. plan 階段錯誤
  4. apply 階段錯誤
  5. state 與 lock 錯誤
  6. provider 錯誤
  7. module 錯誤
  8. 循環依賴錯誤

1. init 階段錯誤

Failed to query available provider packages

Plaintext · 錯誤訊息 
Error: Failed to query available provider packages
Could not retrieve the list of available versions for provider hashicorp/aws

原因：① 無網路或 DNS 問題；② Registry hostname 拼錯；③ Proxy 設定錯誤；④ Provider source 不存在；⑤ Public Registry 暫時不可用。

對策：

  • 檢查網路：curl -v https://registry.opentofu.org
  • 檢查 source 拼字（特別是大小寫）
  • 檢查 HTTP_PROXY / HTTPS_PROXY 設定
  • 用 mirror 替代：~/.tofurc 設 provider_installation { filesystem_mirror { ... } }

Inconsistent dependency lock file

Plaintext 
Error: Inconsistent dependency lock file
The given plan file was created with a different set of external dependency selections

原因：lock 檔的 hash 與當前下載 binary 不符（人為改 lock 檔、跨平台 hash 不一致）。

對策：

  • 重新產生：tofu init -upgrade
  • 跨平台問題：tofu providers lock -platform=linux_amd64 -platform=darwin_arm64 -platform=windows_amd64
  • commit 更新後的 .terraform.lock.hcl

Backend configuration changed

Plaintext 
Error: Backend configuration changed
A change in the backend configuration has been detected, which may require migrating existing state

原因：backend block 修改後未明確告知 OpenTofu 怎麼處理。

對策：依需求加 flag 重新 init：

  • 遷移 state：tofu init -migrate-state
  • 放棄遷移直接重 init：tofu init -reconfigure

Module not installed

Plaintext 
Error: Module not installed
This module is not yet installed. Run "tofu init" to install all modules required by this configuration.

原因：跑 plan / apply 但沒先 init，或新增了 module 來源後沒重 init。

對策：tofu init

Required version not satisfied

Plaintext 
Error: Unsupported OpenTofu Core version
This configuration does not support OpenTofu Core version 1.7.0.
Required version: >= 1.11.0

對策：升級 OpenTofu（用 tenv 切版本：tenv tofu install 1.11.6 && tenv tofu use 1.11.6）或降低 required_version 約束。

2. 設定/語法錯誤

Reference to undeclared resource / variable / module

Plaintext 
Error: Reference to undeclared input variable
A variable named "X" has not been declared

原因：① 變數沒在 variable {} 宣告就用；② 拼字錯；③ 在 child module 用了 root 的變數但沒透過 input 傳遞。

對策：在對應 module 的 variables.tf 宣告該變數，或修正拼字。

Argument or block definition required

Plaintext 
Error: Argument or block definition required
An argument or block definition is required here.

原因：HCL 語法錯誤，常見於：

  • 缺逗號（map / list 元素之間）
  • 多了 =（block 不需要）
  • 少了大括號
  • HCL2 與 HCL1 混用

對策：跑 tofu fmt 看格式化結果、tofu validate 找具體位置。

Invalid for_each argument

Plaintext 
Error: Invalid for_each argument
The "for_each" value depends on resource attributes that cannot be determined until apply

原因：for_each 引用了 plan 階段「未知值」（如 cloud 自動產生的 ID）。

對策：

  • 用「已知值」當 key（變數、locals、不依賴 cloud 動態的屬性）
  • 不得已時：先 apply 部分資源（-target）讓 ID 確定後再跑全部
  • 改用 count 並接受可能的 destroy/recreate

Self-reference

Plaintext 
Error: Self-referencing resource
The resource X is referencing itself, which causes a dependency cycle

對策：拆分依賴（建第二個 resource、用 data source 查詢已建立資源、用 self 在 postcondition / provisioner 中）。

Each.value cannot be used in this context

原因：在不該用 each.value 的地方用了（例如 moved block 內）。

對策：把 each.value 替換成具體值，或檢查 block 是否支援 for_each 內 context。

3. plan 階段錯誤

Forces replacement

Plaintext · plan 顯示 
# forces replacement
- aws_instance.web must be replaced
~ ami = "ami-old" -> "ami-new" # forces replacement

原因：改了某個 ForceNew 屬性（不能 in-place 修改的屬性，如 AMI、subnet_id）。

對策：

  • 確認真要重建（接受 destroy + create）
  • 不想停機：加 lifecycle { create_before_destroy = true } + 確認名稱可衝突
  • 是誤改：改回原值 plan 應顯示 No changes

Provider produced inconsistent final plan

Plaintext 
Error: Provider produced inconsistent final plan
When expanding the plan for X to include new values learned so far during apply,
provider "Y" produced an invalid new value for ATTR

原因：Provider bug——plan 階段聲明的屬性值與 apply 階段不符。

對策：

  • 升級 provider 版本
  • 提報到 provider 的 GitHub issue（附上 .tf + 完整 trace log）
  • 暫時 workaround：加 lifecycle { ignore_changes = [ATTR] }

Invalid count argument

Plaintext 
Error: Invalid count argument
The "count" value depends on resource attributes that cannot be determined until apply

對策：同 for_each 問題——用已知值，或先 -target 部分 apply。

The given plan file was created against a different state

Plaintext 
Error: Saved plan is stale
The given plan file can no longer be applied because the state was changed

原因：plan 檔產生後 state 又變了（別人 apply、drift）。

對策：重新 plan 並 review。

4. apply 階段錯誤

Resource already exists

Plaintext · 來自 cloud API 
Error: BucketAlreadyExists: The requested bucket name is not available

原因：① 雲端已有同名資源（OpenTofu 不知道）；② 之前 apply 失敗但雲端有殘留；③ 資源命名衝突全球範圍。

對策：

  • 用 import block 納管既有資源
  • 改名（S3 bucket、IAM role 等需全域唯一）
  • 到 console 確認後手動刪除殘留再 apply

Operation timed out

Plaintext 
Error: timeout while waiting for state to become 'available'

原因：雲端建立資源超時（如 RDS 建立要 10+ 分鐘、EKS 要 15 分鐘）。

對策：

  • resource 加 timeouts { create = "30m" } block
  • 檢查 cloud console 是否實際建立成功（可能是 OpenTofu 等不及而非真失敗）
  • 下次 apply 會 refresh，若雲端建好了就會被納入 state

Throttling / RequestLimitExceeded

Plaintext · AWS 範例 
Error: throttling: Rate exceeded

原因：cloud API rate limit。

對策：

  • 降低 parallelism：tofu apply -parallelism=5
  • provider 設定 retry：provider "aws" { retry_mode = "adaptive", max_retries = 10 }
  • 拆 stack（小 stack 一次跑的 API call 少）

InvalidClientTokenId / Permission Denied

Plaintext 
Error: AccessDenied: User: arn:aws:iam::xxx is not authorized to perform: ec2:CreateVpc

原因：IAM role / user 缺權限。

對策：

  • 檢查 role 的 IAM policy（用 IAM Access Analyzer / CloudTrail）
  • 確認 role 真的被 assume（aws sts get-caller-identity）
  • 檢查 SCP（service control policy）是否擋了

5. state 與 lock 錯誤

Error acquiring the state lock

Plaintext 
Error: Error acquiring the state lock
Lock Info:
  ID:        12345678-abcd-...
  Path:      myorg-tofu-state/prod/terraform.tfstate
  Operation: OperationTypeApply
  Who:       alice@laptop
  Created:   2026-04-15 10:00:00

原因：別人正在跑（最常見）、或之前的 apply 異常退出沒釋放 lock。

對策：

  • 看 Who 與 Created 時間，先確認是否真的有人在用
  • 等等再試（最常見的解決方式）
  • 確認沒人在用後：tofu force-unlock LOCK_ID（廣播一下避免衝突）

State snapshot was created by OpenTofu vX.Y

Plaintext 
Error: state snapshot was created by OpenTofu v1.11.0 which is newer than current v1.6.0

原因：state 被新版 OpenTofu 寫過，舊版不能讀。

對策：升級本機 OpenTofu 到 state 標記的版本（或更新）。

Lineage mismatch

Plaintext 
Error: state has lineage X, but current state file has lineage Y

原因：你嘗試把 state A 寫到 state B 的位置（典型錯誤：複製錯 backend 設定）。

對策：檢查 backend 設定，確認 key 路徑正確。誤操作時可從 S3 versioning 還原原版。

State file does not exist (404)

原因：第一次跑 init / 換 backend 路徑後第一次跑。

對策：正常情況——OpenTofu 會建立新 state。

State has been corrupted

原因：state 檔結構被破壞（手動編輯、寫入中斷）。

對策：

  • 從 S3 versioning 還原（必開）
  • 從本機備份還原：tofu state push backup.json
  • 最壞情況：用 import block 重建

6. provider 錯誤

Provider configuration not present

Plaintext 
Error: Provider configuration not present
To work with X.Y its original provider configuration is required, but it has been removed

原因：state 中還有資源綁定某個 provider 設定，但 .tf 中已移除該設定。

對策：

  • 把 provider block 暫時加回來，跑 destroy 或 state rm 移除資源後再移除
  • 或 tofu state rm 把孤兒資源從 state 移掉

Plugin reinitialization required

對策：tofu init

Provider produced unexpected new value for X

原因：provider 的 PlanResourceChange 與 ApplyResourceChange 結果不一致（provider bug）。

對策：升級 provider、提 issue、暫時 ignore_changes。

Provider crashed

Plaintext 
Error: The provider hashicorp/aws crashed

對策：

  • 看當前目錄的 crash.log
  • 用 TF_LOG=TRACE 重跑找 panic stack trace
  • 提到 provider GitHub repo 的 issue
  • 嘗試降級或升級 provider 版本

7. module 錯誤

Module source has changed

對策：tofu init 重新拉取 module。

Could not download module

Plaintext 
Error: Could not download module "vpc"
Failed to download module from git::https://github.com/...: exit status 128

對策：

  • 檢查 source URL 是否正確
  • private repo：設定 git credentials 或 SSH key（~/.ssh/id_rsa）
  • OCI module：確認 docker login 過、artifactType 正確

Module does not declare provider X

Plaintext 
Error: Module does not declare provider configuration aws.tokyo

原因：傳了 alias provider 給 module，但 module 沒在 configuration_aliases 宣告。

對策：在 child module 的 required_providers 加上 configuration_aliases = [aws.tokyo]。

8. 循環依賴錯誤

Cycle

Plaintext 
Error: Cycle: aws_security_group.a, aws_security_group.b

原因：兩個資源互相引用（A 的屬性引用 B、B 的屬性引用 A）。

對策：

  • 視覺化：tofu graph -draw-cycles | dot -Tpng > cycles.png
  • 常見解法：把 SG rule 拆成獨立 aws_security_group_rule resource，避免兩個 SG 互相引用
  • 用 data source 取代直接引用

9. 版本相容錯誤

Required provider version not available

Plaintext 
Error: Failed to query available provider packages
no available releases match the given constraints "~> 99.0"

對策：修正 version 約束（檢查 registry 上的可用版本）。

Resource type not supported

Plaintext 
Error: Invalid resource type
The provider hashicorp/aws does not support resource type "aws_new_thing"

對策：升級 provider；或檢查 resource 名稱拼字。

Argument not allowed in vX

原因：provider 升級後 schema 變了，舊屬性已 deprecated 或移除。

對策：看 provider CHANGELOG，依新 schema 改寫 .tf。

10. 雲端 API 錯誤

AWS：UnauthorizedOperation

對策：缺 IAM 權限——查 CloudTrail 看具體缺哪個 action。

AWS：InvalidParameterValue

對策：參數值格式錯（如 CIDR 格式不對、port 範圍超出），看 error 詳細描述。

AWS：DependencyViolation

原因：要刪的資源還被別的東西使用（如 VPC 還有 ENI）。

對策：先處理依賴資源（ENI / SG），或讓 OpenTofu 用正確順序刪除。

Azure：BadRequest / SubscriptionNotRegistered

對策：到 Azure Portal 註冊對應的 resource provider（Microsoft.ContainerService 等）。

GCP：API not enabled

對策：gcloud services enable compute.googleapis.com 等。

11. CI/CD 專屬錯誤

Inconsistent dependency lock file（CI 中）

原因：CI 跑 init 時平台 hash 與 lock 檔不符（本機 macOS 寫的 lock 在 Linux 跑）。

對策：tofu providers lock -platform=linux_amd64 -platform=darwin_arm64 ... 預先寫多平台。

Could not assume role

原因：OIDC trust policy 不對、role ARN 拼錯、subject claim 不匹配。

對策：

  • 檢查 IAM role trust policy 的 token.actions.githubusercontent.com:sub 是否包含當前 PR / branch
  • 本機用 aws sts assume-role-with-web-identity 模擬

tflint / checkov violations

對策：依工具輸出修正規則違反，或加 inline 抑制（謹慎使用）。

Drift detected (exit code 2)

對策：drift detection 會回 exit code 2 提示有 drift，看是否需要人工處理（不一定是錯）。

Plan file too large

原因：state 太大導致 plan artifact 上傳失敗。

對策：拆 stack（500 行 module、依 lifecycle 分 state）。

12. 通用 debug 技巧

第一道防線：詳細 log

Bash · 4 個 log 級別 
# INFO 級別（一般觀察）
TF_LOG=INFO tofu plan 2>&1 | less

# DEBUG（細節）
TF_LOG=DEBUG TF_LOG_PATH=debug.log tofu plan

# TRACE（最詳細，含 gRPC）
TF_LOG=TRACE TF_LOG_PATH=trace.log tofu plan

# 只看 provider 的 log（不要 OpenTofu Core）
TF_LOG_PROVIDER=DEBUG tofu plan

第二道防線：state 與 plan 檢查

Bash 
# 看當前 state
tofu state list
tofu state show ADDR

# 看 plan 細節
tofu plan -out=tfplan.bin
tofu show -json tfplan.bin | jq '.resource_changes[] | select(.change.actions | contains(["delete"]))'

# 找 forces replacement 原因
tofu show tfplan.bin | grep -B 2 "forces replacement"

第三道防線：console 試算

Bash 
tofu console
> var.environment
> aws_vpc.main.id
> lookup(var.config, "key", "default")
> can(parseint(var.x, 10))

第四道防線：dependency graph

Bash 
# 視覺化依賴
tofu graph | dot -Tpng > graph.png

# 找循環
tofu graph -draw-cycles | dot -Tpng > cycles.png

# 看不同階段的 graph
tofu graph -type=plan
tofu graph -type=apply
tofu graph -type=plan-destroy

第五道防線：social

  • OpenTofu 官方 Slack（CNCF Slack 的 #opentofu）
  • OpenTofu GitHub Discussions / Issues
  • Provider 各自的 GitHub repo
  • Stack Overflow opentofu tag
  • Reddit r/opentofu

提 issue 該附什麼

① OpenTofu 版本（tofu version）；② Provider 版本（tofu providers）；③ 最小可重現的 .tf 範例；④ TF_LOG=TRACE 完整 log（敏感資料先遮蔽）；⑤ 預期行為 vs 實際行為。提供完整 reproduction，回應速度會快很多。
