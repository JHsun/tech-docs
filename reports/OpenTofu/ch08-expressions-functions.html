1. Expression 是什麼

Expression（表達式）是計算出一個值的東西。最簡單的 expression 是字面值（literal），例如 "hello"、42、true；複雜的 expression 可以包含運算、引用、條件、函式呼叫等。

HCL · 從簡到繁的 expression 
# 字面值
filename = "/tmp/hello.txt"
count    = 3
enabled  = true

# 引用
name = var.project

# 運算
total = var.base_count + 5

# 條件
size = var.environment == "prod" ? "large" : "small"

# 函式呼叫
hash = sha256(local.config_str)

# 多層組合
tags = merge(local.common_tags, {
  Name      = "${var.project}-${var.environment}"
  CreatedAt = formatdate("YYYY-MM-DD", timestamp())
})

expression 可以放在哪？

大多數 argument 的右邊都是 expression。但有些位置有限制，例如：variable 的 default 必須是字面值；count 與 for_each 必須在 plan 階段就能決定值（不能引用「apply 後才知道」的 resource 屬性）。第 2 章已介紹過 plan 對 expression 的影響。

2. 運算子：算術、比較、邏輯

類別運算子說明
算術+加法（也用於字串/list 之間？不，HCL 不重載 + 給字串）
-減法 / 負號
*乘法
/除法（整數 / 整數 = 整數，需小數要先 1.0 *）
%取餘
-x負值
比較==等於
!=不等於
<小於
<=小於等於
>大於
>=大於等於
邏輯&&且（短路求值）
||或（短路求值）
!非
HCL · 運算子範例 
locals {
  # 算術
  total_capacity = var.replicas * var.cpu_per_replica
  half           = var.budget / 2.0          # 強制浮點

  # 比較
  is_prod = var.environment == "prod"
  is_high = var.replicas >= 5

  # 邏輯
  needs_ha = var.environment == "prod" || var.replicas > 1
  ready    = local.is_prod && var.cert_arn != ""
}

字串連接：用 ${...} 不用 +

HCL · 字串組合 
# ❌ HCL 不支援字串 + 字串
name = var.project + "-" + var.environment    # 會 error

# ✅ 用內插
name = "${var.project}-${var.environment}"

# ✅ 或 format() 函式
name = format("%s-%s", var.project, var.environment)

3. 條件表達式（三元運算）

HCL 用標準三元運算 condition ? true_val : false_val：

HCL · 條件表達式 
locals {
  # 簡單三元
  instance_type = var.environment == "prod" ? "m5.large" : "t3.micro"

  # 巢狀三元（可讀性差，建議拆 local）
  instance_type_v2 = (
    var.environment == "prod"     ? "m5.large" :
    var.environment == "staging"  ? "t3.medium" :
                                    "t3.micro"
  )

  # 與 null 結合：選擇性傳遞
  vpc_id = var.create_vpc ? aws_vpc.main[0].id : var.existing_vpc_id

  # 給 count（條件性建立）
  # → 配合 count = ... ? 1 : 0
}

resource "aws_eip" "nat" {
  count = var.use_nat ? 1 : 0
  # ...
}

OpenTofu 1.11+ 推薦：用 enabled meta-argument

傳統用 count = condition ? 1 : 0 來條件化資源，但這會讓資源變成 list，後續引用要用 aws_eip.nat[0]，可讀性差。OpenTofu 1.11+ 推出了 enabled meta-argument：

HCL · enabled 取代 count hack（OpenTofu 1.11+） 
resource "aws_eip" "nat" {
  enabled = var.use_nat   # 直接的條件化開關

  domain = "vpc"
}

# 引用時不需要 [0]
output "nat_eip" {
  value = aws_eip.nat.public_ip
}

第 9 章 meta-arguments 會詳細介紹 enabled 與 count 的差別。

條件表達式的型別

三元的 true_val 與 false_val 必須同型別，否則會自動轉型或報錯。常見問題：

HCL · 型別問題 
# ⚠️ 兩邊型別不一致：number vs string
size = var.is_big ? 100 : "small"
# OpenTofu 會試圖把 100 → "100"，可能不是你要的

# ✅ 確保一致
size = var.is_big ? "100" : "50"
# 或
size = var.is_big ? 100 : 50

4. For 表達式：集合轉換

For 表達式是 OpenTofu 最強大的工具之一：從一個集合產出另一個集合。語法分兩種：

輸出形式語法產出
List/tuple 形式[for x in input : f(x)]tuple
Object/map 形式{for k, v in input : key_expr => value_expr}object

基本範例

HCL · for 基本範例 
locals {
  names = ["alice", "bob", "charlie"]

  # List → list
  upper_names = [for n in local.names : upper(n)]
  # ["ALICE", "BOB", "CHARLIE"]

  # List → object
  name_map = {for n in local.names : n => upper(n)}
  # { alice = "ALICE", bob = "BOB", charlie = "CHARLIE" }

  # 帶索引
  indexed = [for i, n in local.names : "${i}-${n}"]
  # ["0-alice", "1-bob", "2-charlie"]
}

過濾：if 條件

HCL · for + if 
locals {
  users = [
    { name = "alice", role = "admin" },
    { name = "bob",   role = "viewer" },
    { name = "charlie", role = "admin" },
  ]

  # 只取 admin
  admins = [for u in local.users : u.name if u.role == "admin"]
  # ["alice", "charlie"]

  # 把 list 轉 map（過濾後）
  admin_map = {for u in local.users : u.name => u if u.role == "admin"}
  # { alice = {...}, charlie = {...} }
}

實戰：把 resource 結果轉成 map

HCL · 資源結果轉 map 
resource "aws_subnet" "private" {
  count             = 3
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(aws_vpc.main.cidr_block, 4, count.index)
  availability_zone = data.aws_availability_zones.available.names[count.index]
}

# 轉成 「AZ → subnet ID」 的 map
output "subnet_ids_by_az" {
  value = {
    for s in aws_subnet.private :
    s.availability_zone => s.id
  }
}
# { "us-east-1a" = "subnet-abc", "us-east-1b" = "subnet-def", ... }

分組模式：... 後綴

當 key 不是唯一時，加 ... 把同 key 的 value 收集成 list：

HCL · 分組 
variable "users" {
  type = map(object({ role = string }))
  default = {
    alice   = { role = "admin" }
    bob     = { role = "viewer" }
    charlie = { role = "admin" }
    dave    = { role = "viewer" }
  }
}

locals {
  # 不分組會錯：admin 對應到多個值
  # 加 ... 後 → 收集成 list
  users_by_role = {
    for name, user in var.users :
    user.role => name...
  }
  # { admin = ["alice", "charlie"], viewer = ["bob", "dave"] }
}

5. Splat 表達式：簡潔取值

Splat 表達式 list[*].attr 是「對 list 中每個元素取屬性」的簡寫，等同於 for 表達式 [for x in list : x.attr]。

HCL · splat 範例 
resource "aws_instance" "web" {
  count = 3
  # ...
}

# 取所有實例的 id
output "instance_ids" {
  value = aws_instance.web[*].id
}

# 取所有 private IP
output "private_ips" {
  value = aws_instance.web[*].private_ip
}

# 巢狀屬性
output "first_disk_sizes" {
  value = aws_instance.web[*].root_block_device[0].volume_size
}

splat 對 for_each 不直接生效

for_each 產出 map，不是 list；splat 只能用在 list/set/tuple。需要時用 values() 轉 list：

HCL · for_each 取所有實例屬性 
resource "aws_instance" "web" {
  for_each = toset(["a", "b", "c"])
  # ...
}

# ❌ 不能直接 splat
# output "ids" { value = aws_instance.web[*].id }

# ✅ 先 values() 轉 list 再 splat
output "ids" {
  value = values(aws_instance.web)[*].id
}

# 或用 for
output "ids_v2" {
  value = [for k, i in aws_instance.web : i.id]
}

splat 處理 null：可空值轉 list

Splat 對 null 有特殊行為：null[*] 回傳空 list，非 null 值[*] 回傳單元素 list。

HCL · null 處理 
variable "website_setting" {
  type = object({
    index_document = string
    error_document = string
  })
  default = null
}

resource "aws_s3_bucket" "example" {
  # ...

  dynamic "website" {
    # null → []，否則 → [一個元素]
    for_each = var.website_setting[*]

    content {
      index_document = website.value.index_document
      error_document = website.value.error_document
    }
  }
}

6. Dynamic Block：動態產生巢狀 block

有些 resource 需要重複的巢狀 block（不是 argument），例如 security group 的 ingress、IAM policy 的 statement。dynamic 讓你能根據集合動態產生它們。

基本語法

HCL · dynamic block 基本 
variable "ingress_rules" {
  type = list(object({
    port        = number
    protocol    = string
    cidr_blocks = list(string)
    description = string
  }))

  default = [
    { port = 80,  protocol = "tcp", cidr_blocks = ["0.0.0.0/0"],   description = "HTTP"  },
    { port = 443, protocol = "tcp", cidr_blocks = ["0.0.0.0/0"],   description = "HTTPS" },
    { port = 22,  protocol = "tcp", cidr_blocks = ["10.0.0.0/8"],  description = "SSH"   },
  ]
}

resource "aws_security_group" "web" {
  name = "web-sg"

  dynamic "ingress" {
    for_each = var.ingress_rules

    content {
      from_port   = ingress.value.port
      to_port     = ingress.value.port
      protocol    = ingress.value.protocol
      cidr_blocks = ingress.value.cidr_blocks
      description = ingress.value.description
    }
  }
}

裡面的 ingress 是迭代器名稱（=外層 dynamic 的 label），有兩個屬性：ingress.key（list 索引或 map key）與 ingress.value（當前元素）。

巢狀 dynamic block

HCL · 巢狀 dynamic 
variable "origin_groups" {
  type = map(object({
    origins = set(object({ hostname = string }))
  }))
}

resource "some_provider_resource" "lb" {
  dynamic "origin_group" {
    for_each = var.origin_groups

    content {
      name = origin_group.key

      dynamic "origin" {
        for_each = origin_group.value.origins

        content {
          hostname = origin.value.hostname
        }
      }
    }
  }
}

不要過度使用 dynamic

官方明確建議：「能寫成靜態 block 就寫靜態」。Dynamic block 適合「使用者數量不定」的場景；如果是固定的幾條 ingress 規則，硬轉 dynamic 反而讓 module 難讀難 debug。

8. 最常用函式深入

String 系列

HCL · string 函式 
locals {
  # format：類似 printf
  full_name = format("%s-%s-%03d", var.project, var.env, 7)
  # → "myapp-prod-007"

  # join / split
  csv      = join(",", ["a", "b", "c"])      # "a,b,c"
  parts    = split(",", "a,b,c")              # ["a", "b", "c"]

  # replace
  cleaned = replace("hello-world", "-", "_")  # "hello_world"

  # regex
  match = regex("([0-9]+)\\.([0-9]+)", "v1.5")
  # ["1", "5"]

  # regexall：全部匹配
  ips = regexall("[0-9]+\\.[0-9]+\\.[0-9]+\\.[0-9]+", "ips: 1.2.3.4 and 5.6.7.8")
  # ["1.2.3.4", "5.6.7.8"]

  # 大小寫
  upper_name = upper("hello")          # "HELLO"
  title      = title("hello world")    # "Hello World"

  # 修剪
  trimmed = trimspace("  hello  ")     # "hello"
  trimmed_prefix = trimprefix("https://example.com", "https://")  # "example.com"
  trimmed_suffix = trimsuffix("file.txt", ".txt")                 # "file"

  # 重複
  dashes = strrev("abc")               # "cba"
}

Collection 系列

HCL · collection 函式 
locals {
  list1 = ["a", "b", "c"]
  list2 = ["c", "d", "e"]
  m     = { a = 1, b = 2, c = 3 }

  # 基礎
  count_l = length(local.list1)             # 3
  has_a   = contains(local.list1, "a")      # true

  # map 操作
  ks = keys(local.m)                        # ["a", "b", "c"]
  vs = values(local.m)                      # [1, 2, 3]
  v  = lookup(local.m, "x", "default")      # "default" (不存在用預設)

  # 合併（後者覆蓋前者）
  merged = merge(
    { a = 1, b = 2 },
    { b = 99, c = 3 },
  )
  # { a = 1, b = 99, c = 3 }

  # concat：連接 list
  joined = concat(local.list1, local.list2)
  # ["a", "b", "c", "c", "d", "e"]

  # distinct：去重
  unique = distinct(local.joined)           # ["a", "b", "c", "d", "e"]

  # flatten：展平巢狀 list
  nested = [["a", "b"], ["c"], ["d", "e"]]
  flat   = flatten(local.nested)            # ["a", "b", "c", "d", "e"]

  # slice：切片
  middle = slice(local.list1, 1, 3)         # ["b", "c"]

  # element：循環取元素（負索引也支援）
  first  = element(local.list1, 0)          # "a"
  cycled = element(local.list1, 4)          # "b"（循環，4 % 3 = 1）

  # sort：排序（字串）
  sorted = sort(["c", "a", "b"])            # ["a", "b", "c"]

  # zipmap：兩個 list 配對成 map
  m2 = zipmap(["a", "b"], [1, 2])           # { a = 1, b = 2 }

  # setproduct：笛卡兒積
  pairs = setproduct(["app", "db"], ["dev", "prod"])
  # [["app","dev"], ["app","prod"], ["db","dev"], ["db","prod"]]
}

Encoding 系列

HCL · encoding 函式 
locals {
  config = {
    name    = "myapp"
    port    = 8080
    debug   = true
    tags    = ["web", "api"]
  }

  # JSON
  json_str = jsonencode(local.config)
  # {"debug":true,"name":"myapp","port":8080,"tags":["web","api"]}

  # YAML
  yaml_str = yamlencode(local.config)

  # 從字串解析
  parsed   = jsondecode("{\"a\":1}")     # { a = 1 }

  # Base64
  b64      = base64encode("hello")       # "aGVsbG8="
  decoded  = base64decode("aGVsbG8=")    # "hello"

  # URL encoding
  encoded  = urlencode("name=Mary Jane") # "name%3DMary+Jane"
}

resource "aws_iam_policy" "example" {
  name = "example"
  # 用 jsonencode 比手寫 JSON 字串安全
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject"]
      Resource = "*"
    }]
  })
}

Filesystem 系列

HCL · 檔案讀取與模板 
locals {
  # 讀檔案
  ssh_key = file("${path.module}/ssh-public-key.pub")

  # 檔案是否存在
  has_config = fileexists("${path.module}/config.json")

  # base64 編碼讀取（給 user_data）
  cloud_init = filebase64("${path.module}/cloud-init.yaml")

  # templatefile：類似 heredoc 但模板與資料分離
  user_data = templatefile(
    "${path.module}/user-data.sh.tpl",
    {
      app_name = var.app_name
      port     = var.port
      env      = var.environment
    }
  )
}

對應的模板檔 user-data.sh.tpl：

Bash · user-data.sh.tpl 
#!/bin/bash
echo "Starting ${app_name} in ${env}"
export APP_PORT=${port}
systemctl start ${app_name}

Hash 與 Crypto 系列

HCL · hash 函式 
locals {
  config_hash = sha256(jsonencode(local.config))
  # 用 hash 觸發資源更新（搭配 replace_triggered_by）

  # bcrypt（密碼用）
  hashed = bcrypt(var.password, 10)

  # uuid v4：每次 plan 都不同！要小心
  random_id = uuid()

  # uuid v5：根據 namespace + name 確定性產生
  stable_id = uuidv5("dns", "example.com")
}

uuid() 會造成永遠的 drift

uuid() 每次 plan 都產生新值，會讓 OpenTofu 永遠認為「需要更新」。如果要產生穩定的隨機 ID，用 random_id resource（值會存進 state，下次不變）；如果是給 stateless 場景（如 user_data 中的暫時 token），才用 uuid()。

IP / Network 系列

HCL · CIDR 計算 
locals {
  vpc_cidr = "10.0.0.0/16"

  # cidrsubnet(prefix, newbits, netnum)
  # 從 /16 切出 /20（多 4 bit），第 0、1、2 個
  subnet_cidr_0 = cidrsubnet(local.vpc_cidr, 4, 0)  # 10.0.0.0/20
  subnet_cidr_1 = cidrsubnet(local.vpc_cidr, 4, 1)  # 10.0.16.0/20
  subnet_cidr_2 = cidrsubnet(local.vpc_cidr, 4, 2)  # 10.0.32.0/20

  # cidrhost：CIDR 內的第 N 個 IP
  gateway = cidrhost(local.vpc_cidr, 1)             # 10.0.0.1

  # cidrnetmask
  netmask = cidrnetmask("10.0.0.0/24")              # 255.255.255.0
}

# 實戰：依 AZ 動態切 subnet
resource "aws_subnet" "private" {
  count             = length(var.availability_zones)
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(aws_vpc.main.cidr_block, 4, count.index)
  availability_zone = var.availability_zones[count.index]
}

Type Conversion 系列

HCL · 型別轉換 
locals {
  num_str    = tostring(42)               # "42"
  str_num    = tonumber("42")             # 42
  bool_str   = tostring(true)             # "true"

  list_to_set = toset(["a", "b", "a"])    # set(["a", "b"]) — 去重
  set_to_list = tolist(local.list_to_set) # ["a", "b"]（順序可能變）

  # try：嘗試多個 expression，回第一個成功的
  config_value = try(
    var.config.advanced.timeout,
    var.config.timeout,
    30,                                   # 最後 fallback
  )

  # can：能不能算（不丟錯，回 bool）
  is_valid_cidr = can(cidrhost(var.cidr, 0))

  # nonsensitive：強制取消 sensitive 標記（少用，需自行確認真的不敏感）
  visible = nonsensitive(some_sensitive_value)
}

9. Provider-defined Functions（OpenTofu 1.8+）

從 OpenTofu 1.8 起，provider 可以定義自己的函式，呼叫語法為 provider::<name>::<function>(args)。這些函式由 provider 註冊，能力比內建函式更專業（例如 AWS provider 提供 ARN 解析）。

HCL · provider function 範例 
locals {
  arn = "arn:aws:s3:::my-bucket"

  # 假設 AWS provider 提供 arn_parse 函式
  parsed = provider::aws::arn_parse(local.arn)
  # 回傳 object：{ partition = "aws", service = "s3", account_id = "", resource = "my-bucket", ... }

  # AWS provider 也提供 trim_iam_role_path
  role_name = provider::aws::trim_iam_role_path(
    "arn:aws:iam::123456789012:role/some/path/MyRole"
  )
  # → "MyRole"
}

如何知道 provider 提供哪些 function？

查 provider 的 documentation。在 registry.opentofu.org 上每個 provider 頁面有「Functions」分頁，列出所有可用函式。

10. tofu console：互動式試算

tofu console 是非常實用的除錯工具，可以即時驗證你的 expression 結果：

Bash · tofu console

11. 常見陷阱與最佳實踐

陷阱 1：整數除法產生整數

HCL 
half = 5 / 2          # 2 ❌（整數除法）
half = 5 / 2.0        # 2.5 ✅
half = 5.0 / 2        # 2.5 ✅

陷阱 2：lookup 找不到 key 沒給預設值

HCL 
# ❌ key 不存在會 error
v = lookup({a = 1}, "missing")

# ✅ 提供預設
v = lookup({a = 1}, "missing", "fallback")

# ✅ 或用 try
v = try({a = 1}["missing"], "fallback")

陷阱 3：splat 對 for_each 失效

第 5 節已提過：for_each 產 map，splat 只能用在 list/set/tuple。改用 values() 或 for 表達式。

陷阱 4：concat 對 set 不適用

HCL 
s1 = toset(["a", "b"])
s2 = toset(["b", "c"])

# ❌ concat 接受 list 不接受 set
joined = concat(s1, s2)

# ✅ 用 setunion
joined = setunion(s1, s2)
# → toset(["a", "b", "c"])

陷阱 5：jsonencode + heredoc 的縮排陷阱

用 indented heredoc 寫 JSON 很容易因為 OpenTofu 的縮排剝離邏輯出錯。永遠用 jsonencode()：

HCL 
# ❌ 容易出錯（縮排、跳脫、語法）
policy = <<-EOT
  {
    "Version": "2012-10-17",
    "Statement": [{...}]
  }
EOT

# ✅ 結構化、安全
policy = jsonencode({
  Version = "2012-10-17"
  Statement = [{
    Effect = "Allow"
    # ...
  }]
})

最佳實踐速查

需求建議
多分支條件避免巢狀三元，拆 local 或 lookup map
條件性建立資源OpenTofu 1.11+ 用 enabled，舊版用 count = ? 1 : 0
集合轉換用 for expression，避免 concat 後過濾
取資源屬性集合count 用 splat，for_each 用 values() 或 for
動態 nested block用 dynamic，但能寫靜態就寫靜態
產生 IAM JSON用 jsonencode() 或 aws_iam_policy_document data source，不要手寫字串
產生 user_data用 templatefile() 把模板獨立成檔案
除錯 expression進 tofu console 試算
路徑 / 檔案用 ${path.module} 而非相對路徑

12. 本章重點與練習

重點回顧

  • Expression 是「能算出值的東西」，從字面值到複雜函式呼叫都是
  • HCL 不重載 + 給字串，字串組合用 ${...} 或 format()
  • 條件用三元 cond ? a : b；OpenTofu 1.11+ 推薦用 enabled 取代 count = ? 1 : 0
  • For 表達式：[for x in input : f(x)] 產 list、{for k,v in input : key => val} 產 object，可加 if 過濾、... 分組
  • Splat list[*].attr 是 for 的簡寫，但對 for_each 失效，需用 values()
  • Dynamic block 動態產生巢狀 block，但能用靜態就用靜態
  • 九大類內建函式：numeric、string、collection、encoding、filesystem、date_time、hash、IP、type conversion
  • OpenTofu 1.8+ 支援 provider-defined functions：provider::aws::arn_parse(...)
  • tofu console 是除錯 expression 最有效的工具
⚡ 動手實作 · Hands-on Lab 8

Expression 與 Function 綜合練習

  1. 建立 expr-lab/ 目錄與 main.tf，包含一個變數 users（map(object 含 role、email、active 欄位））
  2. 用 locals 計算：
    • active_users：只取 active = true 的使用者（用 for + if）
    • users_by_role：依 role 分組（用 for 加 ...）
    • email_domains：所有不重複的 email 網域（用 split + distinct）
  3. 跑 tofu init 與 tofu console，互動式驗證每個 local 的結果
  4. 練習 A：用 resource "local_file" 配 for_each = local.active_users，每個 active user 產生一個檔案，內容包含其 email 與 role
  5. 練習 B：用 dynamic block（雖然 local provider 沒有適合的，可以用 null_resource 配 triggers）模擬動態產生
  6. 練習 C：用 cidrsubnet() 從 10.0.0.0/16 切出 4 個 /20 子網路，輸出成 list
  7. 挑戰題 1：用 templatefile() 寫一個模板檔，依輸入產生 nginx 設定。模板支援 server_name list 與 port
  8. 挑戰題 2：用 jsonencode() 產生一個 IAM policy JSON，並用 file() + jsondecode() 讀回來，確認結構一致
  9. 用 tofu apply 與 tofu destroy 結束
