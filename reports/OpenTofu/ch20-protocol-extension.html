1. OpenTofu 三大擴充點

OpenTofu 是「平台」不是「孤立工具」——它定義了三個明確的擴充協定，社群可以在不修改 OpenTofu Core 的前提下擴充能力。

擴充點形式難度
Backend需修改 OpenTofu Core 並 PR高（需 Go + 深入 OpenTofu）

Provider Registry實作 HTTP API 即可中（需處理多平台）

最常擴充的是 Provider

9 成的擴充需求是「我要管理某個 SaaS 或內部服務」——做 provider 即可。Backend 擴充非常少見（90%+ 用戶需求 S3/GCS/Azure 已涵蓋）。Registry 擴充已被 OCI 大幅取代（第 18 章）。

2. Backend：state 儲存的擴充

Backend interface

OpenTofu 內部用 backend.Backend Go interface 抽象 state 儲存：

Go · 簡化的 backend interface 
type Backend interface {
    // backend 設定 schema
    ConfigSchema() *configschema.Block

    // 驗證設定
    PrepareConfig(cty.Value) (cty.Value, tfdiags.Diagnostics)

    // 套用設定
    Configure(cty.Value) tfdiags.Diagnostics

    // 取得 state manager（特定 workspace）
    StateMgr(workspace string) (statemgr.Full, error)

    // 列出 workspace
    Workspaces() ([]string, error)

    // 刪除 workspace
    DeleteWorkspace(name string, force bool) error
}

三類 backend 實作

類別說明範例
Standard只實作 state 儲存S3、GCS、Azure、HTTP、kubernetes、postgres
Enhanced含本機執行能力（執行 plan/apply）Local backend
Cloud含遠端執行能力（在 SaaS 平台執行）Cloud backend（HCP Terraform）

Cloud backend 的限制

OpenTofu 不支援 HCP Terraform / Terraform Enterprise 的 cloud {} block。如要 SaaS 化執行，改用 Spacelift、env0、Scalr、Atlantis 等支援 OpenTofu 的 TACOS 平台。

新增自訂 backend 的流程

實作新 backend 需要：

  1. Fork OpenTofu source code
  2. 在 internal/backend/remote-state/<name>/ 建立你的 backend package
  3. 實作 backend.Backend interface
  4. 實作 statemgr.Full（state 讀寫與 lock）
  5. 在 internal/backend/init/init.go 註冊
  6. 提 PR 到上游

這條路很少團隊走得通——通常用 HTTP backend 對接自有服務即可。

3. 用 HTTP backend 對接自有服務

HTTP backend 是萬用接頭——任何能實作幾個 HTTP endpoint 的服務都能當 OpenTofu 的 state backend。

HTTP backend 設定

HCL · 使用 http backend 
terraform {
  backend "http" {
    address        = "https://state.example.com/api/states/myapp"
    lock_address   = "https://state.example.com/api/states/myapp/lock"
    unlock_address = "https://state.example.com/api/states/myapp/lock"
    lock_method    = "POST"
    unlock_method  = "DELETE"
    username       = "user"
    password       = "pass"
  }
}

需要實作的 HTTP endpoints

MethodPath用途請求 body
GET/{name}讀取 state無
POST/{name}?ID=...寫 statestate JSON
DELETE/{name}刪除 state無
POST/LOCK/{name}/lock取 locklock info JSON
DELETE/UNLOCK/{name}/lock釋放 lock無

HTTP backend 的回應碼語意

狀態碼意義
200成功
404state 不存在（首次 init 會看到）
409lock 衝突（已被別人持有）
423state 被鎖定

知名 HTTP backend 服務

  • GitLab Managed Terraform State：每個 GitLab project 自動有 state backend，https://gitlab.com/api/v4/projects/${PROJECT_ID}/terraform/state/${NAME}
  • Atlantis：自架 PR-based workflow 工具，提供 state proxy
  • 自家服務：用 nginx + 簡單腳本 + S3 後端就能架

4. Module Registry Protocol 詳解

第 18 章已介紹過，這裡完整呈現協定細節。Module Registry Protocol 是純 HTTP，讀取請求只有兩個 endpoint。

Service Discovery

JSON · GET /.well-known/terraform.json 
{
  "modules.v1": "/api/v1/modules/"
}

OpenTofu 第一步先抓這個檔案，得知 module API 的 base path。

Endpoint 1：列出版本

JSON · GET /api/v1/modules/{namespace}/{name}/{provider}/versions 
{
  "modules": [
    {
      "versions": [
        { "version": "1.0.0" },
        { "version": "1.1.0" },
        { "version": "1.2.0" },
        { "version": "1.2.1" }
      ]
    }
  ]
}

Endpoint 2：取得下載位置

HTTP · GET /api/v1/modules/{namespace}/{name}/{provider}/{version}/download 
HTTP/1.1 204 No Content
X-Terraform-Get: https://github.com/myorg/m/archive/v1.2.0.tar.gz//*?archive=tar.gz

關鍵在 X-Terraform-Get header——可以是任何 go-getter 支援的 URL（git、HTTPS archive、S3、GCS）。OpenTofu 收到後會用 go-getter 拉取實際的 module zip。

Module Registry 認證

使用者透過 credentials block 或 TF_TOKEN_xxx（第 16 章）提供 bearer token，OpenTofu 自動帶在 Authorization: Bearer xxx header。Server 端驗證 token 並回應。

5. Provider Registry Protocol 詳解

Provider 比 module 複雜——要支援多平台，且有完整性與 GPG 簽章驗證。

Service Discovery（同 module）

JSON 
{
  "providers.v1": "/api/v1/providers/"
}

Endpoint 1：列出版本（含支援平台）

JSON · GET /api/v1/providers/{namespace}/{type}/versions 
{
  "versions": [
    {
      "version": "5.30.0",
      "protocols": ["5.0", "6.0"],
      "platforms": [
        { "os": "linux",   "arch": "amd64" },
        { "os": "linux",   "arch": "arm64" },
        { "os": "darwin",  "arch": "amd64" },
        { "os": "darwin",  "arch": "arm64" },
        { "os": "windows", "arch": "amd64" }
      ]
    }
  ]
}

Endpoint 2：取得特定平台下載資訊

JSON · GET /api/v1/providers/{namespace}/{type}/{version}/download/{os}/{arch} 
{
  "protocols": ["5.0", "6.0"],
  "os": "linux",
  "arch": "amd64",
  "filename": "terraform-provider-aws_5.30.0_linux_amd64.zip",
  "download_url": "https://releases.hashicorp.com/.../terraform-provider-aws_5.30.0_linux_amd64.zip",
  "shasums_url": "https://releases.hashicorp.com/.../terraform-provider-aws_5.30.0_SHA256SUMS",
  "shasums_signature_url": "https://releases.hashicorp.com/.../terraform-provider-aws_5.30.0_SHA256SUMS.sig",
  "shasum": "a1b2c3...",
  "signing_keys": {
    "gpg_public_keys": [
      {
        "key_id": "34365D9472D7468F",
        "ascii_armor": "-----BEGIN PGP PUBLIC KEY BLOCK-----\n..."
      }
    ]
  }
}

OpenTofu 完整下載流程

sequenceDiagram
    participant Tofu as OpenTofu
    participant Reg as Registry
    participant CDN as Download Server
    participant GPG as Signer

    Tofu->>Reg: GET /.well-known/terraform.json
    Reg-->>Tofu: {providers.v1: "..."}

    Tofu->>Reg: GET /providers/hashicorp/aws/versions
    Reg-->>Tofu: 版本清單

    Note over Tofu: 依 version constraint 選版本

    Tofu->>Reg: GET /providers/hashicorp/aws/5.30.0/download/linux/amd64
    Reg-->>Tofu: {download_url, shasums_url, signature_url, signing_keys}

    Tofu->>CDN: GET shasums_url
    CDN-->>Tofu: SHA256SUMS 內容

    Tofu->>CDN: GET signature_url
    CDN-->>Tofu: SHA256SUMS.sig

    Note over Tofu: 用 signing_keys 驗證 .sig

    Tofu->>CDN: GET download_url
    CDN-->>Tofu: provider zip

    Note over Tofu: 比對 sha256 與 SHASUMS

    Tofu->>Tofu: 解壓到 .terraform/providers/...
    Tofu->>Tofu: 寫 .terraform.lock.hcl

6. 用靜態檔架 minimal registry

因為 Module/Provider Registry Protocol 都是純 GET，用 nginx + 靜態 JSON 就能架。OpenTofu Public Registry 自己用 GitHub repo 當 storage 也是同樣道理。

架 module registry：靜態 JSON 範例

Plaintext · 目錄結構 
/var/www/registry/
├── .well-known/
│   └── terraform.json
└── api/
    └── v1/
        └── modules/
            └── myorg/
                └── vpc/
                    └── aws/
                        ├── versions
                        └── 1.2.0/
                            └── download
JSON · 各檔案內容 
// /.well-known/terraform.json
{ "modules.v1": "/api/v1/modules/" }

// /api/v1/modules/myorg/vpc/aws/versions
{ "modules": [{ "versions": [{ "version": "1.2.0" }] }] }

// /api/v1/modules/myorg/vpc/aws/1.2.0/download
// （回傳 204 + X-Terraform-Get header）

nginx 設定回傳 X-Terraform-Get

Nginx · 設定 download endpoint 
location /api/v1/modules/myorg/vpc/aws/1.2.0/download {
  add_header X-Terraform-Get "https://archives.example.com/myorg-vpc-aws-1.2.0.tar.gz" always;
  return 204;
}

使用者引用

HCL 
module "vpc" {
  source  = "registry.example.com/myorg/vpc/aws"
  version = "~> 1.2"
}

Minimal registry 的價值

① 5 行 nginx 設定 + 幾個 JSON 檔；② 沒有應用程式碼要維護；③ static archive 放 S3 / GCS；④ 不用 docker、不用 K8s。真的需要 private registry 又不想用 OCI 時，這是最輕量的做法。但 2026 年新團隊應該優先評估 OCI（第 18 章）。

7. Provider 開發概覽

Provider 是 OpenTofu 中最常被擴充的元件。寫 provider 等於把某個 SaaS / API / 內部系統的「建立 / 讀取 / 更新 / 刪除」對應到 HCL block。

什麼時候該寫 provider

場景建議
有現成 provider 但少了一兩個 resource提 PR 給原 provider 或 fork 維護
內部系統 / API（公司自家 SaaS、IDM 系統）寫 provider
需要把 OpenTofu 跟 webhook / 外部腳本整合用 http data source 或 terraform-provider-shell
單純要在 apply 後跑命令不用寫 provider，用 local-exec provisioner（最後手段）
單一 stack 內的工具函式用 OpenTofu 1.7+ 的 provider-defined functions（更輕量）

Provider 開發的兩個 SDK

SDK狀態建議
Terraform Plugin Framework（terraform-plugin-framework）現代、recommended🟢 新 provider 用這個
Terraform Plugin SDKv2（legacy）遺留、仍維護中🟡 既有 provider 維護用，新專案不要選
terraform-plugin-go（low-level）最低層 gRPC 包裝🔴 99% 場景不需要

為什麼仍叫 terraform-plugin-framework

OpenTofu 沒 fork 自己的 SDK，直接相容 HashiCorp 的 terraform-plugin-framework（MPL 2.0 授權）。這意味著為 Terraform 寫的 provider 通常能直接給 OpenTofu 用，反之亦然。Acceptance test 階段用環境變數 TF_ACC_TERRAFORM_PATH=tofu 切換到 OpenTofu CLI。

    version string
}

func New(version string) func() provider.Provider {
    return func() provider.Provider {
        return &jsonconfigProvider{version: version}
    }
}

func (p *jsonconfigProvider) Metadata(_ context.Context, _ provider.MetadataRequest, resp *provider.MetadataResponse) {
    resp.TypeName = "jsonconfig"
    resp.Version = p.version
}

func (p *jsonconfigProvider) Schema(_ context.Context, _ provider.SchemaRequest, resp *provider.SchemaResponse) {
    resp.Schema = schema.Schema{
        Attributes: map[string]schema.Attribute{},
    }
}

func (p *jsonconfigProvider) Configure(_ context.Context, _ provider.ConfigureRequest, _ *provider.ConfigureResponse) {
}

func (p *jsonconfigProvider) Resources(_ context.Context) []func() resource.Resource {
    return []func() resource.Resource{
        NewFileResource,
    }
}

func (p *jsonconfigProvider) DataSources(_ context.Context) []func() datasource.DataSource {
    return nil
}

Step 3：定義 Resource

Go · resource_file.go（簡化版） 
package provider

import (
    "context"
    "encoding/json"
    "os"

    "github.com/hashicorp/terraform-plugin-framework/resource"
    "github.com/hashicorp/terraform-plugin-framework/resource/schema"
    "github.com/hashicorp/terraform-plugin-framework/types"
)

type fileResource struct{}

type fileResourceModel struct {
    Path types.String `tfsdk:"path"`
    Data types.Map    `tfsdk:"data"`
    ID   types.String `tfsdk:"id"`
}

func NewFileResource() resource.Resource { return &fileResource{} }

func (r *fileResource) Metadata(_ context.Context, req resource.MetadataRequest, resp *resource.MetadataResponse) {
    resp.TypeName = req.ProviderTypeName + "_file"
}

func (r *fileResource) Schema(_ context.Context, _ resource.SchemaRequest, resp *resource.SchemaResponse) {
    resp.Schema = schema.Schema{
        Attributes: map[string]schema.Attribute{
            "path": schema.StringAttribute{
                Required: true,
                Description: "Path to write the JSON config",
            },
            "data": schema.MapAttribute{
                Required:    true,
                ElementType: types.StringType,
                Description: "Key-value pairs to write",
            },
            "id": schema.StringAttribute{
                Computed: true,
            },
        },
    }
}

func (r *fileResource) Create(ctx context.Context, req resource.CreateRequest, resp *resource.CreateResponse) {
    var plan fileResourceModel
    resp.Diagnostics.Append(req.Plan.Get(ctx, &plan)...)
    if resp.Diagnostics.HasError() { return }

    // 把 map 寫到 JSON 檔
    bytes, _ := json.MarshalIndent(plan.Data, "", "  ")
    if err := os.WriteFile(plan.Path.ValueString(), bytes, 0644); err != nil {
        resp.Diagnostics.AddError("Write failed", err.Error())
        return
    }

    plan.ID = plan.Path
    resp.Diagnostics.Append(resp.State.Set(ctx, plan)...)
}

func (r *fileResource) Read(ctx context.Context, req resource.ReadRequest, resp *resource.ReadResponse) {
    var state fileResourceModel
    resp.Diagnostics.Append(req.State.Get(ctx, &state)...)

    // 從檔案重新讀取內容並更新 state
    // ... 完整實作略
}

func (r *fileResource) Update(ctx context.Context, req resource.UpdateRequest, resp *resource.UpdateResponse) {
    // 改檔案
    // ... 完整實作略
}

func (r *fileResource) Delete(ctx context.Context, req resource.DeleteRequest, resp *resource.DeleteResponse) {
    var state fileResourceModel
    resp.Diagnostics.Append(req.State.Get(ctx, &state)...)
    os.Remove(state.Path.ValueString())
}

10. 發佈 provider 到各類 registry

方案 A：Public OpenTofu Registry

  1. 命名 GitHub repo 為 terraform-provider-<name>

11. 常見陷阱與最佳實踐

陷阱 1：用過時的 SDKv2 寫新 provider

SDKv2 是 legacy，新 provider 應該用 terraform-plugin-framework。

陷阱 2：忘了實作 ImportState

沒實作 ImportState，使用者就不能用 import block 把既有資源納入管理。Production-grade provider 必須支援。

陷阱 3：Read 沒處理「資源被外部刪除」

Go · Read 必須處理 404 
func (r *fileResource) Read(ctx context.Context, req resource.ReadRequest, resp *resource.ReadResponse) {
    var state fileResourceModel
    resp.Diagnostics.Append(req.State.Get(ctx, &state)...)

    if _, err := os.Stat(state.Path.ValueString()); os.IsNotExist(err) {
        // 檔案被外部刪除：把資源從 state 移除
        resp.State.RemoveResource(ctx)
        return
    }

    // 讀取並更新 state
    // ...
}

陷阱 4：dev_overrides 改完忘了移除

用完內建 provider 開發後，記得從 ~/.tofurc 移除 dev_overrides，否則影響其他專案。

陷阱 5：Provider schema 改版沒處理 state migration

Resource schema 變更時，舊 state 可能無法 unmarshal。實作 UpgradeResourceState 處理升級邏輯。

陷阱 6：plan 階段把 unknown 當 known

Provider 在 PlanResourceChange 時，對「未知於 plan 階段」的計算屬性要回傳 types.StringUnknown()，不要回傳預設值。否則使用者會看到 plan 顯示固定值，apply 後變成不同值。

12. 本章重點與練習（含 Part 4 總回顧）

本章重點回顧

  • OpenTofu 三大擴充點：Backend Protocol、Module/Provider Registry Protocol、Provider Plugin Protocol
  • Backend 擴充罕見，多數情況用 HTTP backend 對接自有服務即可
  • HTTP backend 只需實作 5 個 endpoints（GET/POST/DELETE state + lock/unlock）
  • Module Registry Protocol 純 GET，2 個 endpoint：versions + download
  • Provider Registry Protocol 純 GET，需多平台 metadata、SHA256、GPG 簽章
  • 用 nginx + 靜態 JSON 就能架 minimal registry，但 2026 年新團隊優先評估 OCI
  • Provider 開發用 terraform-plugin-framework（OpenTofu 直接相容 HashiCorp 的 SDK）
  • Provider 必備方法：Metadata / Schema / Configure / Create / Read / Update / Delete + ImportState
  • 本地開發用 dev_overrides，用完記得移除
  • Acceptance test 用 TF_ACC_TERRAFORM_PATH=tofu 對 OpenTofu CLI 跑
  • 發佈 provider 四種路：Public Registry / OCI Registry / 自架 Static Registry / Filesystem Mirror
  • 輕量擴充需求改用 OpenTofu 1.7+ 的 provider-defined functions
