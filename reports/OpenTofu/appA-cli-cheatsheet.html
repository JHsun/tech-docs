1. init 與 setup

動作指令
第一次初始化tofu init
升級 provider 與 moduletofu init -upgrade
用 backend config 檔tofu init -backend-config=prod.s3.tfbackend
動態 backend 參數tofu init -backend-config="bucket=xxx"
遷移 state 到新 backendtofu init -migrate-state
強制重新初始化 backendtofu init -reconfigure
跳過 backend（只 validate）tofu init -backend=false
不下載 moduletofu init -get=false
CI 嚴格 lockfiletofu init -lockfile=readonly
非互動 + 無顏色tofu init -input=false -no-color
啟用 tab completiontofu -install-autocomplete

2. 核心工作流程

動作指令
看格式問題tofu fmt -check -diff -recursive

看會做什麼tofu plan

CI 退出碼判斷tofu plan -detailed-exitcode（0=無變更、1=錯、2=有變更）

傳單一變數tofu plan -var="env=prod"
只處理某個 moduletofu plan -target=module.network
排除某資源（1.9+）tofu plan -exclude=module.legacy
強制重建tofu plan -replace=aws_instance.web
不 refreshtofu plan -refresh=false
並行度tofu plan -parallelism=20

互動式套用tofu apply

自動同意tofu apply -auto-approve
接受外部變更為新 baselinetofu apply -refresh-only
互動銷毀tofu destroy
銷毀某個 moduletofu destroy -target=module.dev
CI 自動銷毀tofu destroy -auto-approve

3. state 操作

動作指令
列出所有資源tofu state list
篩選列出tofu state list 'module.network.*'
看單一資源tofu state show 'aws_instance.web[0]'
備份 state（必做）tofu state pull > backup-$(date +%Y%m%d-%H%M).json
推 state（高危！）tofu state push state.json
重新命名（建議用 moved block）tofu state mv aws_instance.old aws_instance.new
跨 state 移動tofu state mv -state-out=../other/terraform.tfstate ADDR ADDR
從 state 移除（保留雲端）tofu state rm aws_iam_user.legacy
批次移除tofu state list \| grep '^aws_subnet' \| xargs -L1 tofu state rm
替換 provider sourcetofu state replace-provider OLD NEW
強制解鎖tofu force-unlock LOCK_ID

宣告式重構（優先選擇）

HCL · 三種重構 block 速查

import {
  to = aws_s3_bucket.legacy
  id = "my-existing-bucket"
}

# 改名 / 搬進 module
moved {
  from = aws_instance.web
  to   = aws_instance.web_primary
}

# 移除（保留雲端實體）
removed {
  from = aws_s3_bucket.legacy
  lifecycle { destroy = false }
}

9. 環境變數

環境變數用途
TF_VAR_xxx傳變數值（變數名 xxx）
TF_LOG=DEBUG開啟 debug log（TRACE/DEBUG/INFO/WARN/ERROR）
TF_LOG_PATH=filelog 寫到檔案
TF_INPUT=0禁用互動詢問（同 -input=false）
TF_IN_AUTOMATION=true標示為 CI 環境（影響輸出格式）
TF_PLUGIN_CACHE_DIRprovider plugin cache 目錄
TF_DATA_DIR替代 .terraform/ 目錄位置
TF_WORKSPACE選擇 workspace
TF_TOKEN_HOSTNAMEprivate registry token（hostname 用底線、連字號→雙底線）
TF_CLI_CONFIG_FILE自訂 ~/.tofurc 位置
TF_CLI_ARGS_xxx對 xxx 子指令自動加 flag（例 TF_CLI_ARGS_apply="-auto-approve"）
OTEL_EXPORTER_OTLP_ENDPOINTOpenTofu 1.10+ tracing 後端

10. CI/CD 完整 pipeline

Bash · 標準 CI 模板 
#!/bin/bash
set -euo pipefail

# 環境
export TF_INPUT=0
export TF_IN_AUTOMATION=true
export TF_PLUGIN_CACHE_DIR=$HOME/.terraform.d/plugin-cache
mkdir -p "$TF_PLUGIN_CACHE_DIR"

# 1. Init（嚴格 lockfile）
tofu init -lockfile=readonly -no-color

# 2. Format check
tofu fmt -check -recursive -no-color

# 3. Validate
tofu validate -no-color

# 4. Plan with detailed exit code
tofu plan -out=tfplan.bin -no-color -detailed-exitcode || EXIT=$?

case ${EXIT:-0} in
  0) echo "No changes"; exit 0 ;;
  1) echo "Plan failed"; exit 1 ;;
  2) echo "Changes pending approval" ;;
esac

# 5. Apply（生產前面有 manual gate）
tofu apply -no-color tfplan.bin

GitHub Actions 雙 IAM role 摘要

YAML · OIDC 標準寫法 
permissions:
  contents: read
  id-token: write
  pull-requests: write

env:
  TF_INPUT: "0"
  TF_IN_AUTOMATION: "true"

# Plan 用 read-only role
- uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::ACCT:role/TofuPlanRole
    aws-region: us-east-1

# Apply 用 write role（不同 job、需 environment approval）
- uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::ACCT:role/TofuApplyRole
    aws-region: us-east-1

11. 緊急救援指令

狀況救援指令
state 被鎖住打不開tofu force-unlock LOCK_ID（先廣播確認沒人在用）
state 被寫壞要回上一版S3 versioning 還原 + tofu plan 確認
外部刪了資源tofu state rm ADDR 接受刪除
外部改了資源tofu apply -refresh-only 接受新 baseline
provider 卡住不回TF_LOG=TRACE tofu plan 查 gRPC log
plan 顯示意外 destroy找 plan 中 forces replacement 訊息追原因
循環依賴 errortofu graph -draw-cycles 找循環
plan/apply 太慢提高 -parallelism 或拆 stack
partial apply 停在中間查 state、修復根因、再 tofu apply 繼續
誤刪了 .terraform/重跑 tofu init
誤改 lock 檔git checkout 還原 + tofu init -lockfile=readonly
多平台 hash 衝突tofu providers lock -platform=... 預先寫多平台

常用 trace log 查詢片段

Bash · trace log 解析速查 
# 抓 trace
TF_LOG=TRACE TF_LOG_PATH=trace.log tofu plan

# 看 provider 與 OpenTofu 之間的請求
grep "GRPCProvider" trace.log | head -50

# 看 ReadResource 呼叫
grep "ReadResource" trace.log

# 看 PlanResourceChange 的 input/output
grep -A 20 "PlanResourceChange" trace.log

# 找 panic 或 crash
grep -i "panic\|crash\|stack trace" trace.log

# 看 state lock 取得時間
grep -i "lock" trace.log

state pull / push 完整備份還原

Bash · 災難備援模板 
# 備份
tofu state pull > "backup-$(date +%Y%m%d-%H%M%S).json"

# 從 backup 還原（極端情境，務必先確認）
tofu state push backup-20260415-103000.json

# 從 S3 versioning 還原
aws s3api list-object-versions \
  --bucket myorg-tofu-state \
  --prefix prod/myapp/terraform.tfstate

aws s3api copy-object \
  --bucket myorg-tofu-state \
  --copy-source "myorg-tofu-state/prod/myapp/terraform.tfstate?versionId=ABC..." \
  --key prod/myapp/terraform.tfstate

# 還原後驗證
tofu plan
