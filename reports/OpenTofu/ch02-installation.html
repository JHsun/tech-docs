1. 安裝方式總覽：選你最順的那條路

OpenTofu 是一個用 Go 寫的單一靜態二進位檔（tofu），這代表它沒有任何執行期依賴——你下載下來、丟進 PATH、就能跑。也因此安裝方式非常多元，從「一行 curl」到「企業 OS 套件管理員」都有。

對絕大多數使用者，我們的建議很簡單：

使用者類型 推薦方式 原因
macOS / Linux 個人開發者 Homebrew 最簡單，brew upgrade 一鍵更新
需要管多個版本（多專案） tenv（強烈推薦） 跨平台、自動偵測 required_version
Windows 個人開發者 winget 或 Chocolatey 原生套件管理
Linux 伺服器（apt / yum） 官方 standalone installer 自動處理 GPG key 與 repo 設定
CI/CD pipeline Docker image 或 opentofu/setup-opentofu action 無狀態、版本鎖定
離線 / Air-gapped 環境 GitHub Releases 直接下載 binary 不需任何外部 repo

核心觀念：tofu 與 terraform 可以共存

OpenTofu 的指令名稱是 tofu，不會跟現有的 terraform 衝突。你可以兩個都裝在同一台機器上，分別跑不同專案。如果想完全取代 Terraform，許多使用者會額外設一個 alias：alias terraform=tofu。

2. macOS 安裝

方式一：Homebrew（建議）

Homebrew 有 OpenTofu 的官方 formula，這是 Mac 上最簡單的安裝方式。

Bash · macOS Homebrew 安裝 
# 若還沒裝 Homebrew，先裝
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Apple Silicon Mac 需設定 PATH
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

# 更新 brew metadata
brew update

# 安裝 OpenTofu
brew install opentofu

# 驗證
tofu version
# 預期輸出：OpenTofu v1.11.6 on darwin_arm64

更新版本只要：

Bash 
brew upgrade opentofu

方式二：MacPorts

Bash · MacPorts 
sudo port install opentofu
tofu version

方式三：官方 Standalone Installer Script

適合不想用套件管理員的使用者，或想嘗鮮 nightly build：

Bash · 官方 installer 
# 下載 installer
curl --proto '=https' --tlsv1.2 -fsSL https://get.opentofu.org/install-opentofu.sh \
  -o install-opentofu.sh

# 給執行權限
chmod +x install-opentofu.sh

# 執行 standalone 模式安裝
./install-opentofu.sh --install-method standalone

# 清掉 installer
rm -f install-opentofu.sh

完整性驗證需求

Standalone installer 預設會驗證下載檔案的數位簽章。你需要事先安裝 cosign 或 GnuPG，或加上 --skip-verify 略過驗證（不建議在 production 機器上略過）。

3. Linux 安裝

方式一：官方 installer script（最通用）

官方 installer 會自動偵測你的發行版（Debian/Ubuntu、RHEL/CentOS/Fedora、Alpine、Arch），加入正確的 GPG key 與 repo，再透過原生套件管理員安裝。

Bash · Debian / Ubuntu 
curl --proto '=https' --tlsv1.2 -fsSL https://get.opentofu.org/install-opentofu.sh \
  -o install-opentofu.sh
chmod +x install-opentofu.sh

# 用 deb 套件方式安裝（會註冊 apt repo，後續用 apt upgrade 更新）
./install-opentofu.sh --install-method deb

rm -f install-opentofu.sh
tofu version
Bash · RHEL / Fedora / CentOS 
curl --proto '=https' --tlsv1.2 -fsSL https://get.opentofu.org/install-opentofu.sh \
  -o install-opentofu.sh
chmod +x install-opentofu.sh

# rpm 套件方式
./install-opentofu.sh --install-method rpm

rm -f install-opentofu.sh
tofu version

方式二：手動 apt 設定（Debian/Ubuntu）

如果你想精確控制安裝過程（例如 ansible playbook 內部署），可以手動加入 apt repo：

Bash · 手動 apt repo 
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl gnupg

# 加入 OpenTofu GPG key
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://get.opentofu.org/opentofu.gpg \
  | sudo tee /etc/apt/keyrings/opentofu.gpg >/dev/null
curl -fsSL https://packages.opentofu.org/opentofu/tofu/gpgkey \
  | sudo gpg --no-tty --batch --dearmor -o /etc/apt/keyrings/opentofu-repo.gpg >/dev/null
sudo chmod a+r /etc/apt/keyrings/opentofu.gpg /etc/apt/keyrings/opentofu-repo.gpg

# 加入 apt source
echo "deb [signed-by=/etc/apt/keyrings/opentofu.gpg,/etc/apt/keyrings/opentofu-repo.gpg] \
https://packages.opentofu.org/opentofu/tofu/any/ any main
deb-src [signed-by=/etc/apt/keyrings/opentofu.gpg,/etc/apt/keyrings/opentofu-repo.gpg] \
https://packages.opentofu.org/opentofu/tofu/any/ any main" \
  | sudo tee /etc/apt/sources.list.d/opentofu.list > /dev/null

sudo apt-get update
sudo apt-get install -y tofu
tofu version

方式三：直接下載 Binary（Air-gapped 環境）

如果你的機器無法連到外部 repo，可以直接從 GitHub Releases 下載 binary：

Bash · 手動下載 binary 
TOFU_VERSION=1.11.6
ARCH=amd64   # 或 arm64

curl -fsSL -o tofu.tar.gz \
  "https://github.com/opentofu/opentofu/releases/download/v${TOFU_VERSION}/tofu_${TOFU_VERSION}_linux_${ARCH}.tar.gz"

# 驗證 SHA256（建議！）
curl -fsSL -o tofu.SHA256SUMS \
  "https://github.com/opentofu/opentofu/releases/download/v${TOFU_VERSION}/tofu_${TOFU_VERSION}_SHA256SUMS"
sha256sum -c tofu.SHA256SUMS --ignore-missing

# 解壓並安裝
sudo tar -C /usr/local/bin -xzf tofu.tar.gz tofu
sudo chmod +x /usr/local/bin/tofu

rm -f tofu.tar.gz tofu.SHA256SUMS
tofu version

方式四：Snap

Bash · Snap 
sudo snap install opentofu --classic
tofu version

32-bit 架構即將停止支援

OpenTofu 官方已宣布將在未來版本停止提供 32-bit（*_386、*_arm）架構的官方套件。1.12.x 與 1.13.x 仍會繼續提供，但建議規劃遷移到 64-bit 架構（*_amd64 或 *_arm64）。

4. Windows 安裝

方式一：winget（建議，Windows 10/11 內建）

PowerShell 
winget install OpenTofu.OpenTofu

# 重開 PowerShell 後驗證
tofu version

方式二：Chocolatey

PowerShell 
choco install opentofu
tofu version

方式三：Scoop

PowerShell 
scoop bucket add main
scoop install opentofu
tofu version

方式四：官方 PowerShell Installer

PowerShell 
# 下載 installer
Invoke-WebRequest -OutFile "install-opentofu.ps1" `
  -Uri "https://get.opentofu.org/install-opentofu.ps1"

# 檢查內容（建議）
Get-Content install-opentofu.ps1 | Select-Object -First 30

# 執行安裝
.\install-opentofu.ps1 -installMethod standalone

Remove-Item install-opentofu.ps1
tofu version

Windows + WSL 的選擇

如果你在 Windows 上開發，但 production 環境是 Linux，強烈建議使用 WSL2（Windows Subsystem for Linux）。在 WSL 內安裝 OpenTofu 等同於 Linux 安裝，且能避免日後跨平台路徑、行尾、權限等差異引發的奇怪問題。

5. Docker / 容器化使用

OpenTofu 官方在 GitHub Container Registry 提供 OCI image，是 CI/CD 與容器化工作流程的首選。

Bash · 拉取與執行 image 
# 拉最新版
docker pull ghcr.io/opentofu/opentofu:latest

# 拉特定版本（production 強烈建議用版本號，不要用 latest）
docker pull ghcr.io/opentofu/opentofu:1.11.6

# 在當前目錄跑 init
docker run --rm \
  -v "$(pwd):/workspace" \
  -w /workspace \
  ghcr.io/opentofu/opentofu:1.11.6 init

# 跑 plan
docker run --rm \
  -v "$(pwd):/workspace" \
  -w /workspace \
  ghcr.io/opentofu/opentofu:1.11.6 plan

建立本地 alias 讓 Docker 用起來像原生

Bash · ~/.bashrc 或 ~/.zshrc 
alias tofu='docker run --rm -it \
  -v "$(pwd):/workspace" \
  -w /workspace \
  -v "$HOME/.aws:/root/.aws:ro" \
  -e AWS_PROFILE \
  ghcr.io/opentofu/opentofu:1.11.6'

這樣即使本機沒裝 OpenTofu，下 tofu init 也能跑起來。但要注意：掛載點與環境變數需要對應你實際的 provider 認證方式。

在 GitHub Actions 中使用

YAML · .github/workflows/tofu.yml 
name: OpenTofu CI

on:
  pull_request:
    paths:
      - '**.tf'

jobs:
  plan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup OpenTofu
        uses: opentofu/setup-opentofu@v2
        with:
          tofu_version: 1.11.6
          tofu_wrapper: false

      - name: Init
        run: tofu init -input=false

      - name: Format check
        run: tofu fmt -check

      - name: Validate
        run: tofu validate

      - name: Plan
        run: tofu plan -input=false -no-color

6. 版本管理工具：tenv vs tofuenv

當你開始管多個 OpenTofu 專案，版本問題就會浮現：A 專案要 1.6.x、B 專案要 1.10.x、C 專案要 1.11.x。每次手動切換 binary 太累，版本管理工具就是來解這個的。

工具 特色 建議使用對象
tenv Go 撰寫的二進位檔，跨平台支援最廣（Linux / macOS / Windows / BSD / Solaris），同時管 OpenTofu / Terraform / Terragrunt / Atmos，能解析 HCL 自動偵測 required_version 所有人，2026 年的主流選擇
tofuenv Shell script 撰寫，靈感來自 tfenv，只管 OpenTofu，依賴 bash/curl/grep 已習慣 tfenv 介面、不想換的使用者
asdf-vm + asdf-opentofu 通用語言版本管理器，可同時管 Node、Ruby、Go、OpenTofu 已重度使用 asdf 管多種工具的人

安裝 tenv（推薦）

Bash · macOS / Linux 
# macOS / Linuxbrew
brew install tenv

# 或 Linux 用 Snap
sudo snap install tenv

# 或從 GitHub Releases 下載 binary
# https://github.com/tofuutils/tenv/releases

tenv 核心工作流程

Bash · tenv 常用指令 
# 列出可安裝的 OpenTofu 版本
tenv tofu list-remote --stable

# 安裝特定版本
tenv tofu install 1.11.6

# 安裝最新穩定版
tenv tofu install latest-stable

# 安裝專案 .tf 檔聲明的最大允許版本
tenv tofu install latest-allowed

# 切換預設版本
tenv tofu use 1.11.6

# 列出本機已安裝版本（* 標記目前使用）
tenv tofu list

# 把目前版本寫入 .opentofu-version（鎖在當前專案）
tenv tofu pin 1.11.6

# 解除安裝
tenv tofu uninstall 1.10.0

專案層級版本鎖定

在專案根目錄建立 .opentofu-version：

Plaintext · .opentofu-version 
1.11.6

之後在這個目錄底下執行 tofu，tenv 會自動使用 1.11.6。團隊成員 clone 下來也會自動鎖在同一版，避免「在我電腦能跑」這種地獄。

更聰明的：自動偵測 required_version

OpenTofu 設定檔裡通常會宣告 required_version：

HCL · versions.tf 
terraform {
  required_version = "~> 1.11.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

這時用 tenv tofu install latest-allowed，tenv 會解析 HCL，自動裝出符合條件的最高版本。對團隊統一版本管理非常方便。

sequenceDiagram

        T->>G: 下載對應版本

    end
    T->>U: 執行 tofu plan（使用該版本）

8. Shell 自動補全與環境變數

啟用自動補全

OpenTofu 內建一鍵設定 shell 補全的指令：

Bash 
# 自動偵測你的 shell（bash / zsh）並設定
tofu -install-autocomplete

# 重開 shell 或 source 設定檔
source ~/.bashrc   # 或 ~/.zshrc

之後你打 tofu 按 Tab，就會看到所有子指令；打 tofu apply - 按 Tab 會看到所有 flag。

手動設定（如果上面的指令失敗）

Bash · ~/.bashrc 
complete -C "$(which tofu)" tofu
Bash · ~/.zshrc 
autoload -U +X bashcompinit && bashcompinit
complete -C "$(which tofu)" tofu

常用環境變數速查

環境變數 用途
TF_LOG Log 等級：TRACE / DEBUG / INFO / WARN / ERROR，除錯時必備
TF_LOG_PATH Log 寫入檔案路徑（搭配 TF_LOG）
TF_INPUT=0 停用互動式詢問，CI/CD 必設
TF_IN_AUTOMATION=1 告訴 tofu 它跑在自動化環境，會調整輸出格式
TF_VAR_xxx 傳入變數 xxx，例如 TF_VAR_region=us-east-1
TF_PLUGIN_CACHE_DIR Provider 快取目錄，避免每個專案重複下載相同 provider
TF_DATA_DIR 覆寫 .terraform 目錄位置
TOFU_CLI_CONFIG_FILE OpenTofu 1.6+ 開始建議的 CLI config 路徑

Provider Plugin Cache：值得設一次的最佳實踐

每個 OpenTofu 專案 tofu init 都會下載 provider，幾百 MB 不誇張。設定一個全域 cache 目錄能省下大量時間與頻寬：

Bash · ~/.bashrc 或 ~/.zshrc 
mkdir -p ~/.terraform.d/plugin-cache
echo 'export TF_PLUGIN_CACHE_DIR="$HOME/.terraform.d/plugin-cache"' >> ~/.zshrc

9. 驗證安裝與第一個指令

安裝完成後，跑下面這幾個指令確認一切就緒：

Bash · 安裝驗證 
# 看版本

# 預期：
# OpenTofu v1.11.6
# on darwin_arm64

# 看 binary 位置

# macOS Apple Silicon: /opt/homebrew/bin/tofu
# macOS Intel:        /usr/local/bin/tofu

# 列出所有可用子指令

# 看詳細的某個子指令說明

建立你的第一個 OpenTofu 專案

用最不需要雲端帳號的 random provider，產出第一個資源：

Bash · 建立專案目錄 
mkdir hello-tofu && cd hello-tofu
HCL · main.tf 
terraform {
  required_version = ">= 1.6.0"

  required_providers {
    random = {
      source  = "hashicorp/random"
      version = "~> 3.6"
    }
  }
}

resource "random_pet" "name" {
  length    = 2
  separator = "-"
}

output "your_pet_name" {
  value = random_pet.name.id
}
Bash · 執行三步驟 
# 1. 初始化（下載 provider）
tofu init

# 2. 預覽要做什麼
tofu plan

# 3. 執行
tofu apply
# 輸入 yes 確認

# 看結果
tofu output
# 預期類似：your_pet_name = "happy-tiger"

# 清掉（很重要！避免下一章混亂）
tofu destroy

恭喜！你已經跑完第一個 OpenTofu 流程

剛才你經歷的就是 OpenTofu 整個工具的精神：Write → Init → Plan → Apply。即使是管理一萬個 AWS 資源，流程也是這四步。第 3 章會詳細拆解每一步背後發生的事。

10. 常見安裝問題排除

「command not found: tofu」

PATH 沒包含 OpenTofu 的安裝位置。先確認 binary 在哪：

Bash 
find / -name 'tofu' -type f 2>/dev/null

# 找到後，加入 PATH（假設在 /opt/homebrew/bin）
echo 'export PATH="/opt/homebrew/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

「signature verification failed」（standalone installer）

安裝過程驗證 cosign / GPG 簽章失敗。三種解法：

  1. 裝 cosign：brew install cosign 或 apt install cosign
  2. 裝 GnuPG：brew install gnupg 或 apt install gnupg
  3. 不要驗證（不建議在 production）：加 --skip-verify

「Error: Could not load plugin」（init 失敗）

通常是 provider 下載失敗。檢查順序：

  1. 網路連線是否正常（curl -v https://registry.opentofu.org）
  2. 是否在公司 proxy 後面？需設 HTTPS_PROXY 環境變數
  3. 磁碟空間是否夠？provider 動輒幾百 MB
  4. 清掉 .terraform/ 目錄重跑 tofu init

macOS 跳出「Apple cannot check it for malicious software」

從 GitHub Releases 直接下載的 binary 沒簽名通過 Gatekeeper。解法：

Bash 
xattr -d com.apple.quarantine /usr/local/bin/tofu

或者：用 Homebrew 安裝（簽章已通過 notarization）。

Windows PATH 沒生效

winget / Chocolatey 安裝後 PATH 已自動設定，但必須重開新的 PowerShell 視窗才會生效。如果重開仍無效：

PowerShell · 手動加入 PATH 
# 找出 tofu.exe 的位置
Get-ChildItem -Path C:\ -Recurse -Filter "tofu.exe" -ErrorAction SilentlyContinue

# 永久加入使用者 PATH（範例路徑）
[Environment]::SetEnvironmentVariable(
  "Path",
  [Environment]::GetEnvironmentVariable("Path", "User") + ";C:\Program Files\OpenTofu\bin",
  "User"
)

WSL2 與 Windows 同時裝了 tofu，但版本不一致

這通常是 PATH 順序問題。WSL 預設會把 Windows 的 PATH 也載入。檢查：

Bash · WSL 
which -a tofu      # 看所有路徑下的 tofu
echo $PATH | tr ':' '\n'   # 看 PATH 順序

把 Linux 的 binary 路徑（例如 /usr/local/bin）放到 PATH 較前面。

11. 本章重點與練習

重點回顧

  • OpenTofu 是單一靜態 binary，安裝極簡——選擇你最熟悉的套件管理員即可
  • macOS 用 Homebrew、Linux 用官方 installer script、Windows 用 winget——這三種是各平台最佳預設
  • 多專案、多版本切換建議用 tenv（推薦）或 tofuenv
  • 專案根目錄放 .opentofu-version 鎖定版本，避免團隊環境不一致
  • VS Code 的 HashiCorp Terraform 擴充套件對 OpenTofu HCL 完全相容
  • 設定 TF_PLUGIN_CACHE_DIR 全域 provider 快取，省下大量初始化時間
  • CI/CD 用官方 Docker image 或 opentofu/setup-opentofu action
⚡ 動手實作 · Hands-on Lab 2

把開發環境一次到位

  1. 選擇你的平台，安裝 OpenTofu（推薦：macOS → Homebrew，Linux → installer script，Windows → winget）
  2. 安裝 tenv，並用它再裝一次 OpenTofu 1.11.6（確認版本切換能運作）
  3. 裝 VS Code 的 HashiCorp Terraform 擴充套件
  4. 設定 TF_PLUGIN_CACHE_DIR 全域 cache
  5. 啟用 shell 自動補全：tofu -install-autocomplete
  6. 執行第 9 節的 random_pet 範例，跑完一輪 init → plan → apply → destroy
  7. 檢查點：在新建的專案目錄裡，建立 .opentofu-version 檔，內容寫 1.10.7，然後執行 tofu version。如果你裝了 tenv，應該會看到自動切換成 1.10.7（且若沒裝會自動下載）
