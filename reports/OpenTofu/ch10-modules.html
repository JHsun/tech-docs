1. 什麼是 Module、為什麼需要

在 OpenTofu 中，一個 module 就是一個目錄，裡面有 .tf 檔，定義一組相關的 resource、variable、output。Module 是 OpenTofu 的程式碼重用單位——把基礎設施的某個邏輯區塊（VPC、RDS、ECS service）封裝起來，到處用。

為什麼要寫 module？

無 module有 module
每個專案重寫相同 VPC 設定呼叫共用 VPC module，傳幾個變數即可
10 個團隊各自踩坑、修 bug修一處 module 全公司受惠
合規檢查靠 review合規邏輯封裝在 module 內，無法繞過
新人需理解 1000 行才能改一個 EC2新人讀 module API（input/output）就能用

module 的本質：函式

把 module 當作函式理解就對了：variable 是輸入參數、output 是回傳值、內部的 resource/locals 是函式體。設計 module 與設計 API 是同一件事——關鍵在介面。

3. module block：呼叫子 module

用 module "" { ... } 呼叫一個 module。name 是本地別名，用來在父 module 內引用子 module 的 outputs。

HCL · module 呼叫範例 
module "vpc" {
  source = "./modules/vpc"

  cidr_block         = "10.0.0.0/16"
  availability_zones = ["us-east-1a", "us-east-1b", "us-east-1c"]

  tags = {
    Project = "myapp"
    Env     = "prod"
  }
}

module "rds" {
  source = "./modules/rds"

  # 引用其他 module 的 output 作為輸入
  vpc_id     = module.vpc.vpc_id
  subnet_ids = module.vpc.private_subnet_ids

  # 跨 module 的隱式依賴會自動推斷：rds 在 vpc 之後建立
  engine    = "postgres"
  size      = "db.t3.medium"
  password  = var.db_password
}

# 引用 module output
output "vpc_id" {
  value = module.vpc.vpc_id
}

module block 支援的 meta-arguments

除了 source 與 version 是 module 專屬，module block 也支援以下 meta-arguments：

Meta-argument用途
source（必填）module 來源位址
version版本約束（僅 registry 來源支援）
count產生 N 個 module 實例
for_each依 map / set 產生命名 module 實例
providers傳遞 provider 設定（多 region/account 場景）
depends_on顯式宣告 module 依賴
lifecycle.enabled（1.11+）條件性啟用整個 module

用 for_each 多次實例化同一個 module

HCL · 多環境部署 
variable "environments" {
  type = map(object({
    cidr_block = string
    instance_size = string
  }))

  default = {
    dev = {
      cidr_block    = "10.10.0.0/16"
      instance_size = "t3.micro"
    }
    staging = {
      cidr_block    = "10.20.0.0/16"
      instance_size = "t3.small"
    }
    prod = {
      cidr_block    = "10.30.0.0/16"
      instance_size = "m5.large"
    }
  }
}

module "env" {
  source   = "./modules/full-stack"
  for_each = var.environments

  env_name      = each.key
  cidr_block    = each.value.cidr_block
  instance_size = each.value.instance_size
}

# 引用：module.env["dev"]、module.env["prod"]
output "all_endpoints" {
  value = {
    for k, m in module.env : k => m.endpoint
  }
}

4. 八種 module 來源

source 可指向多種來源，OpenTofu 透過位址前綴自動識別：

mindmap
  root((module sources))
    本地
      Local Path
        ./modules/vpc
        ../shared/modules/db
    Registry
      OpenTofu Registry
        terraform-aws-modules/vpc/aws
      Private Registry
        registry.example.com/...
    Git
      Generic Git
        git::https://...
        git::ssh://...
      GitHub 簡寫
        github.com/org/repo
      Bitbucket 簡寫
        bitbucket.org/org/repo
    HTTP
      tar.gz / zip
        https://example.com/m.tar.gz
    OCI
      Container Registry
        oci://ghcr.io/org/m
    雲端 storage
      S3
        s3::https://s3.amazonaws.com/...
      GCS
        gcs::https://storage.googleapis.com/...
    Mercurial
      hg::https://...

① Local Path：最簡單的相對路徑

HCL · local path 
module "vpc" {
  source = "./modules/vpc"      # 相對 root module
}

module "shared_db" {
  source = "../../shared-modules/db"   # 相對路徑往上跳
}

必須以 ./ 或 ../ 開頭，否則 OpenTofu 會嘗試解析成 registry 位址。適合「同一 repo 內的私有 module」。

② Terraform / OpenTofu Registry

HCL · public registry 
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"   # NAMESPACE/NAME/PROVIDER
  version = "~> 5.0"

  name = "my-vpc"
  cidr = "10.0.0.0/16"
  # ...
}

Registry 來源是唯一支援 version 約束的來源（其他來源要鎖版本得用 ref）。OpenTofu Registry 是 Terraform Registry 的 mirror，預設可用所有公開的 module。

③ Git 通用形式

HCL · git 來源 
# HTTPS clone
module "vpc" {
  source = "git::https://github.com/myorg/terraform-vpc.git?ref=v1.2.0"
}

# SSH clone（用於 private repo，會用本機 SSH key）
module "private" {
  source = "git::ssh://git@github.com/myorg/private-module.git?ref=v2.0.0"
}

# 子目錄
module "subdir" {
  source = "git::https://github.com/myorg/monorepo.git//modules/vpc?ref=main"
  #                                                   ^^---- 雙斜線指定子目錄
}

# 用 commit SHA 鎖定（最不可變，但難維護）
module "pinned" {
  source = "git::https://github.com/myorg/m.git?ref=abc123def456"
}
ref 類型範例建議
Tag（推薦）?ref=v1.2.0✅ 不可變、語意化
Branch?ref=main⚠️ 內容會變，dev 用、production 別用
Commit SHA?ref=abc123...✅ 最不可變，但不易閱讀
無 ref（不指定）❌ 抓 default branch HEAD，最不穩定

④ GitHub / Bitbucket 簡寫

HCL · GitHub 簡寫 
module "vpc" {
  source = "github.com/myorg/terraform-vpc?ref=v1.2.0"
}

module "vpc_bb" {
  source = "bitbucket.org/myorg/terraform-vpc?ref=v1.2.0"
}

等價於 git::https://...，OpenTofu 自動加上 git:: 前綴。

⑤ HTTP（tar.gz / zip）

HCL · HTTP archive 
module "vpc" {
  source = "https://example.com/modules/vpc-1.2.0.tar.gz"
}

# 也支援需驗證的 archive download
module "private_archive" {
  source = "https://example.com/modules/vpc.zip?archive=zip"
}

⑥ OCI Registry（OpenTofu 1.10+ 獨家）

OpenTofu 1.10 推出將 module 發佈到 OCI registry（Docker Hub、GHCR、ECR、Harbor 等）的能力。第 7 節會詳細介紹發佈流程。

HCL · OCI 來源 
module "vpc" {
  source = "oci://ghcr.io/myorg/aws-vpc?tag=1.2.0"
}

# 用 digest 鎖定（最不可變）
module "vpc_digest" {
  source = "oci://ghcr.io/myorg/aws-vpc?digest=sha256:abc123..."
}

⑦ S3 與 GCS

HCL · 雲端儲存 
module "vpc_s3" {
  source = "s3::https://s3-eu-west-1.amazonaws.com/my-bucket/modules/vpc.zip"
}

module "vpc_gcs" {
  source = "gcs::https://www.googleapis.com/storage/v1/modules/foo/bar/v1.tar.gz"
}

用對應雲端的 ambient credentials（AWS_ACCESS_KEY_ID、GOOGLE_APPLICATION_CREDENTIALS）認證。

⑧ Mercurial

HCL · Mercurial 
module "vpc" {
  source = "hg::https://example.com/vpc.hg?rev=v1.2.0"
}

5. 版本約束與 lock 檔

version 約束語法（僅 registry 來源支援）

HCL · 版本約束 
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"

  # 精確等於
  version = "5.1.2"

  # 等於某主版本（pessimistic constraint）
  version = "~> 5.0"   # 5.0.x、5.1.x... 但不到 6.0
  version = "~> 5.1.0" # 5.1.x 但不到 5.2.0

  # 範圍
  version = ">= 5.0, < 6.0"
  version = ">= 5.1.0, != 5.1.5"
}
運算子意義範例
= 或無精確= 1.2.3 或 1.2.3
!=不等於!= 1.2.3
> >= < <=大小於>= 1.0
~>悲觀約束（最右一位可變）~> 1.2 = >= 1.2, < 2
~> 1.2.3 = >= 1.2.3, < 1.3

非 registry 來源如何鎖版本

Git / OCI / HTTP 來源不支援 version 屬性，需用其他機制鎖定：

來源鎖版本方式
Git?ref=v1.2.0 或 ?ref=<commit-sha>
OCI?tag=1.2.0 或 ?digest=sha256:...
HTTP archive檔名含版本 + 提供 sha256（用 ?checksum=sha256:...）

module 中的 .terraform.lock.hcl

OpenTofu 的 lock 檔（.terraform.lock.hcl）只鎖 provider 版本與 hash，不鎖 module 版本。Module 版本鎖定靠 source 的 ref / version 字串本身。

在 reusable module 中不要寫 ~> 版本上限

如果你寫的是給別人用的 module，required_providers 中只寫 >= 5.0，不要寫 ~> 5.0。否則使用者每次升級都得跟著你的 module 升級節奏。由 root module 決定上限，child module 只決定下限。

6. Public Registry 與 Private Registry

OpenTofu Public Registry

位於 search.opentofu.org，是 Terraform Registry 的 community-maintained mirror，加上 OpenTofu 獨家功能標記。

常用的高品質 module（值得認識）

命名空間提供備註
terraform-aws-modules/*AWS 全家桶（VPC、RDS、EKS、IAM、Lambda 等 30+ module）事實標準，社群維護積極
terraform-google-modules/*GCP 全家桶Google 官方維護
Azure/*Azure 官方 module覆蓋率較分散
cloudposse/*包含命名規範、tag 標準較有觀點性，需熟悉其哲學

使用 module 的版本管理建議

HCL · 推薦的版本鎖定 
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.5"      # 容許 5.5.x 與 5.6+，但不跨主版本

  name = "my-vpc"
  cidr = "10.0.0.0/16"
  # ...
}

Private Registry：架設自己的 module 服務

企業常需要 private module registry。OpenTofu 支援 module registry protocol，任何實作這個 HTTP 協定的服務都能當 registry：

選項適合對象
Spacelift / env0 / Scalr已使用 TACOS 平台的團隊
GitLab Module Registry已用 GitLab 的團隊（內建）
JFrog Artifactory大型企業已有 Artifactory
Citizen / Mass-Driver開源自建選項
OCI Registry（建議）OpenTofu 1.10+，技術門檻最低

CLI Config 設定 private registry credentials

HCL · ~/.tofurc 或 ~/.terraformrc 
credentials "registry.example.com" {
  token = "xxxxxx"
}

# 環境變數方式（CI 友善）
# export TF_TOKEN_registry_example_com=xxxxxx

7. OCI Registry 發佈 module（OpenTofu 1.10+）

OpenTofu 1.10 起原生支援把 module 包成 OCI artifact 推到任何 OCI registry（GHCR、ECR、Docker Hub、Harbor）。這是技術門檻最低的 private registry 方案——不需架設專屬服務。

發佈 module 到 OCI（用 oras 工具）

Bash · 打包與推送 
# 1. 安裝 oras CLI
brew install oras   # macOS
# Linux：https://github.com/oras-project/oras/releases

# 2. 進到 module 目錄
cd terraform-aws-vpc/

# 3. 打包成 zip（OpenTofu OCI 規範要求 zip 格式）
zip -r ../vpc-1.2.0.zip . -x ".terraform/*" "*.tfstate" "*.tfstate.backup" ".git/*"

# 4. 登入 OCI registry
oras login ghcr.io --username YOUR_USER --password $GITHUB_TOKEN

# 5. 推送 module（artifactType 是關鍵）
oras push \
  --artifact-type=application/vnd.opentofu.modulepkg \
  ghcr.io/myorg/aws-vpc:1.2.0 \
  ../vpc-1.2.0.zip:archive/zip

# 6. 加上多個 tag（latest、major、minor）
oras tag ghcr.io/myorg/aws-vpc:1.2.0 1.2
oras tag ghcr.io/myorg/aws-vpc:1.2.0 1
oras tag ghcr.io/myorg/aws-vpc:1.2.0 latest

使用 OCI module

HCL · 在設定中引用 
module "vpc" {
  source = "oci://ghcr.io/myorg/aws-vpc?tag=1.2.0"

  cidr_block = "10.0.0.0/16"
  # ...
}

OpenTofu 會用機器既有的 OCI 認證（與 docker、podman 共用 ~/.docker/config.json）。

GitHub Actions 自動發佈

YAML · .github/workflows/publish-module.yml 
name: Publish Module to OCI

on:
  push:
    tags:
      - 'v*.*.*'

jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Install oras
        run: |
          curl -LO https://github.com/oras-project/oras/releases/download/v1.3.0/oras_1.3.0_linux_amd64.tar.gz
          tar -xzf oras_1.3.0_linux_amd64.tar.gz
          sudo mv oras /usr/local/bin/

      - name: Login to GHCR
        run: |
          echo "${{ secrets.GITHUB_TOKEN }}" | oras login ghcr.io \
            --username ${{ github.actor }} --password-stdin

      - name: Package module
        run: |
          VERSION=${GITHUB_REF#refs/tags/v}
          echo "VERSION=$VERSION" >> $GITHUB_ENV
          zip -r module.zip . -x ".git/*" ".github/*" "*.tfstate*"

      - name: Push to OCI
        run: |
          oras push \
            --artifact-type=application/vnd.opentofu.modulepkg \
            ghcr.io/${{ github.repository }}:$VERSION \
            module.zip:archive/zip

          # 標記 latest
          oras tag ghcr.io/${{ github.repository }}:$VERSION latest

為什麼 OCI 是 2026 年最好的 private module 方案

① 不需架設新服務（GHCR / ECR 多數團隊已在用）；② 同樣的 registry 可以放 container image、provider mirror、module package；③ Tag 與 digest 兩種版本鎖定；④ 標準 OCI 認證機制與既有工具鏈無縫接軌。新專案建議直接採用 OCI。

8. Module 設計最佳實踐

原則 1：把 module 當函式設計

  • 單一職責：一個 module 解決一件事（VPC、RDS、ALB），不要把整個 stack 塞進一個 module
  • 清晰介面：variables 是參數、outputs 是回傳值、internals 是黑箱
  • 合理預設值：90% 的使用者不需動 module，只覆寫關鍵變數
  • 不洩漏實作細節：output 不要直接暴露所有 resource 屬性

原則 2：標準的 module 目錄結構

Plaintext · module 標準結構 
terraform-aws-vpc/             # 命名慣例：terraform-<PROVIDER>-<NAME>
├── README.md                  # 必須有（描述用途、輸入、輸出、範例）
├── main.tf                    # 主要 resource
├── variables.tf               # 所有 input
├── outputs.tf                 # 所有 output
├── versions.tf                # required_version + required_providers
├── LICENSE                    # 授權
├── examples/                  # 至少一個完整 example
│   ├── basic/
│   │   ├── main.tf
│   │   └── README.md
│   └── ha/
│       ├── main.tf
│       └── README.md
└── modules/                   # 可選：sub-modules
    └── public-subnet/
        └── ...

原則 3：variable 與 output 都要寫 description

HCL · 可供他人使用的 module 範本 
# variables.tf
variable "name" {
  type        = string
  description = "Name prefix used for all resources in this VPC."

  validation {
    condition     = length(var.name) <= 32
    error_message = "Name must be 32 characters or fewer."
  }
}

variable "cidr_block" {
  type        = string
  description = "CIDR block for the VPC, e.g. \"10.0.0.0/16\". Must be in private RFC 1918 range."

  validation {
    condition     = can(cidrnetmask(var.cidr_block))
    error_message = "cidr_block must be a valid CIDR notation."
  }
}

variable "enable_dns_hostnames" {
  type        = bool
  description = "Whether to enable DNS hostnames for the VPC."
  default     = true
}

variable "tags" {
  type        = map(string)
  description = "Tags applied to all created resources."
  default     = {}
}

# outputs.tf
output "vpc_id" {
  value       = aws_vpc.main.id
  description = "ID of the created VPC."
}

output "private_subnet_ids" {
  value       = aws_subnet.private[*].id
  description = "List of private subnet IDs, in same order as availability_zones input."
}

原則 4：tag 與命名標準化

HCL · 統一 tag 處理 
locals {
  module_tags = {
    "Module" = "terraform-aws-vpc"
    "ManagedBy" = "OpenTofu"
  }

  # 合併 module 預設與使用者傳入
  effective_tags = merge(local.module_tags, var.tags)
}

resource "aws_vpc" "main" {
  cidr_block = var.cidr_block
  tags = merge(local.effective_tags, {
    Name = "${var.name}-vpc"
  })
}

原則 5：用 sub-module 做組合

大型 module 可拆成 sub-modules，讓使用者選擇「整套用」或「拆開用」：

Plaintext · 組合式設計 
terraform-aws-vpc/
├── main.tf              # 整套使用：呼叫所有 sub-module
├── variables.tf
├── outputs.tf
└── modules/
    ├── vpc-only/        # 只要 VPC core
    ├── public-subnet/   # 只要 public subnet
    ├── nat-gateway/     # 只要 NAT
    └── flow-logs/       # 只要 flow logs

# 使用者可全用：
# module "vpc" { source = "..." }

# 或只用部分：
# module "vpc_core" { source = "...//modules/vpc-only" }
# module "public" { source = "...//modules/public-subnet" }

9. 大型專案的目錄結構

策略 A：單一 stack（小型專案）

Plaintext · 小型專案 
myapp-infra/
├── main.tf              # 所有環境（dev/staging/prod）共用一套 stack，用 workspace 區分

策略 B：每環境獨立 stack（中型專案，推薦）

Plaintext · 環境隔離

│   ├── dev/

每個 env 目錄是獨立 root module，cd envs/prod && tofu apply。State 完全分開，避免 dev 操作意外影響 prod。

10. 反模式：什麼時候不該寫 module

並非所有東西都該包成 module。以下情況不要寫 module：

反模式 1：包了 module 但只是 1:1 對應 resource

HCL · ❌ 沒有抽象的 wrapper module 
# module/s3-bucket/main.tf
resource "aws_s3_bucket" "this" {
  bucket = var.bucket
  tags   = var.tags
}

# 使用：
# module "my_bucket" {
#   source = "./modules/s3-bucket"
#   bucket = "my-bucket"
#   tags   = local.tags
# }
# 等同於直接用 aws_s3_bucket！多繞一層

原則：如果你的 module 內部 resource 數 ≤ 2 且沒有額外邏輯，直接用 resource 就好。

反模式 2：把 root module 也包進 module 裡

有些團隊把整個專案做成 module，再在另一個 repo 呼叫它。除非你真的要重複部署同一套架構（如 SaaS 多 tenant），否則 root 直接寫即可。

反模式 3：variable 暴露了內部所有屬性

HCL · ❌ 變數爆炸的 module 
# module 有 50 個 variable，等於沒抽象
variable "vpc_cidr_block" {}
variable "vpc_enable_dns_hostnames" {}
variable "vpc_enable_dns_support" {}
variable "vpc_instance_tenancy" {}
variable "vpc_assign_generated_ipv6_cidr_block" {}
# ... 還有 45 個

原則：好的 module 透過合理預設值把選擇縮減到關鍵幾個。如果你發現需要 50 個 variable，module 設計可能有問題。

11. 常見陷阱與 troubleshooting

陷阱 1：改 module source 後忘了 tofu init

修改 source 或 version 後，OpenTofu 會提醒你需要 tofu init -upgrade。沒跑 init 直接 plan 會用舊的 cached module 內容。

陷阱 2：相對路徑搞錯

Module 內的 ${path.module}、${path.root}、${path.cwd} 各自指向不同地方：

路徑意義
path.module當前 module 的目錄
path.rootroot module 的目錄
path.cwdOpenTofu 當前的工作目錄（通常 == path.root）

讀取 module 自帶的檔案（templates、user-data scripts）一定要用 ${path.module}。

陷阱 3：在 child module 裡寫 backend

backend 設定只能在 root module。在 child module 寫 backend 會被忽略且發出警告。

陷阱 4：OCI module 的 zip 格式錯誤

OpenTofu 1.10+ 的 OCI module 規範要求：

  • artifactType 必須是 application/vnd.opentofu.modulepkg
  • 單一 layer，mediaType 必須是 archive/zip
  • zip 檔內不能有額外目錄包裹（解壓後直接看到 .tf 檔）

陷阱 5：Git source 用 https 但需要驗證

HTTPS clone 私 repo 時 OpenTofu 不會主動詢問密碼。改用：

Bash · git credentials 
# 方法 1：用 SSH（建議）
source = "git::ssh://git@github.com/myorg/m.git?ref=v1.0"

# 方法 2：用 git credential helper（事先 git config 設好）
# 方法 3：在 URL 帶 token（CI 用）
source = "git::https://${TOKEN}@github.com/myorg/m.git?ref=v1.0"
# 但要小心 token 不要寫在 .tf 檔！

12. 本章重點與練習

重點回顧

  • Module 是 OpenTofu 的程式碼重用單位，把它當作函式設計：variable=參數、output=回傳、internals=黑箱
  • Root module 是 tofu apply 的目錄；child module 是被呼叫的；backend 與 tfvars 只在 root 有意義
  • Module 支援 count、for_each、providers、depends_on、lifecycle.enabled（1.11+）等 meta-arguments
  • 八種來源：local path、registry、git、GitHub/Bitbucket 簡寫、HTTP archive、OCI、S3/GCS、Mercurial
  • 只有 registry 來源支援 version 屬性；其他來源用 ref / tag / digest 鎖定
  • Public OpenTofu Registry 直接可用 Terraform Registry 的 module；Private 需 Spacelift / GitLab / OCI 等方案，OCI 是 2026 年首選
  • OpenTofu 1.10+ 用 oras CLI 把 module 推到任何 OCI registry，artifactType = application/vnd.opentofu.modulepkg
  • Module 設計原則：單一職責、清晰介面、合理預設、tag 標準化、可拆解的 sub-module
  • 反模式：1:1 wrapper module、變數爆炸、把 root 也包成 module
  • 大型專案三策略：單一 stack（小）、每環境 stack（中）、多 stack mono-repo（大）
⚡ 動手實作 · Hands-on Lab 10

從零開始設計、發佈、使用一個 module

  1. 建立 module repo terraform-local-greeting/，標準結構（main.tf、variables.tf、outputs.tf、versions.tf、README.md、examples/basic/）
  2. module 功能：接收 names list 與 greeting 字串，用 local_file 為每個 name 產生一個檔案，內容是 "${greeting}, ${name}!"
  3. variable 帶 description、type、validation；output 帶 description
  4. 練習 A · local source：在另一個目錄建立 caller 專案，用 source = "../terraform-local-greeting" 呼叫
  5. 練習 B · git source：把 module 推到 GitHub，用 source = "git::https://github.com/YOU/terraform-local-greeting.git?ref=v0.1.0" 呼叫（記得打 tag）
  6. 練習 C · for_each module：用 for_each = var.environments 多次實例化同一個 module，每環境不同的 names list
  7. 練習 D · providers：在 module 內 require local provider，從 root 傳入
  8. 挑戰題 1 · OCI 發佈：用 oras CLI 把 module 推到 GHCR，並從 caller 用 oci://... 引用
  9. 挑戰題 2 · enabled module：(OpenTofu 1.11+) 在 caller 用 module "g" { lifecycle { enabled = var.create_greetings } ... } 條件啟用整個 module
  10. 挑戰題 3 · sub-module：把 module 拆成 core 與 sub-module（例如把「產生問候語」與「寫檔」分成兩個 sub-module），測試組合式呼叫
  11. 用 tofu destroy 清掉資源
