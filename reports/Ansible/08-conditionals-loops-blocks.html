第二篇 — 基礎使用

第 8 章 — 條件、迴圈、區塊

第一個 playbook 通常是一個 task 跑遍所有 host 一視同仁。但真實世界的 playbook 必須有「腦袋」——只有 Debian 系才裝 apt 套件、只有 production 環境才備份、服務啟動後等它真的就緒、5 個 user 一次建好。Ansible 用 when（條件）、loop（for 迴圈）、until（while 迴圈含重試）三個關鍵字加上第 6 章的 block 給你完整的控制流。本章把這四件事整合，並補上實戰中最常踩雷的細節：when 不要寫 {{ }}、loop 與 with_items 的選擇、loop_control 控制輸出標籤、retries / delay 的合理數字。

本章覆蓋官方文件對應：Conditionals · Loops · Until
初學者必讀（8.1–8.4） 開發者必讀（全章） DevOps / SRE 必讀（特別 8.5 until 重試與 8.7 實戰場景）

8.1when — 條件式執行

第 6 章已多次出現 when。本節系統整理它的語法陷阱與設計策略。

8.1.1基本語法：不要寫 {{ }}

⚠ when 內不要寫 {{ }}

when 的值本身就是 Jinja2 表達式，不需要再用 {{ }} 包起來——這是 Ansible 為了減少視覺噪音的設計。寫 when: "{{ x == 1 }}" 雖然有時能跑，但會收到 deprecation warning，未來版本可能直接報錯。

yaml · when 的標準寫法 
# ✓ 正確：直接寫表達式
- name: 只在 Debian 系執行
  ansible.builtin.apt:
    name: nginx
    state: present
  when: ansible_os_family == "Debian"

# ✗ 錯誤：不需要 {{ }} (deprecated)
- when: "{{ ansible_os_family == 'Debian' }}"

# 但 — 引用變數值當作模組參數時，要寫 {{ }}
- name: 參數中的變數要 {{ }}
  ansible.builtin.copy:
    src: "./{{ env }}.conf"            # 這裡需要
    dest: /etc/myapp/app.conf
  when: env == "production"           # 這裡不要

8.1.2多條件組合

yaml · 三種多條件寫法 
# 方式 ①：用 and / or / not
- when: ansible_os_family == "Debian" and ansible_memtotal_mb > 1024

# 方式 ②：寫成 list（隱含 AND，最易讀）
- when:
    - ansible_os_family == "Debian"
    - ansible_memtotal_mb > 1024
    - "'production' in group_names"

# 方式 ③：括號明確分組
- when: >
    (ansible_os_family == "Debian" or ansible_os_family == "RedHat")
    and ansible_distribution_major_version | int >= 9

8.1.3常用條件運算與測試

類型範例用途
比較ansible_distribution_major_version | int >= 22數字比較記得轉型 int
等於 / 不等env == "production" / env != "dev"字串比較
包含'production' in group_nameslist 內含元素
不包含'staging' not in group_names
正則ansible_kernel is match("6\\..+")regex 匹配
已定義my_var is defined變數有沒有設定
未定義my_var is undefined
檔案存在config_file is exists需先 stat / register
register 結果成功result is succeeded等價 result is not failed
register 結果改變result is changed常用於依前一 task 結果分流
register 結果跳過result is skipped條件不符時的判斷
版本比較my_ver is version('2.0', '>=')語意化版本比較

8.1.4用前一個 task 結果作條件

yaml · register + when 配合 
- name: 查 nginx 是否 active
  ansible.builtin.command: "systemctl is-active nginx"
  register: nginx_status
  changed_when: false
  failed_when: false

- name: 不在跑 → 啟動它
  ansible.builtin.service:
    name: nginx
    state: started
  when: nginx_status.stdout != "active"

- name: 如果某設定檔不存在才複製預設值
  ansible.builtin.stat:
    path: /etc/myapp/app.conf
  register: cfg_stat

- name: 複製預設設定
  ansible.builtin.copy:
    src: default.conf
    dest: /etc/myapp/app.conf
  when: not cfg_stat.stat.exists

8.1.5沒有 if / else — 用兩個 task

ⓘ Ansible 沒有 if/else 結構

Ansible 不支援 if X then A else B 這種結構。需要二選一就寫兩個 task，用互補的 when 條件：

yaml · 互補 when 模擬 if/else 
- name: Debian 系 — 用 apt
  ansible.builtin.apt: { name: nginx, state: present }
  when: ansible_os_family == "Debian"

- name: RedHat 系 — 用 dnf
  ansible.builtin.dnf: { name: nginx, state: present }
  when: ansible_os_family == "RedHat"

8.2loop — for 迴圈

當你發現自己在寫「裝 nginx、裝 curl、裝 git」三個一模一樣的 task，就該用 loop。

8.2.1基本 loop

yaml · 簡單 loop 範例 
- name: 安裝多個套件
  ansible.builtin.apt:
    name: "{{ item }}"             # item 是 loop 提供的內建變數
    state: present
  loop:
    - nginx
    - curl
    - git
    - htop

# 但 — 對於 package 類模組，「直接傳 list」更高效（一次 transaction）
- name: 同樣效果但更快
  ansible.builtin.apt:
    name: [nginx, curl, git, htop]
    state: present
ⓘ 何時該 loop，何時該傳 list？

支援 list 參數的模組（如 apt、dnf、package），傳 list 比 loop 快很多——一個 transaction 處理所有套件。Loop 適合每個 item 邏輯不同的情境（不同檔名、不同設定）。

8.2.2Loop dict 結構

yaml · loop list of dicts 
- name: 建立多個 user
  ansible.builtin.user:
    name: "{{ item.name }}"
    groups: "{{ item.groups }}"
    shell: "{{ item.shell | default('/bin/bash') }}"
    state: present
  loop:
    - { name: alice,   groups: sudo,docker }
    - { name: bob,     groups: developers, shell: /bin/zsh }
    - { name: deploy,  groups: deploy }
  become: true

8.2.3Loop dict（key-value）

yaml · 用 dict2items 走訪 dict 
vars:
  services_ports:
    nginx: 80
    postgresql: 5432
    redis: 6379

tasks:
  - name: 列出每個服務的 port
    ansible.builtin.debug:
      msg: "{{ item.key }} = {{ item.value }}"
    loop: "{{ services_ports | dict2items }}"
    # dict2items 把 dict 轉成 [{key: nginx, value: 80}, ...]

8.2.4Loop + register

第 7 章 下已介紹過：loop 配 register 時，結果存在 .results list 裡。

yaml · loop + register 結構 
- name: 查多個 service
  ansible.builtin.command: "systemctl is-active {{ item }}"
  register: svc_results
  loop: [nginx, postgresql, redis]
  changed_when: false
  failed_when: false

- name: 挑出沒在跑的服務
  ansible.builtin.debug:
    msg: "{{ item.item }} 沒在跑！(stdout: {{ item.stdout }})"
  loop: "{{ svc_results.results }}"
  when: item.stdout != "active"
  loop_control:
    label: "{{ item.item }}"           # 輸出時只顯示服務名（見 8.3）

8.3loop_control — 控制 loop 行為

當 loop item 是大型 dict，預設輸出會把整個 dict 印出來，log 變得難以閱讀。loop_control 提供幾個關鍵設定。

8.3.1label — 簡化輸出

yaml · loop_control.label 
- name: 部署多個設定檔
  ansible.builtin.template:
    src: "{{ item.template }}"
    dest: "{{ item.dest }}"
    mode: "{{ item.mode }}"
  loop:
    - { template: api.conf.j2,   dest: /etc/myapp/api.conf,    mode: "0644" }
    - { template: db.conf.j2,    dest: /etc/myapp/db.conf,     mode: "0600" }
  loop_control:
    label: "{{ item.dest }}"            # log 只印 /etc/myapp/api.conf
    # 沒設 label 時 log 會印整個 dict (template+dest+mode)

8.3.2loop_var — 改變預設變數名

ⓘ 巢狀 loop 的命名衝突

當你在 include_tasks 或巢狀情境下有兩層 loop，預設兩層都用 item 變數，內層會覆蓋外層。loop_var 改名解決衝突：

yaml · loop_var 範例 
- name: 外層 loop — 對每個 user 引入子 tasks
  ansible.builtin.include_tasks: setup-user.yml
  loop: "{{ users }}"
  loop_control:
    loop_var: user                  # 外層用 user 而非 item

# setup-user.yml 內可以再有 loop 用 item 不會衝突
- name: 部署該 user 的多個 SSH keys
  ansible.posix.authorized_key:
    user: "{{ user.name }}"          # 外層 user
    key: "{{ item }}"                # 內層 item
  loop: "{{ user.ssh_keys }}"

8.3.3index_var、pause、extended

yaml · loop_control 進階 
- name: 逐筆處理（含序號）
  ansible.builtin.debug:
    msg: "處理第 {{ idx }} 個 user: {{ item.name }}"
  loop: "{{ users }}"
  loop_control:
    index_var: idx                  # 從 0 開始的序號變數名
    pause: 2                          # 每 item 之間 sleep 2 秒
    extended: true                    # 提供 ansible_loop.first/last/index 等

8.4Loop + when 組合

when 配 loop 時，每個 item 都會獨立評估一次條件。這是極常用的模式——對 list 中只處理符合條件的 item。

8.4.1用 item 屬性當條件

yaml · 只處理 enabled 的 item 
- name: 只裝標記為 required 的套件
  ansible.builtin.apt:
    name: "{{ item.name }}"
    state: present
  loop:
    - { name: nginx,   required: true }
    - { name: apache2, required: false }
    - { name: curl,    required: true }
    - { name: telnet,  required: false }
  when: item.required
  become: true

8.4.2結合 host 條件 + item 條件

yaml · 跨平台條件 loop 
- name: 裝平台特定工具
  ansible.builtin.package:
    name: "{{ item.package }}"
    state: present
  loop:
    - { package: apt-transport-https,    os_family: Debian }
    - { package: yum-utils,              os_family: RedHat }
    - { package: curl,                   os_family: all }
  when: item.os_family == ansible_os_family or item.os_family == "all"
  become: true

8.4.3多條件組合

yaml · 多條件 loop 
- name: 部署符合「啟用 + 環境匹配」的設定檔
  ansible.builtin.template:
    src: "{{ item.template }}"
    dest: "{{ item.dest }}"
  loop:
    - template: api.conf.j2
      dest: /etc/myapp/api.conf
      enabled: true
      environments: [production, staging]
    - template: debug.conf.j2
      dest: /etc/myapp/debug.conf
      enabled: true
      environments: [development]
    - template: legacy.conf.j2
      dest: /etc/myapp/legacy.conf
      enabled: false
      environments: [production]
  when:
    - item.enabled
    - target_env in item.environments
  loop_control:
    label: "{{ item.template }}"

8.5until — while 迴圈與重試

跟 loop 不同，until 是「同一個 task 重複跑直到條件成立」的 while 迴圈，常見用於等服務啟動、API 就緒、檔案出現等情境。

8.5.1基本用法

yaml · until 等服務就緒 
- name: 啟動 nginx
  ansible.builtin.service:
    name: nginx
    state: started

- name: 等 nginx 真正開始接受連線
  ansible.builtin.uri:
    url: "http://localhost/health"
    status_code: 200
  register: health
  until: health.status == 200          # 條件成立才結束
  retries: 10                            # 最多重試 10 次
  delay: 5                               # 每次間隔 5 秒
  # 總共最多等 10 × 5 = 50 秒

8.5.2retries 與 delay 的合理數字

場景retriesdelay (秒)總等待 (秒)
本地服務啟動10330
Web 應用就緒（含 DB 預熱）305150
外部 API 等候2010200
雲端資源 provisioning6015900
K8s pod ready3010300
ⓘ 預設值是 retries=3, delay=5

沒指定的話 Ansible 預設總等待僅 15 秒——對大部分服務啟動太短。永遠明確指定 retries 與 delay。

8.5.3典型場景：DB cluster 啟動

yaml · 等 PostgreSQL 完全就緒 
- name: 啟動 PostgreSQL
  ansible.builtin.systemd:
    name: postgresql
    state: started

- name: 等 PostgreSQL 接受連線
  ansible.builtin.command: "pg_isready -h localhost -p 5432"
  register: pg_ready
  until: pg_ready.rc == 0
  retries: 15
  delay: 4
  changed_when: false            # 純查詢不算 changed

- name: 建立 application database
  community.postgresql.postgresql_db:
    name: myapp
    state: present
  become_user: postgres
  register: db_create
  until: db_create is succeeded
  retries: 3
  delay: 5

8.5.4典型場景：等部署版本生效

yaml · 跨 LB 等新版本 
- name: 驗證新版本已部署
  ansible.builtin.uri:
    url: "https://api.example.com/version"
    return_content: true
  register: version_check
  until: >
    version_check.status == 200
    and version_check.json.version == target_version
  retries: 20
  delay: 10
  vars:
    target_version: "2.5.0"

8.5.5三種迴圈一表看懂

機制對應用途
loopfor-each對 list 每個 item 跑一次（可不同參數）

8.6with_* 系列：舊版 loop 風格

Ansible 2.5 之前用 with_items、with_dict 等。2.5+ 推薦改用 loop，但 with_* 沒被 deprecated，老 playbook 仍能執行。

8.6.1常見 with_* 變體

舊風格 with_*新風格等價差異
with_items: [a, b, c]loop: [a, b, c]with_items 會自動 flatten 一層 list
with_dict: {...}loop: "{{ d | dict2items }}"新風格要顯式轉換
with_fileglob: "*.txt"loop: "{{ query('fileglob', '*.txt') }}"用 query / lookup 取代
with_subelementsloop: "{{ a | subelements('b') }}"同上
⚠ with_items → loop 的 flatten 陷阱

with_items 自動展平一層巢狀 list：[[a,b],[c]] → [a,b,c]。改用 loop 不會自動展平，可能要加 | flatten(1) 維持原行為。轉換時務必對照測試。

8.7實戰場景：條件 + 迴圈 + 重試 + Block 整合

實戰中以上四件事很少單獨使用。下面是把它們整合的完整範例：

8.7.1場景一：跨 OS 部署 web 後驗證

yaml · 整合範例：跨 OS + 重試 + 錯誤處理 
- name: 部署 web 服務
  block:
    # 1) 跨 OS 安裝（互補 when）
    - name: Debian 系裝套件
      ansible.builtin.apt:
        name: [nginx, curl]
        state: present
        update_cache: true
      when: ansible_os_family == "Debian"

    - name: RedHat 系裝套件
      ansible.builtin.dnf:
        name: [nginx, curl]
        state: present
      when: ansible_os_family == "RedHat"

    # 2) 用 loop 部署多個設定檔
    - name: 部署 nginx 設定群
      ansible.builtin.template:
        src: "{{ item.src }}"
        dest: "{{ item.dest }}"
      loop:
        - { src: nginx.conf.j2, dest: /etc/nginx/nginx.conf }
        - { src: vhost.conf.j2, dest: /etc/nginx/conf.d/site.conf }
      notify: restart nginx
      loop_control:
        label: "{{ item.dest }}"

    # 3) 啟動服務
    - name: 啟動 nginx
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

    # 4) until 等服務就緒
    - name: 等 nginx 接受連線
      ansible.builtin.uri:
        url: http://localhost/health
        status_code: 200
      register: health
      until: health.status == 200
      retries: 15
      delay: 3

  rescue:
    - name: 部署失敗 — 通知
      ansible.builtin.uri:
        url: "{{ alert_webhook }}"
        method: POST
        body: '{"text": "Web deploy failed on {{ inventory_hostname }}"}'

  become: true

8.7.2場景二：批次處理多個目標

yaml · 整合範例：批次 user 設定 
vars:
  team_users:
    - { name: alice,  role: admin,    enabled: true }
    - { name: bob,    role: developer, enabled: true }
    - { name: old,    role: developer, enabled: false }

tasks:
  - name: 建立 enabled user
    ansible.builtin.user:
      name: "{{ item.name }}"
      groups: "{{ 'sudo' if item.role == 'admin' else 'developers' }}"
      state: present
    loop: "{{ team_users }}"
    when: item.enabled
    loop_control:
      label: "{{ item.name }} ({{ item.role }})"
    become: true

  - name: 移除 disabled user
    ansible.builtin.user:
      name: "{{ item.name }}"
      state: absent
      remove: true
    loop: "{{ team_users }}"
    when: not item.enabled
    loop_control:
      label: "{{ item.name }}"
    become: true

8.8本章重點回顧

01

when 不要寫 {{ }}

表達式直接寫，when: ansible_os_family == "Debian"。多條件用 list 寫法（隱含 AND）最易讀。

02

沒有 if/else

需要二選一就寫兩個 task，用互補的 when 條件。Ansible 設計哲學：聲明式而非命令式。

03

loop 取代多個重複 task

loop: [...] 取代多個一樣的 task。但對於支援 list 的模組（apt、dnf、package），傳 list 比 loop 快。

04

Loop dict 用 dict2items

走訪 dict 時 loop: "{{ mydict | dict2items }}"，內部用 item.key / item.value 訪問。

05

loop_control 改善可讀性

label 簡化 log 輸出、loop_var 解巢狀命名衝突、index_var 取序號、pause 限速。

06

Loop + when 每 item 評估

條件對 loop 內每個 item 獨立評估。常用模式：list of dict 含旗標，when: item.enabled。

07

until 是 while 迴圈

同一個 task 重試。必設 retries 與 delay（預設 3×5=15 秒太短）。常用於等服務就緒、API 可用、版本生效。

08

with_* 與 loop 並存

with_items 等舊風格還能用但建議改 loop。注意 with_items 自動 flatten 一層，轉換時可能要加 | flatten(1)。

練習題

  1. 初學者：寫一個 playbook 用 when 在 Debian 系裝 apt-utils，在 RedHat 系裝 dnf-plugins-core。觀察 PLAY RECAP 中 skipped 的數字。
  2. 初學者：用 loop 一次建立 3 個目錄（/opt/app/logs、/opt/app/data、/opt/app/cache）。
  3. 初學者：把上題改用 list of dict，每個 item 含 path 與 mode 兩個 key，部署不同權限。
  4. 開發者：寫一個 loop 走訪 list of dict（user 清單），用 when: item.enabled 只處理 enabled 的；加 loop_control.label 讓 log 只顯示 user name。
  5. 開發者：用 dict2items 走訪一個 service:port 的 dict，印出每個服務名與 port 的對照。
  6. 開發者：寫一個 until 等服務的 health endpoint 回 200。設 retries=20、delay=3，故意先讓 endpoint 不存在，觀察重試 log。
  7. DevOps / SRE：寫一個整合 block + loop + when + until 的部署 playbook（參考 8.7.1 範例），包含跨 OS 套件安裝、設定檔批次部署、服務啟動、健康檢查、失敗 rescue 通知。
  8. DevOps / SRE：拿一個既有用 with_items 的 role / playbook，改寫成 loop。仔細測試，特別注意原本是巢狀 list 時的 flatten 行為差異。
  9. DevOps / SRE：在跨 5 台 host 的部署中，用 loop_control.pause: 3 讓 task 之間 sleep 3 秒，避免對 LB / DB 的同時壓力。觀察 log 看到的時間差異。

本章詞彙表

when
Task 層 directive，控制 task 是否執行。值是 Jinja2 表達式，不要寫 {{ }}。寫成 list 表示 AND 組合。
loop
Task 層 directive，對 list 每個 item 重複執行 task。Ansible 2.5+ 推薦寫法。
item
loop 內建的迴圈變數名。可用 loop_control.loop_var 改名解決巢狀衝突。
with_items / with_dict / with_fileglob 等
舊風格 loop 系列，2.5+ 推薦改用 loop + lookup / filter。沒被 deprecated 但已不是首選。
loop_control
Task 層 directive，含子設定 label / loop_var / index_var / pause / extended 等，控制 loop 行為與輸出。
label (loop_control)
自訂 log 輸出時顯示的 item 標籤。當 item 是大型 dict 時必設，否則 log 太雜亂。
loop_var (loop_control)
把預設 item 變數名改成自訂名。巢狀 loop（外層 + include_tasks 內層）時必用。
index_var (loop_control)
取得當前 item 的序號（從 0 開始）。
until
Task 層 directive，重試 task 直到條件成立。配 retries（最多重試次數）與 delay（每次間隔秒）。預設 3 / 5。
retries
until 的最大重試次數。預設 3，生產建議 10–60 視場景而定。
delay
until 的每次重試間隔（秒）。預設 5。
dict2items
Jinja2 filter，把 dict 轉成 list of {key, value} dict 供 loop 使用。
flatten
Jinja2 filter，把巢狀 list 展平。| flatten(1) 等同 with_items 預設行為。
changed_when / failed_when
Task 層 directive，自訂何時算 changed / failed。常用於 command/shell 抑制誤報，或設更嚴格的失敗判定。
is succeeded / is failed / is changed / is skipped
Jinja2 test，用於 when 判斷前一個 task（透過 register 取得）的結果狀態。
is defined / is undefined / is exists
Jinja2 test，判斷變數是否定義、檔案是否存在等。
