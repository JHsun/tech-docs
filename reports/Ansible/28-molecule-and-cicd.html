28.1為什麼 Ansible 也要測試

「Ansible 是 declarative，自動 idempotent」是迷思。idempotence 不是 Ansible 給你的，是你給 Ansible 的——只要你寫了 command: / shell: 沒加 creates: / changed_when: / when:，idempotence 就破了。本節給三個 testing 必要性。

28.1.1三個必須測的場景

🔁

Idempotence

「跑兩次與跑一次結果應一致」。第二次跑應該全 OK 與 0 changed。沒測就不知道有沒有 bug。Molecule 內建 idempotence 階段自動驗。

🐧

多 OS / 多版本

Role 在 Ubuntu 22 跑得好，到 Rocky 9 可能 package 名換、systemd unit 路徑換。Matrix testing 對 4-5 個 OS 跑同份 role。

⚠

邊界條件

變數沒設、檔案不存在、第二次 deploy（已部署過）、partial failure 後重跑。verify task 寫 assertion 確認結果。

⚠ 常見破壞 idempotence 的三大寫法

① command: rm /tmp/x — 沒加 creates: 永遠 changed；② shell: pip install foo — 沒判斷已裝；③ 任何用 register: ... 後跑 task — register 本身永遠不算 changed，但 conditional 沒設好就會。Molecule idempotence 階段跑第二次 converge、檢查整 play recap 沒任何 task 是 changed。違反就 fail。

28.3.2常用命令

命令做什麼典型用途
molecule test跑完整 11 階段（含銷毀）CI 跑 / 完整驗證
molecule create啟 instance 但不跑 role準備 debug 環境

✓ 開發迴圈 — converge + verify

反覆改 role 時，不要每次都跑 molecule test（每次重啟 container 慢）。改成：① molecule create（一次）→ ② 改 role → molecule converge（快、複用 container）→ ③ molecule verify（跑 assertion）→ 改完最後 molecule destroy。完整 test 留給 CI。

28.5converge.yml 與 verify.yml

28.5.1converge.yml — 對 instance 跑 role

---
- name: Converge
  hosts: all
  become: true

  vars:
    # 測試特定的 role 變數
    webapp_port: 8080
    webapp_log_level: debug

  tasks:
    - name: 套用 role
      ansible.builtin.include_role:
        name: my_webapp

28.5.2verify.yml — Ansible 風格 assertion

yaml · molecule/default/verify.yml 
---
- name: Verify
  hosts: all
  gather_facts: false
  tasks:

    # 確認套件裝了
    - name: 查 nginx 套件
      ansible.builtin.package:
        name: nginx
      check_mode: true
      register: pkg
      failed_when: pkg.changed     # changed 表示沒裝（要去裝）

    # 確認 service 跑著
    - name: 查 nginx 服務狀態
      ansible.builtin.systemd:
        name: nginx
      register: svc

    - ansible.builtin.assert:
        that:
          - svc.status.ActiveState == 'active'
          - svc.status.SubState == 'running'

    # 確認端點回應
    - name: 打健康檢查
      ansible.builtin.uri:
        url: "http://localhost:{{ webapp_port }}/health"
        status_code: 200
        return_content: true
      register: health

    - ansible.builtin.assert:
        that:
          - "'ok' in health.content"

    # 確認 config 內容正確
    - name: slurp app.env
      ansible.builtin.slurp:
        src: /etc/webapp/app.env
      register: cfg

    - ansible.builtin.assert:
        that:
          - "'LOG_LEVEL=debug' in (cfg.content | b64decode)"

28.5.3verify 派系：Ansible vs Testinfra

派系機制優劣
Ansible verifier（推薦） verify.yml 用 assert 模組 同語言、低學習成本、與 Ansible 模組整合好
Testinfra verifier tests/ 目錄寫 pytest 測試 pytest 生態強、進階斷言；多一層學習
python · tests/test_default.py — Testinfra 範例（替代） 
def test_nginx_installed(host):
    nginx = host.package("nginx")
    assert nginx.is_installed

def test_nginx_running(host):
    nginx = host.service("nginx")
    assert nginx.is_running
    assert nginx.is_enabled

def test_nginx_listening(host):
    socket = host.socket("tcp://0.0.0.0:8080")
    assert socket.is_listening

def test_app_env_content(host):
    cfg = host.file("/etc/webapp/app.env")
    assert cfg.exists
    assert cfg.user == "webapp"
    assert cfg.mode == 0o600
    assert "LOG_LEVEL=debug" in cfg.content_string

28.6ansible-lint 與 yamllint

Lint 是 cheap 的第一道防線——比 Molecule 快百倍，能抓 80% 低級錯誤。

28.6.1兩個 linter 分工

工具檢查什麼例子
yamllint YAML 語法 / 排版 縮排不對、行太長、trailing space
ansible-lint Ansible best practices 沒寫 name、用 shell 而非 module、沒 FQCN、idempotence 警告

28.6.2常見 ansible-lint 警告

yaml · 常被 ansible-lint 抓到的反模式 
# ❌ 沒 name — name[missing]
- apt:
    name: nginx

# ✓ 有 name + FQCN
- name: 裝 nginx
  ansible.builtin.apt:
    name: nginx

# ❌ shell 跑能用 module 做的事 — command-instead-of-module
- name: restart nginx
  ansible.builtin.shell: systemctl restart nginx

# ✓ 用 module
- name: restart nginx
  ansible.builtin.systemd:
    name: nginx
    state: restarted

# ❌ shell 沒 changed_when — no-changed-when
- name: 查版本
  ansible.builtin.shell: my-app --version

# ✓ 加 changed_when: false
- name: 查版本
  ansible.builtin.shell: my-app --version
  changed_when: false          # 查詢動作不算 change

# ❌ 用 latest 不指定版本 — package-latest
- ansible.builtin.apt:
    name: nginx
    state: latest          # 每次跑可能裝不同版！

# ✓ 用 present + 指定版本
- ansible.builtin.apt:
    name: nginx=1.24.*
    state: present

28.6.3設定檔

yaml · .ansible-lint — rule 配置 
---
profile: production          # min / basic / moderate / safety / shared / production

exclude_paths:
  - .cache/
  - .github/
  - tests/

skip_list:
  - 'experimental'            # 還在實驗的規則

warn_list:
  - 'fqcn-builtins'            # 警告但不 fail

use_default_rules: true

28.7GitHub Actions CI 整合

本地能跑 Molecule 是好事；CI 自動跑才是必要。每次 push / PR 都跑、所有 OS 矩陣、不過不能 merge。

28.7.1完整 CI workflow

yaml · .github/workflows/ci.yml 
---
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  # Job 1: lint — 快速失敗 fast-fail
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install lint tools
        run: pip install ansible-lint yamllint

      - name: Run yamllint
        run: yamllint .

      - name: Run ansible-lint
        run: ansible-lint

  # Job 2: molecule matrix — 多 OS 並行
  molecule:
    runs-on: ubuntu-latest
    needs: lint             # lint 過了才跑（節省 CI 時間）
    strategy:
      fail-fast: false      # 一個 OS 失敗其他繼續跑
      matrix:
        distro:
          - ubuntu2404
          - debian12
          - rocky10

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install Molecule
        run: |
          pip install ansible-core molecule "molecule-plugins[docker]" \
            ansible-lint pytest-testinfra

      - name: Install role dependencies
        run: |
          ansible-galaxy collection install -r requirements.yml || true
          ansible-galaxy role install -r requirements.yml || true

      - name: Run Molecule
        run: molecule test
        env:
          MOLECULE_DISTRO: ${{ matrix.distro }}
          PY_COLORS: "1"
          ANSIBLE_FORCE_COLOR: "1"

28.8.3自動發布 workflow

yaml · .github/workflows/release.yml 
---
name: Release to Galaxy

on:
  push:
    tags: ["v*"]

jobs:
  galaxy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install ansible
        run: pip install ansible-core

      - name: Trigger Galaxy import
        env:
          GALAXY_API_TOKEN: ${{ secrets.GALAXY_API_TOKEN }}
        run: |
          ansible-galaxy role import \
            "${{ github.repository_owner }}" \
            "${{ github.event.repository.name }}" \
            --token "$GALAXY_API_TOKEN"

28.9業界最佳實踐

①

每個 role 都有 Molecule scenario

沒測試的 role = 定時炸彈。新 role 一律 molecule init scenario 帶 default scenario。

②

idempotence 是 testing 第一條

跑兩次都 0 changed 才算過。Molecule 內建 idempotence 階段不過 = 直接 fail。

③

Multi-OS matrix testing

支援的所有 OS 都加入 matrix。Geerlingguy 的 docker images（含 systemd）是常用選擇。

④

用 Podman 而非 Docker

Podman rootless 更安全、CI 兼容性好、systemd 支援更乾淨。Docker 仍可用但不是首選。

⑤

verify task 要實質

不要只「裝了就好」。確認 service 跑著 + endpoint 回應 + config 內容正確。

⑥

ansible-lint profile=production

用最嚴格 profile。FQCN 全用、沒 name 不過、idempotence 警告當錯誤。

⑦

CI 鎖版本

ansible-core==2.18.*、molecule==26.* 鎖死。新版發布前先在 dev branch 測。

⑧

semantic versioning + 自動發布

Git tag vMAJOR.MINOR.PATCH → GitHub Actions → Galaxy / Automation Hub。手動 import 是反模式。

28.10本章重點回顧

01

Ansible 也要測試

Idempotence、多 OS、邊界條件三大場景。「跑過一次沒爆」≠「正確」。

02

Molecule 是事實標準

啟 instance → 跑 role → 驗證 → 銷毀。Docker / Podman driver 容器化、ephemeral。

03

11 階段生命週期

dependency → lint → destroy → syntax → create → prepare → converge → idempotence → side_effect → verify → destroy。核心三個：converge / idempotence / verify。

04

scenario 設計

default 基本 + multi-os 矩陣 + upgrade 升級場景。每個 scenario 一個 molecule.yml + converge.yml + verify.yml。

05

verify 兩派

Ansible verifier（assert + register）— 推薦；Testinfra（pytest）— 進階。多數選 Ansible verifier。

06

ansible-lint + yamllint

cheap fast-fail。FQCN / name / changed_when / package version 等常見反模式。profile: production 嚴格。

07

CI 整合 — GitHub Actions

lint job → molecule matrix job（多 OS 並行）。push / PR 自動觸發。沒過不能 merge。

08

Galaxy 自動發布

git tag v1.2.0 → Actions → ansible-galaxy import。semantic versioning + meta/main.yml 完整必填。

練習題

  1. 初學者：對既有 role 跑 molecule init scenario。理解 molecule/default/ 內三個檔案（molecule.yml / converge.yml / verify.yml）的角色。
  2. 初學者：跑 molecule test。觀察 11 階段順序輸出（dependency → lint → destroy → … → verify → destroy）。
  3. 初學者：用 molecule create + molecule converge + molecule login 進入容器手動探查。改 role 後不重啟容器、再 converge 驗證迭代速度。
  4. 開發者：故意在 role 內寫 command: rm /tmp/x（沒 creates），觀察 idempotence 階段失敗訊息。修成有 creates 的版本，重跑觀察通過。
  5. 開發者：寫 verify.yml — 至少 5 個 assertion（package / service / port / file content / endpoint health）。molecule verify 確認都通過。
  6. 開發者：建第二個 scenario multi-os，平台 ubuntu2404 + rocky10 + debian12 三個。觀察哪個 OS 失敗，修 role 加 OS 兼容判斷。
  7. DevOps / SRE：寫完整 GitHub Actions CI workflow — lint job + molecule matrix job（3 個 OS 並行）。push 後到 Actions 看綠燈。
  8. DevOps / SRE：加 ansible-lint profile: production。把所有 warning 修到 0。對 PR 加 branch protection 規則（lint + molecule 都要過才能 merge）。
  9. DevOps / SRE：發布你的 role 到 Galaxy（用 lab 帳號）。寫 release.yml 自動 workflow — push tag v0.1.0 自動觸發 import。

本章詞彙表

Molecule
Ansible role 測試框架。事實標準。提供生命週期管理、driver、verifier、lint 整合。
Scenario
Molecule 的測試配置單元。一個 role 可有多 scenario（default / multi-os / upgrade）。每 scenario 一個目錄含 molecule.yml + converge.yml + verify.yml。
molecule.yml
scenario 主設定。dependency / driver / platforms / provisioner / verifier 五段式。
converge.yml
對測試 instance 跑的 playbook。通常 include_role 套用被測 role + 設定測試特定變數。
verify.yml
套完 role 後跑的驗證 playbook。用 assert + register 模組做 assertion。
Driver
Molecule 啟動測試 instance 的後端。常用 podman / docker / delegated。Vagrant / EC2 等 community 維護。
Platform
具體的測試 instance 定義。指定 image / privileged / systemd / capabilities 等。
11 階段生命週期
dependency → lint → destroy → syntax → create → prepare → converge → idempotence → side_effect → verify → destroy。core 三階段：converge（套 role）/ idempotence（驗證）/ verify（assertion）。
Idempotence 階段
Molecule 內建——converge 完再跑一次，整個 play recap 沒任何 task 是 changed 才算過。違反 idempotence 的 role 自動 fail。
side_effect
選用階段。在 converge 與 verify 之間觸發某些 trigger（如重啟 host、模擬故障），測試 role 對 side effect 的恢復能力。
pre_build_image
platform 選項。true 表示 image 已含必要工具（systemd / Python），不需 Molecule 動手裝。Geerlingguy 系列 image 多數有。
geerlingguy/docker-*-ansible image
Jeff Geerling 維護的測試 image 系列（docker-ubuntu2404-ansible / docker-debian12-ansible / docker-rockylinux10-ansible）。社群事實標準。
Verifier — Ansible
用 verify.yml + assert 模組寫 assertion。低學習成本、與 Ansible 整合好。多數選擇。
Verifier — Testinfra
用 pytest 風格寫測試（tests/test_*.py）。提供 host fixture（host.package / host.service / host.file / host.socket）。pytest 生態強。
ansible-lint
Ansible 程式碼靜態分析工具。檢查 best practices（FQCN / name / changed_when / package version 等）。profile 控制嚴格度。
yamllint
YAML 語法 / 排版 lint。檢查縮排、行長度、trailing whitespace。與 ansible-lint 互補。
profile（ansible-lint）
嚴格度 profile：min / basic / moderate / safety / shared / production。生產建議 production（最嚴）。
FQCN (Fully Qualified Collection Name)
完整 collection.module 命名。ansible.builtin.apt 而非 apt。ansible-lint 預設要求。
changed_when
task 選項，覆蓋預設 changed 判斷。changed_when: false 表示這 task 永遠不算 changed（查詢類用）。
creates / removes（command/shell）
command / shell 模組的選項。creates: /tmp/x 表示「如果 /tmp/x 存在就跳過此 task」。實作 idempotence 的關鍵。
GitHub Actions matrix
workflow 的 strategy.matrix。對多個變數值並行跑同 job。多 OS 測試的標準做法。
fail-fast
matrix 選項。true = 一個失敗整個 cancel；false = 各自跑完。Molecule matrix 通常設 false 看完整結果。
Branch protection
GitHub repo 的設定 — main branch 必須某些 CI check 通過才能 merge PR。確保 broken code 不進主幹。
Semantic versioning (semver)
版本號規範 MAJOR.MINOR.PATCH。MAJOR = breaking change；MINOR = 加功能但相容；PATCH = bug fix。Galaxy 與 Automation Hub 都遵循。
Ansible Galaxy
Ansible 社群 role / collection 中心倉庫。免費、公開、open source。
Automation Hub
Red Hat 商業版 — Ansible Automation Platform 的 role / collection 倉庫。經 Red Hat 認證、含 Ansible Validated Content。
ansible-galaxy import
命令——觸發 Galaxy 從 GitHub 拉指定 tag 的 role。配 GitHub Actions 自動跑。
meta/main.yml
role 的 metadata 檔。Galaxy 用此判斷 role 名稱、作者、相依、支援平台。發布前必填齊。
