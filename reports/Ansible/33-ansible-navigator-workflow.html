33.1navigator vs ansible-playbook — 為什麼換

33.1.1痛點與解法

傳統 ansible-playbook 痛點navigator 解法
本機 vs CI vs prod 三邊環境不一致 — Python / 套件版本差 三邊都用同一個 EE container — 完全一致
200 task 跑完只看一片黑白 stdout、找失敗 task 像大海撈針 TUI 可 drill 進每個 task、看 register / stderr / args
失敗了想再看上次結果 → 只能重跑（risky / 慢） 每次跑都自動存 JSON artifact、replay 可重複看
不知道 EE 內裝了什麼 collection / Python pkg collections / images subcommand 直接看
查 module 文件要切瀏覽器 TUI 內 :doc apt 就看
本機跑通 AAP 跑炸 — 預設參數不同 navigator 預設 = AAP / Controller 跑法（一致）
ⓘ 預設行為與 AAP 一致

navigator 預設行為刻意做成跟 AAP / Controller / AWX 相同——目的是讓「本機能跑」直接保證「AAP 上能跑」。例外：vars_prompt / pause / --ask-pass 預設不支援（AAP 也不支援），需要用 --enable-prompts flag 強制 stdout 模式才能用。

33.4八個 subcommand 全集

navigator 不只是 run。run 只是 8 個 subcommand 之一。

Subcommand做什麼典型用法
run跑 playbookansible-navigator run site.yml
inventory瀏覽 / 列 inventoryansible-navigator inventory -i hosts.yml
collections列 EE 內含的 collectionsansible-navigator collections
config看 ansible configansible-navigator config
images檢視 EE image 內容ansible-navigator images
doc看 module / lookup / filter 文件ansible-navigator doc apt
replay重看之前 run 的 artifactansible-navigator replay site-2026-05-08.json
exec在 EE container 內執行任意命令ansible-navigator exec -- ansible-test sanity

33.4.1常用範例

bash · 八個 subcommand 實戰 
# 1) run — 最基本
$ ansible-navigator run site.yml -i inventory/

# 2) inventory — 看 group / host 結構（替代 ansible-inventory）
$ ansible-navigator inventory -i inventory/ -m stdout --list
$ ansible-navigator inventory -i inventory/ -m stdout --graph

# 3) collections — 看 EE 含哪些 collection
$ ansible-navigator collections \
    --eei quay.io/ansible/awx-ee:latest -m stdout

# 4) config — 看 ansible 設定（哪個值生效）
$ ansible-navigator config -m stdout --dump

# 5) images — 檢視 image 詳情、含 collection / Python pkg / system
$ ansible-navigator images

# 6) doc — 看 module 文件（替代 ansible-doc）
$ ansible-navigator doc ansible.builtin.apt -m stdout
$ ansible-navigator doc community.postgresql.postgresql_db

# 7) replay — 重看之前的 run（不重跑）
$ ansible-navigator replay artifacts/site-2026-05-08.json

# 8) exec — 在 EE container 內跑任意命令
$ ansible-navigator exec -- ansible-test sanity --python 3.12
$ ansible-navigator exec -- ansible-galaxy collection list
$ ansible-navigator exec -- bash       # 互動 shell

33.5完整 settings 配置

ansible-navigator.yml（或 .ansible-navigator.yml）是專案級配置檔。寫好一份、團隊每人都用同一套規則。

33.5.1查找順序

優先序位置
1（最高）$ANSIBLE_NAVIGATOR_CONFIG 環境變數指定
2當前目錄 ./ansible-navigator.yml 或 .ansible-navigator.yml
3家目錄 ~/.ansible-navigator.yml
4（最低）命令列 flag 永遠覆蓋以上

33.5.2Dev profile

yaml · ansible-navigator.yml — dev 開發用 
---
ansible-navigator:
  # 預設互動模式
  mode: interactive

  execution-environment:
    enabled: true
    image: ghcr.io/ansible/community-ansible-dev-tools:latest
    container-engine: podman
    pull:
      policy: missing             # 本機 dev — 有就用、沒有才拉

    # 把本機 SSH key mount 進去（讓 EE 能用本機 key 連線）
    volume-mounts:
      - src: "${HOME}/.ssh"
        dest: /home/runner/.ssh
        options: ro

    environment-variables:
      set:
        ANSIBLE_FORCE_COLOR: "true"

  playbook-artifact:
    enable: true
    save-as: "{playbook_dir}/artifacts/{playbook_name}-{time_stamp}.json"

  logging:
    level: debug
    file: /tmp/ansible-navigator-dev.log

  ansible:
    cmdline: "--diff"           # dev 永遠看 diff

33.5.3CI profile

yaml · ansible-navigator.yml — CI/CD 用 
---
ansible-navigator:
  # CI 必 stdout（沒 TTY）
  mode: stdout

  execution-environment:
    enabled: true
    image: registry.example.com/myorg/ansible-ee:2.1.0
    pull:
      policy: missing            # CI 緩存命中省流量

    environment-variables:
      # CI 用 pass 模式 — 從 host env 透傳（不寫 secret 進 config）
      pass:
        - VAULT_PASSWORD
        - AWS_ACCESS_KEY_ID
        - AWS_SECRET_ACCESS_KEY
      set:
        ANSIBLE_FORCE_COLOR: "true"

  playbook-artifact:
    enable: true
    save-as: "/artifacts/{playbook_name}-{time_stamp}.json"

  logging:
    level: warning            # CI log 不要太多
    file: /var/log/ansible-navigator.log

  color:
    enable: true
✓ pass vs set 之差

set = 把值寫進 EE 環境（值在 config 裡看得到，secret 別這樣）；pass = 從 host 環境變數透傳到 EE（值不出現在 config）。secret 一律 pass、非 secret（如 ANSIBLE_FORCE_COLOR）才 set。

33.6Playbook artifact 與 replay

navigator 最強功能之一——每次跑都自動存完整 JSON 結果，可離線 replay。

33.6.1artifact 內容

📄

每個 task 完整結果

changed / failed / skipped 狀態、register / stdout / stderr / args / 跑了多久。

📊

play recap

每個 host 的 ok / changed / failed / skipped 統計。

🕐

時間戳

play / task 的 start / end / duration。可分析效能瓶頸。

💾

變數快照

跑當下的 inventory / extra_vars / group_vars 等。事後可重現環境。

33.6.2replay 工作流

bash · 三個典型 replay 場景 
# 1) 自己 debug — 跑完後沒馬上看結果，回頭再 inspect
$ ansible-navigator run site.yml -m stdout
# ... task 47 失敗，但你已經 scroll 到看不見 ...

$ ls artifacts/
# site-2026-05-08T15-30-22.json

# 進 TUI replay 看完整結果（不用重跑）
$ ansible-navigator replay artifacts/site-2026-05-08T15-30-22.json


# 2) 分享給同事 debug
$ scp artifacts/site-prod-2026-05-08.json colleague@bastion:/tmp/

# 同事在他電腦：
$ ansible-navigator replay /tmp/site-prod-2026-05-08.json
# 完整看到所有 task 結果，不需 access prod inventory / hosts


# 3) 合規 / 稽核保留
# 把 artifact 存進 S3 或 audit storage
$ aws s3 cp artifacts/ s3://compliance-audit/ansible/$(date +%Y/%m/) --recursive

# 半年後稽核要查「2026-05-08 那次部署改了什麼」 → replay 即可

33.7開發迴圈最佳化

反覆改 playbook 時要的不是「完整跑」，而是快速確認改的對不對。

33.7.1七個加速技巧

bash · 加速 dev 迭代 
# 1) syntax check — 毫秒級
$ ansible-navigator run dev.yml --syntax-check -m stdout

# 2) list-tasks 不執行 — 看 task 名稱對不對
$ ansible-navigator run dev.yml --list-tasks -m stdout

# 3) list-hosts — 確認 hosts 範圍對
$ ansible-navigator run dev.yml --list-hosts -m stdout

# 4) check + diff — dry run 看會改什麼
$ ansible-navigator run dev.yml --check --diff -m stdout

# 5) tags — 只跑某類 task
$ ansible-navigator run dev.yml --tags "nginx,ssl" -m stdout

# 6) start-at-task — 跳過前面成功的
$ ansible-navigator run dev.yml \
    --start-at-task "Process application config" -m stdout

# 7) limit — 只對單一 host 跑（debug 用）
$ ansible-navigator run dev.yml --limit web-01 -m stdout

33.7.2Jinja2 lab — 快速試 filter / lookup

yaml · jinja-lab.yml — 試 Jinja2 表達式 
---
- name: Jinja2 expression lab
  hosts: localhost
  connection: local
  gather_facts: false
  vars:
    items:
      - {name: "alpha", score: 85, active: true}
      - {name: "beta",  score: 92, active: false}
      - {name: "gamma", score: 95, active: true}
  tasks:
    - name: selectattr 過濾
      ansible.builtin.debug:
        msg: "Active: {{ items | selectattr('active') | map(attribute='name') | list }}"

    - name: json_query
      ansible.builtin.debug:
        msg: "High scorers: {{ items | json_query('[?score > `90`].name') }}"

    - name: combine + default
      ansible.builtin.set_fact:
        merged: "{{ {'a': 1, 'b': 2} | combine({'b': 3, 'c': 4}) }}"

    - ansible.builtin.debug:
        var: merged

# 跑：ansible-navigator run jinja-lab.yml
# 在 TUI 內 drill 每個 debug task 看完整結果

33.8CI 整合 — 與 AAP 用同一個 EE

本地能跑 → AAP 能跑（理論上）。但實際上人們在本地用 ansible-playbook、AAP 用 EE → 環境差異 → 翻車。解法：本地也用 navigator + 同一個 EE。

33.8.1三邊環境統一

Figure 33.3 — 三邊用同一個 EE = 行為一致

33.8.2GitHub Actions 完整 workflow

yaml · .github/workflows/ansible.yml 
---
name: Ansible CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  syntax-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install navigator
        run: pip install ansible-navigator

      - name: Login to registry
        run: |
          echo "${{ secrets.REGISTRY_PASSWORD }}" | \
            podman login registry.example.com -u ci-bot --password-stdin

      - name: Syntax check
        run: |
          ansible-navigator run site.yml \
            --syntax-check \
            -m stdout

  deploy-staging:
    runs-on: ubuntu-latest
    needs: syntax-check
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    env:
      VAULT_PASSWORD: ${{ secrets.VAULT_PASSWORD }}
      AWS_ACCESS_KEY_ID: ${{ secrets.AWS_KEY_ID }}
    steps:
      - uses: actions/checkout@v4
      - run: pip install ansible-navigator

      - name: Deploy staging
        run: |
          ansible-navigator run deploy.yml \
            -i inventory/staging \
            --extra-vars "release=$(git rev-parse --short HEAD)" \
            -m stdout

      # Upload artifact for debug
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: ansible-artifact
          path: artifacts/*.json
ⓘ artifact 上傳到 GitHub Actions

把 navigator 的 JSON artifact 上傳到 GitHub Actions artifact — CI 失敗時開發者能下載 JSON 用本機 navigator replay debug、不必再次跑 prod inventory。團隊協作神器。

33.10業界最佳實踐

①

本機全面取代 ansible-playbook

不要兩個工具並存。navigator 全面用、有 alias alias ap='ansible-navigator run -m stdout' 過渡期。

②

每專案一份 ansible-navigator.yml

commit 進 git。團隊每人 clone 後就有一致設定。EE image 鎖定。

③

本機 dev / CI / AAP 同一 EE

同一個 image tag。「在我電腦能跑」直接保證 AAP 也能跑。

④

artifact 預設啟用

每次 run 都存 JSON。佔空間不大但 debug 時無價。CI artifact 也上傳。

⑤

secret 用 pass 不用 set

EE 環境變數 secret 一律 pass 從 host 透傳。set 只放非 secret。

⑥

pull policy 看場景

本機 dev 用 missing（有就用）；CI 用 missing（cache 友善）；prod 用 never（完全離線）。

⑦

TUI 用於 debug、stdout 用於 CI

互動模式適合人；stdout 適合 script。CI 強制 stdout（沒 TTY）。

⑧

合規場景存 artifact 到 audit storage

金融 / 醫療每次部署 artifact 推 S3 audit bucket。半年後稽核可 replay 完整看。

33.11本章重點回顧

01

navigator 解決真實痛點

三邊一致 / TUI debug / artifact replay / 內建 EE 支援 / 預設與 AAP 一致。

02

兩種模式

interactive（TUI）= dev 用；stdout = CI / 自動化用。CI 必須 stdout（沒 TTY）。

03

TUI cheat sheet

數字選 / Esc 退 / :doc :collections :inventory :run :replay /pattern :quit。

04

八個 subcommand

run / inventory / collections / config / images / doc / replay / exec。doc 取代 ansible-doc、replay 是殺手鐧。

05

settings 兩 profile

dev profile（interactive / pull missing / mount SSH key）+ CI profile（stdout / pass secret / quiet log）。

06

Artifact + replay

每次跑存 JSON。本機 debug / 分享同事 / 合規稽核三大場景。

07

Dev 加速七招

--syntax-check / --list-tasks / --list-hosts / --check --diff / --tags / --start-at-task / --limit。

08

練習題

  1. 初學者：裝 ansible-navigator + podman。對任意 playbook 跑 ansible-navigator run xxx.yml 進 TUI、用數字 drill 看 task 結果、用 :quit 退出。
  2. 初學者：用 ansible-navigator doc ansible.builtin.apt 看 apt module 文件。比較與 ansible-doc apt 的差別。
  3. 初學者：用 ansible-navigator collections -m stdout 看 EE 內含 collection 列表。換不同 EE 比較差異。
  4. 開發者：寫 ansible-navigator.yml dev profile。鎖某個 EE image / mount SSH key / 啟用 artifact / cmdline --diff。確認 commit 進 git 後同事 clone 跑 navigator 行為一致。
  5. 開發者：跑某個 playbook 後不關 terminal。看 artifact JSON 內容（用 jq 檢視）、再用 navigator replay TUI 重看。
  6. 開發者：寫 jinja-lab.yml 試 5 個 Jinja2 表達式（selectattr / map / json_query / combine / regex_replace）。用 navigator 跑、TUI 內 drill 看每個結果。
  7. DevOps / SRE：寫 GitHub Actions workflow — syntax-check + deploy job 兩段、artifact 上傳。故意觸發失敗、下載 artifact 用本機 navigator replay debug。
  8. DevOps / SRE：對某個 production playbook 用 navigator + AAP 同一個 EE image。本地跑 + AAP 跑兩處結果，確認 100% 一致。記下任何不一致時的原因。
  9. DevOps / SRE：寫 VS Code launch.json 配置 debug navigator 自己。對某 collection 進入 navigator 內部執行流程設 breakpoint、step 看執行邏輯。

本章詞彙表

ansible-navigator
新一代 Ansible CLI + TUI。本機跑 playbook 在 EE container 內。漸取代 ansible-playbook。安裝：pip install ansible-navigator。
interactive mode
navigator 預設模式（-m interactive）。啟動 TUI、可 drill 進 task、用 vim-like 命令探索。dev / debug 用。
stdout mode
-m stdout flag。輸出像 ansible-playbook 一樣 stream 到 terminal。CI / 自動化必用（沒 TTY）。
TUI (Text User Interface)
navigator 的文字介面。數字選項 / Esc 退 / :命令 / /搜尋。類 vim / less 操作。
Subcommand
navigator 的 8 個子命令：run / inventory / collections / config / images / doc / replay / exec。每個都有 -m interactive / -m stdout 兩種模式。
run subcommand
跑 playbook。最常用。ansible-navigator run site.yml。
inventory subcommand
瀏覽 / 列 inventory。替代 ansible-inventory。--list / --graph 格式輸出。
collections subcommand
列 EE 內含的 collections。看 EE 裝了什麼。
config subcommand
看 ansible 的 config 設定（哪些值生效、來自哪個來源）。替代 ansible-config。
images subcommand
檢視 EE image 的內容（collection / Python pkg / system pkg / 環境變數）。debug 用。
doc subcommand
看 module / lookup / filter 文件。替代 ansible-doc。ansible-navigator doc apt。
replay subcommand
重看之前跑的 artifact。ansible-navigator replay site-2026-05-08.json。debug + 分享神器。
exec subcommand
在 EE container 內執行任意命令。ansible-navigator exec -- ansible-test sanity。collection 開發 / 測試用。
Playbook artifact
navigator 每次跑自動產的 JSON 檔。含每 task 完整結果、play recap、時間戳、變數快照。預設存當前目錄。
artifact save-as
artifact 檔名 / 路徑模板。支援 {playbook_dir} / {playbook_name} / {time_stamp} placeholder。
ansible-navigator.yml
專案級配置檔。當前目錄與 ~/ 都會被讀。設定 EE / mode / artifact / logging 等預設。commit 進 git 同團隊一致。
$ANSIBLE_NAVIGATOR_CONFIG
環境變數指定 config 檔位置。覆蓋當前目錄與家目錄的 config。最高優先序。
execution-environment.image
config 內指定預設用哪個 EE image。CLI --eei 可覆蓋。
execution-environment.pull.policy
image pull 策略：always（每次拉）/ missing（沒有才拉）/ never（不拉）/ tag（tag 是 latest 或 mutable 才拉）。
volume-mounts
把 host 目錄 mount 進 EE container。常見用途：mount SSH key（讓 EE 能用本機 key 連線）、mount ansible.cfg。
environment-variables.set
config 中直接設定環境變數值寫進 EE。值出現在 config 檔——secret 別這樣。
environment-variables.pass
從 host 環境變數透傳到 EE。值不出現在 config。secret（VAULT_PASSWORD / API key）必用此模式。
--enable-prompts
navigator flag。允許 vars_prompt / pause / --ask-pass 互動（預設不允許、保持與 AAP 一致）。需要時才用、會關閉 artifact。
--syntax-check
只檢查 YAML 語法、不執行。毫秒級。commit 前快速 sanity。
--list-tasks / --list-hosts
不執行、列 task 名稱 / hosts 範圍。確認 playbook 結構與目標。
--start-at-task
從指定名稱 task 開始跑。debug 反覆同 task 時加速。
--tags / --skip-tags
限制只跑 / 跳過某 tag 的 task。reduced run。
--limit
限制 host 範圍。debug 對單一 host 跑用。
cmdline (config)
config 中 ansible.cmdline 設定額外 ansible-playbook flag。例如 cmdline: "--diff" 永遠帶 diff。
community-ansible-dev-tools
官方 dev EE image（ghcr.io/ansible/community-ansible-dev-tools）。內含 navigator + builder + lint + molecule + 常用 collection。dev 推薦用。
VS Code Ansible extension
官方 redhat.ansible 擴充。整合 navigator、ansible-lint、語法 highlight、auto-complete。
