第五篇 — 網路與雲端自動化

第 22 章 — Windows 自動化

前 21 章預設情境是 Linux + SSH + Python module。Windows 三件事都不一樣：協定是 WinRM（不是 SSH）、模組語言是 PowerShell（不是 Python）、認證機制比 Linux 複雜（Basic / NTLM / Kerberos / CredSSP / Certificate）。本章帶你完整跨進 Windows 領域：① Windows 為何不同（架構與限制）；② 三大 connection plugin（winrm / psrp / 新的 SSH）的選擇；③ 五種 authentication 方法的實際差異與 trade-off；④ Windows 端 WinRM 設定；⑤ 三大 Windows collection（ansible.windows / community.windows / chocolatey.chocolatey）；⑥ 實戰常見 ops（套件管理、服務、註冊表、使用者、檔案）；⑦ Active Directory 管理（從 control 端用 community.windows）。本章預設讀者熟悉 Linux 自動化（前面 21 章），但 Windows 經驗不必豐富——重點是把 Windows 自動化整合進你既有的 Linux + Cloud Ansible 體系。

本章覆蓋官方文件對應：Managing Windows Hosts · Windows Remote Management · ansible.windows · community.windows
初學者選讀（22.1–22.3 概念與簡單模組） 開發者選讀（22.7 寫 Windows module 概要） DevOps / SRE / Windows admin 必讀（全章）

22.1Windows 自動化的三件不一樣

動工前先校準心智模型——Windows 不是「裝了 SSH 的 Linux」。三個關鍵差異決定了 inventory、connection、模組怎麼寫：

22.1.1差異對照

面向Linux 自動化Windows 自動化
連線協定SSH（port 22）WinRM 預設（port 5985 HTTP / 5986 HTTPS）；2.18+ 也支援 SSH
遠端執行語言PythonPowerShell（Windows 沒預裝 Python）
模組語言PythonPowerShell + 額外的 Ansible.Basic 框架
FQCN 命名ansible.builtin.copyansible.windows.win_copy 等 win_ 前綴
認證SSH key（簡單）5+ 種選擇（Basic / NTLM / Kerberos / CredSSP / Certificate）
套件管理apt / yum 標配需要 Chocolatey / WinGet 或 MSI 直接裝
FQCN 範例ansible.builtin.serviceansible.windows.win_service

ⓘ Control node 必須是 Linux / macOS

Ansible 官方支援的 control node 是 Linux / macOS。Windows 上的 Ansible 只有 WSL（Windows Subsystem for Linux）這個半官方路徑——本章假設你的 control node 是 Linux。但 managed node（要被管的）可以、也經常是 Windows。

22.2三大 connection plugin 的選擇

22.2.1三選一對照

Plugin底層優點限制
winrm（傳統） WinRM SOAP / WS-Man 歷史悠久、文件多、最廣泛部署 性能稍弱、protocol overhead 較大
psrp（推薦） WinRM 傳輸 + PowerShell Remoting Protocol 同樣 WinRM port、效能更好、PowerShell 原生資料 需 pypsrp library
ssh（2.18+ 官方支援） OpenSSH（Windows Server 2019+ 內建可開） SSH key 驗證簡單、不必設 WinRM 較新、與 PowerShell credential delegation 整合不如 WinRM

22.2.2選擇建議

①

新專案 / Domain 環境

用 psrp + Kerberos。性能好、credential delegation 完善、生產環境最佳組合。

②

非 Domain / lab 環境

用 psrp + NTLM，或 SSH + key（Win Server 2019+）。lab / 小團隊測試環境用 SSH 最簡單。

③

已有 winrm 設定

不必改——winrm 仍是穩定首選。psrp 是 incremental 升級，可以後再換（只改 inventory）。

④

跨 forest / 多 domain

用 winrm 或 psrp + CredSSP。是唯一支援 second-hop credential delegation 的組合。

22.2.3inventory 寫法對照

yaml · inventory/windows.yml — 三種 connection 寫法 
---
all:
  hosts:
    # --- 1) winrm （傳統） ---
    win01:
      ansible_host: 10.0.1.10
      ansible_connection: winrm
      ansible_winrm_transport: ntlm
      ansible_port: 5986
      ansible_winrm_server_cert_validation: ignore     # lab 用，prod 應驗證

    # --- 2) psrp （推薦） ---
    win02:
      ansible_host: 10.0.1.11
      ansible_connection: psrp
      ansible_psrp_auth: negotiate          # 自動嘗試 Kerberos / NTLM
      ansible_psrp_protocol: https
      ansible_psrp_port: 5986
      ansible_psrp_cert_validation: ignore

    # --- 3) ssh （Windows Server 2019+） ---
    win03:
      ansible_host: 10.0.1.12
      ansible_connection: ssh
      ansible_shell_type: cmd          # 或 powershell
      ansible_user: Administrator

  vars:
    ansible_user: Administrator
    ansible_password: "{{ vault_win_password }}"

22.3五種認證方法

Windows 認證比 Linux 複雜得多——五種方法各有適用場景。選錯認證會讓 playbook 跑不起來、credentials 卡住、second-hop 失敗。

方法適用credential delegation安全度
basic local user / lab 否 低 — 明文密碼，必須 HTTPS
ntlm local + domain（無 Kerberos infra） 否 中
kerberos domain 環境（推薦） 是（with delegation flag） 高
credssp second-hop 場景 是（最強） 中 — 需小心暴露 credential
certificate 無人值守 / 自動化 否 高 — 無密碼

22.3.1second-hop 問題與 CredSSP

⚠ 「double-hop」/ second-hop 問題

Linux 沒這個問題，但 Windows 必踩。場景：control node 用 user A 連 win01，win01 上的 task 要再連 file server win02 時——NTLM/Kerberos 預設不允許 win01 拿 user A 的 credential 再對 win02 認證。會看到 Access is Denied。解法：① CredSSP（最快）；② Kerberos 加上 delegation flag；③ 把 task 拆成兩段，先在 control 端做。

22.3.2實際設定範例

yaml · 四種典型認證設定 
# --- NTLM（local user / 無 Kerberos）---
ansible_connection: psrp
ansible_psrp_auth: ntlm
ansible_user: Administrator
ansible_password: "{{ vault_win_password }}"

# --- Kerberos（domain，推薦） ---
ansible_connection: psrp
ansible_psrp_auth: kerberos
ansible_user: [email protected]      # 必須 user@REALM 格式
ansible_password: "{{ vault_win_password }}"

# --- CredSSP（second-hop）---
ansible_connection: psrp
ansible_psrp_auth: credssp
ansible_user: domain\Administrator
ansible_password: "{{ vault_win_password }}"

# --- Certificate（無人值守）---
ansible_connection: winrm
ansible_winrm_transport: certificate
ansible_winrm_cert_pem: /etc/ansible/win-cert.pem
ansible_winrm_cert_key_pem: /etc/ansible/win-cert-key.pem

22.4Windows 端 WinRM 設定

新裝的 Windows Server 預設 WinRM 沒對遠端開放——必須先設定。下面是可一行跑完的腳本，原本的 ConfigureRemotingForAnsible.ps1 從 GitHub 取得（已存檔的話可直接打）。

22.4.1用 ConfigureRemotingForAnsible.ps1

powershell · 在 Windows host 端執行（Administrator PowerShell） 
# 下載並執行 — 啟用 WinRM HTTPS、自簽憑證、Basic Auth
$url = "https://raw.githubusercontent.com/ansible/ansible-documentation/devel/examples/scripts/ConfigureRemotingForAnsible.ps1"
$file = "$env:temp\ConfigureRemotingForAnsible.ps1"

(New-Object -TypeName System.Net.WebClient).DownloadFile($url, $file)
powershell.exe -ExecutionPolicy ByPass -File $file

# 該腳本會做：
# - 啟用 WinRM service 並設成 auto-start
# - 建立自簽憑證綁定 5986 port
# - 啟用 Basic auth（lab 用 — prod 應該 disable 改用 NTLM/Kerberos）
# - 開 firewall 規則允許 5985 5986

22.4.2手動設定 — 較細的控制

powershell · 生產環境手動設定 
# 1) 啟用 WinRM service
Enable-PSRemoting -Force

# 2) 不啟用 Basic（生產用 Kerberos / NTLM 即可）
Set-Item -Path WSMan:\localhost\Service\Auth\Basic -Value $false

# 3) 啟用 NTLM / Kerberos（預設已開）
Set-Item -Path WSMan:\localhost\Service\Auth\Kerberos -Value $true
Set-Item -Path WSMan:\localhost\Service\Auth\Negotiate -Value $true

# 4) 強制 HTTPS — 用 AD CA 簽的證書取代自簽
$cert = New-SelfSignedCertificate -DnsName $env:COMPUTERNAME -CertStoreLocation Cert:\LocalMachine\My
New-Item -Path WSMan:\localhost\Listener -Transport HTTPS -Address * -CertificateThumbprint $cert.Thumbprint

# 5) 關掉 HTTP listener（強制 HTTPS）
Get-ChildItem WSMan:\Localhost\Listener | Where-Object {$_.Keys -contains "Transport=HTTP"} | Remove-Item

# 6) firewall 規則
New-NetFirewallRule -DisplayName "WinRM HTTPS" -Direction Inbound -Protocol TCP -LocalPort 5986 -Action Allow

# 驗證
Test-WSMan -ComputerName localhost -UseSSL

22.4.3從 Linux 端測試

bash · ad-hoc ping 測試 
# 用 ansible.windows.win_ping 測連線
$ ansible -i inventory/windows.yml win01 \
    -m ansible.windows.win_ping

# 預期：
# win01 | SUCCESS => { "changed": false, "ping": "pong" }

# 設定錯誤常見錯誤訊息：

22.6實戰：常見 Windows ops

22.6.1裝 IIS + 部署簡單網站

yaml · playbooks/iis_setup.yml 
---
- name: 配置 IIS web server
  hosts: windows_servers
  gather_facts: true
  tasks:
    - name: 裝 IIS Windows feature
      ansible.windows.win_feature:
        name:
          - Web-Server
          - Web-Common-Http
          - Web-Mgmt-Console
        state: present
        include_management_tools: true
      register: iis

    - name: 必要時 reboot
      ansible.windows.win_reboot:
      when: iis.reboot_required

    - name: 部署 index.html
      ansible.windows.win_copy:
        content: "<h1>Hello from Ansible-managed IIS</h1>"
        dest: 'C:\inetpub\wwwroot\index.html'

    - name: 確保 W3SVC 服務跑著
      ansible.windows.win_service:
        name: W3SVC
        state: started
        start_mode: auto

    - name: 放行 HTTP 80
      community.windows.win_firewall_rule:
        name: HTTP Inbound
        localport: 80
        action: allow
        direction: in
        protocol: tcp
        state: present
        enabled: yes

22.6.2使用者 / 群組管理

yaml · 建立 local user 並加進 Administrators 
- name: 建立 local user
  ansible.windows.win_user:
    name: deploy_svc
    password: "{{ vault_deploy_password }}"
    password_never_expires: yes
    user_cannot_change_password: yes
    groups:
      - Administrators
      - Remote Management Users
    groups_action: replace      # add / remove / replace
    state: present

- name: 加既有 user 到群組
  ansible.windows.win_group_membership:
    name: Administrators
    members:
      - jenkins_svc
      - monitoring_svc
    state: present

22.6.4註冊表編輯

yaml · 改 registry 與 Windows Update 設定 
- name: 關閉 Windows Update 自動 reboot
  ansible.windows.win_regedit:
    path: 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU'
    name: NoAutoRebootWithLoggedOnUsers
    data: 1
    type: dword
    state: present

- name: 查 Windows 版本
  ansible.windows.win_reg_stat:
    path: 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion'
    name: DisplayVersion
  register: winver

- debug:
    var: winver.value

22.6.5Windows Updates + reboot

yaml · 自動套用 Windows updates 
- name: 裝所有 critical / security updates
  ansible.windows.win_updates:
    category_names:
      - CriticalUpdates
      - SecurityUpdates
    state: installed
    reboot: true          # 必要時自動 reboot
    reboot_timeout: 3600
  register: update_result

- debug:
    msg:
      - "裝了 {{ update_result.installed_update_count }} 個 updates"
      - "reboot 過：{{ update_result.reboot_required }}"

22.7.2建立 AD user

yaml · 從 control 端管理 AD（透過任一 domain-joined Windows host） 
---
- name: 管理 AD users
  hosts: domain_controller      # 一台 DC 或 domain-joined member
  tasks:
    - name: 建立 AD user
      community.windows.win_domain_user:
        name: jdoe
        firstname: John
        surname: Doe
        password: "{{ vault_jdoe_password }}"
        state: present
        enabled: true
        password_never_expires: false
        user_cannot_change_password: false
        path: "OU=Engineers,OU=Users,DC=example,DC=com"
        groups:
          - Engineers
          - VPN Users
        attributes:
          title: Senior SRE
          department: Platform
          company: Example Inc.
          mail: [email protected]

    - name: 查 AD user 詳細
      community.windows.win_domain_object_info:
        filter: "sAMAccountName -eq 'jdoe'"
      register: user_info

    - debug:
        var: user_info.objects

22.7.3把 host join 進 domain

yaml · 新 server 加入 domain 
- name: 加入 example.com domain
  community.windows.win_domain_membership:
    dns_domain_name: example.com
    domain_admin_user: admin@EXAMPLE.COM
    domain_admin_password: "{{ vault_domain_admin_pwd }}"
    domain_ou_path: "OU=Servers,OU=Production,DC=example,DC=com"
    state: domain
  register: join

- name: 必要時 reboot
  ansible.windows.win_reboot:
  when: join.reboot_required

22.8跨平台 inventory（Linux + Windows）

實際企業大多是混合環境。設計 inventory 讓 Linux 與 Windows 共存：

yaml · inventory/all.yml — Linux + Windows 並行 
---
all:
  children:

    linux_servers:
      hosts:
        app01: { ansible_host: 10.0.1.10 }
        app02: { ansible_host: 10.0.1.11 }
      vars:
        ansible_user: ubuntu
        ansible_connection: ssh

    windows_servers:
      hosts:
        winapp01: { ansible_host: 10.0.2.10 }
        winapp02: { ansible_host: 10.0.2.11 }
      vars:
        ansible_connection: psrp
        ansible_psrp_auth: kerberos
        ansible_user: [email protected]
        ansible_password: "{{ vault_win_password }}"
        ansible_psrp_protocol: https

    monitoring_targets:        # 業務群組 — 跨平台
      children:
        linux_servers:
        windows_servers:
yaml · 在 playbook 中分流 
# 跨平台 ping 測試
- hosts: monitoring_targets
  tasks:
    - name: Linux ping
      ansible.builtin.ping:
      when: ansible_os_family != 'Windows'

    - name: Windows ping
      ansible.windows.win_ping:
      when: ansible_os_family == 'Windows'

# 較乾淨：兩個 play 分流
- hosts: linux_servers
  tasks: [{ ansible.builtin.ping: }]

- hosts: windows_servers
  tasks: [{ ansible.windows.win_ping: }]

22.9業界最佳實踐

①

新環境用 psrp

從 winrm 升級到 psrp 只改 inventory（無需 Windows 端改動）。psrp 性能好、PowerShell 原生資料、未來主流。

②

domain 環境用 Kerberos

有 domain 就 Kerberos。NTLM 是後備、Basic 是 lab 用。Kerberos + delegation flag 解決 second-hop。

③

HTTPS over HTTP

WinRM 預設 5985 是 HTTP（明文）。生產一律 5986 HTTPS。憑證用 AD CA 簽，不要永遠 ignore 自簽。

④

密碼 vault 必上

Windows password 在 inventory 永遠 {{ vault_xxx }}。不要寫死。

⑤

用 win_powershell 跑進階 PS 腳本

標準 win_* 模組不夠時用 ansible.windows.win_powershell（取代舊的 win_shell），支援結構化輸出與 idempotency。

⑥

reboot_required 處理

許多 Windows 操作（feature install / update）會要求 reboot。用 register + when: x.reboot_required + win_reboot 處理。

⑦

chocolatey 取代 MSI 手裝

套件管理用 win_chocolatey 比 win_package 更乾淨。鎖版本、easy upgrade、卸載也乾淨。

⑧

跨平台 inventory 分群清楚

Linux / Windows 分不同 group + 不同 group_vars。不要強行讓同一個 play 跑 mixed host——分兩個 play 乾淨。

22.10本章重點回顧

01

Windows 三件不一樣

連線是 WinRM、模組是 PowerShell、認證有 5 種選擇。前 21 章 Linux 範式不能照抄。

02

三大 connection plugin

winrm（傳統穩定）、psrp（推薦，效能好）、ssh（2.18+，OpenSSH on Windows）。新專案選 psrp。

03

五種認證方法

basic（lab）、NTLM（無 domain）、Kerberos（推薦）、CredSSP（second-hop）、certificate（無人值守）。

04

Windows 端設 WinRM

用 ConfigureRemotingForAnsible.ps1 一行搞定 lab；prod 手動設 HTTPS + 關 Basic + AD CA cert。

05

三大 collection

ansible.windows（核心，~50 模組）、community.windows（進階 / AD / IIS，~80 模組）、chocolatey.chocolatey（套件管理）。

06

常見 Windows ops 模組

win_feature / win_service / win_user / win_regedit / win_copy / win_template / win_updates / win_reboot 八大類覆蓋日常 90%。

07

AD 管理

community.windows.win_domain_* 系列。建 user / group / membership / domain join。透過 domain-joined Windows host 跑。

08

業界 8 條最佳實踐

psrp / Kerberos / HTTPS / vault / win_powershell / reboot_required / chocolatey / 跨平台 inventory 分群。

練習題

  1. 初學者：在 VirtualBox / Hyper-V / 雲端起一台 Windows Server 2022，跑 ConfigureRemotingForAnsible.ps1。從 Linux control node 用 ansible -m ansible.windows.win_ping 確認連線。
  2. 初學者：對該 Windows host 跑 ansible.windows.win_user 建一個 local user，用 PowerShell Get-LocalUser 確認建立成功。
  3. 初學者：用 chocolatey.chocolatey.win_chocolatey 裝 git + notepad++ 兩個套件，state: present。跑兩次確認第二次 idempotent（changed=False）。
  4. 開發者：實作本章 22.6.1 的 IIS setup playbook，加上：① 建立第二個 site（綁不同 port）；② 用 community.windows.win_iis_webapppool 建獨立 app pool。
  5. 開發者：把 inventory 從 winrm 改成 psrp，比對前後跑同一份 playbook 的時間（profile_tasks callback）。
  6. 開發者：寫一個 playbook 把 host 從 workgroup 加進你的 lab domain（用 win_domain_membership），register 後處理 reboot。
  7. DevOps / SRE：設計一個跨平台 inventory（Linux + Windows），寫一個「裝 monitoring agent」playbook 對兩種 OS 用對應模組（apt 對 Linux、win_chocolatey 對 Windows）裝同個 agent。
  8. DevOps / SRE：寫 patch management playbook — 對所有 windows_servers 跑 win_updates（critical + security），serial: 25% 分批，每批 reboot 完再下一批。失敗就停止。
  9. DevOps / SRE：實作 second-hop scenario — 從 control 連 win01、win01 上 task 要連 file server 拉檔案。先用 NTLM 觀察 Access Denied 錯誤，再切 CredSSP 確認可行。

本章詞彙表

WinRM (Windows Remote Management)
Microsoft 的 HTTP-based 遠端管理協定。Ansible 對 Windows 預設用 WinRM。Port 5985（HTTP）/ 5986（HTTPS）。
PSRP (PowerShell Remoting Protocol)
用 WinRM 為傳輸層的 PowerShell 原生 protocol。Ansible 的 psrp connection plugin 用此 protocol，比 winrm SOAP 高效。
winrm connection plugin
傳統的 Ansible Windows connection plugin。底層用 SOAP / WS-Man over HTTP(S)。需 pywinrm。
psrp connection plugin
較新的 Windows connection plugin（現為 ansible-core 內建）。底層仍是 WinRM 但以 PowerShell Remoting Protocol 通訊。需 pypsrp。
ssh on Windows
Windows Server 2019+ 內建 OpenSSH。Ansible 2.18+ 官方支援用 ssh connection 對 Windows。
Basic auth
明文密碼認證。最簡單但最不安全。lab / 學習用，必須 over HTTPS。
NTLM
Microsoft 老牌 challenge-response 認證。支援 local + domain account。預設啟用。不支援 credential delegation。
Kerberos
業界標準 ticket-based 認證。domain 環境推薦。支援 credential delegation（with flag）。需 krb5 lib + 正確 DNS / SPN 設定。
CredSSP
Credential Security Support Provider。唯一能解決 second-hop 問題的常用方法。透過 TLS 包覆 credential。
Certificate auth
X509 客戶端憑證認證。無密碼、適合無人值守自動化。需在 Windows 端 map cert 到 user。
Second-hop / double-hop 問題
從 control 連 win01、win01 task 再連 win02 的場景。NTLM/Kerberos 預設不允許 credential 二次傳遞。CredSSP 或 Kerberos delegation 解決。
ansible.windows collection
核心 Windows collection。提供 ~50 個 win_* 模組（win_ping / win_copy / win_user / win_service / win_regedit / win_updates 等）。
community.windows collection
進階 Windows 模組。AD / IIS / DSC / scheduled task / DNS 等 ~80 個。
chocolatey.chocolatey collection
Windows 套件管理 Chocolatey 的 Ansible collection。win_chocolatey 模組。
win_ping 模組
Windows 版 ping 模組。對 Windows host 必須用此而非 ansible.builtin.ping（後者跑 Python）。
win_feature 模組
裝 / 移除 Windows server feature（IIS / DNS server / DHCP server 等）。對應 PowerShell Install-WindowsFeature。
win_powershell 模組
跑任意 PowerShell 腳本並回傳結構化結果。比 win_shell 強大 — 取代它的現代版本。
win_updates 模組
套用 Windows updates。可指定 category（CriticalUpdates / SecurityUpdates）、自動 reboot。
win_reboot 模組
重啟 Windows host 並等回到可連線狀態。常配 when: register_var.reboot_required 用。
win_domain_user / win_domain_group
community.windows 的 AD 物件管理模組。需在 domain-joined Windows host 上跑（不是 control node）。
win_domain_membership
把 host join 進 domain。需 domain admin credential。
ConfigureRemotingForAnsible.ps1
Ansible 官方提供的 PS 腳本，一行設定 Windows host 啟用 WinRM HTTPS / 自簽 cert / 5986 port。lab 環境最快路徑。
ansible_psrp_auth / ansible_winrm_transport
inventory 變數，指定認證方法。psrp 用 basic / negotiate / ntlm / kerberos / credssp / certificate；winrm 用同樣集合但鍵名不同。
