31.1EE 四階段 build pipeline

理解 build 內部流程是排查 build 失敗的關鍵。ansible-builder build 不是黑盒——是有結構的四階段。

31.1.1四階段架構

Figure 31.1 — Ansible Builder 四階段 build pipeline

31.1.2各階段職責

階段做什麼常見失敗
1 Base pull base_image + 裝 Python / pip / ansible-core / ansible-runner base image pull 失敗（registry 認證、網路）
2 Galaxy 下載 collection（從 Galaxy / Hub） collection 找不到、版本衝突、需 git 但 base 沒裝
3 Builder 下載 Python wheels + 系統 pkg（rpm / deb） 需 build tool（gcc / python3-devel）、缺 system header
4 Final 整合三 stage 結果產出最終 image 權限 / 路徑問題、entrypoint 衝突
ⓘ 為什麼分四階段

多階段（multi-stage）build 的標準好處：較大的 build dependencies（gcc / dev headers）只存在 builder stage，最終 final image 不含這些——image 體積小很多（典型減 30-50%）。Galaxy 與 Builder 階段平行跑（不互相依賴）也加快速度。

31.2v3 schema 完整解析

2026 主流是 schema v3。整體結構：

yaml · 完整功能 execution-environment.yml v3 
---
version: 3

# ① 基底 image — 所有 stage 起點
images:
  base_image:
    name: quay.io/ansible/awx-ee:latest
    signature_original_name: quay.io/ansible/awx-ee:latest

# ② build 階段預設參數（CLI --build-arg 可覆蓋）
build_arg_defaults:
  ANSIBLE_GALAXY_CLI_COLLECTION_OPTS: "--timeout 120"
  PKGMGR_PRESERVE_CACHE: "always"     # 保留 dnf/apt cache（迭代 build 較快）

# ③ 依賴聲明
dependencies:
  ansible_core:
    package_pip: ansible-core>=2.18,<2.19

  ansible_runner:
    package_pip: ansible-runner

  # 指定 Python 版本（base image 沒對的版本時）
  python_interpreter:
    package_system: python3.12
    python_path: /usr/bin/python3.12

  galaxy: requirements.yml
  python: requirements.txt
  system: bindep.txt

  # 排除（即使 collection 依賴有寫也不裝）
  exclude:
    python:
      - "~mysqlclient.*"          # tilde = regex match
    system:
      - subversion

# ④ 額外複製到 build context 的檔案 / 目錄
additional_build_files:
  - src: files/ansible.cfg
    dest: configs                  # 進 _build/configs/

  - src: files/custom-certs/
    dest: certs

# ⑤ 八個 build hook（prepend / append × 4 stage）
additional_build_steps:
  prepend_base:
    - RUN whoami

  append_galaxy:
    - COPY _build/configs/ansible.cfg /etc/ansible/ansible.cfg

  prepend_final:
    - COPY _build/certs/ /etc/pki/ca-trust/source/anchors/
    - RUN update-ca-trust

  append_final:
    - RUN chmod -R 755 /usr/share/ansible
    - LABEL maintainer="myorg-platform@example.com"
    - LABEL version="2026.05"

# ⑥ entrypoint 自訂（高級、罕用）
# options:
#   container_init:
#     entrypoint: '["/usr/bin/dumb-init", "--"]'
#     cmd: '["bash"]'

31.3八個 build hook — 何時用哪個

hook 是 EE 高級用法的核心。四階段 × prepend / append = 8 個 hook。

31.3.1八 hook 對照

Hook時機典型用途
prepend_base Base stage 開始前 設環境變數、driver pre-config
append_base Base 完成、Galaxy/Builder 前 裝 git（Galaxy 需要從 GitHub 拉時）
prepend_galaxy Galaxy stage 起始 放入 ansible.cfg（含 private Galaxy server）
append_galaxy Galaxy 完成 事後處理 collection 內容
prepend_builder Builder stage 起始 升級 pip、設 PyPI mirror
append_builder Builder 完成 清理 build cache
prepend_final Final stage 起始 放 CA 證書、信任企業 CA
append_final Final 完成 chmod、LABEL、final cleanup

31.3.2實用 hook 範例

yaml · 三個常見 hook 模式 
---
version: 3
images:
  base_image: { name: quay.io/ansible/awx-ee:latest }

additional_build_files:
  - src: files/corp-ca.crt
    dest: certs
  - src: files/ansible.cfg
    dest: configs
  - src: files/pip.conf
    dest: configs

additional_build_steps:

  # 模式 1: 信任企業 CA — 必須在 base 結束後、Galaxy 之前
  append_base:
    - COPY _build/certs/corp-ca.crt /etc/pki/ca-trust/source/anchors/
    - RUN update-ca-trust
    - RUN microdnf install -y git           # Galaxy 從 GitHub 拉需要

  # 模式 2: 用內部 PyPI mirror — Builder 階段前設好
  prepend_builder:
    - COPY _build/configs/pip.conf /etc/pip.conf
    - RUN pip install --upgrade pip

  # 模式 3: 最終 image 加 metadata
  append_final:
    - LABEL maintainer="platform@example.com"
    - LABEL org.opencontainers.image.source="https://github.com/example/ee"
    - LABEL org.opencontainers.image.version="2.1.0"
    - RUN ansible-galaxy collection list > /etc/ee-manifest.txt

31.4Private registry 整合

企業環境下 EE pipeline 全部來源都要私有：① 拉 base image 從私有 registry；② collection 從 private Hub；③ Python 從內部 PyPI mirror；④ push 完成的 EE 到 private registry。

31.4.1私有 base image — registry 認證

bash · 用 podman / docker login 後 build 
# 1) 先登入私有 registry
$ podman login registry.example.com -u "$USER" -p "$REG_PASS"

# 2) execution-environment.yml 用私有 base
#    images:
#      base_image:
#        name: registry.example.com/internal/ansible-base:rhel9

# 3) build — builder 用 podman 認證快取
$ ansible-builder build \
    --tag registry.example.com/myorg/myapp-ee:1.0 \
    --container-runtime podman

31.4.2private Galaxy / Automation Hub

ini · ansible.cfg — 指向 private Hub 
[galaxy]
server_list = private_hub, public_galaxy

[galaxy_server.private_hub]
url = https://hub.example.com/api/galaxy/content/published/
token = $AH_TOKEN

[galaxy_server.public_galaxy]
url = https://galaxy.ansible.com/
yaml · execution-environment.yml — 把 ansible.cfg 帶進 Galaxy stage 
---
version: 3

additional_build_files:
  - src: files/ansible.cfg
    dest: configs

additional_build_steps:
  prepend_galaxy:
    # 在 Galaxy stage 把 ansible.cfg 放好 — galaxy 會用
    - COPY _build/configs/ansible.cfg /etc/ansible/ansible.cfg
    # token 透過 build arg 傳入（不寫進 image）
    - ARG AH_TOKEN
    - ENV ANSIBLE_GALAXY_SERVER_PRIVATE_HUB_TOKEN=$AH_TOKEN
bash · build 時傳入 token（不存在 image 內） 
$ ansible-builder build \
    --tag myapp-ee:1.0 \
    --extra-build-cli-args "--build-arg AH_TOKEN=$AH_TOKEN"

31.4.3內部 PyPI mirror

text · files/pip.conf — 用內部 mirror 
[global]
index-url = https://pypi.example.com/simple/
trusted-host = pypi.example.com
timeout = 60

31.5Image 大小優化

預設 EE 通常 1.0-1.5 GB。生產環境（air-gapped / edge）需要瘦身。

31.5.1四個瘦身手段

①

用 minimal base

不用 awx-ee（功能完整、體積大），改用 ee-minimal-rhel9 或 fedora 的 minimal 變體。可省 200-400 MB。

②

排除不需 collection

只裝該專案用到的 collection（不要 community.general 整套）。每 collection 30-100 MB。

③

清 cache

append_final 加 RUN microdnf clean all + rm -rf /var/cache/*。20-100 MB。

④

用 dive 找肥肉

dive 工具看 image 每層佔多少。找出意外大的層。

31.5.2瘦身範例

yaml · 瘦身配置 
---
version: 3

images:
  base_image:
    # minimal 基底 — 比 awx-ee 小 ~300 MB
    name: registry.redhat.io/ansible-automation-platform-25/ee-minimal-rhel9:latest

build_arg_defaults:
  # cache 不保留 — 雖然 build 慢點 但 image 小
  PKGMGR_PRESERVE_CACHE: ""

dependencies:
  galaxy: requirements.yml          # 只列必要
  python: requirements.txt
  system: bindep.txt

additional_build_steps:
  append_final:
    # 清理 — 30+ MB
    - RUN microdnf clean all && rm -rf /var/cache/{dnf,yum} /tmp/*
    - RUN find /usr/share/ansible/collections -name "tests" -type d -exec rm -rf {} + 2>/dev/null || true
    - RUN find /usr/share/ansible/collections -name "*.md" -delete
bash · 用 dive 工具 inspect image 
# 安裝
$ brew install dive

# 互動 inspect — TUI 看每層大小、檔案分佈
$ dive my-ee:latest

# CI 用 — 檢查無用空間比例
$ CI=true dive my-ee:latest \
    --highestUserWastedPercent 0.10 \
    --highestWastedBytes 100M

31.6CI 自動 build pipeline

31.6.1GitHub Actions 完整 workflow

yaml · .github/workflows/ee-build.yml 
---
name: Build and Push EE

on:
  push:
    branches: [main]
    paths:
      - "execution-environment.yml"
      - "requirements.yml"
      - "requirements.txt"
      - "bindep.txt"
      - "files/**"
  workflow_dispatch:           # 也允許手動觸發

jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
      id-token: write            # 簽章用

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install ansible-builder
        run: pip install ansible-builder

      - name: Login to registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build EE
        run: |
          ansible-builder build \
            --tag ghcr.io/${{ github.repository }}/ee:${{ github.sha }} \
            --tag ghcr.io/${{ github.repository }}/ee:latest \
            --container-runtime docker \
            --verbosity 2
        env:
          AH_TOKEN: ${{ secrets.AUTOMATION_HUB_TOKEN }}

      - name: Scan image with Trivy
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ghcr.io/${{ github.repository }}/ee:${{ github.sha }}
          severity: CRITICAL,HIGH
          exit-code: "1"

      - name: Smoke test — 驗 collection 都進去了
        run: |
          docker run --rm \
            ghcr.io/${{ github.repository }}/ee:${{ github.sha }} \
            ansible-galaxy collection list

      - name: Push image
        run: |
          docker push ghcr.io/${{ github.repository }}/ee:${{ github.sha }}
          docker push ghcr.io/${{ github.repository }}/ee:latest

      - name: Sign image with Cosign
        uses: sigstore/cosign-installer@v3
      - run: cosign sign --yes ghcr.io/${{ github.repository }}/ee:${{ github.sha }}

31.7.2Cloud EE

yaml · cloud-ee — AWS / Azure / GCP 
---
version: 3
images:
  base_image:
    name: quay.io/ansible/awx-ee:latest

dependencies:
  galaxy:
    collections:
      - name: amazon.aws
      - name: community.aws
      - name: azure.azcollection

      - name: community.general

31.8Debug EE 內部

build 過了不代表 image 真能跑。進去看一下是必要技能。

31.8.1進 image 探查

bash · 五個必跑檢查命令 
# 1) 互動 shell 進去
$ podman run --rm -it my-ee:1.0 bash

# 2) 看 ansible 版本（確認是預期的 core）
$ podman run --rm my-ee:1.0 ansible --version

# 3) 看 collection 都進去了沒
$ podman run --rm my-ee:1.0 ansible-galaxy collection list

# 4) 看 Python pkg
$ podman run --rm my-ee:1.0 pip list

# 5) 看系統 pkg
$ podman run --rm my-ee:1.0 rpm -qa | grep -E "openssh|git|sshpass"

# 6) 看 image 大小、多少層
$ podman images my-ee
$ podman history my-ee:1.0

31.8.2常見問題排查

症狀原因解法
"Collection not found" build 階段 requirements.yml 名字錯 / 版本不存在 ansible-galaxy collection list 確認、用 ">=X" 而非鎖死版本
pip install fail（缺 build tool） 缺 gcc / python3-devel bindep.txt 加 gcc + python3-devel [platform:rpm]
Permission denied（rootless podman） subuid / subgid 沒設好 cat /etc/subuid /etc/subgid 確認、podman system migrate
Base image pull fail 沒 login / 網路斷 / image 名打錯 podman login + 確認 image 確實存在
EE run 在 AAP 上但 collection 找不到 AAP 配的 EE entry 指向錯版本 UI 內確認 EE entry 與實際 push 的 tag 一致
build 慢但每次都重 download cache 沒生效（layer 順序不對） requirements.yml 變動少的放前面、--no-cache 只在 CI 用

31.9業界最佳實踐

①

每個團隊一個 EE

不要全公司一個 mega-EE。Network team / Cloud team / DBA 各自的 EE，只裝自己用的 collection。瘦身又責任清楚。

②

EE = git repo

execution-environment.yml + requirements.* 都進 git，與 application code 同等對待。code review、tag、changelog 都要有。

③

image 版本明確（不要 latest）

tag 用 2.1.0 或 $GITHUB_SHA。AAP job template 鎖版本。要升版時改 template、不靠 latest。

④

CI 必跑 CVE scan

Trivy / Grype / Snyk。CRITICAL / HIGH 一律 fail build。安全合規必做。

⑤

image 簽章

cosign 簽章（sigstore）。AAP 2.5+ 支援 verify signed image。供應鏈安全標配。

⑥

private registry + private hub

內部 collection 走 Hub、image 走 private registry（Harbor / Quay / GHCR）。不依賴 public infrastructure。

⑦

smoke test 在 CI

build 完跑 ansible --version + collection list + 一個最簡 hello playbook。確認 image 是 functional 的。

⑧

image 含 LABEL metadata

append_final 加 LABEL org.opencontainers.image.source 等 OCI 標準 label。orchestration 工具能識別來源。

31.10本章重點回顧

01

四階段 build pipeline

Base（pull base + Python）→ Galaxy（拉 collection）+ Builder（拉 Python/system pkg）→ Final（整合）。

02

v3 schema 七大欄位

images / build_arg_defaults / dependencies / additional_build_files / additional_build_steps / options / version。

03

八個 build hook

prepend / append × 四階段。CA cert 用 prepend_final、git 安裝用 append_base、清理用 append_final。

04

Private registry 整合

podman login + ansible.cfg private hub + pip.conf mirror。token 用 build-arg 傳、不存進 image。

05

image 大小四手段

minimal base + 排除 collection + 清 cache + dive 找肥肉。1.5 GB 可瘦到 800 MB。

06

CI pipeline 五步驟

build → CVE scan → smoke test → push → cosign sign。GitHub Actions / GitLab CI 都類似。

07

三種 EE 類型範本

Network（cisco/arista/junos + netaddr/netmiko）、Cloud（amazon.aws/azure/google + boto3 等）、K8s（kubernetes.core + kubectl/helm binary）。

08

debug EE 五命令

ansible --version / collection list / pip list / rpm -qa / history。build 過了不代表能跑。

練習題

  1. 初學者：對既有 execution-environment.yml 跑 ansible-builder create 而非 build。看 context/ 目錄與 Containerfile 內容。理解四 stage 在 Dockerfile 中如何呈現。
  2. 初學者：用 podman history my-ee:1.0 看 build 出來的 image 有多少層、各層做什麼。
  3. 初學者：寫個最小 EE 用 minimal base、只裝 community.general、build 完 dive 看有沒有意外大檔。
  4. 開發者：用 append_final hook 在 image 加 5 個 LABEL（含 maintainer / version / source / vendor / build-date）。podman inspect 看到這些 metadata。
  5. 開發者：把 ansible.cfg 透過 additional_build_files + prepend_galaxy 帶進 image，配置內部 Galaxy server。pull 一個只在 private hub 的 collection 驗證。
  6. 開發者：寫 Network / Cloud / K8s 三個 EE 各一份。比較 build 出來大小（沒優化 vs minimal base + cache 清乾淨）。
  7. DevOps / SRE：寫完整 GitHub Actions workflow — build + Trivy CVE scan + smoke test + push + cosign sign。push tag 自動觸發。
  8. DevOps / SRE：對你公司目前的 venv 做盤點 — 哪些可以轉成 EE？寫一頁遷移計畫（時程 / 哪些團隊先 / pilot scope）。
  9. DevOps / SRE：模擬 air-gapped 環境 — 把 EE image + 所有 collection mirror 到 internal registry / Hub。在隔離環境中只用內部 source build 出新 image。

本章詞彙表

Build pipeline 四階段
ansible-builder 的內部 build 流程：Base（pull base + 裝 Python/ansible）→ Galaxy（拉 collection）+ Builder（拉 Python/系統 pkg）→ Final（整合產 image）。Galaxy 與 Builder 平行。
Multi-stage build
容器 build 模式 — 中間 stage 暫存 build deps（gcc / dev headers），final stage 只取產出。EE 預設就是多階段。
Schema v3
execution-environment.yml 的 schema 第三版（2026 主流）。比 v1/v2 多了 additional_build_files、八 hook、option 等 fine-grained 控制。
base_image
EE 的起點 image。常見：quay.io/ansible/awx-ee（社群）、registry.redhat.io/.../ee-minimal-rhel9（瘦身）、registry.fedoraproject.org/fedora:42（最 minimal）。
build_arg_defaults
execution-environment.yml 內的 build-time 預設參數。ANSIBLE_GALAXY_CLI_COLLECTION_OPTS / PKGMGR_PRESERVE_CACHE 等。CLI --build-arg 可覆蓋。
PKGMGR_PRESERVE_CACHE
build_arg_defaults 之一。設 "always" 保留 dnf/apt cache（迭代 build 較快），設 "" 不保留（image 較小）。trade-off。
dependencies.galaxy
EE 聲明檔中的 collection 依賴。指向 requirements.yml 或直接 inline 列。
dependencies.python
Python 套件依賴。指向 requirements.txt。
dependencies.system
系統套件依賴。指向 bindep.txt。[platform:rpm] / [platform:dpkg] 區分。
dependencies.exclude
排除清單。即使 collection 自己宣告需要某 Python / system pkg 也不裝。~regex 支援正規表達。
additional_build_files
把本機檔案複製到 build context 的 _build/。供 hook 階段用 COPY _build/... 引用。常見：ansible.cfg / 企業 CA 證書 / pip.conf。
八個 build hook
prepend / append × 4 階段（base / galaxy / builder / final）。在指定 stage 前後注入自訂 RUN / COPY / ENV / LABEL 指令。
prepend_base
Base stage 開始前。設環境變數、driver 預配置。
append_base
Base 完成、Galaxy/Builder 前。最常用——裝 git（為 Galaxy 從 GitHub 拉用）、加 CA。
append_final
Final stage 結尾。最常用——加 LABEL、清理、權限調整。
options.container_init
進階選項——自訂 entrypoint / cmd。dumb-init 處理 zombie process。罕用。
signature_original_name
v3 新欄位。指定 base_image 簽章驗證的原始名稱。供應鏈安全用。
private registry
企業內部容器 registry（Harbor / Quay / GHCR / Nexus）。EE image 推送到這裡，AAP / AWX 從這裡拉。
private Automation Hub
AAP 內部的私有 Galaxy。EE build 時透過 ansible.cfg 配置從這裡拉 collection。
internal PyPI mirror
企業內部 pip 源（pulp / devpi / Artifactory）。透過 pip.conf 配置。air-gapped 環境必備。
--build-arg
ansible-builder CLI 選項。透過 --extra-build-cli-args "--build-arg KEY=VAL" 傳入 build-time 變數（如 token）。不會存進 image。
dive
image 分析 TUI 工具。看每層大小、找出沒清乾淨的肥肉。CI 內可用 --highestUserWastedPercent 自動 fail。
cosign / sigstore
image 簽章工具。CI 中對 push 後的 image 簽。AAP 2.5+ 可驗 signed image。供應鏈安全標準。
Trivy / Grype / Snyk
容器 image CVE 掃描工具。CI 內必跑、HIGH/CRITICAL fail build。
OCI label（org.opencontainers.image.*）
OCI 標準 image metadata label。source / version / vendor / created。append_final 加。
Network EE / Cloud EE / K8s EE
三大典型專業 EE 類型。Network 含 cisco/arista/junos collection；Cloud 含 amazon.aws/azure/google + boto3；K8s 含 kubernetes.core + kubectl/helm binary。
smoke test (EE)
CI 內 build 完跑的最小驗證——ansible --version、collection list、簡單 hello playbook。確認 image 可運作。
