第 18 章 — Connection Plugin

Ansible 對 managed node 做事的第一步是「連上去」——把模組檔案傳過去、執行命令、收 stdout 回來。負責這件事的就是 connection plugin。第 2 章你看到 SSH 是預設、第 4 章用過 connection: local、第 11 章用 community.docker.docker 操作容器——這些底下全是 connection plugin 在工作。本章帶你看清楚：模組執行時 Ansible 如何透過 connection plugin 與遠端對話（六步驟流程）、內建 11 種 plugin 速查（ssh / paramiko / local / docker / podman / kubectl / winrm / network_cli / httpapi / netconf / chroot）、ConnectionBase 的四個必須方法（_connect / exec_command / put_file / fetch_file）、寫一個自定 docker_exec connection plugin 的完整範例、以及 SSH 進階調優（pipelining / ControlMaster / ProxyJump）讓 100 host 部署從 30 分鐘壓到 3 分鐘。

18.1.1意義

Connection plugin 是 Ansible 與遠端的抽象層。Module 的 code 不關心「我是用 SSH 還是 docker exec 還是 REST API 連過去的」——它只負責「讀 args 印 JSON」（Ch14）。Connection plugin 負責怎麼把那個 module 送到那個遠端、怎麼跑、怎麼取回結果。

ⓘ 為什麼 Ansible 要分這層？

因為這個分層，同一個模組可以跑在 SSH 機器、Docker container、Kubernetes pod、Windows host、網路設備——只要切換 connection plugin。Module 開發者不必懂底層通訊細節；connection plugin 開發者不必懂業務邏輯。這是 Ansible 能跨環境的核心原因。

18.3什麼時候該寫自定 connection plugin？

內建 plugin 已涵蓋 95% 場景。寫自定的真正動機通常是：

🔌

商業設備 REST API

沒 SSH 但有 REST API 的網路設備、儲存陣列、防火牆。包成 connection plugin 後就能用 Ansible 既有模組。

🏢

內部管理平台

公司內部自建的 host 管理代理、container orchestrator。包成 connection plugin 比每個模組重寫一次乾淨。

🚀

特殊傳輸協定

VMware vCenter API、IPMI、自家 RPC 協定——任何「跟 host 對話的方式」都能包成 connection plugin。

🛠

SSH 上的特殊 wrapper

需要 jumpbox 多跳、特殊 auth flow、加密 audit log 等——內建 SSH 接不上時的客製化。

⚠ 寫前的檢查清單

① 有沒有現成 collection？逛 galaxy.ansible.com 找有沒有人寫過。② 能用 SSH 嗎？多數設備裝個 SSH agent 是更便宜的做法。③ 能用 uri 模組嗎？單純打 API 操作不需要寫 connection plugin。真的有「想統一用 Ansible 既有模組」的需求才寫。

18.4ConnectionBase 核心架構

所有 connection plugin 都繼承 ConnectionBase。它定義 4 個必須實作的方法 + 1 個 lifecycle hook：

18.4.1四大必備方法

方法職責必須回傳
_connect() 建立連線。Ansible 會呼叫一次再呼叫 exec_command 等。 self
exec_command(cmd, in_data, sudoable) 在遠端執行命令。最重要。 (rc, stdout, stderr) tuple
put_file(in_path, out_path) 上傳本地檔案到遠端。 無（成功 silent，失敗 raise）
fetch_file(in_path, out_path) 從遠端拉檔案到本地。 無
close() 結束連線、清理資源。 無

18.4.2骨架

python · connection plugin 骨架 
from __future__ import absolute_import, division, print_function
__metaclass__ = type

DOCUMENTATION = """
    name: my_connection
    short_description: My custom connection plugin
    description:
        - 自訂連線 plugin 範例
    options:
        host:
            description: Target host
            vars:
                - name: inventory_hostname
                - name: ansible_host
"""

from ansible.errors import AnsibleConnectionFailure
from ansible.plugins.connection import ConnectionBase
from ansible.utils.display import Display

display = Display()


class Connection(ConnectionBase):

    transport = 'my_connection'          # 必設 — plugin 識別名
    has_pipelining = False              # 是否支援 pipelining 加速

    def _connect(self):
        """建立連線。第一次被呼叫時跑這。"""
        if self._connected:
            return self
        display.vvv('establishing connection', host=self._play_context.remote_addr)
        # TODO: 實際建立連線（auth、socket、API session 等）
        self._connected = True
        return self

    def exec_command(self, cmd, in_data=None, sudoable=True):
        """遠端執行命令，回 (rc, stdout, stderr)。"""
        super().exec_command(cmd, in_data=in_data, sudoable=sudoable)
        # TODO: 實際執行 cmd
        return (0, b'', b'')

    def put_file(self, in_path, out_path):
        """把本地 in_path 上傳到遠端 out_path。"""
        super().put_file(in_path, out_path)
        # TODO: 實際上傳

    def fetch_file(self, in_path, out_path):
        """把遠端 in_path 下載到本地 out_path。"""
        super().fetch_file(in_path, out_path)
        # TODO: 實際下載

    def close(self):
        """結束連線，清理資源。"""
        super().close()
        # TODO: 釋放 socket、關閉 session 等
        self._connected = False

18.5實戰：docker_exec connection plugin

寫一個讓 Ansible 對 Docker container 執行任務的 connection plugin（不需 container 內裝 SSH）。內建的 community.docker.docker 已涵蓋此情境，本範例用簡化版示範核心結構。

18.5.1完整實作

python · connection_plugins/docker_exec.py 
from __future__ import absolute_import, division, print_function
__metaclass__ = type

DOCUMENTATION = """
    name: docker_exec
    short_description: Run tasks in Docker containers via docker exec / cp
    description:
        - 用 docker exec / docker cp 與容器互動
        - 容器內不需要 SSH server
    options:
        container:
            description: 容器名稱或 ID
            required: true
            vars:
                - name: ansible_docker_container
                - name: inventory_hostname
        docker_extra_args:
            description: 額外傳給 docker 命令的參數
            default: ""
            vars:
                - name: ansible_docker_extra_args
"""

import os
import shlex
import subprocess
import shutil

from ansible.errors import AnsibleConnectionFailure, AnsibleFileNotFound
from ansible.plugins.connection import ConnectionBase
from ansible.utils.display import Display

display = Display()


class Connection(ConnectionBase):
    """透過 docker exec/cp 與容器互動的 connection plugin。"""

    transport = 'docker_exec'
    has_pipelining = True     # 支援 pipelining 加速

    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self._docker = shutil.which('docker')
        if not self._docker:
            raise AnsibleConnectionFailure(
                'docker binary not found in PATH'
            )

    # --------- _connect ---------
    def _connect(self):
        if self._connected:
            return self

        container = self.get_option('container')
        display.vvv(f'docker_exec: connecting to {container}',
                    host=container)

        # 用 docker inspect 確認容器存在且運作中
        cmd = [self._docker, 'inspect', '--format', '{{.State.Running}}', container]
        result = subprocess.run(cmd, capture_output=True, text=True)

        if result.returncode != 0:
            raise AnsibleConnectionFailure(
                f'container "{container}" not found: {result.stderr.strip()}'
            )
        if result.stdout.strip() != 'true':
            raise AnsibleConnectionFailure(
                f'container "{container}" is not running'
            )

        self._connected = True
        return self

    # --------- exec_command ---------
    def exec_command(self, cmd, in_data=None, sudoable=True):
        super().exec_command(cmd, in_data=in_data, sudoable=sudoable)

        container = self.get_option('container')
        extra = shlex.split(self.get_option('docker_extra_args') or '')

        # docker exec [-i] container sh -c ''
        docker_cmd = [self._docker, 'exec'] + extra
        if in_data:
            docker_cmd.append('-i')        # 接收 stdin（pipelining 用）
        docker_cmd += [container, 'sh', '-c', cmd]

        display.vvv(f'docker_exec EXEC: {cmd}', host=container)

        proc = subprocess.Popen(
            docker_cmd,
            stdin=subprocess.PIPE if in_data else None,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
        )
        stdout, stderr = proc.communicate(input=in_data)
        return (proc.returncode, stdout, stderr)

    # --------- put_file ---------
    def put_file(self, in_path, out_path):
        super().put_file(in_path, out_path)

        if not os.path.exists(in_path):
            raise AnsibleFileNotFound(f'file not found: {in_path}')

        container = self.get_option('container')
        display.vvv(f'docker_exec PUT {in_path} -> {out_path}', host=container)

        # docker cp local_path container:remote_path
        cmd = [self._docker, 'cp', in_path, f'{container}:{out_path}']
        result = subprocess.run(cmd, capture_output=True, text=True)
        if result.returncode != 0:
            raise AnsibleConnectionFailure(
                f'docker cp failed: {result.stderr.strip()}'
            )

    # --------- fetch_file ---------
    def fetch_file(self, in_path, out_path):
        super().fetch_file(in_path, out_path)

        container = self.get_option('container')
        display.vvv(f'docker_exec FETCH {in_path} -> {out_path}', host=container)

        # docker cp container:remote_path local_path
        cmd = [self._docker, 'cp', f'{container}:{in_path}', out_path]
        result = subprocess.run(cmd, capture_output=True, text=True)
        if result.returncode != 0:
            raise AnsibleConnectionFailure(
                f'docker cp failed: {result.stderr.strip()}'
            )

    # --------- close ---------
    def close(self):
        super().close()
        self._connected = False

18.6Pipelining — 加速關鍵

預設情況下執行一個 task 需要兩次傳輸：先 put_file 把模組傳上去，再 exec_command 執行。Pipelining 把這合併——透過 stdin 把模組 code 直接灌進 exec 的 sh，省掉 put_file 那次。

18.6.1效能差異

Figure 18.2 — Pipelining 把兩次 SSH 合併為一次

18.6.2啟用 pipelining

ini · ansible.cfg — SSH pipelining 
[ssh_connection]
pipelining = true            # 預設 false — 強烈建議開
ssh_args = -o ControlMaster=auto -o ControlPersist=60s
retries = 3
⚠ Pipelining 的陷阱

啟用 pipelining 需要 sudoers 沒有 requiretty（多數現代 Linux 預設就沒有，但 RHEL 6 / 老 Ubuntu 可能有）。如果你看到神秘的 sorry, you must have a tty to run sudo 錯誤——是 pipelining + requiretty 衝突。解法：在 sudoers 加 Defaults !requiretty，或關掉 pipelining。

18.6.3自寫 plugin 支援 pipelining

python · pipelining 實作要點 
class Connection(ConnectionBase):
    has_pipelining = True           # ① 宣告支援

    def exec_command(self, cmd, in_data=None, sudoable=True):
        # ② in_data 不為 None 表示 Ansible 用 pipelining 把模組 code 透過 stdin 給你
        if in_data:
            # 你的職責 — 把 in_data 灌進遠端 sh 的 stdin
            proc = subprocess.Popen(remote_sh_cmd, stdin=subprocess.PIPE, ...)
            stdout, stderr = proc.communicate(input=in_data)
        else:
            # 沒 pipelining 時的一般執行（put_file 已先傳檔）
            stdout, stderr = subprocess.run(...)

        return (proc.returncode, stdout, stderr)

18.7SSH 進階調優

SSH 是 95% 部署的瓶頸。三招把 SSH connection 從拖油瓶變高效：

18.7.1三大加速技巧

①

Pipelining

合併 put_file + exec_command。一個 task 從 2 次 SSH 變 1 次。

②

ControlMaster / ControlPersist

OpenSSH 連線多工：第一次連完保持 socket，後續 task 重用。100 task 從 100 次 TCP handshake 變 1 次。

③

forks 加大

預設 5 並行——對 100 host 部署太少。改 50 / 100 視 control node 規模。

18.7.2業界推薦的 ansible.cfg

ini · 生產級 ansible.cfg 
[defaults]
forks = 50                        # 並行 host 數，預設 5 太小
host_key_checking = false         # CI 場景需要；正式環境用 known_hosts
gathering = smart                # fact 用 cache
fact_caching = jsonfile
fact_caching_connection = /tmp/ansible_facts
fact_caching_timeout = 3600

[ssh_connection]
pipelining = true               # 加速 ① — 合併 put + exec

ssh_args = -C -o ControlMaster=auto -o ControlPersist=60s -o PreferredAuthentications=publickey
# -C: 啟用壓縮（高 latency 環境有用）
# ControlMaster=auto + ControlPersist=60s: 加速 ② — 連線多工
# PreferredAuthentications=publickey: 跳過 password 嘗試節省 auth 時間

retries = 3                       # 連線失敗重試
control_path = /tmp/ansible-ssh-%h-%p-%r
timeout = 30

18.9Connection plugin 開發 Checklist

✓

transport 屬性必設

class 內 transport = 'my_name' 是 plugin 識別。配檔名 my_name.py。

✓

四個方法都呼 super

_connect / exec_command / put_file / fetch_file / close 開頭都先 super().method(...)。base class 做必要的 logging / 狀態。

✓

exec_command 回 bytes

tuple 第二三項是 stdout / stderr，必須是 bytes 不是 str。string 用 .encode()。

✓

失敗 raise AnsibleConnectionFailure

從 ansible.errors 引入。Ansible 把它呈現為 UNREACHABLE，host 標為 unreachable。

✓

display.vvv 不要 print

從 ansible.utils.display 拿 Display() 物件，用 .vvv() / .warning()。配合 -vvv 才看得到。

✓

has_pipelining 仔細評估

支援的話加速顯著但實作複雜。protocol 不允許灌 stdin（如純 REST）就設 False。

✓

用 vars: 而非寫死 attribute

DOCUMENTATION options 加 vars: list 讓使用者能在 inventory 設 ansible_xxx 變數。

✓

實作 close 釋放資源

關 socket、登出 API、清理暫存。Ansible 結束 host 處理時呼一次。

除錯用 -vvvv

看 SSH 詳細命令、socket 狀態。從 log 抓出 SSH 命令直接重跑是最快的問題定位法。

練習題

  1. 初學者：用 ansible-doc -t connection -l 列出所有可用 connection plugin，挑 3 個沒看過的閱讀其 DOCUMENTATION（如 chroot、buildah、vmware_tools）。
  2. 初學者：對 localhost 與本機 docker container 各跑一個 playbook（一個用 connection: local、一個用 community.docker.docker），觀察兩者 PLAY RECAP 差異。
  3. 初學者：故意把 inventory 中的 ansible_host 設成不存在的 IP，跑 playbook 用 -vvvv 看完整 SSH 嘗試與失敗原因。
  4. 開發者：實作本章 18.5 的 docker_exec plugin。建一個測試容器，跑 playbook 確認能 command + copy 進去。
  5. 開發者：擴展 docker_exec plugin 支援 ansible_docker_user 選項——用 docker exec 的 -u 旗標切換容器內使用者。
  6. 開發者：寫一個簡化版的 chroot_exec plugin。_connect 確認 chroot 目錄存在，exec_command 用 chroot <path> sh -c '<cmd>'。
  7. DevOps / SRE：對你既有的 ansible.cfg 加上 18.7.2 的調優設定。對某個 100 host 部署量化測試前後耗時差異。
  8. DevOps / SRE：模擬 jumpbox 環境（用 docker 起兩個 container，一個當 bastion 一個當內網），用 ProxyJump 設定讓 Ansible 透過 bastion 對內網 host 部署。
  9. DevOps / SRE：研究你公司是否有「沒 SSH 但需要 Ansible 自動化」的設備或平台（內部 PaaS、商業設備、雲端 console API）。設計（不必實作）一個自定 connection plugin 的 spec：列出 4 個 method 各做什麼、要哪些 inventory 變數、有什麼 edge case。

本章詞彙表

Connection plugin
定義 Ansible 與 managed node 通訊方式的 plugin。控制連線建立、檔案傳輸、命令執行。
ConnectionBase
所有 connection plugin 必繼承的 base class。從 ansible.plugins.connection 引入。
transport class attribute
connection plugin 的識別名。配 ansible_connection: my_name 使用。
_connect
connection plugin 必實作方法。建立連線、auth。回 self。
exec_command(cmd, in_data, sudoable)
在遠端執行命令。最重要的方法。回 (rc, stdout_bytes, stderr_bytes)。
put_file(in_path, out_path)
本地 → 遠端檔案上傳。SSH 用 sftp / scp，docker 用 docker cp。
fetch_file(in_path, out_path)
遠端 → 本地檔案下載。
close
結束連線、釋放資源。Ansible 結束 host 處理時呼叫。
has_pipelining
connection plugin 的 class 屬性。True 表示支援把模組 code 透過 stdin 灌進遠端 sh，省掉 put_file。
Pipelining
SSH connection 加速技巧，合併 put_file + exec_command 為一次傳輸。需 sudoers 沒 requiretty。
ControlMaster / ControlPersist
OpenSSH 連線多工。第一次連完保持 socket，後續 task 重用。-o ControlMaster=auto -o ControlPersist=60s。
ProxyJump
SSH 多跳。透過 bastion 連內網 host，-o ProxyJump=user@bastion 或 inventory 的 ansible_ssh_common_args。
ssh plugin
預設 connection plugin。基於 OpenSSH binary。
paramiko_ssh plugin
基於 Python paramiko library 的 SSH。OpenSSH 不可用時備用。
local plugin
在 control node 自己執行（不連線）。connection: local 用於 localhost task。
winrm plugin
Windows 連線方式。需 control node 裝 pywinrm。
community.docker.docker plugin
對 Docker container 直接執行 task，不需容器內裝 SSH。
kubernetes.core.kubectl plugin
透過 kubectl exec 對 K8s pod 執行 task。
network_cli / httpapi / netconf plugins
網路設備的三大連線方式。SSH+CLI / REST API / NETCONF XML。ansible.netcommon collection 提供。
AnsibleConnectionFailure
connection plugin 連線失敗時 raise 的 exception。Host 會標為 unreachable。
display.vvv
從 ansible.utils.display.Display() 取得物件的 verbose 訊息方法。配 -vvv 看到。
ansible_connection
inventory host 變數，指定該 host 用哪個 connection plugin。
connection: 關鍵字
play / task 層級指定 connection plugin 的 keyword。
