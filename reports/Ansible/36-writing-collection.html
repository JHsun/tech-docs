第 36 章 — 寫自己的 Ansible Collection

第 35 章教你怎麼貢獻別人的 collection；本章教你建立自己的。場景：公司內部有獨家 API / SaaS / 設備需要管理 → 寫一個 internal collection。場景：你想開源造福社群 → namespace + Galaxy。十個主題：① 何時該寫 collection——不是每個 playbook 都需要；② scaffold 起步——ansible-galaxy collection init 與 ansible-creator；③ 完整目錄結構——galaxy.yml / plugins / roles / docs / tests / meta；④ 寫第一個 module——argument_spec、check mode、fail_json / exit_json；⑤ module_utils 共用程式碼；⑥ Filter 與 Lookup plugin；⑦ 把 role 放進 collection；⑧ module DOCUMENTATION + EXAMPLES + RETURN；⑨ build 與 publish——Galaxy / Automation Hub / private hub；⑩ 版本管理 SemVer + deprecation 流程。讀完這章你能用 2 小時 scaffold 出 collection、用 1 天寫好第一個 production-ready module、用 CI 自動 release 到 Galaxy。

本章是貢獻 + 復用兩用 — 內部工具集中化、社群貢獻起步
初學者選讀（36.1–36.3 概念與目錄結構） 開發者必讀（全章 — 寫 module / plugin 的標準做法） DevOps / SRE 必讀（特別 36.7 把現有 role 整理進 collection）

36.1何時該寫 collection

36.1.1四個訊號

🔄

同樣的 role 在多個專案 copy paste

每次新專案複製 nginx role / monitoring role 等 — 改 bug 要改多處。Collection 把它變 single source of truth。

🏢

公司有獨家系統

內部 ticketing / 自家 API / 客製設備 — 沒現成 module。寫 internal collection 給整公司用。

🌐

想開源

解決某 niche 問題、社群也會用 → Galaxy 發布。簡單問題就一個 module、複雜場景做整 collection。

📦

跨團隊復用 plugin / filter

多 team 都用同個 custom filter / lookup → collection 集中管理。每 team 不必重發明輪子。

36.1.2不該寫 collection 的訊號

⚠ 不該寫的反面訊號

① 單一 playbook 專用 — 普通 playbook 加 role 就夠；② 沒 maintainer 承諾 — collection 是 long-term commitment、要持續發版回應 issue。沒有 owner 一年後就成廢墟；③ 純 task 集合（沒 module / plugin / filter）— 用 role 比 collection 簡單。collection 真正價值在能裝 plugin。

module 是 collection 的核心。本節寫一個完整可動的 server_config module。

36.5.2完整 module 範例

python · plugins/modules/server_config.py 
#!/usr/bin/python
# -*- coding: utf-8 -*-
# Copyright: (c) 2026, MyOrg
# GNU General Public License v3.0+ (see LICENSE)

from __future__ import annotations

DOCUMENTATION = r'''
---
module: server_config
short_description: 管理 MyApp server 配置
version_added: "1.0.0"
description:
  - 連線 MyApp server、查詢 / 設定 config 項目
  - 支援 check mode 與 idempotence
options:
  name:
    description: config 項目名稱
    required: true
    type: str
  value:
    description: config 項目值（state=present 必填）
    type: str
  state:
    description: 期望狀態
    choices: [present, absent]
    default: present
    type: str
  api_url:
    description: MyApp API endpoint
    required: true
    type: str
  api_token:
    description: API 認證 token
    required: true
    type: str
    no_log: true
author:
  - Your Name (@your-github-id)
'''

EXAMPLES = r'''
- name: 設定 max_connections
  myorg.infrastructure.server_config:
    name: max_connections
    value: "200"
    state: present
    api_url: https://api.myapp.example.com
    api_token: "{{ vault_myapp_token }}"

- name: 移除 deprecated 設定
  myorg.infrastructure.server_config:
    name: legacy_setting
    state: absent
    api_url: https://api.myapp.example.com
    api_token: "{{ vault_myapp_token }}"
'''

RETURN = r'''
changed:
  description: 是否有實際改動
  type: bool
  returned: always
config:
  description: 目前的 config 值
  type: dict
  returned: success
  sample:
    name: max_connections
    value: "200"
'''

from ansible.module_utils.basic import AnsibleModule
from ansible_collections.myorg.infrastructure.plugins.module_utils.myapi import MyApiClient


def main():
    # ① 定義參數規格
    argument_spec = dict(
        name=dict(type='str', required=True),
        value=dict(type='str'),
        state=dict(type='str', choices=['present', 'absent'], default='present'),
        api_url=dict(type='str', required=True),
        api_token=dict(type='str', required=True, no_log=True),
    )

    # ② 建 module — 必開 check_mode 才能 dry-run
    module = AnsibleModule(
        argument_spec=argument_spec,
        supports_check_mode=True,
        required_if=[
            ('state', 'present', ['value']),     # present 時 value 必填
        ],
    )

    name      = module.params['name']
    value     = module.params['value']
    state     = module.params['state']
    api_url   = module.params['api_url']
    api_token = module.params['api_token']

    client = MyApiClient(api_url, api_token)

    try:
        # ③ 查目前狀態
        current = client.get_config(name)

        # ④ 計算是否需要變更
        if state == 'present':
            if current and current['value'] == value:
                module.exit_json(changed=False, config=current)

            # check mode — 不真的做、回報「會 changed」
            if module.check_mode:
                module.exit_json(changed=True, config={'name': name, 'value': value})

            new = client.set_config(name, value)
            module.exit_json(changed=True, config=new)

        elif state == 'absent':
            if not current:
                module.exit_json(changed=False)
            if module.check_mode:
                module.exit_json(changed=True)
            client.delete_config(name)
            module.exit_json(changed=True)

    except Exception as e:
        # ⑤ 失敗 — 用 fail_json（不要 raise）
        module.fail_json(msg=f"API 呼叫失敗: {e}")


if __name__ == '__main__':
    main()

36.5.3module 三大寫作守則

🔁

idempotent — 先 query 再決定

查目前狀態 → 與期望比對 → 一致就 changed=False，不一致才動作。

🧪

支援 check_mode

supports_check_mode=True + check 時不真做、回報「會 changed」。

🔐

secret 標 no_log

token / password 等參數一律 no_log=True。否則 verbose / log 會洩漏。

36.6module_utils 共用程式碼

多個 module 共用的邏輯（API client / 參數正規化 / 工具函式）放 module_utils。

python · plugins/module_utils/myapi.py 
# -*- coding: utf-8 -*-
# Copyright: (c) 2026, MyOrg / GPL-3.0+

from __future__ import annotations

from ansible.module_utils.urls import open_url
import json


class MyApiClient:
    """MyApp API 共用 client。"""

    def __init__(self, base_url, token, timeout=30):
        self.base_url = base_url.rstrip('/')
        self.headers = {
            'Authorization': f'Bearer {token}',
            'Content-Type': 'application/json',
        }
        self.timeout = timeout

    def _request(self, method, path, data=None):
        url = f'{self.base_url}{path}'
        body = json.dumps(data) if data else None
        resp = open_url(
            url,
            method=method,
            headers=self.headers,
            data=body,
            timeout=self.timeout,
        )
        return json.loads(resp.read())

    def get_config(self, name):
        try:
            return self._request('GET', f'/configs/{name}')
        except Exception:
            return None

    def set_config(self, name, value):
        return self._request('PUT', f'/configs/{name}', {'value': value})

    def delete_config(self, name):
        self._request('DELETE', f'/configs/{name}')
ⓘ module_utils 的 import 路徑

從 module 內 import 必須用完整 FQCN 路徑：
from ansible_collections.myorg.infrastructure.plugins.module_utils.myapi import MyApiClient
不能用相對 import。open_url 是 ansible-core 內建的 HTTP client、不必另裝 requests。

36.7Filter 與 Lookup plugin

36.7.1Filter plugin — 處理變數

python · plugins/filter/infra_filters.py 
from __future__ import annotations


def to_nginx_upstream(servers, port=80):
    """把 server IP list 轉成 nginx upstream 格式。"""
    return "\n    ".join(f"server {ip}:{port};" for ip in servers)


def cidr_to_netmask(cidr):
    """把 CIDR 轉成 dotted netmask。例: 24 → 255.255.255.0"""
    if not (0 <= cidr <= 32):
        raise ValueError(f"無效 CIDR: {cidr}")
    mask = (0xffffffff << (32 - cidr)) & 0xffffffff
    return '.'.join([str((mask >> (8 * (3 - i))) & 0xff) for i in range(4)])


class FilterModule:
    """Custom filters for infrastructure management."""

    def filters(self):
        return {
            'to_nginx_upstream': to_nginx_upstream,
            'cidr_to_netmask': cidr_to_netmask,
        }
yaml · 在 playbook / template 內用 
# 用 FQCN 引用
- ansible.builtin.debug:
    msg: "{{ ['10.0.0.1', '10.0.0.2'] | myorg.infrastructure.to_nginx_upstream(port=8080) }}"

- ansible.builtin.debug:
    msg: "{{ 24 | myorg.infrastructure.cidr_to_netmask }}"     # 255.255.255.0

36.7.2Lookup plugin — 從外部取資料

python · plugins/lookup/vault_secret.py 
from __future__ import annotations

from ansible.errors import AnsibleError
from ansible.plugins.lookup import LookupBase

DOCUMENTATION = """
---
name: vault_secret
author: MyOrg
short_description: 從 internal vault 取 secret
options:
  _terms:
    description: secret path
    required: true
"""

EXAMPLES = """
- ansible.builtin.debug:
    msg: "{{ lookup('myorg.infrastructure.vault_secret', 'apps/myapp/db-pass') }}"
"""

RETURN = """
_raw:
  description: secret 值
  type: list
"""


class LookupModule(LookupBase):
    def run(self, terms, variables=None, **kwargs):
        results = []
        for term in terms:
            try:
                # 實際情境：呼叫 vault API
                value = self._fetch(term)
                results.append(value)
            except Exception as e:
                raise AnsibleError(f"取 secret {term} 失敗: {e}")
        return results

    def _fetch(self, path):
        # 此處示意 — 實際呼叫 hvac client 等
        return f"value-of-{path}"

36.9SemVer 與 deprecation

36.9.1Collection 版本規範

版本變動表示例子
MAJOR（X.0.0）Breaking change移除 module / 改參數預設值 / 改回傳結構
MINOR（X.Y.0）新功能但相容新 module / 新參數（向後相容）/ deprecation 警告
PATCH（X.Y.Z）Bug fix修 bug / 文件改善 / test 補強

36.9.2Deprecation 三步驟

Figure 36.3 — 健康的 deprecation 三步驟
⚠ 永遠別在 minor / patch 裡 break

使用者預期 v1.5 → v1.6 不會壞 playbook。你硬改 = 信任崩盤。即使是「明顯的 bug fix」也要評估有沒有人靠這 bug 行為運作。Breaking change 一律進下個 MAJOR、且 changelog 顯眼標註。

36.10業界最佳實踐

①

用 ansible-creator 不用 init

ansible-creator scaffold 含 CI / pre-commit / changelog 系統。手動補這些既麻煩又容易漏。

②

argument_spec 完整 schema

每個 option 都標 type / required / choices / default / elements（list 用）/ options（dict 用）。讓 Ansible 自動驗 input。

③

secret 一律 no_log

token / password / api_key — 漏一個就重大事故。no_log=True 是 default 應該開的。

④

module 必支援 check_mode

沒 check_mode 的 module 不能在 dry-run pipeline 用、體驗差。寫的時候就支援。

⑤

用 module_utils 抽共用 client

多個 module 連同個 API → 一個 module_utils class。不要每個 module 重寫 HTTP / auth 邏輯。

⑥

DOCUMENTATION + EXAMPLES + RETURN 三位一體

使用者 ansible-doc 看你的 module 全靠這三段。EXAMPLES 要能直接 copy paste 跑。

⑦

每 PR 一個 changelog fragment

changelog 是 release 的人類可讀紀錄。fragment 強迫每個變更都被記下。

⑧

SemVer 嚴格 + breaking 給 6 個月

v1.5 標 deprecation → v2.0 警告繼續 → v3.0 才移除。給使用者 6 個月以上遷移時間。

36.11本章重點回顧

01

四個訊號該寫 collection

多專案 copy paste / 公司獨家系統 / 開源造福 / 跨團隊共用 plugin。

02

scaffold 兩種

內建 ansible-galaxy collection init 最低門檻；ansible-creator 完整含 CI / pre-commit。

03

標準目錄結構

galaxy.yml + plugins/{modules,module_utils,filter,lookup,...} + roles + docs + tests + changelogs + meta/runtime.yml。

04

module 五大要素

DOCUMENTATION / EXAMPLES / RETURN / argument_spec / main 函式。AnsibleModule 是核心 class。

05

module 三守則

idempotent（先 query 再決定）/ supports_check_mode / secret no_log。

06

module_utils 共用

多 module 共用 client / 工具 → module_utils。FQCN import 路徑：ansible_collections.<ns>.<name>.plugins.module_utils.X。

07

filter / lookup plugin

filter = 處理變數（cidr 轉 netmask）；lookup = 從外部取（vault secret / DB query）。FQCN 引用。

08

build + publish + SemVer

ansible-galaxy collection build → tarball → publish 到 Galaxy / Hub。SemVer 嚴格、deprecation 三步驟、break 給 6 個月。

練習題

  1. 初學者：用 ansible-galaxy collection init local.test scaffold 一個 collection。瀏覽生成的 7 個目錄、瞭解每個用途。
  2. 初學者：對 collection 加一個簡單 hello_world role（task 只 debug 一句話）。ansible-galaxy collection install 到本機後在 playbook 用 local.test.hello_world 引用、確認跑得起來。
  3. 初學者：寫 galaxy.yml — 填齊 namespace / name / version / description / tags / repository / license / dependencies。ansible-galaxy collection build 看 tar 內容。
  4. 開發者：寫第一個 module — 對某 mock REST API（如 jsonplaceholder）查使用者並 register。完整 5 要素 + check_mode + idempotent。
  5. 開發者：對上題加 module_utils — 把 HTTP client 抽出去。寫第二個 module 用同個 client。確認共用邏輯運作。
  6. 開發者：寫一個 filter plugin（如把 IP list 排序、生 nginx upstream config block）+ 一個 lookup plugin（從 etcd / vault mock 取值）。playbook 用 FQCN 引用驗證。
  7. DevOps / SRE：把公司現有 1-2 個 internal role 整理成 collection。寫好文件、加 CI、發布到內部 Hub。寫一頁遷移指引給其他 team。
  8. DevOps / SRE：對某 collection 設計第一個 deprecation case — 把 module 某個參數標 deprecated、寫 changelog fragment、minor release。一週後看 user feedback。
  9. DevOps / SRE：寫 GitHub Actions workflow — push tag 自動 build + sanity test + publish 到 internal Hub。push v0.1.0 觸發 release、看 Hub 有沒有出現新版。

本章詞彙表

Collection
Ansible 的內容打包格式。可含 modules / plugins / roles / playbooks / docs。透過 Galaxy / Hub 分發。namespace.name 命名。
Namespace
collection 名的前半。一個 namespace 下可有多 collection（如 community.general / community.postgresql）。ansible.* 為 Red Hat 保留。
local.* namespace
Galaxy 永不會占用、保留給本機練習 / 開發。沒上 registry 風險可隨意取名。
ansible-galaxy collection init
內建 scaffold 命令。產出最低結構（galaxy.yml + meta + plugins / roles 空殼 + README）。
ansible-creator
新一代 scaffold 工具（在 ansible-dev-tools 包）。比 init 完整 — 含 CI / pre-commit / changelogs / devcontainer。2026 推薦。
ansible-dev-tools
Ansible 官方 dev 工具集合 pip 套件。一裝 ansible-creator / ansible-lint / molecule / navigator 等都有。
galaxy.yml
collection 中繼資料。namespace / name / version / authors / license / dependencies / build_ignore 等。Galaxy 與 Hub 都讀這個。
meta/runtime.yml
runtime metadata。requires_ansible（最低 ansible-core 版本）+ plugin_routing（重新命名 / 廢棄）。
plugin_routing
meta/runtime.yml 內定義 plugin 的 redirect / deprecation / tombstone。改 module 名時舊名 redirect 到新名保證向後相容。
SPDX license identifier
license 的標準字串。GPL-3.0-or-later / MIT / Apache-2.0 等。galaxy.yml 用此。
build_ignore
galaxy.yml 內列出 build 時要排除的檔案 / 目錄。.git / tests/output / __pycache__ 等別人裝不需要的東西。
plugins/modules/
collection 的 custom modules 放這。每個 .py 一個 module。檔名 = module 名（不含 namespace）。
plugins/module_utils/
module 共用程式碼。HTTP client / 共用 helper。從 module 內以 FQCN 路徑 import：ansible_collections.<ns>.<name>.plugins.module_utils.X。
plugins/filter/
Jinja2 custom filter plugin。FilterModule class 的 filters() 方法回傳 dict 對應 filter name → 函式。
plugins/lookup/
Lookup plugin。從外部資料源取值（vault / DB / API）。LookupModule 繼承 LookupBase 實作 run()。
plugins/inventory/
Dynamic inventory plugin。從 cloud / CMDB / API 動態產 inventory。
plugins/callback/
Callback plugin — 改變 stdout 顯示 / 把結果送外部 system / log。
plugins/connection/
Connection plugin — 自訂連線方式（如不用 SSH 而用 HTTP / API / WinRM）。
plugins/action/
Action plugin — 在 controller 上跑、可改變 module 執行流程。進階用法。
roles/ in collection
collection 內的 roles。標準 role 結構（tasks / defaults / handlers 等）。引用：namespace.collection.role_name。
playbooks/ in collection
collection 內可分發的 playbooks。使用者用 ansible-playbook namespace.collection.playbook_name 直接跑。
changelogs/fragments/
每 PR 加一個 fragment yaml 描述變更。release 時用 antsibull-changelog 工具自動 compile 成 CHANGELOG.rst。
AnsibleModule class
module 的核心 class（ansible.module_utils.basic）。處理參數驗證、check mode、log、exit / fail。每個 module 都建一個。
argument_spec
AnsibleModule 的參數規格。dict of dict — 每個 option 含 type / required / default / choices / no_log 等。
supports_check_mode
AnsibleModule 參數。True 表示此 module 支援 dry-run。check 時不真做、回報「會 changed」。
required_if
argument_spec 的條件式 required。如 state=present 時 value 必填。
no_log=True
option 標記 — Ansible 會把這 option 的值在 log / verbose 中遮掩。secret / token / password 一律標。
module.exit_json()
module 成功時呼叫。回傳 dict（含 changed / 自訂欄位）給 controller。
module.fail_json()
module 失敗時呼叫。msg= 為錯誤訊息。不要 raise exception——fail_json 才是正確 idiom。
DOCUMENTATION block
module 內的 YAML 區塊。ansible-doc 與 docs.ansible.com 都讀這個。short_description / version_added / options 等是必要欄位。
EXAMPLES block
module 內示範 playbook 用法的 YAML 區塊。必須能直接 copy paste 跑。
RETURN block
module 回傳結構說明的 YAML 區塊。讓使用者知道 register 後能用什麼欄位。
open_url（ansible.module_utils.urls）
ansible-core 內建 HTTP client。寫 module 別 import requests（增依賴）、用 open_url 即可。
ansible-galaxy collection build
把 collection 打包成 tarball 命令。<namespace>-<name>-<version>.tar.gz 格式。Galaxy 上限 2 MB（壓縮後）。
ansible-galaxy collection publish
把 tarball 推上 Galaxy / Hub 命令。需 API token（--token 或 server_list config）。
SemVer (Semantic Versioning)
X.Y.Z 版本規範。MAJOR break / MINOR 新功能但相容 / PATCH bug fix。collection 嚴格遵守。
Deprecation 流程
v1.5（minor）標警告 → v2.0（major）仍可用持續警告 → v3.0（major）移除。給使用者足夠時間遷移。
Galaxy server_list / token
ansible.cfg 的 [galaxy] 配置。可定義多個 server（public Galaxy / private Hub）優先序、各自 token。
