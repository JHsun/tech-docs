附錄 B — Lab 環境搭建

「Ansible 不能用想的、要練。」本附錄給你五個 lab 方案——從輕量到重量，每個 30 分鐘內可上手 5-10 台 lab host：① Multipass（macOS / Linux 最快）；② Vagrant + VirtualBox（傳統選項）；③ Podman / Docker container 模擬 host（最輕）；④ Docker Compose lab stack（多服務 lab）；⑤ kind / minikube（K8s 練習）。每個方案附完整 install / Vagrantfile / Multipass commands / 配對 Ansible 連線、清理重建、跨平台注意。讀完這附錄你能從零到有完整 lab 用 1 小時——之後本書任何練習題都能跑。

Reference 用 — 5 個 lab 方案 + 跨平台 setup

B.1選 lab 方案的決策樹

Figure B.1 — Lab 方案選擇決策樹

B.1.1五方案對照

方案重量啟動時間真 VMsystemd適合
Multipass中（KVM / Hyper-V）30-60s是完整macOS / Linux 日常 lab
Vagrant + VirtualBox重（每台 1+ GB）1-3 min是完整x86 平台真實環境模擬
Podman / Docker container極輕2-5s否需 image 支援Ansible 操作練習（不練 OS）
Docker Compose輕10-30s否部分多服務協作 lab
kind / minikube中1-2 min在 docker 內n/aK8s 練習
ⓘ 不確定？預設選 Multipass

本書 80% 練習題用 Multipass 最舒服。原因：① 跨平台（macOS Intel + Apple Silicon + Linux + Windows-via-Hyper-V）；② 啟動快；③ 真 VM 完整 systemd；④ 命令簡單到爆；⑤ snapshot 功能讓你可以「弄爛了一鍵還原」。

B.2方案 1：Multipass（推薦預設）

B.2.1安裝

bash · Multipass 跨平台安裝 
# macOS（Intel + Apple Silicon 都行）
$ brew install --cask multipass

# Ubuntu / Debian
$ sudo snap install multipass

# Windows — 從官網下載 .exe（會用 Hyper-V）
#   https://multipass.run/install

# 確認
$ multipass version
$ multipass find                        # 看可用 image

B.2.2建 5 台 lab host（10 秒 spec）

bash · 啟 5 台 Ubuntu 24.04 
# 一行起 5 台
$ for i in 1 2 3 4 5; do
    multipass launch --name lab-host-$i --memory 1G --disk 5G 24.04
done

# 看狀態
$ multipass list
# Name              State    IPv4            Image
# lab-host-1        Running  10.180.0.101    Ubuntu 24.04 LTS
# lab-host-2        Running  10.180.0.102    Ubuntu 24.04 LTS
# ...

# SSH 進去確認
$ multipass shell lab-host-1
ubuntu@lab-host-1:~$ exit

B.2.3讓 Ansible 連線（核心步驟）

bash · 把 host 的 SSH key 注入 lab 
# 確認本機有 SSH key（沒就生）
$ [ ! -f ~/.ssh/id_ed25519 ] && ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519

# 把 public key 注入每台 lab
$ PUBKEY="$(cat ~/.ssh/id_ed25519.pub)"
$ for i in 1 2 3 4 5; do
    multipass exec lab-host-$i -- bash -c "echo '$PUBKEY' >> ~/.ssh/authorized_keys"
done

# 用 IP 直接 SSH 測試（不再透過 multipass shell）
$ multipass info lab-host-1 | grep IPv4
# IPv4: 10.180.0.101
$ ssh ubuntu@10.180.0.101 hostname

B.2.4產生 Ansible inventory

bash · 自動產生 inventory.yml 
$ mkdir -p ~/ansible-lab/inventory
$ cd ~/ansible-lab

$ cat > inventory/hosts.yml <<EOF
all:
  children:
    lab:
      hosts:
EOF

$ for i in 1 2 3 4 5; do
    IP=$(multipass info lab-host-$i | grep IPv4 | awk '{print $2}')
    echo "        lab-host-$i:" >> inventory/hosts.yml
    echo "          ansible_host: $IP" >> inventory/hosts.yml
done

$ cat >> inventory/hosts.yml <<EOF
      vars:
        ansible_user: ubuntu
        ansible_python_interpreter: /usr/bin/python3
EOF

# 測 ansible ping
$ ansible -i inventory/ all -m ping
# lab-host-1 | SUCCESS => { "ping": "pong" }
# lab-host-2 | SUCCESS => { "ping": "pong" }
# ...

B.2.5清理 / 重建 / snapshot

bash · Multipass 日常維運 
# 停止全部
$ multipass stop --all

# 啟動全部
$ multipass start --all

# Snapshot（macOS / Linux）— 保留乾淨狀態
$ multipass snapshot lab-host-1 --name clean
$ multipass restore lab-host-1.clean   # 還原

# 刪除單一
$ multipass delete lab-host-1
$ multipass purge

# 全砍重建
$ multipass delete --all && multipass purge

B.3方案 2：Vagrant + VirtualBox

⚠ Apple Silicon 注意

VirtualBox 在 Apple Silicon（M1/M2/M3/M4）支援仍有限。M 系 Mac 用 UTM 替代，或直接用 Multipass。本節範例假設 x86 Linux / macOS Intel / Windows。

B.3.1安裝

bash · 安裝 Vagrant + VirtualBox 
# macOS Intel
$ brew install --cask virtualbox vagrant

# Ubuntu
$ sudo apt install -y virtualbox vagrant

# Windows — 從官網下 .exe
#   https://www.virtualbox.org/wiki/Downloads
#   https://www.vagrantup.com/downloads

$ vagrant --version
$ vboxmanage --version

B.3.2多 host Vagrantfile

ruby · Vagrantfile — 5 台 lab 
# Vagrantfile
Vagrant.configure("2") do |config|
  # 每台 host 共用設定
  config.vm.box = "ubuntu/jammy64"

  config.vm.provider "virtualbox" do |vb|
    vb.memory = 1024
    vb.cpus = 1
  end

  # 5 台 host：lab-1 ~ lab-5
  (1..5).each do |i|
    config.vm.define "lab-#{i}" do |node|
      node.vm.hostname = "lab-#{i}"
      node.vm.network "private_network", ip: "192.168.56.#{10 + i}"
    end
  end

  # 自動把本機 SSH key 加到 lab（讓 ansible 直接連）
  config.vm.provision "shell", inline: <<-SHELL
    mkdir -p /home/vagrant/.ssh
    echo "#{File.read("#{Dir.home}/.ssh/id_ed25519.pub")}" >> /home/vagrant/.ssh/authorized_keys
    chmod 600 /home/vagrant/.ssh/authorized_keys
    chown -R vagrant:vagrant /home/vagrant/.ssh
  SHELL
end

B.3.3啟動 + Ansible 連線

bash · vagrant up 與配對 
$ cd ~/ansible-lab
$ vagrant up                 # 第一次比較久（拉 box）

# Inventory
$ cat > inventory/hosts.ini <<EOF
[lab]
lab-1 ansible_host=192.168.56.11
lab-2 ansible_host=192.168.56.12
lab-3 ansible_host=192.168.56.13
lab-4 ansible_host=192.168.56.14
lab-5 ansible_host=192.168.56.15

[lab:vars]
ansible_user=vagrant
ansible_python_interpreter=/usr/bin/python3
EOF

$ ansible -i inventory/hosts.ini lab -m ping

B.3.4清理

bash · Vagrant 日常維運 
$ vagrant status
$ vagrant halt                  # 停

$ vagrant reload lab-3          # 重啟單一

B.4方案 3：Podman / Docker container 模擬 host

用 container 當「lab host」是最輕量方案——啟動秒級、記憶體 50 MB / 台、Apple Silicon 原生跑。但不是真 VM、systemd 限制多。適合純練 Ansible 操作（package / file / template）。

B.4.1用 Geerlingguy 的 ansible-ready image

bash · 啟 5 個 container 當 lab host 
# Geerlingguy 維護一系列含 SSH / Python / systemd 的 image
# 完整列表：https://github.com/geerlingguy/docker-*-ansible

$ for i in 1 2 3 4 5; do
    podman run -d \
      --name lab-$i \
      --hostname lab-$i \
      --systemd=always \
      --cap-add=SYS_ADMIN \
      -p 222$i:22 \
      docker.io/geerlingguy/docker-ubuntu2404-ansible:latest \
      /lib/systemd/systemd
done

# 看狀態
$ podman ps
# lab-1 ... 0.0.0.0:2221->22/tcp
# lab-2 ... 0.0.0.0:2222->22/tcp
# ...

B.4.2注入 SSH key 與 Ansible 連線

bash · key 注入與 inventory 
# Geerlingguy image 預設含 root + ansible 用戶可 SSH
# 先看密碼或 key 設定（每個 image 不同、看 README）

# 推薦：把本機 pubkey 注入
$ for i in 1 2 3 4 5; do
    podman exec lab-$i bash -c "mkdir -p /root/.ssh; echo '$(cat ~/.ssh/id_ed25519.pub)' >> /root/.ssh/authorized_keys; chmod 700 /root/.ssh; chmod 600 /root/.ssh/authorized_keys"
done

# Inventory（用 localhost + 不同 port）
$ cat > inventory/hosts.ini <<EOF
[lab]
lab-1 ansible_host=127.0.0.1 ansible_port=2221
lab-2 ansible_host=127.0.0.1 ansible_port=2222
lab-3 ansible_host=127.0.0.1 ansible_port=2223
lab-4 ansible_host=127.0.0.1 ansible_port=2224
lab-5 ansible_host=127.0.0.1 ansible_port=2225

[lab:vars]
ansible_user=root
ansible_ssh_common_args='-o StrictHostKeyChecking=no'
EOF

$ ansible -i inventory/hosts.ini lab -m ping

B.5方案 4：Docker Compose 多服務 lab

練「對多服務 stack 部署」時用——一鍵起 web / db / cache / monitoring 完整環境。

yaml · docker-compose.lab.yml 
services:
  # Lab host：web tier × 2
  web-1: &web_template
    image: geerlingguy/docker-ubuntu2404-ansible:latest
    command: /lib/systemd/systemd
    privileged: true
    tmpfs:
      - /run
      - /run/lock
    volumes:
      - /sys/fs/cgroup:/sys/fs/cgroup:rw
    networks:
      labnet:
        ipv4_address: 172.30.0.11
    ports:
      - "2221:22"

  web-2:
    <<: *web_template
    networks:
      labnet:
        ipv4_address: 172.30.0.12
    ports:
      - "2222:22"

  # DB tier
  db-1:
    <<: *web_template
    networks:
      labnet:
        ipv4_address: 172.30.0.21
    ports:
      - "2231:22"

  # Load balancer 模擬
  lb-1:
    <<: *web_template
    networks:
      labnet:
        ipv4_address: 172.30.0.10
    ports:
      - "2210:22"

networks:
  labnet:
    driver: bridge
    ipam:
      config:
        - subnet: 172.30.0.0/24
bash · 啟動 + inventory 
$ docker compose -f docker-compose.lab.yml up -d
$ docker compose -f docker-compose.lab.yml ps

# Inventory — group 拆 web / db / lb
$ cat > inventory/hosts.yml <<EOF
all:
  children:
    web:
      hosts:
        web-1: { ansible_host: 127.0.0.1, ansible_port: 2221 }
        web-2: { ansible_host: 127.0.0.1, ansible_port: 2222 }
    db:
      hosts:
        db-1: { ansible_host: 127.0.0.1, ansible_port: 2231 }
    loadbalancer:
      hosts:
        lb-1: { ansible_host: 127.0.0.1, ansible_port: 2210 }
  vars:
    ansible_user: root
EOF

$ ansible -i inventory/ all -m ping

# 清理
$ docker compose -f docker-compose.lab.yml down -v

B.7跨平台注意事項

B.7.1三平台對照

平台推薦 lab 方案注意
macOS Apple Silicon（M1/M2/M3/M4） Multipass / kind / Podman VirtualBox 不可、用 UTM 替代或全用 Multipass
macOS Intel Multipass / Vagrant+VirtualBox / kind 無特殊限制
Linux Multipass / Podman / Vagrant+libvirt libvirt 比 VirtualBox 效能好（Linux 原生）
Windows WSL2 + Multipass / Vagrant+Hyper-V VirtualBox 與 Hyper-V 不能共存（裝一個）

B.8常見坑與排查

⚠

SSH 連不上 lab container

看 image 預設 user / password。Geerlingguy image 通常是 root + 沒密碼 → 直接用 key 接管。podman exec -it lab-1 bash 進去 inspect。

⚠

Multipass IP 變動

VM 重啟 IP 可能變。Inventory 不要寫死 IP — 用 multipass info 動態產生（B.2.4 那個 script）或加 alias 進 /etc/hosts。

⚠

Python interpreter warning

Ubuntu 22+ 預設 python3 但 ansible 偶爾還是會 warning。ansible_python_interpreter=/usr/bin/python3 明確設定可消警告。

⚠

VirtualBox + Apple Silicon

不可。改 UTM（macOS 原生 ARM hypervisor）或全部用 Multipass。Vagrant 也支援 UTM provider（vagrant_utm plugin）。

⚠

container lab 沒 systemd

純 alpine / Ubuntu base image 沒 systemd——Geerlingguy image 才有。要練 service module 一定用 systemd-ready image。

⚠

磁碟爆滿

Multipass / Vagrant 預設 disk 不大。記憶體不夠時 OOM。multipass purge + vagrant global-status --prune 定期清。

B.9推薦 lab 拓撲

不同章節需要不同規模 lab。本節給推薦設定。

章節範圍推薦 lab規模
Ch1-Ch9（基礎） Multipass × 3 3 GB RAM 總計、就夠 ad-hoc / playbook 練習
Ch10-Ch13（role / vault） Multipass × 5（含 control + 4 target） 5 GB RAM 總計
Ch20-22（雲端 / K8s / Windows） kind + 個別 cloud free-tier K8s 4 GB；雲端用各家免費 tier
Ch23-Ch29（DevOps SRE 實戰） Docker Compose × 8 服務（web×2 / db×2 / lb×1 / monitoring×3） 4 GB RAM 即可
Ch28（Molecule） Podman + Geerlingguy image × 多 OS 幾乎沒 overhead
Ch30-Ch32（AWX） kind + AWX Operator 8 GB RAM（AWX 比較吃資源）
Ch34（Mesh / EDA） Multipass × 6（1 control + 2 hop + 2 exec + 1 EDA） 8 GB RAM 總計
✓ 16 GB MacBook 一台跑全書 90% 練習

16 GB RAM 的開發機 + Multipass + kind 可以跑本書 90% 練習題。剩 10%（多 region mesh / 大型 AAP cluster）用 cloud free tier（AWS / Azure / GCP / Oracle Always Free）補足。完全自費學習可以做到。

B.10快速重建 — 一鍵 lab script

把 lab 變成「一鍵腳本」是最終境界。每天 ./lab-up.sh、結束 ./lab-down.sh。

bash · lab-up.sh — 完整一鍵起 5 host lab + inventory 
#!/bin/bash
# lab-up.sh — 一鍵起 5 台 Multipass + 自動產 inventory
set -euo pipefail

LAB_DIR="$HOME/ansible-lab"
COUNT=5
PUBKEY="$(cat ~/.ssh/id_ed25519.pub 2>/dev/null)"

if [ -z "$PUBKEY" ]; then
  echo "產生 SSH key..."
  ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
  PUBKEY="$(cat ~/.ssh/id_ed25519.pub)"
fi

echo "=> 啟 $COUNT 台 lab host..."
for i in $(seq 1 $COUNT); do
  if ! multipass list | grep -q "^lab-$i "; then
    multipass launch --name lab-$i --memory 1G --disk 5G 24.04
  fi
  multipass exec lab-$i -- bash -c "echo '$PUBKEY' >> ~/.ssh/authorized_keys"
done

echo "=> 產生 inventory..."
mkdir -p "$LAB_DIR/inventory"
{
  echo "all:"
  echo "  children:"
  echo "    lab:"
  echo "      hosts:"
  for i in $(seq 1 $COUNT); do
    IP=$(multipass info lab-$i | grep IPv4 | awk '{print $2}')
    echo "        lab-$i:"
    echo "          ansible_host: $IP"
  done
  echo "      vars:"
  echo "        ansible_user: ubuntu"
  echo "        ansible_python_interpreter: /usr/bin/python3"
} > "$LAB_DIR/inventory/hosts.yml"

echo "=> 測連線..."
cd "$LAB_DIR"
ansible -i inventory/ all -m ping

echo "=> Lab 就緒！cd $LAB_DIR 開始練習。"
bash · lab-down.sh — 結束清理 
#!/bin/bash
# lab-down.sh — 停 + 清理
set -euo pipefail

echo "=> 停所有 lab host..."
multipass stop --all 2>/dev/null || true

if [ "${1:-}" = "--purge" ]; then
  echo "=> 完全砍掉..."
  multipass delete --all
  multipass purge
fi

echo "=> 完成。"
