第二篇 — 基礎使用

第 9 章 — Templates 與 Jinja2

Templates 是把第 7、8 章學的變數、facts、條件、迴圈，以「檔案內容」形式輸出的機制——典型用途是產生 nginx.conf、application.yml、systemd unit 檔等。Ansible 採用 Jinja2 templating engine，所有變數展開、條件判斷、loop、filter 都在control node處理完，把渲染後的純文字檔送到 managed node。本章帶你從一個最小 .j2 檔開始，逐步學會 Jinja2 控制結構（if / for / set）、業界最常用的 30+ filters、Jinja2 tests、lookup plugins（從外部來源拉資料）、template 模組的關鍵參數，以及 macros / inheritance 等進階組織技巧。

本章覆蓋官方文件對應：Templating · Filters · Lookup Plugins · Tests
初學者必讀（9.1–9.4） 開發者必讀（全章） DevOps / SRE 必讀（特別 9.5 filters 與 9.7 lookup plugins）

9.1Template 模組與 Jinja2 概觀

第 5 章用 copy 把靜態檔案推到遠端，但設定檔通常需要因 host 而異——web01 的 nginx.conf 寫 IP 192.168.1.10、web02 寫 192.168.1.11，copy 沒辦法做到。template 模組就是動態版的 copy，讓你寫一份 .j2 範本檔，由 Ansible 在control node 上用變數 / facts 渲染完，再送到 managed node。

9.1.1第一個 template

jinja2 · templates/hello.conf.j2 
# 由 Ansible 自動產生 — 請勿手動編輯
# Host: {{ ansible_hostname }}
# Generated at: {{ ansible_date_time.iso8601 }}

app_name = {{ app_name }}
app_port = {{ app_port }}
log_level = {{ log_level | upper }}
primary_ip = {{ ansible_default_ipv4.address }}
yaml · 部署 template 
- name: 部署 hello.conf
  ansible.builtin.template:
    src: hello.conf.j2             # templates/ 目錄下，可省略前綴
    dest: /etc/myapp/hello.conf
    owner: root
    group: root
    mode: "0644"
    backup: true                   # 變更前自動備份
    validate: "/usr/sbin/nginx -t -c %s"  # 套用前驗證
  vars:
    app_name: myapp
    app_port: 8080
    log_level: info
  notify: restart myapp
  become: true

9.1.2copy vs template — 關鍵差異

特性copytemplate
變數展開否是（Jinja2 處理）
條件 / 迴圈否是
Idempotent是是（內容比對）
渲染位置—Control node
典型副檔名任意.j2 慣例
查找路徑files/ 目錄優先templates/ 目錄優先

9.1.3template 模組重要參數

參數說明
src / dest來源 .j2 檔（templates/ 內）與遠端目的路徑
owner / group / mode檔案屬主、群組、權限（mode 永遠加引號當字串）
backup: true變更前在 dest 旁產生備份檔（含時間戳）
validate套用前先執行驗證命令，%s 會被換成暫存的渲染結果
force: false只在 dest 不存在時部署，已存在則跳過
lstrip_blocks / trim_blocks控制空白處理（見 9.4）
variable_start_string / variable_end_string改 {{ }} 預設標記，避免與 Jinja2 衝突的場景
ⓘ validate 參數的價值

validate: "/usr/sbin/nginx -t -c %s" 會在 Ansible真正套用前用 nginx 自己的語法檢查器驗證渲染結果。失敗就不部署——這是「壞掉的 nginx.conf 把 production 打掛」的安全網。許多服務都有對應的 validate 命令：sshd -t -f %s、visudo -c -f %s、apachectl configtest 等。

9.2Jinja2 三大標記

所有 .j2 檔的內容只有三類「會被處理」的標記，其餘都是原樣輸出。

標記用途範例
{{ ... }}變數 / 表達式 — 把值印出{{ app_port }}
{% ... %}陳述式 — 控制結構（if / for / set / macro）{% if env == 'prod' %}
{# ... #}註解 — 渲染後消失（與 # 不同）{# 這行不會出現在輸出 #}
⚠ # 開頭的不是 Jinja2 註解

純 # 這是註解 在 Jinja2 眼中是普通文字，會原樣輸出（在 conf 檔中通常被視為 shell 註解，但 Ansible 不認識）。真正的 Jinja2 註解必須用 {# ... #}，這種註解在渲染後消失，看不到。

9.3控制結構：if / for / set

9.3.1if / elif / else

jinja2 · 條件式輸出 
{% if ansible_distribution == 'Ubuntu' %}
PackageManager=apt
{% elif ansible_os_family == 'RedHat' %}
PackageManager=dnf
{% else %}
PackageManager=unknown
{% endif %}

# 行內條件（三元運算）
DBUser={{ 'admin' if env == 'production' else 'developer' }}

# 多條件組合
{% if ssl_enabled and not maintenance_mode %}
listen 443 ssl;
{% endif %}

9.3.2for 迴圈

jinja2 · for 走訪 list / dict / 群組 
# 走訪 list
{% for user in allowed_users %}
AllowUser {{ user }}
{% endfor %}

# 走訪 dict
{% for key, value in tls_config.items() %}
{{ key }} = {{ value }}
{% endfor %}

# 走訪 inventory 群組（搭配 hostvars）
upstream backend {
{% for host in groups['webservers'] %}
    server {{ hostvars[host]['ansible_default_ipv4']['address'] }}:8080;
{% endfor %}
}

# 含條件的 for（只處理符合條件的 item）
{% for user in users if user.active %}
{{ user.name }}: {{ user.email }}
{% endfor %}

9.3.3loop 內建變數

Jinja2 在 for 迴圈內提供一個 loop 物件（不是 Ansible 的 loop directive），含實用的迴圈狀態：

屬性說明
loop.index當前序號（1-based：1, 2, 3...）
loop.index0當前序號（0-based：0, 1, 2...）
loop.first是否第一筆
loop.last是否最後一筆
loop.lengthlist 總長度
loop.previtem / loop.nextitem前 / 後一筆 item
jinja2 · loop 變數應用 
# 產生 JSON-like 結構（最後一筆不要逗號）
{
  "servers": [
    {% for srv in backend_servers %}
    {"host": "{{ srv.host }}", "port": {{ srv.port }}}{% if not loop.last %},{% endif %}
    {% endfor %}
  ]
}

# 含序號的清單
{% for svc in services %}
{{ loop.index }}. {{ svc.name }} on port {{ svc.port }}
{% endfor %}

9.3.4set — 在 template 內定義變數

jinja2 · set 範例 
{% set log_dir = '/var/log/' + app_name %}
{% set max_workers = (ansible_processor_vcpus * 2) %}

log_dir = {{ log_dir }}
access_log = {{ log_dir }}/access.log
error_log = {{ log_dir }}/error.log
workers = {{ max_workers }}

9.4空白處理：trim_blocks 與 lstrip_blocks

Jinja2 控制標記（{% %}）會留下換行與空白，渲染結果常常多出空行。這是新手最大困擾，但有解。

9.4.1問題示範

jinja2 · 預設行為（會多空行） 
# 原始 .j2:
{% for u in users %}
user: {{ u }}
{% endfor %}

# 預設渲染輸出（每個 user 之後多一個空行）：
     ← 來自 {% for %} 那行的換行
user: alice
     ← 來自 {% endfor %} 那行的換行
user: bob
     ← ...

9.4.2解法 1：用 dash 抑制

jinja2 · 用 - 移除空白 
{%- for u in users %}
user: {{ u }}
{%- endfor %}

# {%- 在開頭：移除「左邊」的空白（含前一行的換行）
# -%} 在結尾：移除「右邊」的空白（含當前行的換行）

9.4.3解法 2：在 template 模組設旗標

yaml · trim_blocks / lstrip_blocks 
- name: 部署整潔的設定檔
  ansible.builtin.template:
    src: app.conf.j2
    dest: /etc/myapp/app.conf
    trim_blocks: true      # 移除控制標記後的第一個換行（預設 true）
    lstrip_blocks: true    # 移除控制標記前的縮排空白（預設 false，建議開啟）
ⓘ 業界做法：兩個都開

大部分 .j2 寫起來都假設 lstrip_blocks: true, trim_blocks: true。建議在 ansible.cfg 全域設或在 role 統一啟用，比每個 template 用 dash 處理一致得多。

9.5Filters — 資料轉換的核心工具

Filters 用 | 串接，把輸入轉成新值。Jinja2 內建幾十個，Ansible 又加了幾百個專屬 filter。本節挑出實戰最常用的。

9.5.1字串處理

Filter用途範例
upper / lower大小寫{{ name | upper }}
capitalize / title首字 / 各詞首字大寫{{ env | title }}
replace字串替換{{ s | replace('-', '_') }}
regex_replace正則替換（Ansible 加的）{{ s | regex_replace('^v', '') }}
trim / strip去頭尾空白{{ x | trim }}
truncate截斷字串{{ msg | truncate(80) }}
quoteshell-safe 加引號{{ user_input | quote }}
b64encode / b64decodeBase64 編解碼{{ secret | b64encode }}
hash('sha256')計算 hash{{ s | hash('sha256') }}

9.5.2List / Dict 處理

Filter用途範例
length長度{{ users | length }}
join連接成字串{{ ips | join(',') }}
first / last取第一 / 最後{{ list | first }}
min / max最小 / 最大{{ ports | max }}
sort排序{{ names | sort }}
unique去重{{ tags | unique }}
flatten展平巢狀 list{{ nested | flatten }}
map(attribute='X')取 list 中每個 dict 的 X 屬性{{ users | map(attribute='name') | list }}
select / reject篩選 / 反篩{{ nums | select('>', 5) | list }}
selectattr / rejectattr依屬性篩 list of dict{{ users | selectattr('active') | list }}
dict2itemsdict → [{key,value}, ...]第 8 章已介紹
items2dict反向操作{{ list | items2dict }}
combine合併兩個 dict{{ a | combine(b, recursive=True) }}
zip兩個 list 配對{{ keys | zip(values) | list }}

9.5.3數字 / 轉型 / 格式化

Filter用途範例
int / float / string強制轉型{{ '42' | int + 1 }}
round四捨五入{{ 3.78 | round }}
abs絕對值{{ -5 | abs }}
human_readable檔案大小人讀{{ 1073741824 | human_readable }} → 1.0G
human_to_bytes反向{{ '1G' | human_to_bytes }}

9.5.4JSON / YAML / URL 編碼

Filter用途
to_json / from_json結構 ↔ JSON 字串
to_nice_jsonJSON 含縮排（人讀）
to_yaml / from_yaml結構 ↔ YAML
to_nice_yamlYAML 含縮排
urlencode / urldecodeURL 編碼
quoteshell quote 防注入

9.5.5預設值與安全處理

jinja2 · default 與 mandatory 
# default — 變數未定義或 None 時用預設值
log_level = {{ log_level | default('info') }}

# default(omit) — 在模組參數中「乾脆不傳」
- ansible.builtin.user:
    name: alice
    shell: {{ user_shell | default(omit) }}

# mandatory — 變數必須有值，否則 fail
db_password = {{ db_password | mandatory }}

# 巢狀資料的安全訪問（自動處理中間 undefined）
ip = {{ ansible_facts.networks.eth0.ipv4 | default('127.0.0.1') }}

9.5.6Filter 鏈式組合

jinja2 · 串接多個 filter 
# 取所有 enabled user 的 email，去重，排序，逗號連接
{{ users
   | selectattr('enabled')
   | map(attribute='email')
   | unique
   | sort
   | join(', ')
}}

# 取得 webservers 群組所有 IP，輸出 nginx upstream 格式
{{ groups['webservers']
   | map('extract', hostvars, ['ansible_default_ipv4', 'address'])
   | list
   | join(' ')
}}

9.6Tests — Jinja2 的判斷工具

跟 filter 類似但用法不同——tests 用 is 串接，回傳 boolean。第 8 章 when 條件中已用過幾個。

9.6.1常用 tests

Test用途範例
defined / undefined變數是否已定義{% if x is defined %}
none是否為 None{% if v is none %}
string / number / iterable型別判斷{% if x is iterable %}
match正則從頭匹配{% if hostname is match('^web.+') %}
search正則任意位置{% if v is search('error') %}
version('X', '>=')語意化版本比較{% if my_ver is version('2.0', '>=') %}
file / directory / exists路徑類測試{% if path is directory %}
succeeded / failed / changed / skippedregister 結果狀態{% if r is succeeded %}
in包含於{% if 'admin' in user.roles %}
subset / supersetlist 子集 / 超集{% if l1 is subset(l2) %}

9.7Lookup Plugins — 從外部來源拉資料

Filter 是「轉換已有的資料」，Lookup 是「取得新資料」——從檔案、環境變數、密碼管理工具、API、資料庫等。Lookup 在 control node 執行，結果注入 Jinja2 表達式。

9.7.1filter vs lookup 的關鍵差異

FilterLookup
本質純函式（無副作用）會與外部世界互動
來源已在 playbook 中的資料檔案 / API / 環境變數 / vault 等
語法{{ x | filter_name }}{{ lookup('plugin_name', args) }}
跑在哪Control node（Jinja2 渲染時）Control node（每次評估都跑）
典型例子upper / join / mapfile / env / password / url

9.7.2常用 lookup plugins

yaml · lookup 八個典型用法 
# 1) file — 讀本地檔案內容
- ansible.builtin.copy:
    content: "{{ lookup('file', './ssh_keys/alice.pub') }}"
    dest: /home/alice/.ssh/authorized_keys

# 2) env — 讀控制節點環境變數
- ansible.builtin.debug:
    msg: "deploying as {{ lookup('env', 'USER') }}"

# 3) password — 讀或產生密碼（首次自動建立）
- community.postgresql.postgresql_user:
    name: appuser
    password: "{{ lookup('password', 'credentials/appuser.txt length=24') }}"

# 4) pipe — 跑外部命令取輸出
- ansible.builtin.set_fact:
    git_sha: "{{ lookup('pipe', 'git rev-parse HEAD') }}"

# 5) url — HTTP GET 內容
- ansible.builtin.set_fact:
    latest_release: "{{ lookup('url', 'https://api.example.com/version', split_lines=false) }}"

# 6) template — 渲染 .j2 後當字串使用
- ansible.builtin.copy:
    content: "{{ lookup('template', 'app.conf.j2') }}"
    dest: /some/inline/use

# 7) fileglob — 列出符合 pattern 的檔案
- ansible.builtin.copy:
    src: "{{ item }}"
    dest: /etc/configs/
  loop: "{{ query('fileglob', 'configs/*.conf') }}"

# 8) vars — 動態取一個變數的值（變數名也是動態的）
- ansible.builtin.debug:
    msg: "{{ lookup('vars', 'app_' + env + '_port') }}"

9.7.3lookup vs query

ⓘ 用 query 而非 lookup 配 loop

當 lookup 結果是 list 而你要 loop 它，用 query()（等同 lookup(..., wantlist=True)）。lookup() 預設會把 list 轉成逗號字串，loop 時會誤把整串當一個 item：

yaml · query vs lookup 
# ✓ 正確 — query 確保 list
loop: "{{ query('fileglob', 'configs/*.conf') }}"

# ✗ 錯誤 — 會 loop 一個逗號字串
loop: "{{ lookup('fileglob', 'configs/*.conf') }}"

9.8進階：Macros 與 Template Inheritance

9.8.1Macros — 可重用的 template 片段

jinja2 · macro 範例 — nginx server block 
# 定義 macro
{% macro server_block(name, port, root) %}
server {
    server_name {{ name }};
    listen {{ port }};
    root {{ root }};
    index index.html;
}
{% endmacro %}

# 多次呼叫
{{ server_block('site-a.com', 80, '/var/www/a') }}
{{ server_block('site-b.com', 80, '/var/www/b') }}
{{ server_block('admin.com', 8080, '/var/www/admin') }}

9.8.2Template Inheritance — 共用骨架

jinja2 · base template (templates/base-config.j2) 
# 通用 header
# Generated by Ansible at {{ ansible_date_time.iso8601 }}
# Host: {{ ansible_hostname }}
# DO NOT EDIT MANUALLY

{% block globals %}
{% endblock %}

{% block services %}
{% endblock %}

# end of generated file
jinja2 · child template (templates/web-config.j2) 
{% extends 'base-config.j2' %}

{% block globals %}
worker_processes {{ nginx_workers | default('auto') }};
worker_connections {{ nginx_connections | default(1024) }};
{% endblock %}

{% block services %}
{% for site in sites %}
server {
    server_name {{ site.domain }};
    listen {{ site.port }};
}
{% endfor %}
{% endblock %}
ⓘ 何時值得用 inheritance

Inheritance 適合「多個 template 共用 header / footer / 通用區塊」的場景，例如標準化的「Generated by Ansible」開頭、版本說明、聯絡資訊等。一般小型 .j2 檔不需要 — 直接寫一份就好。

9.9實戰：完整 nginx 設定 template

jinja2 · templates/nginx-site.conf.j2 
# {{ ansible_managed }} ← 標準的「自動產生」標記
# Generated for {{ inventory_hostname }} at {{ ansible_date_time.iso8601 }}

{% if backend_servers | length > 0 %}
upstream {{ app_name }}_backend {
{%- for server in backend_servers %}
    server {{ server.ip }}:{{ server.port }}{% if server.weight is defined %} weight={{ server.weight }}{% endif %};
{%- endfor %}
}
{% endif %}

server {
    listen {{ nginx_port | default(80) }}{% if ssl_enabled %} ssl http2{% endif %};
    server_name {{ server_name }};

{% if ssl_enabled %}
    ssl_certificate {{ ssl_cert_path }};
    ssl_certificate_key {{ ssl_key_path }};
    ssl_protocols {{ ssl_protocols | default(['TLSv1.2', 'TLSv1.3']) | join(' ') }};
{% endif %}

    root {{ document_root }};
    index index.html index.htm;

{% for location in locations %}
    location {{ location.path }} {
{%- if location.proxy_pass is defined %}
        proxy_pass {{ location.proxy_pass }};
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
{%- elif location.try_files is defined %}
        try_files {{ location.try_files }};
{%- endif %}
    }
{% endfor %}

    access_log /var/log/nginx/{{ app_name }}.access.log;
    error_log /var/log/nginx/{{ app_name }}.error.log {{ log_level | default('warn') }};
}
yaml · 對應的 playbook 變數 
vars:
  app_name: myapp
  server_name: api.example.com
  document_root: /var/www/myapp
  ssl_enabled: true
  ssl_cert_path: /etc/ssl/certs/api.crt
  ssl_key_path: /etc/ssl/private/api.key
  backend_servers:
    - { ip: 10.0.0.10, port: 8080, weight: 3 }
    - { ip: 10.0.0.11, port: 8080 }
  locations:
    - { path: /api,    proxy_pass: "http://myapp_backend" }
    - { path: /static, try_files: "$uri =404" }
    - { path: /,       try_files: "$uri /index.html" }

9.10本章重點回顧

01

template 是動態 copy

copy 推靜態檔，template 渲染 .j2 後推。Idempotent — 內容不變不傳。慣例放 templates/ 目錄。

02

三大 Jinja2 標記

{{ }} 印變數、{% %} 控制結構（if/for/set）、{# #} 註解（不是 #）。

03

渲染在 control node

Jinja2 處理發生在 control node，渲染後的純文字才送到 managed node。filter / lookup 都在 control 端執行。

04

空白問題用 lstrip + trim 解

Template 模組設 lstrip_blocks: true, trim_blocks: true，或在標記用 -（{%-、-%}）抑制周圍空白。

05

filter 是純函式

用 | 串接，upper / join / map / selectattr / combine 是核心五件套。可鏈式組合。

06

tests 用 is

回傳 boolean，用於條件判斷：is defined / is succeeded / is version / is match。

07

lookup 取外部資料

file / env / password / pipe / url / fileglob / template。配 loop 時用 query() 而非 lookup()。

08

validate 是安全網

validate: "/usr/sbin/nginx -t -c %s"。套用前先驗證渲染結果，失敗就不部署。所有重要服務都該設。

練習題

  1. 初學者：寫一個最小 .j2 含 app_name 與 app_port 兩個變數，用 template 模組部署到 /tmp/hello.conf，驗證內容已替換。
  2. 初學者：在 .j2 中加入 if 判斷，依 env 變數印出不同的 log_level（production → warn / 其他 → info）。
  3. 初學者：在 .j2 中用 for 走訪 list allowed_users，每個 user 印一行 AllowUser X。
  4. 開發者：寫一個 nginx upstream template，用 groups['webservers'] 與 hostvars 自動列出群組所有成員的 IP。
  5. 開發者：用 filter 鏈處理一個 list of dict — 篩出 enabled，取 email 屬性，去重，排序，逗號連接。在 debug 模組中印出。
  6. 開發者：寫一個 .j2 含「最後一筆不加逗號」的 JSON-like 結構，用 loop.last 處理。
  7. DevOps / SRE：給你的 nginx template 加 validate: "/usr/sbin/nginx -t -c %s"，故意把 .j2 寫壞（如 listen 字串錯誤），確認 Ansible 不會把壞檔部署到 production。
  8. DevOps / SRE：用 lookup('file', '...') 把本地的 SSH public key 內容塞進遠端 authorized_keys；再用 lookup('pipe', 'git rev-parse HEAD') 把 commit 寫進部署 metadata 檔。
  9. DevOps / SRE：替既有的 nginx role 寫一個 base template + 多個 child template（site-a.j2 / site-b.j2）使用 {% extends %} + {% block %}。觀察可重用結構帶來的整潔度。

本章詞彙表

Jinja2
Python 的 template engine，Ansible 用它做變數展開、條件、迴圈等動態渲染。
template 模組
Ansible 模組，把 .j2 檔在 control node 渲染後推到 managed node。Idempotent，內容不變不傳。
.j2 副檔名
業界慣例，標記檔案是 Jinja2 template。nginx.conf.j2 渲染後變 nginx.conf。
{{ ... }}
變數 / 表達式輸出標記。把值印出。
{% ... %}
陳述式標記。控制結構（if / for / set / macro / block）。
{# ... #}
Jinja2 註解標記。渲染後消失，與 # 不同。
trim_blocks / lstrip_blocks
Template 模組參數，控制 Jinja2 控制標記前後的空白處理。建議兩者都開啟。
{%- 與 -%}
標記內加 dash 抑制相鄰的空白與換行。一次性的空白控制。
Filter
用 | 串接的純函式，轉換已有資料。upper / join / map 等。
Test
用 is 串接的判斷函式，回傳 boolean。is defined / is succeeded 等。
Lookup plugin
從外部來源（檔案、環境、API、密碼管理工具）取資料注入 playbook。file / env / password / pipe / url 等。
query()
lookup(..., wantlist=True) 的捷徑。配 loop 時必用，避免 list 被誤轉成逗號字串。
validate 參數
Template / copy 模組參數。套用前先用指定命令驗證渲染結果，失敗就不部署。%s 會被換成暫存檔路徑。
ansible_managed
內建變數，預設值類似「Ansible managed」。常放在檔案開頭警告「自動產生請勿手動編輯」。
Macro
Jinja2 中可重用的 template 片段，類似函式定義。{% macro X(args) %} ... {% endmacro %}。
Template inheritance
{% extends 'base.j2' %} + {% block %}，多個 child template 共用 base 結構，覆寫指定 block。
loop 變數
Jinja2 for 迴圈內建的物件，含 loop.index / loop.first / loop.last / loop.length 等。
