附錄 D — 遷移指南

很多人是從舊版 Ansible 跨來的——2.9 / Ansible 3 / Ansible 5 等等。這附錄專門講「從舊到新」要做什麼。十大主題：① 2.9 → 2.10 拆分歷史——為什麼一個 product 變兩個（ansible-core + 100+ collection）；② FQCN 從建議到強制；③ 五大破壞性類別——module 改名 / 移走 / 移除 / 預設值改 / API 改；④ import vs include 演進；⑤ 版本相容矩陣——ansible-core 2.x ↔ ansible package N.x 對照；⑥ 升級 6 步驟——標準作業流程；⑦ ansible-lint 自動偵測——大型 codebase 第一招；⑧ FQCN 對照表——builtin + 常見 community 完整查；⑨ 重新命名/搬移的 collection——七個常見坑；⑩ 完整遷移案例——一個 2.9 playbook 從頭到 2.18+ ready。讀完你能從容把公司舊 Ansible codebase 升上來、不是踩地雷漫步而是手裡有地圖。

Reference 用 — 從 2.9 / 3 / 5 等舊版升級到 2.18+ 完整指引

D.12.9 → 2.10 拆分歷史

理解現在的 Ansible 必先懂 2020 年那次歷史性拆分。這是有 break 的根源。

D.1.1歷史時間線

Figure D.1 — Ansible 從 monolith 到 ecosystem 的演進

D.1.2為什麼要拆

🎯

release 節奏不同

AWS module 每月需要更新（API 變）；core 引擎想穩定。綁一起兩邊都受罪。

👥

maintainer 分工

核心引擎 vs cisco IOS 是不同人。集中在一個 repo review 變瓶頸。

📦

大小爆炸

2.9 一個 install 含 3000+ module、多數人用不到。拆出來「pay for what you use」。

🔧

vendor 自有節奏

NetApp / Cisco / VMware 等 vendor 想自己 release 自己的 module不被 Ansible release 卡。collection 給他們自治權。

D.2FQCN — 從建議到強制

D.2.1FQCN 演進三階段

階段版本FQCN 狀態
① 短名時代 2.9 與更早 module 名直接用（copy / apt）。沒有 namespace 概念。
② FQCN 建議 2.10 - 2.12 短名仍可用、官方強烈建議用 FQCN。runtime.yml 有 redirect 維持向後相容。
③ FQCN 強制 2.13+（ansible-lint 預設） ansible-lint 預設 fqcn rule 開啟。CI 不過。社群文化全 FQCN。某些第三方 collection 已停 redirect。

D.2.2為什麼 FQCN 重要

ⓘ 同名 module 衝突問題

2.10 後不同 collection 可有同名 module。例：community.general.docker_container vs community.docker.docker_container（後者較新、前者舊版 redirect）。playbook 寫短名 docker_container 怎麼辦？看哪個 collection 先載入決定行為——不可預測。FQCN 把這變確定。

D.3五大破壞性類別

升級時你會遇到的破壞分五大類。每類處理方式不同。

🏷

① Module 改名

同 collection 內 rename。例：postgresql_lang → postgresql_ext。runtime.yml 有 redirect、警告 + 還能跑、major 才移除。

📦

② Module 搬到別 collection

從 community.general 移到專門 collection。例：postgresql 從 community.general 搬到 community.postgresql。2.10+ 有 redirect、2.9 無。

🗑

③ Module 移除（tombstone）

完全移除、有 tombstone 訊息告訴你替代品。例：foreman 移除、用 theforeman.foreman。

⚙

④ 預設值改

同 module / 同參數但預設值不同。最危險——不報錯但行為變了。例：community.crypto get_certificate 的 asn1_base64 從 false 變 true。

🔌

⑤ API / 行為改

module 的回傳結構或 task 行為變了。例：某 module 之前 return string、現在 return list。register 後的 playbook 邏輯需改。

D.4import vs include 演進

D.4.1三種「include」對照

2.9 寫法2.10+ 寫法差異
include: foo.yml ansible.builtin.include_tasks: foo.yml 或 ansible.builtin.import_tasks: foo.yml include 通用 keyword 已廢棄、必須明確 include / import
include_role: name=foo ansible.builtin.include_role: name: foo FQCN + YAML 寫法
roles: [foo] 不變（仍可用） play-level role 引用維持

D.4.2import vs include 何時用哪個

⚡

import_*（靜態）

parsing time 展開。可繼承 tags。不能用 loop / 動態變數名。預設選項 — 簡單可預測。

🔄

include_*（動態）

runtime 展開。可 loop / 動態變數名（include_tasks: "{{ os }}.yml"）。不能用 tags 直接 target 內部 task。

D.5版本相容矩陣

D.5.1ansible-core ↔ ansible package 對照

ansible package內含 ansible-core釋出年狀態（2026.05）
2.9（monolith）—（合一）2019EOL — 不該還在用
3.xansible-core 2.102021EOL
5.xansible-core 2.122022EOL
7.xansible-core 2.142023EOL
9.xansible-core 2.162024EOL
10.xansible-core 2.172024EOL（前個版本）
11.xansible-core 2.182025當下主流
12.x（即將）ansible-core 2.202026 下半年RC 階段
⚠ 升級不能直接跳太多版

從 2.9 直跳 2.18+ 會超痛——中間 4-5 個 major 累積的 break 一次來。建議分兩步：① 2.9 → 5.x（2.12）解決 monolith 拆分；② 5.x → 11.x 解決 FQCN 強制 + 各 collection 的 deprecation。每步跑完整 CI 測試再前進。

D.7ansible-lint 自動偵測

大型 codebase 升級首招 — 不要手動 grep。ansible-lint 一鍵掃出所有 deprecation。

D.7.1專案 .ansible-lint 範例

yaml · .ansible-lint — 升級偵測模式 
---
# 升級期間用嚴格模式抓所有問題
strict: true

# 排除（已知不修的、舊測試 fixture）
exclude_paths:
  - .cache/
  - .git/
  - tests/fixtures/     # 故意保留的舊語法

# 啟用所有 deprecation 相關 rule
enable_list:
  - fqcn
  - deprecated-module
  - deprecated-command-syntax
  - deprecated-local-action

# 警告但不擋（先觀察）
warn_list:
  - fqcn[action-core]          # builtin 沒 FQCN
  - fqcn[action]               # 外部 collection 沒 FQCN
  - no-changed-when            # command 沒 changed_when

ⓘ 升 Ansible 5+ 後 install 時抓不到 collection？

典型情境：你在 Ansible 3 時 community.general 含 postgresql。升到 5 後 community.general 已把 postgresql 抽走、playbook 用 community.general.postgresql_db 仍能 redirect 到 community.postgresql.postgresql_db——但 community.postgresql 沒裝就會 fail。解法：requirements.yml 顯式列出新 collection。

D.10完整遷移案例

本節示範一個 2.9 時代典型 playbook、完整改造到 2.18+ ready。

D.10.1原始 2.9 playbook（破破爛爛）

yaml · 修前 — 2.9 風格 
---
- hosts: web
  become: yes

  tasks:
    - name: Install nginx
      apt:                                          # ⚠ 沒 FQCN
        name: nginx
        state: present
        update_cache: yes

    - name: Set timezone
      timezone:                                     # ⚠ 已搬到 community.general
        name: Asia/Taipei

    - name: Open SSH from internal
      firewalld:                                    # ⚠ 已搬到 ansible.posix
        service: ssh
        permanent: yes
        state: enabled

    - name: Configure DB connection
      postgresql_db:                                # ⚠ 移到 community.postgresql
        name: myapp

    - include: tasks/setup.yml                  # ⚠ include 已廢棄

    - name: Notify monitoring
      local_action:                                 # ⚠ local_action 已廢棄
        module: uri
        url: "https://monitor/notify"

D.10.2修後 2.18+ ready

yaml · 修後 — 2.18+ FQCN 完整 
---
- name: 部署 web tier                          # ✓ 加 play name
  hosts: web
  become: true                                  # ✓ 用 true 不用 yes

  tasks:
    - name: Install nginx
      ansible.builtin.apt:                          # ✓ FQCN
        name: nginx
        state: present
        update_cache: true

    - name: Set timezone
      community.general.timezone:                  # ✓ FQCN 含 collection
        name: Asia/Taipei

    - name: Open SSH from internal
      ansible.posix.firewalld:                     # ✓ 對的 collection
        service: ssh
        permanent: true
        state: enabled

    - name: Configure DB connection
      community.postgresql.postgresql_db:          # ✓ 從 community.postgresql
        name: myapp

    - name: Run setup tasks
      ansible.builtin.include_tasks: tasks/setup.yml     # ✓ 明確 include_tasks

    - name: Notify monitoring
      ansible.builtin.uri:                          # ✓ FQCN
        url: "https://monitor/notify"
      delegate_to: localhost                     # ✓ delegate_to 取代 local_action

collections:
