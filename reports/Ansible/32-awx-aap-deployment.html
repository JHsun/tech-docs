32.2.3建 AWX 實例（CRD）

yaml · awx-instance.yaml — AWX CR 
---
apiVersion: awx.ansible.com/v1beta1
kind: AWX
metadata:
  name: awx
  namespace: awx
spec:
  service_type: ClusterIP     # 用 Ingress 暴露

  ingress_type: ingress
  ingress_class_name: nginx
  hostname: awx.example.com
  ingress_tls_secret: awx-tls

  # 資源規格
  web_replicas: 2
  task_replicas: 2

  web_resource_requirements:
    requests: { cpu: 500m, memory: 2Gi }
    limits:   { cpu: 2,    memory: 4Gi }
  task_resource_requirements:
    requests: { cpu: 500m, memory: 2Gi }
    limits:   { cpu: 2,    memory: 4Gi }

  # Postgres 持久化
  postgres_storage_class: fast-ssd
  postgres_storage_requirements:
    requests: { storage: 20Gi }

  # admin 密碼用 secret
  admin_user: admin
  admin_password_secret: awx-admin-password
bash · apply 與初始登入 
# 4) 建 admin 密碼 secret
$ kubectl -n awx create secret generic awx-admin-password \
    --from-literal=password="$(openssl rand -base64 24)"

# 5) apply CR — operator 會自動建 postgres + redis + web + task pod
$ kubectl apply -f awx-instance.yaml

# 6) 等部署完成（5-10 分鐘）
$ kubectl -n awx get pods -w

# 7) 取 admin 密碼
$ kubectl -n awx get secret awx-admin-password \
    -o jsonpath="{.data.password}" | base64 -d

# 8) 開瀏覽器到 https://awx.example.com — admin / 上題密碼登入

32.4七大物件 — AWX 核心概念

AWX 的世界由七種物件組成。先理解物件關係再做配置。

32.4.1七大物件關係

Figure 32.2 — AWX 七大物件關係（Organization 為頂層、Job Template 為執行單位）

32.4.2七大物件職責

🏢

Organization

最上層。一個公司可有多個 organization（如 Engineering / IT / DBA team 各一）。所有其他物件都屬於某個 org。

👤

User

個人帳號。可整合 LDAP / SAML / OAuth2 SSO。每個 user 屬於某 org（可多個）+ 可加入 team。

👥

Team

user 的集合。權限通常授予 team 而非 user 個人——人員流動時改一條 team membership 比改 N 條 user 權限快。

📂

Project

git repo + playbook 集合。AWX 從 SCM（Git / SVN / 本地）拉。設定 branch / credential / 是否定期 sync。

📋

Inventory

被管 host + group 定義。可手動建（static）、SCM 拉、或從雲端動態拉（aws_ec2 / azure_rm 等 plugin）。

🔐

Credential

所有 secret 的抽象。SSH key / vault password / cloud credentials / SCM token / Container Registry。加密存儲、可整合 HashiCorp Vault。

🚀

Job Template

「誰 + 對誰 + 用什麼 + 跑什麼」的綁定 — Project + Inventory + Credential + EE + playbook 的組合。使用者按按鈕跑的就是 job template。

32.5RBAC 設計

32.5.1四種角色

角色能做什麼適用對象
Admin完全管理（建 / 改 / 刪）org owner、團隊主管
Execute能跑 job template（不能改設定）SRE on-call、DBA、客服
Use能在自己的 job template 內引用此 inventory / credentialjob template owner
Read只能看（不能跑）稽核、新人 onboarding

32.5.2典型 RBAC 設計

text · 典型公司 AWX RBAC 結構 
Organization: "MyCompany"

├── Teams:
│   ├── "Platform-Admins"
│   │   └── Roles: Admin on Organization
│   │
│   ├── "SRE-OnCall"
│   │   └── Roles:
│   │       ├── Execute on Job Template "Restart Service"
│   │       ├── Execute on Job Template "Rotate Logs"
│   │       └── Read on Inventory "Production"
│   │
│   ├── "DBA"
│   │   └── Roles:
│   │       ├── Execute on Job Template "DB Backup"
│   │       ├── Execute on Job Template "DB Migration"
│   │       └── Use on Credential "DB Service Account"
│   │
│   └── "Auditors"
│       └── Roles: Read on Organization (全部唯讀)

# 重點：權限授予 team 而非 user 個人。新人加入只需 add to team。

32.7Survey + Notification

讓非工程師也能跑 — 這是 AWX 真正的魔法。

32.7.1Survey — 用 web 表單問參數

json · job template survey 範例 
{
  "name": "Deploy Application Survey",
  "description": "部署應用前需確認的參數",
  "spec": [
    {
      "question_name": "應用版本",
      "question_description": "git tag 或 docker image tag",
      "required": true,
      "type": "text",
      "variable": "release_version",
      "default": "latest"
    },
    {
      "question_name": "目標環境",
      "required": true,
      "type": "multiplechoice",
      "variable": "target_env",
      "choices": "dev\nstaging\nprod"
    },
    {
      "question_name": "是否跳過 health check",
      "required": false,
      "type": "multiplechoice",
      "variable": "skip_healthcheck",
      "choices": "true\nfalse",
      "default": "false"
    },
    {
      "question_name": "備註",
      "required": false,
      "type": "textarea",
      "variable": "deploy_note"
    }
  ]
}
✓ Survey 把 CLI 變 self-service

原本要工程師在 terminal 打 ansible-playbook -e release_version=v1.2.3 -e target_env=prod ...——對 PM / 客服 / DBA 不友善。Survey 變成 web 表單 → DBA 看到下拉選單就會點，不必學命令列。

32.9API 與 awx CLI — Everything as Code

「我在 web UI 點點點配置好 AWX」是反模式——重建環境時痛苦。AWX 配置應該是 IaC。

32.9.1awx CLI 安裝

bash · 安裝與登入 
# 安裝
$ pip install awxkit

# 登入（產生 personal access token）
$ awx login \
    --conf.host https://awx.example.com \
    --conf.username admin

# Token 寫進 ~/.awxrc — 之後命令自動帶

# 列 organization
$ awx organizations list

# 列 job template
$ awx job_templates list

32.9.2用 CLI 建物件

bash · 從 CLI 建一整套基礎物件 
# 建 organization
$ awx organizations create \
    --name "MyCompany" \
    --description "Main organization"

# 建 team
$ awx teams create \
    --name "DevOps" \
    --organization MyCompany

# 建 credential
$ awx credentials create \
    --name "deploy-ssh" \
    --organization MyCompany \
    --credential_type "Machine" \
    --inputs '{"username": "deploy", "ssh_key_data": "@~/.ssh/deploy.key"}'

# 建 project
$ awx projects create \
    --name "infra-playbooks" \
    --organization MyCompany \
    --scm_type git \
    --scm_url https://github.com/myorg/infra-playbooks \
    --scm_branch main

# 建 job template
$ awx job_templates create \
    --name "Deploy App" \
    --project infra-playbooks \
    --playbook deploy.yml \
    --inventory "Production"

# 觸發 job
$ awx job_templates launch "Deploy App" \
    --extra_vars '{"release_version": "v1.2.3"}'

32.9.3用 REST API 直接呼叫

python · CI 中觸發 AWX job 
import requests, time, os

AWX_URL = "https://awx.example.com"
TOKEN   = os.environ["AWX_TOKEN"]
HEADERS = {"Authorization": f"Bearer {TOKEN}"}

# 觸發 job template
r = requests.post(
    f"{AWX_URL}/api/v2/job_templates/15/launch/",
    json={
        "extra_vars": {"release_version": "v1.2.3"},
        "limit": "prod-us-east-1",
    },
    headers=HEADERS,
)
job_id = r.json()["id"]
print(f"觸發 job {job_id}")

# 等完成
while True:
    s = requests.get(f"{AWX_URL}/api/v2/jobs/{job_id}/", headers=HEADERS).json()
    if s["status"] in ["successful", "failed", "error", "canceled"]:
        break
    time.sleep(10)

print(f"job 結束 status={s['status']}")

32.9.4用 Ansible 配置 AWX 自己

ⓘ 用 Ansible 管 Ansible — awx.awx collection

最 IaC 的做法是寫 playbook 用 awx.awx collection 配置整個 AWX：org / team / user / project / inventory / credential / job_template / workflow 全部 declarative。新環境重建只要 ansible-playbook setup_awx.yml。生產 AWX 一定要這樣管。

32.105 大常見錯誤與業界實踐

32.10.15 大常見錯誤

❌

① 用 docker-compose 跑 production AWX

docker-compose 是 dev only。production 一定要 Operator on Kubernetes。

❌

② 資源不足

少於 4 CPU / 8 GB RAM。OOMKill + UI 爆慢。先 size 對才上線。

❌

③ playbook 內寫死密碼

用 AWX credential（加密 at rest）。不要 commit 密碼到 git。

❌

④ 不升級

AWX 釋出頻繁。落後 2-3 版以上會錯過 security patch。每月一次升級節奏。

❌

⑤ 一個人也用 AWX

單人 / 沒排程需求 → CLI 就夠。AWX 為團隊 / RBAC / audit 而生。

32.10.2業界 8 條最佳實踐

①

配置 IaC 管 — awx.awx collection

org / team / project / job template 全寫 playbook。重建環境靠 ansible-playbook。

②

權限給 team 不給 user

權限授予 team。新人加入 = add to team；離職 = remove from team。比改 N 條 user 權限快。

③

每個 job template 配 survey

讓非工程師按按鈕跑。下拉式 / 必填驗證 / 預設值。

④

關鍵 prod job 配 approval node

workflow template 加 approval node。manager 點同意才跑 prod。

⑤

Credential 走外部 secret store

HashiCorp Vault / AWS SSM / Azure Key Vault credential plugin。AWX 不存 secret 本身、只存 reference。

⑥

Notification 必設

每個 job template 都應配通知（至少 Slack on fail）。沒人看到的 job 失敗等於沒跑過。

⑦

EE 用版本 tag

Job template 指定 EE 用 :2.1.0 而非 :latest。升級先測 staging。

⑧

API token 別用 admin 帳號

CI / 整合用專屬 service account。權限 scoped 到必要範圍。admin token 漏了 = 全公司爆炸。

04

Admin / Execute / Use / Read。權限給 team 不給 user。

05

06

07

08

5 大常見錯誤

docker-compose 上 prod / 資源不足 / 寫死密碼 / 不升級 / 一個人也用 AWX。

練習題

  1. 初學者：在 minikube 用 AWX Operator 部署一個本機 AWX。瀏覽 web UI 找出 organization / project / inventory / job template 四個分頁。
  2. 初學者：建第一個 job template — 對 localhost 跑 hello world playbook。launch 成功後看 stdout / job log。
  3. 初學者：在 web UI 建 1 organization + 2 team（Admins / Operators）+ 3 user（各自加進不同 team）。確認 user 登入後看到的物件不同。
  4. 開發者：對某個 job template 加 survey — 5 個 question 含 text / multiplechoice / textarea。launch 時觀察表單 UI、輸入值傳到 playbook 是 extra_vars。
  5. 開發者：建 workflow template — 三 node：pre-check → approval node → deploy。觸發、在 approval node 暫停、用另一個 user account 點 approve / deny 觀察行為。
  6. 開發者：寫 Python 腳本透過 REST API 觸發 job、poll 狀態到結束、印 stdout。
  7. DevOps / SRE：用 awx.awx collection 寫一份 setup playbook — 建 1 org + 2 team + 3 credential + 5 job template。把整個 lab AWX 配置變成 git 上的 IaC。
  8. DevOps / SRE：把某個 credential 從 AWX 內存改成 HashiCorp Vault credential plugin。AWX 從 Vault 取 secret、不本機存。觀察 job log 不會洩漏 secret。
  9. DevOps / SRE：對你公司目前 Ansible 用法做 RBAC 設計 — 寫一頁 team / role 分配表。team_name × resource × role level。確認 onboarding / 離職 流程相應更新只動 team membership。

本章詞彙表

AWX Operator
AWX 在 Kubernetes 上的 operator（CRD 控制器）。管 AWX 的 lifecycle — install / upgrade / scale / backup。生產級部署唯一推薦方式。
AWX Custom Resource (CR)
kind: AWX 的 K8s 物件。聲明 AWX 實例規格（replicas / 資源 / hostname / TLS）。Operator 看 CR 變更自動 reconcile。
AAP setup bundle
Red Hat 提供的 AAP RPM 安裝套件。tar.gz 解壓含 inventory + setup.sh + playbooks。為傳統 RHEL VM 部署用。
Organization
AWX 最頂層容器。一公司可多個（Engineering / IT / DBA）。所有其他物件都歸屬於某 org。
User
AWX 個人帳號。可整合 LDAP / SAML / OAuth2 / GitHub SSO。
Team
user 集合。權限授予 team 而非個人。新人加入 = add to team。
Project (AWX)
git repo / SVN repo 的抽象。AWX 從 SCM 拉 playbook。設定 branch / SCM credential / Update on launch。
Update on launch
Project 選項。每次 job template 觸發前 git pull 拉最新。確保用最新 playbook。
Inventory (AWX)
被管 host + group 集合。Static（手動建）/ Smart（過濾既有）/ Sourced（從雲端 plugin 動態拉）三種。
Inventory source / sync
動態 inventory 配置。aws_ec2 / azure_rm / gcp_compute / VMware 等 plugin。設定定期 sync 或 update on launch。
Credential
所有 secret 的抽象。Machine / SCM / Vault / Cloud / Container Registry 等 type。加密 at rest、用時注入到 job 不寫 stdout。
Credential plugin
外部 secret store 整合。AWX 不存 secret 本身、只存「從哪取」的 reference。HashiCorp Vault / AWS SSM / Azure Key Vault 等。
Job Template
「Project + Inventory + Credential + EE + playbook」的綁定。使用者按按鈕跑的執行單位。
Workflow Template
多個 job template 的串接。含 approval node / 條件分支（on_success / on_failure / always）/ 並行執行。
Approval node
workflow 的 human gate。暫停等指定 user / team approve 才繼續。生產部署常用。
Survey
job template 的 web 表單。讓使用者輸入 extra_vars。type 支援 text / textarea / password / integer / float / multiplechoice / multiselect。
Notification template
通知配置抽象。Slack / Email / PagerDuty / Webhook 等 type。job template 可配 success / fail 兩種觸發。
RBAC 四角色
Admin（完全管理）/ Execute（能跑 job template）/ Use（能在 job template 引用此資源）/ Read（唯讀）。
awx CLI (awxkit)
pip install awxkit 提供的 awx 命令。CRUD AWX 物件、觸發 job、看狀態。CI 整合用。
awx.awx collection
Ansible collection，用 playbook 配置 AWX 自己。awx.awx.organization / awx.awx.team / awx.awx.job_template 等模組。AWX 配置 IaC 化。
REST API (/api/v2/)
AWX 完整 REST API。awx CLI / awx.awx collection 都是它的 wrapper。直接 HTTP 呼叫適合 CI 整合。
Personal access token
AWX user 用來認證 API 的 token。awx login 產生並寫進 ~/.awxrc。
service account / system token
CI / 整合用的專屬帳號。權限 scoped 到必要範圍、不用 admin 帳號的 token。
Schedule
Job template / workflow 的 cron-like 排程。RRule（iCal RFC 5545）格式。「每週日 02:00 跑備份」這種需求。
Instance group
AWX execution 的分組。配 node 拓撲與容量。多 team / 多 region 部署用。
Smart Inventory
用 search filter 動態挑選 host 形成 inventory。例：「所有有 webserver tag 且在 us-east-1 的 host」。基底 inventory 改變、smart inventory 自動更新。
Job slicing
把單一 job 切成多個 slice 並行跑（每 slice 處理一部分 host）。1000 host 的 job 切 10 slice 各跑 100 host 加速。
