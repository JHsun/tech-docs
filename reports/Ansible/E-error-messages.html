E.1三層 debug 心法

Ansible 的錯誤可能發生在三個層次。抓對層才不會亂找。

Figure E.1 — Ansible 錯誤的三個層次

E.1.1判斷錯在哪層

訊息特徵層次第一招
ERROR! ... line X / could not be parsedLayer 1yamllint + --syntax-check
UNREACHABLE / Connection refused / Permission deniedLayer 2手動 ssh -vvv 重現
FAILED! / module_stderr / rc=非0Layer 3看 stderr / 加 -vvv 看完整輸出

E.1.2萬用三招 SOP

①

看完整錯誤

ansible-playbook -vvv site.yml。-v 看 task 結果、-vv 加參數、-vvv 加連線細節、-vvvv 加 SSH 協定。

②

單獨重現

用 ad-hoc 直接打單一 host：ansible HOST -m MODULE -a "ARGS" -vvv。剝離掉 playbook 干擾。

③

看遠端

SSH 進去手動跑同樣命令。Ansible 失敗 90% 是因為「對的命令在錯的環境跑」——直接跑能定位環境差異。

E.2連線錯誤（Layer 2）

E.2.1UNREACHABLE — 完全連不到

text · 典型訊息 
web-01 | UNREACHABLE! => {
    "changed": false,
    "msg": "Failed to connect to the host via ssh:
            ssh: connect to host 10.0.0.5 port 22: No route to host",
    "unreachable": true
}
ⓘ 排查 SOP

① ping 10.0.0.5 — 網路通嗎；② nc -zv 10.0.0.5 22 — 22 port 開嗎；③ 確認 inventory 的 ansible_host / ansible_port 對；④ 防火牆規則（host firewall + cloud security group）；⑤ host 是否真的 Running（雲端可能 stopped）。

E.2.2Permission denied (publickey)

text · SSH key 不對 
web-01 | UNREACHABLE! => {
    "msg": "Failed to connect to the host via ssh:
            ubuntu@10.0.0.5: Permission denied (publickey,password)."
}
ⓘ 修復 6 招

① 手動 ssh -vvv ubuntu@10.0.0.5 重現；② 確認 ansible_user 對（cloud 預設 user 各家不同——Ubuntu 是 ubuntu、AL2 是 ec2-user、Debian 是 admin）；③ ssh-add -L 看 key agent 有沒有載 key；④ chmod 600 ~/.ssh/id_* 確保權限；⑤ --private-key 強制指定 key；⑥ 對 cloud VM 確認 metadata 注入的 key 是哪一把。

E.2.3Host key verification failed

text · 已知 host key 不符 
fatal: [web-01]: UNREACHABLE! => {
    "msg": "Host key verification failed."
}
bash · 修 
# 已存的 host key 與目前不符（重建 VM 常見）
$ ssh-keygen -R 10.0.0.5    # 移除舊紀錄

# lab 環境常永久關掉
# ansible.cfg：
# [defaults]
# host_key_checking = False

# 或環境變數
$ export ANSIBLE_HOST_KEY_CHECKING=False

# prod 不要關 — 改成預先收集 known_hosts
$ ssh-keyscan -H 10.0.0.5 >> ~/.ssh/known_hosts

E.2.4SSH timeout

text · 連線中斷或太慢 
fatal: [edge-01]: UNREACHABLE! => {
    "msg": "Failed to connect to the host via ssh:
            ssh_exchange_identification: Connection closed by remote host"
}

# 或：
fatal: [edge-01]: FAILED! => {
    "msg": "Timeout (12s) waiting for privilege escalation prompt"
}
ini · ansible.cfg 加長 timeout 
[defaults]
timeout = 60

[ssh_connection]
retries = 5
ssh_args = -o ConnectTimeout=60 -o ControlMaster=auto -o ControlPersist=60s

[privilege_escalation]
become_timeout = 60

E.2.5too many authentication failures

text · key agent 太多 key 
"msg": "Received disconnect from 10.0.0.5 port 22:2:
        Too many authentication failures"
ⓘ 原因

SSH agent 載了 10 把 key、SSH 一把把試、伺服器 5 次失敗就斷線。修：用 IdentitiesOnly=yes 強制只用指定 key。ssh_args = -o IdentitiesOnly=yes -o IdentityFile=~/.ssh/deploy.key。

E.2.6Network is unreachable

text · 路由問題 
"msg": "ssh: connect to host 10.99.99.99 port 22: Network is unreachable"

修：ip route get 10.99.99.99 看路由表。VPN / 跳板機 / NAT 場景要確認連線拓撲。對私有網段 host 通常需先連 bastion。

E.2.7SSH connection reset by peer

text · 中途被斷 
"msg": "ssh: connect to host ... Connection reset by peer"

修：通常是 SSH server 端 fail2ban / DenyHosts / 並發連線限制踢人。① 看 /var/log/auth.log；② 加 fail2ban whitelist control 機；③ 提高 MaxStartups；④ 用 ControlMaster 重用連線降低數量。

E.2.8WinRM 連線失敗（Windows）

text · Windows host 不能連 
"msg": "winrm or requests is not installed: No module named 'winrm'"
# 或：
"msg": "the connection plugin 'winrm' was not found"
bash · 修 
# controller 端裝 pywinrm
$ pip install pywinrm

# inventory 確認
# ansible_connection: winrm
# ansible_winrm_transport: ntlm 或 kerberos 或 basic
# ansible_winrm_server_cert_validation: ignore（lab）

# Windows host 端要先 enable WinRM service
# PowerShell：Enable-PSRemoting -Force

E.2.9Could not chdir to home directory

text · home 目錄不存在 
"stderr_lines": [
    "Could not chdir to home directory /home/deploy: No such file or directory"
]

修：用戶建好但 home 沒建。ansible.builtin.user 加 create_home: true。或在 ansible.cfg remote_tmp = /tmp/.ansible/tmp 不依賴 home。

E.2.10SSH agent 沒啟動

text · agent 連不到 
"Could not open a connection to your authentication agent."

修：eval $(ssh-agent -s) && ssh-add ~/.ssh/id_ed25519。或在 ansible.cfg / inventory 直接 ansible_ssh_private_key_file 指定 key 略過 agent。

E.3認證 / 權限（Layer 2/3）

E.3.1Missing sudo password

text · sudo 要密碼 
fatal: [web-01]: FAILED! => {
    "module_stderr": "sudo: a password is required\n",
    "msg": "MODULE FAILURE"
}

修 4 招：① --ask-become-pass CLI 互動問；② sudoers 設 NOPASSWD（lab 用）；③ vault 存密碼 + ansible_become_password；④ AAP / AWX 用 Machine credential 注入。

E.3.2sudo: requiretty

text · sudo 要 TTY 但 SSH pipelining 沒 
"module_stderr": "sudo: sorry, you must have a tty to run sudo"
⚠ pipelining 與 requiretty 衝突

啟用 SSH pipelining 加速時 sudo 不能要求 TTY。修：① 該 host 的 sudoers 移除 Defaults requiretty；或 ② 為該 host 關 pipelining：ansible_pipelining: false。

E.3.3sudo: unable to resolve host

text · /etc/hosts 沒寫 hostname 
"sudo: unable to resolve host web-01: Name or service not known"

修：/etc/hosts 加 127.0.0.1 web-01。在 cloud-init 階段做、或第一個 task 用 ansible.builtin.lineinfile 補上。

E.3.4SELinux denial

text · SELinux context 不允許 
"msg": "SELinux is in enforcing mode and you are missing python3-libselinux.
        On RHEL 8, install: dnf install python3-libselinux"

# 或：
"msg": "Failed to set permissions on the temporary files Ansible needs
        to create when becoming an unprivileged user"
bash · 修 
# 1) 裝 python selinux binding（最常見）
$ ansible web -b -m raw -a "dnf install -y python3-libselinux"

# 2) 看 audit log 找具體被擋什麼
$ ssh web-01 sudo ausearch -m avc -ts recent

# 3) 用 audit2allow 產 policy
$ ssh web-01 "sudo audit2allow -a -M myapp"
$ ssh web-01 "sudo semodule -i myapp.pp"

# 4) 設正確 context（不要關 SELinux）
- community.general.sefcontext:
    target: '/var/log/myapp(/.*)?'
    setype: var_log_t
    state: present

E.3.5Failed to set permissions / become_user 不行

text · become 到非 root user 
"msg": "Failed to set permissions on the temporary files Ansible
        needs to create when becoming an unprivileged user
        (rc: 1, err: chown: invalid user: 'postgres' )"
ⓘ become_user 到非 root 的特殊處理

SSH 進去是 ubuntu、要 sudo 變 postgres 跑 task — Ansible 用 ACL 或 chown 切 tmp 檔權限。解法：① 安裝 acl 套件；② 或 allow_world_readable_tmpfiles=True（非 sensitive 場景）；③ 或 pipelining=true 跳過 tmp 檔。

E.3.6API token 過期

text · cloud / SaaS API 401 
"msg": "Failed to connect to API: 401 Unauthorized"

# 或 AWS：
"msg": "An error occurred (ExpiredToken) when calling the
        DescribeInstances operation: The provided token has expired."

修：① 重新登入產新 token；② AWS STS token 檢查 expiry；③ vault 存的 token 檢查更新時間；④ EE 內 token 用 pass 模式從外部注入、不寫死 image。

E.3.7Failed to lock apt

text · apt 同時被別人用 
"msg": "Failed to lock apt for exclusive operation: Failed to lock directory
        /var/lib/dpkg/: read-only file system"

# 或：
"msg": "Could not get lock /var/lib/dpkg/lock-frontend.
        It is held by process XXX (unattended-upgrades)"
yaml · retry 等 unattended-upgrades 結束 
- name: Wait for apt lock
  ansible.builtin.shell: while fuser /var/lib/dpkg/lock-frontend >/dev/null 2>&1; do sleep 5; done
  changed_when: false

# 或 module 直接 retry
- ansible.builtin.apt:
    name: nginx
  register: apt_result
  until: apt_result is not failed
  retries: 10
  delay: 15

E.3.8RBAC 拒絕（K8s / cloud）

text · K8s ServiceAccount 沒權限 
"msg": "deployments.apps is forbidden:
        User \"system:serviceaccount:default:my-sa\" cannot create resource
        \"deployments\" in API group \"apps\" in the namespace \"prod\""

修：① 看 kubectl auth can-i create deployments --as=system:serviceaccount:default:my-sa；② 補對的 Role + RoleBinding；③ AWS 看 IAM policy 是否含必要 action（如 ec2:DescribeInstances）。

E.4變數 / Jinja2（Layer 1）

E.4.1'X' is undefined

text · 最常見錯誤 
fatal: [web-01]: FAILED! => {
    "msg": "The task includes an option with an undefined variable.
            The error was: 'release_version' is undefined"
}
ⓘ 排查 SOP

① 用 debug 印當前 vars：ansible.builtin.debug: var=hostvars[inventory_hostname]；② 確認變數來源優先序（extra_vars > play vars > group_vars/host_vars）；③ 加 | default('value') 防呆；④ {{ release_version | mandatory }} 強制 fail 取代不可預測行為。

E.4.2conditional check failed（when 寫錯）

text · when 條件式有問題 
"msg": "The conditional check 'result.changed == true' failed.
        The error was: error while evaluating conditional"
ⓘ 常見 when 陷阱

① 大括號重複：when: "{{ var }} == 'x'" ❌（已在 Jinja2 context、不要再 {{}}）→ when: var == 'x' ✓；② register 沒設：when 用了不存在的變數；③ 布林 vs 字串：when: var 與 when: var == "true" 行為不同；④ 用 is 測式：when: result is succeeded 比 result.failed == false 安全。

E.4.3type error in template

text · template 渲染錯誤 
"msg": "AnsibleError: template error while templating string:
        unsupported operand type(s) for +: 'int' and 'str'"

修：把字串 + 數字。明確轉型：{{ port | int + 1 }} 或 {{ host ~ ":" ~ port }}（~ 是 Jinja2 的字串 concat）。

E.4.4list / dict access 錯誤

text · 索引超界 / key 不存在 
"msg": "list object has no attribute 'name'"
# 或：
"msg": "'dict object' has no attribute 'foo'"
# 或：
"msg": "list index out of range"
yaml · 防呆寫法 
# 用 default + dict get
value: "{{ users[0].name | default('unknown') }}"

# 用 length 先查
when: items | length > 0

# 用 selectattr 過濾
value: "{{ users | selectattr('active', 'eq', true) | list }}"

E.4.5recursive variable

text · 變數自我引用 
"msg": "recursive loop detected in template string"

修：vars: { foo: "{{ foo }}-suffix" } 會無限遞迴。改用 set_fact 在 task 中明確命名新變數。

E.4.6YAML parsing

text · YAML 語法錯 
ERROR! Syntax Error while loading YAML.
  did not find expected key

The error appears to be in '/path/site.yml': line 23, column 5
ⓘ 常見 YAML 陷阱

① tab / space 混用（YAML 只接 space）；② 冒號後沒空格：key:value ❌ → key: value ✓；③ 字串含特殊字元沒引號：port: 80:443 ❌ → port: "80:443" ✓；④ 跨行字串對齊：用 | 或 >；⑤ 數字被當字串 / 反之：version: 1.10 是 1.1 浮點 ❌ → version: "1.10" ✓；⑥ 用 yamllint file.yml 跑 lint。

E.4.7Trailing slash / list of dicts

text · loop 跑出意料外 
# loop 把字串當字元 iterate
"changed": true,
"item": "n"     # ⚠ 你以為 iterate "nginx"、其實 iterate 'n','g','i','n','x'

修：loop: "{{ packages }}"，packages 必須是 list、不是字串。packages: ['nginx', 'redis']，不是 packages: 'nginx'。

E.4.8set_fact 與 register 混用

text · 變數 scope 困擾 
# 在 role 內 set_fact 設變數、外面 play 卻拿不到？
"msg": "'app_version' is undefined"

修：set_fact 是 host-scoped。其他 host 拿要透過 hostvars[]。例：{{ hostvars['web-01']['app_version'] }}。

E.4.9Lookup plugin 錯誤

text · lookup 找不到 
"msg": "An unhandled exception occurred while running the lookup plugin
        'file'. Error was a <class 'ansible.errors.AnsibleError'>,
        original message: could not locate file in lookup: foo.txt"

修：① lookup file 從 controller 端讀（不是 remote）；② 用相對路徑時是相對 playbook / role；③ 用 {{ playbook_dir }}/files/foo.txt 明確路徑。

E.4.10encoding 問題

text · 中文 / unicode 出錯 
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc3 in position X

修：① LANG=en_US.UTF-8 + LC_ALL=en_US.UTF-8 環境變數；② locale 沒裝（最小映像）：locale-gen en_US.UTF-8；③ Ansible target 設 ansible_python_interpreter 對的 Python 3 而非 Python 2。

E.5Module 載入 / Collection

E.5.1couldn't resolve module/action

text · collection 沒裝 
"msg": "couldn't resolve module/action 'community.postgresql.postgresql_db'.
        This often indicates a misspelling, missing collection,
        or incorrect module path."
bash · 修 
# 1) 看裝了哪些
$ ansible-galaxy collection list

# 2) 裝缺的
$ ansible-galaxy collection install community.postgresql

# 3) 用 requirements.yml 鎖版本
$ cat requirements.yml
# collections:
#   - name: community.postgresql
#     version: ">=3.0.0"

$ ansible-galaxy collection install -r requirements.yml

E.5.2To use the X plugin you need Y

text · 缺 Python 套件 
"msg": "boto3 & botocore are required to use the amazon.aws.ec2_instance module"
"msg": "kubernetes>=12.0.0 is required to use this module"
"msg": "psycopg2 is required for community.postgresql modules"

修：在 controller / EE 端裝 Python 套件。pip install boto3 kubernetes psycopg2-binary。EE 內把這些 pip dep 寫進 requirements.txt。

E.5.3Module 已 deprecated

text · 升版後警告 
[DEPRECATION WARNING]: The module community.general.docker_container has
been deprecated. Use community.docker.docker_container instead.

修：跟著 deprecation 訊息改成新 FQCN。本書附錄 D 有完整對照。

E.5.4Module 找不到（短名 + 沒 FQCN）

text · 老 playbook 升上來 
ERROR! couldn't resolve module/action 'foreman'

修：用 FQCN theforeman.foreman.host。看附錄 D「重新命名/搬移的 collection」表。

E.5.5Python interpreter 警告

text · 沒指定 interpreter 
[WARNING]: Platform linux on host web-01 is using the discovered Python
interpreter at /usr/bin/python3.10, but future installation of another
Python interpreter could change the meaning of that path.

修：明確指定 ansible_python_interpreter: /usr/bin/python3.12 在 inventory。或設 interpreter_python = auto_silent 在 ansible.cfg 隱藏警告。

E.5.6shadow / mask 同名 module

text · 兩個 collection 同名 
[WARNING]: Both 'community.general.docker_container' and
'community.docker.docker_container' are available.
Using community.general.docker_container.

修：永遠用 FQCN 避免歧義。community.docker.docker_container 是新版、明確指定。

E.6檔案 / 編輯模組

E.6.1file not found（template）

text · template src 找不到 
"msg": "Could not find or access 'nginx.conf.j2' on the Ansible
        Controller. If you are using a module and expect the file to
        exist on the remote, see the remote_src option"

修：① template 預設找 templates/ 目錄（role 用法）；② 直接給絕對路徑或 {{ playbook_dir }}/templates/foo.j2；③ copy 模組需 remote_src: true 才從遠端複製。

E.6.2permission denied（dest）

text · 沒權限寫 
"msg": "Destination /etc/nginx/nginx.conf not writable"

修：① task 加 become: true；② 確認 deploy user 屬於對的 group；③ 看 SELinux context（E.3.4）。

E.6.3line not found（lineinfile）

text · regex 沒匹配 
# 沒明確錯誤但 line 沒被改 — regex 不匹配
"changed": false

修：① 用 backrefs: yes 加 regexp 才正確替換；② 確認 regex 是 Python 風格不是 grep 風格；③ insertafter / insertbefore 控制位置；④ 太複雜的多行編輯用 blockinfile 或 template。

E.6.4validate 命令失敗

text · template 帶 validate 出錯 
"msg": "failed to validate: rc:1 error:nginx: [emerg] unknown directive
        \"X\" in /tmp/foo.conf:42"

修：① 把 template 改對；② validate 是好東西——錯了不寫進真檔。看 stderr 找具體錯誤；③ 暫時拿掉 validate 看渲染結果，找問題後再加回。

E.6.5diff 太大 / binary 檔案

text · diff 模式塞爆 
"diff": "...<massive output>..."

修：在 task 加 diff: false 跳過 diff（特別是 binary、大檔、含 secret）。

E.7Vault / 加密

E.7.1Decryption failed

text · 密碼錯 
ERROR! Attempting to decrypt but no vault secrets found

修：① --ask-vault-pass 互動問；② --vault-password-file ~/.vault_pass；③ 多 vault id 用 --vault-id prod@~/.vault_prod。

E.7.2Vault format unhexlify error

text · vault 檔損壞 
"msg": "Vault format unhexlify error: Non-hexadecimal digit found"

修：① git merge 衝突沒解乾淨——重新 vault encrypt；② 編輯時用 ansible-vault edit 不要直接打開 vim 改；③ 確認檔案首行是 $ANSIBLE_VAULT;1.1;AES256。

E.7.3Multiple vault password files

text · 多 vault id 沒對應 
ERROR! Decryption failed (no vault secrets were found that
could decrypt) on /path/secrets.yml
bash · 多 vault id 用法 
$ ansible-playbook site.yml \
    --vault-id prod@~/.vault_prod \
    --vault-id dev@~/.vault_dev \
    --vault-id stage@prompt          # prompt 互動問

# ansible.cfg 預設多 vault id
# [defaults]
# vault_identity_list = prod@~/.vault_prod, dev@~/.vault_dev

E.7.4encrypt_string 用法錯

text · inline 加密格式不對 
ERROR! Variable 'db_password' has an invalid value, which includes
an undefined variable.

修：ansible-vault encrypt_string 'mysecret' --name 'db_password' 產出多行格式必須完整貼進 YAML、縮排對齊、不能有多餘空白。

E.8套件 / OS

E.8.1Could not find package

text · 套件名錯或 repo 沒啟 
"msg": "No package matching 'foo' is available"

修：① 套件名各 distro 不同（vim vs vim-enhanced）；② 該 repo 沒 enable（EPEL / 第三方 repo）；③ apt update / dnf clean all；④ 跨 distro 寫 task 用 vars/RedHat.yml + vars/Debian.yml 各自定義套件名。

E.8.2GPG key 錯誤

text · repo GPG 沒匯入 
"msg": "GPG check FAILED" / "no public key for /var/cache/dnf/..."

修：① 先 ansible.builtin.rpm_key 或 ansible.builtin.apt_key 匯入 key；② 再加 repo；③ 順序不能反。

E.8.3service 無法啟動

text · systemd start 失敗 
"msg": "Unable to start service nginx: Job for nginx.service failed
        because the control process exited with error code."

修：① SSH 進去 journalctl -u nginx --no-pager 看具體 fail 原因；② systemctl status nginx 看；③ 多半是 config 問題——template 帶 validate；④ port 衝突；⑤ permissions / SELinux。

E.8.4磁碟滿

text · 各種詭異錯誤的源頭 
"msg": "No space left on device"

修：① ansible HOST -m shell -a "df -h" 看；② 常見：/var/log 爆 / /tmp 爆 / docker images 爆；③ 加 community.general.filesystem + monitoring。

E.8.5kernel / driver 衝突

text · 升 kernel 後 
"msg": "the kernel module foo is not loaded after reboot"

修：① 升 kernel 後 dkms / 第三方 driver 要重 build；② 用 ansible.builtin.reboot + wait_for_connection；③ kernel 套件升級分開做、最後一起 reboot。

E.9容器 / 網路 / API

E.9.1Docker daemon 連不到

text · daemon socket 
"msg": "Error connecting: Error while fetching server API version:
        ('Connection aborted.', PermissionError(13, 'Permission denied'))"

修：① user 不在 docker group：usermod -aG docker $USER；② socket 權限：/var/run/docker.sock 需可讀；③ Podman rootless 用 XDG_RUNTIME_DIR + 對的 socket。

E.9.2K8s context 錯

text · 對錯 cluster 跑 
"msg": "Failed to load kube config: ...The connection to the
        server localhost:8080 was refused"

修：① kubectl config current-context 確認；② 在 task 明確指定：context: my-prod-cluster 或 kubeconfig: /path/to/config；③ AAP / EE 用 K8s service account credential 不靠 kubeconfig。

E.9.3HTTP timeout / SSL

text · uri 模組常見 
"msg": "Status code was -1 and not [200]:
        Request failed: SSLCertVerificationError"

# 或：
"msg": "Request failed: read timeout"
yaml · uri 防呆寫法 
- ansible.builtin.uri:
    url: "{{ api_url }}"
    timeout: 60
    validate_certs: true          # prod 不要關
    ca_path: /etc/ssl/certs/ca-internal.pem   # 內部 CA
    status_code: [200, 201]
  register: resp
  retries: 5
  delay: 10
  until: resp is succeeded

E.9.4cloud rate limit

text · API 被限流 
"msg": "An error occurred (Throttling) when calling the
        DescribeInstances operation: Rate exceeded"

修：① 加 retry + 指數 backoff；② 減少 concurrency（forks）；③ 大 inventory 用 cache（fact_caching）；④ 避免每 task 對雲端打 API——用 register 快取一次再 reuse。

E.9.5kubectl module 找不到

text · k8s module 預期 deployment 找不到 
"msg": "Failed to find exact match for apps/v1.Deployment by [kind, name]"

修：① wait 條件設對：wait: true + wait_condition；② 確認 namespace；③ K8s API server 狀態（kubectl get nodes）；④ 用 kubernetes.core.k8s_info 先查再操作。
