第 16 章 — 自定 Inventory Plugin

第 4 章學了靜態 inventory（INI/YAML）、第 15 章瞥見了 inventory plugin 的概念。本章把它徹底實作——寫一個從內部 service registry / CMDB API 抓 host 的完整 inventory plugin。涵蓋：BaseInventoryPlugin / Constructable / Cacheable 三大 base class 的職責、verify_file / parse 雙核心方法、host 與 group 怎麼註冊到 inventory 物件、cache 機制如何避免每次跑都打 API、與 constructed feature（keyed_groups / compose / groups）整合讓使用者能寫 Jinja2 表達式分群。讀完這章你能把任何「會回 host list 的資料源」（CMDB、雲端 API、Excel 匯入、爬內網）變成 first-class Ansible inventory 來源。

本章覆蓋官方文件對應：Developing Dynamic Inventory · Inventory Plugins
開發者必讀（全章） DevOps / SRE 必讀（全章 — CMDB 整合是企業共通需求）

16.1為什麼要寫自定 inventory plugin？

第 4 章用過靜態 hosts.yml，第 11 章看過 amazon.aws.aws_ec2 動態 inventory。但有些場景兩者都不適合：

🏢

內部 CMDB 整合

公司有自己的 host 登錄系統（內部 ticketing、自建 service registry）。靜態 inventory 跟不上、雲端 plugin 不適用。

📊

多來源整合

Production 在 AWS、staging 在地端 VM、QA 是 Docker container — 用一個自定 plugin 整合多源 host 並統一打 tag。

🔍

篩選與組合邏輯複雜

需要跨多個 API 拉資料 join 後才能決定 host 屬性（例：先查 DNS 取 IP，再查監控系統取 region 標籤）。

🚀

商業設備 / 內部平台

公司用某商業 IPAM、自建 K8s 多 cluster 管理平台、或內部 PaaS — 需要把這些當 inventory source。

16.1.1動態 inventory：script vs plugin

歷史上有「inventory script」這條路——任何輸出 JSON 的 executable 都能當 inventory。Ansible 2.4 後的 plugin 是更現代的做法：

面向Inventory script（舊）Inventory plugin（新）
實作可執行檔，輸出 JSONPython class 繼承 BaseInventoryPlugin
設定命令列參數或 env varYAML 設定檔（聲明式）
cache 機制自己實作內建 Cacheable base class
動態群組（keyed_groups / compose）自己實作內建 Constructable base class
vault 整合有限原生支援
業界推薦不再推薦（仍相容）標準做法

16.2.1各 base class 的職責

Base class提供什麼能力
BaseInventoryPlugin 必繼承。提供 host/group 註冊 API（self.inventory.add_host 等）、verify_file 與 parse 的入口、self.get_option 讀設定。
Constructable 讓 plugin 支援 keyed_groups、compose、groups 三大動態功能。使用者可在 yml 寫 Jinja2 表達式。
Cacheable 整合 cache plugin，避免每次跑 playbook 都打外部 API。設定檔含 cache: true 即啟用。

16.2.2骨架

python · plugin 最小骨架 
from __future__ import absolute_import, division, print_function
__metaclass__ = type

from ansible.plugins.inventory import BaseInventoryPlugin, Constructable, Cacheable
from ansible.errors import AnsibleParserError


class InventoryModule(BaseInventoryPlugin, Constructable, Cacheable):
    NAME = 'service_registry'           # 必須 — 識別 plugin

    def verify_file(self, path):
        """判斷 path 是否是這個 plugin 該處理的 yml 檔。"""
        if not super().verify_file(path):
            return False
        return path.endswith(('service_registry.yml', 'service_registry.yaml'))

    def parse(self, inventory, loader, path, cache=True):
        """主要邏輯 — 讀資料、註冊 host 與 group。"""
        super().parse(inventory, loader, path, cache)
        self._read_config_data(path)            # 讀 yml 設定到 self.get_option

        # 取得使用者在 yml 設定的選項
        api_url = self.get_option('api_url')

        # TODO: 取資料、註冊 host
        hosts = self._fetch_hosts(api_url)
        for h in hosts:
            self.inventory.add_host(h['name'])
            self.inventory.set_variable(h['name'], 'ansible_host', h['ip'])

16.3verify_file — 識別設定檔

verify_file 是 plugin 對 Ansible 說「這個檔案是給我處理的」的方式。Ansible 會輪流問每個啟用的 inventory plugin，第一個說 yes 的處理該檔案。

16.3.1典型實作

python · verify_file 範例 
def verify_file(self, path):
    """
    識別這個 yml 檔是給我處理的。
    判斷只要「夠精確」即可，Ansible 會用 plugin 設定中的 plugin: 欄位再次驗證。
    """
    # 1) 先呼父類驗證 — 確認檔案存在且可讀
    if not super().verify_file(path):
        return False

    # 2) 我接受這些檔名 pattern 的 yml
    return path.endswith((
        'service_registry.yml',
        'service_registry.yaml',
        'cmdb.yml',
    ))
ⓘ 命名約定

業界慣例：inventory yml 檔名以 <plugin_short_name>.yml 結尾。aws_ec2.yml、azure_rm.yml、service_registry.yml。檔名同時也讓人類清楚這檔是哪個 plugin 處理。

16.3.2verify_file 的最終把關

即使檔名匹配，Ansible 還會檢查 yml 內的 plugin: 欄位是否等於 InventoryModule.NAME。所以 verify_file 只是第一道過濾，回傳 True 不代表你一定處理它。

16.5.1完整 plugin 程式碼

python · inventory_plugins/service_registry.py 
from __future__ import absolute_import, division, print_function
__metaclass__ = type

DOCUMENTATION = r'''
    name: service_registry
    plugin_type: inventory
    short_description: 從內部 service registry 取 inventory
    description:
        - 連到內部 service registry HTTP API 抓取 host list
        - 自動依 environment / role / datacenter 分群
    extends_documentation_fragment:
        - constructed
        - inventory_cache
    options:
        plugin:
            description: token，必須是 service_registry
            required: true
            choices: ['service_registry']
        api_url:
            description: service registry API endpoint
            required: true
            env:
                - name: SERVICE_REGISTRY_URL
        api_token:
            description: API bearer token
            required: false
            env:
                - name: SERVICE_REGISTRY_TOKEN
        environment_filter:
            description: 只取指定 environment 的 host (prod / staging / dev / all)
            required: false
            default: all
'''

EXAMPLES = r'''
# inventories/production/service_registry.yml
plugin: service_registry
api_url: https://registry.internal.example.com/api/v1
api_token: "{{ lookup('env', 'SERVICE_REGISTRY_TOKEN') }}"
environment_filter: prod

cache: true
cache_plugin: ansible.builtin.jsonfile
cache_timeout: 600

# 動態建群組
keyed_groups:
  - key: role
    prefix: role
  - key: datacenter
    prefix: dc

# 自動設變數
compose:
  ansible_host: ip
'''

from ansible.plugins.inventory import BaseInventoryPlugin, Constructable, Cacheable
from ansible.errors import AnsibleParserError
import json
import urllib.request
import urllib.error


class InventoryModule(BaseInventoryPlugin, Constructable, Cacheable):

    NAME = 'service_registry'

    # --------- verify_file ---------
    def verify_file(self, path):
        if not super().verify_file(path):
            return False
        return path.endswith(('service_registry.yml', 'service_registry.yaml'))

    # --------- parse ---------
    def parse(self, inventory, loader, path, cache=True):
        super().parse(inventory, loader, path, cache)

        # 讀使用者 yml 設定 — 會把欄位填到 self.get_option 可訪問的地方
        self._read_config_data(path)

        # 設定 cache key（unique per 設定檔內容）
        cache_key = self.get_cache_key(path)
        use_cache = cache and self.get_option('cache')
        update_cache = False

        # 嘗試從 cache 讀
        data = None
        if use_cache:
            try:
                data = self._cache[cache_key]
            except KeyError:
                update_cache = True

        # cache miss → 打 API
        if data is None:
            data = self._fetch_from_api()
            if use_cache:
                update_cache = True

        # 寫回 cache
        if update_cache:
            self._cache[cache_key] = data

        # 把資料注入 inventory
        self._populate(data)

    # --------- 取資料 ---------
    def _fetch_from_api(self):
        api_url = self.get_option('api_url')
        token = self.get_option('api_token')
        env_filter = self.get_option('environment_filter')

        url = f'{api_url}/hosts'
        if env_filter and env_filter != 'all':
            url += f'?environment={env_filter}'

        req = urllib.request.Request(url)
        if token:
            req.add_header('Authorization', f'Bearer {token}')

        try:
            with urllib.request.urlopen(req, timeout=15) as resp:
                return json.loads(resp.read().decode())
        except urllib.error.URLError as e:
            raise AnsibleParserError(f'service registry API 失敗: {e}')

    # --------- 把資料注入 inventory ---------
    def _populate(self, data):
        strict = self.get_option('strict')

        for host in data.get('hosts', []):
            name = host['name']

            # 1) 註冊 host
            self.inventory.add_host(name)

            # 2) 把 API 回的所有 fields 設成 host 變數
            for key, value in host.items():
                self.inventory.set_variable(name, key, value)

            # 3) 自動加進 environment 群組（明確語意）
            env_group = f"env_{host['environment']}"
            self.inventory.add_group(env_group)
            self.inventory.add_child(env_group, name)

            # 4) 套用 Constructable feature — keyed_groups / compose / groups
            #    這三個從父類繼承來，自動讀使用者 yml 設定執行
            self._set_composite_vars(
                self.get_option('compose'), host, name, strict=strict
            )
            self._add_host_to_keyed_groups(
                self.get_option('keyed_groups'), host, name, strict=strict
            )
            self._add_host_to_composed_groups(
                self.get_option('groups'), host, name, strict=strict
            )

16.6Cache 機制深入

沒 cache 的 plugin 每次跑 playbook 都打 API——大型 inventory 可能 30 秒以上。Cache 機制讓結果存起來，下次跑直接讀本地。

16.6.1Cache 流程

Figure 16.3 — Cache hit / miss 流程

16.6.2Cache 實作要點

①

extends_documentation_fragment 加 inventory_cache

讓你的 plugin 自動繼承 cache / cache_plugin / cache_timeout / cache_connection 等選項。

②

parse 開頭呼 _read_config_data

它會自動載入 cache plugin 並把 cache 物件附到 self._cache。

③

get_cache_key 取唯一 key

確保你的 cache key 不跟其他 plugin / 設定撞。self.get_cache_key(path) 把 path 入 hash。

④

讀寫 self._cache[key]

像 dict 操作。讀：data = self._cache[key]（KeyError 表示 miss）；寫：self._cache[key] = data。

16.6.3使用者強制刷新 cache

bash · 強制清掉 cache 
# 命令列 flag — 跑這次不用 cache（會打 API）
$ ansible-inventory -i ... --graph --refresh-cache

# 或手動清理 cache 檔
$ rm -rf /tmp/ansible_inventory_cache

16.7Constructable 三大功能

繼承 Constructable 後，使用者可在 yml 用三種強大的動態功能。這三個是 aws_ec2 等成熟 plugin 廣泛支援的標配。

16.7.1keyed_groups — 依屬性自動分群

yaml · keyed_groups 範例 
keyed_groups:
  # 依 role 屬性產生群組（role_webserver / role_database / ...）
  - key: role
    prefix: role
    separator: "_"

  # 依環境產生（env_prod / env_staging / ...）
  - key: environment
    prefix: env

  # list 屬性會展開（每個 tag 一個群組：tag_frontline / tag_public / ...）
  - key: tags
    prefix: tag

16.7.2compose — 用 Jinja2 設變數

yaml · compose 範例 
compose:
  # 從現有屬性派生新變數
  ansible_host: ip                                  # 取 ip 欄位
  ansible_user: "'admin' if env == 'prod' else 'devuser'"
  monitoring_url: "'https://monitor.internal/host/' + name"
  is_db: "role == 'database'"

# 注意：compose 的 value 是 Jinja2 expression（已在 {{ }} 內）
# 字串字面量要用單引號 — 'prod'、'devuser' 等

16.7.3groups — 條件式分群

yaml · groups 範例 
groups:
  # 條件成立才把 host 加進該 group
  production_critical: "environment == 'prod' and 'critical' in tags"
  private_only: "public_ip is not defined"
  primary_dbs: "role == 'database' and 'primary' in tags"
  eu_region: "datacenter is match('^eu-.*')"
✓ Constructable 是「使用者擴展點」

Plugin 開發者寫好基本邏輯，使用者用 yml 自己組裝群組與變數，無需改 Python code。同一個 plugin 在不同團隊用不同 yml 設定，產出完全不同的 inventory 結構——這是 Ansible 設計的精髓。

16.9Plugin 開發 Checklist

✓

NAME 與檔名一致

collection 內 NAME 必須是 FQCN（namespace.collection.short_name）。錯了 Ansible 找不到。

✓

verify_file 先呼 super

super().verify_file(path) 先讓父類確認檔案存在可讀。再加自己的 endswith 判斷。

✓

parse 開頭三件事

① super().parse(...)。② self._read_config_data(path)（讀 yml 設定）。③ 設定 cache key 與 use_cache 旗標。

✓

用 self.get_option 取設定

不直接讀 yml 字典——透過 self.get_option('xxx') 才能享受 env / vault / type 驗證。

✓

失敗 raise AnsibleParserError

取 API 失敗、設定缺欄位等情況用此 exception，Ansible 會以友善方式呈現。

✓

支援 Constructable 三件套

每個 host 註冊後呼 _set_composite_vars / _add_host_to_keyed_groups / _add_host_to_composed_groups，讓使用者能用 yml 擴展。

✓

extends_documentation_fragment

DOCUMENTATION 加 constructed 與 inventory_cache fragment，自動繼承標準選項與文件。

✓

用 ansible-inventory 測試

ansible-inventory --graph --list --host X 三種看 inventory 的方式。每個都跑過確認結構正確。

16.10本章重點回顧

01

三大 base class 各司其職

BaseInventoryPlugin 提供 host/group 註冊 API；Constructable 提供 keyed_groups/compose/groups；Cacheable 提供 cache 機制。

02

verify_file = 識別檔案

讓 Ansible 知道某個 yml 是給這個 plugin 處理。先呼 super，再用 endswith 過濾檔名。

03

parse = 主邏輯三步驟

① super.parse + _read_config_data；② 取資料（API / DB / 等）；③ 註冊 host / group / variables。

04

inventory API 五件套

add_host / add_group / add_child / set_variable / get_option。掌握這 5 個就能寫絕大多數邏輯。

05

Cache 是必備

大型 inventory 不 cache 會慢得不能忍。extends_documentation_fragment: inventory_cache + self._cache[key] 即可。

06

Constructable 三件套

每個 host 註冊後呼三個 _add_host_* 方法，把使用者擴展能力交出去。Plugin 寫一次，使用者千變萬化。

07

命名約定

檔名 service_registry.py、yml 命名 *.service_registry.yml 或 service_registry.yml、collection 內 NAME 用 FQCN。

08

用 ansible-inventory 驗證

--graph 看群組樹、--list 看完整 JSON、--host X 看單 host 變數。三招輪流用確認 plugin 正確。

練習題

  1. 開發者：寫一個讀本地 CSV 的 inventory plugin（my_csv.py）。CSV 欄位 name, ip, role, env。實作 verify_file（*.csv.yml）+ parse（讀 CSV → 註冊 host）。用 ansible-inventory --graph 確認結構。
  2. 開發者：擴展上題加 Constructable 支援，使用者可以在 yml 用 keyed_groups 與 compose。確認 compose: ansible_host: ip 生效。
  3. 開發者：為 CSV plugin 加 cache 支援。第二次跑時用 -vvv 觀察 log 確認沒重新讀 CSV。試 --refresh-cache 強制刷新。
  4. 開發者：實作本章 16.5 的 service_registry plugin。先用 python -m http.server 跑一個 mock JSON server 測試（給靜態 hosts.json），確認流程正確再接真實 API。
  5. DevOps / SRE：寫一個從 Excel（.xlsx）讀 inventory 的 plugin。用 openpyxl 解析。考量 sheet 名稱、欄位變化、空值等 edge case。
  6. DevOps / SRE：寫一個合併多源的「meta inventory plugin」——同時從 AWS（用 amazon.aws.aws_ec2 風格）+ 內部 CMDB 取 host，統一打 source 標籤分群。
  7. DevOps / SRE：把第 4 題的 service_registry plugin 包成 collection（myorg.internal namespace），ansible-galaxy collection build 產出 tarball，本地安裝後測試 FQCN 引用。
  8. DevOps / SRE：寫個自動化測試 — 在 CI 中 mock 一個假 service registry HTTP server，跑 plugin 後驗證 ansible-inventory --list 輸出含預期的 group / host / variable。
  9. DevOps / SRE：研究你的組織既有 inventory 來源（CMDB、雲端、Excel、自建工具）。給出一份「值不值得寫自定 plugin」的評估——包含 cost / benefit / 維護成本。

本章詞彙表

Inventory plugin
Ansible 用以動態產生 host 清單的 plugin。從 AWS / Azure / K8s / CMDB / 自定來源等取資料。Ansible 2.4 後的標準做法。
BaseInventoryPlugin
所有 inventory plugin 必繼承的 base class。提供 verify_file / parse 入口、self.inventory 註冊 API、self.get_option 讀設定。
Constructable
Plugin 加此 mixin 後支援 keyed_groups / compose / groups 三大動態功能。讓使用者能用 yml 擴展群組與變數。
Cacheable
Plugin 加此 mixin 後可使用 cache plugin 快取 API 結果。配 inventory_cache documentation fragment。
InventoryModule class
Plugin 程式碼中的 class 名（必須叫這個）。繼承 BaseInventoryPlugin（與 mixin）。
NAME class attribute
Plugin 的識別名稱。專案層 plugin 用短名稱（service_registry），collection 內用 FQCN。
verify_file 方法
Plugin 用以判斷某 yml 設定檔是不是它該處理的。回傳 True/False。第一道過濾。
parse 方法
Plugin 的主邏輯。讀資料、註冊 host / group / variables。Ansible 唯一會呼叫的工作 method。
_read_config_data
BaseInventoryPlugin 提供的方法。讀 yml 設定到內部，之後可用 self.get_option 取值。同時載入 cache plugin。
self.inventory.add_host(name, group=None)
註冊 host 到 inventory。可選擇加入指定 group。
self.inventory.set_variable(host, key, value)
設定 host（或 group）的變數。ansible_host / ansible_user 等連線用變數常見場景。
self.get_option(name)
取使用者在 yml 中設定的選項值。型別轉換、env var fallback 都自動處理。
self._cache[key]
Cacheable mixin 提供的 cache 操作介面。讀寫像 dict。KeyError 表示 cache miss。
get_cache_key(path)
產生 unique cache key（包含 path hash），避免不同 plugin 或設定撞 key。
extends_documentation_fragment
DOCUMENTATION 中宣告繼承標準選項區塊。常用 constructed + inventory_cache。
keyed_groups
Constructable 功能。依 host 屬性自動建立群組。key: role, prefix: role → role_webserver / role_database。
compose
Constructable 功能。用 Jinja2 表達式設 host 變數。ansible_host: ip 把 ip 欄位 alias 成 ansible_host。
groups
Constructable 功能。條件式分群。production_critical: "env == 'prod' and 'critical' in tags"。
AnsibleParserError
Inventory plugin 解析失敗時 raise 的 exception。從 ansible.errors 引入。
ansible-inventory 命令
查 inventory 結構的 CLI。--graph 看樹、--list 看 JSON、--host X 看單 host 變數、--refresh-cache 強制刷新。
