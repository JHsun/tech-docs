第四篇 — 模組／Plugins 生態

第 15 章 — Plugin 系統

第 14 章學了 module——Ansible 派到遠端執行動作的單位。本章看 Ansible 引擎本身的擴展點：plugin。Module 跑在 managed node、plugin 跑在 control node。Ansible 內部幾乎所有元件都是 plugin——你寫的 playbook 就是「把 plugin 串起來」的設定。本章帶你認識 11+ 種 plugin 類型（filter / lookup / callback / inventory / connection / become / strategy / vars / cache / action / test）的職責定位、寫一個自定 filter plugin（4 行起手）、一個 lookup plugin（與外部來源對話）、一個 callback plugin（聽 task 事件做 Slack 通知）。讀完這章你會理解——module 解決「能做什麼」，plugin 解決「怎麼做」、「在哪做」、「資料從哪來」、「結果報哪去」。

本章覆蓋官方文件對應：Working with Plugins · Developing Plugins
初學者選讀（15.1–15.2 概念） 開發者必讀（全章） DevOps / SRE 必讀（全章特別 15.5 callback 與 15.6 inventory plugin 概覽）

15.1Plugin vs Module 的關鍵差異

第一次接觸 Ansible 開發的人最大的混淆：plugin 與 module 都是 Python 檔，差在哪？關鍵差異只有一條，但衍生出全部其他差異：跑在哪台機器。

15.1.1核心差異圖

Figure 15.1 — Module 跑遠端、plugin 跑本地

15.1.2一覽對比

面向ModulePlugin
執行位置Managed node（遠端）Control node（本地）
呼叫方式Task name 欄位呼叫多種：filter 用 |、lookup 用 {{ lookup() }}、callback 自動觸發、inventory 由 -i 觸發
Python 環境遠端的 Python（managed node 安裝）本地的 Python（控制端）
I/O 介面JSON in / JSON outPython function / class（依 plugin 類型）
idempotent 要求必要（changed=true/false）不適用（多數 plugin 是純函式）
典型用途「在 host 上做某件事」「擴展 Ansible 引擎本身」
放哪裡library/ 或 collection 的 plugins/modules/filter_plugins/ 等專屬目錄或 collection 的 plugins/<type>/
ⓘ 心智模型

Module 是「動詞」——「裝套件」、「複製檔案」、「重啟服務」。Plugin 是「介系詞 / 副詞」——「從哪取資料」、「怎麼連線」、「用什麼順序執行」、「結果送到哪」。Module 解決 WHAT，plugin 解決 HOW / WHERE / WHEN。

15.211 種 plugin 類型總覽

Ansible 內部所有功能都是 plugin。以下分四類整理：

15.2.1第一類：資料處理（最常自定）

類型用途呼叫方式
filter Jinja2 中轉換資料 {{ var | my_filter }}
test Jinja2 中判斷 boolean {% if x is my_test %}
lookup 從外部來源（檔案／API／DB）取資料 {{ lookup('my_lookup', arg) }}
vars 注入額外變數（host_vars / group_vars 也是 vars plugin） 自動執行

15.2.2第二類：執行控制

類型用途
action 包裝 module 執行邏輯（許多核心模組如 copy、template 都有對應 action plugin）
strategy 控制 play 執行策略（linear 預設、free 不等待、debug 互動）
cache 快取資料（最常用：fact caching）

15.2.3第三類：連線與權限

類型用途
connection 與遠端通訊的方式（ssh、local、docker、kubectl、winrm）
become 權限提升方法（sudo、su、doas、pbrun）
shell 遠端 shell 種類（sh、powershell）
cliconf / netconf / httpapi / terminal 網路設備專用通訊（cisco / juniper / arista 等）

15.2.4第四類：輸入輸出

類型用途
inventory 動態 inventory 來源（AWS / GCP / Azure / Kubernetes / 自定 CMDB）
callback 觀察 Ansible 執行事件並輸出（預設 callback、Slack 通知、Prometheus metrics、JSON log）

15.2.5哪些常自定？

①

最常自定：filter / test

幾行 Python 就完成一個資料轉換。專案常會累積一批內部 filter（IP 處理、字串格式化、業務邏輯）。

②

常自定：lookup / inventory

內部 secret manager / CMDB / 自定 inventory 來源等接入點。中大型團隊常見。

③

偶爾自定：callback

整合通知系統（Slack / PagerDuty / Datadog）、自定 log 格式、CI/CD 整合。

④

少數自定：connection / become / strategy

專業場景：自家管理工具、特殊 escalation、複雜執行流程。Ch18 詳解 connection。

專案層 plugin 目錄名以 _plugins 結尾（filter_plugins/、lookup_plugins/），collection 內則無此後綴（plugins/filter/、plugins/lookup/）。歷史相容因素，記住即可。

15.4第一個 plugin：自定 Filter

Filter plugin 是最簡單的——就是 Python function 包進一個 class。看完這節你就能寫自家專屬 filter。

15.4.1最小範例

python · filter_plugins/my_filters.py 
# filter_plugins/my_filters.py
from __future__ import absolute_import, division, print_function
__metaclass__ = type


def mask_secret(value, show=4):
    """遮蔽 secret，只露出後 N 碼。"""
    if not value:
        return value
    value = str(value)
    if len(value) <= show:
        return '*' * len(value)
    return '*' * (len(value) - show) + value[-show:]


def to_snake_case(s):
    """CamelCase → snake_case。"""
    import re
    s1 = re.sub(r'(.)([A-Z][a-z]+)', r'\1_\2', s)
    return re.sub(r'([a-z0-9])([A-Z])', r'\1_\2', s1).lower()


class FilterModule(object):
    """Ansible 透過此 class 收集所有 filter。"""

    def filters(self):
        return {
            'mask_secret': mask_secret,
            'to_snake_case': to_snake_case,
        }

15.4.2使用

yaml · 在 playbook 中使用自定 filter 
- name: 遮蔽 API key 顯示
  ansible.builtin.debug:
    msg: "API key: {{ api_key | mask_secret(show=6) }}"
  # 輸出：API key: ************abc123

- name: 統一變數命名
  ansible.builtin.debug:
    msg: "{{ 'CamelCaseValue' | to_snake_case }}"
  # 輸出：camel_case_value

15.4.3進階：filter 接多參數

python · 多參數 filter 
def truncate_middle(value, max_len=40, separator='...'):
    """超長字串中間截斷。範例：abcdefghij... wxyz"""
    if len(value) <= max_len:
        return value
    half = (max_len - len(separator)) // 2
    return value[:half] + separator + value[-half:]

# 用法 yaml:
# {{ very_long_path | truncate_middle(max_len=30) }}
ⓘ filter 是純函式，無 idempotency 包袱

Filter 不該有副作用（不寫檔案、不打 API、不改變數）——純粹資料 in / 資料 out。寫 filter 比寫 module 簡單一個量級，又能大幅提高 playbook 可讀性。專案累積一批內部 filter 是常態。

15.5第二個 plugin：自定 Lookup

Lookup plugin 從外部來源取資料注入 Jinja2。第 9 章用過 file / env / password / pipe / url 等內建 lookup。本節寫一個自家版本。

15.5.1範例：從內部 secret manager 取值

python · lookup_plugins/internal_secret.py 
#!/usr/bin/python
from __future__ import absolute_import, division, print_function
__metaclass__ = type

DOCUMENTATION = """
    name: internal_secret
    author: Platform Team
    short_description: 從內部 secret manager 取值
    description:
        - 連到內部 secret manager API 取值
    options:
        _terms:
            description: secret 路徑（如 prod/db/password）
            required: true
"""

EXAMPLES = """
- ansible.builtin.debug:
    msg: "{{ lookup('internal_secret', 'prod/db/password') }}"
"""

RETURN = """
_raw:
    description: secret 值
    type: list
"""

from ansible.errors import AnsibleError
from ansible.plugins.lookup import LookupBase
import os
import requests


class LookupModule(LookupBase):

    def run(self, terms, variables=None, **kwargs):
        api_url = os.environ.get('INTERNAL_SECRET_API', 'https://secret.internal')
        token = os.environ.get('INTERNAL_SECRET_TOKEN')

        if not token:
            raise AnsibleError('INTERNAL_SECRET_TOKEN env var required')

        results = []
        for term in terms:
            try:
                resp = requests.get(
                    f'{api_url}/secrets/{term}',
                    headers={'Authorization': f'Bearer {token}'},
                    timeout=10,
                )
                resp.raise_for_status()
                results.append(resp.json()['value'])
            except requests.RequestException as e:
                raise AnsibleError(f'取 secret {term} 失敗: {e}')

        return results

15.5.2使用

yaml · 在 playbook 中使用 
- name: 取 production DB 密碼
  community.postgresql.postgresql_user:
    name: appuser
    password: "{{ lookup('internal_secret', 'prod/db/password') }}"
  no_log: true      # 重要：lookup secret 時 task 加 no_log

15.5.3Lookup plugin 的關鍵設計原則

①

跑在 control node

所有外部 API call、檔案讀取都發生在控制節點。對 managed node 沒影響。

②

每次評估都跑一遍

Jinja2 表達式每被評估時 lookup 都重新跑。如有 expensive 操作（API call）要考慮 cache。

③

始終回傳 list

run() 必須回傳 list（即使只有一個結果）。lookup() 預設取 list 第一個並 join 成字串，query() 取整個 list。

④

失敗用 AnsibleError

從 ansible.errors 引入並 raise。Ansible 會把錯誤訊息以 task 失敗形式呈現。

15.6第三個 plugin：自定 Callback

Callback plugin 是 Ansible 的「事件監聽器」。每當 task 開始 / 完成 / 失敗、play 結束等都會觸發對應 method。寫 callback 可以做：自家 log 格式、Slack 通知、Prometheus metrics、CI 整合等。

15.6.1事件 method 速查

method觸發時機
v2_playbook_on_startplaybook 開始
v2_playbook_on_play_start每個 play 開始
v2_playbook_on_task_start每個 task 開始
v2_runner_on_oktask 在某 host 上成功（含 changed）
v2_runner_on_failedtask 在某 host 上失敗
v2_runner_on_unreachablehost 連不到
v2_runner_on_skippedtask 被 when 跳過
v2_playbook_on_statsplaybook 結束（PLAY RECAP）

15.6.2範例：失敗自動發 Slack

python · callback_plugins/slack_notify.py 
from __future__ import absolute_import, division, print_function
__metaclass__ = type

DOCUMENTATION = """
    callback: slack_notify
    type: notification
    short_description: 失敗時發 Slack 通知
    description:
        - 監聽 task failed / unreachable / playbook stats 事件
    requirements:
        - SLACK_WEBHOOK_URL 環境變數
"""

from ansible.plugins.callback import CallbackBase
import json
import os
import urllib.request


class CallbackModule(CallbackBase):
    """失敗時發 Slack。"""

    CALLBACK_VERSION = 2.0
    CALLBACK_TYPE = 'notification'
    CALLBACK_NAME = 'slack_notify'

    # 必須是 whitelisted（避免不請自來）
    CALLBACK_NEEDS_ENABLED = True

    def __init__(self):
        super().__init__()
        self.webhook = os.environ.get('SLACK_WEBHOOK_URL')
        self.failed_tasks = []

    def _send(self, text, color='danger'):
        if not self.webhook:
            return
        payload = json.dumps({
            'attachments': [{'color': color, 'text': text}],
        }).encode()
        try:
            urllib.request.urlopen(
                urllib.request.Request(
                    self.webhook,
                    data=payload,
                    headers={'Content-Type': 'application/json'},
                ),
                timeout=5,
            )
        except Exception:
            pass      # 通知失敗不該讓 playbook 也失敗

    def v2_runner_on_failed(self, result, ignore_errors=False):
        if ignore_errors:
            return
        host = result._host.get_name()
        task = result.task_name()
        msg = result._result.get('msg', '(no message)')
        self.failed_tasks.append(f'{host}: {task}')
        self._send(f'❌ Task FAILED on {host}: {task}\n{msg[:500]}')

    def v2_runner_on_unreachable(self, result):
        host = result._host.get_name()
        self._send(f'⚠ Host unreachable: {host}', color='warning')

    def v2_playbook_on_stats(self, stats):
        if self.failed_tasks:
            summary = f'Playbook 結束。共 {len(self.failed_tasks)} 個失敗 task'
            self._send(summary, color='danger')
        else:
            self._send('✅ Playbook 全部成功', color='good')

ini · ansible.cfg — 啟用 callback

# 預設 callback 不啟用 NEEDS_ENABLED 的 plugin，要明確列出

# 多個 callback 用逗號隔開
# callbacks_enabled = slack_notify, profile_tasks, timer
ⓘ 內建好用的 callback 推薦

不必每個都自己寫——Ansible 內建很多實用 callback：profile_tasks（顯示每個 task 耗時）、timer（總時長）、json（輸出 JSON 格式）、yaml（更可讀的輸出）、dense（緊湊輸出）。在 callbacks_enabled 列出即可。

15.8Plugin 開發建議

✓

從 filter 開始

Filter 是進入 plugin 開發最簡單的入口——4 行 boilerplate 就能寫一個。先寫 filter 培養感覺，再進 lookup / callback 等。

✓

看現有 plugin 原始碼

Ansible 內建 plugin 全部 GitHub 開源。ansible/plugins/<type>/ 下都是好範例。寫前先看 5 個既有的同類 plugin。

✓

寫 DOCUMENTATION 區塊

跟 module 一樣 — DOCUMENTATION / EXAMPLES / RETURN 三大區塊讓 ansible-doc 能查、IDE 能補全。

✓

callback / lookup 失敗別讓 play 掛

Slack 通知失敗、secret manager 暫時不可用——這些不該讓整個 play 死掉。catch exception 做 graceful degradation。

✓

Callback 用 NEEDS_ENABLED

Callback plugin 對全 playbook 都生效，不請自來會嚇到使用者。設 CALLBACK_NEEDS_ENABLED = True，只在明確啟用時才執行。

✓

Lookup 結果該有 cache 考量

每次 Jinja2 評估都跑一遍——expensive lookup（API call）會被觸發很多次。考慮用 cache 或 set_fact 把結果存起來。

15.9本章重點回顧

01

Plugin = Ansible 引擎本體擴展點

Module 跑遠端，plugin 跑本地。Module 是「動詞」（做什麼），plugin 是「介系詞」（從哪、怎麼、何時）。

02

11+ 種 plugin 類型

四大類：資料處理（filter / test / lookup / vars）、執行控制（action / strategy / cache）、連線權限（connection / become / shell）、輸入輸出（inventory / callback）。

03

放對目錄即生效

專案層用 filter_plugins/、lookup_plugins/ 等；collection 用 plugins/filter/、plugins/lookup/ 等。無需註冊。

04

Filter 是入門首選

Python function + FilterModule class 5 行 boilerplate。寫起來最簡單、用起來最頻繁。

05

Lookup 從外部取資料

繼承 LookupBase、實作 run() 回傳 list。常見用途：secret manager 整合、CMDB 查詢、外部設定。

06

Callback 監聽 Ansible 事件

繼承 CallbackBase、實作 v2_* 系列 method。常見用途：Slack 通知、自家 log、CI metrics。需 CALLBACK_NEEDS_ENABLED = True。

07

Inventory 動態 host 來源

從 AWS / Azure / K8s / CMDB 等動態列 host。yml 設定檔配合 inventory plugin。Ch16 詳解。

08

從 filter 開始 → 看內建 plugin 學

進入 plugin 開發路徑：寫幾個 filter → 看內建 plugin 原始碼 → 寫 lookup → 寫 callback → 進階 inventory / connection。

練習題

  1. 初學者：用 ansible-doc -t filter -l 列出所有可用 filter，挑 5 個沒看過的閱讀其 EXAMPLES。
  2. 初學者：用 ansible-doc -t callback -l 列所有 callback，啟用 profile_tasks 跑一次 playbook，觀察輸出多了什麼資訊。
  3. 初學者：找一個 ansible 內建的 filter（如 ansible/plugins/filter/core.py）讀原始碼，找出 FilterModule.filters() 是怎麼註冊的。
  4. 開發者：實作本章 15.4 的 my_filters.py（含 mask_secret + to_snake_case + truncate_middle 三個 filter），在 playbook 中用 debug 印出測試結果。
  5. 開發者：寫一個自定 test plugin（位置：test_plugins/my_tests.py）內含 is_valid_ip 與 is_strong_password 兩個 test。在 playbook 用 {% if x is is_valid_ip %} 測試。
  6. 開發者：實作一個簡化版的 lookup plugin cmd_with_timeout——比 pipe lookup 更安全，限制最大執行時間 30 秒，超時 raise AnsibleError。
  7. DevOps / SRE：寫一個 callback plugin 把 task 結果輸出成 JSON 行，每行是一個事件（task_started / task_ok / task_failed），方便 log aggregator 收集。
  8. DevOps / SRE：把上一題的 callback 加 metrics 輸出——統計每個 task 的耗時、成功率，v2_playbook_on_stats 結束時 push 到 Prometheus pushgateway 或 Datadog API。
  9. DevOps / SRE：研究 amazon.aws.aws_ec2 inventory plugin 設定。寫一個 yml 從你的 AWS 帳號（或本地 LocalStack）列 EC2，用 keyed_groups 依 tag 分群，compose 設 ansible_host 用 private IP。

定義與 managed node 通訊方式的 plugin。ssh 預設、local / docker / kubectl / winrm 等。Ch18 詳解。
Become plugin
權限提升方法。sudo 預設、su / doas / pbrun 等。
Strategy plugin
控制 play 執行策略。linear（預設，等所有 host 完成才下一個 task）、free（不等待）、debug（互動 debug）。
Cache plugin
快取資料的 plugin。常見：fact caching、inventory caching。
Vars plugin
注入額外變數的 plugin。host_vars / group_vars 都是 vars plugin。
Action plugin
包裝 module 執行邏輯的 plugin。copy、template 等核心模組都有對應 action plugin。
FilterModule class
Filter plugin 的標準入口 class。實作 filters() 方法回傳 dict 註冊所有 filter。
LookupBase
Lookup plugin 的 base class，從 ansible.plugins.lookup 引入。實作 run() 方法。
CallbackBase
Callback plugin 的 base class，從 ansible.plugins.callback 引入。實作 v2_* 系列事件 method。
CALLBACK_NEEDS_ENABLED
CallbackBase 的 class 屬性。設 True 後 callback 不會自動執行，需在 callbacks_enabled 明確啟用。
AnsibleError
從 ansible.errors 引入的 exception class。Plugin 失敗時 raise 此 exception，Ansible 會以友善方式呈現錯誤。
callbacks_enabled
ansible.cfg 中啟用 callback plugin 的設定，逗號分隔多個 plugin 名稱。
