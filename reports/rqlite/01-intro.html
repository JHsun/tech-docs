CH. 01認識 rqlite

Beginner Developer DevOps

1.1 rqlite 是什麼？SQLite + Raft 的組合

rqlite 是一套輕量級、使用者友善、容錯、分散式的關聯式資料庫。它將 SQLite 的簡潔特性結合 Raft consensus 演算法所提供的高可用性，讓你能在雲端、邊緣（edge）或一般機房中，部署一套不需要複雜運維就能提供強一致性（strong consistency）的資料庫。

核心設計目標只有一句話：「部署與運維的簡潔（simplicity of deployment and operation）」。rqlite 以單一自帶相依的二進位（self-contained binary）形式釋出，把它丟到機器上就能跑；組成叢集只需要數秒，組態幾乎只需要幾個 flag。所有資料會透過 Raft 自動複製到多個節點，任一節點失效都不會讓整個叢集停擺。

架構上，每個 rqlite 節點都包含三層：

  1. HTTP API 層：對外提供 JSON-based 的讀寫端點（/db/execute、/db/query、/db/request、/db/backup 等）。任何節點都能接收請求，寫入會自動轉送（forward）到 leader。
  2. Raft 層：負責 leader election、log replication、log compaction 與 snapshotting。Raft log 是叢集所有變更的權威紀錄（authoritative record）。
  3. SQLite 儲存層：每個節點都持有完整 SQLite 資料庫副本。Raft 套用 log 時會把命令重放到本地 SQLite，因此所有節點的 SQLite 內容最終一致。

1.2 與相鄰系統的定位差異

rqlite 常被拿來和 etcd、Consul、PostgreSQL、MySQL 比較。它們解決的問題不完全相同，理解差異有助於判斷何時該選 rqlite：

系統資料模型共識 / 複製典型用途vs. rqlite
rqlite 關聯式 SQL（SQLite） Raft HA SQL store、edge、配置/狀態 —
etcd Key-Value（hierarchical） Raft 分散式設定、服務發現、k8s 後端 rqlite 提供完整 SQL；etcd 在 watch / lease 上更專精
Consul KV + 服務目錄 Raft 服務網格、健康檢查、KV 設定 rqlite 不做服務發現，只專心做 SQL 儲存
PostgreSQL / MySQL 關聯式 SQL（完整） 非同步或半同步複製，HA 需額外工具 主流 OLTP 工作負載 rqlite 寫入吞吐量遠較低，但 HA 開箱即用、運維簡單
CockroachDB / TiDB SQL（PostgreSQL/MySQL 相容） Raft / Multi-Raft 大規模分散式 OLTP rqlite 不分片（no sharding），單一資料集；複雜度與資源需求差數量級
SQLite（單機） 關聯式 SQL 無 嵌入式、單機應用 rqlite ≈「networked、replicated SQLite」
💡 一句話定位

rqlite 的官方定位是「think etcd, but with relational modeling available」 — 像 etcd 一樣容易部署、容易運維、強一致，但你能用 SQL 而非 KV。

1.3 核心特性總覽

核心功能（Core functionality）

  • Relational：完整 SQL 支援（基於 SQLite），含 FTS5 全文檢索、JSON1 文件支援、Window functions、CTE 等。
  • Extensible：可載入 SQLite extension，例如 sqlite-vec（vector search）、sqlean（密碼學、數學函式）。
  • Atomic writes：單一請求中的多個 SQL statement 會 atomically 執行；任一失敗則整批 rollback，等同 mini-transaction。
  • Change Data Capture (CDC)：rqlite 9.0（2025-09-15）引入，可將 SQLite 的 INSERT / UPDATE / DELETE 事件即時串流到外部系統（webhook、Kafka 等），用於 cache invalidation、二級資料庫同步、稽核。

運維簡潔（Easy operations）

  • Simple deployment：單一 binary，無外部相依。Docker、Docker Compose、Kubernetes 部署都極為直接。
  • High availability：只要 quorum（多數節點）存活，叢集就繼續服務讀寫。
  • Dynamic clustering：節點可自動透過 DNS、Consul、etcd、Kubernetes 互相發現。
  • Effortless backups：熱備份（hot backup）API；支援自動上傳到 S3、MinIO、GCS。

開發者體驗（Developer experience）

  • Convenient APIs：HTTP / JSON 介面；任何語言都能直接用。
  • Secure by design：節點間與客戶端皆支援 TLS；可啟用 authentication 與 role-based access control。
  • Tunable consistency：每次查詢都能挑 none / weak / linearizable / strong 一致性等級。
  • Queued Writes：以吞吐量交換 durability 保證的高速寫入模式。

1.4 典型使用場景

邊緣運算與 IoT

rqlite 的足跡（footprint）小，適合部署在邊緣設備、遠端辦公室、IoT 硬體。常見作法是在每個邊緣節點跑一個 rqlite 單節點，提供本地 SQL 儲存；需要 HA 時，多台邊緣設備可組成 cluster 互相複製。許多人甚至只是把單節點 rqlite 當作「networked SQLite」來用。

簡化雲端服務

對於需要 HA、但寫入吞吐量不極端的雲端服務，rqlite 是 PostgreSQL / MySQL 的輕量替代。Raft 架構讓你不需要額外的 clustering 軟體或 sidecar，VM 或 Pod 掛掉時叢集自動承受。Replicated（前 SaaS 業者）公司公開分享過用 rqlite 替代 Kubernetes 系統內部某些狀態儲存的案例。

讀取密集、全球分散應用

因為每個節點都有完整資料副本，可以加掛唯讀節點（read-only nodes）。唯讀節點不參與 Raft 投票，純粹擴充讀取能力，並可部署在不同地理區（geographic regions）提供低延遲查詢。對於變更頻率低、但需要全球可用的配置型資料（reference data），這個模式特別合適。

1.5 不適合 rqlite 的場景

誠實地說，rqlite 不是萬靈丹。以下情境應該慎重考慮其他選擇：

⚠ 不適合的工作負載
  • 極高寫入吞吐量：每次寫入都要經過 Raft log replication + fsync 週期，寫入 QPS 上限遠低於 PostgreSQL / MySQL。需要寫入規模化（write scaling）時，請考慮 CockroachDB、TiDB、Vitess。
  • 大型 OLAP / 資料倉儲：rqlite 是 OLTP 取向，SQLite 也不為 PB 級資料設計。請用 ClickHouse、DuckDB、BigQuery、Snowflake。
  • 需要 sharding 的超大資料集：rqlite 不分片，單一節點儲存空間就是整個叢集容量上限（雖然 8.0+ 後的 snapshot 已支援更大資料集）。
  • 需要 PostgreSQL / MySQL wire protocol 相容：rqlite 只提供 HTTP API；現有 ORM 需要走 rqlite 提供的 driver。
  • 需要多 statement transaction 跨 request：rqlite 的原子性只在單一 request 內保證；它不提供傳統 BEGIN ... COMMIT 跨多次 HTTP request 的長交易。
🟢 初學者重點
  • rqlite = SQLite + Raft，是「網路化、容錯版的 SQLite」
  • 用 HTTP JSON 操作，不需要特殊 driver
  • 單一 binary 部署
🔵 開發者重點
  • 完整 SQL（含 FTS5、JSON1、CTE、Window）
  • 每次 request 內的多 SQL atomically 執行
  • 9.0+ 支援 CDC，可作為 event source
🟡 DevOps / SRE 重點
  • Raft quorum：節點數建議奇數（3、5、7）
  • 讀寫吞吐量遠低於傳統 RDBMS，定位是 HA SQL store
  • 每次寫入都 Raft replicate + fsync，磁碟延遲是關鍵效能因素

CH. 02快速入門

Beginner Developer

本章在 5 分鐘內帶你從零跑起 rqlite。我們會：啟動單節點 → 用 shell 建表寫入 → 用 curl 呼叫 HTTP API → 驗證資料持久化 → 額外組一個 3 節點叢集。

2.1 啟動單節點

最快的方式是從 GitHub Releases 下載對應你作業系統與 CPU 架構的 tarball，解開後即可使用。以下示範 Linux amd64：

bash
# 1. 下載並解開（請以實際最新版本 tag 替換）
curl -LO https://github.com/rqlite/rqlite/releases/download/v9.3.0/rqlite-v9.3.0-linux-amd64.tar.gz
tar -xzf rqlite-v9.3.0-linux-amd64.tar.gz
cd rqlite-v9.3.0-linux-amd64

# 2. 啟動單節點（資料寫入 ./data 目錄）
./rqlited -node-id=1 ./data

啟動後 rqlite 預設監聽：

  • HTTP API：http://localhost:4001
  • Raft 內部通訊：localhost:4002（單節點時用不到，但 port 仍會 bind）

data/ 是 rqlite 用來儲存 Raft log、snapshot、SQLite 檔的目錄。-node-id 是這個節點在 Raft 叢集中的識別碼，正式環境建議明確指定，不要依賴自動產生。

🐳 用 Docker 更快

如果你已經有 Docker，一行就能跑起來：

bash
docker run -p 4001:4001 rqlite/rqlite

2.2 用 rqlite shell 建立第一筆資料

另開一個 terminal，啟動 rqlite shell（就是同一個 release 裡的 CLI binary）：

bash
./rqlite
# 進入 shell 後可以直接打 SQL，也可以打 dot commands（以 . 開頭）

在 shell 內依序執行以下指令：

sql
-- 建立 table
CREATE TABLE foo (id INTEGER NOT NULL PRIMARY KEY, name TEXT);
-- 1 row affected (0.000668 sec)

-- 檢視 schema
.schema

-- 寫入資料
INSERT INTO foo(name) VALUES("fiona");
INSERT INTO foo(name) VALUES("bob");

-- 查詢
SELECT * FROM foo;

預期輸出：

text
+----+-------+
| id | name  |
+----+-------+
| 1  | fiona |
| 2  | bob   |
+----+-------+

2.3 用 curl 直接呼叫 HTTP API

rqlite 的核心介面是 HTTP / JSON，意即任何能發 HTTP request 的工具都能操作它。以下示範三個最常用的端點：

2.3.1 /db/execute — 寫入

bash
curl -XPOST 'localhost:4001/db/execute?pretty&timings' \
  -H "Content-Type: application/json" \
  -d '[
    "INSERT INTO foo(name) VALUES(\"charlie\")",
    "INSERT INTO foo(name) VALUES(\"dora\")"
  ]'

這是 Bulk Write 範例：一次送出兩個 INSERT，rqlite 會 atomically 執行；任一失敗則整批 rollback。

2.3.2 /db/query — 讀取

bash
curl -G 'localhost:4001/db/query?pretty&timings' \
  --data-urlencode 'q=SELECT * FROM foo'

回應大致長這樣（精簡）：

json
{
  "results": [{
    "columns": ["id", "name"],
    "types": ["integer", "text"],
    "values": [
      [1, "fiona"],
      [2, "bob"],
      [3, "charlie"],
      [4, "dora"]
    ],
    "time": 0.000345
  }],
  "time": 0.001012
}

2.3.3 /db/request — 混合讀寫

如果單一請求中同時有讀與寫的 statement，可改用 /db/request：

bash
curl -XPOST 'localhost:4001/db/request?pretty' \
  -H "Content-Type: application/json" \
  -d '[
    "INSERT INTO foo(name) VALUES(\"eve\")",
    "SELECT COUNT(*) FROM foo"
  ]'
📍 兩種查詢風格

?q=... 是 GET-friendly 的簡單寫法；POST + JSON array 則支援批次、參數化查詢、命名參數等進階用法。我們會在第二部 第 5 章完整解析所有端點與選項。

2.4 驗證資料持久化

關掉 rqlite 程序（Ctrl + C），然後重新啟動：

bash
./rqlited -node-id=1 ./data
# 注意：data 目錄保持不變

再次查詢 foo table，資料仍然存在。這證明：

  • rqlite 把所有變更寫入 Raft log（位於 data/ 目錄）
  • 啟動時 rqlite 會從 Raft log 重放命令（或從 snapshot 還原）
  • SQLite database file 是 Raft log 的衍生物（derived state）

2.5 (Bonus) 在本機組 3 節點叢集

單機把全部 3 個節點跑起來只是為了 demo，正式環境每個節點應跑在不同機器上。先關掉前面的單節點，然後執行：

bash
# 節點 1（也是初始 leader）
./rqlited -node-id 1 \
          -http-addr localhost:4001 \
          -raft-addr localhost:4002 \
          ./data1 &

# 節點 2，透過 -join 加入
./rqlited -node-id 2 \
          -http-addr localhost:4003 \
          -raft-addr localhost:4004 \
          -join localhost:4002 \
          ./data2 &

# 節點 3
./rqlited -node-id 3 \
          -http-addr localhost:4005 \
          -raft-addr localhost:4006 \
          -join localhost:4002 \
          ./data3 &

透過 shell 確認叢集狀態：

bash
./rqlite
127.0.0.1:4001> .nodes

預期會看到 3 個節點，其中一個 leader: true，其他兩個 leader: false，全部 voter: true、reachable: true。詳細的叢集管理請見第三部 第 12 章。

🟢 初學者重點
  • 單節點啟動：rqlited -node-id=1 data/
  • 用 rqlite shell 練 SQL 最直覺
  • 資料寫在 data/ 目錄，重啟仍在
🔵 開發者重點
  • 三個主要端點：/db/execute 寫、/db/query 讀、/db/request 混合
  • 多 SQL atomically：把多個 statement 包成 JSON array
  • 記得在生產環境用 POST + JSON array，避免 URL encoding 坑
🟡 DevOps / SRE 重點
  • 每節點需要兩個 port：HTTP（-http-addr）+ Raft（-raft-addr）
  • -join 指向任一已知節點的 Raft port
  • -node-id 必須在叢集內唯一，且生產環境必須明確指定

CH. 03安裝 rqlite

Beginner DevOps

rqlite 提供多種安裝方式，覆蓋從快速試玩到正式部署的各種情境。以下依推薦程度由易至難排列。

3.1 預編譯二進位（推薦）

官方為許多平台預編譯了二進位，可以從 GitHub Releases 下載最新版（截至本手冊撰寫為 v9.3.0，2025-11-12 釋出）。

支援平台一覽

OSCPU 架構檔名範例
Linux (glibc)amd64rqlite-v9.3.0-linux-amd64.tar.gz
Linux (musl)amd64rqlite-v9.3.0-linux-amd64-musl.tar.gz
Linuxarm64rqlite-v9.3.0-linux-arm64.tar.gz
Linuxarmrqlite-v9.3.0-linux-arm.tar.gz
Linuxmips / mips64 / mipsle / mips64lerqlite-v9.3.0-linux-mips*.tar.gz
Linuxppc64le / riscv64 / s390xrqlite-v9.3.0-linux-{arch}.tar.gz

⚠ glibc 版本需求

官方 Linux release（非 musl 版）目前要求 glibc 2.32 或以上。較舊的 LTS 系統（如 Ubuntu 18.04、CentOS 7、RHEL 8）可能不符；遇到 GLIBC_2.32 not found 錯誤時，請改用 -musl 版本，或從原始碼編譯。

標準安裝流程（Linux / macOS）

bash
# 1. 下載（以 Linux amd64 為例）
VERSION=v9.3.0
ARCH=linux-amd64
curl -LO "https://github.com/rqlite/rqlite/releases/download/${VERSION}/rqlite-${VERSION}-${ARCH}.tar.gz"

# 2. 校驗 sha256（從 Release page 取得官方 hash）
sha256sum rqlite-${VERSION}-${ARCH}.tar.gz

# 3. 解壓並安裝到系統路徑（可選）
tar -xzf rqlite-${VERSION}-${ARCH}.tar.gz
sudo install rqlite-${VERSION}-${ARCH}/rqlited /usr/local/bin/
sudo install rqlite-${VERSION}-${ARCH}/rqlite  /usr/local/bin/

# 4. 驗證
rqlited -version

3.2 Docker 映像檔

rqlite 同時發佈到 Docker Hub 和 GitHub Container Registry：

bash
# Docker Hub
docker pull rqlite/rqlite:9.3.0

# 或 GitHub Container Registry
docker pull ghcr.io/rqlite/rqlite:9.3.0

# 最快測試方式
docker run -p 4001:4001 rqlite/rqlite

# 帶持久化 volume（建議）
docker run -d \
  --name rqlite \
  -p 4001:4001 \
  -v rqlite-data:/rqlite/file \
  rqlite/rqlite:9.3.0

官方映像支援多 CPU 架構（amd64、arm64、arm/v7 等），docker pull 會自動依宿主機架構抓對應 manifest。Kubernetes 與 Docker Compose 的完整範例請見第三部 第 16-17 章。

3.3 套件管理工具

Homebrew（macOS / Linux）

bash
brew install rqlite

# 確認安裝
rqlited -version
rqlite -version

Windows

Windows 沒有官方 Chocolatey / Scoop 套件，請從 GitHub Releases 直接下載 rqlite-v9.3.0-win64.zip。或者使用 AppVeyor 上的 top-of-tree build（適合開發測試，不適合生產）：https://ci.appveyor.com/api/projects/otoolep/rqlite/artifacts/rqlite-latest-win64.zip?branch=master

3.4 從原始碼編譯

適用情境：需要自訂 build flag、開發 / 貢獻、glibc 版本不符要自己編、或自帶 SQLite extension 編進去。

環境前提

  • Go 1.24.0 或以上（推薦用 gvm 管理多版本）
  • C 編譯器（gcc / clang），因為 SQLite source 是 C，rqlite 透過 CGO 編譯進去
  • git

編譯流程

bash
# 1. 建立 GOPATH 結構（rqlite 仍要求標準 GOPATH 目錄佈局）
mkdir rqlite
cd rqlite/
export GOPATH=$PWD
mkdir -p src/github.com/rqlite

# 2. clone
cd src/github.com/rqlite
git clone https://github.com/rqlite/rqlite.git
cd rqlite

# 3. build & install
go install ./...

# 4. 執行
$GOPATH/bin/rqlited ~/node.1
🔧 為什麼還要 GOPATH？

雖然 Go 早已預設使用 Go modules，但 rqlite 仍要求保留 $GOPATH/src/github.com/rqlite/rqlite 的目錄結構，以避免 import path 衝突；這是專案開發規範，與 module 機制可並存。如果是貢獻 PR，請 fork 自己的 repo，但保留同樣的目錄結構。

執行單元測試

bash
cd $GOPATH/src/github.com/rqlite/rqlite
go test ./...

典型輸出包含 auth、db、http、store 等 package 的測試結果，每個 package 都應顯示 ok。提交 PR 前應確保全綠。

3.5 驗證安裝

無論用哪種方式安裝，最後都用同樣的方式確認：

bash
# 1. 確認版本
rqlited -version
# 預期：v9.3.0 ...

# 2. 啟動單節點（背景）
rqlited -node-id=1 /tmp/rqlite-verify &
RQLITE_PID=$!

# 3. 等 1 秒待節點 ready
sleep 1

# 4. ping health 端點
curl -sf http://localhost:4001/readyz && echo " rqlite READY"

# 5. 收尾
kill $RQLITE_PID
rm -rf /tmp/rqlite-verify

如果上面流程一路順利，rqlite 就裝好了。/readyz 在叢集情境下還會回報 leader 狀態與是否已 catch up，是後續 healthcheck 的主端點之一（詳見第三部 第 21 章 監控）。

🟢 初學者重點
  • 最快路徑：brew install rqlite 或 docker run rqlite/rqlite
  • 包含兩支主要 binary：rqlited（server）、rqlite（CLI）
  • 沒安裝成功？檢查 glibc 版本或改用 musl 版
🔵 開發者重點
  • Go 1.24+ 編譯，CGO 編譯 SQLite
  • 使用 go test ./... 跑單元測試
  • 貢獻 PR 前要 squash commits，保持 master 歷史乾淨
🟡 DevOps / SRE 重點
  • 正式環境鎖定具體版本 tag（如 9.3.0），不要用 latest
  • 下載後務必校驗 sha256
  • Docker volume 一定要持久化 /rqlite/file 路徑

CH. 04rqlite shell 與 UI 工具

Beginner Developer DevOps

rqlite shell 是與 rqlite 服務互動的官方 CLI，包裝在每個 release 內。它的設計刻意接近 SQLite 的 sqlite3 shell，讓熟悉 SQLite 的人能無痛上手。

4.1 啟動 rqlite CLI

查看完整 flag

bash
rqlite -h
Flag預設值說明
-h, --help—顯示說明
-a, --alternatives—備援節點清單（逗號分隔的 host:port），主節點不可達時自動嘗試
-s, --schemehttp協定（http / https）
-H, --host127.0.0.1rqlited 主機位址
-p, --port4001rqlited HTTP port
-P, --prefix/HTTP URL prefix（reverse proxy 場景用）
-i, --insecurefalse不驗證 HTTPS 憑證（測試環境用，正式環境勿用）
-c, --ca-cert—信任的 X.509 root CA 憑證路徑
-u, --user—Basic auth credentials：username:password
-v, --version—顯示 CLI 版本

4.2 Dot commands（點指令）

進入 shell 後，所有以 . 開頭的指令都是 dot commands，用來操作叢集元數據、診斷狀態、備份還原。打 .help 可看完整清單：

指令用途章節對應
.tables列出所有 table本章
.schema顯示所有 table 的 CREATE 語句本章
.indexes顯示所有 index本章
.nodes顯示叢集所有節點連線狀態第三部
.status顯示當前節點的詳細狀態 / 診斷第三部
.ready檢查當前節點是否 ready 接收請求第三部
.expvar顯示 expvar 指標（Go runtime + rqlite 自訂）第三部
.consistency [none|weak|strong]顯示或設定當前 session 的讀取一致性等級第二部
.backup <file>把資料庫備份成 SQLite binary 檔第三部
.dump <file>把資料庫匯出成 SQL 文字檔第三部
.restore <file>從 SQLite 檔或 SQL dump 還原第三部
.remove <raft ID>從叢集移除節點第三部
.sysdump <file>傾印系統診斷資訊供事後分析第三部
.exit / quit離開 shell本章
💡 .consistency 是 session-level 設定

.consistency strong 只影響當前 shell session 之後發出的查詢。對應 HTTP 端點則是 ?level=strong 參數。一致性層級的完整討論在第二部 第 9 章。

4.3 連線到不同節點 / TLS / 認證

4.3.1 連到非本機節點

bash
rqlite -H 192.168.0.1 -p 4001
# 進入 prompt：192.168.0.1:4001>

4.3.2 連到 HTTPS / TLS 節點

bash
# 正式環境：指定 CA 憑證驗證
rqlite -s https -H rqlite.internal -p 4001 -c /etc/ssl/ca.crt

# 測試環境：跳過憑證驗證（self-signed cert）
rqlite -s https -H localhost -p 4001 -i

4.3.3 Basic Auth

bash
rqlite -u admin:secret123 -H localhost

4.3.4 多節點 fallback

bash
# 主節點不可達時自動切到 alternatives
rqlite -H node1.example.com -p 4001 \
       -a node2.example.com:4001,node3.example.com:4001

4.3.5 command history

shell 會把命令歷史寫入家目錄下的 .rqlite_history，預設保留 100 筆。透過環境變數調整：

bash
# 保留 1000 筆
export RQLITE_HISTFILESIZE=1000
rqlite

# 完全停用 history（共用主機建議）
export RQLITE_HISTFILESIZE=0
rqlite

4.4 UI 應用

rqlite 官方不提供內建 Web UI。社群與第三方產品有以下選擇（官方文件目前點名兩個）：

Dataflare
商業桌面應用（macOS / Windows / Linux），支援 SQLite、MySQL、PostgreSQL、rqlite 等多種資料庫；提供 GUI 表格編輯、SQL 編輯器、ER 圖。
LibSQL Studio
開源 Web 介面，原本為 libSQL 設計，亦可連 rqlite。瀏覽器即用、可自架。
⚠ 第三方工具的安全評估

官方明確提醒「do your own evaluation」。第三方工具會用 rqlite 的 HTTP API 操作資料；正式環境連線前請確認：（1）工具如何儲存帳密，（2）是否能走 HTTPS，（3）是否符合公司資安政策。

替代方案：自己用 curl + jq

很多 SRE 在生產環境其實只用 curl 加 jq 就能做完所有運維操作：

bash
# 查當前節點狀態
curl -s http://localhost:4001/status | jq .store.leader

# 列出叢集所有節點
curl -s http://localhost:4001/nodes | jq

4.5 常見操作範例

4.5.1 完整的「探索」流程

text
$ rqlite
127.0.0.1:4001> .status
# 顯示完整節點狀態，含 Raft term、commit index、leader、disk size 等

127.0.0.1:4001> .nodes
# 確認叢集成員與健康度

127.0.0.1:4001> .tables
# 列出 schema

127.0.0.1:4001> .schema
# 看每個 table 的 CREATE 語句

127.0.0.1:4001> SELECT name, sql FROM sqlite_master WHERE type='table';
# 等同於 .schema 的底層 SQL（也可手寫）

4.5.2 切換一致性層級做 debug

text
127.0.0.1:4001> .consistency
weak
127.0.0.1:4001> .consistency strong
127.0.0.1:4001> SELECT COUNT(*) FROM foo;
# 這次查詢會強制走 Raft 確保完全最新

4.5.3 從 shell 做熱備份

text
127.0.0.1:4001> .backup /tmp/backup-2026-05-12.sqlite
# 寫出 SQLite binary 檔，可直接用 sqlite3 開啟檢視

127.0.0.1:4001> .dump /tmp/dump-2026-05-12.sql
# 寫出 SQL 文字檔，可用文字工具 diff 或 grep

4.5.4 把 shell 接到 stdin（idempotent 自動化）

shell 也支援 pipe 輸入，方便用於自動化腳本（playbook）：

bash
# 用 here-doc 一次跑多個指令
rqlite -H rqlite.internal <<'EOF'
.consistency strong
CREATE TABLE IF NOT EXISTS app_config (key TEXT PRIMARY KEY, value TEXT);
INSERT OR REPLACE INTO app_config VALUES ('version', 'v1.2.3');
SELECT * FROM app_config;
EOF

這種模式很適合放進 Ansible playbook 或 CI 步驟中，做為 idempotent 的 schema migration 起步。

🟢 初學者重點
  • .help 看所有 dot commands
  • .tables / .schema 是 SQLite 慣用語
  • 離開：.exit 或 quit
🔵 開發者重點
  • .consistency 在 ad-hoc debug 切讀一致性很方便
  • shell 支援 stdin 餵 SQL，可整合進 migration 腳本
  • UI：推 LibSQL Studio（OSS）或 Dataflare（商業）
🟡 DevOps / SRE 重點
  • 共用主機請 RQLITE_HISTFILESIZE=0 避免 credential 殘留 history
  • -a alternatives 提供客戶端側 failover
  • 正式環境永遠用 -c CA，不要用 -i insecure
  • curl + jq 通常比 GUI 更可重現、更可放進 playbook
