附錄使用說明

  • 截至 Kernel 6.16，BPF helpers 約 220+ 個，本附錄按 14 大類整理。
  • 每個 helper 列出：函式 signature 摘要、引入版本、主要用途。
  • 受限於空間，細節參數說明請查 man bpf-helpers(7)，本表為「分類索引 + 速查」。
  • Helpers 屬於 UAPI，有長期穩定保證；若可用 helper 完成，優先用 helper 而非 kfunc（kfunc 無 ABI 穩定性保證）。
  • 每個 helper 可被哪些 program type 呼叫，受 bpf_*_func_proto 函式中的白名單限制；未列出時表示「多數 program type 可用」。

章節第六部 附錄 對應原始碼linux/kernel/bpf/ + linux/net/bpf/ 等模組分散註冊 使用方式分類速查；具體 signature 與細節以 docs.ebpf.io / kernel.org 為準

KFunc vs Helper：關鍵差別

  • Helper 屬於 UAPI（user-space API），長期 stability。Kernel 不會輕易改動。
  • KFunc 屬於 kernel module export 給 BPF 的函式，無 ABI 穩定性保證，跨版本 rename / 改 signature 的可能性高。
  • 多數新功能優先以 KFunc 形式釋出，成熟後可能升格為 helper（罕見）。
  • 用 KFunc 時建議用 bpf_core_type_exists / bpf_core_func_exists 等做條件式存取，跨 Kernel 安全 fallback。

B.1 KFunc 註解後綴

看 KFunc signature 時常見的後綴註解：

後綴意義例
__sz緊跟其後的參數是前一個 buffer 的 size（runtime）bpf_dynptr_from_mem(void *data, u32 data__sz, ...)
__szk緊跟的 size 必須是 const（compile-time known）void *bpf_dynptr_slice(..., void *buf, u32 buf__szk)
__k該 scalar 必須是 compile-time constflag 必須在 const 範圍
__uninit參數不需初始化（kfunc 會初始化它）iterator new
__nullable允許傳 NULLoptional task pointer
__opt該 size 對應的 buffer 可為 NULLoptional output buffer
__refcounted_kptr必須是 reference-counted kptr把 ref 存進 map

B.2 KFunc Flags（kernel 側設定）

Kernel 註冊 KFunc 時帶的 flag 決定 BPF 的使用限制：

Flag意義
KF_ACQUIRE呼叫後 BPF 拿到 reference，須以 KF_RELEASE 配對釋放
KF_RELEASE釋放 reference
KF_TRUSTED_ARGS所有參數必須是 trusted pointer
KF_RCU必須在 RCU read-side critical section 內呼叫
KF_RCU_PROTECTEDsleepable 也必須包 rcu_read_lock
KF_SLEEPABLE可能 sleep（限 sleepable BPF 程式）
KF_DESTRUCTIVE可能改變 kernel 狀態（限制更嚴）
KF_ITER_NEW / NEXT / DESTROYiterator 三段式

bpf_iter_scx_dsq_new / next / destroy6.12sched_ext dispatch queue

B.5.1 範例：bpf_iter_num

用 iterator 取代 for loop
SEC("tp_btf/something")
int my_handler(void *ctx) {
    struct bpf_iter_num it;
    int *v;

    bpf_iter_num_new(&it, 0, 100);
    while ((v = bpf_iter_num_next(&it))) {
        if (*v == target_val) break;
        /* ... */
    }
    bpf_iter_num_destroy(&it);
    return 0;
}

B.18 KFunc 使用慣例

B.18.1 條件式呼叫：偵測 KFunc 是否存在

用 weak 宣告 + 偵測
/* 在 BPF C 端宣告 weak symbol */
extern struct task_struct *bpf_task_from_pid(s32 pid) __ksym __weak;

SEC("tp_btf/foo")
int handle(...) {
    if (bpf_task_from_pid) {     /* 6.2+ 才有 */
        struct task_struct *t = bpf_task_from_pid(target_pid);
        /* ... */
        if (t) bpf_task_release(t);
    } else {
        /* fallback：用 helper */
    }
    return 0;
}

B.18.2 與 helper 並存的情況

場景helper 是否存在kfunc 是否存在建議
Map 操作✓✗用 helper
Dynptr 基礎✓（5.19）✗用 helper
Dynptr from skb / xdp✗✓（6.4）用 kfunc
Cpumask 操作✗✓（6.2）用 kfunc
Iterator✗✓（6.4+）用 kfunc
Stack trace✓✗用 helper
Ringbuf 基礎✓✗用 helper

B.19 速查總結

使用順序原則
  1. 有 helper 用 helper（UAPI stable）
  2. 沒 helper 才用 kfunc
  3. 用 kfunc 時宣告 __weak + 條件式呼叫，跨 Kernel 相容
  4. 注意 KF_ACQUIRE / KF_RELEASE 的成對使用，否則 verifier 拒絕載入
  5. Sleepable BPF + RCU-protected kfunc 必須包 bpf_rcu_read_lock / unlock
