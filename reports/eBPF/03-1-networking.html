8.1.3 Socket 與連線事件

除了封包路徑，還有事件式的 hook：

  • SOCK_OPS：TCP 連線狀態變化（SYN_SENT → ESTABLISHED → CLOSE_WAIT...）。
  • SK_SKB：Stream Parser，把 byte stream 切成訊息。
  • SK_MSG：app 呼叫 sendmsg 寫入 socket 時觸發。

8.2 XDP — 最早期的封包處理

BPF_PROG_TYPE_XDP
分類
Networking
觸發位置
NIC driver（最早），可選 SKB-mode（generic）或 HW-offload
Context
struct xdp_md *（含 data、data_end、ingress_ifindex、rx_queue_index 等）
Return values
XDP_PASS / XDP_DROP / XDP_TX / XDP_REDIRECT / XDP_ABORTED
支援版本
4.8 起
典型場景
DDoS 緩解、L4 負載平衡（Katran / Cilium）、封包轉發

8.2.1 三種運行模式

模式需求效能備註
Native（XDP_FLAGS_DRV_MODE）NIC driver 必須支援（mlx5、ixgbe、i40e、virtio-net、ena 等大多支援）最快，~25 Mpps/core主流選擇
Generic / SKB（XDP_FLAGS_SKB_MODE）無需 driver 支援慢得多（已分配 sk_buff）除錯、相容性 fallback
Offload（XDP_FLAGS_HW_MODE）SmartNIC（Netronome、目前少見）無 CPU 成本少數場景

8.2.2 XDP 範例：拒絕特定 IP

xdp_blocklist.c
#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_endian.h>

#define ETH_P_IP 0x0800

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __type(key, __u32);     // IPv4 (network byte order)
    __type(value, __u32);
    __uint(max_entries, 10240);
} blocklist SEC(".maps");

SEC("xdp")
int xdp_filter(struct xdp_md *ctx) {
    void *data     = (void *)(long)ctx->data;
    void *data_end = (void *)(long)ctx->data_end;

    struct ethhdr *eth = data;
    if ((void *)(eth + 1) > data_end) return XDP_PASS;
    if (eth->h_proto != bpf_htons(ETH_P_IP)) return XDP_PASS;

    struct iphdr *ip = (void *)(eth + 1);
    if ((void *)(ip + 1) > data_end) return XDP_PASS;

    if (bpf_map_lookup_elem(&blocklist, &ip->saddr))
        return XDP_DROP;     // 命中黑名單，丟棄

    return XDP_PASS;
}

8.3 SCHED_CLS（tc / tcx）— 主力 datapath

BPF_PROG_TYPE_SCHED_CLS
分類
Networking
觸發位置
tc ingress 或 egress qdisc
Context
struct __sk_buff *（已分配 socket buffer，metadata 較豐富）
Return values
TC_ACT_OK / TC_ACT_SHOT / TC_ACT_REDIRECT / TC_ACT_PIPE / ...
支援版本
4.1 起，tcx 6.6+（強烈推薦新專案使用 tcx）
典型場景
L3/L4/L7 policy、QoS、流量整形、Service Mesh

8.3.1 tc 與 tcx 的差別

tc（傳統）：透過 cls_bpf classifier 載入，依賴 qdisc 結構，attach 流程複雜，多程式管理麻煩。

tcx（6.6+）：BPF link 機制重新設計，支援：

  • 多程式 attach：同一個 ingress 可以接多支程式，由 priority 排序。
  • 原子替換：升級時不會有 packet drop window。
  • 更乾淨的 API：cilium/ebpf 與 aya 都優先支援 tcx。
Linux 6.6+ 新專案請用 tcx

官方文件已標註 tc、classifier、action attach type 為 deprecated。新專案應使用 tcx/ingress / tcx/egress。tc 寫法仍可運作但不再推薦。

8.3.2 XDP vs SCHED_CLS 怎麼選

面向XDPSCHED_CLS / tcx
位置NIC driver（極早）tc 階段（已 alloc skb）
效能最快（無 skb 開銷）稍慢但仍極快
方向僅 ingress（XDP_TX 算特殊轉發）ingress 與 egress 都有
可用 helper有限（無 process 上下文）豐富（已有 socket / cgroup 資訊）
修改封包較粗糙透過 sk_buff helper 較完整
可同時掛多個5.10+ 支援 chain，但複雜tcx 原生支援 priority chain
典型用途DDoS、極限 L4 LBL7 policy、Service Mesh、QoS

實務原則：需要 ingress 極限速度 → XDP；需要 egress 或更豐富的 metadata → tcx。大部分 Cilium datapath 兩者都用。

8.4 SCHED_ACT — tc action

BPF_PROG_TYPE_SCHED_ACT
分類
Networking 傳統
觸發位置
傳統 tc action chain
支援版本
4.1，現已基本被 SCHED_CLS direct-action 取代
典型場景
歷史用途，新程式請用 SCHED_CLS

SCHED_ACT 出現比 SCHED_CLS 早，曾經是「classifier 決定 → action 執行」的兩階段模型中的 action 部分。但實務上，所有現代 datapath 都用 SCHED_CLS direct-action mode（return value 同時兼任 verdict），SCHED_ACT 已少使用。本書不再深入。

8.5 SOCKET_FILTER — 經典封包過濾

BPF_PROG_TYPE_SOCKET_FILTER
分類
Networking
觸發位置
socket recv path（封包進入該 socket 前）
Context
struct __sk_buff *
Return values
0 = drop / 非 0 = accept（+ 可指定截斷長度）
支援版本
3.19 起（最早的 program type）
典型場景
類 tcpdump 的 socket 級封包過濾

這是 BPF 的始祖類型，cBPF 時代的 tcpdump 過濾就是它。現代很少自寫 SOCKET_FILTER，但它有一個獨特優勢：權限要求最低，在 BPF Token 等延遲機制下常被當成 capability probe（libbpf 啟動時會載入一個 dummy SOCKET_FILTER 試試 Kernel 是否支援 BPF）。

8.6 SOCK_OPS — TCP 事件 hook

BPF_PROG_TYPE_SOCK_OPS
分類
Networking
觸發位置
cgroup attach；TCP 連線生命週期事件（SYN sent、ESTABLISHED、retransmit、RTT 量測等）
Context
struct bpf_sock_ops *
Return values
op-specific（多數 0 = OK）
支援版本
4.13
典型場景
TCP header 注入、TCP 觀測、TCP 行為調整

SOCK_OPS 不是過濾器，而是「TCP stack 的可程式化回呼」。Kernel 在 TCP 連線生命週期的關鍵點呼叫你的 BPF 程式，傳入 op 標識當前事件類型：

op意義
BPF_SOCK_OPS_TIMEOUT_INIT連線初始化 timeout 設定
BPF_SOCK_OPS_RWND_INIT初始化 receive window
BPF_SOCK_OPS_TCP_CONNECT_CB主動發起 connect
BPF_SOCK_OPS_ACTIVE_ESTABLISHED_CB主動連線 established
BPF_SOCK_OPS_PASSIVE_ESTABLISHED_CB被動連線 established
BPF_SOCK_OPS_RTT_CBRTT 量測 callback
BPF_SOCK_OPS_RETRANS_CB重傳事件
BPF_SOCK_OPS_STATE_CBTCP 狀態切換
BPF_SOCK_OPS_HDR_OPT_LEN_CB / BPF_SOCK_OPS_WRITE_HDR_OPT_CB注入 TCP header option

典型應用：Cilium 用 SOCK_OPS 把連線資訊塞入 SOCKMAP，後續 SK_MSG 程式可以攔截該連線進行 L7 重導。

8.7 SK_SKB — Stream Parser

BPF_PROG_TYPE_SK_SKB
分類
Networking
觸發位置
SOCKMAP / SOCKHASH 內 socket 收到資料時
Context
struct __sk_buff *
支援版本
4.14
典型場景
把 byte stream 切成訊息邊界，再做 redirect 或 drop

TCP 是 byte stream，但應用層常有訊息邊界（如 HTTP 一個請求是一個訊息）。SK_SKB 的 parser 子類型負責決定「下一個訊息的長度」，verdict 子類型再決定要 drop / pass / redirect。是 L7 加速的底層元件。

8.8 SK_MSG — sendmsg 攔截

BPF_PROG_TYPE_SK_MSG
分類
Networking
觸發位置
app 對 SOCKMAP 內 socket 呼叫 send/sendmsg 時
Context
struct sk_msg_md *
Return values
SK_PASS / SK_DROP（搭 bpf_msg_redirect_* 改變目的地）
支援版本
4.17
典型場景
Service Mesh 加速：在 socket 層直接把流量送到目標 sidecar，省掉 kernel network stack

SK_MSG 是 Cilium Service Mesh 不需要 sidecar 也能處理 L7 的關鍵。它讓 BPF 程式在「app 寫入 socket」這個瞬間就攔截資料，重導向到別的 socket，封包根本不必走完整網路堆疊。

8.9 SK_LOOKUP — 自訂 socket 選擇

BPF_PROG_TYPE_SK_LOOKUP
分類
Networking
觸發位置
新進 TCP 連線或 UDP 封包要找對應的 listening socket 時
Context
struct bpf_sk_lookup *
Return values
SK_PASS（用內建邏輯）/ SK_DROP（透過 bpf_sk_assign 指定 socket）
支援版本
5.9
典型場景
「一個 socket 接收成千上萬個 port」、容器/sandbox 動態 port 派發、TLS termination 集中

傳統 Linux 必須對每個 port bind() 一個 socket。SK_LOOKUP 打破這個限制：BPF 程式可以決定「無論封包是要哪個 port，都用某個特定 socket 處理」。Cloudflare 用它做大規模 TLS termination。

8.11 FLOW_DISSECTOR — 程式化流量解析

BPF_PROG_TYPE_FLOW_DISSECTOR
分類
Networking
觸發位置
Kernel 需要解析封包流量資訊（如算 RSS hash、NAT、tunnel inner header）時
Context
struct __sk_buff *（含 flow_keys 待填）
支援版本
4.20
典型場景
自訂 tunnel 協定的解析、為新型協定加上 RPS/RFS 支援

Kernel 內部有 flow_dissector 元件，從封包抽出 5-tuple（src/dst IP + ports + proto）給 RPS、RFS、conntrack 等用。FLOW_DISSECTOR 程式取代這個元件，讓你能正確解析任意自訂協定。

8.12 NETFILTER — BPF-based netfilter hook

BPF_PROG_TYPE_NETFILTER
分類
Networking 較新
觸發位置
netfilter 5 個 chain（PREROUTING / INPUT / FORWARD / OUTPUT / POSTROUTING）
Context
struct bpf_nf_ctx *（含 skb + state）
Return values
NF_ACCEPT / NF_DROP / NF_QUEUE / NF_STOLEN / NF_REPEAT

2023 年加入的程式類型，把 BPF 帶到傳統 iptables/nftables 領域。優勢：可以利用 conntrack KFunc 配合決策。劣勢：netfilter 已是上層位置，性能不如 XDP / tc。多數新專案仍會把防火牆做在 XDP/tc 而非 NETFILTER。

8.13 完整實作範例：XDP IP 黑名單（Go + Rust）

把第 8 章串起來，做一個能實際運行的 XDP IP 黑名單工具：user space 維護一份 IP 黑名單，BPF 程式收到封包時查 map，命中即 drop。

8.13.1 BPF C（Go 路線）

bpf/blocklist.c
#include "headers/vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_endian.h>

#define ETH_P_IP 0x0800

char LICENSE[] SEC("license") = "GPL";

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __type(key, __u32);
    __type(value, __u32);
    __uint(max_entries, 10240);
    __uint(pinning, LIBBPF_PIN_BY_NAME);
} blocklist SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_ARRAY);
    __type(key, __u32);
    __type(value, __u64);
    __uint(max_entries, 2);     // [0]=passed, [1]=dropped
} stats SEC(".maps");

static __always_inline void inc_stat(__u32 idx) {
    __u64 *v = bpf_map_lookup_elem(&stats, &idx);
    if (v) (*v)++;
}

SEC("xdp")
int xdp_blocklist(struct xdp_md *ctx) {
    void *data     = (void *)(long)ctx->data;
    void *data_end = (void *)(long)ctx->data_end;

    struct ethhdr *eth = data;
    if ((void *)(eth + 1) > data_end) {
        inc_stat(0);
        return XDP_PASS;
    }
    if (eth->h_proto != bpf_htons(ETH_P_IP)) {
        inc_stat(0);
        return XDP_PASS;
    }

    struct iphdr *ip = (void *)(eth + 1);
    if ((void *)(ip + 1) > data_end) {
        inc_stat(0);
        return XDP_PASS;
    }

    if (bpf_map_lookup_elem(&blocklist, &ip->saddr)) {
        inc_stat(1);
        return XDP_DROP;
    }
    inc_stat(0);
    return XDP_PASS;
}

8.13.2 Go user space

gen.go
package main

//go:generate go tool bpf2go -cc clang -target amd64,arm64 \
//  blocklist bpf/blocklist.c -- -I./bpf/headers
main.go
package main

import (
    "encoding/binary"
    "log"
    "net"
    "net/netip"
    "os"
    "os/signal"
    "syscall"
    "time"

    "github.com/cilium/ebpf"
    "github.com/cilium/ebpf/link"
    "github.com/cilium/ebpf/rlimit"
)

func main() {
    if len(os.Args) < 3 {
        log.Fatalf("usage: %s <iface> <blocked-ip>[,...]", os.Args[0])
    }
    ifaceName := os.Args[1]
    blockedIPs := os.Args[2]

    if err := rlimit.RemoveMemlock(); err != nil { log.Fatal(err) }

    objs := blocklistObjects{}
    if err := loadBlocklistObjects(&objs, nil); err != nil {
        log.Fatalf("load: %v", err)
    }
    defer objs.Close()

    iface, err := net.InterfaceByName(ifaceName)
    if err != nil { log.Fatalf("interface %s: %v", ifaceName, err) }

    l, err := link.AttachXDP(link.XDPOptions{
        Program:   objs.XdpBlocklist,
        Interface: iface.Index,
        Flags:     link.XDPGenericMode, // 任何環境都能用，正式環境改 XDPDriverMode
    })
    if err != nil { log.Fatalf("attach: %v", err) }
    defer l.Close()

    // 載入黑名單
    for _, s := range splitCsv(blockedIPs) {
        addr, err := netip.ParseAddr(s)
        if err != nil { log.Printf("skip %s: %v", s, err); continue }
        if !addr.Is4() { log.Printf("skip %s: not v4", s); continue }
        b := addr.As4()
        key := binary.LittleEndian.Uint32(b[:])
        // BPF 端 ip->saddr 是 network-byte-order，這裡保持 raw
        raw := binary.BigEndian.Uint32(b[:])
        if err := objs.Blocklist.Put(raw, uint32(1)); err != nil {
            log.Printf("put %s: %v", s, err)
        } else {
            log.Printf("blocked %s (raw=0x%08x, le=%d)", s, raw, key)
        }
    }

    sig := make(chan os.Signal, 1)
    signal.Notify(sig, os.Interrupt, syscall.SIGTERM)
    tick := time.NewTicker(2 * time.Second)
    defer tick.Stop()

    log.Printf("XDP attached on %s. Ctrl-C 結束。", ifaceName)
    for {
        select {
        case <-sig:
            return
        case <-tick.C:
            passed, dropped := readStats(objs.Stats)
            log.Printf("passed=%d dropped=%d", passed, dropped)
        }
    }
}

func splitCsv(s string) []string {
    out := []string{}
    cur := ""
    for _, r := range s {
        if r == ',' { out = append(out, cur); cur = ""; continue }
        cur += string(r)
    }
    if cur != "" { out = append(out, cur) }
    return out
}

func readStats(m *ebpf.Map) (uint64, uint64) {
    var (
        key0 uint32 = 0
        key1 uint32 = 1
    )
    var pcpu0, pcpu1 []uint64
    _ = m.Lookup(key0, &pcpu0)
    _ = m.Lookup(key1, &pcpu1)
    var passed, dropped uint64
    for _, v := range pcpu0 { passed += v }
    for _, v := range pcpu1 { dropped += v }
    return passed, dropped
}

8.13.3 Rust（aya）user space

blocklist-ebpf/src/main.rs
#![no_std]
#![no_main]

use aya_ebpf::{
    bindings::xdp_action,
    macros::{map, xdp},
    maps::{HashMap, PerCpuArray},
    programs::XdpContext,
};
use core::mem;
use network_types::{
    eth::{EthHdr, EtherType},
    ip::Ipv4Hdr,
};

#[map] static BLOCKLIST: HashMap<u32, u32> = HashMap::with_max_entries(10240, 0);
#[map] static STATS:    PerCpuArray<u64> = PerCpuArray::with_max_entries(2, 0);

#[xdp]
pub fn xdp_blocklist(ctx: XdpContext) -> u32 {
    match try_filter(ctx) {
        Ok(act) => {
            unsafe {
                let idx = if act == xdp_action::XDP_DROP { 1 } else { 0 };
                if let Some(v) = STATS.get_ptr_mut(idx) { *v += 1; }
            }
            act
        }
        Err(_) => xdp_action::XDP_ABORTED,
    }
}

#[inline(always)]
unsafe fn ptr_at<T>(ctx: &XdpContext, off: usize) -> Result<*const T, ()> {
    let start = ctx.data();
    let end   = ctx.data_end();
    if start + off + mem::size_of::<T>() > end { return Err(()); }
    Ok((start + off) as *const T)
}

fn try_filter(ctx: XdpContext) -> Result<u32, ()> {
    let eth: *const EthHdr = unsafe { ptr_at(&ctx, 0)? };
    if unsafe { (*eth).ether_type } != EtherType::Ipv4 {
        return Ok(xdp_action::XDP_PASS);
    }
    let ip: *const Ipv4Hdr = unsafe { ptr_at(&ctx, mem::size_of::<EthHdr>())? };
    let saddr = u32::from_be(unsafe { (*ip).src_addr });
    if unsafe { BLOCKLIST.get(&saddr).is_some() } {
        return Ok(xdp_action::XDP_DROP);
    }
    Ok(xdp_action::XDP_PASS)
}

use aya::{
    maps::{HashMap, PerCpuArray, PerCpuValues},
    programs::{Xdp, XdpFlags},
    Ebpf,
};
use clap::Parser;
use std::{net::Ipv4Addr, time::Duration};
use tokio::{signal, time};

#[derive(Parser, Debug)]
struct Opt {
    #[clap(short, long)] iface: String,
    #[clap(short, long, value_delimiter = ',')] block: Vec<Ipv4Addr>,
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let opt = Opt::parse();
    env_logger::init();

    let mut bpf = Ebpf::load(include_bytes_aligned!(
        "../../target/bpfel-unknown-none/release/blocklist-ebpf"
    ))?;

    let prog: &mut Xdp = bpf.program_mut("xdp_blocklist").unwrap().try_into()?;
    prog.load()?;
    prog.attach(&opt.iface, XdpFlags::SKB_MODE)?;

    let mut blocklist: HashMap<_, u32, u32> =
        HashMap::try_from(bpf.map_mut("BLOCKLIST").unwrap())?;
    for ip in &opt.block {
        let raw: u32 = u32::from_be_bytes(ip.octets());
        blocklist.insert(raw, 1, 0)?;
        println!("blocked {}", ip);
    }

    let stats: PerCpuArray<_, u64> = PerCpuArray::try_from(bpf.map("STATS").unwrap())?;
    let mut tick = time::interval(Duration::from_secs(2));
    println!("XDP attached on {}. Ctrl-C 結束。", opt.iface);
    loop {
        tokio::select! {
            _ = signal::ctrl_c() => break,
            _ = tick.tick() => {
                let p: PerCpuValues<u64> = stats.get(&0u32, 0)?;
                let d: PerCpuValues<u64> = stats.get(&1u32, 0)?;
                let passed: u64 = p.iter().sum();
                let dropped: u64 = d.iter().sum();
                println!("passed={} dropped={}", passed, dropped);
            }
        }
    }
    Ok(())
}

8.14 第 8 章小結

  1. 網路類有 11 種 program type，依「觸發位置」分布在 RX 與 TX 路徑與 socket 事件上。
  2. 主力組合：XDP（極早 RX） + tcx ingress/egress（豐富 metadata）+ SOCK_OPS / SK_MSG（連線級操作）。
  3. SOCKET_FILTER 是始祖，現代少自寫但常作 capability probe。
  4. SK_LOOKUP 打破「一個 socket 一個 port」的歷史限制。
  5. NETFILTER（6.4+）是新加入的 BPF chain，但效能位置上不會取代 XDP / tc。
  6. SCHED_ACT 已被 SCHED_CLS direct-action 取代，新專案不要再用。
  7. tcx（6.6+）是新一代 tc attach，支援多程式 chain 與原子替換，新專案請優先採用。

9.1 什麼是 LWT

LWT（Lightweight Tunneling）是 Linux Kernel 中一個輕量級隧道封裝機制。它與「重量級」的 GRE、IPIP、VXLAN 不同，不需要建立 virtual netdev，而是直接附在 routing entry 上：

在 route 上掛 BPF
# 把一個 BPF 程式掛在路由 10.0.0.0/24 的 input 階段
$ sudo ip route add 10.0.0.0/24 \
    encap bpf in obj lwt_in.o section in \
    dev eth0

LWT BPF 程式只在該 routing entry 命中時觸發，與 tc / XDP 等基於 interface 的 hook 不同。

9.3 LWT_SEG6LOCAL 與 SRv6

SRv6（Segment Routing over IPv6）是新一代資料中心路由協定，把路由路徑（一連串 segment）寫進封包 IPv6 header，每跳處理一個 segment。Linux Kernel 從 4.10 起原生支援 SRv6，但內建的 segment 處理動作（End、End.X、End.T...）有限。

LWT_SEG6LOCAL 讓你用 BPF 自訂任意 segment 處理邏輯，例如：

  • 自訂 End.bpf 動作：BPF 程式決定下一跳。
  • SRv6 路徑統計、tracing。
  • SRv6 Service Function Chaining。

這是 5G 核心網、Service Provider 大型網路的常用技術，一般應用程式較少接觸。

9.4 第 9 章小結

  1. LWT 是基於 routing entry 的輕量隧道機制，不需要建 virtual netdev。
  2. 4 個 program type 對應 routing 不同階段：LWT_IN / LWT_OUT / LWT_XMIT / LWT_SEG6LOCAL。
  3. 實務上一般工作負載很少自寫 LWT；主要用於 SRv6、自訂 tunnel 協定等網路工程場景。
  4. 多數通用情境用 tc / XDP 即可，不需要動到 LWT。
